# 为何从 ops 拆出 AI Infra

> **样机诚实**：现 `apps/ops` 把「模型 / infra」和日志/SLA 挤在同一运维壳；无真训推。  
> **落地目标**：**运维可观测**与 **AI 训推基建**分平面、分 Owner、分数据面，避免 GPU 作业与办案 SLA 混台账。

## 1. 问题

用户认定「现运维不够」。根因不是少几个 mock 页，而是能力域不同：

| ops 心智 | AI Infra 心智 |
|----------|----------------|
| 系统是否健康、密钥/配置是否正确、告警是否到达 | 任务能否在 GPU 上跑完、吞吐/延迟、权重如何发布、如何回滚 |
| 面向 SRE / 平台运维 | 面向算法 / 数据 / MLOps + 平台 |

混在同一 `ops-platform` 会导致：权限模型拧巴、配额与办案租户纠缠、误把案数据送进训练桶。

## 2. 拆分原则

1. **`ops-platform` ≠ `ai-infra`**（硬）。  
2. 产品默认 **独立壳** `apps/ai-infra` 端口 **5179**（并行样机，类似 doc-harness:5178）；**不**掏空现 ops 六路由。  
3. 附录允许「先挂 ops 子路由，条件满足再拆壳」（见 [surfaces.md](./surfaces.md)）。  
4. ai-infra **禁止**持有或写入 `PatentCase`。  
5. 与 enterprise C 混合：Agent 调模型走**网关**；网关消费 ai-infra **已发布**的推理端点/配额，不在办案路径上申请 GPU job。

## 3. 协作对象

- 算法 / 数据：训练数据契约、评测集、指标定义（标准化在 roadmap）。  
- 平台：调度、镜像、密钥（密钥元数据可与 ops 密钥仓引用，明文不进壳）。  
- 办案：只读「可用模型列表 / 配额」类 API，不读训练任务详情到案卷。
