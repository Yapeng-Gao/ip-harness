# 偏好学习与强化学习

## 1. 方法选择（产品默认）

| 方法 | 数据 | 适用 | 备注 |
|------|------|------|------|
| **DPO / IPO 等** | 偏好对 (chosen, rejected) | 默认优先 | 无在线奖励模型也可 |
| **RLHF（PPO 等）** | RM 数据 + 在线滚出 | 有奖励模型与稳定性团队时 | 成本高 |
| **GRPO/RLOO 等** | 可验证奖励或两两比较 | 工具正确性、格式 | 视框架 |
| **拒绝采样精炼** | 多候选+裁判 | 过渡方案 | |

## 2. 数据需求

| 类型 | 说明 |
|------|------|
| 成对偏好 | 同 prompt 下好/坏回答；维度：正确、完整、合规、语气 |
| 多维度标注 | 可先单维再综合 |
| 安全偏好 | 有害/越权必须 rejected |
| 裁判模型标签 | 可放大，但要黄金集校准 |

## 3. 奖励信号（若走 RL）

- 自动：格式 JSON schema、是否调用正确工具、检索引用是否幻觉（规则+检索回查）  
- 模型：偏好 RM  
- 人工：抽检校准  

## 4. 风险

- 奖励黑客、啰嗦病、过度拒答  
- 必须留 **SFT 锚点混训** 或正则，防分布漂移  

## 5. IP 场景注意

- **禁止**把「像律师」当作奖励；奖励「引用命中与诚实不确定」  
- FTO/侵权表述走「辅助草稿 + 免责」模板
