# 数据怎么准备

## 1. 端到端步骤

1. **立项与许可证审查**（无许可不进湖）  
2. **采集** → Raw（对象存储）  
3. **清洗**：去重、语言、垃圾 OCR、模板噪声  
4. **脱敏**：案号/客户/个人信息；办案导出强制流水线  
5. **标注/合成**：人工、专家、模型合成+审校  
6. **切片与格式化**：转 messages / 偏好对 / 纯文本  
7. **配比采样**（Recipe）→ 物化 train/valid split  
8. **质量门** → 发布 `dataset version` + manifest（路径、条数、hash、license）  
9. **ai-infra Job 只读拉取**  

## 2. 长专利策略

| 策略 | 做法 |
|------|------|
| 分段 | 按权利要求/段落切，带 `docId+offset` |
| 两阶段 | 先检索相关段再生成（RAG SFT） |
| 压缩 | 中间摘要作输入，保留可追溯引用 |
| 丢弃 | OCR 极差页不进 SFT，可进 CPT 降权或不进 |

## 3. 合成数据

- 允许：改写、多风格、对抗拒答、工具轨迹合成  
- 必须：抽样人工审校；合成比例写入 Recipe；评测集禁止被合成污染  

## 4. 泄漏防控

- 评测题、客户数据、未公开交底：**黑名单指纹**  
- train/valid/test 按文档家族拆分，避免同族泄漏  

## 5. 交付物

- Parquet/JSONL + manifest  
- 字段字典与 schema 版本  
- 已知缺陷列表（随 version）


## 4. 长文专利切片

| 策略 | 用途 |
|------|------|
| 按章节/权利要求项切 | SFT 样本 |
| 滑动窗口 + 标题上下文前缀 | CPT |
| 检索段落作 RAG 块 | RAG 专项；保留 doc id |

## 5. Tokenizer

- 评估专利号、化学式、IPC 碎片是否被过度切分  
- 需要则领域继续训练词表或预处理规范化（规格层记录，实施另立 spike）
