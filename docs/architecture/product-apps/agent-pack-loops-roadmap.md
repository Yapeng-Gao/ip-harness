## Knife1 · F5 内循环 + 跨席环边

**范围**：交底→查新→撰写→附图 主链上的：

- **内循环**：交底追问（mock 缺项轮次）；**查新覆盖度自修复**（mock Issue≤3，节点内边）；撰写四类校验自修复（mock≤3）；超限→escalate 兜底  
- **外循环环边（四环边中的跨席/HITL）**：HITL③/⑤ 驳回带批注重跑；**附图→撰写 feedback**；HITL④ 不乐观→回流示意（可灰）。查新自修复**不算**外循环四环边。

### 验收标准

- [ ] 业务案子时间线：确认交底 / 确认查新 / 确认权项 后进度前进；点「退回」后人话提示「请按意见修改」且该项回到待确认  
- [ ] 专家台 / 过程面板：可见「检查未通过·已重试 n/3」或「附图退回撰写改术语」类过程行（勿写 validator 英文黑话给业务）  
- [ ] 超 3 次自修复：过程面板出现「需人工接手」示意（mock escalate），**不**静默死循环  
- [ ] 无真沙箱、无真 LLM 必过；剧本驱动即可

### 壳面

| 面 | 表现 |
|----|------|
| 业务 `/agent/cases/:id` | 人话进度；待确认收件箱 |
| 专家台 `/agent/catalog` | 环边 / worklog 过程可见 |
| mid 深链 | **仍禁**可点验收 |

### 不做

真沙箱 · 真覆盖度公式 · packages 新 key 写入。

### 依赖

无（首刀）。设计稿 §5.1 / §5.5 F5 已钉。

## Knife2 · F6 OA N 通外循环

**范围**：审查答复席上的：

- 理由分类（mock 分支：创造性 / 清楚性 …）  
- 子任务汇入示意（补充检索 / 修术语）  
- HITL⑥ 策略确认 / 驳回  
- **N 通外循环**：提交后「第 2 通通知书到达」→ 回到答复入口（计数器可见）  
- 超范围 blocker：一次失败 → 「需人工接手」（**0 次自修复**）

### 验收标准

- [ ] 业务面：仅「已递交」案子解锁审查答复；人话「确认答复策略」；下一通到达后进度显示「第 N 通」  
- [ ] 专家台：可见 N 通计数 + 策略驳回重做过程  
- [ ] blocker 路径：不出现「自动重试修改」假闭环  
- [ ] 无真局端递交

### 壳面

同 Knife1；OA 闸对齐 SEAT_ROSTER（已 file）。

### 不做

真 OA 解析 · 真超范围检查器代码（可用 mock Issue `blocker: true`）。

### 依赖

**Knife1**（F5 递交 mock 状态可进入 OA）。设计稿 §5.2 / §5.5 F6。

## Knife3 · F9→F3 飞轮 + 其他回流

**范围**：

- 维权/监测事件（mock）→ **布局漏洞报告** feedback 信封 → 布局策略师（F3）示意  
- 串联展示：查新不乐观回流、立项低分回流（可与 Knife1 灰入口复用）  
- Phase 席可灰显「即将推出」，但过程面板能点开飞轮故事线

### 验收标准

- [ ] 专家台：一条「布局漏洞回流 → 布局待拍板」过程可追踪（mock）  
- [ ] 业务面：若启用布局，待确认出现人话「请确认布局调整」；未启用则仅专家台可见  
- [ ] **≠ FTO**：不把 `expert-fto` 当成维权席  
- [ ] 无真监测爬虫

### 壳面

业务「更多专家」灰显维权/布局；专家台完整故事线。

### 不做

真全面覆盖比对器 · packages `enforcement_brief` 写入。

### 依赖

**Knife1**（信封/feedback 心智已通）。可与 Knife2 文档并行；样机建议 Knife1→2→3。设计稿 §5.3。
