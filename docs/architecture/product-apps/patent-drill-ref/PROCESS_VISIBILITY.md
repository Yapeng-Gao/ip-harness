# 过程可见性规范（解决「只见交卷不见办案」）

## 1. 问题

现状：各席把「交付」理解成最终 `NN_*.md`，中间怎么拆特征、怎么取舍、查了什么、否决了什么方案，都留在席位私聊或模型脑内。总控聊天只有摘要句，用户点开各 bot 也几乎看不到办案过程。

结果：交付物像「天降文档」，无法质检、无法带教、无法复盘回退。

## 2. 原则

**交卷 = 成果文件 + 过程文件**，缺过程 = 不合格，总控打回。

聊天摘要必须能指到过程文件里的步骤编号，禁止只有「已落盘」。

## 3. 文件约定（每席必交）

| 类型 | 路径 | 谁写 | 何时 |
|------|------|------|------|
| 成果 | `{NN}_{产出键}.md` | 该席 | 定稿时 |
| **过程** | `{NN}_{产出键}_worklog.md` | 该席 | **与成果同步**；多轮则追加，不覆盖 |

例：
- `06_research_report.md` + `06_research_report_worklog.md`
- `09_draft_claims.md` + `09_draft_claims_worklog.md`
- R2 单独回合：`09_draft_claims_R2_worklog.md`

总控案级过程（可选但推荐）：`00_case_worklog.md`（分派/验收/闸门时间线）。

## 4. worklog 最低章节（缺一打回）

```markdown
# 工作过程 · {席位} · {产出键}

| 案号 | 版本 | 开始/结束 | HITL |
|------|------|-----------|------|

## 1. 收到什么
- 上游文件与版本
- 总控分派原话要点

## 2. 目标与成功标准
- 本拍要交什么；怎样算合格

## 3. 步骤时间线（编号，可复述）
| 步 | 动作 | 输入/依据 | 中间结论 | 耗时感 |
|----|------|-----------|----------|--------|
| 1 | … | … | … | … |

## 4. 关键取舍（至少 2 条）
| 选项 A | 选项 B | 选了谁 | 为什么 |

## 5. 证据与材料
- 检索式/对比文件/权要条款/图号等（可摘录，勿空喊「已检索」）

## 6. 卡点与求助
- 缺什么；向谁退回；是否等 HITL

## 7. 交给下家什么
- 成果路径；阅读顺序；红线/开放问题
```

## 5. 各席过程要「看得见」的内容（示例）

| 席 | 过程里必须看得见 |
|----|------------------|
| 查新 | 每轮检索式、命中筛选理由、为何定 X/Y/A |
| 立项 | 吃了哪些上游段落、Go 论据行号 |
| 交底 | 原始材料→特征拆分草稿→与查新对照笔记 |
| 撰写 | 特征表草稿演变、独权必要集增减理由、R 轮纪要 |
| 制图 | 从图号需求到冻锁的核对清单 |
| FTO | 障碍专利入选理由、chart 怎么填、blocker 升降级理由 |
| 递交 | 齐套逐项勾选痕迹、硬缺发现与清除 |
| OA | 通知书拆解、策略备选、要数清单形成过程 |

## 6. 总控验收加一条

1. 成果文件存在且厚度够  
2. **同键 worklog 存在且含 §3 步骤表 + §4 取舍**  
3. 聊天摘要含：`过程见 NN_…_worklog.md`  
否则：**打回，不转 docx，不派下家**

## 7. 和聊天的关系

- 席位自己的对话：应用来**边做边记**（可短），最终以 worklog 为准沉淀。  
- 总控对话：只保留调度与验收，不替代 worklog。  
- 用户要看过程：打开案目录 `*_worklog.md`（及 Word），不要只看成果书。

## 8. 落地顺序

1. 写入本规范 + 更新 OWNER 矩阵「产出」列加 worklog  
2. 更新各席人设 P0：无 worklog=不合格  
3. 下一案（或补做 04 抽样一席）强制双文件交卷验证
