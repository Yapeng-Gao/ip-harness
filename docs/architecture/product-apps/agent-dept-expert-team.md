## 0. 要解决什么

**现状**：主链「节点」≈ **一个专家席**。Pack **16** 节点；业务默认 **7** 席 + 静默案子助手。

**目标**：

```text
案子
 ├─ 主链节点 = 部门（≈ Pack 节点容器；默认 7，目标 16）
 │    └─ 部门内专家（主责真干活；副席一期占位）
 └─ 团队 = 勾选（后加拖拽）跨部专家 → 讨论；默认不产闸
```

| 勿混 | 含义 |
|------|------|
| **部门** | Pack 节点的**容器**；交卷闸挂这里 |
| **专家** | 部内人；**主责** = 现 `expert-*` 真会话 |
| **团队** | 本案讨论专班；非冷启动墙、非第二条主链 |
| **阶段（5 段）** | 粗进度；一阶段可含多部门 |
| **HITL×8** | 收费确认语义；**≠** 部门个数 |

**非目标**：真 IAM · 真 LLM 会商 · 冷启动专家墙 · 按人头开闸 · 推翻 HITL×8 · 一期塞满副专家真会话。

## 3. 部门内专家

### 3.1 规则

- 每部有且仅有一名 **主责** = 现 Catalog `expert-*`（真会话 / 真交卷）。
- **副席**：壳扩展示意编制，**不是** Pack 第二权威。
- 侧栏：**部门一级** → 展开见主责 + 副席；禁冷启动平铺全部人。

### 3.2 样机纪律（防新墙）

| 期 | 副席 |
|----|------|
| **样机 1** | **名单占位**（灰 · 文案「流程位·暂不可聊」）；点击 → 仍进**主责**会话，或 toast「样机仅主责可聊」 |
| **样机 2** | 最多选 **1～2 个部门**做真双会话（建议撰写部）；其余仍占位 |
| **禁止** | 一期 7×2～3 真会话把侧栏铺回超市 |

示意编制（占位名可改，主责 id 不变）：

| 部门 | 主责 | 副席（占位） |
|------|------|--------------|
| 查新部 | 查新主责 | 覆盖度复核 |
| 立项部 | 立项评审 | 评分助理 |

## 4. 「待我确认」= 部门交卷闸

**采用部门闸；否决按专家开闸、否决只按 5 段一闸。**

```text
部内（主责干活；副席占位/后真协助）
  → 主责「交卷」一份成果+过程
  → 本案一条 pending（kind 绑部门）
  → 人确认/退回（必挂助手审校；退回→改稿→再交）
  → 主链前进
```

| 规则 | 规格 |
|------|------|
| pending | 与现 `BusinessConfirmKind` 同源；`preparedBy` = 部门名 |
| 谁交卷 | **仅主责**（样机不开放副席代交，免状态分叉） |
| 副席 | 不进铃铛 |
| 团队聊天 | **默认不产** pending |
| 并行 | 同 kind 最多 1 条；禁截入纪律不变 |

| Pack / 壳 | 部门闸 |
|-----------|--------|
| ④③②⑤⑥ | 查新 / 交底 / 立项 / 撰写 / OA |
| 壳附图 · 壳递交 | 附图部 · 递交部 |
| ①布局 | 布局部（可选） |
| ⑦⑧ | Phase |

收件箱一行：案子 · 确认什么（人话）· **哪一部门** · 时间。

## 10. 心智：新建案子 → 各部门 · 专家 / 部门 / 团队怎么配合

### 10.1 一句话

```text
人开案子 → 走阶段粗进度
  → 当前部门主责干活（部内副席按流程分工协助）
  → 主责交卷 →「待我确认」（部门闸）
  → 确认后解锁下游部门
  → 需要跨部对齐时：组「本案团队」讨论（不产闸）
```

| 角色 | 干什么 | 不干什么 |
|------|--------|----------|
| **部门** | 主链位置；**一份**交卷 / 待确认 | 不是聊天室 |
| **专家·主责** | 真会话、推进深度步骤、**唯一交卷人** | 不一人垄断所有流程角色名 |
| **专家·副席** | 对应深度步骤里的专责（检索式/追问/质检…） | 不单独进铃铛（除非日后升 session） |
| **团队** | 跨部门勾选/拖入，会商对齐 | 不是第二条主链、默认不挂 pending |
| **案子助手** | 巡检 / HITL 辅审 / 静默编排 | 不算部门、不抢主 CTA |

### 10.2 从新建到结案（主链）

```text
开新案子（向导）
  │ 可选：跳过准备 / 启用更多部门
  ▼
准备（可跳）──可选布局部 / 前研
  ▼
立项阶段 ── 查新部交卷④ → 人确认 → 立项部交卷② → 人确认
  ▼
撰写申请 ── 交底部③ → 撰写部⑤ → 附图部(壳) → 各闸人确认
  ▼
递交 ── 递交部授权 → 人确认 → filed
  ▼
审查答复 ── OA 部⑥（N 通可循环）→ 人确认策略
```

侧栏始终：**当前部门高亮**；点主责进会话；展开见副席（多数占位，说明书为真副席）。

### 10.3 旧「一节点多流程」→ 单专家还是多专家？

Pack / 深度步骤里，**一个节点常有 4～6 步**。判定：

| 判据 | → 多人（部内副席） | → 仍算主责一人串 |
|------|-------------------|-------------------|
| 步骤产物类型不同 | 是（权要 vs 说明书） | |
| 有独立内循环/校验角色 | 是（覆盖度复核、四类质检、追问） | |
| 只是同一人连贯操作 | | 是（读意见→写策略可同主责） |
| 要对人交卷的那份 | **只主责** | |

**结论**：深度步骤 **拆成部内多专家角色**；**交卷与 HITL 仍绑部门主责一人**。不是「一步一闸」，也不是「全流程塞进一个无名 bot」。

### 10.4 默认 7 部编制（对照深度步骤）

| 部门 | 主责（交卷） | 副席（流程专责） | 深度步骤来源 |
|------|-------------|------------------|--------------|
| 查新部 | 查新检索 | 检索式 · 覆盖度复核 · 三性意见 | researchDepth |
| 立项部 | 立项评审 | 区别特征 · 三轴评分 · 范围报价 | intakeDepth |
| 交底部 | 交底工程师 | 六段采集 · 缺项追问 · 实施例 | disclosureDepth |
| 撰写部 | 权要撰写 | 特征表 · **说明书(真会话)** · 四类质检 | draftDepth |
| 附图部 | 附图工程师 | 图号清单 · 草图 · 图注校对 | figureDepth |
| 递交部 | 流程管家 | 齐套 · 形式审查 · 期限台账 | filingDepth |
| 审查答复部 | OA 策略 | 理由分类 · 创造性子席 · 答复起草 | oaDepth |

样机：副席默认 **占位**；仅说明书升真会话。日后可按同表逐个升 session。

### 10.5 团队何时上场

| 时机 | 动作 |
|------|------|
| 部内自洽、主责交卷 | **不用**团队 |
| 跨部口径冲突（如附图术语 vs 权要） | 勾选/拖入相关主责 → 组队讨论 |
| 立项前想对齐查新+布局 | 「按阶段推荐」一键组班 |
| 讨论出结论要进主链 | 回到**对应部门主责**改稿再交卷（团队本身不挂闸） |

### 11.1 建案：要不要讨论？→ **要引导，不强制长聊**

| 裁定 | 内容 |
|------|------|
| **做** | 默认路径：**整理本案计划 → 再开干**。客户常说不清情况，向导须给可改的计划骨架（目标 / 起点阶段 / 先找谁），不是只填标题就进工作台。 |
| **不做** | 不强制多轮 LLM「会商」挡创建；不把「选专家组队」做成开新活主 CTA。 |
| **与「跳过准备」共存** | 「跳过准备」= **主链起点**跳过准备阶段（直接立项/查新），**≠** 跳过「本案计划」步。计划步始终出现；勾选跳过准备时，计划文案写明「已跳过准备，从立项/查新起」。 |
| **样机** | 向导在路线之后多一步「本案计划」（可改 textarea）；写入 `CaseProgress.casePlan`。案页案子助手可「按巡检补全计划 / 改写本案计划」（`patchCasePlan` 脚本模板，非真 LLM）→ `updateCasePlan`；侧栏可见计划摘要。 |
| **状态** | **已裁定** · **向导样机已落地** · **助手改计划已落地** |

衔接心智：计划属于**案子助手域**（编排意图），不占部门席；开案后侧栏仍是部门树，团队仍空组。

### 11.2 组队：每步如何「帮忙规划」？→ **推荐理由 + 缺口 + 一键采纳**

| 裁定 | 内容 |
|------|------|
| **做** | 组队面板不只勾选框：展示**本阶段推荐班底**、每人/整体**为何需要**、相对当前勾选**还缺谁**；一键「采纳推荐」。 |
| **不做** | 不自动静默改组；不因组队产 pending；不按人头开闸。 |
| **算法（样机）** | 仍 `recommendTeamForStage`（阶段席 ± 上下游）；外挂 `buildTeamRecommendPlan` 产出 `reasons` / `missingIds`。 |
| **状态** | **已裁定** · **样机补丁优先** |

衔接心智：团队 = 跨部会商专班；推荐只帮人选人，交卷仍回各部门主责。
