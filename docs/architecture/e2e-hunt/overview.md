# 总览

## 1. 问题

现仓 Playwright L0/L1（见 `e2e/REVIEW_RUBRIC.md`）擅长：

- 端口/地标冒烟（壳挂了立刻红）  
- 少量关键路径闸门  

不擅长：

- 过程态故障（console / 失败请求 / 内存毛刺）  
- UI 改版后 brittle 选择器维护  
- 「像人点一遍」的探索与证据化缺陷报告  
- 跨产品复用同一套猎虫能力  

## 2. 目标

建设 **通用 Hunt Harness** + **按产品替换的 AppAdapter**：

1. 廉价规则层先抓硬错误  
2. 增强遥测按需打开  
3. LLM 环只处理探索与歧义判定  
4. 统一报告契约（截图 / 日志 / 复现路径 / 严重度）  

## 3. 非目标

- 替代 L0「秒级发现壳挂」  
- 保证零假阳性的全自动放行  
- 深度视觉回归像素比对（可后置）  

## 4. 原则

| # | 原则 |
|---|------|
| 1 | **信号分层**：能规则定论的不烧 LLM |
| 2 | **Driver 语义稳定**：Cursor 浏览器 MVP ↔ Playwright 后置字段对齐 |
| 3 | **选择器不进通用层**：产品选择器/检查点只在 Adapter |
| 4 | **样机诚实**：`backend:mock` / 诚实横幅 / 空态种子 ≠ 缺陷 |
| 5 | **可中止可去重**：步数上限、同指纹合并、循环检测 |
