# 为何单独成平面：AI Data

> **样机诚实**：现仓无数据湖、无标注平台、无语料版本仓。  
> **落地目标**：把「训推算力」与「训练数据真相」拆开，避免算法把案卷当语料桶、或把 ETL 塞进 ops。

## 1. 问题

用户口径覆盖整条大模型数据链：采集→解析→标准化→清洗→去重→过滤→数据集发布；预训练 / SFT / 偏好学习 / 评测数据；筛选配比采样；质量打分、敏感信息、污染检测、异常追踪；版本、元数据、血缘、处理记录；大规模分布式处理与存储布局、训练加载；与算法协作的评测→数据改进闭环。

这些能力：

- **不是** ops（可观测/配置/密钥）；  
- **不是** ai-infra（GPU/作业/模型权重发布）；  
- **不是** case-core（办案聚合）。

混放会导致：PII 泄漏进训练桶、血缘不可追、训推作业与数据版本脱钩。

## 2. 拆分原则

1. **`ai-data` ≠ `ops` ≠ `ai-infra` ≠ `case-core`**（硬）。  
2. 产品默认独立壳 `apps/ai-data` 端口 **5181**（并行样机；**不**改 `APP_PORTS`）。  
3. 发布契约：dataset version → ai-infra 消费。  
4. **禁** PatentCase 直写；仅脱敏导出。  
5. 样机诚实：无真 Spark / 湖仓 / PII 引擎。
