# 16 Bot 专家资产清单与养成闭环

> 配套：《patent-domain-pack-implementation.md》§1.5（能力实现原理）
> 本文档回答两个落地问题：**每个 bot 的四层资产具体是什么**（资产台账）、**能力如何持续变强**（养成闭环）。
> 定位：这是领域包的核心资产登记表——护城河不在代码（代码可抄），在表里的加工数据和回流机制。

---

## 1. 四资产模型速览

**专家能力 = 通用 LLM + ① SOP prompt + ② 领域 KB + ③ 确定性工具 + ④ validator**

- ① 告诉它**怎么干**（步骤、填法、红线）→ `prompts/<bot>.md`
- ② 告诉它**知道什么**（法条/判例/模板）→ `kb/`（断网进镜像，联网走 RAG）
- ③ 替它**算**（手艺固化成代码）→ `tools.py`
- ④ 替它**把关**（代码裁判）→ `rules/<bot>.py`

## 3. 逐 Bot 四资产清单（16 × 4）

### 阶段一 · 创新源头

**1. 行业分析师**
- ① SOP：技术分解→分面检索→聚类→趋势→空白点评分；结论必须挂数据，禁止越权建议
- ② KB：#1 法条库（法律状态判断）、行业市场数据源
- ③ 工具：patent_search*、cluster_analysis*、chart_render、空白点评分公式*（`gap_score`）
- ④ Validator：空白点清单 schema 固定列 + **评分与公式重算比对**（防编造数字）

**2. 竞争情报员**
- ① SOP：读竞对新公开全文→**撰写威胁分析**（技术路线判断、对己方布局的影响推演）→分级；告警必须附证据链接——分类是代码，**分析是 LLM**
- ② KB：#8 竞对清单、己方分类树
- ③ 工具：patent_search*、compare_layout*、notify；**cron 触发器**（与对话类 bot 唯一差异）
- ④ Validator：P0/P1/P2 分级规则=代码（P0=覆盖己方核心权项）

**3. 创新教练**
- ① SOP：TRIZ 重构→多方案生成（每空白点≥3）→冲突自检；**只产出不评价**
- ② KB：#6 TRIZ 库+领域映射
- ③ 工具：kb_query、write_file
- ④ Validator：方案四要素必填 + 替代方案≥2（`check_idea_package`）

**4. 专利挖掘师**
- ① SOP：特征树拆解→逐特征≥3 种替代实现→七问 checklist 逐项→三段式校验；不遗漏"用途"类保护
- ② KB：#2 驳回判例库（反向教学：什么点会被驳）
- ③ 工具：kb_query、patent_search*
- ④ Validator：挖掘七问强制流程 + 三段式 validator（技术问题-手段-效果）

**5. 布局策略师**
- ① SOP：分诊（核心/外围/防御公开）→时序（基础先于改进）→引用链建篱笆；防御公开必须说明"断谁的路"
- ② KB：#7 模板、各国申请费用/审查周期表
- ③ 工具：layout_canvas、kb_query
- ④ Validator：**引用图无环+全覆盖**（networkx）；公开时点规则

### 阶段二 · 申请中

**6. 立项评审**
- ① SOP：读初筛对比文件→**撰写区别特征分析**（最接近文件是什么、区别在哪、是否公知）→采集三轴证据→调评分工具；**分析判断是 LLM，打分是代码**
- ② KB：市场数据源（万得/企查查）
- ③ 工具：patent_search*、extract_evidence、**scoring_formula***（注册成工具，LLM 只交证据不碰数字）
- ④ Validator：评分卡 schema + 区间规则（≥75/<50/中间转人工）

**7. 交底书工程师**
- ① SOP：六段采集→缺项追问（一次一项、≤5 轮、工程师语言）→效果核验；**超限如实标注，禁止硬编**
- ② KB：#10 优质交底样例
- ③ 工具：docx_template、ask_inventor（追问交互）
- ④ Validator：六段必填 + 效果证据规则（`check_disclosure`）

**8. 查新检索员**（手艺最重的 bot）
- ① SOP：特征拆解（三段式）→检索式→初检→逐篇精读填映射表（每格引用段落号）；评级只调公式工具
- ② KB：**#4 同义词表、#5 检索式模板、#3 公知常识表**、#2 判例（公知性判断）
- ③ 工具：patent_search*、**检索式生成器***、risk_rating*
- ④ Validator：覆盖度检查器（自修复触发器）+ 映射表 schema

**9. 撰写代理人**（红线 bot）
- ① SOP：先布局权项层级（独权最小集+从权梯度）再成文；术语首现必定义；validator 错误逐条改不整篇重写
- ② KB：**#1 法条库+审查指南（打进断网镜像=合规卖点）**、#7 权项/说明书模板、#10 样例
- ③ 工具：docx_template、kb_query
- ④ Validator：**引用链完整性/支持性/单一性/清楚性**四类 + **超范围检查（blocker）**

**10. 附图工程师**
- ① SOP：按权项定附图类型→绘制→流程图与权项步骤一一对应
- ② KB：附图规范、#7 附图样例
- ③ 工具：drawing_tool、ocr_check
- ④ Validator：附图规范检查器 + **图注术语 ⊆ 权项术语**（差集报 Issue → feedback 回撰写）

**11. 流程管家**
- ① SOP：**读官方通知书原文**（受理/补正/审查意见，非结构化）→抽取期限事件→比对代码期限表→**起草客户沟通文书**→多案优先级排序；**文书与理解是 LLM，期限计算是代码**
- ② KB：**#9 期限表（代码常量）**
- ③ 工具：deadline_calc*、notify、file_package
- ④ Validator：期限计算与官方法定值比对（#17 专家核对后冻结版本）

**12. OA 答复代理**（流转最复杂 bot）
- ① SOP：拆解通知书→分类→分支路由→三案并列附成功率预估；**红线错误不自修复直接 escalate**
- ② KB：#1 审查指南、#2 复审决定判例、#4/#5 检索资产（补检用）
- ③ 工具：**理由分类器***、策略分叉矩阵*、patent_search*
- ④ Validator：**beyond_original_scope***（字面/等同依据）——代理行业生命线

### 阶段三 · 资产管理

**13. 年费管家**
- ① SOP：窗口计算→读价值分级+专利对应产品线→**撰写维持/放弃建议书**（给客户的 reasoning letter，含替代方案如放弃外围转防御公开）→HITL⑦
- ② KB：#9 期限表、缴费规则
- ③ 工具：deadline_calc*、annuity_query
- ④ Validator：建议规则（外围优化/低分放弃）+ 缴费金额比对

**14. 价值评估师**
- ① SOP：**读权利要求+产品资料做专利-产品映射分析**（引用性质解读：防御性还是侵权性）→指标采集→分级公式→**撰写分级说明报告**
- ② KB：#12 估值对标库（辅助）
- ③ 工具：citation_query*、family_query*、**grading_formula***
- ④ Validator：分级评分公式（代码）

**15. 转化顾问**
- ① SOP：估值（DCF/市场法）→交易结构（普通/排他/独占×地域×期限）→合同草案
- ② KB：#7 合同模板库（四类）、#12 估值对标
- ③ 工具：valuation*、contract_template
- ④ Validator：**合同必备条款**（标的/范围/对价/违约/分许可）

**16. 无效维权顾问**
- ① SOP：竞品扫描→全面覆盖比对（逐项映射、逐格附证据）→稳定性初筛→漏洞报告必须含可执行补局建议
- ② KB：#2 无效判例库、己方专利档案
- ③ 工具：**全面覆盖比对器***、stability_check*
- ④ Validator：比对表 schema（特征×产品映射，无 LLM 自由裁量）

> ③ 标注 * 的为确定性代码工具（手艺固化层）——16 个 bot 共 **23 个代码工具/公式**，是"代码做裁判"的全部落点。

## 4. 养成闭环（能力如何持续变强）

### 4.1 四条回流通道

```
        ┌─────────────── 能力资产（§2/§3）───────────────┐
        │                                                │
通道① HITL 签批语料                                        │
  代理人驳回理由 + 人工修改 diff                              │
  → 归因三层（prompt/KB/工具）→ 打补丁                        │
  度量：驳回率趋势（业务层）                                    │
通道② Golden Set 评测                                        │
  季度全量跑评测集 → 召回率/采纳率                             │
  → 未过门禁 → 阻断发版 → 强制归因整改                          │
  度量：任务层三指标                                           │
通道③ 一线结构化反馈                                          │
  队列批注自动结构化 → KB 补条目/validator 补规则               │
通道④ 优质产物沉淀                                            │
  一次过检的交付件 → 脱敏 → #10 样例库                        │
        │                                                │
        └──────── 反哺下一次执行（冷启动→越用越厚）──────────┘
```

### 4.2 迭代节奏

| 周期 | 动作 | 产物 |
|---|---|---|
| 周 | 一次过检率/成本看板 | 异常 bot 定位 |
| 月 | KB 更新（判例/同义词/竞对）+ 通道①③ 补丁 | kb/ 小版本 |
| 季 | Golden Set 全量评测 + 资产版本冻结 | **pack 小版本（门禁绑定）** |
| 半年 | 资产评估（哪些资产在增值）+ 检索式模板库评审 | 资产年报 |

### 4.3 发版门禁（能力质量的硬约束）

```
pack 发版 = 三指标全过门禁（召回率≥85% / 采纳率≥60% / 过检率≥70%）
        + 归因无遗留（每个失败样本都有三层归因记录）
        + 变更资产 diff 经维护责任人 review
```

### 4.4 护城河演化

| 资产 | 冷启动（现在） | 运行一年后 | 可复制性 |
|---|---|---|---|
| 法条/指南 | 公开下载整理 | 无变化 | 高（人人可得） |
| 判例标注 | 千级人工标注 | 万级 + 自动初标人工复核 | 中（半年追赶） |
| 同义词/检索式 | 专家存量手艺 | + HITL 回流补充 | **低（手艺+数据双壁垒）** |
| 样例库/Golden Set/签批语料 | 20-30 件种子 | 千级，含客户私有数据 | **极低（不可迁移）** |

**结论：护城河 = 23 个代码工具 + 12 项共享资产 + 四条回流通道。代码和公开资产决定下限（可用），回流通道和客户私有数据决定上限（越用越强）——对手抄得走文档，抄不走你跑了一年后沉淀的语料。**

## 5. Bot 资格审计（LLM 不可替代职责 · 防"退化成链路节点"）

判定标准：**一个 bot 必须存在至少一项"没有 LLM 就干不了"的判断职责**——纯代码能完成的环节（计算、定时、查表、格式校验）只能是它的兜底，不能是它的主体。否则它就是链路节点，不是 bot。

| # | Bot | LLM 不可替代职责（判断力所在） | 代码兜底（可替换实现） |
|---|---|---|---|
| 1 | 行业分析师 | 空白点的技术解读与趋势叙事 | 聚类、评分公式 |
| 2 | 竞争情报员 | 威胁分析：竞对技术路线推演、对己方布局影响判断 | P0/P1/P2 分级 |
| 3 | 创新教练 | 方案生成与冲突自检 | 四要素 schema 校验 |
| 4 | 专利挖掘师 | 替代实现方式枚举（可规避性洞察） | 七问流程强制、三段式校验 |
| 5 | 布局策略师 | 分诊判断、引用链篱笆设计、防御公开时机 | 引用图无环校验 |
| 6 | 立项评审 | 区别特征分析（最接近文件+公知性判断） | 三轴评分公式 |
| 7 | 交底书工程师 | 追问策略（判断缺什么、怎么问） | 六段必填校验 |
| 8 | 查新检索员 | 精读对比文件、特征映射判断 | 检索式生成、覆盖度、评级公式 |
| 9 | 撰写代理人 | 权项布局（保护范围策略）、成文 | 四类校验、超范围检查 |
| 10 | 附图工程师 | 附图类型决策、图面表达 | 规范与一致性校验 |
| 11 | 流程管家 | 通知书原文理解、期限事件抽取、客户沟通文书 | 期限计算、台账 |
| 12 | OA 答复代理 | 答复策略权衡（修改幅度 vs 授权前景） | 理由分类、超范围红线 |
| 13 | 年费管家 | 维持/放弃的商业 reasoning（替代方案设计） | 窗口计算 |
| 14 | 价值评估师 | 专利-产品映射、引用性质解读 | 分级公式 |
| 15 | 转化顾问 | 交易结构设计、条款权衡 | 估值公式、条款 validator |
| 16 | 无效维权顾问 | 侵权比对中"等同特征"的认定叙述 | 全面覆盖逐项映射 |

**审计结论：16/16 具备 bot 资格。** 其中 2/6/11/13/14 号曾因 SOP 写得偏代码而接近"链路节点"，本轮已把 LLM 职责补回（§3 ① 列）。F5-lite 中的"递交服务"是显式声明的降级项（实现文档 §8），全量版流程管家仍是 bot——降级是产品档位选择，不是设计漏洞。
