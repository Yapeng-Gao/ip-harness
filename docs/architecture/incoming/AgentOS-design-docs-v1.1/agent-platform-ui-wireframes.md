## 1. 信息架构

## 2. 设计规范（Design Tokens）

### 2.1 色彩

| 用途 | 色值 | 说明 |
|---|---|---|
| 主色 | `#4f6ef7` | 主按钮、激活态、链接 |
| 成功 | `#18a058` | done、签批通过、validator 0 issue |
| 警示 | `#e2a23b` | HITL 待办、驳回、预热池高水位 |
| 危险 | `#e05d5d` | 熔断、escalate、超范围红线、注入检出 |
| 紫 | `#8b5cf6` | 飞轮/AI 相关（F9、反向组队） |
| 青 | `#0ea5b7` | 检索类 bot、数据类视图 |
| 文本主/次 | `#1c2333` / `#6b7386` | — |
| 背景/卡片/线 | `#f4f6fb` / `#ffffff` / `#e6e9f2` | — |
| 侧栏底 | `#1b1f2e` | 导航深色 |

语义锁定：**红色只用于"需要人介入"**（熔断/红线/驳回），普通失败（validator 打回）用琥珀——界面扫一眼就知道哪里需要人。

### 2.2 字号与间距

- 页面标题 15/600；卡片标题 13.5；正文 13.5（行高 1.65）；辅助 12.5；说明 11.5
- 卡片圆角 12、内边距 16、卡片间距 14；控件圆角 8–10；芯片圆角 7–16
- 布局：侧栏 226px，顶栏 52px，内容区 padding 18/22；列表行高约 44

### 2.3 通用组件

Bot 卡（146px 宽：圆点+名称+沙箱策略一行）、Flow 卡（150px：阶段点+标题+说明）、Run 行（ID+名称+进度条+状态）、沙箱芯片（🧊ID+镜像+时长+销毁状态+产物去向）、信封代码块、时间线（左侧竖线+节点圆点）、状态徽标六态（done/run/wait/hitl/fb/esc）。

## 4. 逐视图线框

### 4.1 通用对话（Solo）

```
┌──────────────────────────────────────────────────────────────────┐
│ 消息流（滚动）                                                     │
│ [AI 头像32] 你好。我可以直接对话，也可以在需要时调用工具…            │
│                                          [张][蓝底气泡] 帮我画…    │
│ [AI] 已生成 React 原型并在沙箱渲染完成…                             │
│   ┌ 🧊 沙箱芯片：sbx-1042（img-proto）· 运行47s · ✔已销毁 · 产物归档 ┐│
│                                          [张] 我们要申请专利…      │
│ [AI] 识别为「新申请」，已升级 Run run-0093                          │
│   ┌ ⬆ Escalate 条（#fff7ec）：Solo → Run ────[进入流程模拟器→](主色)┐│
│ [技能条] 🔍检索 🎨画原型 💻Code 🧩Skill市场                       │
│ [输入框………………………………]                          [发送]              │
└──────────────────────────────────────────────────────────────────┘
```
组件逻辑：普通问答零沙箱；沙箱芯片四要素（ID+镜像/时长/销毁/产物去向）= 成本透明；Escalate 条 = Solo→Run 唯一入口；气泡 me 主色底。

### 4.2 团队模式（Team）

```
┌─ Leader 看板（渐变底）：任务标题 + 事件流（feedback红/report蓝/validator绿）─┐
├─ Worker 卡 ×N（栅格）：头像+名称+状态徽标 | 沙箱规格 | 产出清单 | 读取记录 ─┤
│   关键行："收到 feedback ×1 · 修订 v2" = 回环是协作而非错误                  │
├─ 共享 Workspace（文件树：归属人·时间·版本）───────────────────────────────┤
└─ 顶部团队选择器：团队▾ + 👑Leader/成员 chips + 协议 + [组建新团队] ─────────┘
```

### 4.3 专利工作台（Domain）

```
┌─ 三阶段 Flow 卡（F1–F9，HITL 角标悬浮）+ F9「→回流F3」飞轮标注 ────────┐
├─ Bot 花名册：16 卡（圆点色=沙箱类型：青=白名单/绿=断网/红=撰写红线）   │
│   点击 → 五层抽屉（规则层/流程层内循环/行为层/产物层/数据层）            │
├─ 运行实例：Run 行（点击 → 流程模拟器按 flow 载入：F5 五步 / OA 六步）   │
└────────────────────────────────────────────────────────────────────────┘
```

### 4.4 流程模拟器（Run 状态机可视化 · 核心视图）

```
┌─ 仪表带 4 格：当前步 x/N（N 随 flow 变 5/6）│ attempts x/3 │ iterations x/8 │ 状态四色 ─┐
├─────────────────────────────┬──────────────────────────────────────────────────────────┤
│ 步骤时间线（smrow 卡片）      │ 执行日志（暗色底/等宽/最新在底）                            │
│ ① 交底书工程师 [done 绿]     │ [时] 事件（着色：v蓝/ok绿/err红/hl紫）                     │
│  ↩ 红块回环（#fdf6f6 红左边条）│                                                          │
│   "自修复中：第1次打回·原地重跑"│ 📨 Handoff 信封面板（pre 等宽）                            │
│ ② 查新检索员 [●运行中 蓝边高亮]│  handoff:                                                │
│ ③ 撰写代理人 [pending 灰]    │   type: deliver | feedback                                │
│ …                            │   step / validator / feedback / audit                     │
│ 控制区（按 phase 渲染）：      │                                                          │
│  bot 态：[✓通过][✗打回自修复]  │ 🎛 剧本说明（当前 validator 规则+上限提示）                │
│  draft 态追加：[↩feedback回上游]│                                                          │
│  HITL 态：[✓签批→resume][↩驳回]│                                                          │
└─────────────────────────────┴──────────────────────────────────────────────────────────┘
```
关键交互语义：普通步打回 = 自修复（红块）；OA「超范围检查」步打回 = ⛔ 红线直接 escalate（不自修复）；iterations≥8 = 💥 熔断并自动移交兜底工作台。

### 4.5 签批队列（代理人）

```
┌─ 待签批 qitem 行：📄 [事项 600] [Run·等待时长 灰 flex1] [✓签批][忽略] ─┐
│ 来源：既有实例 + 流程模拟器实时产生（按 Run.id 关联，签批后该 Run resume）│
│ 文案红线：「无签批 = 产物禁止导出（系统强制，非提示）」常驻视图副标题      │
└──────────────────────────────────────────────────────────────────────────┘
```

### 4.6 兜底工作台（管理员）

```
┌─ resc 卡（红系底）：🚑 Run [熔断/escalate 原因红徽标] ──────────────────┐
│   现场摘要（产物+错误已归档）                                            │
│   [✍️ 人工修订产物→强制重跑 validator]（回到流程原步骤）                  │
│   [✖ 终止流程（通知租户·全程留档）]                                       │
├─ 接管手册：① 先看现场 ② 能修订就修订 ③ 修订不了就终止                     │
│   核心原则：绝不静默重跑（专利流程重跑有副作用，如重复递交）                │
└──────────────────────────────────────────────────────────────────────────┘
```

### 4.7 安全与评测

```
┌─ KPI 三卡：召回率/采纳率/过检率 + 门禁徽标（≥线绿 ✓ / 未达红）──────────┐
├─ 注入消毒时间线：untrusted 打标 → 检出隔离 → 消毒放行 → 白名单校验 ──────┤
└─ 评测回溯表：失败样本 → 归因三层（检索源/行为层/规则层）→ 整改状态 ───────┘
```

### 4.8 运行与审计

```
┌─ 预热池三桶进度条（solo-tools / team-workers / domain-patent）──────────┐
│   【设计待补】池耗尽 → 排队 → 抢占 的演示与界面                                          │
└─ 审计时间线：全平台共享插入（handoff/validator/签批/接管/熔断），最新在顶 ─┘
```

### 4.9 Bot 工坊（造 Bot · 四段表单 = 五层体现）

```
┌─ 左 四段表单 ──────────────────────────┬─ 右 实时预览卡（主色边高亮）─────┐
│ ① 岗位：名称 / 头像emoji / 一句话岗位   │ ┌───────────────────────────┐  │
│ ② 职责描述（textarea）：长期规则         │ │🔍 名称                    │  │
│   「怎么干」写这里，「本周干什么」发消息  │ │岗位一句话                  │  │
│   （铁律：Profile 与消息分离）          │ │模型·沙箱·规格·技能一行     │  │
│ ③ 能力装配：模型▾ 沙箱▾(断网/白名单)     │ └───────────────────────────┘  │
│   CPU/内存/步数 · 技能chips · KB chips  │ 保存 = bots/<名>.yaml          │
│ ④ 产物契约：模板▾ + validator chips     │ （= 实现文档 §5 装配格式）      │
│ [💾 保存 Bot]                           │                                │
└─────────────────────────────────────────┴────────────────────────────────┘
┌─ 我的 Bots 网格（预置 + 自建累加）────────────────────────────────────────┘
```
要点：描述 placeholder 硬编码审批红线（"未经签批绝不生成可递交文件"）——§13.1 合规红线的行为层落点。

### 4.10 组队中心（组团队）

```
┌─ ✨ 反向组队：业务描述[…………] [AI 帮我组队]                              │
│   → 建议阵容（Chief of Staff：👑大管家+专家）→ [采用此阵容]               │
├─ 手动组队（两栏）：                                                      │
│  左：👑 Leader 单选 chips │ 👷 成员多选 chips（来自我的 Bots）            │
│  右：📜 协作协议：☑共享Workspace(RWX) · 交接方式▾(@点名/信封) ·           │
│      对外动作▾(统一审批/按Profile边界) · ☑feedback 边                     │
│                                    [💾 创建团队]                        │
├─ 我的团队卡：名称 · 👑+成员 · 协议 · [进入团队→] ────────────────────────┘
```
要点：协作协议三件套 = 编排语义的用户可见配置（交接载体/交接协议/审批模式）。

## 5. 交互逻辑字典（界面动作 ↔ 引擎语义）

| 用户动作 | 界面反馈 | 引擎语义 | 技术出处 |
|---|---|---|---|
| 消息触发专利业务 | Escalate 条出现 | Solo→Run 升级 | 模式层设计 |
| 沙箱芯片显示运行秒数 | 递增 → 已销毁✓ | lease/release | Driver 四操作 |
| validator 打回（普通步） | attempts+1、红块回环 | 自修复转移 | §2 状态机 |
| validator 打回（OA 超范围步） | ⛔红线 + escalate 入兜底台 | blocker 不自修复 | 实现文档 §5-12 |
| feedback 回上游 | 跳步 + 信封 type:feedback | 回流转 iterations+1 | §3 信封协议 |
| 签批 | 队列-1、resume 日志、advance | awaiting_hitl→next | §4 hitl.py |
| 驳回 | 批注入信封、attempts 清零 | awaiting_hitl→retry | §4 hitl.py |
| iterations≥8 | 💥熔断横幅 + 兜底台任务 | 全局熔断 | §15.2 |
| 兜底「修订→重跑」 | 任务消失、审计+1 | 人工接管恢复 | §15.2 |
| 保存 Bot / 创建团队 | 网格+团队卡新增 | 生成装配 YAML / team 配置 | 实现文档 §5 |
| AI 反向组队 | 建议阵容 chips | 配置生成（非运行时） | 组队设计 |
