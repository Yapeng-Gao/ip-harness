## 0. 方法论：业务逻辑五层体现

| 层 | 内容 | 形态 |
|---|---|---|
| 规则层 | 公式 / 校验器 / 分类器 / 期限表 | **代码（裁判）** |
| 流程层 | 内循环 SOP / 分支 / 退出条件 | 编排脚本 / 状态机 |
| 行为层 | 人设 / 边界 / 追问策略 | system prompt（选手动作） |
| 产物层 | 模板 + Schema + validator | 契约文件 |
| 数据层 | 法条库 / TRIZ 库 / 模板库 / 判例库 | KB/RAG，断网 bot 打进镜像 |

铁律：**代码做裁判，LLM 做选手**；能写成 if/公式/校验器的绝不写进 prompt。

## 2. 编排执行状态机（flow 是带环图，不是直线）

```mermaid
stateDiagram-v2
    [*] --> Planning: 任务进入
    Planning --> Running: 领沙箱+启动bot
    Running --> Validating: bot 交付
    Validating --> Running: validator 失败（自修复, attempts++）
    Validating --> HumanReview: 产物过检 且步骤含 HITL
    Validating --> NextStep: 产物过检
    HumanReview --> Running: 驳回带批注（attempts++）
    HumanReview --> NextStep: 人工批准
    NextStep --> Running: 下游bot启动
    Running --> Feedback: 下游feedback信封
    Feedback --> Running: 退回上游bot
    state NextStep {
        [*] --> 下一步
        下一步 --> [*]
    }
    Running --> Suspended: pause() 挂起
    Suspended --> Running: resume() 恢复
    Running --> Failed: 超max_iterations / token预算 / deadline
    NextStep --> [*]: 流程结束
    Failed --> [*]: 转人工兜底
```

## 3. Handoff 信封（流转协议）

```yaml
handoff:
  id: ho-20260920-0007
  flow: 新申请
  step: 查新检索 → 撰写
  type: deliver | feedback        # 交付 or 退回
  from: 查新检索员
  to: 撰写代理人
  inputs: [检索报告v2.pdf, 特征映射表.xlsx]
  acceptance: 权利要求书草案v2    # 下游应交付什么
  feedback:                        # type=feedback 时必填
    reason: 特征F3缺乏最接近对比文件
    requested: 补充检索F3相关IPC小类
  audit: {timestamp, sandbox_id, validator_results}
```

### 阶段一 · 创新源头

#### 1. 行业分析师（F1）· 沙箱：白名单联网

- **职责**：技术全景与空白点识别
- **输入**：技术领域关键词 / 产品线 → **输出**：全景图、趋势报告、空白点清单（按价值排序）

```mermaid
flowchart TD
    A["领域关键词/产品线"] --> B["技术分解<br/>IPC/CPC 分类树"]
    B --> C["分面检索<br/>每个技术分支一批检索式"]
    C --> D["聚类 → 专利地图"]
    D --> E["趋势分析<br/>申请量/申请人/法律状态分布"]
    E --> F["空白点识别<br/>高价值技术点 × 低密度专利区"]
    F --> G{"空白点评分≥阈值?"}
    G -- "否" --> H["换分类面/调参数"] --> F
    G -- "是" --> I["Top-N 空白点清单 + 全景报告"]
```

- **规则层**：空白点评分 = 市场热度 × (1 − 专利密度) × 规避难度；聚类阈值；Top-N 截断
- **行为层**：只做事实分析，每个结论必须挂数据；不下"该不该做"的判断
- **产物层**：全景报告模板（固定章节）、空白点清单 schema（技术点/热度/密度/规避难度/评分）
- **数据层**：IPC/CPC 分类表、行业市场数据源

#### 2. 竞争情报员（F1/F9）· 沙箱：白名单联网

- **职责**：竞对监控与预警
- **输入**：竞对清单 → **输出**：预警（P0/P1/P2）+ 竞对布局分析

```mermaid
flowchart TD
    A["cron 定时触发"] --> B["拉取竞对新公开专利"]
    B --> C["技术归类<br/>落到己方分类树"]
    C --> D["与己方布局比对"]
    D --> E{"威胁等级?"}
    E -- "P0 覆盖己方核心专利" --> F["立即告警 → 通知无效维权顾问"]
    E -- "P1 进入己方空白点" --> G["进入周报 + 通知布局策略师"]
    E -- "P2 一般动态" --> H["存档进数据中台"]
```

- **规则层**：威胁分级规则（P0/P1/P2 定义）；比对规则代码
- **行为层**：归类时引用己方分类树标准术语；告警内容必须附证据链接
- **产物层**：预警模板、竞对雷达图模板
- **数据层**：竞对清单（配置）、己方分类树

#### 3. 创新教练（F2）· 沙箱：断网

- **职责**：从空白点/痛点产出技术方案
- **输入**：空白点清单 / 业务痛点 → **输出**：技术方案草案（多方案并列）

```mermaid
flowchart TD
    A["空白点/痛点"] --> B["问题重构<br/>TRIZ 40 发明原理/减法/反作用"]
    B --> C["多方案生成<br/>每个空白点≥3 方案"]
    C --> D["可行性自检<br/>与现有技术冲突初检"]
    D --> E{"存在致命冲突?"}
    E -- "是" --> F["标记冲突点 → 换原理再生成"] --> C
    E -- "否" --> G["方案草案包<br/>技术问题/方案/效果/替代方案枚举"]
```

- **规则层**：方案必填四要素；自检触发条件（关键词撞车表）
- **行为层**：发散约束——禁止评价方案好坏，只负责产生；每个方案附至少 2 个替代实现
- **产物层**：方案模板（四要素固定结构）
- **数据层**：TRIZ 原理库、本领域现有技术摘要库

#### 4. 专利挖掘师（F2）· 沙箱：白名单联网

- **职责**：从技术方案挖出全部可专利点
- **输入**：方案草案 → **输出**：可专利点清单（每方案 3–5 个保护点）

```mermaid
flowchart TD
    A["方案草案"] --> B["技术特征树拆解"]
    B --> C["逐特征问: 还有没有其他实现方式?<br/>可规避性枚举"]
    C --> D["保护客体枚举<br/>方法/装置/系统/介质/用途"]
    D --> E["挖掘七问 checklist<br/>省去/替换/反过来/组合/缩放/迁移/预处理"]
    E --> F{"三段式校验<br/>技术问题-手段-效果?"}
    F -- "否" --> C
    F -- "是" --> G["创新点排序<br/>可专利性×商业价值"]
    G --> H["可专利点清单"]
```

- **规则层**：挖掘七问 checklist（代码强制逐项执行）；三段式 validator
- **行为层**：每个特征至少给出 3 种替代实现才允许进下一步；不遗漏"用途"类保护
- **产物层**：可专利点 schema（技术问题/手段/效果/替代方案/客体类型/排序分）
- **数据层**：可专利性判例库（驳回案例反向教学）

#### 5. 布局策略师（F3）· 沙箱：断网 → 【HITL①】

- **职责**：把可专利点排成棋局
- **输入**：可专利点清单 + 全景图 → **输出**：布局方案（申请路线图）

```mermaid
flowchart TD
    A["可专利点清单 + 全景图"] --> B["分诊<br/>核心专利 / 外围专利 / 防御公开"]
    B --> C["申请时序排序<br/>基础申请先于改进申请, 防自我堵路"]
    C --> D["地域建议<br/>市场×竞对手×费用"]
    D --> E["引用链设计<br/>己方专利互相引用建篱笆"]
    E --> F{"引用图 validator<br/>无环 + 全覆盖?"}
    F -- "否" --> E
    F -- "是" --> G["布局画布 + 申请路线图"]
    G --> H{{"【HITL①】<br/>人审: 保护哪些/公开哪些/先后顺序"}}
    H -- "驳回" --> B
    H -- "批准" --> I["布局方案定稿 → 进入 F4"]
```

- **规则层**：引用链 validator（图无环且每个可专利点被覆盖）；公开时点规则（申请日 18 个月前禁止论文/展会公开）
- **行为层**：防御性公开的建议必须说明"断谁的路"；时序建议必须标注冲突风险
- **产物层**：布局画布模板（棋盘图）、申请路线图 schema
- **数据层**：各国申请费用/审查周期表

### 阶段二 · 申请中

#### 6. 立项评审（F4）· 沙箱：白名单联网 → 【HITL②】

- **职责**：三轴评分与申请建议
- **输入**：可专利点 + 检索初筛 → **输出**：评分卡

```mermaid
flowchart TD
    A["可专利点"] --> B["可专利性轴<br/>近似对比文件数 × 区别特征显著度"]
    A --> C["商业价值轴<br/>市场规模 × 对手规避成本"]
    A --> D["成本轴<br/>申请费 + 维持费现值 × 年限"]
    B --> E["三轴评分公式"]
    C --> E
    D --> E
    E --> F{"分数区间"}
    F -- "≥75" --> G["建议申请 → 进 F5"]
    F -- "50~75" --> H{{"【HITL②】转人工判断"}}
    F -- "<50" --> I["建议放弃 → 回流 F2 换方向"]
```

- **规则层**：评分公式代码化；阈值常量可配
- **行为层**：每个维度打分必须附证据来源
- **产物层**：评分卡模板（雷达图 + 文字依据）

#### 7. 交底书工程师（F5）· 沙箱：断网 → 【HITL③】

- **职责**：结构化交底书采集
- **输入**：技术方案 + 挖掘结果 → **输出**：交底书.docx

```mermaid
flowchart TD
    A["技术方案 + 可专利点"] --> B["六段式采集<br/>背景技术/现有缺陷/发明内容/实施方式/有益效果/附图说明"]
    B --> C{"六段必填 validator<br/>有缺项?"}
    C -- "是" --> D["追问发明人 ≤5 轮<br/>每轮只问缺的部分"]
    D --> B
    C -- "否" --> E["有益效果核验<br/>必须有数据或机理支撑"]
    E -- "不通过" --> D
    E -- "通过" --> F["交底书.docx"]
    F --> G{{"【HITL③】发明人确认"}}
    G -- "驳回带批注" --> B
    G -- "确认" --> H["交付查新检索员"]
```

- **规则层**：六段必填 validator；效果核验规则
- **行为层**：追问策略——一次只问一个缺项，用工程师语言不用法律语言；发明人说"大概"时要求具体参数
- **产物层**：交底书模板（六段固定结构）
- **数据层**：优质交底书样例库

#### 8. 查新检索员（F5/F6）· 沙箱：白名单联网 → 【HITL④】

- **职责**：支撑申请决策的检索报告
- **输入**：交底书（HITL③ 确认后）→ **输出**：检索报告 + 特征映射表

```mermaid
flowchart TD

    B --> C["检索式生成<br/>同义词扩展表=代码常量 + IPC/CPC"]
    C --> D["初检 + 相关度阈值过滤"]
    D --> E["逐篇精读<br/>填特征映射表"]
```

## 5. 跨 Bot 交互时序与 Loop 索引

> 单 bot 的内循环见 §4 各节点图；本节画**多个 bot 之间的多次交互**（sequence 时序），并给全系统 loop 的总索引。

### 5.1 F5 新申请 · 完整运行 trace（含 4 类 loop）

```mermaid
sequenceDiagram
    autonumber
    participant O as 编排器
    participant D as 交底书工程师
    participant S as 查新检索员
    participant W as 撰写代理人
    participant P as 附图工程师
    participant C as 流程管家
    participant H as 执业代理人(HITL)
    participant E as 兜底工作台

    O->>D: lease 沙箱 · 交底任务
    loop 内循环：六段采集+追问（≤5 轮，一次一项）
        D->>D: 缺项追问 → 六段 validator → 效果核验
    end
    D-->>O: deliver 交底书.docx
    O->>H: HITL③ 交底确认
    alt 驳回带批注
        H-->>O: feedback（批注）
        O->>D: 带批注重跑（HITL 循环）
        D-->>O: 再交付
    else 确认
        H-->>O: approved（执业证号入审计）
    end

    O->>S: handoff（交底书 → 查新任务）
    loop 内循环：覆盖度循环（检索→精读映射表）
        S->>S: 检索式生成 → 初检 → 逐篇精读
        alt 特征 F 无对比文件覆盖
            S->>S: 补检索式 · 同沙箱原地重跑（自修复）
        end
    end
    S-->>O: deliver 检索报告+映射表
    O->>H: HITL④ 查新结论确认
    H-->>O: approved / feedback（不乐观→回流 F2/F3 换方向）

    O->>W: handoff（交底+检索报告 → 撰写任务）
    loop 自修复循环：四类校验（≤3 次，逐条修订非重写）
        W->>W: 引用链/支持性/单一性/清楚性 validator
    end
    alt 自修复超 3 次
        O->>E: escalate（不静默重跑）
    else 通过
        W-->>O: deliver 权项+说明书
    end
    O->>H: HITL⑤ 权项确认
    H-->>O: approved

    O->>P: handoff（权项 → 附图任务）
    alt 图注术语与权项不一致
        P-->>O: feedback（差集清单）
        O->>W: 回流转：改术语（跨 bot 退回）
        W-->>O: 再交付 v2
        O->>P: 恢复附图
    end
    P-->>O: deliver 附图集
    O->>C: handoff（递交包）
    C-->>O: 受理归档 · 全程 handoff/validator/签批已落审计链
```
