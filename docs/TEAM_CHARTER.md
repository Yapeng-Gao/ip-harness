# 协作章程（总控编排 · 同级 Owner）

> 用户口径（2026-09-12）：bot **同级**；把项目按域分给不同 bot **协作到完成**；每个 bot **自己跟进、推动、回报总控**；总控再安排下一批。  
> **评审口径（2026-09-18 冻结）**：**不**给每个 Owner 配专属审核影子；按**风险挂评审席**（固定配对 + 共享席 + 总控抽验）。

## 角色

| 角色 | 谁 | 做什么 |
|------|-----|--------|
| 编排 / 验收 | 平台总控 | 对齐目标、派工边界、验收、仲裁冲突、必要时新建助手；决定升格评审席 |
| 领域 Owner | 各应用/专项助手 | 主动推进本域待办、自测、留档、**主动回报**总控（完成/阻塞/下一步） |
| 评审 | 见「评审分层」 | 对计划/文档/合入边界出通过或驳回；**不**替代 Owner 写实现 |

**没有父子 bot。** 需要扩编由总控新建并列助手。

## 评审分层（冻结）

| 层 | 名称 | 谁 | 何时 |
|----|------|-----|------|
| **A** | 固定配对 | e2e测试 ↔ e2e用例评审；架构设计 ↔ 架构评审；UI质感 ↔ UI评估 | **一直保留**；计划先评再写；大改可复评 |
| **B** | 共享评审席 | 业务深度审计 · 架构评审（兼） | 新壳 deep-demo、落地 MVP 实现合入前、跨壳契约、检索/训练落地边界扫 |
| **C** | 总控抽验 | 平台总控 | 薄壳改动、文案、单文件修；Owner 自测清单 + 总控验收即可 |
| **D** | 临席（少用） | 总控临时新建「××评审」 | 仅当某域连续翻车，或进入生产级真 API/真训且现有席不够 |

### 域 → 默认评审席

| 域 / Owner 类型 | 默认 | 说明 |
|-----------------|------|------|
| e2e 实现 | **A** | 计划必须先过 e2e用例评审再写 spec |
| 架构文档 | **A** | 规格包过架构评审 |
| UI 质感实现 | **A** | 大波先 UI评估出带验收标准的 REVIEW |
| 产品壳（mid/wb/agent/ops/iam/search/fto/…） | **C** | 可点清单自测 + 总控验收；跨 3+ 壳或深业务升 **B** |
| 落地实现（检索落地、猎虫、日后 SFT 流水线） | **B** | 规格已 A 评过的，**实现合入前**再轻扫边界（APP_PORTS、诚实 backend、不碰 L0） |
| 共享包 / 接口样机 | **C**，契约大改升 **B** | 契约冲突报总控 |
| 业务深度审计 | 本身是 **B 席** | 可被总控派去评他域，不抢 apps/ops 实现 |

**禁止**：为每个 Owner 自动创建一对一「××评审」助手。

## Owner 工作法（硬）

1. **主动跟进**：本域有缺口就推；阻塞立刻报总控（缺端口、越界、等评审）。
2. **回报格式**：完成了什么 / 留档路径 / 怎么验 / 阻塞 / 建议下一步。
3. **设计留档**：凡设计落 `docs/`；禁止只口头。
4. **样机口径**：有设计示意即可时不接真后端；诚实空态。
5. **不越界**：不改他域 `apps/*`；契约冲突报总控仲裁。
6. **收工**：验收通过后待命，持续盯本域回归。
7. **对评审**：属 A/B 的域，计划/规格未 Pass 不写大实现；合入前按默认席请求轻扫或总控代排。

## 总控工作法

- 收回报 → 验收或打回 → 派下一刀或新建助手。
- 跨域冲突只在总控拍板。
- 用户一句话目标 → 拆成 Owner 责任，不替 Owner 写业务大页。
- **升格评审**：连续翻车或进生产级 → 才考虑 D 临席；默认不加影子助手。
