# 协作章程（总控编排 · 同级 Owner）

> 用户口径（2026-09-12）：bot **同级**；把项目按域分给不同 bot **协作到完成**；每个 bot **自己跟进、推动、回报总控**；总控再安排下一批。

## 角色

| 角色 | 谁 | 做什么 |
|------|-----|--------|
| 编排 / 验收 | 平台总控 | 对齐目标、派工边界、验收、仲裁冲突、必要时新建助手 |
| 领域 Owner | 各应用/专项助手 | 主动推进本域待办、自测、留档、**主动回报**总控（完成/阻塞/下一步） |
| 评审 | e2e用例评审、架构评审 | 对计划/文档出通过或驳回；不替代 Owner 写实现 |

**没有父子 bot。** 需要扩编由总控新建并列助手。

## Owner 工作法（硬）

1. **主动跟进**：本域有缺口就推，不必等用户每句催；阻塞立刻报总控（缺端口、越界、等评审）。
2. **回报格式**（给总控）：完成了什么 / 留档路径 / 怎么验 / 阻塞 / 建议下一步。
3. **设计留档**：凡设计落 `docs/`（架构进 `docs/architecture/`）；禁止只口头。
4. **样机口径**：有设计示意即可时不接真后端；诚实空态。
5. **不越界**：不改他域 `apps/*`；契约冲突报总控仲裁。
6. **收工**：本单验收通过后待命，但持续盯本域回归（如 e2e 绿、文档索引不断链）。

## 总控工作法

- 收回报 → 验收或打回 → 派下一刀或新建助手。
- 跨域冲突只在总控拍板。
- 用户一句话目标 → 拆成 Owner 责任，不替 Owner 写业务大页。
