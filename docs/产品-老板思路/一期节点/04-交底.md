# ④ 交底（交底书）

> 老板「交底过得硬」／系统名「成稿」。  
> **产品真源**：[`交底书撰写/`](../../各产品开发/交底书撰写/)、[`腾讯交底书完善/`](../../各产品开发/腾讯交底书完善/)、[`评估工作台/`](../../各产品开发/评估工作台/)。  
> **老板册**：总纲 §3.4；保障计划交底诊断合格项；代理所册节点④。  
> **产品逻辑（方向可冻）**：[../一期-产品逻辑/04-交底.md](../一期-产品逻辑/04-交底.md)；进部门前见 [接待与分诊](../一期-产品逻辑/01-接待与分诊.md)。  
> 两段：**发明人成稿** + **企业 IP 审核**（有岗走、无岗可跳过）→ 再交代理（[05](05-申请.md)）。

---

## 0. 老板册对齐（一眼）

| 项 | 口径 |
|---|---|
| **系统** | 「成稿」陪写 + 质检；**检测全绿**才算合格 |
| **顾问交付** | 《交底书质量诊断报告》+ 问题清单（专家签字；标准 2 次/年、旗舰 5 次） |
| **免费质检** | 可作获客入口（系统检测，代理可不介入） |
| **本步不做** | 不写申请文件；不终裁申不申；不代替⑤接案理解对齐 |
| **往下流** | 定稿交底 → ⑤；诊断数据可回流检测模型（规划） |

---

## 1. 这步干什么

**先把技术事实写成交底，有企业 IP 岗再审一审，然后才交给代理办案。**  
这里不写申请文件，也不终裁「要不要申请」。

```
③ 挖掘（可有可无）
    ↓
发明人 0→1 写交底并本人确认
    ↓
有 IP 岗：齐套/合规/批准；无岗：跳过
    ↓
交给代理开案 → 理解对齐 → 查新/决策 → 写申请 → 递交
```

手里有技术线索就能开（挖掘来的点，或发明人自己带的）。干完：交底成稿且发明人确认过；有 IP 岗还要审过（或明示条件放行）。代理深度追问、正式查新、申不申、写申请文件——开案后在 05。

---

## 2. 给谁用

发明人不会写也能从 0 起步，最后本人确认「事实是我说的」。  
有企业 IP 岗时，空壳交底别往外推，权属和公开时点要过一眼；批准交底不等于批准申请。  
没内部 IP 编制的，审核整段跳过，成稿后直接交代理（代理在 05 再审）。  
代理接案要的是：事实有人认过的交底，领域和缺项看得见，别靠口头补故事。

## 3. 两段怎么走（B 方案）

```
┌──────────────────────────────────────────────┐
│  ④ 交底                                      │
│                                              │
│  【④-a 发明人成稿】                           │
│     0→1 写 + 发明人确认                       │
│     ↓ 可选                                    │
│     轻量查新 → 【1+】按检索结果改交底书         │
│                                              │
│  【④-b 企业 IPR 审核】← 独立小节              │
│     有岗：审核 → 退回 ④-a / 批准交底包         │
│     无岗：跳过，交卷进 05                      │
└──────────────────────────────────────────────┘
```

| 段 | 谁主场 | 说明 |
|---|---|---|
| **④-a 成稿** | 发明人 | 必有；可含可选 **1+**（查新后改稿） |
| **④-a 内可选：查新→1+** | 发明人 / 企业 IP 辅助 | **能做、非必经**；用来改交底，不是终裁申不申 |
| **④-b IPR 审核** | 企业 IPR/IP | **有编制则走；无编制则跳过**（中小企业常见） |

## 4. 怎么写成稿

> 撰写资产：[`交底书提示词`](../../各产品开发/交底书撰写/交底书提示词/)（录入→提纲→初版）、[`交底书优化-常总`](../../各产品开发/交底书撰写/交底书优化-常总26.2假期改.docx)。借鉴流程与纪律，不照搬工程步骤当唯一 UI。

### 4.1 成稿主线（0→1）

| 项 | 说明 |
|---|---|
| **目标** | 第一版交底 + **发明人确认** |
| **真人逻辑** | 材料进场 → 问清问题/方案/效果/例子 → 落成正文 → 本人确认 |
| **人必须** | 答真事；确认；不编数据/公开号 |
| **AI 可** | 提取字段、追问缺项、据人答起草；**缺失保持空，禁止补造** |
| **成功** | 可交 ④-b、可进可选 1+、或（无 IPR）可交代理 |
| **失败** | 一键生成无人确认；空字段被模型填满装齐套 |

**交卷物核心：** 技术问题、技术方案、有益效果 + 确认留痕。可扩六项：名称、领域、问题、方案、关键特征、效果（细则见 lifecycle 00）。

**产品里大致对应：** 内容录入（文档/会议/图→结构化字段，保留部件号/符号/参数）→ 可选要点提纲 → 按章生成初版（守章节边界）→ 可选润色/评分/对照或喂 1+。

### 4.2 章节边界（成稿规矩）

| 章节 | 要写 | 禁止 |
|---|---|---|
| **背景** | 相关现有情况与需求铺垫 | **泄露发明点**；过度展开成技术启示；未公开内部资料当现有技术 |
| **技术问题** | 现有缺陷/待解决事项（原文可核） | 把目标、用途、效果口号改写成「问题」 |
| **技术方案** | 怎么实现（装置：部件—连接—功能；方法：步骤—顺序—条件；系统：模块—交互—数据流） | 夸张宣传；只有功能/结果没有手段 |
| **有益效果** | 由方案可推导的效果；能量化更好 | 空泛「体验更好」；编造数据 |
| **实施方式** | 可复现的例子/参数/路径 | 「如图所示」空壳；发明人没说过的细节 |

**术语：** 同一对象前后一名；别称须能回溯；冲突术语不得擅自统一成「好像清楚」。

### 4.3 分领域成稿清单（一期就要有）

开写前选定领域模板（电学_通用 / 机电 / 化学…）。代理侧更全见 [05 §6.3–6.4](05-申请.md)。

| 域 | 成稿必追问（摘要） | 成稿就该有的图/式/数据 |
|---|---|---|
| **电学 / 软件偏电** | 模块谁连谁、信号/数据流、关键步骤输入输出、和现有方案差在哪 | 框图/流程图；关键界面或时序草图（可糙） |
| **机械 / 机电** | 零件与装配、怎么动、核心结构是不是发明点、工况 | 结构/装配草图；关键尺寸量级 |
| **化学 / 生物医药** | 组成或通式、步骤与条件、效果怎么证明、对照有没有 | 结构式/通式或工艺草图；**效果数据/表**（无数据须标明缺失，不编） |
| **交叉（如药械）** | 主领域 + 勾选附加项 | 结构图 + 数据，两套都要意识 |

**图 / 公式：** 发明人供原料并确认；禁 AI 编曲线/结构式/序列；申请用图整理在 05。

### 4.4 优化与可选 1+（查新后改稿）

对应老「优化」：敢改、可对照、可回退。**不是必经**；无检索也可交 ④-b / 交代理。

**优化交互（常总优化底稿）：** 候选不覆盖正文（采纳才进稳定版）；任一稳定版可回退；采纳后其他段不连环改写（只出联动待办）；对照卡含变化点/收益/联动影响/影响等级；区分原始事实 / 推导概括 / 泛化表述。

**查新 + 原始素材 → 审核并完善交底（可选 1+）**  
报告怎么生成见 **[接口-查新.md](接口-查新.md)**。完善手法：[`腾讯交底书完善/系统二`](../../各产品开发/腾讯交底书完善/提示词/系统二%20辅助完善提示词.docx)（场景6 新创强化 + 场景1–5/3A/3B 质检完善）。[`系统一`](../../各产品开发/腾讯交底书完善/提示词/系统一%20真实使用提示词.docx) 是从原始素材 **0→1 成稿**，落 §4.1，不与本段混岗。

**三份材料、三种职责：**

| 材料 | 职责 | 禁止 |
|---|---|---|
| **查新报告** | 定攻击点：新颖性/创造性风险、区别特征、公开关系、否定理由与评价路径 | 脱离报告另开检索或另评现有技术 |
| **技术交底书** | **唯一修改对象**；改前须回查**全文**（某章没写≠事实缺失） | 把公知/已公开内容继续当主创新点硬吹 |
| **原始研发/技术素材** | 仅补「交底与报告都没写清、但材料已明确披露」的真实事实 | 从素材主动挖新创新点；按缺陷倒推新方案；用常识补造 |

**统一路径：** 查新报告定攻击点 → 定位交底原文 → **优先回查交底全文** → 必要时查原始素材 → 判断能否形成有效区别 → 输出**可直接替换**的改文（或嵌 `【待补：具体缺失】`）→ **发明人确认采纳**。

**读报告（场景6）：** 发明要点（确认评的是哪套方案）；新颖性评述（**单篇**对比，不得组合文献重评）；创造性评述（最接近现有技术→区别特征→实际问题→显而易见理由）；特征对比表只核对已识别攻击点；检索策略/专利列表附录**不作**修改判断的独立证据。

**特征状态（改稿时用）：** `[公知]` / `[公开]` / `[部分公开]` / `[差异]` — 不得仅因名称、场景、装饰、尺寸或效果形容词不同就认定实质差异。

**新创向问题类型（只出实质项）：** 新颖性支撑不足（把材料已有、单篇未公开的结构/顺序/条件/规则写清）；区别限定缺失（嵌 `【待补：…】`，**不设计新方案**）；区别特征不显著（强化已有输入—处理—输出、依赖、反馈、确定规则）；创造性支撑不足（只写材料已有的实现/组合/机制；禁造协同或「预料不到」数据）；创新点错位（公知/公开降级，真实限定抬为重点）；组合关系不足（仅材料已披露依赖/传递/联动时才写技术链）；效果关联不足（仅材料有机制/测试时写「特征→机制→问题→效果」）。

**完善纪律（系统二上位）：** 其他材料已披露→忠实补入；全未披露的必要硬事实→禁止编造，用 `【待补：具体内容】`；只出对理解/可实施/创新支撑有实质影响的问题；每条意见：问题类型 · 修改理由 · 分析依据 · 改后文本 · 原文定位。**完善交底 ≠ 决定申请。**

同包可复用：场景1 脱敏与表述 · 场景2 问题—方案—效果闭环 · 场景3/3A/3B 充分公开与实施例/材料差集 · 场景4 代码接口参数 · 场景5 图文公式一致 · 场景7 特征抓取。

| 项 | 说明 |
|---|---|
| **谁认** | 发明人认事实与是否采纳；IPR 可协审不可代改已确认事实 |
| **成功** | 修订版交底 + 改动能指回报告/素材；待补项对人可见 |
| **失败** | 脱离报告另评；编造区别；无人确认；把完善当成已决定申请 |

**质量评分（辅助，非批准）：** 老「打分」作**缺项雷达**——背景/问题是否具体、方案是否可实施、效果能否由方案推导；评语落到原文 + 修改方向，不代填假数据。

### 4.5 这一步的查新 vs 开案后的正式查新

| | **④ 可选查新（喂 1+）** | **05 正式查新（喂决策/撰写）** |
|---|---|---|
| **何时** | 成稿中/交代理前 | 代理接案理解之后、开写前 |
| **为谁** | 把**交底书**改好 | 判能不能申、怎么写**申请文件** |
| **厚度** | 常轻量；可跳过 | 可正式鉴新；可弱可跳，跳过认风险 |
| **出口** | 修订交底 → 再 ④-b 或交卷 | Go/No-Go、类型；再进撰写 |

## 5. 企业 IP 怎么审（有岗 / 无岗）

> 对齐 lifecycle 00：交底完成常含 **IPR 批准交底包**；申不申仍在 05。  
> 审核资产：[`评估工作台/拼接好完整提示词-交底书审核`](../../各产品开发/评估工作台/拼接好完整提示词-交底书审核.docx)。

### 5.1 审核分析纪律

| 纪律 | 说明 |
|---|---|
| **中立解析先行** | 先抽结构、标缺失；本步不出抗辩策略、不补外部常识当事实 |
| **有根可回溯** | 结论须有原文依据；引用须一字不差连续原文；未记载写「交底书未明确记载」 |
| **问题≠目标≠效果** | 不得把用途/效果口号改写成技术问题；不得把抽象功能当完整技术手段 |
| **六项独立识别** | 名称、领域、问题、方案、关键特征、效果——**一项有不能推定其他项成立** |
| **装置/方法/系统分型** | 同 §4.2 结构展开方式 |

### 5.2 发明构思拆解（审核核心）

把交底拆成若干组 **问题—方案—效果**（非普通摘要）：

| 单元 | 怎么判 |
|---|---|
| **主要发明构思** | 先定**主要技术问题** → 反提解决该问题所必需的**最小技术特征集合**作主要方案 → 主要效果须由该方案直接产生 |
| **次要/附加构思** | 主要方案之外的附加特征；各对应次要问题 + 附加效果 |
| **删除测试** | 删掉某特征后主要问题仍能解决 → 该特征**不应进主要方案**，宜作附加 |
| **禁止** | 把所有特征堆进主要方案；空泛效果无依据；编造未记载内容 |

输出用于：齐套判断、退回补什么、交给 05 的发明点映射原料（**05 写独权时再圈地**，此处不写权项）。

### 5.3 专利属性门槛（预检标签）

是否达到「能当专利交底往下谈」的基础门槛；标签固定：`技术问题不清` / `技术手段不清` / `技术效果不清` / `对应关系断裂` / `多要素缺失` / `表达抽象或空泛` / `暂无明显问题`。另可跑：核心逻辑是否可理解、结构栏目是否齐、特征拆解、附图/术语表、完整性。**新颖性/创造性深析**若做，须有查新材料，且**不得靠补造事实抬信息量**——深度结论建议挂 05（尤其无企业 IPR、或已开案时）。

### 5.4 有岗时

| 项 | 说明 |
|---|---|
| **谁** | 企业 IPR / IP（或明确授权审核人） |
| **审什么** | 上列解析 + 齐套；权属/署名/公开时点合规；空壳/不可核验；是否值得交代理的**建议**（≠ Go） |
| **出口** | 退回 ④-a / 批准（可附条件）+ 建议往下 |
| **人必须** | 批准/退回认领；不得代改已确认事实、不得代加发明人 |
| **AI 可** | 六项抽取、发明构思拆解、缺项清单、评分雷达（结论须人认） |
| **失败** | 未审装批；建议写成「已决定申请」；无依据空评 |

离职未满一年、外部合作、权属未决等 → 法务会签意识（lifecycle 00）。

### 5.5 无岗时

**默认跳过 ④-b**，④-a 确认后交卷进 05。产品配置「有无 IPR 岗」，跳过须可见。评估工作台类能力在 **05 接案**变厚。

### 5.6 和「评估工作台」怎么分

| | **④-b 企业 IPR** | **05 接案 / 评估工作台** |
|---|---|---|
| 身份 | 企业内部审核 | 代理开案后审核 |
| 何时 | 交代理**前**（有岗） | 开案**后** |
| 手法 | 可共用解析/构思/缺项提示词 | 同样资产，服务代理理解确认与放行 |
| 无岗 | 跳过 | 必有（代理侧） |

**按谁审、何时审归属，不按工具名归属。**

## 6. 交出去是什么、跟申请怎么接

**四条业务底线：** ④-a 无发明人确认不得进 ④-b / 不得交代理装完成；配置了 IPR 岗则未批准不得交代理（除非显式特批）；无岗跳过 ④-b 合法且须标明；**IPR 批准交底 ≠ 要不要申请**（那是 05 决策）。

### 6.1 上游 ← ③ 挖掘

| 项 | 说明 |
|---|---|
| **③ 交出** | 建议申请的创新点（可含去向建议、粗证据）；不是齐套交底 |
| **④ 接收** | 以「点」开 ④-a；发明人仍须走成稿确认 |
| **没有 ③** | 允许：发明人直接带着技术线索进 ④-a（中小企业常见） |
| **勿混** | 挖掘报告 ≠ 交底书；不得把挖掘四步当成交底已完成 |

### 6.2 ④-a → ④-b → 交卷 → 05

| 从 → 到 | 必须带上 |
|---|---|
| ④-a → ④-b | 发明人已确认交底；领域；缺项清单（含图/式/数据）；若做了可选查新→改稿依据 |
| ④-b → 交卷 | IPR 批准（或条件批准）留痕；或配置为无岗并**显式跳过**标记 |
| → **05 开案** | 交底包终稿；确认/批准或跳过留痕；委托人与发明人信息；领域；已知附件（图草/数据表）；委托范围（若已定） |

### 6.3 开案后与回流

进 05 后：理解确认、正式查新、权项说明书都在 05，不算 04 未完成。IPR 退回 → 回 ④-a。代理已开案要补事实 → 优先在 **05 接案线程**补；大改交底也可回写 04 文档对象，**节点归属仍是 05 案子**。

**04 不做：** 代理人接案五问 / 深度追问 / 代理侧评估工作台；正式查新 + 申请决策 Go、写申请文件、递交（04 只允许**可选轻量查新喂 1+ 改交底**）；无 IPR 岗却强制走企业审核墙；把可选查新做成必经步骤。

## 7. 怎样算够用

### 7.1 场景验收（S1–S3）

| ID | 画像 | 路径 | 通过标准 |
|---|---|---|---|
| **S1** | 有 IPR 的中大企业 | ④-a 成稿（±可选查新 1+）→ **④-b 必审** → 交卷 05 | 有发明人确认 + IPR 批准/退回留痕；建议未写成「已决定申请」 |
| **S2** | 无 IPR 的中小企业 | ④-a 确认 → **跳过 ④-b** → 交卷 05 | 跳过可见；不假装已批准；质量期望交给 05 接案 |
| **S3** | 生物医药 / 重数据 | ④-a 用生医清单要通式/条件/**效果数据**；缺数据标缺失不编 → ±④-b → 05 | 数据真伪有人认；无数据未装「齐套可写宽通式」 |

三场景都要能演示：**无人确认不能交卷**。

### 7.2 一期做透 / 可薄

| 分档 | 内容 |
|---|---|
| **做透** | 录入→成稿章节边界；发明人确认；领域模板；有岗 ④-b（六项+发明构思删除测试+门槛标签）/ 无岗跳过；交接物齐 |
| **建议同期有** | 可选查新→靶向 1+；优化候选/回退纪律；评分作缺项雷达；图/式/数据缺项 |
| **可薄 / 后置** | 专家签字级全套评估（新颖性/创造性深析可放到 05）；制图引擎；多语言 |

### 7.3 成功 / 失败（摘要）

| 段 | 成功 |
|---|---|
| **④-a** | 已确认交底；领域清单该问的问到；图/式/数据缺失可见 |
| **④-b 有岗** | IPR 批准或明确退回；建议 ≠ 申请决议 |
| **④-b 无岗** | 正确跳过并交卷 |
| **交接** | 05 能凭交接物开案，不靠口头回忆 |
| **失败** | 无人确认；有岗未审装批；把 05 接案当成 ④-b |
