# ② 创新激发

> 老板「研发有思路 / 创见」。一期**可薄**；**整段可跳过**，不挡交底→申请。  
> **产品逻辑**：[../一期-产品逻辑/03-创新激发.md](../一期-产品逻辑/03-创新激发.md)（讨论稿 · 首开）  
> **产品真源（业务流程）**：[`各产品开发/创新激发/`](../../各产品开发/创新激发/)（问题→路径→方案→专利启发；提示词 AI-01～04）。  
> **可选上游种子**：旗舰报告里的「低密度 × 在研」——那是报告侧用**检索式**按业务线检本公司/竞对专利、看疏密之后写出的挂钩，**不是**本步主流程（见 [接口-创新报告](接口-创新报告.md)）。

---

## 1. 这步干什么 · 为什么有

研发卡壳时：从**一个技术问题**出发，摊开可比较的技术路径，必要时参考专利，收成可收藏的思路/方案——**不谈申不申、能不能授权**。

**为什么单列：** 解决的是**方向/路径不够**，不是「立哪条」（①），也不是「已有成果怎么拆」（③），更不是跑赛道检索出三图（那是创新报告）。

```
【本步主流程 · 创见】
问题（文本/语音）
  → 问题结构化（AI-01）
  → 多技术路径 + 推荐一条（AI-02）
  →（可选）按路径查相似专利  ← 检索动作，挂在路径上，不是全景三图
  → 解决方案文（AI-03） / 单篇专利解读（AI-04）
  → 人编辑、收藏进成果库
  → 可去③挖，或直接④写交底

【可跳过】方向已明 → 不进②，主链照常
【可选种子】报告命题 / 一句问题 都能当入口；无报告也能冷启动
```

---

## 2. 给谁用

| 角色 | 干什么 |
|---|---|
| **企业研发** | **主用户**：提问题、选路径、认方案、收藏 |
| **技术管理 / 产品** | 看路径是否可推进、风险与边界 |
| **顾问** | 可带工坊；思路建议书须人认 |
| **代理人** | 答疑为主；**不替研发拍最终方向**；不在这里拆案 |

和③相反：③代理人主操；②研发自助。

## 3. 业务流程（主链）

### 3.1 端到端

| 步 | 谁 | 做什么 | 产出 |
|---|---|---|---|
| 1 输入问题 | 研发 | 文本或语音描述技术问题 | 问题原文 |
| 2 结构化分析 | 系统 AI-01 | 对象—作用—目标—约束—矛盾等 | 结构化问题分析 |
| 3 技术路径 | 系统 AI-02 | 生成多条路径，**只推荐一条** | 路径卡 + 问题三元组 |
| 4 人选题 | 研发 | 选要推进的路径（可改推荐） | 已选路径 |
| 5 相似专利（可选） | 系统检索 | 按路径关键词查相似专利 | 专利列表（非 LLM 主责） |
| 6 方案 / 解读 | AI-03 / AI-04 | 七章方案文；或对单篇专利做问题向解读 | 方案稿 / 解读稿 |
| 7 编辑与沉淀 | 研发 | 改稿、存成果库、导出/分享 | 收藏成果 |
| 8 交接 | 人 | 定去向：送③挖掘 / ④交底 / 仅留存 | 去向意图 |

**一期轻跑：** 1→3→7 即可（有几条方向并收藏）；4～6 可后做。

### 3.2 别和「创新报告的专利检索」搅在一起

| | **② 创新激发（本步）** | **创新报告** |
|---|---|---|
| 起点 | **一个研发问题** | 本公司**业务线** + 竞对名单 |
| 手段 | 问题分析 → 路径 → 方案（路径上可附带相似专利查询） | 构造**检索式**，检赛道/本公司/竞对专利 → 建树 → **三图** → 可选写稿 |
| 「低密度×在研」 | 最多当**可选问题种子** | 检索看疏密、叠在研之后，报告写给②的挂钩 |
| 主操 | 研发 | 顾问建档与交付；检索式决定命中 |

服务包说「②从报告取低密度×在研」——是报告挂钩，不是创见里重跑一遍业务线检索。

## 4. 规则清单

### 4.1 流程与边界

1. 主链是**问题驱动**，不是「先跑全景检索再激发」。  
2. 整段可跳过；跳过须能续交底。  
3. 相似专利检索挂在**已选/候选路径**上，≠ 旗舰三图，≠ ⑤正式查新终局。  
4. 图2-4 落点矩阵主喂①③，**不是**本步主输入。  
5. 代理人不在本步拆案、不定保护去向、不拍单案申不申。

### 4.2 会话红线（AI-01～04）

**全局**

6. 严格依托输入；事实与推断分开；信息不足只做审慎分析。  
7. **禁止虚构**专利号、图片、实验数据、权利人、标准号、型号、无依据精确数值。  
8. 禁止营销口号、「大概可以」替结论；禁止直接写成齐套交底/申请文件。  
9. 校验卡保留；结构稳定可靠运行时，业务红线以提示词为准。

**AI-01 问题分析**

10. 覆盖对象—作用—目标—约束—异常—已知前提。  
11. 按约定分析单元出齐；落地方向要有机制与着力点。  
12. 产出 ≠ 交底、≠ 权要。

**AI-02 技术路径**

13. 多路径须彼此独立；同家族机制拉不开就合并。  
14. 每条含原理、动作链、抓手、边界、优劣、检索关键词、风险缓解。  
15. **仅推荐一条**；理由覆盖匹配度/成本/复杂度/副作用/验证等。  
16. 无真实专利/图输入时相关字段必须空，禁止编造。  
17. 输出问题三元组供 AI-03，不得写成行业口号。

**AI-03 解决方案**

18. 输入含已选路径 + 三元组 +（可选）参考专利；**不得偷换未选机制**。  
19. 七章顺序固定；结构章与工程章禁止换皮重复。  
20. 无精确输入时禁止瞎编尺寸/温度/寿命等；改用相对约束与验证门槛。  
21. 参考专利只能引真实输入；支撑有限须标明启发级别。

**AI-04 专利解读**

22. 面向**当前问题**写异同、边界、不可迁移点。  
23. 建议分层：直接借鉴 / 局部吸收 / 思路参考 / 风险对照。  
24. ≠ 查新终局、≠ 可授权；文本不足则审慎、不强结论。

### 4.3 人必须做

25. 选路径、认方案主线、收藏或记跳过原因。  
26. 定去向意图（挖 / 交底 / 留存）。  
27. 若用了报告命题：确认在研是否属实（报告灰框项）。  
28. 思路建议书对外须人认。

## 5. 产出

| 产出 | 说明 |
|---|---|
| 结构化问题分析 | AI-01 |
| 技术路径卡（含推荐） | AI-02 |
| 解决方案文 | AI-03；可编辑 |
| 专利问题向解读 | AI-04 |
| 成果库条目 | 收藏/标签/导出 |
| （可选）思路建议书 | 人认后可交 |

**不是：** 三图、旗舰报告正文、创新点清单、拆案排案、查新终局、可授权结论、FTO。

## 6. 跟前后怎么接

| 方向 | 口径 |
|---|---|
| ← 冷启动 | 一句问题即可开跑 |
| ← 报告命题（可选） | 只用「低密度×在研」当问题种子；**不在本步重做业务线检索式/检本公司与竞对** |
| ← ① | 立项课题可转化成问题入口；②不代替立项签字 |
| → ③ | 只带方向/路径线索；进挖掘仍要拆点、去向、拆案 |
| → ④ | 方案文是交底引子；发明人还得成稿确认 |
| ≠ 查新 | 路径上的相似专利 ≠ [接口-查新](接口-查新.md) 终局 |
| ≠ 创新报告主链 | 检索式检业务线/本公司/竞对 → 三图+写稿，见 [接口-创新报告](接口-创新报告.md) |

---

## 7. 怎样算够用（一期）

- 能走通：问题 → 路径（有推荐）→ 收藏（或跳过有原因）。  
- 无虚构公开号；无「一定能授权」。  
- 去向意图清楚。  
- 深跑（方案/专利解读）可后做；报告灌创见接口可后做。
