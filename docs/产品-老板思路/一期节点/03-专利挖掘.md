## 1. 这步干什么

把**研发资料**理成：创新点（含怎么护）→ 现有技术证据 → **拆案排案建议** → 双口径分析报告。

- 交出去的是**点 + 建议**，不是齐套交底，也不是「这一案正式申不申」。  
- 小企业可以整段不做挖掘，线索直接去写交底。

```
资料 → 创新点（去向）→（对照检索）→ 拆案排案 → 报告
        ↓
「建议申请 / 补充后可申请」的点 → 发明人写交底 → 代理开案…
```

四步看结果有没有，不锁死顺序：有创新点就能出分析报告，拆案排案可以后做。

### 实现数字（·可变，非业务铁律）

| 项 | 当前实现量级 | 说明 |
|---|---|---|
| 活跃项目上限 | ≤ **20** | 软删；配额可调 |
| 可写进权要的关键特征 | 至少约 **2** 条非空壳 | 未就绪：可有检索候选，不作正式风险/创造性长文 |
| 去向可进拆案排案 | 仅「建议申请 / 补充后可申请」且勾选 | 后三档默认不进；全是后三档 → 不能生成拆案建议 |
| 正式报告对比文献 | 原则上仅 **已核验** | 「已核验」只能人勾；相似度不自动核验 |
| 无已核验时新颖性风险 | 不得写成「低」（常抬到中等） | 报告诚实口径 |
| 分析用草稿池分数线等 | 语义分门槛等 | 与正式报告口径两套；**可调** |

## 2. 给谁用

**这是代理人（专利代理师 / 代理所侧）的工作台，不是企业研发自助主产品。**

| 角色 | 干什么 |
|---|---|
| **代理人** | **主操**：收资料、拆点、定去向、核证据、拆案排案、出报告并复核 |
| **企业研发** | **供料**；认点子是不是自己的事；按诊断稿补材料——不是坐在工作台里主跑四步 |
| **企业老板 / 委托人** | 看建议、拍保护去向；买的是「成果被理清、别乱申」的服务结果 |

对外可以说「帮企业挖成果」；**操作系统的人是代理人**。企业有自己的 IP 岗时，也可以是企业 IP 按同一套手法主操——本质仍是**专业 IP 作业**，不是发明人自学挖掘。

别搞混：报告≠交底；站内检索≠正式查新终局；**拆案排案≠单案申不申**；输入叫研发资料，别默认叫交底书；模板资料不能当真案导出。

## 3. 资料

- **称呼**：研发资料（产品文案刻意不叫交底书）。  
- **归属**：自有 / 公开 / 待确认。用户已标自有或公开时，解析不得改掉；只有「待确认」才允许解析回写归属。  
- **角色**：研发技术 / 企业介绍 / 经营规划 / 混合（按文件名+正文判断，默认偏研发技术）。  
- **解析成功**后项目进入「待创新点」；同一材料旧解析归档，只留当前版。  
- **企业洞察**（可选）：提炼前若没有，会先试着生成，供后面引用。

### 3.1 资料够不够（质量闸）

| 级别 | 含义 | 拆案排案 / 导出 |
|---|---|---|
| 达标 | 可继续 | 正常 |
| 需补材料 | 字太少、像提纲、或解析标明需补 | 可二次确认后继续（按「内部审阅」口径） |
| 模板占位 | 文件名带模板/样例/示例，或填空提示密且没有实质技术正文 | **硬拦，不能靠确认放行** |

补充：AI 单独标成「模板」但文件名和正文都不像模板时，会**降成「需补」**，避免误伤真资料。  
无资料 → 按需补处理。  
解析后若偏研发技术、仍是粗抽取且需补，可再排队精读（PDF 等）。

## 4. 创新点

每个点至少：**问题—方案—效果**（可带实施例、关键特征、新颖性风险简述等）。

**人做的事**：确认 / 编辑 / 合并 / 排除 / 复制；合并至少两点，被合并的排除并软删，特征矩阵和创造性简述会清掉。  
**状态**：待确认 / 已确认 / 已编辑 / 已排除。排除后不再进拆案排案，相关深挖标过期。

### 4.1 五种去向

| 去向 | 默认勾进排案 | 会不会进拆案建议生成 |
|---|---|---|
| 建议申请 | 是 | 会 |
| 补充后可申请 | 是 | 会 |
| 技术储备 | 否 | 不会 |
| 商业秘密 | 否 | 不会 |
| 放弃 / 不宜专利 | 否 | 不会 |

- 空或乱码去向 → 按「补充后可申请」处理。  
- 人把去向改成后三档 → 强制取消「进排案」；人硬勾进排案但去向不可排案 → 拒绝。  
- 全是后三档 → **不能生成拆案建议**（明确提示）。  
- 「建议申请」但方案推断步骤偏多 → 自动降成「补充后可申请」，并带补充清单。

**和老板「四出口」**：申请 ↔ 建议申请（及补完后的补充后可申请）；商业秘密、放弃对齐；**防御性公开产品暂无单独一档**；系统多出「技术储备」「补充后可申请」。代理建议，**保护方式客户拍**。

### 4.2 提炼后系统会拦/降级的空壳（代码里就有）

顺序大致是：写好默认去向 → 企业介绍闸 → 弱创造性闸 → 拥挤界面闸 → 特征够不够 → 机制救援上调 → 去重与元数据。

| 情况（摘要） | 常见结果 |
|---|---|
| 资料整体偏企业介绍/经营规划 | 原可申请档 → **技术储备** |
| 看不出步骤/结构/频率等机制轮廓 | → **技术储备** |
| 偏缺陷统计、纯增删改查、看板展示，又没有硬机制 | → **放弃** 或 **技术储备** |
| 复制导入类、无强机制 | → **技术储备** |
| 拖拽/可视化编辑等拥挤交互、机制弱 | → **技术储备**；有一点机制则不许直接「建议申请」，可「补充后可申请」 |
| 申请路径但可写进权要的特征不到约 **2** 条（·可变） | 有机制轮廓可留在「补充后可申请」；否则 **技术储备** |
| 已是储备但特征≥2、有机制、不是弱创造性标签 | 可**上调**为「补充后可申请」并勾进排案 |

**特征就绪（原则：要有可写进权要的实特征才谈正式新创叙述）：** 当前实现按「至少约 2 条」非空壳关键特征；「待补」和空壳句不算——**条数·可变**。未就绪：检索可落候选，不写正式风险/创造性长文。

### 4.3 重新提炼

会软删旧创新点、作废旧拆案建议、深挖标过期、组合排案打成「已编辑/过期」——**ID 和编码重建**。必须先跟用户说清楚。  
前提：至少有一条当前有效的解析；否则提示先解析资料。

### 4.4 漏挖（可选）

- 只对 **自有** 资料，且已有至少一个勾进排案的创新点时，才自动/可跑。  
- 对照「资料里的机制单元」和已有点的差分；人可接受（新建点，默认补充后可申请并勾排案，并异步检索）、忽略、或合并。  
- 公开资料不跑漏挖；已覆盖的机制不复活。

### 4.5 深挖（可选）

创造性分析、权利要求草稿：状态草稿 / 已确认 / **过期**（上游一变就过期）。  
权要草稿依赖未过期的创造性分析。  
**不是**申请文件定稿；禁止编造公开号和实验数据。已确认创造性 ≠ 对比文件已核验。

## 5. 现有技术检索与证据

### 5.0 和开案后「正式查新」为什么都像在搜

| | **本步（挖点时的检索）** | **⑤ 开案后查新**（见 [接口-查新](接口-查新.md)） |
|---|---|---|
| **谁在做** | 代理人在挖掘工作台 | 代理人在申请案子里 |
| **为了什么** | 拆点、定去向、写挖掘报告时**对照现有技术**；证据要分层诚实 | 回答「新不新、值不值得申/怎么写」；喂**申不申**和权项/背景 |
| **算不算终局** | **不算**可专利性终局；没人核验就不能装已有正式对比 | 建议有结论（或显式跳过认风险）；仍须人认 |
| **能不能互相替代** | 挖过 ≠ 自动完成⑤查新 | ⑤做过 ≠ 回头代替挖点时的证据作业 |

原则：**空壳不进申请路径；证据分层（查到 ≠ 确认 ≠ 对照完）。** 具体库、分数线随实现可变。

### 5.1 何时跑（当前产品）

提炼后异步（可进排案的去向优先）；改方案/特征会再跑；生成拆案建议时若没证据会跑；也可手动。  
检索没配好：老实说没有，不伪造。

### 5.2 核验与报告口径（必须诚实）

- **「已核验」只能人勾**；相似度高也不会自动核验。  
- **正式写进报告当对比文献**：原则上只用已核验的；没有就写待核验。  
- 分析用草稿池可以更宽（当前实现用语义分门槛等——**可调**）；和正式报告口径不是同一套。  
- 无已核验时：不得把新颖性风险写成「低」（当前会抬到中等）。  
- 证据分层要看得见：**查到 ≠ 确认相关 ≠ 对照完成。**

## 6. 拆案排案（产品 UI：「布局」）

**业务在问：** 这些点拆成几件申请、谁主谁外围、什么类型/节奏、案件之间什么关系、大概什么顺序交。  
**不是：** 行业全景、空白点猎场、战略攻防沙盘（→ 二期 [专利导航](../二期节点/01-专利导航.md)）；也不是旗舰图2-4 的赛道落点矩阵（那是**喂**本步任务书；⑧见 [08-复盘](08-复盘.md)）。

### 6.1 单案建议

前提：至少一个「建议申请/补充后可申请」且勾进排案；过质量闸；覆盖已确认稿须再确认。

常见字段：保护定位（核心/外围/防御/储备）、申请类型、策略与节奏、优先级、四方向（替代/新用途/系统/工艺）→ **人确认**。

生成约束（原则）：风险高别瞎抬优先级、别假装可授权；申请路径就别标成「储备/不申请」（极端高风险另说）；效果缺口禁止写可授权。具体档位随模型提示可变。

### 6.2 组合（多案怎么摆）

多案、角色、关系（主从/依赖/重叠/并列替代/分案等）、顺序——在挖掘产品里做（UI 常叫「组合布局」= **组合排案**）。  
改单案会让组合变「脏」，进带排案的报告前一般要再确认（或明示带风险）。  
拆案建议和深挖权要都是**初稿**，不是申请定稿。

## 7. 报告与导出

| 口径 | 给谁 |
|---|---|
| 代理师交付稿 | 代理 / 企业交付（偏已完成分析 + 待核验交代） |
| 研发诊断稿 | 研发（偏证据进度、补料任务） |

- **没有拆案建议也能出**分析报告；有勾进排案的条目时，默认要拆案建议已确认（或明示带风险）。  
- 覆盖全部去向；「拟申请」专章对着可进排案去向的点；储备等单独压缩。  
- 旧报告归档，新报告为当前版。  
- 页眉：**系统初稿 · 须代理师复核后方可对外**；缺实验时创造性只说「可写方向」。

### 7.1 章节（与车联网样例同构）

执行摘要 → 查新与证据进展 → 去向一览 → 现有技术观察 → 拟申请点（每点：证据边界、问题—方案—效果、创造性/权要雏形、还缺什么）→ 暂不申请 → 申请安排 → 近半年推进 → 各方待办 → 附录。

样例常态：很多检索候选，**已确认对比可以是 0**——全文就不能下「可授权」结论。拟申请点的补料清单可直接喂交底/接案。

### 7.2 导出比生成更严

导出还要过：资料质量闸（模板仍硬拦）；占位词泄漏；关键表格（证据分层、去向表等）；交叉引用一致。过不了就不能导出。

## 9. 跟前后怎么接

前面立项/激发可有可无。  
出去给交底：人确认过的「建议申请 / 补充后可申请」的**点** + 去向 + 证据/报告——不是齐套交底（见 [04](04-交底.md)）。  
不要跳过交底直接写申请文件。

## 10. 规则清单（从代码收束）

1. 活跃项目 ≤20（·可变）；普遍软删。  
2. 重提炼：旧点/旧拆案建议作废，深挖过期，组合排案打脏。  
3. 只有「建议申请 / 补充后可申请」且勾进排案的点能生成拆案建议。  
4. 模板资料：拆案排案与导出硬拦。  
5. 需补材料：可确认后继续拆案排案/导出（内部审阅）。  
6. 已核验仅人工；正式报告对比口径以已核验为准。  
7. 特征未就绪（约 2 条·可变）：可有候选，不作正式风险/创造性结论。  
8. 无拆案建议可出报告；有则默认须确认（或明示带风险）。  
9. 组合排案未确认（或仍脏）会挡带排案的报告（或明示带风险）。  
10. 导出质量检查严于「生成报告」。  
11. 企业介绍/弱机制/空壳软件等会强制降去向。  
12. 跨创新点公开号去重，避免证据堆同一篇。  
13. 无已核验时新颖性风险不得写成「低」。  
14. 漏挖仅自有资料 + 已有勾进排案的点。  
15. 产品不做立案、不做权要定稿；报告须代理师复核。  
16. 「已完成」项目状态业务侧基本不写；步骤不靠演示/正式锁死。

## 11. 怎样算走通

| 走法 | 怎样算过 |
|---|---|
| 代理完整跑 | 资料→点确认→去向→检索并有人核验→拆案排案确认→双报告；声明不替撰写 |
| 小企业不挖 | 允许直去写交底 |
| 只要分析报告 | 有点无拆案建议也能出 |
| 组合排案 | 多案可见；进报告前组合已确认或明示带风险 |
| 对照车联网样例 | 主章节齐；证据分层可见；未确认对比就不写可授权；拟申请有补料清单 |

一期建议做到：四步、五档去向、自动检索+人工核验、单案拆案确认、双报告与导出纪律、点能交到交底。
