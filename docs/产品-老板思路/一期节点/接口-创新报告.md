## 0. 一句话

先把**本公司业务线**说清楚，再写成**专利检索式**：分别（并交叉）检**本公司专利**和**竞争对手专利**，在命中集合上建树、看疏密、出三图，需要时再写成旗舰报告。  
件数来自检索命中，不是编的；**检索式**是这条业务链的核心手段。

```
建档：公司是谁、几条业务线、关键词/范围、竞对是谁
        ↓
构造检索式（技术主题式 + 申请人式 AP…）
        ↓
检赛道/业务线专利 · 检本公司 · 检竞对（可再 ∧ 主题）
        ↓
建技术树 → 三图（结构 / 演进 / 密度）+ 按线分析
        ↓（可选）
旗舰写稿 → 全年服务基线
```

## 1. 业务流程（专利检索口径）

### 1.1 建档要齐什么

| 项 | 干什么 |
|---|---|
| 委托方名称 / **申请人检索式** | 圈定「本公司专利」集合（如 `AP-OR=(上海临滴科技有限公司*)`） |
| **业务线**（可多条，深度/浅析） | 分析本公司实际在做的技术方向；每线有关键词、范围说明 |
| **竞对** + 其申请人检索式 | 圈定「竞争对手专利」；可挂到相关业务线 |
| 在研方向（可选） | 公开专利盖不住的投入；须客户确认，不是检索猜出来的 |

金样案例即此结构：`business_lines[].keywords` + `applicant_query` + `competitors[].applicant_query`。

### 1.2 检索式在干什么（不是空话「取数」）

| 类 | 检什么 | 业务用途 |
|---|---|---|
| **业务线 / 赛道主题式** | 标题摘要等技术词（中英）、可加 IPC 等 | 这条业务线相关的公开专利母集；看整体疏密、建树 |
| **本公司申请人式** | 委托方 AP | 本公司在册/公开布局落在哪 |
| **竞对申请人式** | 各竞对 AP | 竞对落在哪；再与主题式交叉看「谁在哪枝密布」 |
| **交叉** | 主题 ∧ 申请人 | 本公司/竞对在某技术枝上的命中（密度矩阵、落点对照） |

母集过宽要收紧关键词/IPC——那是**改检索式**，不是「缺数就编」。

### 1.3 检完之后才有图和报告

| 步 | 业务结果 |
|---|---|
| 建树 | 业务线技术枝（L1/L2）挂上命中 |
| **三图** | 图1 分支结构（本司/竞对落点）；图2 演进；图3 主题×申请人密度 |
| 按线分析 | 疏区、竞对已占、在研能否从专利看出等 |
| 旗舰写稿（可选） | 把检索与图上的事实写成全年基线；缺数则省略，不编件数 |

默认常先停在三图；进页后再写稿。

## 3. 三图 / 报告分别看什么

| | 业务在看 |
|---|---|
| 图1 | 技术怎么分枝；本公司、竞对专利落在哪 |
| 图2 | 近年演进、谁在加码 |
| 图3 | 哪条主题上谁申请得多（密度） |
| 旗舰报告 | 在检索事实之上写诊断与服务衔接（①命题池、②低密度×在研、③图2-4 任务书、⑦健康度、⑧基线等） |

**纪律：** 库（检索式命中）给可复核件数；叙述不发明件数；撑不住的章节省略。

## 4. 谁用 · 产出

| 角色 | 干什么 |
|---|---|
| **顾问** | 建档（业务线/竞对/申请人式）→ 出三图给客户 → 需要时写稿 |

## 5. 和②创新激发怎么挂（勿混）

| | **创新报告（本接口）** | **② 创新激发** |
|---|---|---|
| 手段 | **检索式**检业务线 / 本公司 / 竞对专利 → 三图与报告 | 从**一个技术问题**展开路径与方案 |
| 「低密度×在研」 | 报告第四章写给②的**取材挂钩** | 最多当创见的**可选问题种子** |
| 主流程 | 见上文 §1 | 见 [02](02-创新激发.md)：问题→路径→方案 |

不是把全景检索重跑一遍叫「激发」。
