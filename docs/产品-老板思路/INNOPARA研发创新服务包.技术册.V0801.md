## 第一章 背景与输入

本册为"一总三册"之第四册，读者为技术与产品团队。前三册（客户册、代理所册、保障计划）已从外部承诺侧定义了"系统必须支撑什么"；本册把这些承诺翻译为开发任务：**先有承诺，再有需求，最后排开发——本册中每一行开发任务都必须能回溯到前三册的具体章节。**不允许出现无承诺来源的开发项。

## 第四章 整合架构与数据流转

### 4.1 两个载体原则

- **客户侧：平台统一服务入口（D1）**——提问、传料、确认、查账单一入口；「创见」「鉴新」「智掘」「成稿」挂在同一平台，客户无需记多个系统；
- **代理师侧：代理师工作台（M2-4）**——案件流转、答疑工单、撰写辅助包、考核数据、全记录调阅统一于此；
- **纪律**：任何新需求先查两个载体装不装得下，装得下不立独立系统（代理所册方法论，防系统碎片化）。

### 4.2 检索生成一体化

所有应用内置检索与查新——查新不是独立动作，是生成过程的一部分；客户操作伴随检索、一体留痕。架构后果：客户自助查新的记录可直接作为立项报告依据（保障计划节点①标准第3项），不存在"另做一次检索"的数据孤岛。新系统设计必须沿用此原则。

### 4.3 两层打包原则

- **客户可导出层**：最终交付文件（报告、申请文件、交底书）——归客户，随时可导出；
- **平台沉淀层**：全量交互与修改数据——质量的原料、验收与结算的凭证、代理师调阅（D2）的对象；
- 两层schema均须在M5-6前固化（承接第五章）。

### 4.4 全链数据流转图与断点清单

主流转链：客户需求→【D1统一入口】→①（创见/鉴新→立项报告）→③（材料→智掘→锁定确认单）→④（锁定单schema→成稿→诊断报告）→⑤（D7辅助包→申请文件→受理信息）→⑥（通知书→OA辅助→答复→结果回流）→⑦（期限台账/费用看板）→⑧（聚合→复盘）→回流①立项。

两条横切流：**台账**（全节点留痕→工作台考核结算）；**情报底座/客户理解档案**（M2-3→①③⑧＋情报官）。

现状断点（＝数据缺口汇总，均有主）：锁定单→成稿（D5④）／成稿↔审核系统（D6）／锁定与预警→撰写（D7）／费用与状态→复盘（D12/D13）／交互记录→代理师（D2）。

### 4.5 数据归属与隔离红线（架构约束）

案件数据归客户、代理师通用经验归代理师、平台沉淀过程数据用于服务质量与系统优化（代理所册三条边界）。对架构的硬约束：**任何客户的未公开资料不得成为其他客户的服务输入**（客户册承诺）——档案/画像的检索增强与模型应用，数据隔离到客户空间粒度，技术方案评审时此项为一票否决项。

## 第五章 留痕schema设计

### 5.1 总原则：台账格式即未来schema

人工过渡期所有留痕以结构化台账记录，**台账格式即未来系统的数据schema——开发直接沿用，不返工**（总纲数据纪律）。schema设计权不在开发在流程：schema由前三册定稿的模板与台账字段反向生成；改动流程模板＝改动schema，须同步登记。M7-12"留痕schema固化"里程碑以本章为验收依据。

### 5.2 核心schema清单

| schema | 产生节点 | 关键字段 | 下游消费 |
|---|---|---|---|
| 提问/答疑工单 | ② | 问题类型·相关问题涉及（下拉）·描述·上下文引用·答复·纪要·响应时间戳（1+3计时）·后续建议·客户采纳状态·经验总结 | 知识库·线索视图·考核 |
| 创新点拆解清单 | ③ | 创新点·依据来源（对比文件/相似度）·新创性初判·客户逐项确认/修改/否决及理由 | 复核意见书·锁定确认单·年度聚合 |
| 四出口决策单 | ③ | 成果项·去向（申请/商业秘密/公开/放弃）·理由·客户拍板及理由·时间戳 | 布局建议书·档案（全链判断密度最高数据） |
| 创新点锁定确认单 | ③ | 锁定创新点·方向描述·客户确认 | 成稿撰写锚定（D5④）·RDI第4项对照·D7辅助包 |
| 交底诊断记录 | ④ | 全绿验证·诊断意见·问题清单（逐条修改方向）·客户回应与修改 | 检测模型校准（D6） |
| 撰写与验收记录 | ⑤ | 撰写留痕（自动）·通俗两件套确认记录·RDI五项验收结论·返修复验记录 | 考核·结算双凭证·专家池评级 |
| 答复策略记录 | ⑥ | 通知书·三套策略·概率与代价·客户拍板·保持度·审查结果回流 | 策略命中率校准 |
| 期限与费用台账 | ⑦ | 关键日期（凭证号）·录入时间戳·核对记录·费用分项·缴费确认 | 提醒·看板·复盘聚合·责任认定 |
| 情报报告记录 | 贯穿 | 点名名单·关切点·四维信号·置信度·复核记录·客户使用反馈 | 情报偏好·档案 |
| 经验总结与建议 | 全节点（每单必记） | 系统与模板改进点·客户后续服务建议 | 开发需求台账·档案补充 |

### 5.3 设计要求（四条）

1. **可溯源**：每个字段都能指出"谁在哪本册的哪节承诺了它"；
2. **可举证**：时间戳与操作人必填——留痕即举证，缺时间戳的记录视同未留痕；
3. **枚举即口径**：去向四选一、验收三档、置信度三级等枚举值先行固定——口径不一致的字段不许上线；
4. **变更走登记**：改字段＝提开发需求，任何角色不得私自加字段。

### 5.4 与里程碑的关系

人工期schema（现在）＝M5-6全线打通的接入依据＝M7-12固化的对象。历史台账数据全量继承（对代理所的承诺："上线第一天就在里面"）——**数据迁移方案随各系统上线单独评审，继承完整性为该上线的验收项**。

## 第七章 里程碑成本坍缩预期

### 7.1 口径说明

继承总纲7.2测算口径。人天成本、结算价、算力账单均为测算值，**本章数字全部标注【待校准】**——真实成本数据（结算价、顾问综合日成本、销售编制薪酬、提成组合、算力账单）在悬挂待定项清单中，数据到位后本章重算。坍缩逻辑：系统替代重复劳动→人从"做"转"审＋签字"→单位交付人天下降→毛利率爬坡。

### 7.2 节点成本坍缩表

| 节点 | 现阶段成本 | 坍缩后 | 依赖里程碑 |
|---|---|---|---|
| ①立项 | 2人天 | 0.5人天 | D15（M4-5）＋D3（M5-6） |
| ②答疑 | 人工书面答复 | 答疑量随知识库下降 | D4（M2-4） |
| ③挖掘 | 智掘上线后0.5人天/次 | 审＋签字 | D5（M1） |
| ④交底 | 0.5人天/次 | 审系统预诊断＋签字 | D6（M5-6） |
| ⑤申请 | 结算4,000元/件【内部预估，待校准】 | 辅助包降返工率 | D7（M2-4） |
| ⑥答复 | 1-2人天 | 0.5人天 | D9（M3-4） |
| ⑦维护 | ≈0（录入义务） | ≈0 | D12/D13 |
| ⑧复盘 | 1-1.5人天 | 标准版自动生成、旗舰审＋签字 | M5-6＋D12/D13 |
| 情报官 | 建档2人天 | 底座半自动备料 | D16（M2-3）＋D14 |

### 7.3 里程碑坍缩预期（总纲口径，待校准）

- **0-6个月**：工具全线支撑→报告类人天降50-70%；首年实际亏损重估（客户按月均匀签约，下半年签约客户直接享受系统降本）：标准版约5,000-7,000元、旗舰版约8,500-10,500元【待校准】；
- **7-12个月**：流程优化完成→毛利率目标50-65%【待校准】。

### 7.4 坍缩的四个制约条件（防乐观）

1. **坍缩前提是"系统内完成"**——代理师绕行则数据与效率双失，结算杠杆与三铁规是坍缩的守门员；
2. **签字专家池是硬约束**——系统替代"做"之后瓶颈在人，单个专家年审核量有上限，坍缩天花板由专家池规模决定（总纲7.5）；专家池建设与系统开发同优先级；
3. **数据质量前提**——坍缩测算假设录入纪律达标（铁规二＋D10）；录入失守则复盘、看板、考核全线失真，坍缩无从谈起；
4. **真实数据重算**——交接包3.4校准清单（结算价、顾问日成本、销售摊销、算力账单）到位后，7.2/7.3全部重算并向经营层报告差异。

## 第八章 里程碑验收标准

### 8.1 验收总原则

里程碑验收不看"功能上线"，看"承诺兑现"——每个里程碑的验收问题只有一个：**三册里依赖它的承诺，现在能兑现了吗？**验收三方会签：产品（功能达标）＋业务（承诺兑现）＋数据（留痕与继承完整）。验收不通过的里程碑不许宣称完成，按6.4排期失守处置。

### 8.2 分里程碑验收标准

| 里程碑 | 验收标准（承诺兑现视角） |
|---|---|
| D1统一入口 | 客户提问/传料/确认单一入口可用；台账自动留痕；答疑1+3时限系统可计时 |
| D14模板SOP | 年报/简报模板＋四维信号SOP经业务评审通过——**旗舰版情报官交付承诺闸门解除** |
| M1智掘 | D5六项全落地：拆解附依据（无依据不输出）、交互留痕可查、四出口预填、锁定确认单schema与「成稿」打通验证通过、策略文档结构化可入台账、年度聚合接口可用；代理师"审＋签字"流程跑通≥3个真实案件 |
| D10录入校验 | 日期矛盾阻断、二次确认上线；录入错误率建立基线并可对比 |
| M2-3情报底座 | 四交付物（情报官/立项/监控/复盘）均可调用底座数据；点名竞对动态推送跑通 |
| M2-4工作台 | 案件流转、答疑工单、辅助包组装、状态机、全记录调阅在工作台内完成；考核数据自动归集替代人工维护 |
| M3-4 OA辅助 | 意见解析＋对比文件比对＋三策略初稿＋保持度自动计算；答复人天实测下降（基线1-2天，目标0.5天） |
| M4-5布局统计 | 商业库API接入；竞对布局对照由系统生成初稿；立项报告人天实测2→0.5 |
| M5-6全线打通 | D3/D6/D13上线；两层schema全链接入；**历史台账数据全量继承验证（抽样核对零遗漏）**；顾问"审＋签字"模式覆盖全节点 |
| M7-12流程优化 | schema固化封版；检测模型校准报告（检出率/误报率基线）；续费升级流程跑通 |

### 8.3 验收数据纪律

每个里程碑验收记录入档（达标项／未达标项／处置），作为下一里程碑排期输入；**人天降本类验收以实测为准——坍缩预期不等于坍缩实现，不许用估算宣称达标**。

## 第九章 风险与对策

| 风险 | 说明 | 对策 |
|---|---|---|
| 情报底座单点依赖 | 四交付物共用底座；延期＝成本坍缩整体延期（总纲7.5） | 资源最高优先保；延期即触发经营重估，不许静默滑期（6.4） |
