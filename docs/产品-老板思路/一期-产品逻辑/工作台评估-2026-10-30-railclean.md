## 0. 一段总评（勿过誉）

**主栏按步已基本站住；右栏仍未过关。**  
圈注那四刀（顶空、顶栏堆、四步横条、质检墙）在默认事实步的 DOM/截图里**确实没了**——上次自评「都做完了」却屏上还在，是藏 CSS / 缓存的假 PASS，本轮以硬刷截图为准算真删。  
八部**视觉同壳**也兑现了（薄部不再居中 thin 卡）。  

但 Leslie 紧接着指出的「右侧 AI 区很乱」——`55e5be7` 只做了**结构重排**（身份一行 + 头像横排 + feed 吃高），**没有把硬请示从「迷你表单仪表盘」改成「对话里的一句拍板」**。度量：④侧栏 **15 个可见按钮**、**9 个工具芯片**、编制区 **95px**、请示卡仍带依据摘录 +「拍板理由」槽 + P0 大卡。相对 Kimi / Codex / WorkBuddy 的右栏（或主对话），这仍是**汇报卡墙**，不是干净对话。  

**综合：一期工作台骨架可用、按步叙事可演示；高保真与右栏对话化未完成。不要再说「都优化了」。**

## 4. 仍差什么（诚实 P0 / P1 / P2）

### P0（不改则 Leslie 仍会说「右栏乱 / 不够高保真」）

| # | 现象 | 为何算 P0 | 建议方向（本轮不落地） |
|---|---|---|---|
| **P0-1** | 硬请示仍是**重卡**：P0 标签 + 长说明 + 依据摘录框 +「本步闸口·依据」+「拍板理由」+ 确认/还要改/暂停 | 用户点名右栏乱；与「对话吃高」目标冲突；sticky 已说「确认交底事实」，卡再复述一遍 | 默认轻气泡：一句结论 + 琥珀主钮；摘录/理由进「展开」；暂停次级 |
| **P0-2** | 编制区常开 6 席 + 身份行 ≈ **95px**，工具芯片 9 枚插在历史里 | 对话可视高被身份墙与噪点吃掉；轻量应收名册未兑现 | 默认只保留负责人一行；点「编制」再展；工具芯片默认折或只留当前步 1～2 枚 |
| **P0-3** | sticky「当前要你拍」与下方 ask 卡**信息同构重复** | 大纲要钉顶可达，不是双份墙 | sticky 仅 chip 跳转；或轻量态只留 sticky、对话里用短气泡 |

### P1

| # | 现象 | 建议 |
|---|---|---|
| P1-1 | 侧宽 360 vs 文档常写 340；主栏比例略吃亏 | 锁 CSS token |
| P1-2 | 薄部同壳但主栏空、文案「示意」感强；composer 变「回大厅/去④」尚可，仍不像能办事 | 一期可接受薄；补一条「从大厅委托进主链」故事，少空态旁白 |
| P1-3 | ④质检步主栏大片留白（文书折起后） | 未过项卡应光学居中/加说明，避免「空了一屏」 |
| P1-4 | ⑤⑥ `apply-layout`/`reply-layout` 类残留；view testid 不一致 | 收敛命名，减双 DOM 风险（曾测到隐藏侧栏重复） |
| P1-5 | 轨迹/全流程入口弱：无 pill 后用户不知「我在哪一步」 | 壳顶一行「本步 · 事实确认」即可，勿复活四步墙 |

## 6. Top 缺口（≤5 · 给下一轮）

1. **硬请示气泡化**：砍摘录墙与拍板理由默认态；一结论一主钮。  
2. **编制默认收**：只留负责人；展开再 6 席。  
3. **去重 sticky / 卡**：二选一做「层 1」，另一份不占眼。  
4. **工具芯片与依据 details 默认静音**：当前步最多留必要锚点。  
5. **质检步主栏留白**：未过项成为视觉重心，勿整屏空纸。
