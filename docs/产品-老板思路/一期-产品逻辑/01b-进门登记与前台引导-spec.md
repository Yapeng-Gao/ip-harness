# Spec：账号身份 · 登录后画像种子 · 大厅前台引导

> **状态**：方案可评 · **样机已落**（L2 门闸 + 前台领路卡 desk-line；L1 沿用登录角色）  
> **之上**：[`一期-产品理念.md`](../一期-产品理念.md) · [`00-用户与系统.md`](00-用户与系统.md) · [`01-接待与分诊.md`](01-接待与分诊.md)  
> **交互**：[`交互大纲.md`](交互大纲.md) §3 · §8「首次进入 / 前台去向建议」  
> **拟人化领进后**：[`01c-拟人化样机落点-spec.md`](01c-拟人化样机落点-spec.md) §2（J2 部台收件；本文件不管领进后上下文）  
> **本 spec 钉什么**：三层信息——①账号身份（登录档）②登录后画像种子 ③前台引导/材料持续完善画像与**本次意图**；前台说话为主、上传为有料支线。  
> **本 spec 不钉**：高保真视觉、真鉴权细节、组织树、模型细则；组织拟人驾驶舱/人设/移交见 01c。

## 0. 一句话

**登录认账号；进厅先留一层粗画像；前台每次把「今天要办啥」说清，并顺带把画像补全。**  
材料上传是完善信号，不是进门握手。

---

## 0.1 三层别混（本 spec 核心）

| 层 | 何时 | 解决什么 | 典型字段/信号 | 不是什么 |
|---|---|---|---|---|
| **L1 账号身份** | 登录 / 注册 | 你是系统里的谁 | 称呼、企业或个人、登录凭证 | 不是用户画像，更不是本次意图 |
| **L2 画像种子** | **登录之后**、进大厅办事前（可极短一屏或可跳过） | 你大致是哪类人、常办哪类事 | 角色、领域粗分、熟悉度等（§3） | 不是问卷墙；不是选今天去哪一部 |
| **L3 会话意图 + 画像加厚** | 大厅前台每次 | **今天先去哪**；并回写画像 | 第一句、示例、确认部门、附件识物、粗缺口 | 上传不是唯一入口 |

**关系：** L1 稳态少改 → L2 可改、可补 → L3 每次刷新「本次意图」，稳定偏好再沉淀进 L2。

```
登录（L1 账号）
    ↓
若无画像种子 → 极短 L2 采集（可跳过）
    ↓
大厅
    ↓
前台 L3：说话 / 附材料 → 建议去向 → 确认领进
         └─ 同时：完善画像、解析本次意图
```

## 1. 端到端时序

```
① 登录 / 注册（L1：称呼·主体·凭证）——属账号页，本产品可薄接
    ↓
② 【登录后】画像种子（L2：可选极短 · 可跳过）
    ↓
③ 进入大厅（前台 + 八部 + 项目）
    ↓
④ 前台引导（L3：第一句 → 复述去向 → 确认领进）
    │         支：有材料可附上 → 分析补强意图 + 回写画像
    ↓
⑤ 领进某部或直达某部/项目
    ↓
⑥ 部门门槛与办稿（前台不代替）
```

再来用户：有 L1+L2 → 直达③；L2 未填过仍可在设置补，不挡路。

## 2. L1 · 账号身份（登录档 · 不是画像）

> 你说得对：称呼 / 企业或个人 **更像登录页信息**。本 spec 把它归 **账号层**，与「用户画像」分开。

### 2.1 目的

账号认领、显示名、案卷主体归属。类比：门禁卡上的名字和公司，不是 HR 画像表。

### 2.2 字段（一期）

| 字段 | 必填 | 说明 |
|---|---|---|
| 称呼 / 显示名 | 是 | 界面称呼 |
| 企业 / 团队名，或「个人」 | 是 | 主体 |
| 登录凭证 | 正：是；样机可免 | 手机/邮箱/SSO 等后置细节 |

**角色粗分不放 L1 必填**（放到 L2 画像种子，避免登录页变问卷）。

### 2.3 验收（L1）

| # | 期望 |
|---|---|
| A1 | 无账号不能进办事大厅（样机可用本地档案模拟） |
| A2 | L1 页无「今天去哪部」、无上传主 CTA、无领域长表 |

## 3. L2 · 登录后画像种子（初步用户画像）

### 3.1 目的

登录之后、前台办事之前，留一层**可跳过的粗画像**，让开场话术与示例更贴人——**仍不是本次分诊**。

| 做 | 不做 |
|---|---|
| 常办事项倾向、熟悉度（领域粗分可后补） | 再问一遍登录已选的角色 |
| 可跳过；可设置里补 | 强制写清「今天去交底部」；技术交底长问卷 |
| | 超过约 3～4 个控件的墙 |

### 3.2 字段（一期建议）

| 字段 | 必填 | 说明 | 如何被用 |
|---|---|---|---|
| 角色粗分 | **不在 L2 再问** | 沿用 L1 登录 `entryRole` 写入种子 `roleHint` | 代理默认更强调案盘/直达；企业默认前台引导略完整 |
| 主要办事倾向 | 否 | 多选至多 2：写交底 / 递申请 / 答审查 / 还不确定 | 排序示例句；不锁死本次去向 |
| 领域粗分 | 否 · 样机可后补 | 单选或可输入标签：机械 / 电子 / 软件 / 化工 / 其他 | 话术举例；材料识物弱先验 |
| 熟悉度 | 否 | `第一次用` / `用过类似工具` | 第一次→示例更显；熟→弱引导 |

**明确不做进 L2：** 上传材料包、选八部、填发明名称/交底全文。

### 3.3 交互

1. 登录成功且无 L2 种子 → 一屏「先了解你几句（可跳过）」→ 进大厅。  
2. 跳过 = 空种子，前台用中性开场 + 通用示例。  
3. 设置 / 前台侧可「完善画像」。  
4. **不**在每次进大厅强制重填。

### 3.4 验收（L2）

| # | 期望 |
|---|---|
| P1 | 可全部跳过仍进大厅办事 |
| P2 | 填了「代理 + 常答审查」→ 示例句顺序偏向 OA，仍可改口去交底 |
| P3 | L2 屏无大上传主钮 |

## 4. L3 · 前台：完善画像 + 分析本次意图

> 你的判断成立：**前台引导和材料上传，是在完善用户画像，并解析当次意图**——不是替代 L1/L2。

### 4.0 双写模型

| 写入 | 内容 | 寿命 |
|---|---|---|
| **本次意图**（会话） | 第一句、建议部、用户确认部、本轮材料标签与粗缺口 | 本案/本轮；领进时带给部门 |
| **画像加厚**（L2+） | 稳定偏好：常去④、常附通知书、代理口吻等 | 跨次；仅在用户确认去向或明确偏好后弱更新，避免一次误点污染 |

规则：**本次意图即时用于领进；画像只吸收「确认后」的稳态信号。**

### 4.1 角色

- **接待专家（小林 / PMO）**：弄清去向、介绍能办啥、建议部门、整理交办/粗缺口、领进。  
- **不做**：交底全绿、权项、OA 争点、三性终裁、代替部门进入门槛绿灯。

### 4.2 主路径（说话为主）

取代「上传＝主 CTA」的 idle 态：

```
开场（名片 + 一句能力边界）
    ↓
主操作：输入框发出第一句
  · ≤3 条可点进输入框再改的示例话（非问卷墙）
  · 旁挂次要：「有材料可附上」
    ↓
前台复述：意图假设 + 主推部门 + ≤2 备选 + 一句理由
    ↓
【硬】用户确认去向（可改选）
    ↓
对照该部粗缺口（已有/可能缺）→ 交办提示
    ↓
领进部门（说清下一步在部内）
```

**每轮引导必须有出口：**「建议部门 + 确认领进 / 改选」。禁止只寒暄、空转「您再详细说说」。

### 4.3 三条访客分流

| 类型 | 行为 |
|---|---|
| 说得清 | 一句话或示例发出 → 建议 → 确认 → 进部；材料可选 |
| 说不清 | 示例句降开口成本；两路同强时**最多再追一句**澄清；不逼上传、不丢选择题墙 |
| 明确有料 | 用户附材料或声明「先看材料」→ 走分析支线（§4.6）→ 汇报 → 确认 |

### 4.4 示例话（一期建议稿 · ≤3）

点入后写入输入框，用户可改再发：

1. 「有个结构改动，还没写成交底」→ 偏④  
2. 「交底差不多了，想递申请」→ 偏⑤  
3. 「手里有审查意见，不知道往哪走」→ 偏⑥  

「更多」目标若保留：折起，视觉弱于输入；**不当主墙**。

### 4.5 与直达、项目的关系

| 进法 | 前台 | 部门 |
|---|---|---|
| 经前台领进 | 字段/建议默认继承 | 补差额 + 门槛检 |
| 大厅直达某部 | 可不出场 | 短收件 + 门槛检 |
| 左侧项目续案 | 不强制前台 | 按案进度进部 |

### 4.6 有料支线 · 上传分析（完善意图 + 回写画像）

**何时出现：** 输入区附件 / 「有材料可附上」；原话声明有料；确认前补充。  
**不作为**大厅 idle 主 CTA。

四路信号与冲突表继承 `01` §4.1。产出进**本次意图**；用户确认去向后，弱更新 L2（如常附通知书、常去⑥）。

```
附材料（可与第一句同时）
  → 析 → 汇报 →【硬】确认 → 粗缺口 → 领进
  →（确认后）可选回写画像种子
```

## 5. 大厅结构（进门第一眼）

与 `01` §1 一致：

| 区域 | 职责 |
|---|---|
| 前台卡 | 默认引导：弄清本次去向；完善画像 |
| 八部名牌 | 直达；非藏在前台后 |
| 项目（左栏等） | 已有案子续办 |
| 老板待办等 | 见交互大纲 |

**前台不是唯一闸门**：说得清或熟客可直达部门/项目。

## 6. 信息架构 · 大厅前台卡（UI）

### 6.1 Idle（已登录 · 未发出第一句）· **领路卡，非聊天壳**

1. 区名：前台 · 弄清去向  
2. 职员条（薄）：小林 · 前台 · tagline（**无聊天气泡**）  
3. 普通说明一句：来意怎么写 + 可直达八部 / 项目  
4. **主：** 单行「今天想办的事」+「看看去哪」（非 composer / 非大 textarea）  
5. **辅：** ≤3 弱示例（点入可改；**禁止**抬成情景卡主墙）  
6. **次：** 「有材料可附上」文字链级  

### 6.2 Suggest · **去向确认单**（非助手又回一条）

- 标题：去向确认  
- 来意摘要 / 材料摘要（若有）  
- 主推 + 备选部门（可改选）  
- 粗缺口一句  
- 主按钮：确认去向 · 领进××  
- 次：重来  

### 6.3 明确拿掉或降级

| 旧 | 新 |
|---|---|
| 「丢材料进来」大主按钮 | 降为文字链附件 |
| 「或点主链目标」大块 / 情景卡主墙 | ≤3 弱示例；不点选直跳进部 |
| 气泡开场 + 对话回合感 | 领路卡说明 + 去向确认单 |
| 聊天式 textarea +「请前台看看」 | 单行 +「看看去哪」 |

## 7. 硬请示与诚实

| 事项 | 档 |
|---|---|
| 识物、意图假设、主推理由、粗缺口 | 自决 |
| 两路同强须澄清一句 | 建议后请示 |
| **本次去哪一部**；与建议不一致仍要进 | **硬请示**（用户定案；案卷留痕） |

- 没材料也能领进；**硬拦在部门门槛**。  
- 领进时须露出粗缺口，避免「假通行证」体感。  
- 不确定标不确定；不编专业结论。

## 8. 数据与样机落点（薄）

| 层 | 样机建议 |
|---|---|
| L1 账号 | `ip-agent-account-v1`：`displayName` · `orgName` · `orgIsPersonal` · `completedAt` |
| L2 画像种子 | `ip-agent-persona-v1`：`roleHint` · `jobTendencies[]` · `domain` · `familiarity` · `skipped` · `updatedAt` |
| entryRole | `roleHint=代理` → `ip-agent-entry-role=agency`；否则 enterprise |
| 本次意图 | 会话态 / 案卷字段：goalText · suggest · confirmedDept · materials · gaps |
| 建议引擎 | `receptionSuggest`：goalText + fileNames +（可选）L2 先验 → 同一 Suggest UI |
| 路由 | L1/L2 完成或跳过 → `/agent`；领进 → `hallDeptHref` + `?reception=1` |

正：L1 进账号；L2/加厚进用户画像服务；意图进案卷；产品规则（权重序、冲突表）不变。

## 9. 范围裁剪

### 9.1 一期做满

- L1 账号薄身份 + L2 可跳过画像种子  
- 前台 idle：输入主位 + ≤3 示例（可按 L2 排序）+ 附件次要  
- 一句话/附件 → Suggest → 硬确认领进；确认后弱回写 L2  
- 粗缺口提示；八部/项目直达保留  

### 9.2 一期可后置

- 画像自动学习仪表盘、多轮深度澄清  
- 演示走通动画、真上传深度识物  

### 9.3 明确不做（一期）

- 把 L2 做成登录页长问卷  
- 上传当唯一主 CTA  
- 前台目标芯片墙 / 连续盘问  
- 前台代替部门门槛亮绿灯  
- 未确认的一次性点击就永久写死画像
