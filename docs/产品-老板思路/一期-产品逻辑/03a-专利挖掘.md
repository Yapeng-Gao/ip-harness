## 0. 一期薄合格线（已冻 · 勿厚做）

| 项 | 钉死（一期只认这些） |
|---|---|
| **进得去** | 大厅③门可点进；小企业可**整段不做挖掘**直去④ |
| **合格线一句话** | **双路径择一**经用户确认：分析报告路径 **或** 可交④创新点包路径 |
| **禁超卖** | 不代替④写齐套交底；不代替⑤申不申/申请定稿；不承诺可授权 |

厚做（深挖权要、组合排案极致体验）仍讨论稿。细节见 §4 结束合格线 / §13。

## 1. 部门职责

把**研发资料**理成：创新点（含保护去向）→ 现有技术对照证据 → **拆案排案建议** → 双口径分析报告。  
交出的是**点 + 建议**，不是齐套交底，也不是「这一案正式申不申」。

**硬产出（至少一种合格结束）：**  
- **分析报告**（代理师交付稿 / 研发诊断稿；页眉须「系统初稿 · 须代理师复核」）  
- 和/或：**已确认的拆案排案**（有可排案点时）+ 拟交④的**创新点包**（建议申请 / 补充后可申请 + 去向 + 证据摘要）

**不做：** 代替④写齐套交底；代替⑤开案查新终局 / 申不申终裁 / 申请文件定稿；FTO；二期赛道导航厚册；用报告冒充「可授权」。

小企业可**整段不做挖掘**，线索直去④——系统允许，不强制先过③。

## 2. 产品里有谁（只三类）

| | 说明 |
|---|---|
| **用户** | 真人（代理/企业 IP/发明人…谁登录谁是用户）；听汇报、拍板、可 1:1、可看产出 |
| **部门** | 挖掘部；进门看见名册与工作台 |
| **专家** | **全部是 Agent**；能一个办完不硬拆 |

没有「真人专家席」与用户并列。套餐对人签字＝服务交付另走，不进产品编制。

### 2.1 谁主持——部门负责人（不是前台）

| | 现实 | 本产品 |
|---|---|---|
| **前台** | 大厅引导、领到某部 | 只在大厅 ([01](01-接待与引导.md))；**不进部内派活** |
| **部门负责人** | 科室主办：对接、拆活、盯进度、汇总 | 挖掘部 **Agent**（名：部门负责人） |

前台领进门、交案卷；进部后换负责人。

```
用户 ←→ 部门负责人（主持、分配、汇总汇报）
              ↓
     资料 / 创新点 / 检索 / 拆案排案 / 报告 …（可串可并）
用户也可 ←→ 某专家（盯细活）· 随时看产出
```

**惯用：** 代理人（代理师 / 所侧 IP）更常主操整台四步；企业研发常供料、认点子、按诊断稿补料。  
**系统不按身份锁**：企业 IP / 发明人登录也可主操同一套；汇报一律向**当前用户**（见 [00](00-用户与系统.md)）。

## 3. 编制：能一个就一个，要拆就拆

均为 Agent。

| 专家 | 对应业务段 | 职责 |
|---|---|---|
| **部门负责人** | 全程 | 收件/门槛、分活、冲突汇总、组织结束确认、开④工单 |
| **资料专家** | **A** | 研发资料解析、归属/角色、质量闸、企业洞察（可选） |
| **创新点专家** | **B** | 提炼点、去向建议、合并/排除协助、漏挖候选（可选）、深挖草稿（可选） |
| **检索专家** | **C** | **挖点向**现有技术对照（异步/手动）；证据分层；≠ ⑤开案查新 |
| **拆案排案专家** | **D** | 单案建议 + 组合排案（UI「布局 / 组合布局」）；≠ 二期导航；≠ ⑤权项布局 |
| **报告专家** | **E** | 双口径报告生成/块编辑；导出质量闸 |

活少可合并呈现（如「挖掘专家」兼 A+B+D）；逻辑上仍按上表。

### 3.1 边界（硬钉）

| | 本部门 | 不是 |
|---|---|---|
| **「布局」** | UI 第四步＝**拆案排案**（几件、主从/分案、类型与节奏、顺序） | 二期专利导航 / 赛道战略布局；⑤单案独从「权项布局」；旗舰图2-4 落点矩阵（那是**喂**任务书，非③本体） |
| **查新 / 检索** | 挖点对照：定去向、写报告时分层诚实 | ⑤申请向查新终局；科技查新冒充；FTO |
| **报告** | 点+建议+证据进展；须复核声明 | 齐套交底；申不申终裁；可授权承诺 |
| **点 → 交底** | 确认过的可申请档点 + 补料清单可喂④ | 跳过④直接写申请文件 |

下文凡写「进布局 / 生成布局」＝**进拆案排案 / 生成拆案建议**（对齐产品字段名）。

### 3.2 合并呈现 · 时序（薄）

| 活量 | 呈现 |
|---|---|
| 常案 | 「挖掘专家」兼 A+B；C/D/E 按需分席 |
| 只要交④点包 | 可弱化 E 报告席；仍须点确认 |

```
门槛 → A → B →【硬】确认点/去向 →（建议）C 核验 →（可后）D → E 报告或交④打包
```

## 4. 必做 · 选做

四步看**结果有没有**，不锁死顺序：有创新点就能出分析报告；拆案排案可后做。

| | 内容 |
|---|---|
| **必做** | **进入门槛**（有可依托研发资料，§6）→ **B** 至少一批创新点且用户确认过（或认风险挂起）→ **结束门槛**（§9.1：报告已出 **或** 点包可交④，见下） |
| **强建议** | **C** 挖点向检索 + **人工核验**勾选；**D** 有可排案点时做拆案排案并确认 |
| **可弱** | 拆案排案：无拆案建议也可出分析报告；有勾进排案条目时默认要确认（或明示带风险） |
| **选做** | 企业洞察、漏挖、深挖（创造性/权要草稿）、组合排案加厚 |

**「已核验」只能人勾**；相似度高也不自动核验。  
正式报告对比文献原则上只用已核验；无则写待核验——**不得**无核验却把新颖性风险写成「低」。

**结束合格线（产品钉法）：**  
至少满足其一且用户确认本部门办结（**双路径均为合格，不强制两路都做**）：  
1. **报告路径**：当前版分析报告已生成；若含排案专章则拆案/组合已确认或明示带风险；导出若做则过导出闸；  
2. **交④路径**：至少一条「建议申请 / 补充后可申请」点经用户确认，案卷可开「现在做④」工单（点+去向+证据/报告摘要）。  

开「现在做④」→ 须路径 2（或报告路径已含可交④点包说明）。  
≠ ④交底全绿；≠ ⑤申请过线；≠ 已授权。见 [00 §6.1](00-用户与系统.md)。

手法（质量闸数字、去向降级链、特征就绪条数等 ·可变）→ 业务章程 + patent-dig；**不抄进本文当铁律**。

## 5. 领域

看材料建议；收件或提炼前确认；**随时可改**。不在注册死锁。  
领域影响资料角色判断、补料话术、报告表述——**不改变**四步主路径。

## 6. 进门门槛：先有研发资料

> 通则见 [00 §6](00-用户与系统.md)。大厅点进③ ≠ 已过门槛。

输入叫**研发资料**（产品刻意不叫交底书）。可来自①/②、大厅直达、或用户上传。

### 6.1 进入检查表（开干四步前）

| 必备 | 说明 |
|---|---|
| 研发资料 | 至少一份可解析材料（技术说明/图纸/规划等）；**空卷不开干** |
| 目标确认 | 本次要挖点/出报告/拆案排案（用户认） |
| 领域（可暂定） | 收件建议；提炼前宜确认 |
| 来源记录 | ①/② 工单 / 自带上传 / 前台领进 |

### 6.2 两种进法 · 收件

| 来源 | 做法 |
|---|---|
| 前台领进 | **继承**前台字段；核进入检查表差额 |
| 大厅直达 | **短收件** + 进入检查表 |
| ①/②「现在做③」 | 继承上家材料与批注；仍跑质量闸 |
| 自带资料 | 解析 + 质量闸；不过见 §6.3 |

### 6.3 资料质量闸（对齐业务）

| 级别 | 含义 | 拆案排案 / 导出 |
|---|---|---|
| **达标** | 可继续 | 正常 |
| **需补材料** | 字太少、像提纲、解析标明需补 | 可二次确认后继续（「内部审阅」口径） |
| **模板占位** | 模板/样例/填空无实质技术 | **硬拦**；不能靠确认放行 |

无资料 → 按需补；**不假装已开提炼**。

### 6.4 进部后发现问题：分流

| 问题类型 | 谁主责 | 动作 |
|---|---|---|
| **资料空壳 / 模板** | A | 补料或硬拦；不降级硬写可授权 |
| **点不像创新 / 去向争议** | B + **用户** | 改去向、排除、合并；后三档默认不进排案 |
| **证据不够 / 未核验** | C + **用户** | 继续检索或诚实写待核验；禁止装已有正式对比 |
| **拆几案有分歧** | D + **用户** | 选项汇总；用户拍；≠ ⑤申不申 |

**禁止：** 用「先出报告」绕过进入门槛（无资料）；用挖点检索冒充⑤查新已完成；模板资料确认放行导出。

## 7. 部内怎么干

1. 负责人与用户对齐：目标＝点+建议+（可选）拆案排案+报告；是否做 C/D；领域。  
2. 核对 **进入检查表** + 质量闸；不过则 §6.3，不假装开提炼。  
3. 分配 A/B/C/D/E（能一个就一个；可串可并，如检索∥补料）。  
4. **A** 解析资料 → 待创新点；归属已标自有/公开不得被解析改掉。  
5. **B** 提炼 → 用户确认/编辑/合并/排除/定去向；可进排案仅「建议申请 / 补充后可申请」且勾选。  
6. **C**（建议）对照检索 → 人勾核验；证据分层可见（查到 ≠ 确认相关 ≠ 对照完）。  
7. **D**（有可排案点时建议）单案 → 组合排案 → 用户确认（或带风险进报告）。  
8. **E** 报告 → 用户选口径 →（可选）导出过闸 → 用户确认办结 / 开「现在做④」。

```
进入门槛通过
    ↓
A 资料 → B 创新点·去向 → C 挖点检索·核验（建议）→ D 拆案排案（可后）→ E 报告
    ↓ 可申请档点确认
  工单④（点包，非齐套交底）
```

四步解锁按结果：有点即可进报告；无拆案建议也能出分析报告。  
**重新提炼**会软删旧点、作废旧拆案、深挖过期、组合打脏——**必须先跟用户说清**。

**禁止（对齐业务纪律）：**  
无人确认当真交付；编造公开号/实验数据；自动当已核验；报告代替申不申；拆案建议当申请定稿；空命中当查新过关；报授权概率当结论；跳过④直接写申请文件。

并行冲突由负责人汇总选项给用户，不私下定案。

### 7.1 请示矩阵（薄）

| 事项 | 档 |
|---|---|
| A 解析/质量闸、B 抽点草稿、C 线索、D/E 初稿 | **自决** |
| 建议做 C/D、漏挖/深挖 | **建议后请示** |
| **确认点与去向**；**勾已核验**；**确认拆案**（或带风险）；**选口径/办结/交④** | **硬请示** |

Agent 低置信须示弱；**不得冒充**点已确认、证据已核验、拆案已定、报告可对外。

### 7.2 部间谁打包（薄）

| 工单 | 谁打包 |
|---|---|
| 现在做④（点包） | **③ 部门负责人**（须交④路径合格；≠④全绿） |

## 8. 向用户汇报什么

| 节点 | 汇报 | 用户常拍 |
|---|---|---|
| 进入门槛 | 资料成色能否开挖 | 补料 / 回前台 / 轻留痕 |
| A–B | 点列表、去向、空壳降级原因 | 确认/改去向/排除/合并 |
| C | 命中分层、核验缺口 | **勾核验**；是否继续搜 |
| D | 拆几案、主从/节奏、组合关系 | **确认排案**或带风险 |
| E | 报告摘要、拟申请补料清单 | 口径；是否导出；是否交④ |

## 9. 多次不行 · 缺料 · 结案

| 情况 | 做法 |
|---|---|
| 点质量差、材料够 | 限定焦点再提炼/编辑 → 再确认 |
| **关键机制/特征没有** | 回 A/B 补料；仍无 → 降去向或暂停，不空转「可授权」长文 |
| 全是后三档去向 | **不能生成拆案建议**（明确提示）；仍可出分析报告 |
| 用户暂不往下 | 暂停；案卷保留 |
| 小企业不挖 | 允许直去④；本部门可不建办结 |

**不能：** 未确认点当真交付；未核验装正式对比；模板导出；把③办结标成「已申请」。

### 9.1 结束检查表（办结 / 开「现在做④」）

| 必备 | 说明 |
|---|---|
| 进入门槛记录 | 有资料且非空卷；质量闸结果留痕 |
| 创新点确认 | 至少一批点：已确认/已编辑，或用户认风险挂起 |
| 去向一览 | 五档可见；可排案勾选符合规则 |
| 报告 **或** 交④点包 | 报告路径：当前版报告；交④路径：可申请档点+去向+证据/报告摘要 |
| C（若做） | 核验勾选或跳过认风险；无核验不得「新颖性低」 |
| D（若有排案进报告） | 单案/组合已确认或明示带风险 |
| 缺口与备注 | 选做未做、补料清单、重提炼告知等 |
| 工单（交④时） | 现在做④ / 批注（**点包 ≠ 齐套交底**） |

≠ ④交底书；≠ ⑤申不申；≠ 授权结果。

### 9.2 走通画像（对齐业务「怎样算走通」）

| ID | 画像 | 产品上必须看见 |
|---|---|---|
| **M1** | 代理完整跑 | 资料→点确认→去向→检索有人核验→拆案排案确认→双报告；声明不替撰写 |
| **M2** | 小企业不挖 | 允许直去④；③可空过 |
| **M3** | 只要分析报告 | 有点无拆案建议也能出；证据分层诚实 |
| **M4** | 组合排案 | 多案可见；进报告前组合已确认或明示带风险 |

共性：**无人确认不对外；无核验不装可授权；点交④不跳交底。**

### 9.3 容易漏（产品意识清单）

| 项 | 产品意识 |
|---|---|
| 资料称呼 | 研发资料，不默认叫交底书 |
| 归属 | 自有/公开已标不得被解析改掉 |
| 五档去向 | 后三档默认不进排案；全后三档不能生成拆案 |
| 特征就绪 | 未就绪可有检索候选，不作正式风险/创造性长文（条数·可变） |
| 漏挖 | 仅自有资料 + 已有勾进排案的点 |
| 深挖 | 草稿/确认/过期；≠ 申请定稿；已确认创造性 ≠ 对比已核验 |
| 导出 | 严于生成；占位词/交叉引用不过则不能导出 |
| 活跃项目配额 | 实现量级·可变；非业务铁律 |

## 10. 依据链

| 环节 | 要求 |
|---|---|
| A 资料 | 解析可对回原文；模板硬拦有据 |
| B 创新点 | 问题—方案—效果可对回资料；禁猜实验数据 |
| C 检索 | 命中可核；「已核验」仅人勾；跳过有留痕 |
| D 拆案排案 | 建议绑已确认可排案点；初稿非定稿 |
| E 报告 | 对比口径以已核验为准；页眉须复核声明 |

## 11. 交出去 · 边界

| | 内容 |
|---|---|
| ← ①/②/大厅 | 工单或直达 + 研发资料/批注 |

## 13. 一期够用

用户↔负责人↔专家；进入检查表；资料→点→（建议）检索核验→（可后）拆案排案→报告；人确认点（§7.1）；结束检查表；点能交④；M1–M4；易漏意识；段间交出；手法链业务文与 patent-dig。

**一期可薄：** 深挖权要做厚、老板签字单电子化、组合排案极致体验。  
**不做：** 代替交底；代替正式查新/单案申不申/申请定稿；FTO；赛道导航厚册；用检索代替实施例。
