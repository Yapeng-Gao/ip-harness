## 1. 部门职责

把技术事实写成**交底书**，质检**检测全绿**后可交下游。  
**不做：** 写申请文件；终裁申不申；替代⑤开案理解对齐。  
**不做：** 「写完再在平台上找真人代理人」——本期不是撮合平台。

---

## 2. 产品里有谁（只三类）

| | 说明 |
|---|---|
| **用户** | 真人（研发/代理/IP…谁登录谁是用户）；听汇报、拍板、可与专家 1:1、可看产出 |
| **部门** | 交底部；进门看见名册与协同场 |
| **专家** | **全部是 Agent**；按需一个或多个 |

没有「真人专家席」和用户并列。套餐里要对客户**签字**的，是服务交付另走，不在产品编制里再造一类人。  
多角色（发明人确认 / IP 视角）→ **换人登录**即换当前用户，或同一人兼拍留痕；不做按身份 ACL（见 [00 §6.1](00-用户与系统.md)）。

### 2.1 谁主持分活？——部门负责人（不是前台）

| | 现实 | 本产品 |
|---|---|---|
| **前台** | 公司大门接待、分诊、领到某部 | 只在大厅 ([01](01-接待与分诊.md))；**不进部内派活** |
| **部门负责人** | 科室主办/组长：对接委托方、拆活、盯进度、汇总汇报 | 交底部的一个 **Agent 专家**（名：部门负责人） |

部内分活、向用户汇报进度 → **部门负责人**做。  
前台只负责领进门、交案卷；进部之后换部门负责人对接。

```
用户 ←→ 部门负责人（主持、分配、汇总汇报）
              ↓
        其他专家 Agent 执行（可 1 人包办，可多人拆开）
用户也可 ←→ 某个专家（盯细活）· 随时看产出物
```

---

## 3. 编制：能一个就一个，要拆就拆

均为 Agent。具体活能由一个专家干完就不硬拆；需要并行/专长再拆多个。

| 专家 | 职责 |
|---|---|
| **部门负责人** | 对用户；收件/进入门槛；分配谁做哪步；汇总汇报；组织交⑤ |
| **成稿专家** | 材料/问诊/提纲/起草（活少时可与负责人或质检等合并呈现，逻辑上仍可分） |
| **润色专家** | 改表述不改技术含义 · 按需 |
| **检索专家** | **交底向**查新（薄）· **按需**（用户要或负责人建议且用户同意）；≠ ⑤申请向 |
| **质检专家** | 检测；**必做**；未全绿则推动优化，直至全绿 |
| **IP 顾问** | 权属/公开/齐套/放行视角 · 按需 |
| **代理顾问** | 专利成色/诊断视角 · 按需 |

质检 vs IP vs 代理顾问：检测项 / 放行视角 / 成色视角；批准交底 ≠ 批准申请。

### 3.2 合并呈现（逻辑岗 ≠ UI 名片）

| 活量 | 可合并呈现为 | 逻辑上仍分 |
|---|---|---|
| 材料薄、一人可串完 | 「交底专家」兼成稿+润色 | 质检**不**并进同一名片冒充已检 |
| 只要成稿+质检 | 成稿 ‖ 质检 两席 | 负责人可兼主持+轻派活 |
| 用户要成色/放行视角 | 另开 IP / 代理顾问席 | 与质检检测项分列 |

原则：**能一个就一个**；合并的是呈现与调度，不是取消质检岗纪律。

### 3.3 协作时序

```
门槛通过 → 成稿（可∥问诊）→ 【硬】事实确认 → 质检 →（未全绿则优化∥再检）→ 【硬】可交⑤
                ↑选做：润色 / 交底向查新 / IP·代理顾问（须用户同意派）
```

| 段 | 触发 | 默认可并 | 不可并/硬闸 |
|---|---|---|---|
| 成稿 | 门槛过 | 问诊∥起草 | 无材料空转 |
| 事实确认 | 成稿有正文 | — | **当前用户**；Agent 不可代认 |
| 质检 | 事实已确认（默） | 润色可先于或夹在质检循环 | **未全绿不交⑤** |
| 选做查新等 | 用户同意 | ∥ 成稿中后段 | 不代替申不申；≠⑤查新 |

并行冲突 → 负责人汇总选项给用户。

## 4. 必做 · 选做

| | 内容 |
|---|---|
| **必做** | **进入门槛**（§6）→ **交底书** → **成稿事实确认** → **质检全绿** → 用户确认可交⑤ |
| **选做** | 查新、润色、IP 视角、代理顾问诊断等——负责人可建议，用户同意再派 |

**质检不能跳过。** 有问题 → 优化 → 再检，直到全绿（或用户决定暂停/退回补材料，但**不能**带着未质检或未全绿当「合格交卷」）。  
系统内结束合格线＝**全绿**（≠ ⑤申请过线，见 [00 §6.1](00-用户与系统.md)）。

查新仍非强制（交底向、薄）；与⑤正式查新分开。

### 4.1 请示矩阵（自决 / 建议后请示 / 硬请示）

| 事项 | 档 | 谁 |
|---|---|---|
| 问诊提纲、起草、润色改表述、质检出项与改稿建议 | **自决** | 对应专家 |
| 派选做（查新/IP/代理顾问）、领域暂定→确认建议 | **建议后请示** | 负责人建议 → 用户同意再派/确认 |
| **成稿事实确认**、**确认可交⑤**（须已全绿） | **硬请示** | **当前用户** |
| 缺关键事实：暂停 vs 退回补料 | **硬请示** | 用户（负责人备选项） |

Agent 不得冒充事实已确认、全绿已可交⑤。

### 4.2 质检节奏

1. 首次检：成稿事实确认后（默）；可应要求先预检但**预检全绿 ≠ 可交⑤**（仍须确认后正式全绿）。  
2. 未全绿 → 质检专家推动优化（成稿/润色）→ 再检；限定焦点，不无的放矢。  
3. 全绿 → 负责人组织「可交⑤」硬请示。  
4. 用户拒交⑤ → 暂停；案卷保留全绿状态，不强迫开⑤。

## 5. 领域

看材料建议；收件或开写前确认；**随时可改**。不在注册死锁。交叉可主领域+附加。

## 6. 进门门槛 · 收件

> 通则见 [00 §6](00-用户与系统.md)。大厅点进④ ≠ 已过门槛。

**开写成稿前：** 至少有可依托的技术材料（说明/图纸/挖掘点/口述纪要等之一），不是空卷开写。  
手里有技术线索就能开（挖掘来的点，或发明人自带）——与业务口径一致。

### 6.1 进入检查表

| 必备 | 说明 |
|---|---|
| 技术材料线索 | 技术说明 / 图纸照片 / 挖掘创新点 / 口述或聊天纪要等，至少一类非空 |
| 目标确认 | 本次要做「交底书且质检全绿」（用户认） |
| 领域（可暂定） | 收件建议；开写前宜确认 |

无材料、只有「我想申请」→ 先补料或回前台分诊；可建议先③若实为挖点，**不假装已开写成稿**。

### 6.2 收件对照

案卷规则见 [00 §5](00-用户与系统.md)。

| 来源 | 做法 |
|---|---|
| 前台领进 | **继承**；核进入检查表差额 |
| 大厅直达 | **短收件** + 进入检查表 |
| ③ 工单 | 看批注与创新点；核材料线索 |
| 上家标签 | 先补 / 带着干（须留痕） |

### 6.3 进部后分流（薄）

| 情况 | 动作 |
|---|---|
| 材料实为「要挖点/拆案」 | 建议工单/直达③；用户坚持留④可，但缺创新点清单则进入门槛缺口留痕 |
| 已有合格交底、只要递交 | 建议⑤（见 [01](01-接待与分诊.md)） |
| 关键事实没有 | 补材料或暂停，不空转成稿 |

## 7. 部内怎么干

1. 负责人与用户对齐：目标＝交底书且质检全绿；是否加查新等。  
2. 核对进入检查表。  
3. 分配（能一个就一个；可串可并）——见 §3.2–3.3。  
4. 成稿事实 → **用户确认**（§4.1 硬请示）。  
5. 质检 → 优化再检，直到全绿（§4.2）。  
6. 用户确认可交⑤ → **部间工单**（§8.1）+ 案卷。

并行冲突由负责人汇总选项给用户，不私下定案。

### 7.1 段间交出（可中停）

| 段 | 案卷宜有 |
|---|---|
| 门槛 | 进入检查表通过记录 |
| 成稿 | 交底书正文草稿/定稿候选 |
| 事实确认 | 当前用户确认记录 |
| 质检 | 末次检测摘要；全绿或未关闭项清单 |
| 选做 | 查新/顾问稿或「未做」备注 |

---

## 8. 多次优化 · 缺料 · 交⑤

| 情况 | 做法 |
|---|---|
| 表述/结构问题，材料够 | 限定焦点再改 → 再质检 |
| **关键事实/数据/图根本没有** | **退回补材料或暂停**，不空转「优化」 |
| 需要成色视角 | 加派代理顾问 Agent |
| 用户暂不往下 | 暂停；案卷保留 |

**不能：** 跳过质检交⑤；未全绿开「现在做⑤」。

**开「现在做⑤」前置：** 交底书正文 + 成稿事实已确认 + **质检全绿**（＝结束检查表）。

### 8.1 部间工单谁打包（④→⑤）

| | 钉法 |
|---|---|
| **谁打包** | **交底部 · 部门负责人**（质检专家提供全绿摘要，不单独开工单） |
| **包内** | 结束检查表（§9）各项 + 案卷指针；缺口与选做未做备注 |
| **何时** | 用户硬请示「可交⑤」通过之后 |
| **⑤侧** | 申请部负责人接单；核进入检查表（可抽查/差分） |

---

## 9. 结束检查表（交⑤案卷必备）

| 必备 | 说明 |
|---|---|
| 交底书正文 | 至少含问题 / 方案 / 效果等核心块（随领域模板） |
| 成稿事实确认记录 | 当前用户已确认 |
| 质检全绿记录 | 含末次检测摘要；**无未关闭红灯** |
| 领域 | 当前选用的领域/模板 |
| 缺口与备注 | 选做未做（如未查新）、已知提醒 |
| 工单 | 现在做 / 以后做 / 批注等 |

≠ ⑤：说明书、独权、申不申终裁。

### 9.1 走通画像（薄 · 对齐业务惯用）

| ID | 画像 | 产品上必须看见 |
|---|---|---|
| **D1** | 发明人主操成稿 | 事实确认 + 全绿；可无 IP 顾问任务 |
| **D2** | 有企业 IP 惯用 | IP 顾问按需；**有无该任务不挡全绿交⑤**（④-b 可跳过） |
| **D3** | 代理陪同/诊断 | 代理顾问可出诊断稿；对人签字另走；系统全绿仍必做 |

共性：**未全绿不交⑤。**

---

## 10. 依据链

成稿：材料/原话痕迹，禁补造。  
质检：检测项+原文位置（必有）。  
检索若做：命中可核。  
交⑤：结束检查表齐。

---

## 11. 用语对照

| 业务章程 | 产品逻辑 |
|---|---|
| 发明人确认 | 成稿事实确认（**当前用户**） |
| 检测全绿才合格 | **质检必做，全绿才可交⑤** |
| ④-b 企业 IPR（无岗可跳过） | **IP 顾问按需**；无该任务＝不派，不挡全绿交⑤ |
| 诊断报告专家签字 | 代理顾问可出诊断稿；**对人签字**＝套餐另走 |
| 可选查新改稿 | 检索专家按需（交底向） |
| 交代理开案 | 全绿后部间工单 → ⑤ |

## 12. 一期够用

用户↔负责人↔专家；进入检查表；事实确认；质检全绿；缺料不空转；结束检查表；D1–D3；部间工单；前台不进部派活。  
编制加厚：合并呈现、时序、请示矩阵、质检节奏、段间交出、④→⑤谁打包（§3.2–3.3、§4.1–4.3、§7.1、§8.1）。

**一期可薄：** 诊断数据回流模型、深度领域模板差异。  
**不做：** 申请文件；申不申终裁；⑤接案理解替代；撮合真人代理人平台。
