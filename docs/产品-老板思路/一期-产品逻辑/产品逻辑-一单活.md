# 产品逻辑 · 一单活（理念落到全链）

> **之上**：[`../一期-产品理念.md`](../一期-产品理念.md)  
> **之下**：[`00-用户与系统.md`](00-用户与系统.md)～[`08-复盘.md`](08-复盘.md) 的门槛、合格线、工单、编制。那些条文继续有效。  
> **本文钉什么**：产品逻辑的主语。一单活怎么被这支团队办完。  
> **本文不钉**：屏上用词、头像、提醒句；八部检查表全文；工程实现。  
> **冲突**：理念 > 本文主语 > `00`～`08` 的闸门细则。闸门不改；若某段把用户写成「过闸的人」，以本文为准改叙述，不改合格线本身。  
> **状态**：2026-11-03 收口 · 未试点

---

## 0. 一句

用户把**一件事**交给一支已经组织好的团队。团队在对应部门的工作台上把这件事做成产出。做到要拍的地方才请示。办完一站，把产出和未决问题交给下一站接着干。

卖的是带团队干，不是一张张门槛表。

---

## 1. 主语

| | 是 | 留在下层，不当主语 |
|---|---|---|
| 用户要办的 | **一单活**（一份案卷） | 功能菜单、模型、Prompt |
| 谁在干 | 该部门的专家，在**工作台**上改这份产出 | 部门说明书、「本职 / 不办」文案 |
| 用户在干什么 | 当领导：看活、该拍才拍 | 填检查表、对条文 |
| 纪律 | 进入门槛、合格线、依据链 | 它们约束能不能移交，不代替这单活 |

`00`～`08` 把进得来、出得去、工单四种状态写全了，**保留**。缺的是上面这句主语，所以前台会变成分析流程，工作台会变成步骤壳，移交会变成一条「已交代」。

---

## 2. 全链

```
一单活（案卷）
  → 听懂：这单要办成什么、先交给哪个部门
       前台听，或用户自己把事交给某部
  → 工作台：专家按这单在写、在改产出
       自决的活留在稿上
       要拍的地方才请示（方案 + 依据 → 点头或退回）
  → 合格线过了，才把产出和未决问题交给下一家
       下一家在自己的工作台上接着干
  → 点过的留在案卷；改了技术含义必须再请示当时的当前用户
```

待办只收两样：要你拍的请示，必须让你知道的期限。专家自决的进度留在工作台。待办在左栏，大厅不另贴一条。

---

## 3. 听懂

前台的逻辑只有一件事：把用户说的变成「这单要办成什么、先交给谁、已知什么、还缺什么」，写入案卷。

| 规则 | |
|---|---|
| 前台不办部门的活 | 不写交底、不过申请线、不代替进入门槛 |
| 听懂要能被改口 | 用户可以改交给哪个部门；确认的是这件事，不是一份问卷 |
| 有案续这单 | 写入当前案再进部；无案才建案；可另开新案 |
| 直达同规则 | 熟客不经前台，进部时这单的来意一样进案卷，工作台按这单开干 |
| 进门看得见 | 前台和八部都在；前台不是闸门 |

听懂的结果必须改变工作台上的产出。只在部台顶再贴一句来意，等于没听懂。

### 3.1 第一稿（八部通用）

案卷里有一句**这单要办成什么**（前台确认，或直达时补上的同一句）。

1. 进入检查表是开写前的纪律：不过，就不写这稿，也不假装已开干。  
2. 一过，工作台第一份产出就是按这句展开的稿，不是空白模板，也不是检查表本身。  
3. 上家移交同理：下家第一稿吃的是交来的产出和未决问题，加上这句还要办成什么。

| 部 | 门槛过了之后的第一稿 |
|---|---|
| ① | 项目卡草稿：名称、方向从这句来 |
| ② | 已经结构化的问题，和几条路径草稿 |
| ③ | 从现有资料抽出的待确认创新点 |
| ④ | 按这句要写清的技术事实起笔的交底草稿 |
| ⑤ | 按「要把哪份交底写成可递交文件」起笔的理解稿；不过交底门槛则不写 |
| ⑥ | 按这轮通知书要答什么起笔的争点人话 |
| ⑦ | 这件权利的期限与费用，落在台账上 |
| ⑧ | 本轮要回答的复盘问题，再写成报告 |

---

## 4. 工作台

工作台是专家**正在做这单**的地方。第一眼是这单的产出：稿、改动、做到哪。

| 规则 | |
|---|---|
| 产出已按这单展开 | 来意是「把交底做成申请」，主栏就是这份申请在写，不是空白模板 |
| 自决不打扰 | 起草、检索、格式、内部质检留在稿上 |
| 请示是干活中的一下 | 方案、依据、点头或退回；不是把工作台换成待办页 |
| 依据要能签字 | 来源 / 推演 / 对比；缺链不上关键交付 |
| 三线不混 | ④全绿、⑤过线、⑥本轮 D 过线分开展示 |
| 前台不进部派活 | 进部后由该部负责人主持 |

岗位边界写在编制里，需要时专家用拒绝和请示体现。不在工作台顶用提醒句代替。

---

## 5. 移交

一单活换部门，案卷跟着走。移交的是**正在做的产出 + 未决问题**，不是让用户把事再说一遍。

| 规则 | |
|---|---|
| 合格线未过 | 不能开「现在做下一部门」并假装已经合格 |
| 合格线已过 | 用户确认后交下家；非阻断说明可备注，不拿来跳线 |
| 下家接着干 | 工作台上是上家交来的产出和还要补的事实，不是新的空白表 |
| 退回 | 理由回到交出的部门，记在这单案卷里 |
| 带病 ≠ 未合格 | 选做项跳过、已知提醒，可以明示后流转 |

工单四种状态（现在做 / 以后做 / 退回 / 批注）仍以 [`00` §7.2](00-用户与系统.md) 为准。

---

## 6. 八部：各干各的活

合格线意识与 [`00` §6.1](00-用户与系统.md) 相同，此处只钉「工作台上是什么、你拍什么」。细则仍以 `02`～`08` 为准。

| 部 | 工作台上的活 | 你要拍的 | 办完才能交给下家 |
|---|---|---|---|
| ①立项 | 把这单立成可引用的项目 | 方向与状态 | 项目可引用 |
| ②激发 | 从问题走到可选路径 | 选题或跳过 | 选题或跳过留痕 |
| ③挖掘 | 从资料里挖出可做的点 | 点与去向 | 点包可交④，或报告路径 |
| ④交底 | 把技术事实写成交底 | 事实是否属实 | 全绿 |
| ⑤申请 | 把合格交底写成申请文件 | 申不申、范围、是否递交 | 过线并确认递交 |
| ⑥答复 | 按通知书写这一轮答复 | 策略与是否递交 | 本轮 D 过线并确认递交 |
| ⑦维护 | 管期限、年费、台账 | 缴费或放弃类动作 | 托管纪律过线 |
| ⑧复盘 | 写这一轮复盘报告 | 维持或放弃，或明示只读 | 报告已确认 |

①可跳过，不挡后面真在办的活；需要聚合键时事后补挂。情报、查新不占第九个部门，在办案的部门里用。

任一用户可进任一部门。专家向**当前用户**汇报。企业与代理是同一套系统里的两种用法，不锁部门。

## 7. 领导看见的

| 表面 | 逻辑 |
|---|---|
| 大厅 | 把这单交出去：前台或直达某部。不堆待办、不堆合格线 |
| 工作台 | 这单正在被做 |
| 左栏待办 | 要你拍的、必须知道的期限。点进去回到那份正在做的产出上拍 |
| 案卷 | 材料、点过头的请示、移交。换人可接着已确认的部分干 |

## 9. 每一页

产品面上的每一页，都是这支团队在办某一单时的一个位置。用户在该页的主操作，只能是下面四件事之一：把这单交出去、看正在写的产出、在该拍的地方点头或退回、让下一站接着干。

页顶不贴理念口号。这一页若答不出「哪一单、谁在办、我此刻该做上面四件里的哪一件」，这页就还没体现理念。

| 页 | 用户在做的事 | 主操作 |
|---|---|---|
| 登录 | 来当这支团队的当前领导 | 企业或代理只是用法；选完进大厅，部门不按身份锁 |
| 画像种子 | 让团队知道你大致是谁 | 可跳过；不在这里选今天去哪一部 |
| 大厅 | 把一件事交给团队 | 对前台说要办成什么，或自己走进某部 |
| 前台确认 | 确认这单要办成什么、先交给谁 | 确认后进入该部，主栏已是第一稿 |
| 项目列表 | 看团队手上的各单 | 点开某一单，看到办到哪、在谁手里 |
| 开新案 | 立一单 | 名称就是这单要办的事 |
| 案首页 | 看这一单现在办到哪 | 主按钮进入正在办的部门看稿 |
| 本案部门 | 看这一单哪些部门在办、哪里有缺口 | 点部门进工作台；本页不交卷、不拍板 |
| 部门工作台 | 看专家正在写的产出 | 第一眼是稿；请示出现在这份稿上 |
| 待办 | 处理要你拍的，和必须知道的期限 | 点一条，回到那份稿上拍或处理期限 |
| 请示详情 | 看方案和依据 | 点头或退回；退回后该部接着改这份稿 |
| 案卷 / 判断 | 回看这一单确认过的材料和拍过的板 | 换人从已确认的地方接着干 |
| 期限台 | 看这一单的程序期限 | 处理动作回到⑥或⑦的工作台 |
| 成员 | 看谁是这一单的当前拍板人 | 换人即换领导；不把权限后台当成办事 |
| 账单 / 委托 | 看这一单的委托和费用 | 产生官费或付款的动作仍要你拍 |
| 编制 | 看团队里有哪些部门和专家 | 办活回到大厅或某一单的工作台 |
| 资产 | 看可归入案卷的材料 | 材料进了这一单，才算在办；全局库不代替案卷 |

期限台、成员、账单、编制、资产是这一单的后勤。第一句说明自己在帮哪一单，主按钮回到正在办的部门。

工程旁路（sessions、harness、lab、sandbox、席位演练）不按这个体验装成团队。样机若露出，标非产品面。

## 10. 每一步操作

同一个动作，在每一页的手感相同。

| 操作 | 体验 |
|---|---|
| 对前台说一句话 | 团队听成「要办成什么、交给谁、已知什么、还缺什么」 |
| 确认 | 确认的是这件事和交给谁，或稿上的方案；确认去向的同时，第一稿已经按这句起笔 |
| 直达某部 | 自己把这单交给该部；短收件补上同一句；第一稿同样开 |
| 改稿、检索、质检 | 留在稿上，不把你叫去待办 |
| 请示 | 方案加依据，就在这份产出旁边；点头继续写，退回继续改 |
| 点待办 | 回到那份正在做的产出，不另开一张与稿无关的审批单 |
| 移交 | 下家工作台上是交来的产出和未决问题 |
| 退回 | 理由回到交出的部门，记在这一单里 |
| 看期限 | 知道哪一单要到期；处理仍是进⑥或⑦办事 |
| 换人 | 新的当前用户接着已确认的部分；还没拍的仍然要拍 |
