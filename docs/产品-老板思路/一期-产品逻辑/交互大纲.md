## 1. 原则（交互层只认这些）

| # | 原则 |
|---|---|
| 1 | **像进公司**：先进大厅，再进部门；不是功能列表首页 |
| 2 | **领导＝当前用户**：关键结论以「请示 → 你拍」出现，不偷偷绿勾 |
| 3 | **三线勿混**：④全绿 / ⑤过线 / ⑥本轮 D 过线 **分开展示、分名词** |
| 4 | **带教可淡出**：首次多一句「这步要你拍什么」；熟客直达、可关说明 |
| 5 | **缺料诚实**：没有就写没有；不把猜测写成已确认 |
| 6 | **前台不进部派活**：进部门后换「部门负责人」主持 |
| 7 | **用户＝老板**：大厅能看见「要你拍的 / 快到期的 / 进行中的」，不是只有进部门才知道 |

## 2. 信息架构（顶层）

```
大厅
 ├─ 老板待办（请示 / 期限催办 / 进行中工单）← 一期必有薄版
 ├─ 前台（接待）
 ├─ 八部门入口（①～⑧，可带「有待办」角标）
 └─ 当前案卷摘要

部门内（任一①～⑧）
 ├─ 部门壳（负责人条 · 专家名册 · 合格线 · 案卷抽屉）
 ├─ **工作台**（主作业区：主栏文稿 + 侧栏对话/请示/依据）
 └─ 请示（硬请示钉侧栏顶或打断式；不单靠聊天）
```

贯穿入口（情报官等）：**不**做成第九部门大门；见编制总览 §4。

## 2.1 各部门有没有「日常任务」？

> **多数不是打卡日常**，是**案卷触发**；只有 ⑥⑦（及⑧窗口期）带持续提醒。

| 部 | 节奏 | 用户（老板）常看见什么 |
|---|---|---|
| 前台 | 按需 | 分诊建议待你确认去向 |
| ① | 事件 | 建项/改状态待确认；无每日任务 |
| ② | 事件 | 选题、收藏/去向待拍；可整段跳过 |
| ③ | 事件 | 确认点/去向、核验勾选、交④待拍 |
| ④ | 事件 | 事实确认、可交⑤；质检循环中「待你看」 |
| ⑤ | 事件 | 理解、申不申、范围、确认递交 |
| ⑥ | **有期限** | 本轮答复截止；重大缩限/递交待拍；超期升级 |
| ⑦ | **持续托管** | 三级期限/年费提醒；缴费前确认；旗舰巡检异常 |
| ⑧ | 年末/阶段窗口 | 读报告、逐件维持/放弃或只读不拍 |

**专家自决的活**（起草、检索、质检出项）默认**不**刷老板待办；只有要你拍、要你知情的催办、进行中需你盯的工单才上大厅。

## 2.2 老板待办 · 三类（一期钉）

| 类 | 含义 | 谁产生 | 老板动作 |
|---|---|---|---|
| **A. 待你拍（请示）** | 硬请示未关 | 各部请示矩阵 | 确认 / 改 / 暂停 |
| **B. 期限催办** | ⑥答复期、⑦年费/官费等临近或超期 | ⑥§6.5、⑦三级提醒 | 进部处理或认延期/放弃等 |
| **C. 进行中** | 「现在做」工单未结、部内卡在待你确认 | 部间工单 + 段进度 | 点进该部接着干 |

展示规则（薄）：

1. **大厅第一眼可见**：待办条或「今日要你拍 N · 催办 M」；点开列表。  
2. **排序**：超期 → 今日/临近期限 → 待你拍 → 进行中。  
3. **部门名牌角标**：该部有 A/B 类时亮一点（数字可薄）。  
4. **不是**运营仪表盘：不堆授权率、不堆八部 KPI。  
5. **空态**：无待办时写「各部门暂无要你拍的事」——像老板没事，不是系统坏了。  
6. **提醒渠道**：一期以**系统内**为准（⑦ 短信/邮件＝D11 缺口，不超卖）。

条目字段（列表一行）：来源部门 · 案卷名 · 一句话事由 · 截止（若有）· 去处理。

## 3. 大厅 · 第一眼

### 3.1 必有

| 区块 | 用户看见 | 交互 |
|---|---|---|
| **品牌/公司一句** | 研发创新团队；专家向你汇报 | 非功能菜单堆叠压过这句话 |
| **老板待办** | 待你拍 / 期限催办 / 进行中（§2.2） | 点开列表 → 进部或打开请示 |
| **前台** | 「需要帮忙从这儿开始」 | 点进前台对话/收件 |
| **八部门名牌** | ①～⑧ + 一句话；可有待办角标 | 点击直达 |
| **案卷条（可薄）** | 当前卷；与待办可分可合 | 点开案卷 |

### 3.2 不要

- 把八部藏进「更多」或只剩前台一个入口  
- 首页堆统计看板、多卡片营销、假「每日任务打卡」  
- 用工作流节点图替代部门名牌当第一眼  
- 把专家自决进度条全刷给老板（噪音）  

### 3.3 前台内（分诊）

| 步 | 界面 | 硬请示 |
|---|---|---|
| 上传后 | 材料清单 + 意图假设 + **建议部门**（主推+备选+理由） | — |
| 确认目标 | 「这次先去 X 部，对吗？」 | **是 · 用户确认去向** |
| 领进前 | 交办材料/缺口列表 | — |
| 领进 | 进入部门；前台会话可收起 | — |

两路同强 → **先问清一句**再领（见 01 冲突规则），不静默塞部。

## 4. 部门内 · 通用壳 + **工作台**

> **缺口补钉：** 此前只有「协同场」一笔；**工作台**＝进部门后真正干活的主表面，一期须单独说清。  
> **和仓内 apps：** `@ip/mid`（作业中台）/ `@ip/workbench`（办理台）是工程壳名；**产品语义上的工作台**以本节为准，实现时可映射，不倒过来用壳名定义产品。

所有部门共用同一壳；部内段名不同（④成稿/质检；⑤ A/B/C…）。

### 4.0 三层别混

| 表面 | 是什么 | 不是 |
|---|---|---|
| **大厅** | 公司门口：老板待办 + 前台 + 八部大门 | 写交底/权要的地方 |
| **部门壳** | 进某部后的外框：负责人、名册、合格线、案卷抽屉 | 文稿编辑本体 |
| **工作台** | 壳内**主作业区**：读/改长文 + 结构化侧栏 + 与专家对话 | 纯 IM；也不是 BI 仪表盘 |

进部路径：大厅点部门（或待办「去处理」）→ 部门壳 → **默认落在工作台**。

### 4.1 顶栏（部门壳）

| 元素 | 说明 |
|---|---|
| 部门名 | 如「交底部」 |
| 返回大厅 | 始终可回；不丢案卷 |
| 本部门合格线状态 | 见 §6；未达显示「未过线 / 进行中」 |
| 期限（⑥⑦） | 有则醒目；超期升级态不可静默 |

### 4.2 负责人条

- 「部门负责人」向你汇报进度、建议派谁、汇总冲突选项  
- **不是**前台；进部后默认对接人  

### 4.3 专家名册

| 规则 | 说明 |
|---|---|
| 展示 | 当前启用的专家名片（可合并：如「交底专家」兼成稿+润色） |
| 点名片 | 工作台内聚焦该专家对话/其负责产出 |
| 质检席 | **不可**与成稿合并成「看起来已经检过」的一张糊名片（④⑤⑥纪律） |
| 未派选做 | 名册灰显或「未请来」；点了走「建议后请示」 |

### 4.4 工作台（主作业区 · 一期钉）

#### 4.4.1 谁的工作台 · 偏什么

| | 钉法 |
|---|---|
| **主用户** | **当前用户（老板）**在场监工/拍板；专家在台上干活 |
| **作业形态** | **偏文字知识工作**：交底、权要、说明书、意见陈述、复盘报告——长文 + 修订 |
| **不是** | 纯聊天泡泡墙；也不是只点按钮的表单向导（可有短表，不承重） |
| **也要结构** | 争点表、权项树、检查表红绿、期限、特征表——**旁路结构化**，服务读改长文 |
| **壳不变** | ③⑤⑥ 代理更常主操；②④ 企业更常来；**系统不按身份换壳**；只调**密度态**（§4.4.3） |

#### 4.4.2 布局（低保真约定）

```
┌─ 部门壳顶栏 / 负责人 / 合格线 ─────────────┐
│ 专家名册（可收）                              │
├──────────────────────┬──────────────────────┤
│ 主栏：文稿 / 主产出     │ 侧栏（自上而下钉死）   │
│ （可全屏读改）          │ ①硬请示 ②依据 ③对话  │
├──────────────────────┴──────────────────────┤
│ 底：段进度 · 打开案卷抽屉                     │
└─────────────────────────────────────────────┘
```

| 区 | 放什么 |
|---|---|
| **主栏** | 当前段主产出全文；版本可切；质检/争点命中处可定位高亮 |
| **侧栏** | 见 §4.4.4 层级；禁止把三层糊成一条时间线 |
| **进度条** | 未开始 / 进行中 / **待你确认** / 已过 |
| **空主栏** | 尚未成稿：提纲、问诊要点、或「专家正在起草」+ 可看中间稿 |

手机：主栏优先；硬请示用底部表/全宽卡——**不能只活在滚没的聊天里**。

#### 4.4.3 密度态（同一壳 · 两种默认）

> **不换壳、不换身份 ACL**；按「这次进部要干什么」调默认焦点。可手动切换。

| 态 | 何时默认 | 主栏 | 侧栏 | 名册 |
|---|---|---|---|---|
| **老板轻量** | 从大厅「待你拍」进来；或本段已过线只差硬请示 | 只读/批注为主；大字结论区置顶（要拍什么 + 一两句依据摘要） | **硬请示钉满顶**；对话默认收起 | 收起 |
| **主笔** | 进部做撰写/质检/策略；或点「打开全文编辑」 | 可编辑全文；结构旁路（权项树/争点/红绿）可开 | 对话展开；请示仍钉顶不沉底 | 可展开点专家 |

| 规则 | 说明 |
|---|---|
| 待办进部 | A 类待办 → **默认老板轻量**；处理完可一键切主笔 |
| 熟客直达 | ③⑤⑥ 惯用主操者可记住「本卷默认主笔」（一期可薄） |
| 禁止 | 用换壳假装换身份；轻量态藏掉硬请示 |

#### 4.4.4 侧栏层级（钉死优先级）

自上而下，**不可**把下面层顶掉上面层：

| 序 | 层 | 内容 | 规则 |
|---|---|---|---|
| 1 | **硬请示** | 确认卡（结论 + 依据入口 + 确认/还要改/暂停） | 有则**钉顶**；未处理完不得只靠滚聊天完成；可叠多张，按时间/紧迫 |
| 2 | **依据 / 结构旁路** | 命中原文、对比、权项树入口、争点列表、质检红项跳转 | 服务签字；点条目 → **主栏定位**，不另开迷宫 |
| 3 | **对话** | 负责人/专家汇报、追问、自决进展回放 | 默认可滚；**建议后请示**可以卡片插在对话流，但硬请示仍复制一份到层 1 |

自决进展：不必打断；可在对话流留「已自决摘要」，老板轻量态可折叠。

#### 4.4.5 修订闭环（文字工作最小集）

| 步 | 交互 |
|---|---|
| 发现问题 | 质检红项 / 专家批注 / 用户批注 → 主栏锚点 |
| 谁改 | 默认请对应专家改；用户主笔态可直接改 |
| 回写 | 改完该项变黄「待复检」→ 复检绿或仍红 |
| 过线 | 仅当该部合格线规则满足；**过线按钮 ≠ 硬请示确认递交** |
| 版本 | 至少「当前稿 / 上一确认稿」可切；冲突双稿一期可薄（提示选一边） |

一期不做：实时多光标同卷、精细 track-changes 产品化（能留痕迹即可）。

#### 4.4.6 主链工作台差分（④⑤⑥ · 必钉）

> 共用壳与侧栏层级；**主栏模式不同**。薄部见 §4.4.7。

| | **④ 交底** | **⑤ 申请** | **⑥ 答复** |
|---|---|---|---|
| **主栏主物件** | 交底书**单篇正文** | **权项**与**说明书**（可分页/分栏切换） | **意见陈述** + **修改对照**（可左右或上下） |
| **结构旁路** | 质检项列表 → 跳正文锚点；可选查新备注 | **权项树/列表**；A–J（或质检）进度条；理解要点卡 | **争点列表**（中立→策略后仍可回看）；期限条醒目 |
| **段进度** | 成稿 → 质检循环 → 全绿 | A 理解 → B 查新/申不申 → C 撰写质检 → 过线 | A 争点 → B 策略 → C 起草 → D 审核过线 |
| **老板轻量默认焦点** | 「事实对不对」「可否交⑤」 | 「理解对不对」「申不申」「确认递交」 | 「缩限是否接受」「确认本轮递交」 |
| **主笔默认焦点** | 改交底段落；清红项 | 改权项范围/说明书表述；清 A–J 红 | 改陈述与对照；策略后定调不与 A 混步 |
| **硬请示（验收）** | 成稿事实确认；可交⑤ | 理解确认；申不申；确认递交 | 重大缩限；确认本轮递交 |
| **合格线用词** | 交底质检**全绿** | 申请文件可递交（**过线**） | 本轮答复可递交（**D 过线**） |
| **特别禁止** | 全绿按钮兼作可交⑤ | 过线兼作确认递交；B 未拍就锁独权终稿 | A/B 同屏一次定调；无通知书硬答 |

**⑤ 主栏分页约定：** 默认「权项 | 说明书」切换；理解确认前可先出「理解摘要」单页（短），确认后再进长文主笔。

**⑥ 对照约定：** 修改对照与陈述同属主栏，争点列表在侧栏层 2；点争点 → 陈述/对照定位。

#### 4.4.7 各部门工作台主物件（薄部 + 汇总）

| 部 | 主栏典型物件 | 备注 |
|---|---|---|
| ① | 项目卡片（短） | 轻量为主 |
| ② | 问题卡 / 路径卡 / 方案文 | 可多卡，仍偏文 |
| ③ | 创新点表 + 报告文；排案结果 | 表+文；主笔常见 |
| ④ | **交底书正文** | 见 §4.4.6 |
| ⑤ | **权项 + 说明书** | 见 §4.4.6 |
| ⑥ | **意见陈述 + 修改对照** | 见 §4.4.6 |
| ⑦ | 台账行 + 期限/费用明细 | **偏表**；催办用人话卡（侧栏层 1/对话），不是纯单元格 |
| ⑧ | **复盘报告正文** + 维持/放弃清单 | 只读不拍时清单不可改台账 |

### 4.5 案卷抽屉

| 页签（一期可薄） | 内容 |
|---|---|
| 材料 | 已有 / 缺口 |
| 检查表 | 进入 / 结束；勾选与留痕 |
| 工单 | 现在做 / 以后做 / 退回；谁打包可见 |
| 判断痕迹 | 硬请示记录、认风险、过线摘要（沉淀用） |

## 5. 请示 · 怎么出现

对齐编制「自决 / 建议后请示 / 硬请示」。

| 档 | 界面表现 |
|---|---|
| **自决** | 专家在协同场推进；可不打断；结果可回看 |
| **建议后请示** | 负责人/专家出建议卡：「建议请来检索专家 / 建议去④」→ **同意 / 改主意** |
| **硬请示** | **必须**明确确认控件；未确认不得把下游标成已完成 |

### 5.1 硬请示控件（统一模式）

```
【请示】标题（如：确认交底事实）
简要结论 + 依据入口（链到原文/检测项）
[ 确认 ]  [ 还要改 ]  [ 暂停 ]
（认风险类另附勾选：「我了解风险仍继续」）
```

| 主链硬请示（验收必能找到） | 部 |
|---|---|
| 成稿事实确认；可交⑤ | ④ |
| 理解确认；申不申；确认递交 | ⑤ |
| 重大缩限；确认本轮递交 | ⑥ |
| 确认建项；缴费前确认；逐件维持/放弃或只读不拍 | ① / ⑦ / ⑧ |
| 本次去哪一部 | 前台 |

### 5.2 禁止

- 用自动跳过的 Toast 代替硬请示  
- 硬请示与「已全绿/已过线」绑成同一个按钮糊掉（先过线，再单独「可交⑤/确认递交」）  
- 对外文案写「模型已自动批准」

## 6. 合格线 · 怎么显示（三线勿混）

| 线 | 界面用词（钉） | 出现位置 |
|---|---|---|
| ④ | **交底质检全绿** | ④ 顶栏；交⑤工单前置条件 |
| ⑤ | **申请文件可递交（过线）** | ⑤ 顶栏；确认递交前置 |
| ⑥ | **本轮答复可递交（D 过线）** | ⑥ 顶栏；确认递交前置 |

**不要：** 统一叫「已完成」「All green」「QC Pass」而不标部门。  
**工单上：** 「现在做⑤」仅当④全绿；图标/文案旁可注「交底已全绿 · 申请尚未过线」。

其他部用该部自己的合格线短名（见 [00 §6.1](00-用户与系统.md)），不套用④⑤⑥三词。

## 7. 带教淡出

| 状态 | 交互 |
|---|---|
| 首次进某部 | 短说明：「本部门办完的标志是…；要你拍的是…」；可「知道了」 |
| 再次进入 | 默认收起；设置里可重开「部门说明」 |
| 熟客/代理 | 大厅直达部门；前台长分诊不强制 |
| 选做建议 | 不连环强制引导；一次建议 + 用户拒可记住本卷不再烦（一期可薄） |

带教**不是**挡住协同场的全屏强制课。

## 8. 主链关键屏（验收清单）

对照故事板 Happy path；线框阶段勾选「有没有这块」。

| 屏 | 必备 |
|---|---|
| 大厅 | 前台 + 八部 + **老板待办** +（可）案卷条 |
| 老板待办列表 | A 待拍 / B 催办 / C 进行中；可点进部 |
| 前台分诊结果 | 建议部 + 用户确认去向 |
| ④ 工作台 | 主栏交底正文；侧栏①请示②质检锚点③对话；全绿与「可交⑤」分离；支持轻量/主笔 |
| ④→⑤ 工单 | 打包方＝交底部负责人；结束检查表摘要 |
| ⑤ 工作台 | 权项|说明书切换；理解摘要页；A/B/C；申不申；过线≠确认递交 |
| ⑥ 工作台 | 陈述+对照主栏；争点在侧栏层2可定位；A→B 不混步；期限；D≠确认递交 |
| 老板轻量进部 | 从 A 待办进④/⑤/⑥ → 默认轻量态，硬请示钉顶 |
| 案卷·判断痕迹 | 能回看硬请示与认风险 |

支路 B1–B8：对应入口存在即可（直达④/⑤/⑥、不申结案、超期升级、只读不拍、情报另链说明）。
