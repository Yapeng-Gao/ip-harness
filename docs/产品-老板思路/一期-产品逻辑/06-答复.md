## 1. 部门职责

官方通知来了、期限卡着：拆争点 → 定策略（**重大缩限由用户拍**）→ 写答复 → 审核确认后递交。

**硬产出（本轮）：** 意见陈述书（+ 修改对照表/修改后申请文件若有）+ **递交回执**；期限与回执回写⑦。  

**不做：** 预测授权率；把交底/说明书重写充数；在此**首次**起草权项（那是⑤）；替企业代签范围损失；编法条/编对比文件/编实验数据。

## 2. 产品里有谁（只三类）

| | 说明 |
|---|---|
| **用户** | 谁登录谁是用户；听汇报、拍板（含重大缩限、是否递交） |
| **部门** | 答复部（OA） |
| **专家** | 全部 Agent；能一个办完不硬拆 |

套餐《答复策略建议书》对人签字＝服务交付另走，不进产品编制；系统内可出策略选项稿。  
组织里要「发明人核技术 + 企业拍缩限」→ **换人登录**或同一人兼拍留痕（[00 §6.1](00-用户与系统.md)）。

### 2.1 谁主持——部门负责人（不是前台）

| | 本产品 |
|---|---|
| **前台** | 大厅分诊；不进部内派活 |
| **部门负责人** | 收文/门槛、分活、汇总策略选项、组织递交确认 |

```
用户 ←→ 部门负责人
           ↓ 分配
     收文解析 / 策略 / 起草 / 审核·递交 …（可串可并）
用户可 1:1 某专家 · 随时看产出
```

惯用上代理更常主操；企业侧常来拍范围与递交——系统不锁身份。

## 3. 编制：能一个就一个，要拆就拆

| 专家 | 对应业务段 | 职责 |
|---|---|---|
| **部门负责人** | 全程 | 收件/门槛、分活、冲突汇总、盯期限、组织递交 |
| **收文专家** | **A** | 登记通知与期限；**中立**拆争点、对齐申请/对比文件；列缺料 |
| **策略专家** | **B** | 逐争点多方向选项 + 利弊（§4.2）；**重大缩限标给用户拍** |
| **起草专家** | **C** | 修改文本/对照表、意见陈述书、证据编排；不超 33 意识 |
| **审核专家** | **D** | 按争点查覆盖/策略一致/超范围/证据/形式；推动改到可递交 |
| **递交助理** | **D** | 期限与齐套形式、回执回写案卷与⑦（可与审核或负责人合并） |

活少可合并（如收文+策略、起草+审核）；逻辑上仍分岗。  
**硬分岗：** 中立解析（A）与策略生成（B）**禁止混成一步偷偷定调**——先拆清再出选项。

### 3.1 边界

| | 本部门 | 不是 |
|---|---|---|
| 审核 | 本轮答复覆盖争点、不超范围 | ⑤ 申请文件规则库 A–J 整库主路径（大改权项时可抽跑 A/F/G） |
| 策略 | 选项可见、推荐可驳、用户拍重大缩限 | AI 代签范围；只给一套闷头缩限 |
| 修改 | 针对通知书缺陷；33 边界 | 顺手乱改未指摘权项；超原申请加料救命 |
| 首次权项 | — | ⑤ 的活；此处只在已有申请文件上改 |
| 期限 | 本轮答复期限可见、可催、超期升级（§6.5） | ⑦ 年费/维持主作业；完整复审建模 |

### 3.2 合并呈现

| 活量 | 可合并呈现为 | 不可混 |
|---|---|---|
| 争点少、纯争辩 | 「答复专家」兼 C+D；A/B 可同人**分两步任务态** | A 产出未确认前不塞最终策略定调 |
| 常案 | 收文 / 策略 / 起草 / 审核 分席 | 递交助理可并审核或负责人 |
| 多争点缩限 | 策略席独立汇报缩前/缩后 | 重大缩限未拍不锁递交 |

### 3.3 协作时序

```
进入门槛（含期限）→ A 中立拆争点 → B 策略选项 →【硬】重大缩限等用户拍 → C 起草 → D 审核循环 →【硬】确认递交 → 回执/⑦
                                                              ↓ 下一通
                                                         新通知 → 新 A
```

| 段 | 默认可并 | 硬闸 |
|---|---|---|
| A | 读通知∥对齐申请文件 | 争点清单可核；不夹带定调 |
| B | — | **重大缩限/分案/放弃**用户拍（或先起草再终确认留痕） |
| C | B↔C 来回 | 拟改要点能指回已有记载 |
| D | 改稿∥再检 | **过线**后仍须**确认递交**；期限可见（§6.5） |

## 4. 必做 · 选做

| | 内容 |
|---|---|
| **必做** | **进入门槛**（须答复的官方通知 + 现行申请文件，§6）→ **A** 争点清单 → **B** 策略选定（重大缩限用户确认）→ **C** 答复稿 → **D 审核过线** → 用户确认递交 → 回执入案卷/⑦ |
| **强建议** | 修改对照表（有改则）；缩前/缩后人话给用户 |
| **选做** | 补实验（发明人供数）；所内第二意见；抽跑⑤ A/F/G 联检；实审请求等程序期提醒（可薄） |

**D 审核不能跳过。** 不过线 → 改 → 再检；可暂停；**不能**未审核或未过线却标「本轮已递交」。  
重大缩限/分案/放弃类：用户未拍不得当已定策略锁稿（可显式「先起草再终确认」留痕）。

**本轮合格线：** 见 §9.1；走通画像对齐业务 R1–R3（§9.2）。D 过线 ≠ ⑤申请过线（[00 §6.1](00-用户与系统.md)）。

**递交通道（一期钉法）：** 产品负责齐套、确认、**回执回写案卷与⑦**；向官方递交的具体通道**实现后置**，不在本文承诺已接通官报。

手法（争点字段、法条骨架、三步法/26.3 抓手、陈述三段式、审核清单）→ [业务章程](../一期节点/06-答复.md) + OA 资产；**产品逻辑不抄全文**。

### 4.1 手法真源

| 层 | 路径 |
|---|---|
| 业务边界与过线场景 R1–R3 | [一期节点/06-答复.md](../一期节点/06-答复.md) §5 |
| 解析/策略/陈述提示词 | [`OA答复-提示词终稿.docx`](../../各产品开发/OA答复/OA答复-提示词终稿.docx) |
| 审核（D） | [`OA答复审核/`](../../各产品开发/OA答复审核/)（含拼装提示词） |

### 4.2 策略方向（B · 产品层）

每个争点至少摊开方向；推荐可驳；**范围变动部分由当前用户拍**。

| 方向 | 含义 | 谁拍 |
|---|---|---|
| **争辩** | 基本不改或微澄清；拆审查员逻辑链 | 代理建议；用户知情 |
| **修改** | 缩限/澄清/删权项 | **重大缩限 → 用户** |
| **组合** | 改一点 + 争一点 | 范围变动部分 → 用户 |
| **补实验数据** | 效果/创造性需要 | 用户侧供数；公开风险知情 |
| **分案** | 单一性或止损另案 | **用户**（新费用） |
| **延期 / 放弃** | 程序选择 | **用户** |

约束意识（产品只记边界）：能争辩就不改；能改就不分案；争辩期望低时硬撑＝多一轮成本——利弊给用户，不代拍。  
进 C 前：每争点选定策略 + 理由；拟修改要点须能指回说明书/权项已有记载。

不影响 A→B→C→D 主路径。

## 6. 进门门槛

> 通则见 [00 §6](00-用户与系统.md)。大厅点进⑥ ≠ 已过门槛。

**开干主作业前：** 通常须有**须答复的官方通知** + **现行申请文件**（权项+说明书等）+ 申请号意识（入⑦/案卷）。  
仅有交底、尚未递交 → 应去⑤，不在此开写答复。

### 6.1 进入检查表

| 必备 | 说明 |
|---|---|
| 官方通知原文 | 补正 / 一通·二通… / 驳回等须答复类 |
| 答复期限 | 以通知书为准；写入案卷并挂 §6.5 |
| 现行申请文件 | 权项+说明书（及附图等）；来自⑤案卷或用户自带 |
| 申请号 | 案卷或通知书可核 |
| 对比文件 | 通知书列明的；缺则标风险，紧急可认风险继续 |
| 历史轮次（二通及以后） | 上一轮陈述/修改在卷或标缺失 |

### 6.2 收件对照

| 来源 | 做法 |
|---|---|
| ⑤ 工单「现在做⑥」/有 OA | 继承案卷；核进入检查表 |
| 前台领进 | 继承前台字段；核差额 |
| 大厅直达（上传通知书） | 短收件 + 进入检查表 |
| 无通知、未递交 | 拒开主路径；建议⑤或说明缺件 |
| 上家标签 | 先补 / 带着干（须留痕） |

### 6.3 门槛不过

| 情况 | 动作 |
|---|---|
| 无通知书 | 不进入 A 主作业；引导补传或回⑤ |
| 有通知无申请文件 | 补现行文本；不可凭交底直接答 OA |
| 缺对比文件 | 列清单；可认风险继续解析，策略阶段加重提示 |
| 期限将至/已过 | 按 §6.5 升级；选项交用户 |

### 6.4 进部后问题分流

| 问题类型 | 谁主责 | 动作 |
|---|---|---|
| 缺通知/缺申请文件 | 进入门槛 | §6.3 |
| 争点拆不清 / 材料缺环 | A | 补料；标「原文未明确」；不编造 |
| 重大缩限未拍板 | B + 用户 | 不锁终稿递交 |
| 超范围 / 覆盖不全 | D | 部内改；禁加原文没有的技术方案救命 |
| 要补实验数据 | 用户侧供数 | 无编数据；公开风险知情 |
| 根因是交底/申请写歪且须大改事实 | 视情况工单回⑤（或④） | 不在⑥假装能加新披露绕过 33 |

### 6.5 期限 · 轮次 · 超期升级（产品钉法）

| 规则 | 含义 |
|---|---|
| **期限真源** | 以通知书记载为准；登记进案卷，并回写/对齐⑦期限意识 |
| **可见** | 部门内任一专家场与负责人汇总都能看见本轮截止日期 |
| **可催** | 临近节点提醒当前用户（具体天数可配置，产品逻辑不锁死数字） |
| **超期升级** | 逾期未递交 → 状态升级可见（不得静默）；选项含延期申请 / 放弃 / 仍抢答（用户拍） |
| **轮次独立** | 一通、二通…各是独立片段：新通知 → 新进入检查 → 新 A；上轮陈述/修改入历史案卷 |
| **延期/放弃** | 建议可出，**决定在当前用户** |
| **可薄** | 实审请求等非「意见答复」类程序期：可只提醒，不走完整 A–D |

## 7. 部内怎么干

1. 负责人对齐：本轮目标＝可递交答复 + 回执；**期限**；是否预期重大缩限。  
2. 核对进入检查表；挂上 §6.5 期限状态。  
3. **A** 中立拆争点 → 用户可确认「理解的审查意见是否如此」（人话）。  
4. **B** 按 §4.2 摊选项 → **重大缩限/分案/放弃用户拍**（或先起草再终确认留痕）。  
5. **C** 起草修改+陈述+证据（有改则对照表）。  
6. **D** 审核过线 → 用户确认递交 → 回执 → ⑦；下一通回 A；授权→⑦主维护；驳回→复审/放弃（一期可薄提醒）。

```
进入门槛通过（含期限登记）
    ↓
A 拆争点（中立）→ B 策略（§4.2，重大缩限用户拍）→ C 起草 → D 审核·递交 → ⑦
    ↓ 下一通
  新通知 → 再开 A（独立片段）
```

允许 B↔C 来回；新事实缺口回 A 补料。  
**禁止：** 解析阶段夹带定调策略；无人确认递交；超 33 加料；编数据/编对比文件；预测授权率当结论；重大缩限未拍却递交。

### 7.1 请示矩阵

| 事项 | 档 | 说明 |
|---|---|---|
| 争点拆解草稿、策略选项利弊、陈述/修改草稿、审核出项与改稿建议、期限催办文案 | **自决** | 对应专家 |
| 推荐策略（可驳）、是否抽跑⑤ A/F/G、延期建议 | **建议后请示** | 用户知情或拍 |
| **争点理解确认**（人话）；**重大缩限/分案/放弃**；**确认本轮递交**；超期路径选择 | **硬请示** | **当前用户** |
| 补实验：公开风险知情 + 供数确认 | **硬请示** | 用户侧供数；无编数据 |

### 7.2 审核节奏（D）

1. C 有答复候选（陈述 ± 修改对照）后首次审。  
2. 按争点查：覆盖 / 策略一致 / 超范围 / 证据 / 形式；不过线 → 起草改 → 再审。  
3. 大改权项时可**抽跑**⑤ A/F/G，不替代 OA 审核主路径。  
4. 过线 → 负责人组织递交硬请示 → 回执与⑦（含期限结果）。  
5. 用户暂不递交 → 暂停；**期限仍可见催办**（§6.5）。

## 8. 向用户汇报什么

| 节点 | 汇报 | 用户常拍 |
|---|---|---|
| 进入 / 期限 | 截止日期；缺件 | 补料；延期/放弃（若触发） |
| A | 争点人话；缺什么 | 确认理解；补料 |
| B | 每争点选项与利弊；**缩前/缩后人话** | **策略选定；重大缩限；分案/放弃** |
| C–D | 稿件与审核；是否递交 | 技术/数据属实；**是否递交本轮** |

## 9. 多次不行 · 缺料 · 结案

| 情况 | 做法 |
|---|---|
| 审核覆盖不全/策略不一致 | 改陈述或修改 → 再检 |
| 超范围风险 | 收回修改到已披露依据；不空转硬写 |
| 缺实验/缺对比原文 | 补料清单；不编；可暂停 |
| 用户暂不往下 | 暂停；**期限仍可见催办**（§6.5） |
| 本轮结束 | 回执在卷；等下一通或授权/驳回支路 |

### 9.1 结束检查表（本轮已递交）

| 必备 | 说明 |
|---|---|
| 通知书与期限记录 | 本轮；含递交相对期限的结果 |
| 争点清单 | A 产出；与意见条目可对 |
| 策略选定记录 | 含重大缩限用户确认或显式留痕；方向见 §4.2 |
| 意见陈述书 | 齐 |
| 修改对照表 | 有改则必备 |
| 修改后申请文件 | 有改则必备 |
| D 审核过线记录 | 覆盖/一致/超范围/证据/形式；无未关闭红灯 |
| 递交确认 | 用户授权本轮递交 |
| 回执 | 落案卷；期限相关回写⑦ |
| 缺口与备注 | 缺对比文件认风险、选做未做等 |

≠ 授权结果；≠ 下一通已完成。

### 9.2 走通画像（对齐业务 R1–R3）

产品过线用 §9.1；下列画像验收时对照 [业务 §5](../一期节点/06-答复.md)：

| ID | 画像 | 产品上必须看见 |
|---|---|---|
| **R1** | 一通创造性、建议缩限 | 争点清；缩前/缩后人话；**用户拍后再递交**；对照表+陈述+回执 |
| **R2** | 审查员读歪、纯争辩 | 策略=争辩；引用说明书定位；无超范围加料；用户知情递交 |
| **R3** | 要补实验 | 用户侧供数并确认；陈述有来源；**无编数据**；公开风险知情 |

共性：**超期有升级；重大缩限无用户拍不递交；不超范围。**

## 11. 交出去 · 边界

| | 内容 |

## 13. 一期够用

用户↔负责人↔专家；进入检查表；A 中立→B 策略表用户拍→C 起草→D 审核必做；请示矩阵（§7.1）；审核节奏（§7.2）；期限可见可催超期升级；多轮独立片段；结束检查表；R1–R3；⑤→⑥谁接单（§11.2）；手法链 OA 资产。

**一期可薄：** 复审全文、无效宣告、多国同族看板、官费代缴自动化。  
**不做：** 授权率预测；不可改终稿冒充已确认；首次写权项/说明书；交底成稿主业；年费主作业。
