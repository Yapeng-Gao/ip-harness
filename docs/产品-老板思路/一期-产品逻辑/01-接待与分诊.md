# 公司大厅：前台接待 + 八部门（PMO）

> **文内分层**：大厅结构/分诊规则＝**产品逻辑**；§9 前台名册·请示＝**产品设计·编制**。  
> **定位**：进产品后的**第一眼结构**——前台 + 八部门都可见。  
> **接待**不属于八部门编制，但是公司前台；八部门始终可直达。  
> **理念**：[../一期-产品理念.md](../一期-产品理念.md) · [00](00-用户与系统.md)  
> **状态**：**方向可冻** · 逻辑可冻；前台编制薄  
> **设计**：[编制总览](产品设计-编制总览.md) · [交互大纲](交互大纲.md) · [线框](线框-主链.md)

## 1. 进门看见什么（已钉）

```
进入公司（产品首页 / 大厅）
  ├── 前台接待（PMO / 项目管家）—— 突出：「需要帮忙从这儿开始」
  └── 八个部门名牌（①～⑧）—— 看得见、点得开，不是藏在前台后面
```

| 做法 | 本产品 |
|---|---|
| 只见前台、看不见部门 | ❌ 不用（熟客/代理被拦，不像能自己走进去的公司） |
| 只见八部门、没有前台 | ❌ 不用（小白不知道进哪扇门） |
| **大厅：前台 + 八部门都在** | ✅ **采用** |

- **前台**＝默认引导路径（第一次、不清楚要干嘛、先丢一堆材料时）。  
- **不是唯一闸门**：已清楚来交底/挖掘/申请的，**可直达部门**；部门内仍可做短收件。  
- **代理熟客**更常直达部门。

---

## 2. 为什么要有前台

- 用户进的可能是第 1 个部门，也可能是第 2、第 3 个。  
- 上部门产出会流到下部门——要有人帮着问目标、材料、领到哪一站。  
- 若一上来只丢进某一扇门、又没有大厅导览，不像现实公司。

**接待专家（PMO / 项目管家）**：理解情况、材料诚实、介绍部门、问要做什么、整理**交办材料/收件清单**、必要时领进某部。

---

## 3. 第一次登录

1. 采集基本信息（企业/身份偏好、领域粗分等——字段一期可薄）  
2. 进入**大厅**：看见前台 + 八部门  
3. 话术说明：这是一家研发创新团队；专家向**当前用户**汇报；可找前台，也可直接进部门  

（账号体系细节后置。）

## 4. 再来使用：怎么走

| 用户状态 | 建议路径 |
|---|---|
| 不清楚要干嘛 / 先丢材料 | **找前台**：上传 → **PMO 分析归档**（§4.1）→ 汇报「我理解是…对不对？」→ 介绍各部门能做什么 → 问「这次要做什么？」→ **对照目标部交办清单**看全不全 → 交办材料/收件清单 → 领进某部 |
| 已清楚（如「来写交底」） | **直达该部门**；可选经前台快速过一下材料 |
| 代理 / 熟客 | **直达部门**为主 |

用户目标**清晰或含糊**都按现实引导：澄清、对比部门、建议先去哪一站——由前台做；直达时由部门收件补一句也可。

### 4.1 上传之后：分析 → 判断要做什么 → 建议部门（全八部）

> **要钉清的事：** 用户丢材料进来，前台**怎么分析、怎么猜意图、怎么建议①～⑧**——不只④/⑤。  
> **定案权在用户**；前台只建议。  
> **进部能否开干**＝该部进入门槛（[00 §6](00-用户与系统.md)），前台**不代替**门槛检。  
> **不做：** 查新结论、交底全绿、权项撰写、OA 争点、三性终裁——部内专家的活。

#### A. 总流程

```
上传（文件 / 粘贴 / 口述）
    ↓
【析】识物 · 抽意图线索 · 对八部打分建议（可并列）
    ↓
汇报：「材料里我看到…；你这次更像要…；建议先去 X 部（备选 Y）」
    ↓
用户确认目标（可改口、可坚持跳部）
    ↓
对照**该部**交办清单粗看全不全 → 交办材料 → 领进部门
    ↓
部门进入门槛检（过/补/退）
```

直达部门时：跳过长分诊，部门短收件；若材料明显像别部，负责人可提示「要不要先去某部」，仍不锁死。

#### B. 分析什么（四路信号，合并成建议）

| 路 | 看什么 | 怎么用 |
|---|---|---|
| **1 材料类型** | 文件/段落像什么 | 贴标签进案卷（可多标）；认不出→「未识别」+ 摘录，不编专业结论 |
| **2 生命周期强物件** | 有没有「几乎点名某部」的物件 | 通知书→强⑥；授权证书/年费单→强⑦；合格交底+要递交→偏⑤；等等（见表 C） |
| **3 用户原话** | 这次要干什么 | 「写交底」「答OA」「挖点」「年费」等；**有明确原话时权重大于弱材料** |
| **4 案卷处境** | 是否已有项目/上家工单/未完成部门 | 续案优先接未完成站；新丢料且无项目→当新分诊 |

**材料类型标签（一期）：**  
技术说明·灵感草稿 / 图纸照片 / 交底书（草稿|成稿） / 查新·检索报告 / 申请文件包 / 受理回执·申请号 / **审查意见通知书·对比文件** / 授权证书·年费·期限函 / 立项材料·商业计划 / 挖掘·创新点清单 / 合同·委托意向 / 竞对·情报素材 / 其他杂件。

**分析产出（进案卷，给人看）：**

1. 材料清单（类型 · 一句摘要 · 置信：高/中/低）  
2. **意图假设** 1～3 条（「你可能想…」）  
3. **建议部门** 主推荐 + 至多 2 个备选 + 一句话理由  
4. 相对主推荐的**粗缺口**（一眼缺什么；细检留给部门）

不确定就问一句澄清（例：「你是要先把技术写成交底，还是已经有交底要递申请？」），**不连续盘问**。

#### C. 八部门：材料信号 × 用户说法 → 建议

| 部 | 部门一句话 | 材料侧强信号 | 用户说法示例 | 常见误判 → 应改指 |
|---|---|---|---|---|
| **① 立项** | 要不要立这个方向/建项目 | 立项书、路线对比、决策会材料 | 「立不立得住」「开个项目」 | 只有技术灵感要方案 → 更像②；要挖专利点 → ③ |
| **② 激发** | 问题卡点 → 路径 → 方案 | 问题描述、矛盾、失败尝试；尚无系统方案 | 「没思路」「帮我想办法」 | 已有完整方案要写交底 → ④；资料堆要拆案 → ③ |
| **③ 挖掘** | 研发资料 → 创新点 + 拆案排案 | 多份研发资料、竞品拆解、要「挖哪些点/拆几案」 | 「挖掘」「布局/拆案」 | 单点已清只要写交底 → ④；行业导航长文 → **二期/非本步主路径** |
| **④ 交底** | 技术事实 → 交底书全绿 | 技术说明/图纸；交底草稿；无合格交底却喊申请 | 「写交底」「交底不合格要改」 | 已有合格交底要递交 → ⑤ |
| **⑤ 申请** | 合格交底 → 申请文件 → 递交 | 交底书（成稿）；申请文件草案；要递交/申请号 | 「写申请」「递交」「开案撰写」 | **无交底只有技术说明** → **先建议④**（见下冲突规则）；只要查新决策可仍进⑤走 B |
| **⑥ 答复** | 通知书 → 策略 → 答复 | **审查意见通知书**、对比文件、期限 | 「答OA」「审查意见」 | 尚未递交 → ⑤；已授权年后费 → ⑦ |
| **⑦ 维护** | 确权后期限·年费·台账 | 授权证书、缴费通知、期限监控诉求 | 「年费」「别超时」「资产台账」 | 还在审 → ⑥；要写复盘报告 → ⑧ |
| **⑧ 复盘** | 年末/阶段复盘报告 | 多案台账、年度经营材料、复盘提纲 | 「年底复盘」「创新总结」 | 单案答OA → ⑥；只要竞对动态 → **情报接口**（贯穿，≠⑧，≠检索） |

**情报官**：不是大厅第九部；用户要「竞对年报/动态」时说明走情报能力/旗舰权益，**不要**塞进⑧或③糊弄。

#### D. 冲突与优先级（必须钉死）

| 情况 | 怎么判 |
|---|---|
| **用户原话明确** 且与材料不矛盾 | 听用户；领对应部 |
| **用户要⑤** 但材料无交底、只有技术说明 | **建议改④**（说明⑤进入门槛要合格交底）；用户仍坚持进⑤ → 允许，进部后门槛检挡开写并给退④/补交底选项（[05 §6](05-申请.md)） |
| **用户要④** 但材料已是合格交底+明确「就想递交」 | **建议改⑤**；用户坚持改交底 → ④ |
| **强物件点名某部**（如通知书）用户却说「帮我看看」 | 主推⑥，备选说明「若还没申请过是⑤」 |
| **多目标**（又要挖点又要写交底） | 建议**先一站**（通常③→④或④直接）；开「现在做/以后做」由用户选，不一次进两部假装并行完工 |
| **完全说不清 + 材料杂** | 先介绍八部各一句 → 问「这次最想先办成哪一件事」→ 再建议；宁可多问一句，不猜错部硬塞 |
| **建议与实选不一致** | 允许；案卷留痕；门槛不过再改路 |

**权重经验序（产品层，非模型细则）：**  
用户明确目标 ＞ 强生命周期物件（通知书/授权/交底成稿）＞ 弱技术堆料 ＞ 前台猜测。

**主推怎么定（薄规则，非算法）：**  
- 一路信号明显强于其他 → 该部为主推，至多 1 个备选。  
- 两路同强或互相矛盾 → **强制澄清一句**再领（例：交底 vs 申请）。  
- 置信皆低 → 先介绍八部各一句，问「这次最想先办成哪一件」，不硬塞。

#### E. ④↔⑤ 细表（高频，并入总规则）

| 材料 | 用户目标 | 建议 |
|---|---|---|
| 无交底，仅技术说明等 | 要申请/递交 | **④**（先交底） |
| 无交底 | 写交底 | **④** |
| 有交底（或自称） | 要申请 | **⑤**（进部门槛检） |
| 有交底 | 改交底 | **④** |
| 已有申请文件包 | 改/递交 | **⑤** |

#### F. 齐套与诚实

- 确认目标**之前**：只做识物 + 意图假设 + 粗缺口。  
- 确认目标**之后**：才对照该部交办清单谈「全不全」。  
- 没有就说没有；不编三性/授权结论；不确定标不确定。

## 5. 材料与诚实 · 案卷

- 前台建/更新**案卷**（见 [00 §5](00-用户与系统.md)）：材料分类归档进卷，不是另起「知识库」。  
- 汇报：材料全不全、还缺什么；引导补充。  
- 确实没有 → **按没有说**，不编；缺口写入案卷，下游可见。  
- 领进某部时：附上**交办材料/收件清单**（已有 / 缺口 / 上家问题）。

### 5.1 前台继承 + 直达短收件（已钉）

| 进法 | 部门怎么收件 |
|---|---|
| **经前台领进** | 前台已问过的字段**默认继承**；部门只补差额 + 上家问题，不从头长问一遍 |
| **大厅直达部门** | 部门做**短收件**（要干什么、材料现状、缺什么）；不强制走完前台长分诊 |

## 6. 跨部门时（工单）

部间流转用**工单/交办单**（可带批注）；案卷随单走。详见 [00 §6–7](00-用户与系统.md)（各部门门槛 + 工单）。

| 时机 | 谁 | 动作 |
|---|---|---|
| 离开上部门 | 该部协同结束 → 当前用户确认 | 开出工单：现在做 / 以后做 / 优化退回 / 暂时这样 |
| 进下部门前 | 下部门收件（前台可协助） | 看工单+案卷；上家问题先汇报「先补 / 带着干 / 退回」 |
| 用户跳部门 | — | 允许；案卷标「未经过」，不假装做过 |
| 大厅点另一部门 | — | 直达；短收件；不强制回前台排队 |

## 7. 向谁汇报

前台与各部门专家一律向**当前用户**汇报。

## 8. 和交底部等的关系

- 大厅逻辑是**全公司**的；[04-交底](04-交底.md) 等部门文不重复写「进门第一眼」。  
- 用户直达交底部时：走该部「收件汇报」，不强制先聊完前台长流程。  
- 经前台领进时：带**交办材料/收件清单**进部，部门少问一遍「你是谁要干啥」，仍要核上家/材料。

## 9. 产品设计（前台编制 · 薄）

> 前台**不属于**八部门编制，但是公司入口岗。能一个就一个。

### 9.1 名册

| 专家 | 职责 |
|---|---|
| **接待专家（PMO）** | 识物·意图·八部分诊建议；交办材料/收件清单；领进某部；建/更新案卷 |
| （无部门负责人席） | **不进部内派活**；部内分活换该部负责人 |

活少：单一「前台」名片即可；逻辑上仍是接待专家。

### 9.2 时序（薄）

```
上传 → 析（四路信号）→ 汇报建议 →【硬】用户确认目标 → 对照交办清单粗缺口 → 交办材料 → 领进部门
```

直达部门：跳过长分诊；前台可不出场。

### 9.3 请示矩阵

| 事项 | 档 |
|---|---|
| 识物标签、意图假设、主推/备选理由、粗缺口列表 | **自决** |
| 强制澄清一句（两路同强） | **建议后请示**（问清再领） |
| **本次去哪一部**；坚持跳部/与建议不一致 | **硬请示**（用户定案；案卷留痕） |

### 9.4 交出 · 不打包部间专业工单

| | 钉法 |
|---|---|
| 领进时交出 | 案卷 + **交办材料/收件清单**（已有/缺口/上家问题） |
| 部间「现在做⑤」等 | **不由前台打包**；由上部门负责人打包（见主链各部 §打包） |
| 能力挂接 | 产品编排层；无单独 `各产品开发` 手法库 |
