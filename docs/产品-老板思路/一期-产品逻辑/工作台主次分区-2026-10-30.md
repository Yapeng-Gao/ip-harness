## 1. 一句话

**工作台是「文书作业台 + 领导拍板台」**：主栏持有交付物；侧栏（AI 区）钉硬请示 + 依据 + 对话驾驭；对话不是中心，一键黑箱不上屏。

## 2. 主展示 vs 次要

### 2.1 主展示（首屏必须看见 · 最大面积）

| # | 物件 | 为什么是主 | skill / 大纲依据 |
|---|------|-----------|------------------|
| 1 | **主栏交付物**（④交底书 / ⑤权项·说明书 / ⑥答复·对照） | 用户拿到后要签字/改稿；产物旁置，不活在气泡里 | 大纲原则 8、§4.4.2；理念「交付物可核验」；RDI 第一步交付物清单 |
| 2 | **硬请示卡**（结论 + 依据入口 + 确认/改/暂停） | 领导只在关键节点拍板；未确认不得推进下游 | 理念 §3–5「别让 AI 偷拍板」；理念条目 04；大纲 §4.4.4 层1、§5.1；RDI 第四步 P0 人类签字 |
| 3 | **依据链入口**（可点 → 主栏定位） | 领导能签字的前提是底稿完整 | 理念 T4 / 条目 04；大纲 §4.4.8；RDI 第三步依据链固定格式 |

### 2.2 次要（默认可折 / 飞层 / 轻量收）

| # | 物件 | 放哪 | 规则 |
|---|------|------|------|
| 1 | **进行中案切换** | 壳顶单行薄轨 | 常显但矮；轨迹进飞层 |
| 2 | **编制 / 专家名册** | AI 区可折条 | 主笔可展；老板轻量默认藏 |
| 3 | **负责人身份条** | AI 区薄条 | 一行即可；不压过硬请示 |
| 4 | **团队动态 / 闲聊流** | AI 区层3，默认可滚可折 | 建议后请示可插流，但硬请示必须在层1另钉一份 |
| 5 | **段进度时间线** | 主栏顶薄条或轻量藏 | 服务定位，不抢文书 |
| 6 | **带教 / 工具芯片 / 检索示意 / 版本切换** | 飞层或折叠 | 带教淡出（理念 11）；获取类不挡判断类 |
| 7 | **操作记录** | 案卷抽屉 | 考勤表 ≠ 判断档案（理念 10；工程审计） |

## 3. 区域划分

```
┌─ 壳顶（矮 · 常显）─────────────────────────────────────┐
│ 回大厅 · 部名 · 合格线 · 密度态 │ 进行中薄轨（次要）     │
├──────────────────────────────┬──────────────────────────┤
│ 【主栏 · 最大】                │ 【AI 右栏 · 驾驭】        │
│ 交付物全文 / 分页 / 差分      │ ① 硬请示（钉顶 · 主）    │
│ 质检锚点 / 版本可切（次）     │ ② 薄身份 · 编制可折（次）│
│                              │ ③ 依据 / 结构旁路（主辅）│
│                              │ ④ 对话流可折（次）        │
│                              │ 底：composer 钉底（辅）  │
└──────────────────────────────┴──────────────────────────┘
```

### 3.1 壳顶

- **放**：部名、合格线状态、密度切换（老板轻量 / 主笔）、进行中薄轨。  
- **不放**：全宽身份墙、编制墙、硬请示（请示进 AI 区层1）。  
- **高**：尽量矮；带教一条可关。

### 3.2 主栏（文书 · 最大）

- **宽**：`1fr` 吃满剩余；右栏固定约 **320–340px**（不抢主栏）。  
- **放**：当前段主产出；版本「当前稿 / 上一确认稿」；diff 对照；锚点高亮。  
- **轻量态**：只读/结论摘要优先；大编辑控件可收。

### 3.3 AI 右栏（驾驭 · 钉死序）

自上而下，**不可**用下层顶掉上层（大纲 §4.4.4）：

| 序 | 层 | 内容 | 布局约束 |
|---|---|---|---|
| 1 | **硬请示** | 确认卡 | **置顶**；有卡时首屏必见；未处理完不得只靠滚聊天 |
| 2 | 身份 + 编制 | 负责人一行；名册可折 | 不抢过层1；轻量默认藏名册 |
| 3 | 依据 / 旁路 | 质检红项、争点、命中 | 点条目 → 主栏定位 |
| 4 | 对话 | 汇报 / 追问 / 自决摘要 | 可滚可折；不是整页中心 |
| 底 | composer | @材料 + 一句话驾驭 | **钉在 AI 区底**；辅，不是唯一中心 |

## 4. 三 skill 引用（定主次的条款）

| 主张 | 引用 |
|------|------|
| 用户＝领导；专家递方案+依据，领导拍板 | 理念术语「人机交互」；理念 §3；条目 **04 判断权分配** |
| 别让 AI 偷拍板；一键生成＝架空 | 理念红线；T2/T4；大纲 §5.2 禁止 Toast 代替硬请示 |
| 交付物在主栏，对话来驾驭 | 大纲原则 8、§1.1、§4.4.2 |
| 技术管理层唯一向用户汇报 | RDI 设计第四步「单一汇报口」；00 §7.1 负责人汇总 |
| 依据链：结论+来源+推演+对比+置信 | 理念 T4；RDI 第三步依据链；大纲 §4.4.8 |
| 操作记录 ≠ 判断数据 | 理念条目 **10**；工程纪律「审计留痕」→ 判断档案进案卷 |
| 带教是脚手架，成熟淡出 | 理念条目 **11**；大纲 §7 |
| 真源唯一：硬请示状态不双写糊掉 | 工程纪律一；大纲：过线 ≠ 确认递交 |

## 5. 密度态（同一壳）

| 态 | 主栏 | AI 区 |
|----|------|-------|
| **老板轻量** | 文书可读；时间线可藏 | 硬请示钉满顶；对话默认收；编制藏 |
| **主笔** | 全文可改；结构旁路可开 | 对话展开；请示仍钉顶不沉底；编制可展 |

禁止：用换壳假装换身份；轻量态藏掉硬请示。

## 6. ④⑤⑥ 同构差分

| | 主栏主物件 | 硬请示（验收） |
|---|-----------|----------------|
| ④ | 交底书单篇 | 事实确认；可交⑤ |
| ⑤ | 权项 \| 说明书 \| 差分 | 理解；申不申；确认递交 |
| ⑥ | 答复 \| 通知书 \| 差分 | 争点；策略/缩限；本轮递交 |

壳与 AI 区层级相同；只换主栏物件与请示文案。

## 7. 验收（本文件对应样机）

- [ ] 主栏面积明显大于 AI 栏；文书首屏可读  
- [ ] AI 区自上而下：硬请示 →（身份/编制可折）→ 依据/对话 → composer 钉底  
- [ ] 轻量态编制/闲聊收掉，硬请示与 composer 仍在  
- [ ] 进行中仅壳顶薄轨；轨迹飞层  
- [ ] 硬请示 / 判断档案链路未回退；smoke ALL PASS
