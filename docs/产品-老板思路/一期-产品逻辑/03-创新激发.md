## 1. 部门职责

把研发卡住的**一个技术问题**，摊成可比较的**技术路径**，必要时落到可收藏的**方案/解读**——解决「方向/路径不够」，不谈申不申、能不能授权。

**硬产出（轻跑即可）：** 结构化问题 + 多路径（含推荐）+ 用户已选/已改路径 → **收藏进成果库**（或记跳过原因）。  
**深跑可选：** 解决方案文、单篇专利问题向解读、路径上相似专利列表。

**不做：** 把创新报告/三图当成本部主交付；替研发拍最终方向；拆案排案（③）；写交底/申请文件；查新终局；可授权承诺；FTO。  
**整段可跳过：** 方向已明 → 不进②，不挡④→⑤主链。

## 2. 产品里有谁（只三类）

| | 说明 |
|---|---|
| **用户** | 真人（研发/技术管理/顾问/代理…谁登录谁是用户）；听汇报、拍板、可 1:1、可看产出 |
| **部门** | 创新激发部；进门看见名册与协同场 |
| **专家** | **全部是 Agent**；能一个办完不硬拆 |

没有「真人专家席」与用户并列。套餐对人签字＝服务交付另走，不进产品编制。

惯用上**企业研发主操**；顾问可带工坊；代理人答疑为主、**不替研发拍最终方向**——**系统不按身份锁**（见 [00](00-用户与系统.md)）。

### 2.1 谁主持——部门负责人（不是前台）

| | 现实 | 本产品 |
|---|---|---|
| **前台** | 大厅分诊、领到某部 | 只在大厅 ([01](01-接待与分诊.md))；**不进部内派活** |
| **部门负责人** | 科室主办：对接、拆活、盯进度、汇总 | 创新激发部 **Agent**（名：部门负责人） |

前台领进门、交案卷；进部后换负责人。

```
用户 ←→ 部门负责人（主持、分配、汇总汇报）
              ↓
     问题分析 / 路径 / 方案 / 专利解读 / 路径附检索 …（可串可并）
用户也可 ←→ 某专家（盯细活）· 随时看产出
```

## 3. 编制：能一个就一个，要拆就拆

均为 Agent。

| 专家 | 对应业务段 | 职责 |
|---|---|---|
| **部门负责人** | 全程 | 收件/门槛、分活、冲突汇总、组织收藏与去向、开③/④工单 |
| **问题分析专家** | **P1**（AI-01） | 问题结构化（对象—作用—目标—约束等）；≠ 交底、≠ 权要 |
| **路径专家** | **P2**（AI-02） | 多条独立路径 + **只推荐一条**；问题三元组 |
| **方案专家** | **P3**（AI-03） | 七章方案文（吃已选路径）；不偷换未选机制；不编造精确数据 |
| **专利解读专家** | **P4**（AI-04） | 对单篇专利做**问题向**异同/边界；≠ 查新终局 |
| **检索专家** | **附挂** | **路径上**相似专利列表（按路径关键词）；≠ 旗舰三图、≠ ⑤申请向查新 |

活少可合并呈现（如「创见专家」兼 P1+P2）；逻辑上仍按上表。  
手法（AI-01～04 细则）→ 业务章程 + [`各产品开发/创新激发/`](../../各产品开发/创新激发/)；**不抄进本文**。

### 3.1 边界

| | 本部门 | 不是 |
|---|---|---|
| 起点 | **一个研发问题**（冷启动或种子） | 先跑业务线全景检索再激发 |
| 报告命题 | 最多当**可选问题种子**（低密度×在研） | 创新报告正文/三图主交付；本步重做检索式检本公司/竞对 |
| 相似专利 | 挂在已选/候选**路径**上 | ⑤正式查新；旗舰三图；图2-4 落点矩阵主输入 |
| 路径/方案 | 可比较方向与可收藏思路 | ③拆点拆案；④成稿；⑤权要/说明书 |
| 拍板 | 用户选路径、认方案主线、定去向 | 代理人替研发定方向；申不申终裁 |

### 3.2 合并呈现 · 时序（薄）

| 活量 | 呈现 |
|---|---|
| 轻跑 | 「创见专家」兼 P1+P2（+负责人） |
| 深跑 | 方案 / 解读 / 附挂检索 分席或分任务态 |

```
门槛 → P1 → P2 →【硬】选题 → 收藏/跳过 →【硬】去向；选做 P3/P4/附挂可后
```

## 4. 必做 · 选做

| | 内容 |
|---|---|
| **必做（开干后）** | **进入门槛**（有可依托问题，§6）→ **P1** 问题结构化 → **P2** 多路径+推荐 → **用户选题**（可改推荐）→ **收藏或记跳过原因** → **去向意图**（③ / ④ / 仅留存） |
| **一期轻跑** | 问题 → 路径（有推荐）→ 收藏（或跳过有原因）即可；P3/P4/附挂检索可后做 |
| **选做** | 路径上相似专利；**P3** 方案文；**P4** 专利解读；报告命题灌入；思路建议书（须人认） |
| **整段跳过** | 用户从未进部或进部后显式跳过 → **不挡**④→⑤；须能续交底；跳过原因宜留痕 |

**不能：** 无问题空跑当已激发；把报告三图当成本部合格交付；无人选题却标「路径已定」；虚构公开号/实验数据；报「一定能授权」。

手法与会话红线 → [业务章程 §4](../一期节点/02-创新激发.md)。

## 5. 领域

看问题与材料建议；收件或出路径前确认；**随时可改**。不在注册死锁。  
领域影响路径抓手/风险话术与方案章详略——**不改变** 问题→路径→方案 主路径。

## 6. 进门门槛：先有可依托的问题

> 通则见 [00 §6](00-用户与系统.md)。大厅点进② ≠ 已过门槛。

**开跑主作业前：** 至少有一句可依托的技术问题（文本/语音转写），或可选种子（报告命题 / ①课题转化）。不是空卷开跑。

### 6.1 进入检查表（开跑前）

| 必备 | 说明 |
|---|---|
| 问题线索 | 文本/语音问题原文；或报告命题种子；或①课题可转化成问题句 |
| 目标确认 | 本次要做「问题→路径（可到方案）」或「仅轻跑收藏」（用户认） |
| 领域（可暂定） | 收件建议；出路径前宜确认 |
| 来源记录 | 冷启动 / 报告种子 / ①转化 / 前台领进 |

无问题、只有「我想搞创新/写报告」→ 先补问题或回前台分诊；可建议创新报告另链，**不假装已开跑创见**。

### 6.2 两种进法 · 收件

| 来源 | 做法 |
|---|---|
| 前台领进 | **继承**前台字段；核进入检查表差额 |
| 大厅直达 | **短收件** + 进入检查表 |
| 冷启动 | 一句问题即可 |
| 报告命题（可选） | 只取「低密度×在研」等当种子；**不在本步重做业务线检索**；在研是否属实 → 用户认（报告灰框） |
| ① 课题 | 可转化成问题入口；②**不代替**立项签字 |

### 6.3 门槛不过

| 轻重 | 动作 |
|---|---|
| **重**（无问题、空壳口号） | 补问题或回前台；不进入 P1 |
| **中**（问题过糊、缺约束） | P1 内补问再结构化；仍空 → 暂停 |
| **轻**（缺附图/细节） | 留痕；路径/方案阶段消化 |

### 6.4 进部后分流（不是一律硬干）

| 问题类型 | 谁主责 | 动作 |
|---|---|---|
| **要全景/三图/业务线检索** | 创新报告另链 | 说明 ≠ 本步主链；可只取命题种子 |
| **已有成果要拆点/拆案** | ③ | 建议工单/直达③ |
| **已有合格交底只要递交** | ⑤ | 建议⑤（见 [01](01-接待与分诊.md)） |
| **方向已明只要写交底** | ④ | 可跳过②；开④ |
| **问题糊 / 事实不足** | ② P1 | 补问；不编造 |

**禁止：** 用报告管线冒充创见主流程；或未选题却用「先出方案」绕过路径确认。

## 7. 部内怎么干

1. 负责人与用户对齐：目标＝路径可比较并收藏（轻跑）或加深到方案/解读；是否用报告种子。  
2. 核对 **进入检查表**；不过则 §6.3，不假装开跑。  
3. 分配 P1/P2/（选做）附挂检索/P3/P4（能一个就一个；可串可并）。  
4. **P1** → 结构化问题可见。  
5. **P2** → 多路径 + 推荐一条 → **用户选题**（可改推荐）。  
6. **选做：** 路径上相似专利 → 用户可点篇进 **P4**；或直接 **P3** 出方案文（吃已选路径 + 三元组）。  
7. 用户编辑、**收藏**（或记跳过）→ 定**去向意图**。  
8. 要挖 → 开「现在做③」工单；要写交底 → 开「现在做④」（方案文＝引子，④仍要成稿确认）；仅留存 → 结案留成果库。

```
进入门槛通过
    ↓
P1 问题结构化 → P2 多路径·推荐 → 用户选题
    ↓（选做）
  路径附相似专利 → P4 解读  /  P3 方案文
    ↓
收藏 / 跳过留痕 → 去向：③ / ④ / 仅留存
```

允许 P1↔P2 补问后重出路径；改选路径则方案跟改。  
**禁止（对齐业务纪律）：**  
无真实专利输入却填公开号；偷换未选机制出方案；直接写成齐套交底/申请；空命中当查新过关；报授权概率当结论；代理人替用户定最终方向。

并行冲突由负责人汇总选项给用户，不私下定案。

### 7.1 请示矩阵（薄）

| 事项 | 档 |
|---|---|
| P1 结构化、P2 多路径+推荐、P3/P4/附挂草稿 | **自决** |
| 建议做方案/解读、报告种子用法 | **建议后请示** |
| **选题**；**收藏/跳过**；**去向③/④/留存**；思路建议书对外人认 | **硬请示** |

Agent 低置信须示弱；**不得冒充**路径已选、方案已认、可授权、查新已终局。

### 7.2 部间谁打包（薄）

| 工单 | 谁打包 |
|---|---|
| 现在做③ / 现在做④ | **② 部门负责人**（须结束合格线；方案文≠④全绿） |

## 8. 向用户汇报什么

| 节点 | 汇报 | 用户常拍 |
|---|---|---|
| 进入门槛 | 问题线索够不够开跑 | 补问题 / 回前台 / 改用报告种子 |
| P1 | 问题结构化对不对、缺什么 | 确认 / 补约束 |
| P2 | 多路径 + 为何推荐这一条 | **选题**（可改） |
| 附挂检索 | 路径上相似专利列表（非三图） | 是否点篇解读；是否忽略 |
| P3 | 方案主线与边界 | 认主线 / 改路径重出 |
| P4 | 异同、不可迁移、启发级别 | 认级别 / 不采纳 |
| 结束 | 收藏内容、去向选项 | **收藏/跳过**；**③ / ④ / 留存** |

## 9. 多次不行 · 缺料 · 结案

| 情况 | 做法 |
|---|---|
| 路径家族拉不开、材料够 | 限定焦点重出 P2 → 再选题 |
| **关键问题/约束根本没有** | 回 P1 补问；仍无 → **暂停**，不空转「优化路径」 |
| 用户暂不往下 | 暂停；案卷/成果库保留 |
| 整段不要了 | 跳过留痕；可直达④等 |

**不能：** 未选题标路径已定；虚构专利当依据；把轻跑未收藏当合格交③。

### 9.1 结束检查表（收藏结案 / 开「现在做③或④」）

| 必备 | 说明 |
|---|---|
| 进入门槛记录 | 问题线索来源 |
| 结构化问题 | P1 产出（轻跑可附在路径卡侧） |
| 路径卡 + 推荐 | P2；**用户选题记录**（或显式跳过本段原因） |
| 收藏或跳过 | 成果库条目，或跳过原因留痕 |
| 去向意图 | ③ / ④ / 仅留存 |
| 选做摘要 | 方案文/解读/相似专利是否做；未做备注 |
| 缺口与备注 | 报告种子在研是否已认；已知提醒 |
| 工单（若交下游） | 现在做③ / 现在做④ / 批注 |

**开「现在做③ / 现在做④」＝须先满足本部门结束合格线**（上表：选题+收藏或跳过留痕等）。方案文给④只是**引子**，不等于④已全绿；未达标不得开「现在做」假装合格（见 [00 §7.2](00-用户与系统.md)）。整段跳过②直达③/④另算，不经过本表。

≠ ③创新点清单/拆案；≠ ④交底全绿；≠ 查新终局；≠ 授权结果；≠ 创新报告三图。

### 9.2 走通画像（薄 · 对齐业务惯用）

| ID | 画像 | 产品上必须看见 |
|---|---|---|
| **E1** | 研发自助轻跑 | 问题→路径+推荐→选题→收藏；可不跑 P3/P4 |
| **E2** | 顾问带工坊 | 同上；思路建议书须**人认**；不替研发锁最终方向 |
| **E3** | 带报告命题种子 | 种子入场留痕；**不重跑**业务线检索/三图；在研属实用户认 |

共性：**路径须用户选题（或整段跳过留痕）；无授权承诺；报告≠主交付。**

### 9.3 容易漏（产品意识清单）

不挡主路径硬闸，但案卷/备注宜有着落。

| 项 | 产品意识 |
|---|---|
| 整段可跳过 | 跳过原因 + 仍能续④ |
| 推荐≠已选 | 必须有选题动作或改选 |
| 相似专利挂路径 | ≠ 三图、≠ ⑤查新 |
| 方案不偷换机制 | 已选路径锁定 |
| 去向意图 | 挖 / 交底 / 留存 显式 |
| 报告灰框在研 | 用了种子则用户认是否属实 |
| 版本留痕 | 改选路径后方案重大版进案卷 |

## 10. 依据链

| 环节 | 要求 |
|---|---|
| P1 | 结构化字段可对回问题原文；事实与推断分开；禁猜关键事实 |
| P2 | 路径彼此独立可核；推荐理由可见；无真实专利/图则相关字段空 |
| 附挂检索 | 命中可核；列表≠查新终局 |
| P3 | 吃已选路径+三元组；精确数值须有输入依据；禁编造 |
| P4 | 只引真实输入专利；启发级别标明；≠ 可授权 |
| 结束 | 结束检查表齐；去向意图有 |

## 11. 交出去 · 边界

| | 内容 |
|---|---|
| ← 冷启动 / 报告种子 / ① | 问题句或命题；①不代签立项 |
| → ③ | 工单 + 方向/路径线索（结束检查表）；进挖掘仍要拆点、去向、拆案 |
| → ④ | 工单 + 方案文/路径作**交底引子**；发明人仍须④成稿确认与全绿 |
| → 成果库 | 收藏条目（仅留存时） |
| ≠ | 创新报告主链/三图；⑤查新终局；③拆案本体；授权/FTO；交底/申请成稿主业 |

### 11.1 段间交出（可中停）

| 段 | 案卷宜有 |
|---|---|
| P1 | 结构化问题、补问留痕 |
| P2 | 路径卡、推荐、**用户选题** |
| 附挂检索 | 专利列表或跳过备注 |
| P3 | 方案文版本 |
| P4 | 解读稿与启发级别 |
| 结束 | 收藏/跳过、去向、工单 |

## 13. 一期够用

用户↔负责人↔专家；进入检查表；问题→路径（推荐）→选题→收藏；去向意图；人确认点（§7.1）；结束检查表；E1–E3；段间交出；报告仅种子；手法链业务文与创新激发提示词。

**不做：** 创新报告/三图当本部主交付；③拆案本体；④⑤成稿主业；查新终局；授权/FTO 承诺；本步重跑业务线检索式。
