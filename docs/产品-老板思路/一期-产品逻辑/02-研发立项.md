## 1. 部门职责

开一个可跟踪的**研发项目 / 课题容器**，让后续案件、交底、申请能挂到项目下，并给⑧复盘、③挖掘提供「按项目」聚合键。

**硬产出（一期）：** 项目已创建且可被下游引用（项目 ID / 名称）+ 状态可维护（进行中 / 暂停 / 结项）。

**不做（一期）：** 把建项当成已交付《研发立项决策论证报告》；因未出论证报告挡交底→申请主链；把本步混成③保护去向或⑤单案申不申。

**三种「立项」拆开（业务真源，产品必须钉清）：**

| | 含义 | 归哪 |
|---|---|---|
| **A. 本步（一期）** | 开研发项目容器 | **① 创建项目** |
| **A′. 老板完整版** | 技术路线选哪条的论证报告 | ① **后置**；非一期必达 |
| **B** | 成果保护去向 | **③** |
| **C** | 单案申不申 | **⑤** 井沿 |

## 2. 产品里有谁（只三类）

| | 说明 |
|---|---|
| **用户** | 真人（总工/研发负责人/代理/企业 IP…谁登录谁是用户）；听汇报、拍板、可 1:1、可看产出 |
| **部门** | 立项部；进门看见名册与协同场 |
| **专家** | **全部是 Agent**；能一个办完不硬拆 |

没有「真人专家席」与用户并列。套餐对人签字（完整论证若启动）＝服务交付另走，不进产品编制。

### 2.1 谁主持——部门负责人（不是前台）

| | 现实 | 本产品 |
|---|---|---|
| **前台** | 大厅分诊、领到某部 | 只在大厅 ([01](01-接待与分诊.md))；**不进部内派活** |
| **部门负责人** | 科室主办：对接、拆活、盯进度、汇总 | 立项部 **Agent**（名：部门负责人） |

前台领进门、交案卷；进部后换负责人。

```
用户 ←→ 部门负责人（主持、分配、汇总汇报）
              ↓
     建项 / 改状态 /（后置）论证协助 …
用户也可 ←→ 某专家（盯细活）· 随时看产出
```

惯用上客户/总工更常主操建项；代理可协助——**系统不按身份锁**。

## 3. 编制：能一个就一个，要拆就拆

均为 Agent。一期编制**宜薄**。

| 专家 | 对应业务段 | 职责 |
|---|---|---|
| **部门负责人** | 全程 | 收件/门槛、对齐目标、确认建项字段、汇总汇报；组织挂下游案/开后续工单提示 |
| **建项专家** | **建项** | 起草项目卡片（名称、方向一句话、起止/年度、负责人可选、背景/目标短描述）；改状态建议 |
| **论证助理** | **A′ 后置** | 仅用户**显式要做完整论证**时出现；整理材料清单、提示后置能力与人工交付路径——**不假装一期已交报告** |

活少时建项专家可与负责人合并呈现；逻辑上仍按上表。  
论证助理默认**不派**；一期主路径无此席也不影响结束合格线。

### 3.1 边界

| | 本部门 | 不是 |
|---|---|---|
| 建项 | 项目主数据 + 与下游案关联 | ③拆案排案；⑤写申请；②出方案主场 |
| 「立项有依据」一期口径 | 有可跟踪项目容器 | 已出多路线对比+签字论证报告 |
| 查新 / 鉴新 | 一期建项**不绑**必做检索 | ⑤申请向查新；③挖点检索；科技查新冒充 |
| 创新报告三图 | 可选零件、后置/按需 | 一期建项必出；挡主链 |

### 3.2 合并呈现 · 时序（薄）

| 活量 | 呈现 |
|---|---|
| 默认一期 | 「立项专家」= 负责人兼建项 |
| 用户显式要 A′ | 另开论证助理席（后置说明，不交满报告） |

```
门槛 → 起草项目卡 →【硬】确认建项 → 可引用；可选提示下游工单
```

## 4. 必做 · 选做

| | 内容 |
|---|---|
| **必做** | **进入门槛**（§6）→ **创建/确认项目卡片** → 用户确认建项 → **项目可被下游引用**（结束检查表） |
| **选做** | 背景/目标加长描述；指定项目负责人；从大厅材料预填字段 |
| **后置（非一期必达）** | 完整《研发立项决策论证报告》；多路线对比、专利空间、侵权初判、竞对对照、专家签字 SLA；强制创见前置 + 鉴新撑满合格五项 |
| **可弱** | 无项目也可直达④⑤（主链可跳①）——见业务「可跳」；但若进了①，结束须达标，不能半截当「已立项」。跳过①时案卷可无正式项目容器；**需要聚合键时事后补挂/薄建项**，不强迫先过①（与 [00 §6.1](00-用户与系统.md) 一致） |

**一期结束合格线（产品钉法）：**  
项目已创建（有 ID/名称）+ 方向一句话非空 + 状态已设 + 用户确认；可为⑧、③提供按项目聚合。  

**≠** 论证报告已出；**≠** ③保护决策；**≠** ⑤申不申；**≠** ④全绿 / ⑤过线 / ⑥D 过线（对照见 [00 §6.1](00-用户与系统.md)，①本线为本部自定）。

**禁止超卖：** 对外/对内勿把一期建项说成已交付老板册完整论证报告（销售口径仍可谈完整版套餐，系统一期不交）。

手法（字段细则、完整论证五项）→ 业务章程与老板册；**不抄进本文**。

## 5. 领域

看材料可建议技术方向粗分；建项时**可暂定**；**随时可改**。不在注册死锁。  
领域只进项目卡片备注/标签，**不改变**「创建项目」主路径，也不代替②③的专业作业。

## 6. 进门门槛：先弄清「要建项」而非别部活

> 通则见 [00 §6](00-用户与系统.md)。大厅点进① ≠ 已过门槛。

**开建主作业前：** 用户认本次目标是「开/管一个研发项目容器」（或明确要改已有项目状态），不是空喊「立不立得住」却其实要挖点/写交底。

### 6.1 进入检查表（开建前）

| 必备 | 说明 |
|---|---|
| 目标确认 | 本次要做「创建/维护研发项目」（用户认） |
| 方向线索 | 至少有一句话方向/课题名草稿，或可从材料抽出候选（可极薄） |
| 来源记录 | 前台领进 / 大厅直达 / 续改已有项目 |

无方向、只有「我想申请专利」→ 建议④/⑤或前台分诊；可建「待补方向」项目须**用户知情留痕**，否则不假装已开建。

### 6.2 两种进法 · 收件

| 来源 | 做法 |
|---|---|
| 前台领进 | **继承**前台字段；核进入检查表差额 |
| 大厅直达 | **短收件** + 进入检查表 |
| 续改已有项目 | 载入项目卡；核对权限＝当前用户可改（一期可薄） |
| 材料实为挖点/交底/申请 | 负责人建议③/④/⑤；用户坚持留①可先建薄项目挂后续 |

### 6.3 门槛不过

| 轻重 | 动作 |
|---|---|
| **重**（目标是写交底/申请/答 OA，误进①） | 建议改去正确部门；不硬建空项目充数 |
| **中**（有意向、名称未定） | 部内补问一句话方向再建 |
| **轻**（缺起止日、负责人） | 可空着建；备注缺口 |

### 6.4 进部后分流（薄）

| 问题类型 | 谁主责 | 动作 |
|---|---|---|
| 要完整论证报告 | A′ 后置 | 说明一期不交满；可选材料整理/人工另案；**仍可先建项目** |
| 要保护去向 / 拆案 | ③ | 建议工单/直达③；项目可先建好挂案 |
| 要写交底 / 递交 | ④ / ⑤ | 建议直达；**不因未论证挡主链** |
| 只有卡点无方案 | ② | 建议②；项目可后挂 |

## 7. 部内怎么干

1. 负责人与用户对齐：目标＝可跟踪项目容器（非论证报告）；是否只改状态。  
2. 核对 **进入检查表**；不过则 §6.3，不假装已立项。  
3. 分配建项（能一个就一个）。  
4. 起草项目卡 → **用户确认**名称/方向/状态。  
5. 落主数据；案卷记下项目引用。  
6. 按需提示：可挂②③④…；有下游意向可开「以后做 / 现在做」工单（发出①时结束检查表须齐）。  
7. 若用户要 A′ → 明示后置；不占用一期合格线。

```
进入门槛通过
    ↓
建项（名称·方向·状态·可选字段）→ 用户确认 → 项目可引用
    ↓ 用户要完整论证
  后置说明 / 另案（不挡建项、不挡主链）
```

**禁止：**  
把项目创建写成「已论证通过」；无用户确认冒充已建项；用未出报告拦截④⑤；把申不申/保护去向塞进①必做。

并行冲突由负责人汇总选项给用户，不私下定案。

### 7.1 请示矩阵（薄）

| 事项 | 档 |
|---|---|
| 起草卡片、抽候选名/方向、后置论证材料清单 | **自决** |
| 建议去②③④⑤、建议补挂项目 | **建议后请示** |
| **确认建项**；**状态变更**；「待补方向」知情建项 | **硬请示** |

### 7.2 部间谁打包（薄）

| 方向 | 谁 |
|---|---|
| → ②③④…「现在做 / 以后做」 | **① 部门负责人**（须结束检查表齐） |
| 事后补挂项目 | 负责人；不强迫先过①才许主链 |
| A′ 后置 | 材料清单、缺口提示 | 是否启动后置/人工；**不得**由 Agent 宣称报告已交付 |

Agent 低置信须示弱；**不得冒充**项目已确认、论证已签字。

## 8. 向用户汇报什么

| 节点 | 汇报 | 用户常拍 |
|---|---|---|
| 进入门槛 | 是建项还是该去别部 | 留① / 改去②③④⑤ |
| 建项 | 名称、方向、状态、可选字段 | **确认建项** / 改措辞 |
| 挂下游 | 案是否挂本项目；下一步建议 | 现在做 / 以后做 |
| A′（若提） | 一期不交满；后置要什么 | 先建项走人 / 另开论证 |

## 9. 多次不行 · 缺料 · 结案

| 情况 | 做法 |
|---|---|
| 名称/方向反复改 | 改卡再确认；版本留痕宜有 |
| **关键方向都说不清** | 补问或暂停；不空转「优化论证」 |
| 用户只要申请不要项目 | 可跳①直达④⑤；不强迫建项 |
| 用户暂不往下 | 暂停；项目与案卷保留 |

**不能：** 未确认建项标「已立项」；把后置报告标成一期已交付。

### 9.1 结束检查表（项目已创建 / 可挂下游）

| 必备 | 说明 |
|---|---|
| 项目 ID / 名称 | 可被下游引用 |
| 方向一句话 | 非空（或「待补」+ 用户知情留痕） |
| 状态 | 进行中 / 暂停 / 结项 之一 |
| 用户确认建项 | 当前用户已点头 |
| 缺口与备注 | 未填负责人/起止、未做论证等 |
| 工单（若开） | 现在做②③④… / 批注 |

≠ 论证报告正文；≠ ③保护决策；≠ ⑤申请文件。

### 9.2 走通画像（薄 · 对齐业务惯用）

| ID | 画像 | 产品上必须看见 |
|---|---|---|
| **L1** | 客户/总工主操建项 | 进入检查表 + 用户确认建项；可无代理协助任务 |
| **L2** | 代理协助建项 | 协助起草可见；**建项确认仍向当前用户** |
| **L3** | 点名要完整论证 | 先可建项达标；A′ 明示后置/另案；**不挡**④→⑤ |

共性：**一期合格＝项目可引用；≠ 报告已出。**

### 9.3 容易漏（产品意识清单）

不挡主路径硬闸，但案卷/备注宜有着落。

| 项 | 产品意识 |
|---|---|
| 起止 / 年度归属 | 可空；有则利于⑧汇总 |
| 项目负责人（人） | 可选字段；≠ 部门负责人 Agent |
| 下游挂接 | 案件/交底/申请尽量挂项目 |
| 状态变更留痕 | 暂停/结项原因一句 |
| 与「案卷·项目」用语 | ①＝研发项目容器；单案案卷可叫项目/案件——**别混成已论证**（见 [00 §5](00-用户与系统.md)） |
| 完整论证 / 三图 | 后置或可选；销售勿超卖为一期已交付 |

## 12. 用语对照

| 业务章程 | 产品逻辑 |
|---|---|
| 一期先「创建项目」 | **必做建项**；结束＝项目可引用 |
| 完整《决策论证报告》 | **A′ 后置**；非一期合格线 |
| 创新报告三图可选零件 | 不进一期必做；附录可挂接口 |
| A / A′ / B / C 三种立项 | §1 表；B→③、C→⑤ |
| 不因未论证挡交底→申请 | **产品硬纪律** |
| 客户/总工建项；代理协助 | 均向**当前用户**汇报；不锁身份 |
| 无独立立项产品 | 无单独「立项 SKU」冒充一期已交报告 |

## 13. 一期够用

用户↔负责人↔专家；进入检查表；创建项目；用户确认；结束检查表；L1–L3；三种立项拆开；不挡主链；前台不进部派活。

**一期可薄：** 项目权限/组织树、完整字段模板、状态工作流、与⑦⑧深聚合体验。  
**不做：** 一期必交论证报告；强制鉴新/创见撑满合格五项；用①替代③保护决策或⑤申不申；因①未做满拦截④⑤。
