## 1. 右栏本来该干什么（真源）

**产品一句**：工作台 = **文书作业台 + 领导拍板台**。你（当前用户）是领导；右边不是「另一个 AI 产品」，是**本部门负责人向你汇报、听你驾驭**的地方。

| 分工 | 放哪 | 干什么 |
|------|------|--------|
| **主栏** | 左 · 最大 | 当前步交付物（交底书 / 权项·说明书 / 答复·对照）。签字、改稿看这里。 |
| **右栏** | 右 · 约 340px | **跟本部门领导对话**：听汇报、拍硬请示、下驾驭指令。 |

右栏里各件的角色（按她当天钉过的主次分区）：

1. **跟谁聊**：默认对「本部门负责人」（技术管理层唯一汇报口）；点编制席里某个专家，才切到跟那人聊。  
2. **硬请示怎么进**：凡拿不准 / 关键关 / 硬请示 / 重要节点 → **对话流里的「汇报」气泡**（一句结论 + 可点依据 + 确认/改），**不**另开侧栏表单卡墙。  
3. **编制干什么**：告诉你「谁在台上」；轻量默认只留负责人一行，展开才见全专家名册。不是主内容。  
4. **composer**：钉在右栏底，一句话驾驭 + @材料；辅，不是整页中心。  
5. **主栏 vs 右栏**：长文不活在气泡里；判断不藏在主栏按钮里。

> **诚实：真源自己有一处拧。**  
> 大纲 §4.4.4 曾钉「侧栏三层：①硬请示钉顶 → ②依据 → ③对话」，并写「硬请示仍复制一份到层 1」。  
> 同日主次分区（Leslie 圈注后）改成「硬请示一律进对话流汇报气泡；侧栏只做编制/composer」。  
> **样机后来按「进对话」走，又想兼顾「钉顶可达」**，于是 sticky + 气泡卡叠在一起——这是懵的根之一。

## 2. 样机现在实际在干什么（一层层）

基线 `5111562` / `?v=railfix1b`，④⑤⑥ 共用 `chainSideHtml`：

| 层（上→下） | 实际 | 为什么让人懵 |
|-------------|------|--------------|
| **身份行** | 负责人头像 + 名 + 状态；右「编制」钮 | 还算清楚：这是「谁在向你汇报」。 |
| **编制席** | 默认折起，只留负责人感；点「编制」展 6 席头像 | 角色对；展开后像通讯录，和「对话」抢眼。 |
| **sticky「要你拍」** | 仅**多项**未关请示时出现跳转 chip；单项时隐藏 | 为对齐大纲「钉顶」又为去重；**规则不直观**——有时有有时无，像随机。 |
| **对话 feed** | ① 硬请示「汇报气泡」（一句结论 + 主钮；依据/理由进「展开」）② 历史闲聊/进展气泡 ③ 工具芯片（默认折成「工具 · N」） | **主戏在这**。但气泡仍带「要你拍」标签、展开区、按钮组，观感介于「人说话」和「迷你表单」之间。 |
| **composer** | 底栏「对：××负责人 · 团队」+ 输入 + 发送 | 对：正确；演示感强，和上面请示钮的关系（打字 vs 点确认）没说透。 |

**叠在一起的糊点（直说）：**

1. **两套真源没收口**：钉顶确认卡 vs 对话里汇报——样机做成「气泡为主 + 偶尔 sticky」，逻辑说不清。  
2. **右栏同时装了「组织通讯录 + 审批控件 + 聊天 + 工具轨迹」**，四件事挤同一窄栏，用户不知道先看哪。  
3. **硬请示仍像卡**：railfix 砍了摘录墙，但「结论 + 展开 + 主钮」还不是纯聊天气泡；和左边文书的关系要靠用户自己脑补。  
4. **编制 / sticky / 工具**都是辅，却都占垂直空间，对话「吃高」名不副实。

评估里写过：结构对话化了，内容仍略「卡」——设计大约 6.5–7，**不是逻辑满分后的精致问题，是逻辑叙事本身还糊。**

## 3. 逻辑该怎么钉（一句话模型）

**右栏 = 跟本部门负责人对话；其余都是对话里的事，或点开再看。**

展开成四条（给产品钉死用）：

1. **你只跟一个人说话**：默认负责人。编制是「换人聊 / 看谁在干」，不是第二套 UI。  
2. **要你拍的事 = 对话里的一句汇报**：结论 + 一个主动作；依据点开再看；**不要**再在右栏另开表单区或第二份同文 sticky。  
3. **左边是稿，右边是话**：改稿看主栏；拍板、追问、@材料在右栏。  
4. **工具、质检细项、全编制、多请示列表**：默认藏；需要时再展开——它们不是右栏主叙事。

若保留大纲「钉顶可达」：只允许 **「未关请示数 >1」时的跳转条**，且文案必须是「跳到第 N 个请示」，**禁止**与气泡同构复述「当前要你拍 · 同一句话」。
