## 1. 部门职责

把**合格交底**做成**可递交的申请文件**并递交。  
交底可来自④工单，也可用户**自带交底书**从大厅直达——但开写前都要过**交底门槛**（见 §6）。

**硬产出：** 申请文件包（权要 + 说明书/附图/摘要等）+ **递交回执/申请号**（入⑦台账）。  

**不做：** 把申请部当成交底陪写主场；替企业终裁经营；「申请文件审核」套餐签字超卖；FTO；**外观设计主路径另链**（不进本发明/实用主路径）。

## 2. 产品里有谁（只三类）

| | 说明 |
|---|---|
| **用户** | 真人（代理/发明人/企业 IP…谁登录谁是用户）；听汇报、拍板、可 1:1、可看产出 |
| **部门** | 申请部；进门看见名册与工作台 |
| **专家** | **全部是 Agent**；能一个办完不硬拆 |

没有「真人专家席」与用户并列。套餐对人签字＝服务交付另走，不进产品编制。

### 2.1 谁主持——部门负责人（不是前台）

| | 现实 | 本产品 |
|---|---|---|
| **前台** | 大厅引导、领到某部 | 只在大厅 ([01](01-接待与引导.md))；**不进部内派活** |
| **部门负责人** | 科室主办：对接、拆活、盯进度、汇总 | 申请部 **Agent**（名：部门负责人） |

前台领进门、交案卷；进部后换负责人。④工单由本部门负责人接。

```
用户 ←→ 部门负责人（主持、分配、汇总汇报）
              ↓
     接案 / 检索 / 权项 / 说明书 / 质检 …（可串可并）
用户也可 ←→ 某专家（盯细活）· 随时看产出
```

惯用上代理更常主操；企业/发明人常来确认理解、范围、递交——**系统不按身份锁**。

## 3. 编制：能一个就一个，要拆就拆

均为 Agent。

| 专家 | 对应业务段 | 职责 |
|---|---|---|
| **部门负责人** | 全程 | 收件/门槛、分活、冲突汇总、组织递交确认、开⑥工单 |
| **接案专家** | **A** | 理解复述、请用户确认、补料清单、放行/退④ |
| **检索专家** | **B** | **申请向**查新（厚于④）；命中与区别特征；≠ ④交底向、≠ ③挖点 |
| **权项专家** | **C1** | 独/从权、梯度、与交底/查新对齐；人话圈地 |
| **说明书专家** | **C2** | 说明书各块 + 附图/摘要；不编造实施例 |
| **质检专家** | **C3** | 申请文件质检（规则库 A–J）；推动改到可递交 |
| **递交助理** | **C3** | 形式检查、回执/案号回写案卷与⑦（可与质检或负责人合并） |

活少可合并呈现（如「撰写专家」兼 C1+C2）；逻辑上仍按上表。

### 3.1 边界

| | 本部门 | 不是 |
|---|---|---|
| 查新 | 申请向：申不申 + 撰写靶子 | ④薄查新自动算完；科技查新冒充；FTO |
| 权项「布局」 | 单案独/从怎么搭 | ③拆案排案；二期导航 |
| 质检 | 申请文件递交合格纪律 | 交底质检；套餐「申请文件审核签字」；质量衡器考核 |
| 理解确认 | 开案后 A | ④成稿事实确认（可继承，A 仍要对齐理解） |

### 3.2 合并呈现

| 活量 | 可合并呈现为 | 逻辑上仍分 |
|---|---|---|
| 小案、一人可串 | 「申请专家」兼 A+C1+C2 | B 检索、C3 质检宜可辨（可同人不同任务态） |
| 常写案 | 「撰写专家」= C1+C2；接案 / 检索 / 质检分席 | 递交助理可并负责人或质检 |
| 用户跳过 B | 不设检索席；案卷留「跳过认风险」 | 不假装 B 已做 |

原则：合并呈现 ≠ 取消 A 确认、C3 过线、递交硬请示。

### 3.3 协作时序

```
进入门槛 → A 理解确认 →（建议）B 查新·申不申 → C1 权项 → C2 说明书 → C3 质检循环 → 【硬】确认递交 → 回执/⑦
                              ↓ 不申
                            结案
```

| 段 | 默认可并 | 硬闸 |
|---|---|---|
| A | 补料清单起草∥读卷 | **用户确认理解**（或认风险挂起） |
| B | ∥ A 后段补料 | **申不申/类型**；跳过须认风险 |
| C1 | — | 理解未确认不锁独权终稿；**范围**用户拍 |
| C2 | 与 C1 小改可来回 | 实施例/数据属实（按需用户） |
| C3 | 改稿∥再检 | **过线**后仍须**确认递交** |

允许 A↔C1；重大新命中回 A/B；独权大改则 C2 跟改。

### 3.4 屏上闸（禁止一部一黑箱）

> 业务口径仍以上文 A/B/C 与 [一期节点/05-申请.md](../一期节点/05-申请.md) 为准；本条只钉**屏上必须露出**什么。对齐 [交互大纲 §4.4.6 / §5](交互大纲.md) · [线框-主链](线框-主链.html) · 样机 `docs/prototype/main-path-sample`。

| 段 | 屏上必须看见 | 硬请示分钮（未确认不得推进下游） |
|---|---|---|
| **A 理解** | 段进度亮「A」+ 理解摘要/复述；状态待确认/已确认 | **确认理解**（或认风险挂起） |
| **B 查新·申不申** | 段进度亮「B」+ 查新摘要或「跳过须认风险」；申/不申选项 | **申不申/类型**；跳过 B 须另认风险 |
| **C 撰写递交** | 段进度亮「C」+ 权项\|说明书（可分页）+ 质检过线态 | **确认递交**（过线后**单独**钮） |

**顺序闸：** A 未确认 → 不得开 B 硬请示终态；B 未拍「要申」→ 不得锁独权终稿进 C 主笔；C 未过线 → 确认递交钮灰；**过线 ≠ 确认递交**。

**禁止：**
- 把⑤做成「一部一黑箱」：只有总进度/「申请中」态，看不见 A / B / C 三段
- 三道硬请示并成一个总确认，或用 Toast / 静默绿勾冒充已拍
- 过线按钮兼作确认递交；B 未拍就进 C 撰写主路径

## 4. 必做 · 选做

| | 内容 |
|---|---|
| **必做** | **进入门槛**（交底成色，§6）→ **A** 理解确认 → **C1/C2** 申请文件 → **C3 质检过线** → 用户确认递交 → 递交与回执入案卷/⑦ |
| **强建议** | **B** 申请向查新 + **申不申**由用户拍板后再重投撰写 |
| **可弱** | 查新跳过须**用户认风险留痕**；④做过 ≠ B 完成 |
| **选做** | 所内第二意见、分案建议、撰写中偶发补检等 |

**申请文件质检不能跳过。** 不过线 → 改 → 再检；可暂停/退④补事实；**不能**未质检或未过线却标「已递交」。  
**A 理解确认**默认必过；仅用户**显式认风险挂起**可暂挂（留痕）。

**「过线」＝本部门递交合格（产品钉法）：**  
一期必跑档 **A+B+C+D+F+G** 无未关闭法定红灯；有交底对照则 **E**；有 B 查新则 **J** 深做；软件/商业/实用嫌疑加 **I**；**H** 策略项可先出高风险条并须用户知情。  
绿勾 ≠ 可授权承诺。细则与法条纪律 → §4.1 + [业务章程 C3](../一期节点/05-申请.md)。

申不申若拍「不申」→ 不进撰写主路径，工单结案/转其他（秘密等），不假装已申请。

**递交通道（一期钉法）：** 产品负责齐套、确认、**回执/案号回写案卷与⑦**；向官方递交的具体通道（代报/用户自递等）**实现后置**，不在本文承诺已接通官报。  
合格线用语：④全绿 ≠ ⑤过线 ≠ ⑥D 过线，见 [00 §6.1](00-用户与系统.md)。

手法（A 五问、删除测试、说明书块）→ 业务章程 + 装配说明书；**不抄进本文**。

## 5. 领域

看材料建议；收件或开写前确认；**随时可改**。不在注册死锁。  
交叉＝主领域模板 + 附加清单（电/机/化等补料与图/式差异见业务章程）。  
领域影响 A 补料清单、C2 图/式、C3 部分检项——**不改变** A→B→C 主路径。

## 6. 进门门槛：先过交底成色（含自带）

> 通则见 [00 §6](00-用户与系统.md)。大厅点进⑤ ≠ 已过门槛。

**允许**直达申请（上传已有交底），但**进 A 主写前**必须过交底门槛。

### 6.1 进入检查表（开写前）

| 必备 | 说明 |
|---|---|
| 交底正文 | 问题/方案/效果等核心可见 |
| 事实确认 | ④已有可继承；自带稿须用户再认一次 |
| **交底质检全绿** | 与④合格线相同（自带则本部门组织同标质检） |
| 领域（可暂定） | 收件时建议；开写前宜确认 |
| 来源记录 | ④工单 / 自带 / 前台领进 |

### 6.2 两种进法 · 收件

| 来源 | 做法 |
|---|---|
| 前台领进 | **继承**前台字段；核进入检查表差额 |
| 大厅直达 | **短收件** + 进入检查表 |
| ④「现在做」 | 已全绿 → 进 A（可抽查/差分） |
| ④未全绿打来 | 拒收或退④ |
| 自带交底 | 跑进入检查表；不过见 §6.3 |

### 6.3 门槛不过

| 轻重 | 动作 |
|---|---|
| **重**（空壳、事实大面积不清） | **工单退④** → 全绿再「现在做⑤」 |
| **中**（缺图/数据/几处事实） | **A 补料**再检；仍不行 → 升退④ |
| **轻**（小表述、不影响理解） | 留痕；撰写中消化 |

结构性大改默认退④；申请部只做接案补料/小改；**交底不过硬写**＝不合格路径。

### 6.4 进部后发现问题：分流（不是一律退④）

| 问题类型 | 谁主责 | 动作 |
|---|---|---|
| **交底成色 / 齐套** | ④ | 同 §6.3 |
| **理解/事实对齐** | ⑤ A | 复述确认、补问；大面积缺失升退④ |
| **三性 / 可专利性** | ⑤ B + **用户拍板** | 见下；≠ 交底质检项 |
| **申请文件写稿（A–J）** | ⑤ C3 | 部内改；根因是交底没事实才退④ |

交底全绿 **≠** 已有三性；三性主要在 B 暴露。选项：

| 选项 | 含义 |
|---|---|
| **不申** | 结案/转秘密等；不进撰写 |
| **改范围再申** | 缩权/改主题后重投 C；可留⑤ |
| **退④强化交底** | 区别特征/实施例/数据写进交底再来（撑范围，**不保证授权**） |
| **认风险仍申** | 用户留痕后继续 C；J 档如实提示 |

**禁止：** 用三性风险假装交底不合格拒检；或未全绿却用「先查新」绕过进入门槛。

## 7. 部内怎么干

1. 负责人与用户对齐：目标＝可递交申请文件 + 回执；是否做 B；领域。  
2. 核对 **进入检查表**；不过则 §6.3，不假装开写。  
3. 分配 A/B/C（能一个就一个；可串可并，如补料∥查新）。  
4. **A** → 用户确认理解（或认风险挂起）。  
5. **B**（建议）→ 用户拍申不申/类型；不申则结案。查新手法 → [接口-查新](../一期节点/接口-查新.md)。  
6. **C1** 权项 → 用户确认技术+范围 → **C2** 说明书/图/摘要（消费 B；实施例问用户）。  
7. **C3** 质检过线 → 用户确认递交 → 递交 → 回执/案号 → **当日入⑦**。  
8. 有 OA → 用户确认后开「现在做⑥」工单；否则维护⑦。

```
进入门槛通过
    ↓
A 理解确认 → B 查新·申不申（可弱）→ C1 权项 → C2 说明书 → C3 质检·递交 → ⑦
    ↓ 不申
  结案（非已申请）
```

允许 A↔C1；重大新命中回 A/B；独权大改则说明书跟改。  
**禁止（对齐业务纪律）：**  
理解未确认锁独权终稿；交底粘贴当说明书；无支持特征进独权；超出交底加料；检索编造实施例；无人确认递交；把 A 当成「还在写交底」主场；空命中当查新过关；报授权概率当结论。

并行冲突由负责人汇总选项给用户，不私下定案。

### 7.1 请示矩阵（自决 / 建议后请示 / 硬请示）

| 事项 | 档 | 说明 |
|---|---|---|
| 复述草稿、特征表、补料清单、检索整理、权项/说明书草稿、质检出项与改稿建议 | **自决** | 对应专家 |
| 领域确认建议、是否做 B、分案费用提示、H 策略高风险条 | **建议后请示** | 负责人/专家建议 → 用户知情或拍 |
| **确认理解**；**申不申/类型**；**跳过 B 认风险**；**权项范围**；**确认递交** | **硬请示** | **当前用户** |
| 退④ / 认风险仍申 / 不申结案 | **硬请示** | 用户（负责人备选项） |

Agent 低置信须示弱；**不得冒充**理解已确认、申不申已决、递交已授权。

### 7.2 质检节奏（C3 · A–J）

1. **何时检**：C1/C2 有可递交候选包后做首次检；重大独权改后须再检。  
2. **分档**：一期必跑 **A+B+C+D+F+G** 无未关闭法定红灯；有交底对照则 **E**；有 B 则 **J** 深做；嫌疑加 **I**；**H** 可先出高风险条并须用户知情（§4 过线）。  
3. **谁推动改**：质检专家出项 → 权项/说明书专家改 → 再检；根因是交底没事实 → 升退④（不空转）。  
4. **过线后**：负责人组织「确认递交」硬请示 → 递交助理/负责人走回执与⑦。  
5. **预检**：撰写中可抽检，**预检绿 ≠ 已递交**。

## 8. 向用户汇报什么

| 节点 | 汇报 | 用户常拍 |
|---|---|---|
| 进入门槛 | 交底成色能否开写 | 补料 / 退④ / 轻留痕 |
| A | 理解对不对、缺什么 | 确认理解 / 补料 / 退④ |
| B | 查新或跳过风险；申不申建议 | **申不申、类型** |
| C1 | 人话圈地、过宽过窄 | 范围与预算（分案） |
| C2–C3 | 稿件与质检；是否递交 | 技术是否写歪；**是否递交** |

## 9. 多次不行 · 缺料 · 结案

| 情况 | 做法 |
|---|---|
| 申请质检红灯、材料够 | 限定焦点改稿 → 再检 |
| **关键事实/图/数据没有** | 回 A 补问；仍无 → **退④或暂停**，不空转优化 |
| 查新致范围必须收 | 报用户改范围或退④强化交底 |
| 用户暂不往下 | 暂停；案卷保留 |

**不能：** 未过线标已递交；未确认递交就递交。

递交成功 → 案号**当日**入⑦；后续 OA → 工单⑥。

### 9.1 结束检查表（已递交 / 开「现在做⑥」）

| 必备 | 说明 |
|---|---|
| 进入门槛记录 | ④全绿继承或自带检通过 |
| A 理解确认 | 已确认或认风险挂起 |
| 申请文件包 | 权要 + 说明书/附图/摘要等（随类型） |
| 申请质检过线记录 | 含末次摘要；**无未关闭法定红灯**（§4 过线定义） |
| 递交确认 | 用户拍范围/是否递交 |
| 回执 / 申请号·申请日 | 落案卷并回写⑦ |
| B | 做了：结论/命中摘要；跳过：认风险留痕 |
| 缺口与备注 | 选做未做、H 策略知情、§9.3 易漏项备注等 |
| 工单（有 OA 时） | 现在做⑥ / 批注 |

≠ ⑥答复正文；≠ 授权结果。

### 9.2 走通画像（对齐业务 S1–S3）

产品过线用 §9.1；验收对照 [业务 §6](../一期节点/05-申请.md)：

| ID | 画像 | 产品上必须看见 |
|---|---|---|
| **S1** | 有 IPR / 大企业惯用 | A 理解确认仍做（④批过 ≠ 免 A）；B 查新+用户申不申；C1 范围可见；C3 递交用户拍 |
| **S2** | 无 IPR / 小企业 | A 可变厚；B 可弱但**认风险留痕**；申不申/递交常由同一当前用户拍 |
| **S3** | 生物医药重数据 | 生医/领域清单启用；通式宽度用户知情；实施例有数据来源；**无编数据** |

共性：**理解未确认不写独权终稿；无人确认不递交。**

### 9.3 容易漏（产品意识清单）

不挡主路径硬闸，但案卷/备注宜有着落；细则手法见业务文。

| 项 | 产品意识 |
|---|---|
| 申请类型 | B/C 用户拍发明/实用等 |
| 单一性 / 分案 | C1 选项+费用；用户拍 |
| 删除测试 | C1 建议做；手法在业务文 |
| 术语一致 | C3 / 质检意识 |
| 公开 vs 秘密 | 不申或公开风险 → 用户拍 |
| 优先权 / 国别 | 一期可薄；有则留痕 |
| 请求书著录 / 委托范围 | 递交前齐套意识 |
| 版本留痕 | 权项/说明书重大版进案卷 |
| FTO | **≠ 查新**；另案或外挂，不绑默认申请交付 |
| 外观 | 另链，不进本发明/实用主路径 |

## 11. 交出去 · 边界

| | 内容 |
|---|---|
| ← ④ | 工单 + 案卷（交底全绿、领域、已知附件等；缺项开案则 A 补齐留痕） |
| → ⑥ | 有 OA 时工单 + 结束检查表内容（含查新摘要/权项映射若有） |
| → ⑦ | 申请号/申请日等（递交当日） |
| ≠ | 交底重写主业；申请文件审核套餐签字；授权承诺；外观主路径；FTO 默认捆绑 |

### 11.1 段间交出（可中停）

| 段 | 案卷宜有 |
|---|---|
| A | 已确认理解、特征/补料、放行或退④留痕 |
| B | 查新结论或跳过认风险、申不申留痕 |
| C1 | 独/从结构与发明点映射 |
| C2 | 说明书+图/摘要齐套 |
| C3 | 质检过线、递交确认、**回执** |

### 11.2 部间工单谁打包

| 方向 | 谁打包 | 包内要点 |
|---|---|---|
| **← ④** | 交底部负责人已打包（见 [04 §8.1](04-交底.md)）；本部门负责人**接单核验** | 进入检查表；可抽查全绿 |
| **→ ⑥** | **申请部 · 部门负责人**（有 OA / 用户确认开⑥时） | 结束检查表要点 + 申请号 + 申请文件指针 + 查新摘要/权项映射（若有） |
| **→ ⑦** | 递交助理或负责人 | 申请号/申请日等**当日**入台账 |

开「现在做⑥」前置：§9.1 结束检查表齐（至少已递交回执在卷）。

## 13. 一期够用

用户↔负责人↔专家；进入检查表；A→（建议）B→C；请示矩阵（§7.1）；质检节奏 A–J（§7.2）；回执入⑦；S1–S3；易漏意识；段间交出；⑤→⑥谁打包（§11.2）；手法链业务文与 Excel。

**一期可薄：** 深 PCT/国别、完整 FTO、外观链、自动制图、删除测试全量、多国同族。  
**不做：** OA 答复本体（⑥）；FTO 绑默认申请；④ 成稿主业；③ 拆案排案本体；用检索代替实施例。
