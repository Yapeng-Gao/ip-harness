# 主路径规格 v4（了解 → 汇报 → 执行）

> 状态：规格已确认（按推荐填）· 未动手实现  
> 对照：v2 @8766 · v3 @8767（执行段可复用）  
> 理念不变：虚拟知产公司 / 尽快申专利 · apps/agent 壳不动

---

## 1. 一句话

进应用先了解人，首页展示全部能力（部门+专家），用户可选可不选；上传材料后由材料分析专家做二次了解并汇报（目标 / 谁能做 / 正常流程 / 材料够不够）；确认新建或并入项目后，再进入现有执行逻辑。

---

## 2. 阶段总览

| 阶段 | 名称 | 系统做什么 | 用户做什么 | 产出 |
|------|------|------------|------------|------|
| A | 进应用 · 初步了解 | 引导收集用户信息 | 填/答基础信息 | 用户画像 v1 |
| B | 首页 · 能力地图 | 展示全部部门与专家 | 可选点部门/专家，或不选 | 可选的意向（可空） |
| C | 上传材料 | 接收文件 | 丢材料 | 原始材料包 |
| D | 材料分析 · 二次了解 | 材料分析专家：分析→分类→归档 | 等待 / 可补充说明 | 材料画像 + 归档结果 |
| E | 汇报 | 说清目标、部门/专家、流程、材料缺口 | 阅读；可补料也可不补 | 汇报卡（可确认） |
| F | 项目归属 | 建议新建或并入旧案；吃不准则标歧义 | 拍板：新建 / 合并 / 再说明 | 已确认项目 |
| G | 执行 | 沿用现有执行逻辑（部门开工、缺项闸、聊、交卷） | 协同与拍板 | 交卷物 / 在办态 |

原则：**先了解人 → 再了解料 → 再讲清能做什么与缺什么 → 再定项目 → 再执行。**  
首页是能力地图，不是已经在办的工作台。

---

## 3. 各阶段细则

### A. 进应用 · 初步了解（第一次了解）

**目的**：建立用户画像 v1，后续汇报与推荐有依据。

**最少收集（可原型假数据，但字段要齐）：**
- 身份倾向（发明人 / 代理人 / 企业对接 / 其他）
- 领域或技术方向（可粗）
- 当前诉求一句话（可空，后面材料再补）
- 是否已有在办项目（是/否/不确定）

**闸：** 默认可跳过（已定）；跳过则画像偏弱，汇报里明示「了解不足」。

**落地页：** 欢迎/画像收集页（新），完成后进首页。

---

### B. 首页 · 能力地图

**目的**：一眼看到公司有谁、能干什么；降低「不知从哪下手」。

**必须可见：**
1. **全部部门**：名称、一句话职责、预设标准流程摘要、编制专家列表入口  
2. **全部专家**：姓名/角色、预设能力标签、所属部门、一句「找我能做什么」

**交互：**
- 点专家 → 记下意向专家（**单选**，可取消）
- 点部门 → 记下意向部门（**单选**，可取消）
- **允许谁都不点**，直接走上传

**不在首页主路径强调：**
- 已在办工作台三栏（卷宗/文书/右栏）——那是阶段 G
- 伪装成 SaaS 仪表盘的「待办洪水」——最多弱入口

**主 CTA：** 「上传材料，开始了解」类（文案可调）

---

### C. 上传材料

**目的**：拿到原始材料包。

**行为：**
- 支持多文件；类型不限（原型可提示常见：交底草稿、图纸、聊天记录、已有申请文件等）
- 不强制先选部门/专家
- 若 B 有意向，上传页顶部轻显「当前意向：XX 部 / YY 专家」（可改）

**闸：** 至少 1 个文件才可进入 D；空上传不可进分析。

---

### D. 材料分析 · 二次了解

**执行者：** 固定角色「材料分析专家」（可挂在某个部门下，但阶段 D 必跑，不因用户未选专家而跳过）。

**动作顺序：**
1. **分析**：材料说了什么、与专利/交底相关的线索  
2. **分类**：交底类 / 证据类 / 已有法律文件 / 杂项…  
3. **归档**：进入本案材料库结构（未建项目前进「待归案材料池」）

**产出（给阶段 E 用）：**
- 材料清单（含类型标签）
- 推断目标（如：写交底书 / 准备新申请 / 补正…）置信度
- 建议相关部门与专家
- 材料缺口列表（每项：缺什么、为何需要、是否阻塞）

**闸：** 分析未完成不可进 E；失败可重试，不静默空过。

---

### E. 汇报（给人看清再动手）

**向用户一次性说清（一块汇报卡/页，可滚动）：**

1. **你大概要做什么**（推断目标 + 置信；低置信要明说）  
2. **有哪些部门、哪些专家、各自能做什么**（可高亮与推断相关的；完整列表可折叠）  
3. **正常流程是什么样**（该目标对应的标准步骤，来自部门预设流程）  
4. **现有材料支不支持**（够 / 勉强 / 不够）  
5. **缺什么材料**——每条可「去补充」或「暂不补充」；**不挡死**进入 F

**用户动作：**
- 补充材料 → 回到 C/D 增量分析后刷新汇报  
- 不补充 → 直接进 F  
- 纠正目标（「我不是要交底，是要…」）→ 刷新汇报，不直接跳执行

**闸：** 用户点「下一步：定项目」才进 F。

---

### F. 项目归属

**系统建议：**
- 新建项目（默认当无匹配旧案）  
- 或并入已有项目 X（需列出匹配理由）

**吃不准：**
- 标「系统确认不了」  
- 列出歧义点  
- **禁止静默合并**；必须人拍板

**用户拍板：** 新建 / 并入指定案 / 再说明后重判

**闸：** 无已确认项目不可进 G。

---

### G. 执行（沿用现有）

进入已确认项目的工作台后，**复用 v3 已收口的执行逻辑**，包括但不限于：
- 部门/专家开工与在办态  
- 缺项 chip → 拍板  
- 右栏：experts → gap → triad → chat → compose  
- 卷宗 / 文书 / 确认闸与聊

本规格 **不重写执行段交互**；仅规定「从哪进入执行」与「进入前必须完成 A–F」。

## 4. 页面清单（规格层，非视觉稿）

| 页/态 | 对应阶段 | 备注 |
|-------|----------|------|
| 欢迎/画像收集 | A | 可跳过策略见上 |
| 首页·能力地图 | B | 部门墙 + 专家墙 + 上传 CTA |
| 上传 | C | 可从首页进入；可带意向 |

| 项目归属 | F | 新建/合并/歧义 |
| 工作台（执行） | G | = 现 v3 执行段 |

弱入口可保留：消息、账单、成员等后勤——不挡主路径。

## 5. 状态机（简）

```
未登录 → A(画像) → B(首页)
B → C(上传) → D(分析) → E(汇报)
E → (补料) → C/D → E
E → F(项目) → G(执行)
任意：B 可选意向；意向可空
F 歧义：停在 F 直到人拍板
```

## 7. 验收闸（规格确认后实现时用）

1. 进应用先见画像收集（或明确跳过），不是直接工作台  
2. 首页可见全部部门 + 全部专家及预设能力/流程  
3. 不选人也能上传并触发材料分析  
4. 分析后汇报含：目标、部门专家、流程、材料支持度、缺口（可跳过补料）  
5. 项目新建/合并在吃不准时必须人拍板，无静默合并  
6. 确认项目后进入的执行体验与现 v3 执行段一致（缺项/1:1/发送等）  
7. 理念文案不跑偏：虚拟知产、尽快申专利
