## 0. 样机目标（一句话）

做出「走进新质数研发创新团队」的**可点主链**：大厅 → 前台分诊（上传→分析→建议→确认）→ ④交底协同场 → 工单交⑤ → ⑤申请关键闸 →（可点）⑥答复；人能感到**部门/专家团在办 + 硬请示拍板**，不是聊天机器人，也不是黑白说明书。

**不做（本期样机）**：①②③⑦⑧细屏（门在、进得去、合格线一句话即可）；真后端；apps/agent 壳改造；高保真动效规范。

## 1. 信息架构（顶层）

```
产品壳（样机单页或轻路由）
│
├─ 大厅
│   ├─ 品牌条：新质数研发创新团队 · 专家向你汇报
│   ├─ 前台接待（突出入口）
│   ├─ 八部门名牌（①～⑧ 均可见、可点）
│   └─ 案卷条（当前项目/未完成工单 · 可薄）
│
├─ 前台（分诊）
│   └─ 上传 → 分析产出 → 建议部门 →【硬】确认去向 → 交办清单 → 领进部门
│
├─ 部门内通用壳（④⑤⑥ 厚做；薄部占位）
│   ├─ 顶栏：部门名 · 返回大厅 · 本部门合格线状态
│   ├─ 负责人条（主持，非前台）
│   ├─ 专家名册（可点；质检席不与成稿糊成一张）
│   ├─ 协同场：段进度 + 主产出全文区（不靠聊天碎片）
│   ├─ 请示区：硬请示置顶/打断
│   └─ 案卷抽屉：材料 / 检查表 / 工单 / 判断痕迹
│
└─ 贯穿（不进八部门大门）
    └─ 情报等：文案「另链/旗舰」即可，不做第九部
```

**驱动序（钉死）**：用户上传资料 → 系统自动分析 → 系统主动提出该做什么/去哪部 → 用户确认 → 分配预设部门/专家（团）执行 → 关键处硬请示 → 合格线过后再交下一部 / 终稿感交付。

**非驱动**：首页对话栏推主路径；静默合并项目；自动绿勾代替确认。

## 3. 部门内协同场（④ 为样机标杆）

用户确认可执行后，系统展示**预设编制**（负责人 + 专家/专家团），不是空聊。

| 区块 | 用户看见 | 可做 |
|---|---|---|
| 负责人 | 进度汇总、建议派谁 | 对负责人说话（辅） |
| 专家名册 | 谁在岗、是否在办 | 点专家看 TA 的子任务/子产出 |
| 在办 | 各专家当前步骤 | 只读进度 |
| 子产出 | 成稿段落/质检项/附件 | 提问修改（辅通道）；改技术含义→再硬请示 |
| 硬请示 | 缺料、事实确认、可交下一部 | **必须手动确认**；未确认不得标下游完成 |
| 终稿感 | 本部门合格线过线后的交卷/工单 | ④＝全绿后「现在做⑤」 |

## 4. 视觉与产品气质（样机约束，非视觉定稿）

| 要 | 不要 |
|---|---|
| 管理软件 / 公司大厅感；清晰层级 | 黑白线框说明书风；衬线论文风当主 UI |
| 新质数（或 NOVADA 若品牌钉）公司一句 | 「虚拟知产」试做文案继续当主品牌 |
| 硬请示像签字确认条 | Toast 自动过；聊天气泡代替确认 |
| 产出在中间大区可读 | 只在对话流里碎聊 |

色板/字体不锁死；先结构+可读+公司感。
