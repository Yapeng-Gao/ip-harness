## 3. 欢迎页 `/agent/welcome`（未登录 · 宣传站）

对齐：vision §3.3 A · pages §4.0p · 原型 `welcome.html`。

### 3.1 路由与谁用

| 字段 | 定稿 |
|---|---|
| 路径 | `/agent/welcome`（未登录默认可达；已登录访客可直送 `/agent`） |
| 谁用 | 未登录访客；演示前 |
| 性质 | **非干活页**：无交卷 / 齐套勾选 / 确认拍板 / 进部门作业 |
| 视觉 | 浅色纸白；对齐 main-path 浅色 token |

### 3.2 逐块要素（上→下 · 货 > 文）

| 序 | 块 | 必须要素 | 规则 |
|---|---|---|---|
| 1 | **Hero** | **大标题**固定文案「**外挂知识产权部**」；**定位句**一句（推荐：「把办专利的全流程，拆成七个可交卷的部门。专家出建议稿，你来拍板。」）；禁再堆理念散文 | 字号明显大于后文；居左或居中均可，须一眼可读 |
| 2 | **CTA 行** | 主：「**登录干活**」→ `/agent/login`；次：「**先看货架**」锚到本页 `#shelf`（或等价货架锚点） | 主 CTA 实心 `slate-900` 白字；次 CTA ghost/弱边 |
| 3 | **七部徽章墙** `#shelf` | 七部全部露出：交底 → 查新 → 立项 → 撰写 → 附图 → 递交 → 答复；**每部**：部名 + **职责一句** + **≤3 专家**照片风头像占位（可灰态） | 当前演示部可高亮；禁无部门骨架的花名册墙；灰态只认知，不可点进作业 |
| 4 | **场景卡** | ≥2 张（推荐 3）：**企业走七部** / **代理多案** /（可选）确认拍板 | 白话一句；**不可**当作业入口 |
| 5 | **交卷·待确认样例橱窗** | 1 组示意：交卷物缩略 + 「待你确认」样例文案 | 只展示；无真实确认按钮；明示「登录后在部门台打开」 |
| — | 页脚提示 | 「宣传站 · 未登录可达 · 无交卷 / 齐套 / 拍板」一类 | 可极小字 |

### 3.3 七部职责一句（施工用 · 与原型一致）

| 部 | 职责一句（徽章副文） |
|---|---|
| 交底部 | 交底 · 事实核对 |
| 查新部 | 检索 · 结论稿 |
| 立项部 | 申不申 · 报价 |
| 撰写部 | 权项 · 说明书 |
| 附图部 | 图面 · 标注 |
| 递交部 | 包齐 · 递交 |
| 答复部 | 审查意见 |

（叙事可润色，但须保留「部名 + 一句职责」结构；不得换成 Agent/Harness/Seat 黑话。）

### 3.4 禁止（欢迎页）

- 本页交卷 / 齐套 / 确认拍板 / 进部门作业  
- 登录后待确认真列表  
- 把本页整页复制成登录后 `/agent`  
- 暗色皮肤；对外 Agent / Harness / 智能体编排 / Seat / HITL  
- 要求登录才能看懂品类  

### 3.5 验收（欢迎页）

1. 未登录打开 `/agent/welcome` → 200；大标题为「外挂知识产权部」。  
2. 可见：CTA 登录 + 先看货架；七部墙（每部职责一句 + ≤3 头像）；场景卡；交卷橱窗。  
3. 页内无可用交卷/齐套/拍板控件。  
4. 点「登录干活」→ `/agent/login`。  
5. 截图不靠长文也能读出「外挂 IP 部 / 七部办事」。

## 4. 登录后 `/agent` 薄入口（真双角色）

对齐：vision §3.3 B · pages §4.0a（本文件钉死「禁止三卡平铺」）。

### 4.1 总规则

| 规则 | 定稿 |
|---|---|
| 壳 | 代理与企业**同路由同壳**；**主视觉按角色分化** |
| 主 CTA | **一屏一个**，独占主视觉（大按钮 / 大卡均可，但**不得**并排三个同级大卡） |
| 待确认 | 主 CTA 下方：**真列表或空态**；点条目离开本页去确认页；**不在本页批** |
| 弱链 | 另一角色入口、次要动作 → **仅文字弱链**（下划线/灰色），不得做成第二排大卡 |
| 定位句 | ≤1 句可留（如「外挂知识产权部」或「当前角色：代理」）；可省 |
| 禁止 | 三卡平铺；七部墙 / 专家橱窗 / 场景卡 / 货架；交卷齐套拍板；无首页仅 Redirect |

### 4.2 代理视图（`entryRole === agency`）

| 块 | 定稿 |
|---|---|
| 主 CTA | 文案「**进入案盘**」（或「多案流水」作副标）；`href=/agent/cases`；独占主视觉 |
| 待确认 | 列表在主 CTA 下；有则列出，无则空态一句 |
| 弱链 | 「开案子」「公司首页 / 最近案」等 → 文字链；**不得**与主 CTA 同级大卡 |
| 不出现 | 企业主 CTA 大卡；三格网格 |

### 4.3 企业视图（`entryRole === enterprise`）

| 条件 | 主 CTA | href |
|---|---|---|
| **有案** | 「**进入本公司**」（副标可用当前案名） | 当前/最近案 `cases/:id` 公司首页 |
| **无案** | 「**开案子**」 | `/agent/cases/new` |

| 块 | 定稿 |
|---|---|
| 待确认 | 同代理：列表在主 CTA 下 |
| 弱链 | 「案盘 / 多案流水」等 → 文字链 only |
| 不出现 | 代理「进入案盘」大卡与企业主 CTA 并排；三格网格 |

### 4.4 布局示意（实现约束 · 非线框）

```
┌─────────────────────────────────────┐
│  ≤1 句定位 / 当前角色                 │
│  ┌───────────────────────────────┐  │
│  │   主 CTA（唯一大块）            │  │  ← 按角色二选一，非三选一网格
│  └───────────────────────────────┘  │
│  待你确认                            │
│  · 【案】部门已交卷 · 待你确认：…     │
│  · …                                 │
│  弱链：开案子 · 公司 · 案盘 …         │  ← 纯文字，非大卡
└─────────────────────────────────────┘
```

### 4.5 data / 测试锚点（建议 · 壳实现）

| 锚点 | 含义 |
|---|---|
| `data-home="thin-entry"` | 薄入口根 |
| `data-entry-role="agency\|enterprise"` | 当前角色 |
| `data-testid="home-action-primary"` | **唯一**主 CTA（可见，非 sr-only） |
| `data-testid="home-primary-actions"` | **不得**再渲染三列同级大卡网格；若保留容器，子节点主 CTA 大卡数 = 1 |
| `data-testid="home-secondary-actions"` | 弱链容器 |
| `data-testid="home-pending-entry"` | 待确认区 |

**作废**：登录后 `sm:grid-cols-3` 三入口大卡；`home-action-cases-card` / `company-card` / `new-card` **同时**作为同级可见大卡（弱链可用文字链保留 testid，但样式不得像主 CTA）。

### 4.6 验收（薄入口）

1. 登录选「代理」→ `/agent`：主视觉仅「进入案盘」大 CTA；**无**三卡网格；待确认在下；开案子/公司为弱链。  
2. 登录选「企业」且有案：主视觉「进入本公司」；案盘为弱链。  
3. 登录选「企业」且无案：主视觉「开案子」；案盘为弱链。  
4. 代理截图与企业截图**主 CTA 文案不同**；不得靠高亮色差假装分流。  
5. 页内无七部墙 / 专家橱窗 / 场景卡 / 交卷齐套拍板。  
6. 点主 CTA 离开本页；点待确认条目进确认页。
