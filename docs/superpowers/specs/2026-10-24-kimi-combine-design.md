## 1. 结合原则

1. **理念跟 Kimi**：一家公司 + 一个负责人持续委托 + 部门按需可见 + 可信交付；品牌句仍「外挂知识产权部」；品类可称虚拟知产公司。
2. **硬闸跟咱们**：G1–G3；七部 = 导航投影（不扩默认十部）；登录后薄入口 hops；**壳不动**（禁改 `apps/agent`）。
3. **落点顺序**：本 spec → vision / pages / design（分域）→ 重做 `docs/prototype/main-path-v2` → 验收 PASS 后再谈壳；旧 `main-path/` 保留不覆盖。

## 2. 入口与首页

- 登录后仍走**薄入口 hops**；禁拆成 Kimi 式跨案「公司经营首页」。
- 薄入口：一主 CTA（顾言持续委托）+ 「现在需要我处理」轻量轨（待确认 / 待接力）；跨案「正在推进」**不做**完整经营台。
- 公司页：七部网格仍是认知锚；助手档弱化部门墙，项目档保留；部门退二线，由负责人路由。
- 宣传页在登录前；钉「外挂 IP 部」。

## 3. 工作台 / 深度 / 确认

- **两工作台 B** 保留：企简版 / 代卷宗三栏；中栏文书；协同面（计划 / 专家 / 确认）同页或 Tab 切换；**禁空总台**。
- **三档真行为**：助手藏侧栏与部门地图；项目 = 日常干活；专业 = 工作室占位——同一底座，非三套壳。
- **确认**：G1–G3 硬闸不动；Kimi 四类确认作**类型标签**；确认后可见交付快照。
- **持续委托可点链**：提目标 → 计划可调 → 部门执行 → 确认 → 接力（原型须走通，不只 toast）。
