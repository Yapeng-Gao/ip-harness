## 1. 目标与成功标准

把「外挂知识产权部」从**结构正确**推到**一眼像在办事**：

| 成功 | 失败 |
|---|---|
| 研发/代理人不学编排黑话也能回答：现在在哪个部门、交卷齐了没、谁该确认 | 像 Agent 目录、仪表盘假指标、灰按钮仍可点 |
| 交卷闸 / 确认权在 UI 上不可绕过（与 confirmGate G1–G3 一致） | 装饰性「下一步」、专家自批冒充确认 |
| 浅色、克制、按压与焦点可感（apple-design / make-interfaces-feel-better / web-design-guidelines） | 暗色皮、堆动画、无 focus-ring |
| **截图能分出「企业简版重心」vs「代理卷宗三栏」，且仍是同一部门路由模板**（两工作台 B） | 两套产品壳、空总台、同页滤权限冒充双角色 |

## 2. 浅色设计语言（已评估锁定）

| Token / 规则 | 取值 | 理由 |
|---|---|---|
| 底 | 纸白 `#fff` / 分区 `slate-50` | 办公纸感，非消费 App 炫彩 |
| 字色 | 标题 `slate-900`，正文 `slate-600`，辅 `slate-400` | 层次靠字重+对比，不靠色块 |
| 强调 | 主 CTA `slate-900` 白字；告警/待确认 `amber` | 确认权用琥珀，不做彩虹状态 |
| 圆角 | 外 `radius-lg` · 内 `md` · 芯片 `sm` | 同心，避免嵌套同半径 |
| 阴影 | 仅 `--shadow-rest`；抬起态不加厚 | 克制；层级靠边线+间距 |
| 按压 | `.btn-press` → `scale(0.96)`，pointer-down 即时 | apple-design §1 Response |
| 焦点 | 统一 `.focus-ring` | web-design-guidelines a11y |
| 数字 | `tabular`（铃铛徽标、齐套计数） | 徽标不跳 |
| 头像 | 真人照片风 + `outline-black/10`（深底 white/10） | 部门专家拟人，禁字母圆/机器人插画 |
| 动效 | 抽屉 CSS 滑入；`prefers-reduced-motion` → 淡入 | 无 framer 依赖本轮；可打断优先 |
| 禁用 | 暗色皮肤、假 KPI 环、Agent/Harness/Seat 对外文案 | vision §3 |

## 3. Figma 六帧（一文件 · Frame 顺序即主路径）

文件建议名：`IP外挂部 · 主路径 2026-10-23`  
画板：1440×900（桌面）；每帧标注：路由、角色（企业/代理）、硬闸。

### Frame 1 · 宣传站 `/agent/welcome`
- **感觉**：货架 · 品类/场景卡片叠放 · 「登录再干活」
- **首屏**：定位句 + 七部/场景货架（可滚动）；主 CTA「登录」；无侧栏干活入口
- **业务**：非案内；不展示交卷闸
- **禁**：登录后薄入口的三入口复刻成宣传长页

### Frame 2 · 登录 `/agent/login`
- **感觉**：一张干净表单；企业 / 代理角色一眼可选
- **首屏**：品牌短句 + 角色切换 + 登录；无货架
- **业务**：写入角色后默认落点（企业→公司首页链路；代理→多案）

### Frame 3 · 薄入口 `/agent`（登录后）
- **感觉**：总览薄壳 · **一屏一个角色主 CTA** + 待确认 · 无宣传长文
- **首屏**：≤1 句定位；**禁止三卡平铺**——代理主 CTA「进入案盘」；企业有案「进入本公司」/无案「开案子」；另一角色仅弱链；待确认列表
- **业务**：待确认来自确认队列；点条目进确认页
- **作废**：本帧旧「三入口卡」；施工以 [2026-10-23-welcome-thin-home-dual-role.md](2026-10-23-welcome-thin-home-dual-role.md) §4 为准
- **知产负责人入口（MVP 增强 · vision §3.1c + pages §4.0a）**：
  - 可弱入口或短表「交办业务目标」→ 出计划 → 落到部门
  - **不**替代主 CTA；**不**在本页交卷/拍板
  - **不拆** hops（登录 → 薄入口 → 公司 → 部门 → 铃铛）
  - **禁万能 Agent** / 外挂聊天窗顶替本入口
  - 四类目标细目由 product-logic 承接（本文不编造清单）

#### §3.5 开案子增强（pages §4.1 · 不另开 Frame）
- 开案子同样**可交办业务目标**（可选 · MVP 增强）
- 交办后仍进**公司首页**再「去当前部门」
- **禁万能 Agent**；不拆现有 hops；细目仍归 product-logic

### Frame 4 · 公司首页 `cases/:id`
- **感觉**：一案一公司 · 「现在在哪个部门」
- **首屏**：定位句；七部网格（每部 ≤3 照片头像）；点卡 → 右侧抽屉（同构部门钉栏内容）
- **硬闸露出**：部卡交卷态文案（未齐套 / 待确认 / 已移交）清晰，无假进度环
- **交互**：抽屉 portal、inert 背景、Tab 陷阱、Escape 回焦（实现已有，mock 需画出开态）
- **不变**：本页结构（网格+抽屉）不因两工作台 B 改写；部内作业重心见 Frame 5

### Frame 5 · 部门台 `cases/:id/depts/:slug`（同一模板 · 两工作台 B）
- **同一部门页模板**（同路由 `cases/:id/depts/:slug`）；**禁两套产品壳**；**禁空总台**
- **两工作台 B（角色默认重心 · vision §3.1b / §6.3a · pages §2）**：
  1. **代理默认** = **卷宗 Cursor 三栏**：左目录 / 中产出 / 右对话
  2. **企业默认** = **简版重心**：事项 / 已确认事实 / 待决策；可收折为轻量三栏；中栏可抬事项/事实/决策，左目录可收折
- **布局骨架（三栏仍共用）**：
  1. **左 · 目录**：本案/本部门材料树（交卷物节点、附件、版本）；点选决定中间展示什么；企业简版可收折
  2. **中 · 工作区**：代理 = 产出物（交底正文、查新报告、权利要求等）；企业 = 可将事项 / 已确认事实 / 待决策抬到主视线；齐套勾选挂在当前产出相关项上，不抢中间阅读
  3. **右 · 对话区**（**两侧角色均保留**）：专家协作对话 + **待你确认**（采纳/驳回、缺什么、交卷按钮）；**G1** 未齐套时交卷禁用就画在这里；专家建议稿 ≠ 确认；**质检 ≠ 确认权**
- **硬闸 G1**：未齐套 → 右侧「交卷」不可用（视觉+禁用态）；缺项列表在右侧可见
- **浅色 token**：沿用 §2；禁暗色 OS、假 KPI、Agent 黑话目录名
- **与旧稿差异**：废弃「主区交卷清单 + 右钉专家」两栏；亦废弃「仅代理 Cursor、企业另壳」；F5 mock **须画出企业简版与代理卷宗两种默认态（同路由）**（可同帧双标注，或 Frame 5b 对照）
- **验收句（必须）**：**截图能分出「企业简版重心」vs「代理卷宗三栏」，且仍是同一部门路由模板，不是两套产品壳**；右栏两侧角色均露出 G1 交卷闸与确认条

### Frame 6 · 确认页 `/agent/pending/...`
- **感觉**：人拍板 · 「待你确认」（独立路由；部门台右侧也可嵌入同构确认条）
- **首屏**：交卷摘要、确认人、采纳 / 驳回；专家建议稿标注「非签字」；质检勾选不可冒充确认
- **硬闸 G2/G3**：无确认人不可推进；起草人不得自批（mock 用禁用+说明）；G1–G3 **硬闸原文不动**
- **与三栏关系**：部门台干活时确认在**右栏**；铃铛进独立确认页仍保留（多案待办）
