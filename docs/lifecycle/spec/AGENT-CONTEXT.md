### 00-inventor-disclosure · 节点 00 · 发明交底（Invention Disclosure）· 产品级业务规格（73 条）

- `R00-01` 发明名称与至少一名发明人必填，缺一不可提交
- `R00-02` `patent_type` 必须显式确认后才算六项齐套。这是类型记录。D2 的最终类型在 02，不在本节点定死
- `R00-03` 同一发明人 30 天内提交标题相似度 > 0.9 的交底，提示「疑似重复提报」
- `R00-04` 部门必须来自组织架构，不接受自由文本
- `R00-05` `targetStage` 必须显式选择。它是立案路由，不是 §4.5 的建议去向。不决定检索，也不决定 Go
- `R00-06` 交底进入 `部门审核` 后发明人不可再编辑，只能通过退回重提
- `R00-07` 每次退回必须记录结构化理由，并记退回人。不是 note 字符串
- `R00-08` 退回补充、交底完成、终止三者互斥。终止理由只允许 `withdrawn` / `merged` / `secret_patent`
- `R00-09` 不申请、技术秘密、防御性公开只写入 `recommendation`，禁止写入提报状态
- `R00-10` 6 项技术齐套全为真，只是批准的必要条件。还须 R00-17、R00-18、R00-19
- `R00-11` 未齐套时 UI 显示 `n/6` 并禁用主按钮。四组事实不计入 `n/6`
- `R00-12` 空壳不可装完成：Agent 初稿与 IPR 批准都不得在六项为空时完成。提报提交不要求六项已齐
- `R00-13` `prior_art_1_1` 至少一条印象，对象描述必填。公开号可空；填写则必须带能打开的 url，打不开即作废。禁止编造。无号不是缺项
- `R00-14` `gaps` 必须区分 `blocking` / `non_blocking`
- `R00-15` 存在 `blocking` 缺口时，交底包不可批准
- `R00-16` 齐套勾选必须留痕（谁在何时勾了哪项）
- `R00-17` 权属、署名、奖酬依据、公开时点四组任一未按 §2.2 闭合，不得批准
- `R00-18` 发明人未确认 Agent 初稿，不得批准。Agent 不得把初稿标成已确认
- `R00-19` `recommendation` 未按 §4.5 勾选唯一一条，不得批准。该字段不迁移提报状态
- `R00-20` 发明人离职未满 1 年、外部合作或权属未决 → 法务会签前不得批准（R00-17）
- `R00-21` 发明人贡献为空或只写辅助工作 → 不得列入署名（R00-17）
- `R00-22` 有海外计划但未标 `made_in_china` → 不得批准。保密审查手续未完成只阻断向外申请，不阻断交底批准
- `R00-23` `grace` 为四种情形之一时，从公开日起显示 6 个月宽限期倒计时。不适用不倒计时。倒计时不是建议去向
- `R00-24` 主张宽限期的，必须在申请时声明 + 2 个月内交证明
- `R00-25` 交底须采集研发过程证据（实验记录/样机/测试报告）以应对非正常申请质疑
- `R00-30` 部门审核 SLA
- `R00-31` IP 受理 SLA
- `R00-32` 交底包结构化 SLA（Agent 初稿）
- `R00-33` 齐套补齐 SLA（退回后）
- `R00-34` SLA 逾期 → 升级到部门负责人（复用 `DocketEscalationLevel`）
- `R00-40` 立案时创建 `PatentCase`，`stage` 先等于立案路由 `targetStage`。下游改阶段不必重做交底
- `R00-41` 立案时 `handoffs.disclosure_pack.status = 'drafting'`
- `R00-42` 立案回填 `disclosure.caseId`
- `R00-43` 每次状态变化写 timeline + activity
- `R00-44` 批准交底时登记奖酬依据。立案时不登记，授权时才发放
- `R00-45` 立案后触发第一笔 docket（如「公开风险日倒计时」）
- `R00-46` 提交时必须显式选择公开状态（未公开，或已公开及日期）
- `R00-47` 四种权能（建议 / 决定 / 否决 / 知情）须分别配置到人。审批流不得只有一个「审批人」字段，否则四种权能退化成一个签字按钮
- `R00-48` 发明人只能建议，不能决定是否申请、不能决定申请类型。系统不得向发明人提供「确认申请」类按钮，也不得把发明人的坚持记为已决定申请
- `R00-49` IPR 批准只表示技术事实说清楚了，不表示本件有价值。UI 不得在批准后显示「建议申请」以外的商业结论
- `R00-50` 商业价值一维只抄部门审核人的 `biz_score`，IPR、Agent、系统均不得改写。改写须留痕并标明改写人
- `R00-51` 业务部门有知情权与主张权（可提要求、可书面反对、可在 02 陈述），但不得绕过 IP 部门直接向代理所或专利局提报。系统只保留一个提报入口
- `R00-52` 决定人必须是本单位人员。代理师、代理所承办人不得出现在任何本节点决议记录中，也不得代填 `recommendation`
- `R00-53` 建议与决议分别存储，决议不得覆盖建议原文。02 的决议另记，§4.5 的评分卡保持原样
- `R00-54` 决策人须预设 A/B 角并在立案时登记；B 角代行须在 5 个工作日内 ⚠ 追认，未追认标记「授权瑕疵」进审计清单
- `R00-55` 未获明确答复不得推进任何不可逆动作。**沉默不构成同意**
- `R00-56` 撤回批准、合并终止、署名认定、`grace` 归类四类动作走 L3，须双人复核（发起人 ≠ 批准人）
- `R00-57` D1、保密审查结论、涉密转出、超宽限期仍申请四类动作走 L4，须双签 + 决议纪要
- `R00-58` 级别阈值（金额、条数）必须可配置，不得硬编码。⚠ 具体数值以企业授权制度为准
- `R00-59` `blocking` 缺口只能退回，不得特批；`non_blocking` 缺口可特批，但须记批准人、理由、补齐期限。法务会签组不适用任何特批
- `R00-60` 任何例外须记录：来源（法定 / 合同 / 内部）、批准人、理由、风险、有效期。缺任一项视为违规操作
- `R00-61` 法定例外（宽限期、保密审查）内置为规则，不得做成「特批按钮」
- `R00-62` `blocking` 缺口不得通过任何例外放行（与 R00-59 同一条硬约束的两面）
- `R00-63` 发明人坚持提报的，须有书面意见；IPR 的反对意见不得被删除或覆盖
- `R00-64` 部门审核代核时，涉密与权属两项不得代核
- `R00-65` 署名无法由发明人确认的，只能由法务 + HR 共同认定，IPR 无认定权
- `R00-66` 涉密交底转出后，本节点只保留转出记录与知悉范围，不保留技术细节
- `R00-67` 例外须按案件可统计，例外率异常时触发规则复核，不得靠继续特批消化
- `R00-70` 冲突裁决须记录适用的裁决原则序号（§12.8 表）
- `R00-71` 系统须支持「意见分歧」状态；分歧记录不可编辑，修改须新建版本并保留原版
- `R00-72` 发明人主张与 IPR 评分并存存储，任一方不得删除对方意见
- `R00-73` 留痕要求不得因保密诉求被豁免；可缩小知悉范围，不可无记录
- `R00-74` 署名争议未决时不得递交申请；期限风险由 IP 总监单独签字确认
- `R00-75` 权属争议按任务来源、资源投入、研发过程证据认定，不按部门职级
- `R00-76` 期限压力不得作为编造数据、虚列署名、跳过保密审查的理由
- `R00-77` 升级须有时限（建议 2 个工作日 ⚠ 内给出结论），超时自动上报上一级
- `R00-80` 编造、伪造 `prior_art_1_1` 的公开号或公开内容
- `R00-81` 虚列、增删发明人以换取利益或平息争议
- `R00-82` 隐瞒已知的公开事实（展会、论文、销售、演示）
- `R00-83` 编造、变造实验数据或技术效果
- `R00-84` 伪造研发过程证据（实验记录、样机、测试报告）
- `R00-85` 对外承诺「保证授权」「保证不侵权」或承诺授权率
- `R00-86` 未经保密审查直接向外申请，或未标 `made_in_china` 即放行涉外

### 01-research · 节点 01 · 立项前调研 / 检索（Prior Art Research）· 产品级业务规格（47 条）

- `R01-01` 提交前必须至少有 1 篇勾选命中；空命中不可过闸
- `R01-02` 每篇入选命中必须同时具备 `pubNo` 与 `url`，缺一即整体不可核验
- `R01-03` 每条结论必须能追溯到具体命中（`binding`），不允许「检索了一堆文献但结论无依据」
- `R01-04` 新颖性结论只能基于单篇对比；涉及两篇及以上时必须标注为创造性判断
- `R01-05` 抵触申请（E）不得用于创造性结论
- `R01-06` 检索截止日（`dateTo`）不得早于优先权日；主张优先权时以优先权日为新颖性基准
- `R01-07` 正式检索报告必须记录检索式（含分类号、字段限定、数据库、执行日期），可复现
- `R01-10` 7 项齐套全为真才可 `submit` / `approve`
- `R01-11` 未齐套时显示缺项名，且主按钮禁用
- `R01-12` FTO 初评至少勾选 1 项要素（风险档本身不算，因为 seed 常有值）
- `R01-13` 提交与批准必须过 `evaluateGuardrails`，不得在 UI 复制判定
- `R01-14` 提交时勾选清单 c1–c4，批准时勾 c5
- `R01-20` 检索报告须标注「非法律意见」
- `R01-21` 涉及海外布局时，检索范围须与保密审查判断联动
- `R01-22` 命中涉及自家在先申请时，须提示抵触申请/重复授权风险
- `R01-23` 对比文件须保留原文链接与抓取时间，便于审计
- `R01-24` 实用新型/外观的「可专利性」不得由本节点出具结论（应由 CNIPA 专利权评价报告作出）
- `R01-30` 初步检索 SLA
- `R01-31` 正式检索 SLA
- `R01-32` 检索结论有效期（超期须复核）
- `R01-33` FTO 结论保鲜期（超期须重跑）
- `R01-40` 报告版本变化写 `handoff.versions`，含操作人角色与时间
- `R01-41` 审批链：agency 提交 → enterprise 开始审核/批准/授权 → agency 归档
- `R01-42` 委员与发明人不得提交/批准/授权/归档
- `R01-43` 无 `research_report` 的案件不得进入 Go（决策会必须有检索依据）
- `R01-50` 检索范围三要素（数据库、时间窗、语言）须由企业 IPR 确认并留痕；检索人不得单方缩窄
- `R01-51` 是否委托外部检索由企业 IP 负责人按预算分级决定；代理所不得自行加做后要求付费
- `R01-52` 检索人对方法与可核验性负责，不得出具可专利性结论；结论须由具备资格的 IPR 或代理师签署
- `R01-53` 未经签署的可专利性结论不得进入 02；`drafting` 不得直接跳到 `approved`
- `R01-54` 是否采纳结论由企业 IP 负责人决定；代理所不得代为确认企业结论
- `R01-55` 「暂不建议申请」须附书面理由与逐特征比对，仅作为 02 的输入，不得在 01 结案
- `R01-56` 因结论不利放弃申请属不可逆决策（L4），须 IP 总监批准 + 双人复核
- `R01-57` 检索预算超阈值自动升级；禁止拆分委托合同、拆案、拆检索轮次规避审批
- `R01-58` 发明人、评审委员仅有知情权与建议权，不得签署结论、不得决定是否申请
- `R01-59` 报告对外提供（投资方、客户、尽调）须企业 IP 负责人 + 法务会签，且只提供签署版：脱敏后的结论与命中清单，不提供工作底稿
- `R01-60` 压缩检索范围须走 E1/E5 例外并声明未覆盖范围；不得在报告中隐去未检索的库或语种
- `R01-61` 可专利性结论只能由签署人修改；业务方、IP 负责人不得直接编辑结论字段
- `R01-62` 同一命中在可专利性与 FTO 两处结论可以相反，须分别记录 `kind` 下的判定，不得复用同一结论
- `R01-63` 失效 / 未进入本国的专利，在可专利性检索中仍须作为现有技术引用
- `R01-64` 检索人与代理师意见不一致时，保留两份书面意见，由企业 IP 负责人裁决并记录理由
- `R01-65` 例外情形须记录批准人、理由、有效期，并纳入季度例外率统计
- `R01-66` 任何冲突的裁决须记录所适用的裁决原则序号（§4.8 表）
- `R01-67` 签署人须与检索执行人分离：同一人不得既构造检索式又签署结论（小微企业无法分离时，须由外部代理师复核并留痕）
- `R01-68` 例外不得用于红线事项：编造公开号、伪造命中、隐瞒已知公开、代签结论，不在任何例外范围内，系统硬阻断
- `R01-69` 结论超过有效期（R01-32）后仍被引用时，系统须打「已过期」水印并强制要求复核或重跑，不得静默沿用
- `R01-70` 02 的 Go 决议须引用具体报告 ID 与版本号；会议口述或摘要邮件不得替代签署版报告
- `R01-71` 因保密要求不委托外部检索的，须由 IP 负责人书面承担漏检风险，报告标注「未经独立第三方复核」

### 01b-fto · 节点 01b · FTO 自由实施分析（Freedom to Operate）（47 条）

- `R1B-01` 必须**按目标市场逐国**检索；一件专利只在其授权国有效
- `R1B-02` 只把 `legalStatus ∈ {granted, pending}` 的专利视为障碍
- `R1B-03` 同族必须折叠，同一发明在多国的同族按**各国分别**评估（可能只有部分国家有效）
- `R1B-04` 时间基准为**计划上市日**，不是申请日
- `R1B-05` 权利要求必须取得**全文**；只有摘要/标题不得作为障碍结论依据
- `R1B-06` `pending` 申请须标注「授权后可能构成障碍」，不能当作确定无障碍
- `R1B-07` 检索截止日必须写入报告；结论有效期自该日起算
- `R1B-10` 必须**指明具体权利要求号**，不能笼统比对「该专利」
- `R1B-11` 遵循**全面覆盖原则**：权项每个要素都在产品中找到对应才落入
- `R1B-12` 缺任一要素即**不落入**，比对可立即终止
- `R1B-13` 等同判定须谨慎；FTO 阶段以**字面比对**为主，等同标注「待诉讼确认」
- `R1B-14` 须查阅审查档案，识别**禁止反悔**（审查中放弃的内容不能再主张）
- `R1B-15` 比对表须逐要素填写，不得只写结论
- `R1B-16` 方法专利须注意**举证责任倒置**情形（新产品制造方法）⚠
- `R1B-20` 结论必须落到五种可处置等级（§3.5），不能只有风险色
- `R1B-21` 每个 `design_around` 结论必须给出**具体改哪个特征**
- `R1B-22` 规避设计完成后须**重新比对**，不能直接标为 clear
- `R1B-23` `license_needed` 须评估权利人是否愿意许可、是否有许可先例
- `R1B-24` 全局风险取**最严**的单件结论，不得平均
- `R1B-30` 报告必须声明**检索范围**（市场/时间/数据库/关键词/分类号）
- `R1B-31` 报告必须声明**局限性**（公开盲区、译文缺失、未公开权项）
- `R1B-32` 报告须有制作人 + 复核人签署，且复核人应具备专利代理师/律师资格 ⚠
- `R1B-33` 报告须标注「不构成法律意见」
- `R1B-34` 报告须记录**检索日**，用于日后证明「当时已尽合理注意」
- `R1B-40` 结论有效期 6–12 个月 ⚠
- `R1B-41` 产品技术方案变更 → 必须重跑
- `R1B-42` 进入新市场 → 必须对该市场重跑
- `R1B-43` 收到警告函 / 被诉 → 立即复核
- `R1B-44` 到期前 30 天提醒
- `R1B-50` FTO 的立项由业务上市计划驱动，法务与业务会签；IP 部门不得单独决定做或不做
- `R1B-51` 目标市场由业务提出、法务确认覆盖完整性；制造地、销售地、参展地至少三者齐全
- `R1B-52` 比对结论与风险等级由专利师签署、法务确认；业务方不得修改等级或结论
- `R1B-53` 规避方案的技术路径由专利师与研发共同定；是否采纳（改不改）由业务负责人按成本收益决定
- `R1B-54` 是否取得许可属 L4，须业务负责人 + 法务会签，财务对长期付款义务有否决权
- `R1B-55` 报告对外提供须法务批准；对外版本不得包含未脱敏的客户信息、成本、内部风险评级理由
- `R1B-56` 「发现障碍仍上市」须法务书面风险提示 + 业务负责人签字承担 + 系统标记，缺任一项不得发布上市决议
- `R1B-57` 已收到警告函或被诉的情形，法务对「继续上市」有一票否决权
- `R1B-58` 报告删除、调低等级、另出「干净版」属禁止行为，系统须保留全部版本与差异
- `R1B-59` 客户（OEM）要求提供 FTO 时，由法务决定提供范围与形式，业务不得自行承诺「不侵权」
- `R1B-60` 任何压缩覆盖范围的决定须走 E1/E2 并写明未覆盖市场与未比对权项，报告中不得出现「全球已评估」类概括表述
- `R1B-61` 规避与许可的方案比较须用全周期成本模型（一次性改模 + 持续许可费 + 认证 / 性能损失），不得只比首年支出
- `R1B-62` 法务判断与业务决策冲突时，走「书面风险提示 + 业务签字承担」流程，不得由职级高者直接压过
- `R1B-63` 报告对外提供须版本化并登记接收方；同一项目对不同接收方的版本差异须可追溯
- `R1B-64` 专利师结论与外部律师意见并存时，两者分别留档，不得互相覆盖；对外口径由法务确定
- `R1B-65` 例外须记录批准人、理由、有效期，并统计例外率；E1（加急）与 E6（沿用）合计占比过高说明立项时点管理失效
- `R1B-66` 红线不可例外：承诺「保证不侵权」、编造比对结果、删除已发现的障碍、伪造检索日期
- `R1B-67` 已收到警告函后仍决定上市的案件，必须同时启动 24 诉讼的应诉预案，不得只走 FTO 流程

### 02-decision · 节点 02 · 立项决策（Go / No-Go）· 产品级业务规格（55 条）

- `R02-01` Go/No-Go 只能由企业 IP Persona 执行；委员、发明人、代理所均不可
- `R02-02` 必须选择 Go 或 No-Go，且必须填写决策理由，缺一不可提交
- `R02-03` Go 前置：`disclosure_pack` ∈ approved / authorized_to_file / filed
- `R02-04` 自助模式（`self_serve`）Go 前置：预算非空
- `R02-05` 委托模式（`delegated`）Go 前置：`intake_quote` 已批准，或付款状态 ∈ 已确认待付款/部分付款/已结清
- `R02-06` Go 前阶段清单必做项须全部完成（c1–c4）
- `R02-07` 投票硬挡开关开启时，无委员审计票不可 Go
- `R02-08` 决策理由必须能落到四维（技术/市场/法律/成本）中的至少两项
- `R02-10` 评分卡六维与 00 §4.5 同源，权重一致
- `R02-11` 总分按权重加权计算，保留一位小数
- `R02-12` 总分 < 2.5 时 Go 需强制填写「为何仍申请」
- `R02-13` 评分变更须留痕（谁、何时、改前改后）
- `R02-14` 检索（01）的新颖性/创造性评分自动带入本节点，不手工重填
- `R02-20` 委员池由组织配置，委员有职能域（技术/商业/法务）
- `R02-21` 法定人数：至少 3 人且覆盖技术、商业两域方可表决
- `R02-22` 投票选项四态：同意 / 有条件同意 / 驳回 / 弃权（需理由）
- `R02-23` 任一委员「驳回」→ 不得 Go，除非企业 IP 书面覆议并记录理由
- `R02-24` 委员与本案有利益关系（同部门/共同发明人/持股）须回避，回避后不计入法定人数
- `R02-25` 只有 `committee` Persona 的票进入审计日志；企业 IP 代填不算
- `R02-26` 投票截止后自动锁定，委员不可改票；改票须留痕
- `R02-30` 报价必须拆分为官费 + 代理费（+ 检索费 + 翻译费）四类
- `R02-31` 官费按当期 CNIPA 收费表计算，不硬编码
- `R02-32` 委托范围必须显式列「含/不含」：权项组数、附图、OA 轮次、翻译、年费代缴
- `R02-33` 报价有效期（建议 30 天）到期须重新确认
- `R02-34` 报价变更后须重新走确认，不允许直接覆盖已批准的 `intake_quote`
- `R02-35` 代理费不得与官费混入同一发票条目
- `R02-40` `intake_quote` 3 项齐套全为真才可提交/批准
- `R02-41` 三委员全投齐后可提交（法定人数口径）
- `R02-42` 提交报价 → `paymentStatus = 报价待确认`，`phase = 接案评估`
- `R02-43` 企业确认报价 → `paymentStatus = 已确认待付款`，`phase = 正式委托`，追加待开票发票
- `R02-44` Go → 案件进入下一阶段并重置清单
- `R02-45` Go → `Engagement.phase` 进「撰写中」
- `R02-50` Go 时须确认「技术是否在中国境内完成」，涉外申请前须过保密审查
- `R02-51` Go 时须记录目标国别与是否走 PCT，联动 12 个月优先权窗口
- `R02-52` No-Go 必须选择结构化理由码（非新颖性/无市场/成本过高/权属不清/转技术秘密/防御性公开）
- `R02-53` No-Go 后案件进入「结案」而非停在决策阶段
- `R02-54` 预算审批人须与决策人分离（避免自批）
- `R02-60` 决策周期（进入 decision → Go/No-Go）
- `R02-61` 委员投票窗口
- `R02-62` 报价确认窗口
- `R02-63` No-Go 复议窗口
- `R02-70` Go / No-Go 的决定人必须是企业方人员；代理所人员不得作为决定人出现在任何决议记录中，亦不得任委员或代填选票
- `R02-71` 委员会是建议 + 表决机构，其结论须经企业 IP 负责人签署方生效；不采纳须写明理由与风险承担人
- `R02-72` 财务对超预算 / 无预算来源有一票否决权，但不得否决技术判断或替代 Go / No-Go 决定
- `R02-73` 法务对权属不清、保密审查未过、涉嫌非正常申请有一票否决权，否决须书面说明并进审计清单
- `R02-74` 预算审批按额度分级自动升级；禁止拆案、拆合同、拆年度规避审批
- `R02-75` 报价确认与 Go 是两个独立决策，不得合并为一次点击；确认报价产生付款义务，Go 产生申请义务
- `R02-76` 任何 Go 决议须双人复核（决策人 ≠ 复核人），单人操作不得生效
- `R02-77` 决策人须预设 A/B 角并在立项时签署授权；B 角代行须在 5 个工作日内追认
- `R02-78` 未获明确答复不得推进 Go；沉默不构成同意
- `R02-79` 委员改票须新建记录，原票保留；改票后须重新计算法定人数与票型
- `R02-80` 四种权能（建议 / 决定 / 否决 / 知情）须分别配置到人，不得合并为一个审批按钮
- `R02-81` 例外情形须记录批准人、理由、有效期，并按案件统计例外率（§4.8）
- `R02-82` 规则冲突的裁决须记录适用的裁决原则序号（§4.9）及两方原始意见
- `R02-83` 决议记录一经签署不可编辑，修改须新建版本；跨部门联合立项须先落权属再 Go

### 03-drafting · 节点 03 · 撰写申请（Drafting）· 产品级业务规格（54 条）

- `R03-01` 一件申请至少 1 项独立权利要求，否则不可提交
- `R03-02` 独立权利要求必须包含「前序部分（主题名称 + 与最接近现有技术共有的必要技术特征）」与「特征部分（其特征在于…）」
- `R03-03` 从属权利要求必须引用**在前的**权利要求（引用号 < 自身序号）
- `R03-04` 从属权利要求必须写引用部分（引用号 + 主题名称）与限定部分
- `R03-05` 多项从属权利要求只能以择一方式引用在前权项，且**不得作为另一多项从属权利要求的基础**
- `R03-06` 从属权利要求必须与被引用权项**类别一致**（方法从权不得引用产品独权）
- `R03-07` 删除/插入权项后，所有 `dependsOn` 必须重编号并保持语义
- `R03-08` 权项中不得出现插图；可有化学式/数学式；附图标记放括号内且不构成限制
- `R03-09` 权项术语必须与说明书一致
- `R03-10` 多项独立权利要求必须满足单一性（同一总的发明构思）
- `R03-11` 独权只写必要技术特征：逐条删除后若方案仍能解决技术问题，该特征必须移出独权
- `R03-12` 独权中的每个上位概念，说明书须有至少一个下位实施例支撑（26.4）
- `R03-13` X 类对比文件已公开的特征必须写入独权（否则无新颖性）；Y 类组合必须写入（否则无创造性）
- `R03-14` 独权中不得出现商标、型号、人名、纯功能性表述
- `R03-15` 独权的主题名称必须与说明书技术领域、摘要一致
- `R03-16` 每项独权下应至少有 2 层从权梯度，供无效程序中逐级退守
- `R03-17` 从权应覆盖「参数范围 / 材料替换 / 顺序变化 / 应用场景」四类变体
- `R03-18` 从权不得与独权特征重复（重复项失去退守价值）
- `R03-19` 说明书须含六段：名称 / 技术领域 / 背景技术 / 发明内容 / 附图说明 / 具体实施方式，且各部分前写明标题
- `R03-20` 背景技术须引证最接近的现有技术文件
- `R03-21` 发明内容须写「技术问题 → 技术方案 → 有益效果」闭环
- `R03-22` 具体实施方式须给出可复现的参数/条件/变体
- `R03-23` 说明书不得使用「如权利要求 X 所述的……」引用语，不得使用商业宣传用语
- `R03-24` 实用新型必须有附图
- `R03-25` 涉及核苷酸/氨基酸序列须提交序列表
- `R03-26` 5 项递交清单全为真才可 `approve` / `authorize` / `file`
- `R03-27` `submit` 也要求 5/5（比法定更严，取「更严」口径）
- `R03-28` 权项结构非法时，主按钮禁用并逐条列出错误
- `R03-29` 递交前须完成 Full-check 三项轻量勾选
- `R03-30` 齐套达成时应生成待开票行，且**同一案同阶段不重复开票**
- `R03-31` 首次申请日起 12 个月内可主张发明/实用新型外国优先权，外观 6 个月
- `R03-32` 选择 PCT 途径的，须记录国际申请日与 30/32 个月国家阶段期限
- `R03-33` 国别选择须与预算档位联动，超预算须审批
- `R03-34` 涉外申请前须完成保密审查（专利法第十九条）
- `R03-35` 官费与代理服务费必须**分两账**列示，不得混加
- `R03-36` 费用估算不得随操作者角色变化
- `R03-37` 权利要求超 10 项、说明书超 30 页须计申请附加费
- `R03-38` 符合费减条件的须自动套用减缴比例
- `R03-39` `file` 成功后必须写入递交回执（`receiptNo` + `filedAt`）
- `R03-40` 递交回写应生成 `application_fee`（2 个月/15 日）与 `substantive_exam_request`（36 个月）两条期限
- `R03-41` 每次提交/批准/退回须生成权项版本快照供 diff
- `R03-42` 交底未批准时，权项页仍可阅读但不可提交
- `R03-50` `authorize`（递交授权）只能由企业方执行，代理所与 Agent 不得代签；无授权的递交为效力待定
- `R03-51` 代理师对撰写质量（结构合法、26.3、26.4）负责；企业对保护范围目标与预算负责；两类责任须分别签署
- `R03-52` 企业不得强迫代理师写入明知不可支撑的范围；企业坚持的，须书面记录「已告知 26.4 风险」并进案卷
- `R03-53` 代理师不得擅自缩小范围（并入从权、删除必要特征）；改变范围须企业书面同意
- `R03-54` 独权删减的删除测试结论须随案归档，作为答复阶段的策略基线
- `R03-55` 国别策略（D4）由企业 IP 负责人决定，财务对超预算有一票否决权，法务对未过保密审查有一票否决权
- `R03-56` 说明书公开程度（是否保留技术秘密）属资产处置决策，须企业书面确认后方可递交
- `R03-57` 优先权主张、分案、PCT 路径选择均须企业 IP 负责人决定，不得由代理师在委托范围外代为选择
- `R03-58` 四种权能（建议 / 决定 / 否决 / 知情）须分别配置到人，不得合并为一个审批按钮
- `R03-59` 例外情形须记录批准人、理由、有效期，并按案件统计例外率（§4.9）
- `R03-60` 规则冲突的裁决须记录适用的裁决原则序号（§4.10）及两方原始意见
- `R03-61` 递交前须完成双签：代理师署质量、企业署范围与成本；任一缺失不得 `file`

### 04-prosecution · 节点 04 · 审查答复（Prosecution）· 产品级业务规格（58 条）

- `R04-01` 每条争点必须关联审查员所依据的法条
- `R04-02` 每条争点必须记录对比文件编号与被指出的对应特征
- `R04-03` 每条争点必须标明所属 OA 轮次
- `R04-04` 争点必须覆盖通知书中指出的**全部**缺陷
- `R04-05` 争点须有状态：待处理 / 已答复 / 已克服 / 保留争议
- `R04-06` 实用性、形式缺陷须独立成类，不得并入「其他」
- `R04-07` 每条争点必须选策略且写答复要点，否则不可提交
- `R04-08` 策略为「争辩」时，可不修改权项
- `R04-09` 策略为「缩限」时，须说明缩限依据（说明书哪一段、哪一句）
- `R04-10` 策略为「删除权利要求」时，须同步重编号并检查引用
- `R04-11` 策略为「补充实验数据」时，须标注数据能否被接受（申请日后的补交受限制）
- `R04-12` 同一争点的策略变更须留痕（谁在何时从 A 改为 B）
- `R04-13` 修改不得超出原说明书和权利要求书记载的范围（33 条）
- `R04-14` 答复 OA 时的修改应针对通知书指出的缺陷（细则第五十七条第三款）
- `R04-15` 修改须以「删除 / 替换 / 增加特征」的**结构化操作**表达，可回溯
- `R04-16` 修改后须逐项核对：新权项中的每个特征在原说明书中能找到出处
- `R04-17` 实用新型/外观的主动修改仅限申请日起 2 个月内（细则第五十七条第二款）
- `R04-18` 发明的主动修改窗口：提实审请求时 + 收到进入实审通知书起 3 个月内（细则第五十七条第一款）
- `R04-19` 一通答复期限 4 个月，自通知书发文日起算
- `R04-20` 后续 OA 答复期限 2 个月
- `R04-21` 期限届满日遇法定休假日顺延至节后第一个工作日
- `R04-22` 纸件邮寄送达的，自发文日起满 15 日推定为收到日；电子送达以进入电子系统之日为准
- `R04-23` 延期请求须在期限届满**前**提出，并缴延期请求费
- `R04-24` 逾期未答复 → 申请**视为撤回**，须在收到通知起 2 个月内请求恢复并缴费
- `R04-25` 期限剩余 ≤7 天须告警，≤3 天须升级
- `R04-26` 意见陈述须三段式：修改说明 + 争点分析 + 证据
- `R04-27` 有修改时必须提交替换页
- `R04-28` 陈述中引用的对比文件、实验数据须可核验
- `R04-29` 递交须附回执号与递交日
- `R04-30` 陈述一经确认，改动须留痕并可回退到草稿
- `R04-31` 驳回决定后 3 个月内可请求复审（专利法第四十一条）
- `R04-32` 复审请求须缴费（发明 1,000 元 / 实用新型 300 元 / 外观 300 元 ⚠）
- `R04-33` 分案须在**办理登记手续期限届满前**提出（细则第四十八条第一款引第六十条第一款）
- `R04-34` 分案保留原申请日与优先权日，但不得超出原申请记载范围（细则第四十九条）
- `R04-35` 分案不得改变原申请类别
- `R04-36` 分案后原案与分案须互相可追溯（家族视图）
- `R04-37` `approve` 前必须有争点类型 + 策略要点
- `R04-38` `authorize` / `file` 前必须已确认陈述
- `R04-39` 闸门须校验**全部**争点，而非仅当前激活的那一条
- `R04-40` 递交后应生成下一轮期限（若不是终局）
- `R04-41` 新一轮 OA 到达时应重置陈述确认并按轮次归档上一轮陈述
- `R04-42` 本节点启动前应校验 `draft_claims = filed`
- `R04-43` 答复策略的决定人是企业方人员；代理师持有建议权，不得以 `approve` 身份出现在决议记录中
- `R04-44` 任何导致保护范围缩小的修改（新增特征、删除权项、并入从权）须企业书面确认后方可定稿
- `R04-45` 代理师不得在未获企业确认时为求授权大幅缩限；「大幅」的阈值按特征数与权项数由企业配置 ⚠
- `R04-46` 删除权利要求须逐项记录理由与删除后的覆盖分析，不得整段替换了事
- `R04-47` 延期、会晤、分案、复审四项程序动作各自独立决策，不得打包成一个「继续处理」按钮
- `R04-48` 答复成本按单轮金额分级审批；分案与复审各自独立立项、独立预算，禁止并入本轮答复费
- `R04-49` 发明人对影响其奖酬的权项删除有知情权；知情不阻断流程，但遗漏须记入审计清单
- `R04-50` 企业逾期不答复**不构成**对代理师方案的同意；代理师不得以沉默推定授权
- `R04-51` 同一人不得对同一轮的「策略建议」与「策略批准」同时持有权力
- `R04-52` 决策记录须含被否决的备选方案及否决理由；只记最终策略视为未留痕
- `R04-53` 偏离 §4.8 任一条例外的操作，须记录依据、批准人、风险、有效期四项，缺项不得执行
- `R04-54` 争辩 / 缩限的路径选择须留期望值测算（概率区间 + 成本 + 范围损失），不得只记结论
- `R04-55` 冲突裁决须记录所适用的裁决原则序号（§4.9 表），便于事后审计
- `R04-56` 代理师的专业保留意见与企业决议分别存储，企业驳回意见须给理由
- `R04-57` §4.8 红线五项为硬阻断，不提供特批入口
- `R04-58` 复审、分案的立项理由须与本报答复的路径比较挂钩，禁止「答不下去就复审」的默认惯性

### 05-maintenance · 节点 05 · 授权维持（Maintenance）· 产品级业务规格（56 条）

- `R05-01` 年费年度自**申请日**起算，每年在申请日周年届满前缴纳
- `R05-02` 发明专利年费按**分段定额**：1–3 年、4–6 年、7–9 年、10–12 年、13–15 年、16–20 年，逐段递增 ⚠
- `R05-03` 实用新型 10 年、外观设计 15 年，年费档位与发明不同 ⚠
- `R05-04` 年费档位表必须来自单一配置源，不得在 UI 里硬编码
- `R05-05` 生成日程必须覆盖**全保护期**（20/10/15 年），而非固定 5 年
- `R05-06` 年号超出档位表长度时禁止静默取最后一档，须报配置错误
- `R05-07` 金额字段为字符串时，必须同步结构化数值，否则预算不得汇总
- `R05-10` 逾期未缴的，自应缴期满之日起 **6 个月**内可补缴，同时缴滞纳金
- `R05-11` 滞纳金按**每超过 1 个月加收当年全额年费的 5%** 递增，最高至 25% ⚠
- `R05-12` 宽限期届满仍未缴（含滞纳金）的，专利权**自应缴期满之日起终止**
- `R05-13` 终止后可在收到终止通知起 **2 个月内**请求恢复，须缴恢复权利请求费 ⚠
- `R05-14` 分期/部分缴纳视为未缴足，同样进入宽限与滞纳计算
- `R05-15` 缴费凭证（回执号 + 缴纳日 + 金额 + 年度）必须与日程行一一对应
- `R05-20` 费减须**先备案后享受**，未备案的按全额计
- `R05-21` 减缴比例：**单个**申请人/专利权人 **85%**；**两个以上**共同申请/共有 **70%** ⚠
- `R05-22` 备案条件按上年度收入/应纳税所得额判定，年度变化须重新备案 ⚠
- `R05-23` 权利转移（转让/继承）后费减资格须重新核验，可能失效
- `R05-24` 开放许可实施期间年费可另享减缴（**15%**，不重复享受其他优惠）⚠
- `R05-30` 权利状态至少覆盖：有效 / 年费待缴 / 宽限中 / 终止 / 恢复中 / 放弃 / 质押 / 已许可 / 已转让
- `R05-31` 状态变更须写 `PatentStatusRecord.history`，含变更日、原因、操作人、依据文件
- `R05-32` 已质押的专利，缴费、转让、许可、放弃均须质权人书面同意
- `R05-33` 已许可的专利放弃维持，可能构成许可合同违约，须先核合同
- `R05-34` 著录项目变更（发明人/申请人/代理机构）须登记并留痕，且影响费减资格与送达地址
- `R05-35` 变更事项必须持久化，不得只存在于页面 state
- `R05-36` 专利权人名称变更必须同步发票抬头与费减备案主体
- `R05-40` 提交/批准/授权/归档前，日程每行必须有 `due` 与 `amount`
- `R05-41` 提交/授权/归档前，必须确认官费与代缴服务费
- `R05-42` 预算确认必须基于**非零**官费；官费为 0 时不得视为已确认
- `R05-43` 任何「已缴」标记都必须经发票 `payInvoice` 命令，不得由 UI 直接改写
- `R05-44` 付款解锁仅企业角色可执行
- `R05-45` 命令级与按钮级必须同源校验（防直调）
- `R05-50` 年费日程是 Inbox 与 Flow 的**单一数据源**
- `R05-51` 归档时把日程摘要写入 Drive，供全局检索
- `R05-52` 归档时写入年费 Docket 事件并核销期限
- `R05-53` 日程更新不得覆盖已有缴费记录
- `R05-54` 每次缴纳须追加一条审计，不得覆盖
- `R05-55` 每件年费决策须有具名决定人；系统不得以「无人反对」或「超时未回复」替代决定
- `R05-56` 主动放弃的决定权归 IP 总监及以上，且发起人 ≠ 批准人；财务不得持有放弃的决定权与否决权
- `R05-57` 批量放弃按件数与年化维持成本**孰高**定档，B 档及以上须法务 + 财务联签
- `R05-58` 共有 / 质押 / 已许可专利的放弃，须先完成征询并归档同意文件，否则闸门阻断
- `R05-59` 是否启动恢复由 IP 总监决定；恢复理由的法律定性以法务意见为准，代理师只负责事实与证据
- `R05-60` 代理师与代理流程岗只能建议与执行，不得代客户决定放弃、恢复或转让
- `R05-61` 单件缴纳在年度预算额度内可下放至 IPR；超出额度须 IP 总监批准并记录理由
- `R05-62` 著录项目变更涉及专利权人主体时，须法务会签并同步费减备案与发票抬头
- `R05-63` 决策记录须含被否决的反对意见；只记结论视为未留痕
- `R05-64` 维持价值分层结论（继续 / 观察 / 拟放弃）须由 IP 总监签署；代理所或系统的评分只能作为输入，不得直接构成放弃依据
- `R05-65` 偏离 §4.7 任一条例外的操作，须记录依据、批准人、风险、有效期四项，缺项不得执行
- `R05-66` 系统在未获明确决定时，默认动作为「继续缴费并升级」，不得置为放弃或终止
- `R05-67` 批量放弃的每一件须有独立价值评分与负担核查（共有/质押/许可），规则只用于发起
- `R05-68` 冲突裁决须记录所适用原则序号（§4.8 表）与双方意见，不得只记结论
- `R05-69` 恢复立项须同时评估「在诉状态」，在诉案件按诉讼成本口径而非专利估值口径决策
- `R05-70` §4.7-B 红线五项为硬阻断，不提供特批入口
- `R05-71` 费减资格的年度核验结果是缴费金额的前置输入；未核验不得按减免档位出账
- `R05-72` 终止一旦登记，须在同一事务内自动生成恢复窗口期限并通知权利人；不得等到人工发现
- `R05-73` 同族处置须以对照表形式决策（国家 / 市场 / 维持成本 / 在诉状态），禁止逐件孤立地放弃
- `R05-74` 客户「不打扰」偏好只作用于商业性提醒；宽限、终止、恢复窗口三类硬期限提醒不可关闭

### 06-commercialization · 节点 06 · 运用转化（Commercialization）· 产品级业务规格（58 条）

- `R06-01` 路径至少覆盖：自行实施 / 许可 / 转让 / 质押融资；另有作价入股、专利池、标准必要专利
- `R06-02` 只有权利状态为 `有效` 的专利可进入许可/转让/质押
- `R06-03` 已质押的专利发起转让/许可/放弃，须先取得质权人同意
- `R06-04` 已独占/排他许可的专利，不得就同一地域、同一领域再次对外许可
- `R06-05` 路径切换须保留原路径已填内容，不得静默清空
- `R06-06` 诉讼路径必须走 07 的「升级维权」，本台只做标记
- `R06-07` 路径选择须记录决策理由（为什么是许可不是转让）
- `R06-10` 许可类型必须是**枚举**：独占 / 排他 / 普通 / 交叉 / 分许可
- `R06-11` 独占许可必须显式确认「许可期内权利人自己也不得实施」
- `R06-12` 分许可须在合同中明确授权，否则被许可人无权再许可
- `R06-13` 许可合同应自生效之日起 **3 个月内**备案
- `R06-14` 未备案的许可不得对抗善意第三人
- `R06-15` 许可期不得超过专利权剩余保护期
- `R06-16` 地域范围必须落在专利权有效地域内（中国专利只能许可中国境内实施）
- `R06-17` 对价必须结构化：入门费（一次性）/ 提成率（%净销售额）/ 最低保底 / 里程碑款 / 分期
- `R06-18` 提成基数必须定义（净销售额 / 毛利 / 台数），并约定审计权
- `R06-19` 改进成果归属必须约定（各自 / 共有 / 回授）
- `R06-20` 转让须订立**书面合同**并向官方**登记**，**自登记之日起生效**
- `R06-21` 转让标的可以是全部权项，也可以是部分权项（须明确）
- `R06-22` 转让不影响已存在的许可关系，但须书面通知被许可人
- `R06-23` 转让后费减资格须重新核验（受让人资质决定减缴比例）
- `R06-24` 共有专利转让须**全体共有人同意**
- `R06-25` 向外国人转让须依相关法律办理额外手续 ⚠
- `R06-30` 质押须由出质人与质权人**共同**提出登记申请、共同签章
- `R06-31` 质押期间转让/许可须提交质权人同意证明，否则不予办理
- `R06-32` 质押登记须记载担保债权额、期限、质押范围
- `R06-33` 质押通常要求评估报告，评估结论决定融资额度 ⚠
- `R06-34` 债务违约时质权人可依法处置（折价/拍卖/变卖），须提前约定
- `R06-40` 至少支持三种方法：成本法 / 市场法 / 收益法
- `R06-41` 收益法须显式给出：剩余经济寿命、预期现金流、折现率、技术贡献率 ⚠
- `R06-42` 市场法须给出可比交易来源与调整因素（时间/地域/范围/排他性）⚠
- `R06-43` 成本法须区分研发成本与重置成本，并说明为何不适用收益法
- `R06-44` 评估结论必须记录假设与局限，不得只给一个数
- `R06-45` 定价须参照可比费率区间，且标注数据来源与日期 ⚠
- `R06-50` approve / authorize 前必须 `legalReview === 'reviewed'`
- `R06-51` 提交前必须填交易对手与对价
- `R06-52` 诉讼路径豁免 `terms` / `party` 两项齐套
- `R06-53` 法务标记人不得与商务批准人同一人
- `R06-54` 法务审阅必须留附意见与附件
- `R06-55` 归档时写入登记/备案凭证号
- `R06-56` 里程碑逾期须升级（进 Docket 或 Inbox）
- `R06-70` 四种权能（建议 / 决定 / 否决 / 知情）须分别配置到人，不得合并为一个审批按钮
- `R06-71` 独占许可、转让、质押、作价入股一律按 L4 处理：高层批准 + 双人复核 + 决议纪要
- `R06-72` 业务部门不得单独对外承诺许可条件；未经书面授权的报价、意向、口头承诺不产生内部效力，且须在 24 小时内 ⚠ 上报
- `R06-73` 谈判底线须在首次对外报价前书面批准并锁定；超出授权幅度的要求须暂停谈判并重新报批，**不得先答应后补批**
- `R06-74` 法务对合同条款有终审权；法务标记人不得与商务批准人同一人（另见 R06-53）
- `R06-75` 合同签署人须持与本次交易一致的书面授权；越权签署按效力待定处理，须追认或撤销
- `R06-76` 转让须按公司章程与金额分级报董事会 / 股东会，决议纪要入卷
- `R06-77` 质押融资须 CFO 与法务总双签，且须先取得评估结论
- `R06-78` 作价入股须持牌评估机构出具报告 + 董事会决议，缺一不得办理
- `R06-79` 对方违约是否解约、是否索赔由法务总决定；业务负责人可就客户关系行使否决权
- `R06-80` 许可备案由法务负责时限管理，签约日即生成「生效 + 3 个月 ⚠」期限，逾期进入例外流程（E5）
- `R06-81` 决定人须预设 A/B 角，授权书事先签署；未获明确答复不得推进不可逆动作，沉默不构成同意
- `R06-82` 每个决策须记录：决策人、时间、依据、备选方案、未采纳原因；决议记录一经签署不可编辑，修改须新建版本
- `R06-83` 独占 / 排他许可批准前须出具「自实施收益 vs 许可费收入」对照测算，未出具不得进入 L4 决议（对应 C1）
- `R06-84` 同一交易中，谈判代表不得同时担任条款批准人；批准人须能看到完整谈判记录与每轮让步
- `R06-85` 已作 FRAND 承诺的专利，须维护费率对照表；同类被许可人条件差异无客观理由的，阻断并提交 L4 复议（对应 E3）
- `R06-86` 跨境许可签约前须完成税务与外汇路径测算，测算未完成不得签署（对应 E7）

### 07-monitoring · 节点 07 · 监控预警（Monitoring / IP Watch）· 产品级业务规格（66 条）

- `R07-01` 监控必须按三类对象分别配置：①竞品新申请 ②自有专利被引用 ③侵权线索（市场/展会/电商/招投标）
- `R07-02` 每条监控规则必须绑定「命中后生成的告警类型 + 默认级别 + SLA 天数」
- `R07-03` 关键词与竞品主体为必填，二者至少一项非空
- `R07-04` 规则启用/关闭必须留痕（谁在何时改了什么）
- `R07-05` 规则阈值必须可机判（数值 + 比较符），不接受自由文本
- `R07-06` 监控范围须声明地域与时间窗（如「中国 + 近 30 天新公开」）
- `R07-07` 同一被监控对象在 7 日内重复命中，必须合并为一条告警
- `R07-08` 规则变更后应能回溯「这条告警当时是哪条规则命中的」
- `R07-10` 级别必须是枚举（高/中/低 或 P1–P4），不接受自由文本
- `R07-11` 高风险 = 命中我方独权全部技术特征（全面覆盖成立）；中 = 部分特征重叠；低 = 仅技术领域相关
- `R07-12` 级别变更须记录变更人与理由
- `R07-13` 「高」级或超 SLA 的告警必须进入统一收件箱，且排在最前
- `R07-14` 涉及我方**在审**申请的引用告警，须回写该案的审查/布局判断
- `R07-15` 涉及我方**已授权**专利的侵权告警，须绑定具体专利号与权利要求号
- `R07-20` 处置枚举固定为 确认 / 升级 / 关闭，不得只有「批准」
- `R07-21` 「升级」分两档：建案升级（建维权线索案）与仅标记升级（不建案），两档必须显式区分
- `R07-22` 关闭告警必须填写理由
- `R07-23` 告警必须按级别路由到不同剧本：高→律师函/诉讼评估；中→协商/警告函；低→观察
- `R07-24` 发函前必须完成权利要求对照（claim chart）
- `R07-25` 行政投诉（专利行政执法）与诉讼是**互斥优先**选择，须记录选择理由
- `R07-26` 升级建案必须携带原告警 ID，形成溯源链
- `R07-27` 升级建案的案件风险等级固定为「高」，办理模式为委托
- `R07-28` 同一告警不得重复建案（幂等）
- `R07-29` 无效宣告作为反制手段时，须记录「无效 vs 诉讼」的时间与成本比较
- `R07-30` 判定顺序固定：全面覆盖 → 等同 → 排除（禁止反悔 / 捐献）
- `R07-31` claim chart 必须逐特征列「我方权项 / 被诉方案 / 相同-等同-不同」三列
- `R07-32` 等同判定须记录「手段/功能/效果」三基本与「是否需创造性劳动」四项结论
- `R07-33` 禁止反悔：须能检索该专利审查/无效程序中的限缩性修改与意见陈述
- `R07-34` 捐献：说明书中公开但未写入权项的技术方案，不得主张
- `R07-35` 取证方式必须结构化：公证购买 / 网页取证（含时间戳或公证）/ 展会取证
- `R07-36` 网页证据必须保存 URL + 抓取时间 + 内容快照三件套
- `R07-37` 公证购买须记录购买人、地点、时间、票据、实物编号
- `R07-38` 展会取证须在展期内完成（闭展后现场证据不可复得）
- `R07-40` 海关备案须在权利有效期内办理，备案到期前 6 个月提醒续展
- `R07-41` 展会保护：参展前完成「是否有被诉风险 + 是否需现场投诉」双检查
- `R07-42` 电商平台投诉须走「通知—删除」要件（权属证明 + 定位信息）
- `R07-43` 发警告函前须评估「确认不侵权之诉」反噬风险
- `R07-44` 侵权诉讼时效 3 年，自知道或应当知道侵权行为**及侵权人**起算；监控须记录「首次发现日」
- `R07-45` 收到警告函/被诉时，须在监控侧开一条**防御向**告警（方向：我方被指侵权）
- `R07-50` 高风险告警首响 SLA
- `R07-51` 中风险告警首响 SLA
- `R07-52` 低风险告警首响 SLA
- `R07-53` `slaDue` 必须由 `openedAt + 级别对应天数` 计算，不得手填
- `R07-54` 超 SLA 自动升级到 IP 负责人（复用 `DocketEscalationLevel`）
- `R07-55` 证据保全时效：发现侵权后 30 日内完成首轮取证
- `R07-60` 代理所意见只能由代理写，企业决策只能由企业写
- `R07-61` 提交交接前必须已填代理所意见且有风险级别
- `R07-62` 每次状态变更写 activity + Drive 条目
- `R07-63` 告警台账在交接批准后才允许写库（Agent 侧约束）
- `R07-64` 告警关闭后不可重开
- `R07-65` 非本案人员不得看到本案告警
- `R07-70` 四种权能（建议 / 决定 / 否决 / 知情）须分别配置到人，不得合并为一个审批按钮
- `R07-71` 监控人只负责发现与评级，不决定是否维权；升级决策须由企业 IP 负责人作出
- `R07-72` 发警告函须法务总终审签发，且前置条件为完整 claim chart + 法律意见 + 业务影响评估（§2.1 五步链）
- `R07-73` 发函、公开谴责、起诉、和解四类不可逆动作一律 L4：双人复核 + 决议纪要，不得单人一键执行
- `R07-74` 业务部门可提出监控某竞品的需求，但不得自行发函、自行投诉、自行联系对方
- `R07-75` 告警分级由代理师定级、企业确认；级别上调须记录理由，降级须法务复核
- `R07-76` 关闭高风险告警须二级审批，并同时保留代理师意见与关闭理由（对应 C6）
- `R07-77` 监控外包须签数据处理协议并通过安全评估；跨境数据源须法务合规会签（对应 E5）
- `R07-78` 误报关闭为 L1；已发函后的误报补救为 L4，须在 24 小时内 ⚠ 启动（对应 E4）
- `R07-79` 防御向告警（我方被指侵权）的应诉、和解、反诉由法务总决定，业务有否决权
- `R07-80` 决定人须预设 A/B 角；未获明确答复不得发函或起诉，沉默不构成同意
- `R07-81` 每个决策须记录：决策人、时间、依据、备选方案、未采纳原因；意见与决议分别存储，不得互相覆盖
- `R07-82` 紧急取证可先执行后补批，但须在 24 小时内 ⚠ 补批并说明证据灭失风险；未补批的取证费用不予报销、证据标记为「授权瑕疵」（对应 E8）
- `R07-83` 监控发现自家专利被提无效时，须自动转 22 并锁定答复期限；监控侧告警与无效案件双向关联（对应 E6）
- `R07-84` 发函前须核验目标专利当前法律状态（有效 / 已质押 / 已独占许可 / 已终止），权利基础灭失的不得发函

### 08-layout · 节点 08 · 布局洞察（Patent Layout / Portfolio Strategy）· 产品级业务规格（57 条）

- `R08-01` 布局评价单位是**组合**，不是单件；考核指标不得用「申请量」
- `R08-02` 每个组合须能回答「核心专利是哪几件、外围是哪几件、谁依赖谁」
- `R08-03` 组合须做**单点依赖度**分析：核心专利被无效后，组合是否仍能阻断对手
- `R08-04` 布局必须同时给出三个维度（技术/地域/时间），缺一维视为未完成
- `R08-05` 布局结论须定期复核（建议年度），技术路线变化时立即复核
- `R08-10` **路障式**：针对竞争对手的必经技术路径申请，迫使其绕行或交叉许可
- `R08-11` **包围式**：围绕核心专利在外围（替代方案、上下游、应用场景）布多件，使核心即使被绕开也被外围拦住
- `R08-12` **地毯式**：在细分密集布点，靠数量与覆盖面取胜（成本高，适用于技术迭代快的领域）
- `R08-13` 布局法选择必须记录理由（对手是谁、我方资源、技术迭代速度）
- `R08-14` 同一格子不得同时标记为「空白」和「已布局」
- `R08-20` 技术维度须覆盖**上游（材料/部件）→ 本体 → 下游（应用/系统）**
- `R08-21` 须显式列出**替代技术路线**（对手可能绕开的方向）
- `R08-22` 涉及标准的，须标记**标准必要专利（SEP）**并单独评估 FRAND 义务
- `R08-23` 矩阵的每一格必须有 `ourCount` 与 `rivalCount` 两个数，不允许只定性
- `R08-24` 对手密度须标注**增速**（近 12 月新增），只看存量会误判
- `R08-30` 国别决策须按四类地打分：**制造地 / 销售地 / 竞争对手所在地 / 诉讼优选地**
- `R08-31` 每个国别须给出「为什么是它」（市场、制造、对手、判赔力度）
- `R08-32` 须区分「必须进」与「可选进」，并标注**放弃的后果**
- `R08-33` 国别建议须能与 09 PCT 的指定国清单对接
- `R08-34` 须给出每国的**预算量级**（官费 + 翻译 + 代理）
- `R08-40` 技术路线有 12 个月优先权窗口的，须在窗口内完成同族布局
- `R08-41` 布局须给出 PCT 决策点（30 个月 / 中国宽限至 32 个月）⚠
- `R08-42` 须标注「现在不申请，多久后会被公开/被对手占位」的倒计时
- `R08-43` 时间维度须与 11 docket 联动（优先权 12 月、PCT 30 月均应有 docket 规则）
- `R08-50` 空白点判定口径：`ourCount = 0` 且 `rivalCount` 低于阈值（建议 ≤ 全矩阵均值）
- `R08-51` 空白点必须排序（机会大小 × 进入成本），不得平铺
- `R08-52` 空白点转案须一键生成调研案，`fromInsight: true`，并回链原矩阵格
- `R08-53` 空白点转案须幂等（同一格不重复建案）
- `R08-54` 空白点转案须支持**批量**（一次把 5 个格打包成一个组合计划）
- `R08-55` 转案后须回写矩阵格状态（未布局 → 布局中）
- `R08-56` 补强建议须能派所（`packAndDispatch`），并带报价
- `R08-60` 3 项齐套全部为真才可提交/批准
- `R08-61` `matrix` 必须是结构化矩阵，不接受一段文字
- `R08-62` 补挂 `layout_insight` 只能写入 `drafting`，不得绕过 REQUIRED、不得自动批准
- `R08-63` 补挂须受角色/案级授权限制
- `R08-64` 提交与批准须由不同角色（代理提交、企业批准）
- `R08-65` 交接不得占用 `research_report`
- `R08-66` 每次补挂/提交/批准须写时间线 + Drive
- `R08-67` 布局方案的决定人是 IP 总监及以上；单案负责人、代理师只有建议权，不得以「已建案」代替布局批准
- `R08-68` 单格转案可按额度授权 IPR；批量转案（阈值企业配置 ⚠）须 IP 总监批准，并附组合理由与预算科目
- `R08-69` 业务部门对技术方向有输入权与否决权，**无布局决定权**；布局决议不得由业务部门单独作出
- `R08-70` 布局预算须单独立项，不得从单案预算挪用；超预算的补强或国别须走 L4
- `R08-71` 布局不得作为无限申请的理由：每条补强须绑定研发证据、预算科目、退出条件，三者缺一不得转案
- `R08-72` 布局与单案冲突时组合结论优先；偏离组合结论的单案须书面记录理由并由 IP 总监批准
- `R08-73` 放弃技术方向须 IP 总监与业务负责人会签，并同步给出存量资产处置方案（维持 / 转让 / 放弃）
- `R08-74` 国别建议的采纳权在 IP 总监（预算维度）；业务部门只提供市场需求输入；采纳结果须回写 09
- `R08-75` 布局复盘由 IP 总监负责，复盘结论须能触发矩阵重评与预算调整，不得只归档
- `R08-76` 布局决议须记录被否决的备选方向及理由；只保留最终矩阵视为未留痕
- `R08-77` 偏离 §4.8 任一条例外的操作，须记录依据、批准人、风险、有效期四项，缺项不得执行
- `R08-78` 预算不足以覆盖全部空白点时，须输出「已覆盖 / 未覆盖 / 监控」三张清单，未覆盖项不得静默消失
- `R08-79` 单案决策与组合结论冲突时，组合优先；单案偏离须附组合理由并由 IP 总监批准
- `R08-80` 前瞻布局须独立预算科目，不得与当期产品线预算混列；汇报不得以申请量代替组合指标
- `R08-81` 技术方向未定时，只允许在技术树下层（材料/工艺/通用结构）布点，不得为占位虚构应用方案
- `R08-82` 自研与收购两条路径须做三维比较（时间价值 / 断链风险 / 整合成本），不得同时全额立项
- `R08-83` 每格补强须绑定「若不布，多久后被对手占位」的倒计时；无倒计时的建议按最低优先级排
- `R08-84` 矩阵数据截至日超过阈值（建议 30 天 ⚠）时，不得据此作出批量转案决议
- `R08-85` 任何布局决议须记录适用的裁决原则序号（§4.9），以便事后审计与复盘

### 09-pct-international · 节点 09 · PCT 与国际进入（PCT International Phase & National Entry）· 产品级业务规格（61 条）

- `R09-01` PCT 国际申请须自最早优先权日起 **12 个月**内提交
- `R09-02` 中国完成的发明向外国申请（含 PCT）前，须先完成**保密审查**；未完成不得递交
- `R09-03` 国际申请须记录受理局、国际申请日、国际申请号三要素
- `R09-04` 国际检索单位（ISA）须在受理时确定，并记录 ISA 名称
- `R09-05` ISR 收到后须完成「引证分类 + 书面意见逐条研判」，并给出「是否继续」结论
- `R09-06` 请求国际初步审查（第 II 章）须在 **22 个月**或 ISR 传送后 3 个月内（取晚）提出 ⚠
- `R09-07` 第 19 条修改（权项）须在收到 ISR 后指定窗口内提出 ⚠ 窗口口径按条约细则核
- `R09-08` 第 34 条修改可在 IPER 出具前提交
- `R09-09` 国际公布 18 个月，公布前不得对外披露技术细节
- `R09-10` 国际阶段的任何修改须能追溯到「因哪条引证而改」
- `R09-20` 每国进入期限独立计算，不得用「PCT 一条期限」代表全部
- `R09-21` 中国：优先权日起 **30 个月**；缴宽限费后可延至 **32 个月** ⚠ 宽限费金额按当期收费表
- `R09-22` 宽限期一旦使用，必须生成「宽限费已缴」凭证，否则视为未进入
- `R09-23` 以外文提交的国际申请，进入中国须提交**中文译文**
- `R09-24` 在中国无长期居所/营业所的外国申请人，必须委托中国专利代理机构
- `R09-25` 进入声明须载明：申请号、进入国、是否修改、是否请求提前处理
- `R09-26` 进入后须在**2 个月内**缴清进入相关费用（申请费/附加费/优先权要求费等）⚠ 期限按细则核
- `R09-27` 权利要求超出规定项数的，按项加收**附加费** ⚠ 单价按收费表
- `R09-28` 进入决策（进/不进/待定）必须落库，且「不进」须写理由
- `R09-29` 同一族在同一国的进入必须幂等，不得重复建档
- `R09-30` 目标国 ≤2 且已确定 → 优先巴黎公约直进；目标国 ≥3 或未定 → 优先 PCT
- `R09-31` 路径选择须给出「成本 + 时间 + 灵活性」三维对比，而非单一建议
- `R09-32` 巴黎公约路径须在 12 个月内完成**全部**目标国递交，无延期
- `R09-33` PCT 路径的国际阶段费用须单列，不得混入国家阶段预算
- `R09-34` 路径选择后须回写 08 布局的国别建议，形成闭环
- `R09-40` 费用须分「官费 / 翻译费 / 当地代理费」三类，不得合成一个数
- `R09-41` 费用须带币种与汇率日期
- `R09-42` 中国作为受理局的 PCT，进入中国时申请费与申请附加费**免征** ⚠ 需按当期口径核
- `R09-43` 进入费用须能按国别汇总成「该案海外总投入」
- `R09-44` 费用估算须标明「示意」并给出复核日期
- `R09-50` 每国一条 docket，触发日 = 优先权日，期限 = 该国进入期
- `R09-51` 期限须三级预警（30 月前 90/30/7 天）并复用 `DocketEscalationLevel`
- `R09-52` 30 月未决 → 强制升级到 IP 负责人 + 商务决策会
- `R09-53` 进入后每国年费独立计算，按该国档位与币种
- `R09-54` 年费须能按「族」汇总，回答「这一族一年要花多少」
- `R09-55` 放弃某国年费须联动权利状态与组合退出记录
- `R09-60` 国际申请日、公布日、进入日是不可逆锚点，写入后不可编辑
- `R09-61` 每次期限变更须记录「谁改、为何改、依据哪份官方通知」
- `R09-62` 国家阶段案卷须回链族根，且能一键看全族状态
- `R09-63` 保密审查结论须存档，并在进入任何外国前校验
- `R09-64` 进入失败（逾期）须生成「权利灭失」事件，不得静默
- `R09-65` 30 个月进入决策的决定人是企业方人员（IP 总监按额度），代理师与当地代理只有建议权
- `R09-66` 每个指定国的 `decision` 须由企业账号写入；当地代理账号对该字段只读
- `R09-67` 国别决策须财务会签；每国须绑定预算科目，无科目的国家不得置为「决定进入」
- `R09-68` 进入决策与进入执行分别设期限：决策须在 24 个月前完成，执行为该国进入期 ⚠
- `R09-69` 译文须三段留痕（译者 / 校对 / 定稿人），定稿人对权项译文准确性负责；无定稿人不得递交
- `R09-70` 译文更正须评估对权项范围的影响并留痕，不得静默替换版本
- `R09-71` 当地代理的委托范围须明确排除「决定进入国别」；超范围指令系统不受理
- `R09-72` 预算按国别包分级审批，超阈值自动升级；**禁止拆国、拆合同规避审批**

### 10-handoff-state-machine · 横切 10 · 交接状态机（Handoff State Machine）· 产品级业务规格（65 条）

### 11-docket-engine · 横切 11 · Docket 期限引擎（Docket Engine）· 产品级业务规格（60 条）

- `R11-27` `mark_at_risk` 必须联动案件 `risk = '高'`
- `R11-28` 每次升级必须写 `escalationAt` / `escalationActor` / `note`
- `R11-29` 升级必须生成/接替运营待办（同事件只保留一条开放项）

- `R11-31` 升级阶梯必须可按时间自动推进，不依赖人点
- `R11-32` `at_risk` 需同时通知企业与代理所两侧

- `R11-34` 第 n 年年费取 `ANNUITY_FEES[n-1]`，越界取末值
- `R11-35` 年费档必须覆盖到法定保护期末（发明 20 年 / 实用新型 10 年 / 外观 15 年 ⚠）
- `R11-36` 外观与实用新型必须用**独立档**（不递增）

- `R11-39` 期限长度、起算点、宽限期、顺延规则属法定硬规则，不得由租户级业务配置覆盖；租户只能配置提醒策略
- `R11-40` 硬规则变更须法务复核 + 双人签署，旧版本保留可查，且变更生效日之前的在办事件不自动重算

- `R11-48` 多时区事件的「今天」以业务主体所在时区的服务端时间为准；跨时区期限各自标注时区
- `R11-49` 节假日顺延规则按官方口径维护，企业内部工作日历不得作为顺延依据
- `R11-50` 规则变更须区分「影响在办事件」与「仅影响新生事件」，并逐条记录重算决定
- `R11-51` 官方系统故障不可由任一方单方认定，须双方共同确认并保存客观证据
- `R11-52` 不可抗力主张须在恢复后第一时间启动法定救济（延期 / 恢复权利），不得只做内部备注
- `R11-53` 起算日存在争议时，按「较早日期」准备并在系统中同时记录争议日期与采用的日期
- `R11-54` 系统时间一律以服务端为准；客户端时间仅作展示，不得参与 `due_soon` / `overdue` 判定
- `R11-55` 例外的批准人、理由、有效期、受影响事件必须可统计；红线项不得提供例外入口
- `R11-56` 提醒节点数须收敛为可配置的少量节点，禁止「越临近越频繁」的无上限叠加
- `R11-57` 状态推进可自动，`done` / 豁免 / 延期不可自动；自动升级最多推进到 `reminded`
- `R11-58` 案件级覆盖只允许作用于策略参数（提前量 / 接收人 / 提醒方式），不得作用于期限长度
- `R11-59` 内部提前量与对外触达时间须分别配置，不得用同一个值
- `R11-60` 同一事件存在多个候选到期日时，一律按最早日期建单并注明差异

### 12-billing-engagement · 横切 12 · 商务线（报价 · 发票 · 付款 · 委托阶段）· 产品级业务规格（59 条）

- `R12-59` 每个商务决策须记录决策人、时间、依据、备选方案、未采纳原因；决议记录一经签署不可编辑

### 22-invalidation · 节点 22 · 无效宣告与异议程序（补建节点）（42 条）

- `R22-01` 无效请求只能针对**已授权**且**仍有效**的专利；已终止的专利无无效实益（但有例外：追溯赔偿）
- `R22-02` 无效理由必须落在法定理由范围内（§5.1），超范围的理由不予考虑
- `R22-03` 请求人可在**决定作出前**增加理由或补充证据，但受期限限制（通常为提出请求之日起 1 个月内补充 ⚠）
- `R22-04` 专利权人可在指定期限内修改权利要求（删除、合并、进一步限定），但**不得扩大保护范围**
- `R22-05` 无效宣告请求的审理采取**合议制**，可依申请或依职权进行**口头审理**
- `R22-06` 对无效决定不服的，可自收到决定之日起 **3 个月**内向北京知识产权法院起诉 ⚠
- `R22-07` 无效决定生效后，**权利视为自始不存在**（追溯力），但已执行的判决/裁定一般不具有追溯力（显失公平除外）
- `R22-08` 同一专利的无效请求可重复提起，但**同一理由和证据**的组合通常不再审理
- `R22-10` 证据必须是**申请日之前**公开的（抵触申请除外，其公开日可在后）
- `R22-11` 外文证据须在指定期限内提交**中文译文**，未提交部分视为未提出
- `R22-12` 公开使用/销售证据须形成**完整证据链**（时间、地点、内容、公开性）
- `R22-13` 网络证据须公证或时间戳固定，否则真实性易被质疑
- `R22-14` 证据之间须能**相互印证**，单一孤证证明力弱
- `R22-20` 无效决策须评估「无效成功概率 × 商业收益」与「成本」
- `R22-21` 被诉侵权时，无效常与侵权诉讼**并行**，需协调中止审理请求
- `R22-22` 防御方须评估「修改权项保专利」vs「硬扛全部维持」的商业后果
- `R22-23` 无效结果须联动更新组合内同族/关联专利的风险评级
- `R22-30` 补充理由/证据期限
- `R22-31` 专利权人答复期限
- `R22-32` 口审通知到口审
- `R22-33` 行政诉讼起诉期限
- `R22-34` 无效程序平均周期
- `R22-40` 任何无效立项须命中至少一条触发事由（被诉侵权 / 自由实施受阻 / 尽调 / 许可谈判），无触发事由不得立项
- `R22-41` 四种权能（建议 / 决定 / 否决 / 知情）须分别配置到人，不得合并为一个审批按钮
- `R22-42` 决定人必须是客户方人员；代理师、律师不得作为决定人出现在任何决议记录中
- `R22-43` 预算审批按额度分级，超阈值自动升级；禁止拆分案件或拆分合同规避审批
- `R22-44` 撤回、放弃维持、和解三类不可逆决策须双人复核 + 书面确认，单人操作不得生效
- `R22-45` 法务合规对存在利益冲突的案件有一票否决权，否决须书面说明理由并进入审计清单
- `R22-46` 决策人必须预设 A/B 角，授权书在立案时签署；B 角代行须在事后 5 个工作日内追认
- `R22-47` 未获明确答复不得推进不可逆动作；沉默不构成同意
- `R22-48` 专利权人修改权项须技术负责人与 IP 负责人会签；修改后须重新评估是否仍覆盖主要竞品
- `R22-49` 涉及核心产品排他的权项修改，业务负责人有否决权
- `R22-50` 代理师对理由成立性、证据强弱、口审策略有专业决定权，客户不得直接指定「必须主张某条理由」而不留痕
- `R22-51` 产生实体处分效果的文书（撤回、和解、放弃）须特别授权，无授权签署为效力待定
- `R22-52` 转委托须客户书面同意，且受托方须具备相应资质
- `R22-53` 代理师不得同时代理同一专利的请求人与专利权人；发现冲突须立即披露并退出
- `R22-54` 代理师的建议与客户的决议须分别存储，不得覆盖；客户驳回建议须给理由
- `R22-60` 每个决策须记录：决策人、时间、依据、备选方案、未采纳原因
- `R22-61` 例外情形须记录批准人、理由、有效期，并按案件统计例外率
- `R22-62` 规则冲突的裁决须记录适用的裁决原则序号（§4.6）
- `R22-63` 决议记录一经签署不可编辑，修改须新建版本并保留原版本
- `R22-64` 请求人侧与专利权人侧的决策记录严格隔离，跨侧可见须经双方授权

### 23-termination-recovery · 节点 23 · 终止 · 放弃 · 权利恢复（补建节点）（56 条）

- `R23-01` 年费应在**上一年度期满前**缴纳；未缴可在**宽限期 6 个月**内补缴并缴滞纳金 ⚠
- `R23-02` 宽限期届满仍未缴，专利权**自应缴年费期满之日起终止**
- `R23-03` 滞纳金按逾期时间**阶梯递增**（比例需按当期规定 ⚠）
- `R23-04` 终止后，系统须自动将案件状态置为 `terminated`，并联动组合看板
- `R23-05` 终止前应至少提前 **90 / 60 / 30 / 7 天**四轮预警
- `R23-06` 一件专利终止不影响同族其他专利
- `R23-10` 因**不可抗力**延误期限导致权利丧失的，可在障碍消除之日起 **2 个月内**、最迟自期限届满之日起 **2 年内**请求恢复 ⚠
- `R23-11` 因**正当理由**延误期限的，可在收到通知之日起 **2 个月内**请求恢复 ⚠
- `R23-12` 恢复请求须**缴纳恢复权利请求费** ⚠
- `R23-13` 恢复请求须提交**证明材料**（不可抗力或正当理由）
- `R23-14` 恢复须同时**补办耽误的手续**（如补缴年费 + 滞纳金）
- `R23-15` 恢复获批后，权利视为**连续存在**（终止期间的行为不追溯为侵权）
- `R23-16` 恢复请求被驳回的，可在法定期限内申诉
- `R23-20` 放弃须由专利权人**书面声明**
- `R23-21` 放弃须**全体专利权人同意**（共有专利）
- `R23-22` 已许可他人的专利放弃，可能构成**违约**，须先核查许可合同
- `R23-23` 已质押的专利放弃，须经**质权人同意**
- `R23-24` 放弃**不可逆**（除意思表示瑕疵）
- `R23-25` 放弃须**双人复核**（发起人 ≠ 批准人）
- `R23-26` 放弃决策须记录**理由与评分**，供日后审计
- `R23-30` 保护期：发明 **20 年**、实用新型 **10 年**、外观设计 **15 年**，均自**申请日**起算 ⚠
- `R23-31` 到期前 1 年应启动「到期处置」流程（是否续展同族、是否转技术秘密）
- `R23-32` 到期后专利进入公有领域，须从「有效组合」中移出
- `R23-40` 终止/放弃/到期须联动更新 `07-monitoring` 的维权范围
- `R23-41` 终止/放弃须联动更新 `06-commercialization` 的可许可资产清单
- `R23-42` 终止须联动 `12-billing` 停止后续年费发票
- `R23-70` 每一件年费决策必须有**具名决定人**；系统不得以「无人反对」替代决定
- `R23-71` 财务角色不得持有放弃/恢复的决定权与否决权，仅可执行付款、核销、开票
- `R23-72` 业务部门的「继续维持」主张须书面记录并可要求复议，但不得覆盖法务的合规否决
- `R23-73` 放弃的发起人与批准人必须是不同自然人；切换角色不构成双人复核
- `R23-74` 批量放弃按件数与年化维持成本**孰高**定档，达到 B 档及以上须法务 + 财务联签
- `R23-75` 共有专利放弃须取得全体共有人书面同意并归档原件，未取得则闸门阻断
- `R23-76` 已质押/已许可专利的放弃与恢复，须先完成征询并归档同意文件
- `R23-77` 启动恢复程序由 IP 总监决定；代理师只能建议，不得代为决定
- `R23-78` 恢复理由的法律定性以法务意见为准；代理师负责事实与证据，不负责定性
- `R23-79` 决策记录须含决定人、时间、依据与**被否决的反对意见**；只记结论视为未留痕
- `R23-80` 权利已过宽限期即置为「已终止·可恢复」，不得继续显示为「有效」；恢复期内的一切对外披露按已终止口径
- `R23-81` 例外处置须在**收到触发信息后 2 个工作日内**完成首次评估并指定责任人
- `R23-82` 代理机构失误不得由系统自动认定为正当理由，须经法务书面定性；定性结论与理由入库
- `R23-83` 系统 / 银行故障类例外，须同时留存「故障证据」与「重试记录」，仅有其一的不得提交恢复
- `R23-84` 已质押/已许可专利的终止，无论是否故意，均须在 3 个工作日内通知质权人/被许可人并评估违约
- `R23-85` 同族专利须**逐件独立**决策；批量操作不得跨国家/地区套用同一结论
- `R23-86` 保护期届满后不启动任何恢复程序；侵权主张只能覆盖到期日前的行为
- `R23-87` 恢复被拒后须在救济期限内给出「救济 / 放弃」的书面结论，不得静默结案
- `R23-88` 例外处置记录须包含「为何未走正常路径」，否则审计视为流程缺陷
- `R23-89` 同一案件 12 个月内出现两次及以上同类例外，须触发流程根因复盘
- `R23-90` 规则冲突按 P1→P7 顺序裁决，前序原则成立时不得援引后序原则
- `R23-91` 争议未决且年费期限在 7 日内，系统默认执行「缴费」并升级，不得默认放弃
- `R23-92` 放弃流程在途时，本期年费仍须照缴；不得以「待批准」为由停止缴费
- `R23-93` 「布局需要保留」的主张必须附带覆盖度/族完整性说明，否则不构成有效对抗
- `R23-94` 业务部门的复议请求须在 5 个工作日内答复，逾期视为维持原决定并留痕
- `R23-95` 法务的合规否决不得被成本理由覆盖；如企业仍要执行，须由法务负责人书面确认风险自担
- `R23-96` 法定期限类通知不得因客户偏好而关闭，只能调整渠道与频次
- `R23-97` 法律状态与业务阶段冲突时，对外披露、许可、维权一律以法律状态为准
- `R23-98` 官方登记状态与内部记录冲突时，以官方为准并将内部记录置「待核」，不得反向覆盖
- `R23-99` 每次冲突裁决须记录：冲突双方、适用原则、裁决人、裁决时间、被否决方意见

### 24-litigation · 节点 24 · 诉讼与维权（补建节点）（53 条）

- `R24-01` 必须**全面覆盖**：被控方案缺少任一技术特征即不侵权
- `R24-02` 等同判定须满足「基本相同的手段、实现基本相同的功能、达到基本相同的效果」且**本领域普通技术人员无需创造性劳动**即可联想
- `R24-03` 禁止反悔：专利权人在审查/无效程序中放弃的内容，不得在诉讼中重新纳入
- `R24-04` 捐献原则：说明书披露但未写入权项的方案，视为捐给公众
- `R24-05` 必须**指明具体权利要求**，不能笼统主张「该专利」
- `R24-06` 比对表须逐特征填写，不得只写结论
- `R24-10` 诉讼时效 **3 年**，自知道或应当知道侵权及侵权人之日起算 ⚠
- `R24-11` 超过 3 年起诉且侵权仍在持续的，赔偿自起诉之日向前推算 3 年 ⚠
- `R24-12` 可申请**诉前禁令**（情况紧急、不采取措施将造成难以弥补的损害）⚠
- `R24-13` 可申请**证据保全**（证据可能灭失或难以取得）⚠
- `R24-14` 方法专利涉及**新产品**的，举证责任倒置（由被控方证明方法不同）⚠
- `R24-15` 对方提无效的，可申请**中止审理**；但原告可提供担保请求不中止
- `R24-20` 不侵权抗辩：缺少必要技术特征 / 不构成等同
- `R24-21` 现有技术抗辩：被控方案实施的是**申请日前的现有技术** ⚠
- `R24-22` 无效抗辩：涉案专利应被宣告无效（须走 22 程序）
- `R24-23` 权利用尽：合法售出后的使用、销售、进口不侵权 ⚠
- `R24-24` 先用权：申请日前已制造相同产品/使用相同方法且仅在原范围内继续 ⚠
- `R24-25` 科研实验例外、Bolar 例外、临时过境 ⚠
- `R24-26` 诉讼时效抗辩
- `R24-30` 赔偿顺位：实际损失 → 侵权获利 → 许可费倍数 → 法定赔偿 ⚠
- `R24-31` 法定赔偿区间 3 万–500 万 ⚠
- `R24-32` 故意侵权且情节严重 → 1–5 倍惩罚性赔偿 ⚠
- `R24-33` 可主张合理开支（律师费、公证费、鉴定费）⚠
- `R24-34` 赔偿测算须有**数据来源**，不得估算填空
- `R24-40` 涉案专利被无效 → 诉讼基础消失，须联动 22 更新
- `R24-41` 诉讼结果须回写 05 权利状态（如专利被反诉无效）
- `R24-42` 胜诉后可作为 06 许可谈判的筹码，须留痕
- `R24-43` 败诉/被认定不侵权 → 须回写 07 监控规则（避免重复误报）
- `R24-50` 每个决策必须有且仅有一个 `decidedBy`；委员会决议须收敛到单一签署人
- `R24-51` 外部律师仅有建议权与执行权；接受和解、放弃诉请、对外表态须客户书面授权
- `R24-52` 起诉审批前须有业务部门书面确认的商业目标（市场排他/许可费/阻止竞品/维护客户关系），缺失不得提交立案审批
- `R24-53` 对外发声须法务事前书面批准；未经批准即发布视为越权
- `R24-54` 和解让步或预算超出 §2.1.4 授权额度的，系统必须阻断，不得以「先签后补」绕过
- `R24-55` 诉前禁令 / 证据保全须同时取得担保额度审批（财务）与策略审批（法务），缺一不得提交
- `R24-56` 因法定期限被迫作出的决策须标 `deadlineDriven`，并在期限届满后 5 个工作日内 ⚠ 补全材料
- `R24-57` 决策记录不可覆盖；更正以追加方式记录，保留原值与更正理由
- `R24-60` 时效将过且证据不足的，优先申请证据保全；只有证据保全不可行才可「先诉后补」，且须双签
- `R24-61` 境外被告须先做可执行财产检索；无可执行财产的，诉讼目标改为阻断而非赔偿
- `R24-62` 中止/继续的选择必须书面化，不得默认中止
- `R24-63` 多被告案件须先定「打源头还是打渠道」，且和解条件内部统一
- `R24-64` 原告须与专利权人或独占被许可人一致；不得借用主体起诉
- `R24-65` 涉密技术案件须在开庭前提出不公开审理申请；无法获得时评估放弃诉讼
- `R24-66` 平台投诉前必须确认「是否准备为此起诉」，否则不得投诉
- `R24-67` SEP 案件须先完成 FRAND 谈判记录整理，未履行谈判义务不得申请禁令 ⚠
- `R24-68` 所有例外必须记录「例外条件、批准人、风险确认、替代方案」四项，缺一不得放行
- `R24-70` 冲突按 P1 期限 → P2 不可逆 → P3 法律风险 → P4 口径统一 → P5 留痕 的顺序裁决
- `R24-71` 取证与止损冲突时，取证优先；止损动作不得早于证据固定
- `R24-72` 被告为战略客户/供应商时，起诉须法务与业务负责人联签，业务须书面确认关系损失
- `R24-73` 索赔策略须以「判赔 × 执行到位率」为口径评估，不得只比索赔金额
- `R24-74` 谈判期间对外发声默认禁止；例外须法务终审并记录对谈判的影响评估
- `R24-75` 多案资源分配须有书面排序公式与当期预算上限，不得按「先来先做」
- `R24-76` 执行阶段须设止损线；继续追加执行成本须重新审批
- `R24-77` 任何冲突裁决须登记冲突类型、裁决人、被牺牲方确认、裁决依据

### 25-claim-chart · 节点 25 · 权利要求比对表 `ClaimChart`（共享对象规格）（12 条）

- `R25-01` `verdict` 必须由 `elements` 推导，UI 不得提供直接选结论的入口
- `R25-02` `targetClaim.claimText` 必须是全文，不得用摘要或标题代替
- `R25-03` 必须指明 `claimNo`；不得以「该专利」笼统指代
- `R25-04` 任一要素 `unresolved` → 整体 `undetermined`，不得跳过
- `R25-05` `note` 为空时不允许设 `identical` / `equivalent` / `different`
- `R25-06` `equivalent` 必须额外说明「手段/功能/效果基本相同」三项
- `R25-07` 从属权项须单独建图，不得用独权结论代替
- `R25-08` `prosecutionRefs` 非空时，须核对是否触发禁止反悔
- `R25-09` 图发布须有 `reviewedBy` 且复核人具备代理师/律师资格 ⚠
- `R25-10` 图与结论一旦发布即锁定；修改须新建版本并说明原因
- `R25-11` 不得跨 `purpose` 复用同一张图
- `R25-12` `invalidation` 用途下不得出现 `equivalent`
