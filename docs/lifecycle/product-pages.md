## 1. 总则

| 项 | 口径 |
|---|---|
| **核心理念** | 外挂知识产权部；公司 / 部门 / 专家为传达与上手隐喻 |
| **与 vision §6** | 页清单、为什么这样切、不做清单以 vision 为准；本文补**逐页规格** |
| **与 product-logic** | 部门工作台 = L1 作业面；壳与确认 = L2；L3/L4 不上手第一屏 |
| **工作台定义** | **工作台 = 部门工作台**；**没有**单独「总工作台」页 |
| **双角色入口** | **禁止同页滤权限冒充双角色**。登录后先有**真正产品首页**（`/`＝`/agent` 总览），**不是**无首页仅 Redirect；双角色**主 CTA 不同**（代理→多案流水；企业→公司首页/开案子）。对齐 [product-vision.md](product-vision.md) §3.2 / §4.1 / §6.2 |
| **上手路径图** | 主链 hops + 每一跳「应感到 / 禁止」以 vision §3.2 与 [working/2026-10-23-onboarding-path-and-forbid.md](working/2026-10-23-onboarding-path-and-forbid.md) 为验收句；下文逐页表须能逐跳对上 |
| **登录入口** | **1** 页：`/login`（实现 `/agent/login`）；选角色后进入**产品首页**；**样机可本地会话**（非真鉴权）。规格见 §3#0 / §4.0 |
| **登录后首页** | **1** 页：`/`（实现 `/agent` index 总览）；跨案入口，**≠**与公司首页抢位的空「总工作台」。规格见 §3#H / §4.0a |
| **MVP 页数** | **15**（产品首页 §3#H + 案内 §3#1–#14；对齐 vision）；登录页另计 |
| **扩展页数** | **12**（见 §5；「更多部门」+ 工具台账；逐页规格已写全） |
| **文档合计** | **28**（登录 1 + MVP 15 + 扩展 12）；另有 §5.13 写明**不单列**项的归属 |
| **官网** | 不在本架构内 |

上手路径（与 vision §3.2 / 路径图一致）：

```
登录 `/login`
  → 产品首页 `/`（`/agent`；人人；薄总览）
  ├─【代理】主 CTA → 多案流水 `/cases` → 点进某案
  └─【企业】主 CTA → 开案子 `/cases/new`（无案）或 公司首页 `/cases/:id`（有案）
                         ↓
                   公司首页（一案一公司）
                         ↓
              七部部门工作台 → 交卷 → 确认页 `/pending`
                         ↓
              回公司首页 或 下一部门工作台
```

> 逐页验收字段统一为：**目的 · 用户应感到 · 首屏三块 · 主 CTA · 不放什么 · 上下页**。禁区全文见路径图。

## 2. 部门工作台统一布局

所有部门工作台共用同一骨架；**只换「交卷物 + 齐套清单 + 专家岗」**。

| 验收 | 口径（vision §3.2 #4） |
|---|---|
| **用户应感到** | 本站交卷是什么、齐套了没、专家建议稿、点交卷 |
| **首屏三块** | ① 交卷物 ② 齐套/硬闸 ③ ≤3 专家建议 |
| **主 CTA** | 交卷（未齐套禁用） |
| **不放什么** | 无交卷物装完成；>3 专家岗变目录；无公司顶栏；对外 Agent/Harness/Seat/HITL 黑话 |
| **上下页** | 上：公司首页「去当前部门」或部门地图 → 本页 → 下：确认页 → 回公司首页或下一部门 |

```
┌─ 顶栏（公司壳，常在）─────────────────────────────────────────┐
│ 案名 · 当前部门 · 七部微进度 · 铃铛(待确认) · 期限 · 更多/后勤   │
├─ 部门头 ────────────────────────────────────────────────────┤
│ 一句话目标 · 本站在主链位置 · 【交卷】主按钮（右）               │
├──────────── 主栏 ≈2/3 ─────────────┬── 右栏 ≈1/3 ────────────┤
│ 交卷物区（编辑 / 预览）              │ 齐套 / 硬闸               │
│                                    │ □ 清单项；红灯；完成标准    │
│                                    ├─ 专家协作（≤3 岗）─────────┤
│                                    │ 岗名 · 建议稿 · 采纳       │
│                                    ├─ 回流 / 说明 ─────────────┤
│                                    │ 驳回意见 / 上一站提示       │
└────────────────────────────────────┴──────────────────────────┘
│ 底栏可选：保存草稿 · 预览交卷 · 交卷（与头栏同动作）              │
```

| 区块 | 必须展示 | 规则 |
|---|---|---|
| 顶栏 | 案、当前部门、铃铛数、最近期限入口 | 任意部门不丢「公司」语境 |
| 部门头 | 白话目标 + 主按钮交卷 | 一屏知道本站干什么 |
| 交卷物 | 本站唯一权威产出 | 对 L1 SKU / 节点产物键 |
| 齐套栏 | 可判定完成项；未齐套禁用交卷 | 硬闸；对齐 nodes 齐套 |
| 专家条 | ≤2–3 岗；建议稿可采纳 | 不列 Agent 黑话名 |
| 回流 | 确认页驳回意见 | 驳回后落回本页 |

**移动端：** 顶栏压缩；齐套与专家改为底部抽屉；主区仍为交卷物；主按钮固定底栏。

**未齐套：** 「交卷」禁用，并列出缺项名（业务口径；实现债另见 working 债清单）。

## 4. 逐页规格（入口 + MVP 15）

每页固定字段：目的 · 首屏 · 布局 · 主/次按钮 · 空态/错误/硬闸 · 产品逻辑 · 业务节点。

### 4.0 登录

| 字段 | 内容 |
|---|---|
| **逻辑路径** | `/login`（实现 `/agent/login`） |
| **谁用** | 未建立工作会话者；样机演示访客 |
| **目的** | 选入口角色，建立样机会话，进入外挂 IP 部 |
| **用户应感到** | 「选我是代理还是企业，然后进外挂 IP 部」 |
| **首屏三块** | ① 定位句（外挂 IP 部）② 角色二选一 ③ 进入主按钮（+ 样机「本地会话、非真登录」） |
| **主 CTA** | 进入 → **产品首页** `/`（`/agent`）；**禁止**按角色直跳案盘/公司 |
| **不放什么** | 无首页直跳乱页；同页滤权限冒充双角色；营销落地页当登录后首页；七部地图/交卷物 |
| **上下页** | 上：站外/未登录 → **本页** → 下：产品首页 |
| **硬闸** | 未选角色不可进入；样机可用 localStorage / 假会话 |
| **产品逻辑** | L2 入口壳；vision §3.2 #0 |
| **业务节点** | 无 |

### 4.0a 产品首页（展示页 · 货架预览 · 非干活处）

> **状态：已锁 · Leslie 钉死 + vision §3.3 / kuaipao 验收**（2026-10-23）。  
> **首页不是干活的地方。** 只负责展示/看懂产品（品类句 + 货架预览含**七部全展示与每部≤3专家岗** + 进干活的主 CTA）。交卷 / 齐套 / 确认拍板 / 进部门作业 → 案盘、公司首页、部门工作台。预览**全灰态、只认知**。  
> **STOP** 只换口号、堆理念句、把首页做成作业台。

| 字段 | 内容 |
|---|---|
| **逻辑路径 / slug** | `/`（实现 `/agent` index；**真实页面**） |
| **谁用** | 已登录；代理与企业同壳 |
| **目的** | 一眼看懂品类与货；点大 CTA 去真干活页 |
| **用户应感到** | 「这是外挂 IP 部 / 办专利全流程；七部与交卷长这样；干活去案盘或公司，不在这页干」 |
| **角色边界** | **本页=展示**；**干活处=案盘 / 公司首页 / 部门台**（及确认页） |

#### 货架叠放（教育块；「已了解」收起；回访默认收起；货 > 文）

| 序 | 块 | 视觉 | 规则 |
|---|---|---|---|
| 1 | **品类大标题** | **一句大字**（非小字价值句） | 「**外挂知识产权部**」或「**把技术做成可递交的专利**」（可二选一或主+短副；**禁再堆理念句**；原价值句/亮点辅文可省） |
| 2 | **① 示范案卡片** | 橱窗主货 | 假案名 + 当前部门 + 进度一句；**灰态示意**；非真作业 |
| 3 | **② 七部徽章墙 + 每部默认露专家** | 对标 logo 条；**面积够抢眼**；七部**必须全部露出** | 交底→查新→立项→撰写→附图→递交→答复；当前高亮。每部**默认露出**该部 **≤3 专家岗**（**头像**占位即可 + 示意岗名；**不要**默认只露部名再点开才见）；隐喻「部门+专家」一眼可见。整墙灰态**只认知**：**不可**进作业/交卷/采纳。**禁**把首屏做成专家花名册墙（无部门骨架、名单铺满） |
| 4 | **③ 交卷缩略** | 与案卡并排/紧挨橱窗 | 2–3 张（交底书/可专利性报告/申请文件稿）± 待确认样例；只展示不编辑 |
| — | 路径微图等辅文 | 可省或极小 | 不得压过 1–4 |

#### 常显（收起教育块后仍在）

| 块 | 规格 |
|---|---|
| **进干活的主 CTA** | **大按钮**一屏一个：代理→案盘；企业有案→公司；无案→开案子 |
| **待确认列表** | 真条目或空态；骨架 `【案名】部门已交卷 · 待你确认：关口`；点击离开本页去确认，**不在首页批** |

| 字段 | 内容 |
|---|---|
| **交卷物 / 齐套 / 确认** | **禁止**本页交卷、齐套勾选、专家采纳、进部门作业、**确认拍板**（待确认条目只跳走确认页，不在首页过/驳） |
| **预览交互** | 全灰态只认知；徽章墙/案卡/缩略**不可**当作业入口 |
| **不放什么** | 首页干活（交卷/齐套/**确认拍板**/进部门作业）；**专家花名册墙**（无七部骨架、名单铺满）；默认只露部名要点开才见专家；>3 专家/部；专家可点进作业/采纳；说明文/口号堆；Agent 目录 |
| **上下页** | 登录 → **本展示页** →（主 CTA）案盘 / 开案子 / 公司首页 → 部门台才交卷 |
| **硬闸** | ① 本页≠干活处：无交卷/齐套/**确认拍板**；主 CTA 必须送人离开。② 七部全展示；每部**默认露出**≤3专家岗（头像占位+岗名；不必点开）；禁花名册墙；均灰态只认知。③ 截图不靠读长文说出品类 |
| **产品逻辑** | L2 展示壳；vision §3.3 |
| **实现交接** | Agent壳：货架布局 + 每部默认露≤3专家（头像占位）+ 钉死非干活；验收截图交 Grok Bot |
| **验收句** | 截图说出品类；七部全露出；每部**默认**可见≤3专家岗（头像占位+岗名；非点开才见；非花名册墙）；案卡+交卷橱窗；大 CTA 送人离开；首页无交卷/齐套/确认拍板 |


### 4.1 开案子

| 字段 | 内容 |
|---|---|
| **逻辑路径** | `/cases/new` |
| **谁用** | 企业无案（产品首页主 CTA）；代理人亦可代建 |
| **目的** | 极少字段立一条业务线，然后进**公司首页** |
| **用户应感到** | 「三步立一条业务线，然后进公司」 |
| **首屏三块** | ① 一句外挂 IP 部 ② 案名（必填）③ 技术一句话/创建人（短） |
| **主 CTA** | 创建并进入**公司首页**（禁止建完直进交底表） |
| **不放什么** | 长表单；六项齐套；直进交底 Word；跳过公司首页认知；七部地图 |
| **上下页** | 上：产品首页（企业无案 CTA）→ **本页** → 下：公司首页 |
| **硬闸** | 无案名不可创建 |
| **产品逻辑** | L2 建案；vision §3.2 #2b |
| **业务节点** | 入口；尚未进入 00 |

### 4.2 多案流水（案盘）

| 字段 | 内容 |
|---|---|
| **逻辑路径** | `/cases` |
| **谁用** | **代理人**主 CTA 目标（企业通常不以此为默认落点） |
| **目的** | 跨案清单：卡住哪、谁待确认、期限红点；点进某案 |
| **用户应感到** | 「我的案子清单：卡在哪、谁待确认、期限红点」 |
| **首屏三块** | ① 案列表（案名/编号、当前部门、待确认、期限红点、客户）② 筛选 ③ 开新案/铃铛入口 |
| **主 CTA** | 点进某案 → **公司首页**（不是直进部门台） |
| **不放什么** | 企业单案陪跑壳；七部作业/交卷物；无案名就进深页；冒充产品首页总览 |
| **上下页** | 上：产品首页（代理 CTA）→ **本页** → 下：公司首页 |
| **空态** | 「还没有案子」+ 开案子 |
| **硬闸** | 无权限案不可见 |
| **产品逻辑** | L2 案盘（**非**产品首页）；vision §3.2 #2a |
| **业务节点** | 横切 |

### 4.3 公司首页

| 字段 | 内容 |
|---|---|
| **逻辑路径** | `/cases/:id` |
| **谁用** | 本案相关所有人；企业有案时产品首页主 CTA；代理从案盘点进 |
| **目的** | 案级认知：这是本案 IP 部、当前部门、专家点开才见、去干活 |
| **用户应感到** | 「这是本案的 IP 部；现在在哪个部门；专家点开才见；去当前部门干活」 |
| **首屏三块** | ① 定位句 + 案名/编号 ② **七部地图**（当前高亮；点部门才展开 ≤3 专家）③ 「去当前部门」+ 铃铛/近期限 |
| **主 CTA** | 去当前部门 → 对应部门工作台 |
| **不放什么** | 直进交底表单；十二部一屏全开；专家花名册墙；与产品首页同构的第二套跨案总览；在此编辑交卷物 |
| **上下页** | 上：案盘点进 / 开案子建成 / 企业有案 CTA → **本页** → 下：七部工作台（或铃铛确认） |
| **空态** | 新案当前=交底部，引导去交底 |
| **硬闸** | 不可在此「一键跳过部门」改法律状态；更多部门默认折叠 |
| **产品逻辑** | L2 案级壳 + 理念；vision §3.2 #3 |
| **业务节点** | 整案视图 |

### 4.4–4.10 部门工作台（共用骨架，分述交卷物）

> 验收对齐 vision §3.2 #4 与 **§2**（应感到 / 首屏三块 / 主 CTA / 不放什么 / 上下页）。下列各部只补**交卷物 · 齐套 · 专家岗示例**差异。

#### 4.4 交底部工作台

| 字段 | 内容 |
|---|---|
| **目的** | 写成可检索、可撰写的技术交底包（**不**拍板申不申） |

### 5.6 终止与恢复（23）

> **定位：** 独立工作台页（E6），**不是**上手七部；公司首页「更多」可见。  
> **入口关系：** 维持部（E5）主区/次要按钮「终止 / 放弃 / 恢复」可深链进入本页；期限台逾期事件亦可打开。亦可视为维持子流程，但**须有独立 URL/页规格**，避免只藏在维持里找不到。

| 字段 | 内容 |
|---|---|
| **谁用** | IP 总监 / 流程员 / 授权决策人 |
| **目的** | 处理年费终止、书面放弃、届满、无效生效后的状态；评估可否恢复并闭环手续 |
| **交卷物** | 终止/放弃/恢复案卷：事件类型、决策人与理由码、手续与费用闭环记录、公告/登记对齐状态 |
| **齐套要点** | 状态变更已登记口径对齐；恢复则手续+费用闭环；终止则归档原因码（摘自 [23](nodes/23-termination-recovery.md) §0.1） |
| **专家岗示例（≤3）** | 窗口期核算；恢复路径建议；放弃批量风险提示 |
| **首屏必须有** | 当前权利状态；事件类型；可恢复性判断摘要；决策人 |
| **布局** | §2；主区=事件与手续清单；右栏=齐套 + 专家；明显链回维持部 |
| **主按钮** | 交卷（提交放弃/恢复请求供确认） |
| **次要** | 回维持部；回写组合/08；关闭监控与转化路径（不可恢复时） |
| **空态** | 「无终止类事件」+ 回维持 |
| **硬闸** | 禁止把「还能补缴」当成权利仍确定有效而不评估；禁止无审批批量放弃；禁止窗口关闭后承诺「一定能救回」；费用以当期公告为准（不写死） |
| **产品逻辑** | L2/资产治理扩展；依附 P05 生命周期 |
