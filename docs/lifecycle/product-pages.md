# 产品页面规格（Product Pages）

> **本文回答：登录后一共哪些页、每页首屏有什么、怎么排布、主按钮是什么、硬闸与空态、对哪条产品逻辑与业务节点。**  
> **上游**：[product-vision.md](product-vision.md) §6（信息架构与理由）、[product-logic.md](product-logic.md) §0.1–§0.2 / §5.4（SKU 与叙事套装）。  
> **业务细节**（齐套项、法条）以 `nodes/` §0.1 / §4 为准；本文**不编造**法条号与金额。  
> **定稿**：2026-10-23（Asia/Shanghai）。非高保真线框；实现路由名为建议。

## 1. 总则

| 项 | 口径 |
|---|---|
| **核心理念** | 外挂知识产权部；公司 / 部门 / 专家为传达与上手隐喻 |
| **与 vision §6** | 页清单、为什么这样切、不做清单以 vision 为准；本文补**逐页规格** |
| **与 product-logic** | 部门工作台 = L1 作业面；壳与确认 = L2；L3/L4 不上手第一屏 |
| **工作台定义** | **工作台 = 部门工作台**；**没有**单独「总工作台」页 |
| **MVP 页数** | **14**（见 §3） |
| **官网** | 不在本架构内 |

上手路径：

```
登录 →（代理：多案流水）/（企业：开案子或直进）→ 公司首页
     → 部门工作台 → 交卷 → 确认页 → 回公司首页或下一部门
```

## 2. 部门工作台统一布局

所有部门工作台共用同一骨架；**只换「交卷物 + 齐套清单 + 专家岗」**。

```
┌─ 顶栏（公司壳，常在）─────────────────────────────────────────┐
│ 案名 · 当前部门 · 七部微进度 · 铃铛(待确认) · 期限 · 更多/后勤   │
├─ 部门头 ────────────────────────────────────────────────────┤
│ 一句话目标 · 本站在主链位置 · 【交卷】主按钮（右）               │
├──────────── 主栏 ≈2/3 ─────────────┬── 右栏 ≈1/3 ────────────┤
│ 交卷物区（编辑 / 预览）              │ 齐套 / 硬闸               │
│                                    │ □ 清单项；红灯；完成标准    │
│                                    ├─ 专家协作（≤3 岗）─────────┤
│                                    │ 岗名 · 建议稿 · 采纳       │
│                                    ├─ 回流 / 说明 ─────────────┤
│                                    │ 驳回意见 / 上一站提示       │
└────────────────────────────────────┴──────────────────────────┘
│ 底栏可选：保存草稿 · 预览交卷 · 交卷（与头栏同动作）              │
```

| 区块 | 必须展示 | 规则 |
|---|---|---|
| 顶栏 | 案、当前部门、铃铛数、最近期限入口 | 任意部门不丢「公司」语境 |
| 部门头 | 白话目标 + 主按钮交卷 | 一屏知道本站干什么 |
| 交卷物 | 本站唯一权威产出 | 对 L1 SKU / 节点产物键 |
| 齐套栏 | 可判定完成项；未齐套禁用交卷 | 硬闸；对齐 nodes 齐套 |
| 专家条 | ≤2–3 岗；建议稿可采纳 | 不列 Agent 黑话名 |
| 回流 | 确认页驳回意见 | 驳回后落回本页 |

**移动端：** 顶栏压缩；齐套与专家改为底部抽屉；主区仍为交卷物；主按钮固定底栏。

**未齐套：** 「交卷」禁用，并列出缺项名（业务口径；实现债另见 working 债清单）。

## 4. 逐页规格（MVP 14）

每页固定字段：目的 · 首屏 · 布局 · 主/次按钮 · 空态/错误/硬闸 · 产品逻辑 · 业务节点。

### 4.1 开案子

| 字段 | 内容 |
|---|---|
| **谁用** | 企业研发（无案）；代理人代建 |
| **目的** | 立一条业务线（进「公司」） |
| **首屏必须有** | 一句「外挂知识产权部」；案名；技术一句话（可选技术领域）；创建人 |
| **布局** | 单栏短表；无部门地图（建完才进公司首页） |
| **主按钮** | 创建并进入公司首页 |
| **次要动作** | 取消回登录后默认页 |
| **空态** | —（本页即创建） |
| **错误态** | 案名必填校验 |
| **硬闸** | 无案名不可创建；不在此要求六项齐套 |
| **产品逻辑** | L2 案件中台 · 建案 |
| **业务节点** | 入口；尚未进入 00 |

### 4.2 多案流水

| 字段 | 内容 |
|---|---|
| **谁用** | **代理人**（企业研发通常不落此页） |
| **目的** | 选案；看见卡住哪、谁在等确认 |
| **首屏必须有** | 案列表：案名/编号、当前部门、待确认数、最近期限红点、客户名 |
| **布局** | 顶：筛选（客户/部门/期限）；主：表格或卡片列表 |
| **主按钮** | 点进某案 → 公司首页 |
| **次要动作** | 开新案；筛选；铃铛汇总 |
| **空态** | 「还没有案子」+ 开案子 |
| **错误态** | 加载失败重试 |
| **硬闸** | 无权限案不可见 |
| **产品逻辑** | L2；代理人首页 |
| **业务节点** | 横切；非单节点 |

### 4.3 公司首页

| 字段 | 内容 |
|---|---|
| **谁用** | 本案相关所有人；**企业有案时默认落点** |
| **目的** | 10 秒懂：我们是外挂 IP 部、有哪些部门、专家怎么来、本案在哪 |
| **首屏必须有** | 定位句；**七部地图**（当前高亮）；铃铛入口；「去当前部门」；案名/编号 |
| **布局** | 上：定位 + 案摘要；中：七部地图（点部门才展开 ≤3 专家岗）；右或下：待确认 / 近期限；底：「更多部门」折叠 |
| **主按钮** | 去当前部门 |
| **次要动作** | 开新案；进期限/账单/成员；展开更多部门 |
| **空态** | 新案：当前=交底部，引导去交底 |
| **错误态** | 案不存在 / 无权限 |
| **硬闸** | 不在此编辑交卷物；不可在此「一键跳过部门」改法律状态 |
| **产品逻辑** | **L2 壳 + 理念传达**；非 L1 表单 |
| **业务节点** | 整案视图 |

### 4.4–4.10 部门工作台（共用骨架，分述交卷物）

以下各页均遵循 §2 布局；只列差异。

#### 4.4 交底部工作台

| 字段 | 内容 |
|---|---|
| **目的** | 写成可检索、可撰写的技术交底包（**不**拍板申不申） |
| **交卷物** | `disclosure_pack`：六项技术 + 四组事实（权属/署名/奖酬依据/公开时点） |
| **齐套要点** | 六项为真；四组闭合；发明人已确认；须法务会签时已通过；无 blocking gap（摘自 [00](nodes/00-inventor-disclosure.md) §0.1/§2） |
| **专家岗示例（≤3）** | 交底辅导（结构提示）；事实核对；（可选）评分建议起草 |
| **主按钮** | 交卷 → 确认（IPR 批准语义） |
| **次要** | 保存草稿；请法务会签；退回发明人补 |
| **空态** | 空交底模板 + 六项指引 |
| **硬闸** | 未齐套不可交卷；禁止代改已确认技术事实；禁止把建议写成已 Go |
| **产品逻辑** | L1 **P01** |
| **业务节点** | [00](nodes/00-inventor-disclosure.md) |

#### 4.5 查新部工作台

| 字段 | 内容 |
|---|---|
| **目的** | 可专利性证据齐套；给出继续/改写/暂缓/放弃建议 |
| **交卷物** | `research_report`（检索式、命中、结论等；业务必齐项见 01） |
| **齐套要点** | 申请主链以可专利性证据为必齐；**FTO 不作为申请硬闸**（摘自 [01](nodes/01-research.md) §0.1） |
| **专家岗示例** | 检索策略；对比文件梳理；结论稿（建议） |
| **主按钮** | 交卷 |
| **次要** | 回流交底补强；附可选 FTO 草稿（不挡） |
| **空态** | 无命中时的空报告骨架 + 须声明已检范围 |
| **硬闸** | 未齐套不可交卷；禁止用 FTO 空缺卡死申请交卷（文档口径） |
| **产品逻辑** | L1 **P02** |
| **业务节点** | [01](nodes/01-research.md) |

#### 4.6 立项部工作台

| 字段 | 内容 |
|---|---|
| **目的** | D1 申不申 / D2 类型；报价与委托意向 |
| **交卷物** | 单案决策书 + `intake_quote`（决议签署、国际路径意向等） |
| **齐套要点** | Go：报价齐套 + 决议签署 + 国际意向已记；或 No-Go：理由码归档（摘自 [02](nodes/02-decision.md) §0.1） |
| **专家岗示例** | 评分卡汇总；报价草稿；会议纪要助手 |
| **主按钮** | 交卷（提交决议供确认） |
| **次要** | 记 No-Go；与布局同会时链到布局产出（两份产物） |
| **空态** | 缺上游交底/查新时提示补齐，不可空转 Go |
| **硬闸** | 无人签署不得 Go；No-Go 必须有理由码 |
| **产品逻辑** | L1 **决策/预算**（确权路径） |
| **业务节点** | [02](nodes/02-decision.md)；决策权 D1/D2 |

#### 4.7 撰写部工作台

| 字段 | 内容 |
|---|---|
| **目的** | 单案权利边界成型（D3）；权项 + 说明书等 |
| **交卷物** | `draft_claims`（权项树、说明书等） |
| **齐套要点** | draft_claims 必填项；与附图/递交清单分工见 03（摘自 [03](nodes/03-drafting.md)） |
| **专家岗示例** | 权项结构建议；说明书章节补全提示；术语一致检查 |
| **主按钮** | 交卷（送企业确认保护范围） |
| **次要** | 跳转附图部；预览申请包 |
| **空态** | 从交底/发明点导入骨架 |
| **硬闸** | 关键范围变更须确认；空权项不可交卷 |
| **产品逻辑** | L1 **P03** |
| **业务节点** | [03](nodes/03-drafting.md) |

#### 4.8 附图部工作台

| 字段 | 内容 |
|---|---|
| **目的** | 图文一致的附图定稿 |
| **交卷物** | 附图包（图号、简要说明与说明书引用一致） |
| **齐套要点** | 图号齐全；与说明书实施例引用一致；格式满足递交检查相关项（摘自 03 递交清单中与图相关项，不另造条号） |
| **专家岗示例** | 制图；图号核对；图文一致性检查 |
| **主按钮** | 交卷 |
| **次要** | 回撰写部；导入图文件 |
| **空态** | 「本案尚无附图」+ 上传/生成入口 |
| **硬闸** | 图文冲突未消不可与撰写一并定稿交卷 |
| **产品逻辑** | **P03 内**（独立部门页） |
| **业务节点** | 03 内附图 |

#### 4.9 递交与程序部工作台

| 字段 | 内容 |
|---|---|
| **目的** | 申请包齐套、缴费/递交责任确认；拿回执 |
| **交卷物** | 申请包 + 递交检查清单（如 `filing_check`）+ 回执/凭证 |
| **齐套要点** | 递交检查项全绿；授权人确认；回执登记（摘自 03 递交闸 / 10 交接） |
| **专家岗示例** | 形式审查清单；官费/费减核对（金额以当期公告为准，页上不写死）；递交队列状态 |
| **主按钮** | 请求递交确认 / 登记已递交 |
| **次要** | 补正；查看账单口袋 |
| **空态** | 无申请包时导回撰写 |
| **硬闸** | **不可逆递交**须授权人确认；未齐套不可递交；官费/代理费分口袋展示 |
| **产品逻辑** | **L2 程序** + 交接 authorize |
| **业务节点** | 03 闸 + [10](nodes/10-handoff-state-machine.md) |

#### 4.10 审查答复部工作台

| 字段 | 内容 |
|---|---|
| **目的** | 登记 OA、定策略、改权项/陈述；D5 |
| **交卷物** | `prosecution_response`（争点、策略、修改对照、陈述确认等） |
| **齐套要点** | 节点要求的答复包必填项；期限可见（摘自 [04](nodes/04-prosecution.md) §0.1） |
| **专家岗示例** | 争点拆解；策略三选一建议；修改对照稿 |
| **主按钮** | 交卷（送企业确认答复策略） |
| **次要** | 延期申请记录；分案/复审入口（支线说明） |
| **空态** | 无 OA 时说明「等待审查意见」+ 期限台链接 |
| **硬闸** | 超绝限须升级；策略无理由不可交卷；超范围修改禁 |
| **产品逻辑** | L1 **P04** |
| **业务节点** | [04](nodes/04-prosecution.md)；D5 |

### 4.11 确认页（铃铛）

| 字段 | 内容 |
|---|---|
| **谁用** | 有确认权者（发明人/IPR/授权人等，按 decision-rights） |
| **目的** | 人拍板后再移交或改法律相关状态 |
| **首屏必须有** | 交卷摘要；**决策含义**（对齐 D1–D7 时明示）；缺项红灯；通过 / 驳回+意见 |
| **布局** | 可全页或右侧抽屉；顶仍可见案名与部门 |
| **主按钮** | 通过（推进下一部门或完成法定动作） |
| **次要** | 驳回；查看全文交卷物；不可逆时责任提示勾选 |
| **空态** | 「暂无待确认」+ 回公司首页 |
| **错误态** | 越权确认；交卷已被撤回 |
| **硬闸** | 起草人不可自批（业务口径）；未齐套不可装通过；不可逆须双确认提示 |
| **产品逻辑** | **L2 交接与审批** |
| **业务节点** | [10](nodes/10-handoff-state-machine.md) |

### 4.12 期限台

| 字段 | 内容 |
|---|---|
| **目的** | 看见法定/程序期限与绝限 |
| **首屏必须有** | 期限列表：名称、到期日、状态、关联案/部门；绝限强调 |
| **布局** | 筛选（即将到期/已逾期）；列表为主 |
| **主按钮** | 打开关联部门工作台或确认项 |
| **次要** | 标记处理中；升级通知（依 11） |
| **空态** | 「本案暂无期限事件」 |
| **硬闸** | 不在此直接改官方法律状态；逾期须可见不可静默 |
| **产品逻辑** | L2 **docket** |
| **业务节点** | [11](nodes/11-docket-engine.md) |

### 4.13 账单/委托

| 字段 | 内容 |
|---|---|
| **目的** | 委托范围与钱清楚；官费与代理费分口袋 |
| **首屏必须有** | 委托单摘要；应收/已付；**官费口袋 vs 服务费口袋**分列 |
| **布局** | 上委托；下发票/付款行 |
| **主按钮** | 确认报价 / 登记付款（权限内） |
| **次要** | 导出对账；链到年费代缴说明（P05 更多部门时） |
| **空态** | 「尚未报价」+ 立项/商务入口 |
| **硬闸** | 禁止官费与代理费混账展示；金额以当期约定/公告为准，页上可链 sources 收费公告 |
| **产品逻辑** | L2 **商务** |
| **业务节点** | [12](nodes/12-billing-engagement.md) |

### 4.14 成员与权限

| 字段 | 内容 |
|---|---|
| **目的** | 谁能进公司、谁能确认交卷 |
| **首屏必须有** | 成员列表：姓名、角色白话（发明人/IPR/代理人/授权人…）、可确认哪些闸 |
| **布局** | 列表 + 邀请；非专家花名册墙 |
| **主按钮** | 邀请成员 / 保存角色 |
| **次要** | 移除；查看决策权说明链到 decision-rights |
