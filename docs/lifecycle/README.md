## 写作纪律（摘要）

1. **业务优先**：先写业务上应该是什么，再谈代码怎么做。不得用「原型就这样」当理由。
2. **规则可测**：每条规则能写成测试用例；「应保证质量」不是规则。
3. **讲因果**：每条规则必须写清违反后的后果。
4. **不编造**：法条号、金额、比例必须有一手来源；查不到就标 ⚠「需复核」，不猜。
5. **分层归类**：规则必须标明属于法定 / 程序 / 商业 / 质量 / 数据哪一类（见总纲 §4）。
