## 人读导览（约 10 分钟）

> **给非实现读者**：先看懂「整条业务怎么走、每站干什么」，再按需下钻规则。实现细节（StageId、handoff、代码路径）可后读。

### 一页主链（中国发明 · 拿专利默认路径）

```
创新激发 Ni（可轻跑）
    ↓
捕获（入池；不单列，并入挖掘/交底入口）
    ↓
专利挖掘 Nm（可粗检；≠正式查新）
    ↓
发明交底 00          ← 技术事实收成可写材料
    ↓
查新 / 可专利性 01   ← 能不能授权（业务必经）
    ↓
（按需）FTO 01b      ← 能不能安全卖；不挡申请
    ↓
布局刷新 08 ＋ 单案立项 02   ← 可同会；两份产出
    ↓
撰写 ∥ 附图 03 → 定稿 → 递交 → … → 年费 05
```

支线（条件触发，不挡主链）：PCT/国际、复审、无效、诉讼、监控、运用。

### 三层必经（先分清，再读节点）

| 层 | 白话 | 例子 |
|---|---|---|
| **法律必经** | 法条/程序卡死，产品不能「业务跳过」 | 递交齐套、期限答复、年费、保密审查（涉外时） |
| **业务必经** | 代理所/企业质控：不做就不合格 | 交底、查新、立项签字、撰写定稿 |
| **条件触发** | 碰到才做；不碰到不挡申请 | 激发加重、FTO、PCT、结构类附图、复审/无效/诉讼 |

边界口诀：激发=还有什么方向；挖掘=申什么；布局=整盘怎么护；查新=能不能授权；FTO=能不能安全卖；立项=这一案怎么定。**查新 ≠ FTO。**

## 写作纪律（摘要）

1. **业务优先**：先写业务上应该是什么，再谈代码怎么做。不得用「原型就这样」当理由。
2. **规则可测**：每条规则能写成测试用例；「应保证质量」不是规则。
3. **讲因果**：每条规则必须写清违反后的后果。
4. **不编造**：法条号、金额、比例必须有一手来源；查不到就标 ⚠「需复核」，不猜。
5. **分层归类**：规则必须标明属于法定 / 程序 / 商业 / 质量 / 数据哪一类（见总纲 §4）。
