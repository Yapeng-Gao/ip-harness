## 0. 一句话讲清这个节点

**商务线 = 把「这件事谁付钱、付多少、什么时候付、付给谁」变成一笔笔可核销的账，并且让「没付钱」能合法地卡住「交活」。**

它管的不是财务总账，而是**案件级委托的履约与结算**：一次委托从评估、报价、确认、派单、开票、付款到结清，全程挂在案件上；每张发票钉到一个节点，逾期就能反卡该节点的递交动作。

行业里最容易被做错的一点，是把它当"开票工具"。真实业务里它是**两条账**：官方费用（代收代缴）与代理服务费（自营收），混在一起就是合规问题（§5.1）。

产品化三条件：

1. **有独立买方**：代理所（应收账款）、企业 IP（预算与成本归集）、年费代缴服务商（批量账单）。
2. **有独立价值**：逾期发票自动停递交，是把"催款"从人情变成规则；对代理所是现金流，对企业是预算纪律。
3. **有独立边界**：输入是案件与合同条款，输出是发票与付款状态，不依赖撰写/答复的具体内容。

## 1. 节点定位与产品边界

### 1.1 在生命周期中的位置

```
02 立项 ──报价──► 03 撰写 ──服务费──► 04 答复 ──服务费──► 05 维持 ──官费+代缴费──► 06 转化 ──交易费
   │                 │                   │                    │                      │
   └── intake_quote  └── draft_claims    └── prosecution_     └── maintain_annuity    └── monetize_terms
       （报价键）         （计价依据）        response              （官费口径）            （分成/入门费）
                            │
                     全部绑定 Engagement（委托单）→ CaseInvoice[]（发票台账）
```

- **无 `StageId`**：横切层，挂在案件上（`PatentCase.engagement`）。
- **与 02 决策的边界**：02 决定「做不做、做多大」，12 决定「怎么收钱」。`intake_quote` 这一个产物键同时承载两边，是当前设计最容易混的地方（§14 差距 8）。
- **页与路由**：`/billing/cases`（费用中心，`src/pages/Billing.tsx`），另有 `CaseDetail` 内嵌发票卡片。
- **命令**：`issueInvoice` / `payInvoice` / `confirmQuote` / `assignAgency`（`commandNames.ts:15`）。

### 1.2 它是什么 / 不是什么

| 是 | 不是 |
|---|---|
| 案件级**委托与结算**台账 | 企业财务总账（应与 ERP 对接，不替代） |
| 两条账的**分类载体**（官费 / 服务费） | 银行支付通道 |
| 逾期卡递交的**业务规则** | 信用管理 / 法务催收系统 |
| 委托阶段（7 段）的**进度视图** | 专利阶段（7 个 `StageId`）——两者不同轴 |
| 报价派单的状态机 | 招投标系统（无评标、无排名） |

### 1.3 上游 / 下游

| 方向 | 对象 | 契约 |
|---|---|---|
| 上游 | 02 立项（`intake_quote`） | 报价金额 + 委托范围 + 委员票 |
| 上游 | 03/04/05/06 各节点 | 触发开票（服务费）+ 官费口径 |
| 上游 | 11 docket | 官费金额与缴纳期限（当前仅文案） |
| 下游 | 交接机（10） | `invoice` blocker 反卡代理的 `authorize/file` |
| 下游 | 05 维持 | `pay_unlock` 闸；付款后回写 docket |
| 下游 | 审计 | `issueInvoice` / `payInvoice` 各一条 |
| 横向 | 租户 / 工作区 | 企业看自己发票，代理看自己应收 |

### 1.4 独立产品的形态

**产品名建议：案件结算中心 / Matter Billing**

| 模块 | 能力 | 谁用 |
|---|---|---|
| 报价与委托 | 报价单、委托范围、委员确认 | 企业 IP + 代理所 |
| 双账台账 | 官费（代收代缴）与服务费（自营）分列 | 财务 |
| 开票与收款 | 开票、部分付款、结清 | 财务 |
| 逾期停权 | 逾期发票 → 停授权/递交 | 代理所负责人 |
| 派单 | 代理意向、比价、派单 | 企业采购 + IP |
| 对账 | 官费实缴 vs 预估、发票 vs docket | 财务 + 流程岗 |

**不做的**：不做开票（对接金税/电子发票平台）、不做支付（对接银企直联）、不做总账与报表合并（那是 ERP）。

## 2. 角色与权限矩阵

| 角色 | 代码对应 | 能做什么 | 不能做什么 |
|---|---|---|---|
| 企业 IP | `enterprise_ip` | 确认报价、确认委托、付款解锁、看全部发票 | 不能改代理所的应收金额 |
| 企业财务 | 无独立 persona（借 `enterprise_ip`） | 付款、结清 | ⚠ 无独立角色，与 IP 权限同权 |
| 代理所 | `agency` | 提交报价、开票、看自己的应收 | **不能付款**（`personaBlocksPay` 硬禁） |
| 发明人 | `inventor` | 无 | 付款 / 开票 / 确认报价全禁 |
| 评审委员 | `committee` | 只投票 | 付款 / 开票 / 确认报价全禁 |
| 系统 Agent | `agent-annuity`（`pay_unlock`）、`agent-intake`（`confirm_quote`） | 生成计划与报价草案 | 不能替人付款 |

**当前实现的权限真相**：

- `personaBlocksPay` 直接复用 `personaBlocksHitlGate(persona, 'pay_unlock')`（`persona.ts:154`），即「代理所不可付款」是通过 HITL 闸间接实现的，**没有独立的财务角色**。
- `payInvoice` 在 `dispatchCommand` 里跑 `evaluatePayUnlock`（`AppContext.tsx:2719`），是真实的中央校验；但 `issueInvoice` **完全没有校验**（`AppContext.tsx:2700`）——任何人可对任何案开票。
- 发票金额是字符串（`amount: string`），无币种、无税额、无精度（§3.2）。

### 2.1 决策权

角色矩阵回答「谁能操作」，不回答「谁说了算」。商务线上每一个数字都对应一笔钱和一个人：**钱可以少收，但必须有人签字；账可以做错，但必须有人认账。**

**四种权能，在本节点必须分开配置**：

| 权能 | 在本节点的含义 | 典型场景 | 系统落点 |
|---|---|---|---|
| 建议权 | 提出价格、账期、减免方案 | 客户经理起草报价；`agent-intake` 起草报价草案 | 报价草稿可被采纳或驳回，驳回须给理由 |
| 决定权 | 拍板商务条件，并对毛利与回款负责 | 代理所负责人定最终价；企业 IP 定预算 | 决议记录 + 决策人签署 + 时间戳 |
| 否决权 | 单方面叫停已定的商务安排 | 财务否决超预算支出、票据不合规的付款 | 一票否决，须书面理由并进入审计 |
| 知情权 | 必须被告知，不参与决策 | 企业业务部门知悉案件成本；代理所财务知悉让价 | 订阅与通知，不阻断流程 |

> **最常见的错误**：把「付款」当成「定价」。付款是执行，定价是决定，两者之间隔着一次审批。把两者合并成一个按钮，等于把毛利交给出纳决定。

**本节点的决策归属**：

| 决策 | 建议权 | 决定权 | 否决权 | 分级与条件 |
|---|---|---|---|---|
| 报价（标准价、无让价） | 客户经理 / Agent 起草 | 代理所商务负责人 | 企业 IP（超出已批预算） | L2；须含金额、范围、有效期、付款节点（R12-01/04/05/06） |
| 折扣 / 让价（阈值内） | 客户经理 | 代理所商务负责人 | 财务（低于成本线 ⚠） | L2；幅度见下表 |
| 折扣 / 让价（超阈值） | 商务负责人 | 上一级（合伙人会议 / 总经理） | 财务 | L3；书面理由 + 双人复核 |
| 费用减免（费减申报 / 服务费减免） | 流程岗 / 客户经理 | 按额度分级（同下表中 L1–L4） | 财务 | **两条线**：费减属官费口径，服务费减免属让价口径，不得互相冲抵 |
| 超预算 / 预算追加 | 企业 IP | 财务 BP + IP 总监 | CFO | L3/L4；先追加后执行（R12-52） |
| 发票开具 | 代理所财务 | 代理所财务负责人 | — | L1；须校验开票信息与合同主体 |
| 发票红冲 / 作废 / 重开 | 原开票人 | 代理所财务负责人 | 企业财务（已认证抵扣时） | L3；受红冲时限约束 ⚠ |
| 付款执行 | 企业 IP（请款） | 企业财务 | — | L2；只执行已确认的商务条件，不改条件 |
| 官费代缴授权 | 代理所流程岗 | 企业 IP（逐笔确认或年度额度内） | 财务 | L3；走代收代付台账（R12-49） |
| 逾期催收（首次 / 升级 / 委外） | 代理所商务 | 商务负责人 | — | L1 → L2 → L3 三档；三个动作分别留痕 |
| 坏账核销 | 商务 + 财务 | 代理所负责人 + 财务负责人会签 | 审计 | **L4**；不可逆，核销不消灭债权 |
| 退款 | 客户经理 | 财务负责人 | 企业（未确认不得退） | L3；已开票的先红冲再退 |

**让价分级（比例与阈值 ⚠ 均为示例，须按代理所授权制度配置，不得硬编码）**：

| 层级 | 让价幅度（占标准价 ⚠） | 批准人 | 留痕 |
|---|---|---|---|
| L1 | ≤ 3% ⚠ | 商务负责人 | 系统记录 + 理由 |
| L2 | 3%–8% ⚠ | 商务负责人 + 财务会签 | 审批流 + 毛利测算 |
| L3 | 8%–15% ⚠ | 总经理 / 合伙人会议 | 双签 + 决议纪要 |
| L4 | > 15% ⚠ | 最高决策层（董事会授权） | 双签 + 决议纪要 + 事后审计 |

> 让价幅度按**单案累计**计算，不按单张发票计算。按票计算就是给拆票留后门。

**四条硬约束**：

**1. 报价与让价分离。** 报价可由业务发起（客户经理，甚至 Agent 起草初稿），但**让价必须单独审批**——谁报的价，不能由谁批自己的让价。报价是「标准价 + 范围 + 有效期 + 付款节点」，让价是「在标准价基础上的减让」，两者是不同对象；不得用一句「按 8 折」覆盖原报价，也不得让让价悄悄改写 `quoteBudget`（§6.5 偏差 6）。

**2. 财务只能执行付款与核销，不能决定商务条件。** 财务持有的是**否决权**（超预算、票据不合规、收款方与合同主体不一致时叫停），不是决定权。财务不得单独决定「这家客户什么价」「这笔账期放到 90 天 ⚠」；反过来，业务也不得代替财务确认「已收款」。

**3. 折扣超过阈值必须上升到上一级。** 阈值是分级线，不是建议线。且**禁止拆分规避**：拆合同、拆发票、拆案件，把一个超阈值让价拆成几个阈值内的让价，与直接超阈值同等处理（R12-45）。

**4. 官费代缴是代收代付，不得与代理费混同。** 官费的所有权不属于代理所，代缴只是**垫付 + 报销**：不进入服务费收入，不参与毛利考核，不适用服务费折扣。官费的减免、垫付、退费走**代收代付台账**（R12-47），与服务费的让价审批**两条线、两个审批人**。客户问「官费为什么不能打折」的正确答案是：官费不是我们的收入，我们无权打折；能谈的只有服务费。

**知情权最小集合**：企业业务部门（案件成本）、企业财务（预算执行与逾期）、代理所负责人（应收与停权）、流程岗（官费缴纳状态）。遗漏知情的典型后果是：客户在收到停权通知时，才知道自己有一张三个月前到期的票。

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | string | ✅ | `inv-*` |

### 3.3 状态枚举

| 枚举 | 取值 | 语义 |
|---|---|---|
| `EngagementPhase` | `接案评估 / 正式委托 / 撰写中 / 审查答复 / 授权维持 / 转化运营 / 监控维权` | 委托的七段生命周期 |
| `PaymentStatus` | `未报价 / 报价待确认 / 已确认待付款 / 部分付款 / 已结清 / 逾期` | 整体付款口径 |
| `InvoiceStatus` | `待开票 / 已开票 / 已付款 / 逾期` | 单张发票 |
| `QuoteDispatchStatus` | `none / intent / quoted / confirmed / assigned` | 报价派单五态 |
| `AgencyIntentStatus` | `intent / ignored / accepted` | 单个代理意向 |
| `FulfillmentMode` | `self_serve / delegated` | 自助 vs 委托 |

### 3.4 `EngagementPhase` 与 `StageId` 不是一回事

| 轴 | 取值 | 谁推进 |
|---|---|---|
| `StageId`（7） | `pre_research / decision / drafting / prosecution / maintenance / commercialization / monitoring` | 业务办理（交接 + 阶段推进） |
| `EngagementPhase`（7） | 接案评估 / 正式委托 / 撰写中 / 审查答复 / 授权维持 / 转化运营 / 监控维权 | 商务动作（报价确认、开票） |

两者**名字相似但语义不同**：`StageId` 说的是"专利办到哪一步"，`EngagementPhase` 说的是"这笔委托走到哪一段"。当前它们由不同代码改（`transitionHandoff` 同时改两者，`AppContext.tsx:1134`），但没有强制一致性约束，会出现"阶段已到答复、委托还停在接案评估"的状态（§11 场景 3）。

### 3.5 四层别混：报价 / 预算 / 发票 / 付款

| 层 | 对象 | 回答什么 | 金额来源 |
|---|---|---|---|
| 报价 | `quoteBudget` + `intake_quote` | 打算收多少 | 人工/Agent 估算 |
| 预算 | `budgetApproved` | 企业批了多少 | 报价确认时锁定 |
| 发票 | `CaseInvoice[]` | 实际开了几张、各多少钱 | 开票动作 |
| 付款 | `PaymentStatus` + 各票 `status` | 收了没有 | `payInvoice` 回写 |

### 4.7 例外情形

规则写「不得」，业务上总有人要问「那这种情况呢」。商务线的例外尤其多，因为**钱的事从来不是纯粹按规则走的**。但例外必须有依据、有批准人、有期限——否则「特批」就成了绕过审批的通用后门。

本节只收**有依据的例外**，不收「客户强烈要求」。

| # | 例外 | 例外条件 | 谁批准 | 风险 | 留痕 |
|---|---|---|---|---|---|
| E1 | 先服务后付费（无预付） | 客户为长期合作方且历史回款记录良好；或合同已约定里程碑付款且首期在服务启动后 ⚠ 30 日内 | 代理所商务负责人 + 财务会签 | 垫付人力与官费，客户中途不认账即为坏账 | 必留：合同付款条款 + 信用评估 + 额度上限 |
| E2 | 政府 / 国企项目回款慢 | 经费来自财政拨付，付款依赖预算下达或验收结算；有立项批文或合同 | 商务负责人（报财务备案） | 账期可能跨年 ⚠；停权会误伤在办的法定动作 | 必留：批文/合同 + 预计回款节点 + 每月对账 |
| E3 | 客户进入破产 / 重整 | 已进入破产受理、重整或清算程序 | 财务负责人 + 法务 | 新增垫付基本无法收回；但停止服务可能构成违约 | 必留：受理裁定 + 债权申报记录 + 停止新增垫付的决议 |
| E4 | 发票开错需重开 | 抬头/税号/金额/品目错误，且已跨月或客户已拒收 | 代理所财务负责人；已抵扣的须企业财务确认 | 超红冲时限则无法更正 ⚠；跨年红冲影响关账 | 必留：错误原因、原票号、红冲票号、重开票号 |
| E5 | 汇率波动导致报价失真 | 外币报价，结算日汇率较报价基准日偏离超约定阈值 ⚠ | 商务负责人（超阈值报上一级） | 单方面调价损害信任；不调则毛利被汇率吃掉 | 必留：报价基准汇率、结算汇率、调整依据 |
| E6 | 跨年预算 | 服务于预算年度内启动、次年完成；客户预算按年下达 | 企业 IP + 财务 BP | 收入确认年度与预算年度错位，次年预算可能未批 | 必留：跨年预算拆分表 + 客户书面确认 |
| E7 | 代理所垫付官费 | 官费缴纳期限临近而客户预付款未到，且不缴将导致权利丧失 | 企业 IP 逐笔确认；年度额度内可批量授权 | 垫付后客户不认账；代收代付台账失真 | 必留：缴费凭证 + 客户确认（书面/系统点击）+ 垫付台账 |
| E8 | 官费涨价，已报价按旧价 | 报价有效期内官方收费标准调整 ⚠ | 商务负责人 | 按旧价收则差额自担；按新价收则违约 | 必留：调价公告 + 报价条款（是否含随行就市） |

**例外不是豁免**：每条例外必须记录**依据、批准人、风险、期限**四项（decision-rights §4.2）。缺任一项视为违规操作。例外只对本案件生效，且必须在 §12 指标中可统计——例外率异常升高，说明规则本身定错了，或者审批人被绕过了。

**两条不能例外的红线**：

| 红线 | 原因 |
|---|---|
| 用让价换「不开票」或「走私账」 | 不是商务安排，是税务违法 |
| 把官费计入服务费收入做毛利 | 代收代付款项不是收入，虚增营业额与税基 |

### 4.8 规则冲突与裁决

商务线的冲突几乎都来自**四个部门的目标不一致**：销售要成单、财务要回款、交付要开工、客户要省钱。不预先给出裁决顺序，执行时就由「谁职级高」或「谁嗓门大」决定。

**六类真实冲突**：

| # | 冲突 | 典型表现 | 裁决 | 裁决人 |
|---|---|---|---|---|
| C1 | 抢单要折扣 vs 价格体系 | 销售为赢单要求超阈值让价，称「这单拿下后面还有量」 | **让价走分级审批，超阈值必须上升**；不得以「先低价报、后续变更」曲线绕过；「后面的量」不得作为本次让价的依据，只能作为下次报价的输入 | 商务负责人；超阈值报总经理/合伙人会议 |
| C2 | 财务要预收 vs 客户要账期 | 财务要求款到开工，客户要求 60–90 日账期 ⚠ | **按客户信用等级分档**：新客户与高风险客户预收；战略客户可给账期，但须设**额度上限 + 到期日 + 担保或对账确认**；不得无额度放账 | 财务负责人 + 商务负责人会签；超额度的报上一级 |
| C3 | 催收伤客户关系 vs 现金流 | 商务不愿催，怕影响续约；财务要求停权 | **催收标准化：提醒 → 对账 → 正式函 → 停权**，逐级升级且全程留痕；停权由规则触发，不由个人判断触发。确有战略价值的可申请豁免，但须 L4 审批并设到期日 | 商务负责人；豁免报 L4 |
| C4 | 两账分离 vs 客户只想收一张发票 | 客户财务系统只接受一张票，要求官费与服务费合并 | **不得合并成一笔，但可以出在一张票上**：同一张发票分行列示（税务口径允许时 ⚠），底层仍保留 `kind` 分类与两套台账；客户只能收一张时，出「汇总发票 + 明细清单」，清单是台账的投影，不是新账 | 代理所财务负责人；口径争议由财税顾问出意见 |
| C5 | 逾期停权 vs 法定期限临近 | 发票未结，但 OA 答复期限 3 天后到期 | **期限优先**（decision-rights §5.1 原则 4）：先递交，**但停权不解除，只是暂缓执行**；同步升级商务与财务，事中留痕，事后追责；不得以「先递了再说」永久绕过停权 | 企业 IP 授权递交，商务负责人知情；暂缓须记录到期时点 |
| C6 | 报价有效期 vs 官费涨价 | 报价 90 天有效 ⚠，期间官费调整 | **服务费按报价锁定，官费按实缴代收**（若报价含随行就市条款）；无该条款时，差额由代理所承担或与客户协商补充确认，**不得单方面按新价开票** | 商务负责人；争议报 L2 |

**裁决顺序（冲突无法自行消解时，自上而下适用）**：

| 序 | 原则 | 含义 | 例外 |
|---|---|---|---|
| 1 | **合规优先** | 发票、税务、代收代付性质不可让渡 | 仅 §4.7 列明且留痕的例外 |
| 2 | **不可逆优先** | 核销、退款、红冲这类动作先于可逆的账务调整 | — |
| 3 | **法定期限优先于内部账期** | 官费期限、答复期限先于内部回款节奏（C5） | 期限已无救济空间时降级 |
| 4 | **合同优先于习惯** | 有合同按合同，无合同按报价单，无报价单按标准价；「一直这么做的」不是依据 | 无书面依据的按标准价执行 |
| 5 | **现金流优先于单案毛利** | 同等条件下先保回款；但不得以牺牲第 1 条为代价 | 战略客户可按 C2 分档 |
| 6 | **书面留痕优先于口头一致** | 任何偏离上述顺序的决定，必须有书面理由与批准人 | — |

> **最重要的一条是 C4**。两账分离不是财务部门的偏好，它由**代收代付的法律性质**决定：官费从来不是代理所的收入。客户要一张发票是合理需求，正确做法是「一张票、两行、两套账」，错误做法是「混成一笔、事后拆分」——后者在客户审计或税务检查时无法还原。

## 5. 法律底座 / 行业规则

### 5.1 两账分离（本节点的第一原则）

**规则（行业基本要求）**：专利代理机构向客户收取的费用通常分为两类——

1. **官费**：由国家知识产权局收取、代理机构**代收代缴**，属代收代付款项，不是代理机构的收入；
2. **代理服务费**：代理机构自有收入。

两者在会计上必须分账（代收款不计收入），在发票上必须分项（代收款项的开票与确认口径不同 ⚠ 具体按当地税务与行业规范）。

**产品落点**：`CaseInvoice` 需要 `kind: 'official' | 'service'` 字段；`amount` 需要数值化；对账要能算「官费实缴 - 官费预估」的差额。

**失效后果**：代收款计入收入会虚增营业额与税基；官费与服费混开一张票，客户无法入账，年费类业务尤其容易被财务打回。

### 5.2 费用减缴（费减）

**规则**：《专利收费减缴办法》（财税〔2016〕78 号）规定，符合条件的申请人可减缴**申请费（不含公布印刷费、申请附加费）、发明专利申请实质审查费、年费（自授权当年起 6 年内）、复审费**。减缴比例为：单个个人或单个单位减缴 **85%**；两个及以上个人/单位为共同申请人或共有专利权人的减缴 **70%**。（⚠ 2018 年及 2024 年有进一步调整，**必须以当期有效文本为准**。）

资格门槛（⚠ 需复核）：个人上年度月均收入低于 5000 元（年 6 万元）；企业上年度应纳税所得额低于 100 万元。须先完成费减备案。

**产品落点**：年费日历（11）与发票（12）都需 `feeReduction: 85 | 70 | none` 字段；官费预估必须按减缴后金额出，否则客户按全额预算、实缴时产生差额争议。

**失效后果**：按全额报价 → 客户实际缴费远低于预算，产生退款与信任损失；反之漏报减缴资格 → 客户多付 7 倍年费。

> ⚠ **本文不写死"70%/85% 对应哪类主体"的最终结论**：两档比例在财税〔2016〕78 号中的表述是「单个/多个」，与"单位/个人"的对应关系在不同资料中表述不一，且 2018、2024 年有调整。部署前必须按当期 CNIPA 公告复核，并在产品里做成**可配置的比例表**而非硬编码。

### 5.3 年费代缴的委托性质

**规则（行业惯例）**：年费代缴是典型的代收代付 + 服务费混合业务：官费按件代缴，服务费按件或按年收取；逾期产生的滞纳金属客户责任，但代缴方若未及时提醒可能承担合同责任 ⚠。

**产品落点**：`maintain_annuity` 交接的两项（年费计划 + 官费/服务费确认）正是这个结构；`pay_unlock` 闸把「付款」与「代缴」分开。

**失效后果**：代缴方垫付后客户不认账——没有"客户已确认缴费"的留痕就是坏账。

### 5.4 发票合规

**规则（行业惯例 + 税务规定 ⚠）**：发票抬头、税号、开户行等必须与合同主体一致；跨期开票、红冲、作废都有时限要求；专票与普票的抵扣资格不同。

**产品落点**：当前无开票信息对象（§14 差距 6）。真实产品必须有 `BillingProfile`（抬头/税号/地址/开户行）与 `contractId`。

**失效后果**：抬头错误 → 客户无法抵扣 → 退票重开 → 跨月红冲 → 财务关账失败。

### 5.5 催收与诉讼时效

**规则（民法典 ⚠ 条号需核）**：普通诉讼时效期间为三年，自权利人知道或应当知道权利受损害之日起算。应收账款的催收记录（函件、对账确认）是时效中断的证据。

**产品落点**：逾期台账需保留「催收动作」记录（谁在何时以何方式催过），当前**完全没有**。

**失效后果**：三年后无法主张；即便起诉也因无催收证据败诉。

### 5.6 跨境支付与税务（涉外场景）

**规则**：向境外代理所支付费用涉及服务贸易付汇、代扣代缴增值税/所得税、税收协定优惠适用等 ⚠ 具体规则按外汇管理与税务规定。PCT/巴黎公约路径必然涉及。

**产品落点**：当前无币种、无汇率、无税务字段。

**失效后果**：无法合规付汇；代扣代缴遗漏会被追缴并罚款。

## 6. 状态机

### 6.1 报价派单（`QuoteDispatchStatus`）

```
none ──代理提交意向──► intent ──(出报价)──► quoted ──(企业确认)──► confirmed ──(派单)──► assigned
                          │                                                              ▲
                          └──────────────── 企业接受意向（当前直接跳）───────────────────┘
```

**现状**：`quoted` 与 `confirmed` 两态**没有任何写入点**——`submitAgencyIntent` 只写 `intent`，`acceptAgencyIntent` 直接写 `assigned`（`AppContext.tsx:1915` / `:1989`）。五态实际用成三态。

### 6.2 发票

```
待开票 ──issueInvoice──► 已开票 ──payInvoice──► 已付款
   │                        │
   └──── 逾期（应自动）◄────┘
              │
              └──payInvoice──► 已付款
```

**现状**：`逾期` 无自动流转（R12-22）；`已付款 → 逾期` 也无守卫（R12-21）。

### 6.3 委托阶段（`EngagementPhase`）

```
接案评估 ──报价确认──► 正式委托 ──撰写开始──► 撰写中 ──OA──► 审查答复 ──授权──► 授权维持 ──► 转化运营
                                                                                        └──► 监控维权
```

**现状**：只有 `intake_quote` 的 submit/approve 会改 `phase`（`AppContext.tsx:1140` / `:1166`），其余阶段靠 seed 或 Flow 各自 `updateEngagement`，**没有统一推进器**。

### 6.4 迁移表

| 对象 | 当前 | 可迁往 | 谁做 | 出口条件 |
|---|---|---|---|---|
| 派单 | `none` | `intent` | 代理 | 提交意向 |
| 派单 | `intent` | `assigned` | 企业 | 接受意向（跳过两态） |
| 发票 | `待开票` | `已开票` | 代理/财务 | 开票 |
| 发票 | `已开票` | `已付款` | 企业 | 付款 |
| 发票 | `已开票` | `逾期` | 系统 | `due < today` |
| 发票 | `逾期` | `已付款` | 企业 | 付款 |
| 付款 | `报价待确认` | `已确认待付款` | 企业 | 报价批准 |
| 付款 | `已确认待付款` | `部分付款` | 系统 | 部分票已付 |
| 付款 | `已确认待付款` / `部分付款` | `已结清` | 系统 | 全部票已付 |

### 6.5 当前实现的偏差

1. `quoted` / `confirmed` 无写入点（§6.1）。
2. `逾期` 不自动置位。
3. `已付款` 状态可被 `updateInvoiceStatus` 任意覆盖，无守卫。
4. `EngagementPhase` 与 `StageId` 无一致性约束。
5. `PaymentStatus` 与发票状态**双写**：`updateInvoiceStatus` 会重算 `paymentStatus`，但 Flow 里也有直接 `updateEngagement({paymentStatus})` 的路径（如 `IntakeFlow.tsx:510`），两条写路径可能打架。
6. `acceptAgencyIntent` 修改 `quoteBudget` 为意向报价，可能覆盖已确认的预算（`AppContext.tsx:1993`）。

## 8. 步骤序列 / 工作流

### 8.1 委托模式（`delegated`）主流程

| # | 步骤 | 谁做 | 耗时 | 产出 | 失败回退 |
|---|---|---|---|---|---|
| 1 | 代理提交接案意向 | 代理 | — | `AgencyIntent(intent)` + 派单态 `intent` | 企业忽略 |
| 2 | 企业接受意向 | 企业 IP | ⚠ 建议 2 工作日 | `assigned` + `delegated` + 待开票 | 拒绝 → `ignored` |
| 3 | 代理提交报价（金额 + 范围） | 代理 | ⚠ 3 工作日 | `intake_quote(submitted)` + `报价待确认` | 退回 → 重报 |
| 4 | 企业确认报价 | 企业 IP | ⚠ 3 工作日 | `approved` + `已确认待付款` + 正式委托 + 自动开「接案报价确认」票 | 退回 |
| 5 | 服务过程中开票 | 代理/财务 | — | `CaseInvoice(已开票)` | 开票信息错 → 退票 |
| 6 | 企业付款 | 企业财务 | ⚠ 账期 15–30 日 | `已付款` + 重算 `paymentStatus` | 逾期 → 停权 |
| 7 | 结清 | 系统 | — | `已结清` | — |

### 8.2 自助模式（`self_serve`）

无代理所，`quoteBudget` 由内部预算替代；立项 Go 要求填预算（`IntakeFlow.tsx:205`），不走报价确认。发票可能只有官费。

### 8.3 年费代缴子流程

`maintain_annuity` 交接 → `pay_unlock` 回写 docket → 代缴完成归档。三步缺一不可，当前「付款」与「回写 docket」没有直接挂钩（只有 `file` 归档回写）。

## 10. 期限与 SLA

### 10.1 硬期限

| 期限 | 长度 | 起算 | 后果 |
|---|---|---|---|
| 官费缴费期限 | 见 11 规则表（申请费 2 个月 / 实审 36 个月 / 年费 12 个月 + 6 个月宽限 ⚠） | 见 11 | 视为撤回 / 终止 |

## 11. 边界与失败场景

| # | 场景 | 正确处置 | 现状 |
|---|---|---|---|
| 1 | 客户要求「官费和服务费开一张票」 | 拆两行（代收/自营），说明口径 | ❌ 无分类字段 |

| 4 | 发票抬头写错，跨月才发现 | 红冲重开流程 | ❌ 无红冲 |
| 5 | 阶段已到答复，委托还停在接案评估 | 一致性校验 | ❌ 无 |
| 6 | 逾期发票，代理仍把稿子交了 | 停权硬挡 | ✅ |
| 7 | 停权被关掉后无人察觉 | 开关变更需审计 + 高危提示 | ⚠ 无审计 |
| 8 | 企业换代理所，旧所发票未结 | 委托终止 + 应收转移 | ❌ 无退出流程 |
| 9 | 两家代理所同时报价 | 比价视图 + 选择理由留痕 | ⚠ 有意向列表，无比价与理由 |
| 10 | 企业采购要求看历史成交价 | 报价历史库 | ❌ |
| 11 | 官费涨价，已报价按旧价 | 报价有效期 + 官费随行就市条款 | ❌ |
| 12 | 客户申请了费减但系统按全额开票 | 减缴字段贯通到发票 | ❌ |
| 13 | 涉外付款需代扣代缴 | 税务字段与凭证 | ❌ |
| 14 | 客户要求开票金额与合同不一致 | 合同对象 + 差异审批 | ❌ |
| 15 | 三年前的老账要起诉 | 催收记录 + 对账确认 | ❌ |
| 16 | 同一案重复开票 | 幂等键（案 + 服务 + 期间） | ⚠ 仅一处去重 |

## 12. 指标（验收尺子）

| 指标 | 定义 | 健康区间 | 说明 |
|---|---|---|---|
| 报价确认周期 | 报价提交 → 企业确认中位数 | < 3 工作日 | 直接影响开工 |
| 报价转化率 | 确认报价数 / 提交报价数 | 60%–85% | 过低说明报价脱离市场 |
| 平均账期（DSO） | 开票到收款天数 | < 45 日 | **直接换算成现金流** |
| 逾期率 | 逾期发票金额 / 应收总额 | < 5% | |
| 停权触发率 | 因逾期被停的案数 / 在办案数 | < 3% | 高说明前端信用审核有问题 |
| 官费对账差异率 | \|实缴 − 预估\| / 预估 | < 2% | 反映 docket 与报价的准确性 |
| 退票重开率 | 因开票信息错误重开的比例 | < 2% | 反映开票信息校验 |
| 费减覆盖率 | 符合条件并实际减缴的案件比例 | > 90% | **能直接省客户的钱** |
| 单案商务处理时长 | 从意向到结清的总人天 | 越低越好 | |

> 能换算成钱的：**DSO**（每缩短 10 天，等于释放约 1/36 的年应收占用）、**逾期率 × 应收**、**费减覆盖率 × 官费**。

## 13. 产品化切分建议

| 层 | 内容 | 是否可独立交付 |
|---|---|---|
| L1 台账层 | 案件发票列表 + 状态 | 是（最低配） |
| L2 双账层 | 官费/服务费分类 + 减缴 | 是（财务刚需，差异化） |
| L3 报价层 | 报价单 + 范围 + 有效期 + 版本 | 是（代理所销售用） |
| L4 派单层 | 意向 + 比价 + 派单 | 是（企业采购用） |
| L5 停权层 | 逾期自动停递交 + 通知 | 是（代理所现金流工具） |
| L6 对账层 | 官费实缴 vs 预估 vs docket | 是（财务 + 流程双用） |

**定价锚点**：按「应收金额的百分比」不现实（客户抗拒），更可行的是按「在办案件数 × 月」或「发票张数」。

**竞品参照系**：CPA Global / Anaqua 的 billing 模块强在**多币种与跨境**，弱在中国官费与减缴；国内案管系统强在开票，弱在**停权联动与对账**。**「中国官费口径 + 停权联动」是空位。**

## 14. 现状差距表

| # | 差距 | 严重度 | 影响 |
|---|---|---|---|
| 1 | `amount` 是字符串，无法求和/对账 | **高** | 整个模块无法做财务计算 |
| 2 | 无官费/服务费分类（两账未分离） | **高** | 合规风险 + 客户无法入账 |
| 3 | 无费减字段（85%/70%） | **高** | 报价与实缴系统性偏差 |
| 4 | 发票与 docket 无对象级关联 | **高** | 官费对账不可做 |
| 5 | 逾期判定两套口径（`status` vs `due`） | **高** | 同一张票在不同页面不同结论 |
| 6 | 无开票信息对象（抬头/税号） | 中 | 退票重开 |
| 7 | 无合同对象 | **高** | 发票无法对应合同，诉讼无据 |
| 8 | `intake_quote` 同时承载决策与商务 | 中 | 两条线互相污染 |
| 9 | `quoted` / `confirmed` 无写入点 | 中 | 五态退化为三态 |
| 10 | `issueInvoice` 无权限校验 | **高** | 任意角色可开票 |
| 11 | 无部分付款金额模型 | 中 | 无法核销 |
| 12 | 无红冲/作废 | 中 | 错票无法纠正 |
| 13 | 无催收记录 | **高** | 诉讼时效无证据 |
| 14 | 无币种/汇率/税务 | 中 | 涉外不可用 |
| 15 | `EngagementPhase` 与 `StageId` 无一致性约束 | 中 | 视图自相矛盾 |
| 16 | 停权开关变更无审计 | 中 | 高危操作无痕 |
| 17 | `acceptAgencyIntent` 可覆盖已确认预算 | 中 | 预算被意向价冲掉 |

**优先补的三件事**：

1. **金额数值化 + 两账分类**（差距 1、2）——一次数据结构改动，解锁对账、统计、减缴全部下游能力。
2. **费减贯通**（差距 3）——直接影响客户成本感知，是最好卖的点。
3. **发票 ↔ docket 关联 + 统一逾期口径**（差距 4、5）——让"官费缴了没"这个问题只在一个地方回答。

## 15. 术语表

| 术语 | 含义 |
|---|---|
| 官费 | 由国家知识产权局收取的费用，代理机构代收代缴 |
| 代理服务费 | 代理机构的自有收入 |
| 两账分离 | 官费与服费分账、分票、分核算 |
| 费减 | 专利收费减缴，符合条件的主体按比例少缴 ⚠ |
| 报价（quote） | 对某一委托范围的价格提案，有金额与范围 |

| 派单 | 企业选择承接代理所的过程（`QuoteDispatchStatus`） |
| 停权 | 因逾期发票而阻断代理递交动作的机制 |
| 账期 / DSO | 开票到收款的天数，衡量现金流 |
| 红冲 | 对错误发票的冲销更正 |
| 代收代付 | 代理机构代客户向官方缴款，不构成收入 |
