# 节点 01b · FTO 自由实施分析（Freedom to Operate）

> **本节点在原型里只是 [01 检索](01-research.md) 下的一个 5 项子勾选（`fto`），外加一个独立的壳（`apps/fto` :5183）。本文把它当作独立业务来梳理。**
> 关联：[01 检索](01-research.md)（可专利性检索，方向相反）· [03 撰写](03-drafting.md)（规避设计回流）· [24 诉讼](24-litigation.md)（FTO 是诉讼中的抗辩证据）· [07 监控](07-monitoring.md)（持续 FTO）
>
> 法律口径：《专利法》（2020 修正）第 11 条、第 34 条、第 71 条；《专利审查指南》。凡条号、期限、金额标 ⚠ 需按当期文本复核。

## 0. 一句话讲清这个节点

**FTO 回答一个商业问题：我这个产品，在这个国家，现在卖，会不会踩到别人仍然有效的权利要求？**

它和可专利性检索用的是同一批数据库，但**问的问题完全相反**：

| | 可专利性检索（01） | FTO（本文） |
|---|---|---|
| 问什么 | 我的方案**新不新** | 我实施会不会**侵权** |
| 找什么 | 任何已公开的技术（论文、展会、销售都算） | 目标市场内、**仍然有效**的**权利要求** |
| 时间基准 | 申请日 / 优先权日 | **实施日**（且结论会过期） |
| 结论 | 可申请 / 不可申请 | 可实施 / 需规避 / 需许可 / 高风险 |
| 谁看 | 研发 + IPR | 业务 + 法务 + 管理层 |
| 做错的后果 | 白花钱，或漏掉资产 | 被诉、赔偿、禁令、被迫改设计 |

**这一条是整篇的地基**：同一个专利，对可专利性检索是「现有技术」，对 FTO 可能完全不是障碍——因为它在你目标市场已经失效，或者根本没进入那个国家。

### 0.1 产品化三条件

1. **有独立买方**：法务部（防被诉）、业务部（能不能上市）、投资方（尽调）。三者的预算科目都和 IP 部门不同。
2. **有独立价值**：见 §5.2——FTO 不只能防侵权，还能**阻却惩罚性赔偿**。这是它最被低估、也最能支撑溢价的价值。
3. **有独立边界**：输入是「产品技术方案 + 目标市场」，输出是「风险结论 + 规避建议」。不依赖撰写、审查、年费任何模块。

> 讲给实习生的一句话：**可专利性检索是「我能不能圈地」，FTO 是「我会不会踩到别人圈的地」。**

## 1. 节点定位与产品边界

### 1.1 在生命周期中的位置

```
研发方案 ──┬──► 01 可专利性检索 ──► 02 立项 ──► 03 撰写 ──► 04 审查 ──► 授权
           │                                                          │
           └──► 【01b FTO】──► 上市决策 ──► 销售 ──────────────────────┤
                     ▲                    │                           │
                     │                    └──► 07 监控（发现侵权）      │
                     │                                                  │
                     ├── 新产品 / 新市场 / 技术变更 → 重跑              │
                     ├── 规避设计 → 回流 03（可能产生新专利点）          │
                     └── 被诉 → 24 诉讼（FTO 报告作为非故意抗辩证据）────┘
```

**关键结构认知**：FTO 不在主阶段轴上，它是**产品生命周期驱动的**，不是专利生命周期驱动的。产品要上市就做 FTO，跟专利走到哪一步无关。

### 1.2 它是 / 不是

| 是 | 不是 |
|---|---|
| 针对**具体产品 + 具体市场**的侵权风险评估 | 泛泛的「技术领域专利分析」 |
| 以**权利要求**为比对对象 | 以摘要、标题、技术方案为比对对象 |
| 输出**可执行的处置建议**（规避/许可/放弃） | 只输出一个风险等级 |
| 商业决策依据 | 法律意见书（除非由律所出具且明确担责） |
| 一次性交付 | 一劳永逸（结论有保鲜期） |

### 1.3 FTO 与「专利预警」的区别（常被混为一谈）

| | FTO | 专利预警 |
|---|---|---|
| 粒度 | 微观：某个产品的某个特征 | 宏观：某个技术方向 |
| 时机 | 上市前 | 研发早期 |
| 对象 | 有效权利要求 | 申请趋势、技术分布、主要玩家 |
| 输出 | 能不能卖、怎么改 | 该往哪投、谁在领先 |
| 谁做 | 专利律师 / 代理师 | 情报 / 战略 |

**产品含义**：这两件事应该做成两个产品，不能合并。合并的结果是两边都不好用。

### 1.4 独立产品的形态

**产品名建议：FTO 工作台 / Freedom-to-Operate Desk**

| 模块 | 能力 | 谁用 |
|---|---|---|
| 产品特征拆解 | 把产品拆成可比对的技术特征 | 产品经理 + 专利师 |
| 目标市场配置 | 按国家/地区分别建检索范围 | 法务 |
| 障碍专利检索 | 按市场 + 法律状态过滤 | 检索员 |
| 权利要求比对 | 逐特征 × 逐权项的对照表 | 专利师 |
| 风险分级 | 按专利/按特征/全局 | 专利师 |
| **规避设计建议** | 改哪个特征能跳出权利要求 | 专利师 + 研发 |
| 报告与免责 | 结构化报告 + 检索局限声明 | 法务 |
| 保鲜与重跑 | 到期提醒、新品/新市场触发 | 系统 |

**不做的**：不做可专利性结论（01）、不做侵权诉讼代理（24）、不做专利预警（战略层）。

## 2. 角色与权限矩阵

| 角色 | 能做什么 | 不能做什么 |
|---|---|---|
| 产品经理 | 提供产品特征、确认上市计划 | 不能判定侵权 |
| 企业 IPR | 拆解特征、初步检索、组织比对 | 不能出具法律意见（除非有资质） |
| 专利律师 / 代理师 | 权利要求解释、比对结论、规避建议 | 不替客户决定是否上市 |
| 法务 | 评估诉讼风险、决定是否取得许可 | 不做技术比对 |
| 业务负责人 | 决定「改设计 / 买许可 / 放弃市场」 | 不参与技术判断 |
| 投资方（尽调场景） | 审阅报告 | 不参与制作 |
| 系统 | 检索、去重、同族折叠、状态过滤、保鲜提醒 | 不能自动下侵权结论 |

> **角色设计的关键**：FTO 是**技术判断 + 商业决策**的分离。技术人员说「覆不覆盖」，业务人员说「值不值得改」。产品必须把这两件事分开，否则会变成技术部门替业务部门做决定。

### 2.1 决策权

上面的矩阵回答「谁能做什么」，不回答「谁说了算」。FTO 有一处与其他专利节点**根本不同**的治理结构，必须先讲清：

> **FTO 的买方是法务，不是 IP 部门。** 可专利性检索（01）的预算、结论、验收都在 IP 体系内闭环；FTO 的预算在法务，风险承受方在业务，报告的使用者在诉讼与尽调。三者不是一条汇报线。把 FTO 塞进 IP 部门的审批流，会出现「IP 写了报告、业务没看、法务不知情、上市照旧」——这是 FTO 最典型的失效方式。

**四条决策链，分别归属**

| 决策链 | 问题 | 主导 | 系统落点 |
|---|---|---|---|
| 技术链 | 覆不覆盖、怎么改 | 专利师 / 代理师 | 比对表 + 规避方案（可专业决定） |
| 法律链 | 风险多高、能不能说、怎么说 | 法务 | 风险定级 + 对外口径批准 |
| 商业链 | 改不改、买不买、卖不卖 | 业务负责人 | 上市决议（不可替代） |
| 合规链 | 明知风险仍上市时的责任归属 | 法务 + 公司治理层 | 书面风险提示 + 签字承担 |

**决策归属**

| 决策 | 建议者 | 决定者 | 否决者 | 级别 | 依据 / 条件 |
|---|---|---|---|---|---|
| 是否做 FTO | 法务（上市计划驱动） | 业务负责人 + 法务会签 | 法务（强制场景） | L2 | 触发条件见下表；新产品、新市场、被诉后强制 |
| 目标市场清单 | 业务（销售计划） | 业务负责人 | 法务（覆盖不足时） | L2 | 制造地 + 销售地 + 参展地 + 客户所在地 |
| 检索范围与截止日 | 专利师 | 法务 | — | L1 | 写入 `scope`，是免责基础（R1B-30） |
| 产品特征拆解 | 产品经理 + 专利师 | 专利师（技术口径） | — | L1 | 特征须具体到可比对；业务不得删减特征 |
| 比对结论 | 专利师 | 专利师（签署） | 法务（可要求复核） | L2 | 逐要素 + 指明权项号；不得由业务改判 |
| 风险等级 | 专利师 | 法务确认 | — | L2 | 五级可处置性；取最严单件（R1B-24） |
| 规避方案：技术路径 | 专利师 + 研发 | 研发负责人（可行性） | — | L2 | 改哪个特征、改到什么程度 |
| 规避方案：是否值得改 | 研发、法务 | 业务负责人 | 财务（成本超限） | L3 | 改设计成本 vs 市场收益 |
| 是否取得许可 | 法务、专利师 | 业务负责人 + 法务会签 | 财务 | **L4** | 涉及长期付款义务与市场准入 |
| 报告能否对外 | 法务 | 法务（唯一有权） | — | L3 | 投资方 / 客户 / OEM 场景见 E4 |
| 发现障碍是否继续上市 | 法务（书面风险提示） | **业务负责人签字承担** | 法务（红线情形除外） | **L4** | 见下方专表 |
| 是否停止销售 / 召回 | 法务 | 总经理 / 董事会 | — | **L4** | 不可逆，涉商业与法律责任 |

**强制做 FTO 的触发条件**（不做须书面说明）

| # | 触发 | 典型场景 |
|---|---|---|
| 1 | 新产品首次上市 | 任何进入量产的产品 |
| 2 | 进入新国家 / 地区 | 出口、跨境电商、海外展会 |
| 3 | 收到警告函或被诉 | 立即复核（R1B-43） |
| 4 | 核心技术方案变更 | 改设计后须重评（R1B-41） |
| 5 | 投融资 / 并购尽调 | 投资方要求 |
| 6 | OEM / 客户合同要求 | 客户要求提供 FTO 或不侵权声明 |

**「发现障碍仍上市」——本节点唯一的 L4 风险决策**

这是全套专利节点里**唯一一个「明知不可为而为之」需要建模的决策**。它本身不违法，但会产生两个后果：一是侵权责任，二是把 FTO 报告从「免责证据」变成「故意证据」（§5.6 的反例）。

| 步 | 要求 | 谁 |
|---|---|---|
| 1 | 法务出具**书面风险提示**：涉及哪件专利、哪条权项、落入概率、赔偿敞口估算 | 法务 |
| 2 | 说明为何不规避、不取得许可、不退出市场（商业理由，不得写「业务要求」了事） | 业务 |
| 3 | 业务负责人**签字承担**，载明「已知悉法律风险并决定继续」 | 业务负责人 |
| 4 | 法务保留一票否决：涉及禁令高风险、核心产品、或已收到警告函的情形 | 法务 |
| 5 | 决议进审计清单，报告封面打「已发现障碍，业务决定继续」标记 | 系统 |

> **禁止的做法**：把「已发现障碍」从报告里删掉、把风险等级调低、或另出一份「干净版」报告给客户。这不是风险控制，是销毁证据——而且下一份报告与这一份的矛盾本身就是证据。

**预算与授权**（金额示意 ⚠，按企业制度配置）

| 级别 | 单项目预算 | 批准人 | 典型情形 |
|---|---|---|---|
| L1 | ≤ 5 万元 ⚠ | 法务经理 | 单市场、单产品、无高价值障碍 |
| L2 | 5–20 万元 ⚠ | 法务负责人 | 3 国以内、含规避建议 |
| L3 | 20–50 万元 ⚠ | 法务总 + 财务 BP | 5 国以上、多产品线、含许可评估 |
| L4 | > 50 万元，或涉及许可谈判 ⚠ | 总经理 / 授权代表 | 全球布局、OEM 合同、诉讼联动 |

**决策权规则**

| ID | 规则 | 现状 |
|---|---|---|
| R1B-50 | FTO 的立项由业务上市计划驱动，法务与业务会签；IP 部门不得单独决定做或不做 | ❌ |
| R1B-51 | 目标市场由业务提出、法务确认覆盖完整性；制造地、销售地、参展地至少三者齐全 | ❌ |
| R1B-52 | 比对结论与风险等级由专利师签署、法务确认；业务方不得修改等级或结论 | ❌ |
| R1B-53 | 规避方案的技术路径由专利师与研发共同定；是否采纳（改不改）由业务负责人按成本收益决定 | ❌ |
| R1B-54 | 是否取得许可属 L4，须业务负责人 + 法务会签，财务对长期付款义务有否决权 | ❌ |
| R1B-55 | 报告对外提供须法务批准；对外版本不得包含未脱敏的客户信息、成本、内部风险评级理由 | ❌ |
| R1B-56 | 「发现障碍仍上市」须法务书面风险提示 + 业务负责人签字承担 + 系统标记，缺任一项不得发布上市决议 | ❌ |
| R1B-57 | 已收到警告函或被诉的情形，法务对「继续上市」有一票否决权 | ❌ |
| R1B-58 | 报告删除、调低等级、另出「干净版」属禁止行为，系统须保留全部版本与差异 | ❌ |
| R1B-59 | 客户（OEM）要求提供 FTO 时，由法务决定提供范围与形式，业务不得自行承诺「不侵权」 | ❌ |

### 3.1 `FtoProject`（FTO 项目）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | string | 系统 | |

| `searchDate` | string | ✅ | 检索截止日（**保鲜期起算**） |
| `freshnessUntil` | string | 系统 | 结论有效期 |
| `report` | `FtoReport` | — | 报告 |

### 3.2 `ProductFeature`（产品特征）

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | |
| `name` | string | 特征名 |
| `description` | string | 技术描述（要具体到可比对的程度） |
| `isEssential` | boolean | 是否为核心特征（决定规避难度） |
| `alternatives` | string[] | 已知替代方案（规避设计的原料） |

**关键区别**：这里拆的是**产品的技术特征**，不是权利要求的特征。两者的关系在 §6 的比对逻辑里。

### 3.3 `ObstaclePatent`（障碍专利）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `pubNo` | string | ✅ | 公开号 |
| `title` | string | ✅ | |
| `assignee` | string | ✅ | 权利人 |
| `jurisdiction` | string | ✅ | 授权/申请国（**必须落在目标市场内**） |
| `legalStatus` | `'granted' \| 'pending' \| 'expired' \| 'invalidated' \| 'not_entered'` | ✅ | **决定是否构成障碍** |
| `expiryDate` | string? | 条件 | 有效期届满日 |
| `familyId` | string | — | 同族（**必须折叠，否则重复计数**） |
| `claims` | `Claim[]` | ✅ | 权利要求全文（**没有权项就无法做 FTO**） |
| `prosecutionHistory` | string? | — | 审查档案（判断禁止反悔必需） |

**核心规则**：`legalStatus` 不是 `granted` 或 `pending` 的，**一律不是障碍**。这条过滤是 FTO 与可专利性检索最本质的差别。

### 3.4 `ClaimChart`（权利要求比对表 · 共享对象）

**本对象已统一为共享规格，见 [25-claim-chart.md](25-claim-chart.md)。** FTO 使用其中 `purpose: 'fto'` 的一种配置：

| 字段 | FTO 用途下的取值/要求 |
|---|---|
| `purpose` | `'fto'` |
| `targetClaim` | 障碍专利的**具体权项全文**；`jurisdiction` **必填**（权项只在授权国有效） |
| `subject` | `{ kind: 'own_product', projectId, productVersion, features }` |
| `elements` | 逐要素；`match ∈ {identical, equivalent, absent, different, unresolved}` |
| `verdict` | **由 elements 推导**，不可手填（缺任一要素即 `not_covered`） |
| `basis` | 结论依赖等同时必填 `'equivalent'` |
| `designAround` | **`not_covered` 时必填**——FTO 要告诉客户怎么改，不是只说侵不侵权 |

> 早期版本在本文里定义的 `ClaimComparison` / `ElementMatch`（`present/absent/different`）与诉讼侧枚举不一致，已合并。**以 [25](25-claim-chart.md) 为准。**

### 3.5 `FtoRisk`（风险等级）

不是简单的低/中/高。业务上必须区分**可处置性**：

| 等级 | 含义 | 处置 |
|---|---|---|
| `clear` | 未发现有效障碍 | 可上市，记录检索范围 |
| `design_around` | 有障碍但可改 | 改设计后重评 |
| `license_needed` | 有障碍且难规避 | 谈判许可 |
| `high_risk` | 有强障碍且无法规避 | 放弃该市场 / 承担风险上市 |
| `undetermined` | 信息不足（如权项未公开、译文缺失） | 补检索 |

> **注意**：原型的 `low/medium/high/unclear` 是纯等级，没有「可处置性」，导致报告出来后业务方不知道下一步做什么。

### 3.6 `FtoReport`（报告）

| 字段 | 类型 | 说明 |
|---|---|---|
| `scope` | `{ markets, dateRange, databases, searchDate }` | **检索范围声明（最重要的免责基础）** |
| `limitations` | string[] | 局限性声明（见 §5.4 公开盲区） |
| `conclusion` | `FtoRisk` | |
| `perPatent` | `{ hitId, claimNo, verdict, action }[]` | 逐件结论 |
| `disclaimer` | string | 非法律意见声明 |
| `preparedBy` / `reviewedBy` | string | 制作人 / 复核人（**抗辩时需要**） |

### 4.6 例外情形

FTO 的例外比可专利性检索更危险，因为**每一次压缩范围都会削弱报告的抗辩价值**。做了半套的 FTO，在诉讼中可能比没做更糟——它证明你查过、也证明你没查全。因此本节所有例外都必须带「报告还能不能用作抗辩证据」这个判断。

| # | 例外 | 例外条件 | 谁批准 | 风险 | 留痕要求 |
|---|---|---|---|---|---|
| E1 | 上市在即，来不及做完整 FTO | 距上市日不足 2 周 ⚠，且产品已在量产 / 已接单 | 业务负责人 + 法务会签 | 报告不能覆盖全部市场与全部权项，抗辩力显著下降 | 必留：上市日证据 + 已覆盖范围 + 未覆盖清单 + 「加急版」标记 + 上市后 30 天内补做承诺 ⚠ |
| E2 | 目标市场过多，需分级 | 市场数 > 5 个 ⚠，或预算不足以覆盖全部 | 法务 + 业务会签 | 未覆盖市场存在完全未知的风险敞口 | 必留：分级依据（销量 / 制造地 / 对手活跃度）+ 各市场完成时序 |
| E3 | 关键权项拿不到全文 | 审中未公开、目标国官方库不全、译文缺失、仅能取得摘要 | 专利师 + 法务知情 | 无法做逐要素比对，结论只能到 `undetermined` | 必留：获取尝试记录（库 + 日期）+ 缺失原因 + 后续监控计划 |
| E4 | 客户（OEM）要求提供 FTO | 合同条款要求，或客户尽调需要 | 法务 | 对外版本可能被客户转交第三方，形成事实上的公开 | 必留：客户请求书面件 + 提供范围审批 + 脱敏记录 + 版本编号 |
| E5 | 发现障碍但可快速规避 | 改一个非核心特征即可跳出，且不影响上市时间 | 专利师 + 研发确认 | 规避未验证即上市，等同未做（R1B-22） | 必留：改前 / 改后方案对比 + 重新比对表 + 变更后的产品版本号 |
| E6 | 报告过期仍被要求沿用 | 未发生技术变更、未进入新市场、且距检索日不超过 18 个月 ⚠ | 法务（不得由业务批） | 这期间新公开的申请完全不可见；沿用等于用旧地图走新路 | 必留：沿用理由 + 增量检索（至少覆盖新增公开）+ 新有效期 + 报告加注「沿用」 |

**E1「加急版 FTO」的最低可接受标准**（否则不如不做）

| 项 | 必须做到 | 做不到则 |
|---|---|---|
| 市场 | 至少覆盖制造地 + 最大销售地 | 不得出具报告，只能出「检索备忘」 |
| 权项 | 主要竞争对手的授权权项已逐要素比对 | 结论只能到 `undetermined` |
| 范围声明 | 明写「未覆盖市场」「未比对的权项」 | 报告不得标注为 FTO 报告 |
| 复核 | 至少一名复核人签署 | 不得对外提供 |
| 补救 | 上市后补做完整 FTO 的时点与责任人 | 不得发布 |

**E6「沿用」的时间边界（最容易被当作免费续期）**

| 情形 | 可否沿用 | 说明 |
|---|---|---|
| 产品、市场、技术方案三者均未变，且 ≤ 12 个月 ⚠ | 可沿用，须补增量检索 | 标准路径 |
| 12–18 个月 ⚠，其余条件不变 | 可沿用，但须完整增量检索 + 重新签署 | 风险上升 |
| > 18 个月 ⚠ | **不可沿用**，必须重跑 | 已跨越一个完整的 18 个月公开周期 |
| 任一要素变化（产品 / 市场 / 方案） | **不可沿用**，必须重跑 | R1B-41、R1B-42 |
| 期间收到警告函或被诉 | **不可沿用**，立即复核 | R1B-43 |

> **例外不是豁免**：每条例外记录批准人、时间、理由、有效期，只对本项目生效。特别提示：**E1 与 E6 都是「用时间换风险」，批准人必须是能承担该风险的人（业务负责人 / 法务），不能是执行层的专利师或检索员**。

### 4.7 规则冲突与裁决

FTO 的冲突比一般节点尖锐，因为它同时挂着**上市时间**和**法律风险**两个不可让渡的东西，而这两件事的责任人不是同一人。

**五类真实冲突**

| # | 冲突 | 典型表现 | 裁决 | 裁决人 |
|---|---|---|---|---|
| C1 | 上市时间 vs FTO 完整性 | 市场窗口已定，检索只做了两个国家 | **分级覆盖 + 明示未覆盖范围**（E1/E2），不得用「已做 FTO」概括半套结果；产品可在已覆盖市场上市，未覆盖市场单独决策 | 业务负责人 + 法务会签；专利师对覆盖范围负责，不对上市时间负责 |
| C2 | 规避成本 vs 许可费 | 改模要 300 万，许可年费 100 万 ⚠ | **算全周期成本**：改模一次性 + 性能损失 + 重新认证 vs 许可年费 × 预期销售年限 + 谈判风险。**默认优先规避**（消除风险优于管理风险），例外须业务负责人书面说明 | 业务负责人决定；财务核成本模型；法务提示许可可得性 |
| C3 | 法务建议不上市 vs 业务坚持 | 法务判 `high_risk`，业务认为市场必须拿下 | **走「发现障碍仍上市」流程**（R1B-56）：书面提示 + 业务签字承担 + 法务保留红线否决。不得由任何一方单方面压过另一方 | 业务负责人签字；法务可否决；总经理知情 |
| C4 | 报告对外 vs 保密 | 客户或投资方要求看完整报告 | **对外只给脱敏版**：结论、涉及的公开专利号、规避建议可给；成本、内部评级理由、未脱敏客户信息、其他产品线风险不给 | 法务唯一有权批准；业务不得自行转发 |
| C5 | FTO 结论 vs 律师意见 | 专利师出「字面不落入」，外部律师出「可能构成等同侵权」 | **两者并存，不合并**：报告保留专利师结论，另附律师意见为独立附件。对外以律师意见为准（如已出具） | 法务决定对外口径；两份意见均留档 |

**裁决顺序（自上而下适用）**

| 序 | 原则 | 含义 | 例外 |
|---|---|---|---|
| 1 | **法定硬规则优先** | 地域性、全面覆盖、法律状态过滤，不可让渡 | 无 |
| 2 | **不可逆优先** | 上市、许诺销售、参展这类一经发生即无法撤回的行为，优先获得决策资源 | — |
| 3 | **留痕优先于结论漂亮** | 宁可报告写「未覆盖 3 国」，不写「全球已评估」 | — |
| 4 | **明确反对意见必留** | 专利师、外部律师的不同意见不得被「统一口径」抹平 | — |
| 5 | **商业决策不外包给专业人士** | 专利师不决定上不上市，业务不重判侵不侵权 | 法务红线否决除外 |
| 6 | **最小风险敞口优先** | 同等成本下，选消除风险（规避）而非管理风险（许可） | 规避成本显著更高且许可可得时 |
| 7 | **书面优先于口头** | 任何偏离须有书面理由与签字 | — |

> **最重要的一条是 C3**：FTO 产品如果只做到「输出一个风险等级」，C3 就无解——因为没有人知道该由谁签字、签的是什么。系统必须把「发现障碍仍上市」做成一个**带四个必填项的决议对象**（风险提示、商业理由、签字人、时间），而不是一个可以忽略的红色标签。这也是 §5.2 所说的商业价值能否守住的分界线。

**冲突与例外规则**

| ID | 规则 | 现状 |
|---|---|---|
| R1B-60 | 任何压缩覆盖范围的决定须走 E1/E2 并写明未覆盖市场与未比对权项，报告中不得出现「全球已评估」类概括表述 | ❌ |
| R1B-61 | 规避与许可的方案比较须用全周期成本模型（一次性改模 + 持续许可费 + 认证 / 性能损失），不得只比首年支出 | ❌ |
| R1B-62 | 法务判断与业务决策冲突时，走「书面风险提示 + 业务签字承担」流程，不得由职级高者直接压过 | ❌ |
| R1B-63 | 报告对外提供须版本化并登记接收方；同一项目对不同接收方的版本差异须可追溯 | ❌ |
| R1B-64 | 专利师结论与外部律师意见并存时，两者分别留档，不得互相覆盖；对外口径由法务确定 | ❌ |

| R1B-66 | 红线不可例外：承诺「保证不侵权」、编造比对结果、删除已发现的障碍、伪造检索日期 | ⚠ 仅靠制度 |
| R1B-67 | 已收到警告函后仍决定上市的案件，必须同时启动 24 诉讼的应诉预案，不得只走 FTO 流程 | ❌ |

## 5. 法律底座

### 5.1 什么行为构成侵权（《专利法》第 11 条）

未经专利权人许可，为**生产经营目的**：

- 制造、使用、**许诺销售**、销售、进口专利产品；
- 使用专利方法，以及使用、许诺销售、销售、进口依照该专利方法直接获得的产品。

**产品落点**：

- FTO 必须覆盖**五种行为**，不只是「制造」。很多企业只评估制造，忽略了「许诺销售」（展会、网站、报价单都算）和「进口」。
- 「使用」也包括下游客户的使用——这决定了零部件供应商为什么需要 FTO。

### 5.2 FTO 最被低估的价值：阻却惩罚性赔偿

《专利法》第 71 条：

> 对**故意**侵犯专利权、**情节严重**的，可以在按照上述方法确定数额的**一倍以上五倍以下**确定赔偿数额。

**两个要件是并列的**：主观「故意」+ 客观「情节严重」。缺一不可。

而一份合格的 FTO 报告，在实务中被用来证明：

> **被告已履行合理注意义务** → 阻却「故意」认定 → 不适用 1–5 倍惩罚性赔偿 → 只承担填平性赔偿。

**这就是 FTO 的商业价值公式**：

```
FTO 的价值 ≈ 避免的惩罚性赔偿倍数 × 赔偿基数 × 被诉概率 + 避免的改设计成本 + 避免的禁令损失
```

举例（示意）：一件产品年销售额 5000 万，若被判侵权且认定故意，赔偿可能是填平额的 3 倍。一份 20 万的 FTO 报告，即使最终仍然败诉，也可能把 3 倍降到 1 倍。**这个 ROI 是 FTO 定价的真正天花板。**

> ⚠ **重要限制**：中国目前对「FTO 做到什么程度才足以抗辩故意侵权」**没有明确判例标准**。实务上参照一般专利侵权标准，从「检索查全率」与「是否遵循全面覆盖原则」两个维度评估报告质量。
> **产品含义**：报告的方法论严谨性（范围声明、逐要素比对、复核人资质）比结论本身更重要。**这决定了 FTO 产品的核心不是"给个结论"，而是"留下可举证的过程"。**

### 5.3 地域性：一件专利只在其授权国有效

这是 FTO 成本高的根本原因。

| 场景 | 需要检索 |
|---|---|
| 中国生产 + 中国销售 | 中国专利 |
| 中国生产 + 出口美国 | 中国 + 美国（出口行为本身在中国也可能构成"制造"） |
| 中国生产 + 全球销售 | 每个销售国 + 制造国 |
| 只在海外生产销售 | 生产国 + 销售国 |

**产品落点**：`targetMarkets` 不是装饰字段，它直接决定检索范围和成本。系统应按市场数量估算工作量与报价。

### 5.4 公开盲区：FTO 永远不可能 100% 完整

《专利法》第 34 条：发明专利申请自**申请日起满十八个月**即行公布（可请求提前公布）。

所以检索时存在三类看不到的东西：

| 盲区 | 原因 | 后果 |
|---|---|---|
| **未公开的申请** | 申请日不满 18 个月 | 完全不可见 |
| **未公开的 PCT 国际申请** | 国际公布滞后 | 进入国家阶段后才可见 |
| **未公布的权利要求修改** | 审查中修改 | 授权公告前权项可能与公开版不同 |

**产品铁律**：FTO 报告**必须**声明「截至检索日未发现」，不能写「不存在侵权风险」。这不是免责话术，是事实陈述。

### 5.5 法律状态过滤：FTO 与可专利性检索的分水岭

| 状态 | 对 FTO | 对可专利性检索 |
|---|---|---|
| 有效（granted, in force） | **构成障碍** | 现有技术 |
| 审中（pending） | 可能构成障碍 | 现有技术（若已公开） |
| 失效（expired / lapsed） | **不构成障碍** | **仍是现有技术** |
| 被无效（invalidated） | 不构成障碍 | 仍是现有技术 |
| 未进入目标国（同族） | 不构成障碍 | 仍是现有技术 |

> **这一张表是整篇最值钱的东西**。它解释了为什么「检索同一批文献，结论完全不同」，也解释了为什么不能拿可专利性检索报告冒充 FTO。

### 5.6 FTO 报告与诉讼的关系（与 24 的接口）

| 场景 | FTO 的作用 |
|---|---|
| 被诉时 | 作为「已尽合理注意义务」的证据，抗辩故意侵权 |
| 主动维权时 | 证明自己尊重他人权利，降低被判滥用诉权的风险 |
| 收到警告函后 | 立即复核并调整设计，可证明「非故意」 |
| 投资尽调 | 证明标的技术可自由实施 |

**反例**：如果做了 FTO 但**发现了障碍仍照常上市**，这份报告反而会成为对方证明「明知故犯」的证据。**这是 FTO 最大的反向风险，产品必须提示。**

## 6. 比对逻辑（本节点技术核心）

### 6.1 三层结构

```
第 1 层  权项解释    权利要求用语的含义（以说明书为字典，参考审查档案）
   │
第 2 层  要素分解    把独立权利要求拆成若干技术特征
   │
第 3 层  全面覆盖    被控产品是否包含每一个要素
        │
        └─ 全部包含 → 落入（可能侵权）
        └─ 缺任一个 → 不落入（不侵权），比对可终止
```

### 6.2 逐要素对照表（示例结构）

假设障碍专利独权为：「一种电池模组，包括 A、B，**其特征在于** C 与 D 的比值为 1.5–2.0」。

| # | 权项要素 | 产品对应 | 判定 | 说明 |
|---|---|---|---|---|
| 1 | 电池模组 | 是 | present | — |
| 2 | 包括 A | 是 | present | — |
| 3 | 包括 B | 是 | present | — |
| 4 | C 与 D 的比值为 1.5–2.0 | 比值为 2.3 | **absent** | **不落入** |

**结论**：第 4 项不满足 → 不侵权。

**规避设计**：把比值调到 2.3 是规避的一种，但要评估：① 是否落入等同；② 2.3 是否影响产品性能；③ 是否还有其他权项覆盖。

### 6.3 唯一例外：等同

字面上不同，但满足「手段、功能、效果基本相同 + 本领域技术人员无需创造性劳动即可联想」的，仍可能构成等同侵权。

**FTO 阶段的处理原则**：

- **以字面比对为准**，等同只做提示。
- 因为等同的最终认定权在法院，FTO 阶段无法定论。
- 报告中应写「字面不落入，但存在等同风险，建议进一步评估」。

### 6.4 规避设计的三条路径

| 路径 | 做法 | 有效性 | 副作用 |
|---|---|---|---|
| **删除一个必要特征** | 产品不做某个要素 | 最强（必不落入） | 可能影响功能 |
| **替换为非等同方案** | 用不同手段实现同一功能 | 中（需评估等同） | 需重新验证性能 |
| **改变技术路线** | 完全不同的实现方式 | 强 | 成本最高 |

**产品落点**：规避设计完成后，往往会产生**新的可专利点**——应回流到 [03 撰写](03-drafting.md)。这是 FTO 常被忽略的正向价值：**排雷的同时可能挖到矿。**

## 11. 边界与失败场景

| # | 场景 | 正确处置 | 现状 |
|---|---|---|---|
| 1 | 只检索本国，产品却出口 | 按销售国 + 制造国分别检索 | ❌ |
| 2 | 把失效专利当障碍 | 核对法律状态，失效不构成障碍 | ❌ |
| 3 | 只比摘要不比权项 | 必须取得权项全文 | ❌ |
| 4 | 只比独权，漏了从权 | 独权不落入时仍须看从权（可能单独构成障碍） | ❌ |
| 5 | 同族重复计数 | 折叠同族，按国别分别评估 | ❌ |
| 6 | 忽略审中申请 | 标注「授权后可能构成障碍」 | ❌ |
| 7 | 报告写「无侵权风险」 | 只能写「截至检索日未发现」 | ❌ |
| 8 | 报告未声明检索范围 | 无法举证已尽注意义务 | ❌ |
| 9 | 发现障碍仍照常上市 | **报告反成「明知故犯」证据** | ❌ |
| 10 | 规避设计后未重评 | 必须重新比对 | ❌ |
| 11 | 结论过期仍在使用 | 到期提醒 + 强制重跑 | ❌ |
| 12 | 方法专利举证责任倒置 | 需特别提示 | ❌ |
| 13 | 权项有译文误差 | 以原文为准，译文仅供参考 | ❌ |
| 14 | 审查档案显示已放弃某特征 | 禁止反悔，该特征不能通过等同拿回 | ❌ |
| 15 | 客户要求「保证不侵权」 | 任何情况下不可承诺 | ❌ |

## 12. 指标

| 指标 | 定义 | 健康区间 | 说明 |
|---|---|---|---|
| 障碍发现率 | 发现有效障碍的项目 / 总项目 | 30%–60% ⚠ | 过低说明检索不足 |
| 规避设计采纳率 | 采纳规避建议的项目 / 提出建议的项目 | > 50% | 反映建议可执行性 |
| 报告被质疑率 | 结论被推翻或要求重做的比例 | < 10% | 质量指标 |
| 平均周期 | 立项到交付 | 2–4 周 | 影响上市节奏 |
| 单市场成本 | 人力 + 数据库 | 视复杂度 ⚠ | 定价依据 |
| 保鲜到期重跑率 | 到期后重跑的项目 / 到期项目 | > 80% | 反映客户粘性 |
| **被诉后报告采信率** | 诉讼中被采纳为「已尽注意义务」的比例 | — | **最能证明价值的指标** |

## 13. 产品化切分建议

| 层 | 内容 | 可独立交付 |
|---|---|---|
| L1 特征与范围 | 产品特征拆解、目标市场配置 | 是（低配） |
| L2 检索层 | 多库检索、同族折叠、法律状态核查 | 是（依赖数据源） |
| L3 比对层 | 逐要素 claim chart、权项解释 | 是（**差异化最强**） |
| L4 规避层 | 规避建议、改设计评估 | 是（高价值） |
| L5 报告层 | 结构化报告、范围与局限声明、复核签署 | 是（**抗辩必需**） |
| L6 持续层 | 保鲜提醒、自动重跑、新品触发 | 订阅制 |

**定价锚点**：

- 按项目（单市场 / 多市场）
- 按产品线订阅（持续 FTO）
- 按次重跑

**竞品**：国际律所提供 FTO 服务但价格高；国内检索工具（智慧芽、incoPat）有 FTO 模块但**缺比对工作流与抗辩证据链**。

**空位**：**「比对 + 规避 + 可举证的报告」三件套**。市面上大多只做到「检索出专利」，没做到「证明我认真查过、并且知道怎么改」。

## 14. 现状差距表

### 14.1 与文档的差距

| # | 差距 | 严重度 |
|---|---|---|
| 1 | FTO 仅在 [01](01-research.md) 里作为一个 `fto` 子对象，无独立规格 | **高** |
| 2 | 无「目标市场」驱动的检索逻辑 | **高** |
| 3 | 无法律状态过滤规则 | **高** |
| 4 | 风险等级只有低/中/高，无「可处置性」 | **高** |
| 5 | 无规避设计建议 | **高** |
| 6 | 无公开盲区声明要求 | **高** |
| 7 | 无「FTO 报告可阻却惩罚性赔偿」这一商业价值论证 | **高** |
| 8 | 无报告的范围声明与复核签署规则 | 中 |
| 9 | 无保鲜期实现（R01-33 标 ❌） | 中 |
| 10 | 无与 24 诉讼的证据接口 | 中 |

### 14.2 与原型（`apps/fto` :5183）的差距

原型五步（特征 → 命中 → 矩阵 → 风险 → 报告）方向对，但缺关键能力：

| # | 原型现状 | 缺什么 |
|---|---|---|
| 1 | `ProductFeature` 有名称/描述/关键词 | 缺 `isEssential`、`alternatives`（规避原料） |
| 2 | `SearchHit` 只有 pubNo/title/applicant/mockClaims | 缺 `legalStatus`、`jurisdiction`、`expiryDate`、`familyId` 的实际使用 |
| 3 | `MatrixCell` 判定为「可能覆盖/未涉及/需人工」 | **不是逐要素比对**，无法支撑全面覆盖原则 |
| 4 | 「自动填假比对」按关键词重叠 | 关键词重叠 ≠ 侵权判定，方向性误导 |
| 5 | `RiskLevel = low/medium/high/unclear` | 缺可处置性等级 |
| 6 | 无目标市场字段 | FTO 无法按国别开展 |
| 7 | 报告无检索范围、无局限声明、无复核人 | **无法作为抗辩证据** |
| 8 | 无保鲜期 | 结论会过期 |

**原型最需要改的一处**：把「特征 × 文献矩阵」改成「**权项 × 要素**」的逐项对照。矩阵是二维的，侵权判定是三维的（专利 → 权项 → 要素）。现在的矩阵无法表达「一件专利有多个权项，每个权项有多个要素」。

## 15. 术语表

| 术语 | 含义 |
|---|---|
| FTO | Freedom to Operate，自由实施，指在不侵犯他人专利权的前提下实施技术 |
| 障碍专利 | 目标市场内仍然有效、且可能被产品落入其权利要求的专利 |
| 全面覆盖原则 | 被控方案须包含权利要求的每一个技术特征才构成侵权 |
| 等同原则 | 手段/功能/效果基本相同且显而易见时，虽不同仍构成侵权 |
| 禁止反悔 | 审查或无效程序中放弃的内容，不得在侵权诉讼中重新主张 |
| 公开盲区 | 申请日起 18 个月内未公开的申请，检索时不可见 |
| 同族 | 同一发明在不同国家/地区申请的一组专利 |
| 法律状态 | 专利当前是否有效（有效/审中/失效/无效/未进入） |
| 规避设计 | 通过修改产品特征，使其不落入障碍专利的权利要求 |
| 保鲜期 | FTO 结论的有效期，超期需重跑 |
| 惩罚性赔偿 | 对故意侵权在填平性赔偿基础上加倍，中国为 1–5 倍 |
| 合理注意义务 | 侵权前已尽到审慎检索与评估的义务，可阻却「故意」认定 |
