## 0. 一句话讲清这个节点

**审批答复 = 在一条有硬期限的流水线上，把「审查员说你的权项不行」翻译成三选一的动作——争辩、缩限、分案——并把每一次选择连同理由与修改痕迹留在案卷里。**

它不是「写一封信」。它是在**时间、范围、成本**三者之间做受约束的决策：期限一到不答复，申请直接视为撤回；缩得太多，专利拿到手也没有维权价值；只争辩不修改，往往换来第二次甚至驳回。

产品化三条件：

| 条件 | 本节点的回答 |
|---|---|
| 有独立买方 | 代理所（答复产能与质控）· 企业 IP（把控策略与预算）· 涉外所（多国期限统一看板） |
| 有独立价值 | 每一轮 OA 都是一次代理费 + 3–6 个月时间；答复质量直接决定是否驳回 |
| 有独立边界 | 输入是 OA 通知书 + 现行权项，输出是 `prosecution_response`，不依赖 05 即可交付 |

### 1.3 它是什么 / 不是什么

| 是 | 不是 |
|---|---|
| **争点级**的答复决策与文本生产 | 一份通用信函模板 |
| 修改边界的**合规执法点**（33 条 / 57 条） | 权项起草（那是 03；本节点只做限缩与澄清） |
| 期限与轮次的**状态跟踪** | 期限引擎本身（那是 11；本节点消费它） |
| 驳回后的**复审入口**（3 个月） | 复审与无效的完整程序建模（当前无） |

> 最容易误判的一点：**答复不是「说服审查员」**。答复是在法律允许的修改边界内，用最小的范围让步换取授权；说服只是手段之一，而且往往不是最有效的那种。

### 1.5 独立产品的形态

**产品名建议：答复工作台 / Office Action Desk**

| 模块 | 能力 | 谁用 |
|---|---|---|
| OA 收文与登记 | 上传/解析通知书，自动抽争点、对比文件、期限 | 代理流程岗 |
| 争点看板 | 每条争点：审查员观点 / 法条 / 对比文件 / 策略 / 状态 | 代理师 |

## 2. 角色与权限矩阵

| 角色 | 代码对应 | 能做什么 | 不能做什么 |
|---|---|---|---|
| 代理师 | `role === 'agency'` / persona `agency` | `save_draft` / `submit` / `file`；写争点策略与陈述草稿 | 不能 `approve` / `authorize` |
| 企业 IP | `role === 'enterprise'` / `enterprise_ip` | `start_review` / `request_changes` / `approve` / `authorize`；确认陈述 | 委托模式下不能 `file` |
| 企业自助 | `fulfillmentMode === 'self_serve'` | 企业身份执行代理动作 | 无（有意放宽） |
| 发明人 | persona `inventor` | 只读；可提供技术事实 | 禁批准/授权/file |
| 委员 | persona `committee` | 只读 | 禁批准/授权/file |
| Agent | `agent-oa` | 拆争点、提修改建议、起草陈述、建议 docket | 无企业身份时禁 `authorize_file` |

**当前实现的权限真相**：

- 与 03 相同，是**角色芯片**（`role` + `persona`），非真实身份认证。
- `oaStatementConfirmed` 写在 **case 级**（`AppContext.tsx:1583-1596`），不是会话级也不是轮次级。任何人勾选后，全案生效且**不会随新一轮 OA 重置**。
- 工作台勾选会镜像到 Agent 会话（`ProsecutionFlow.tsx:294-304`），但反向不成立：Agent 侧确认不会回写 case（除经 ConfirmBar 的专门路径）。

## 3. 业务对象（字段级）

### 3.1 交接产物 `prosecution_response` 的两项必填

`REQUIRED_BEFORE_SUBMIT.prosecution_response`（`handoff.ts:125-128`）：

| 键 | 中文标签 | 业务含义 | 代码判定 | 现状 |
|---|---|---|---|---|
| `strategy` | 争点策略与答复要点 | 至少一条争点已定策略并写要点 | `issues.some(i => i.strategy.trim() && i.response.trim())`（`ProsecutionFlow.tsx:401`） | ✅ |
| `claims_amended` | 修改后权利要求（如需） | 限缩/澄清后的权项全文 | `claimAmended.trim()`（`:402`） | ⚠ **「如需」与必填矛盾**：纯争辩不修改的案子无法提交 |

> 第二个键是本节点**最直接的设计缺陷**：标签写「如需」，实现却是硬必填。业务上「本轮不修改，仅争辩」是完全合法且常见的选择（尤其针对清楚性缺陷的澄清说明），但系统会把它挡在提交之外。

### 3.2 争点 `issues[]`（Flow 内局部类型）

`ProsecutionFlow.tsx:54`，元素结构见 `src/data/workbenchSeeds.ts:401-408`：

| 字段 | 类型 | 必填 | 说明 | 问题 |
|---|---|---|---|---|
| `id` | string | 系统 | `i1` / `i2` | — |
| `type` | string | ✅ | 中文标签（非枚举） | 与 `OaIssueType` 靠 `mapIssueType` 字符串映射（§3.4） |
| `claimRefs` | string | — | 「权利要求 1、3」 | 自由文本，无结构 |
| `examinerView` | string | — | 审查员观点摘录 | 自由文本 |
| `strategy` | string | ✅ | 5 选 1 | 英文策略码不存在 |
| `response` | string | ✅ | 答复要点 | 自由文本 |

**这个对象缺失的东西，就是产品缺失的能力**：

1. 没有**法条引用**字段（审查员依据的是 22.2 / 22.3 / 26.3 / 26.4 / 细则某条）；
2. 没有**对比文件**字段（X/Y 类文献编号、被公开的特征）；
3. 没有**争点状态**（待处理 / 已答复 / 已克服 / 保留争议）；
4. 没有**轮次归属**（属于第几通 OA）。

### 3.3 OA 登记信息（4 个自由字段）

| 字段 | 类型 | 代码行为 | 业务应有行为 |
|---|---|---|---|
| `oaDate` 发文日 | `<input type="date">` | 仅展示与组装草稿（`:211`） | 应驱动期限计算与推定收到日 |
| `deadline` 答复期限 | `<input type="date">` | **手填**，不由 `oaDate` 推算（`:212`） | 应按规则自动算，且允许人工覆盖并留痕 |
| `oaType` 类型 | `<select>` 4 选 1 | 第一次 / 第二次 / 补正通知书 / 驳回决定（`:213-217`） | 应有「第 N 通」数值 + 复审决定分支 |
| `feeReminder` 费用提醒 | 文本 | 来自 seed，只读展示（`:219-221`, `:58`） | 应联动延期费/恢复费规则 |

**`oaType` 的四个选项暴露了模型缺陷**：把「第几通」和「文件性质」混在一个枚举里。第一次/第二次是**轮次**，补正通知书是**初审文件**，驳回决定是**终局决定**——三者不在同一个维度上，却挤在一个下拉里。

### 3.4 争点类型：两套枚举与一个映射函数

`mapIssueType`（`ProsecutionFlow.tsx:65-72`）：

| Flow 下拉（6） | 映射结果 | 领域枚举（5） |
|---|---|---|
| 新颖性 | `novelty` | ✅ |
| 创造性 | `inventiveness` | ✅ |
| 清楚性 | `clarity` | ✅（标签为「清楚」） |
| 支持 | `support_disclosure` | ✅（标签为「支持 / 充分公开」） |
| 实用性 | `other` | ⚠ 语义丢失 |
| 形式缺陷 | `other` | ⚠ 语义丢失 |

**后果**：`Full-check` 与 `oa_meta` 闸门只看映射后的 5 值，因此「实用性」与「形式缺陷」在闸门层面**完全相同**。产品若要做「按争点类型统计授权率」，这两类会被合成一类。

### 3.5 陈述确认标志 `oaStatementConfirmed`

| 属性 | 值 | 位置 |
|---|---|---|
| 存储位置 | `PatentCase.oaStatementConfirmed`（case 级布尔） | `types/index.ts:241-242` |
| 写入 | `setOaStatementConfirmed(caseId, bool)` | `AppContext.tsx:1583-1596` |
| 读取（闸门） | `input.case?.oaStatementConfirmed` 或 `session.oaStatementConfirmed` | `guardrails.ts:180-184` |
| 镜像 | 勾选时同步到本 case 的 `agent-oa` 会话 | `ProsecutionFlow.tsx:294-304` |
| 重置 | **无** | — |

**语义**：「答复草稿 → 已确认陈述」的分界。勾上之前，系统认为这仍是可以任意改的草稿；勾上之后，内容被视为对外的正式陈述，因此禁止递交前未确认。

### 3.6 修改对照 `claimOriginal` / `claimAmended`

| 字段 | 类型 | 说明 |
|---|---|---|
| `claimOriginal` | string | 修改前权项全文（手工粘贴） |
| `claimAmended` | string | 修改后权项全文（手工粘贴） |
| diff 渲染 | `ClaimDiffView` | 字符/词级 LCS diff（`src/utils/textDiff.ts:14-40`） |

**diff 是「文本级」而非「权项级」**：它告诉你「这几个字被删了」，但不告诉你「第 3 项从权被删除」「第 1 项新增了特征 F」。对于要向审查员说明「修改依据是什么、对应说明书哪一段」的场景，文本 diff 远远不够。

### 3.7 三个「轮次」概念，别混

| 概念 | 代码现状 | 含义 |
|---|---|---|
| OA 轮次 | ❌ 无字段（仅 `oaType` 字符串） | 第几通审查意见 |
| 交接版本 | ✅ `handoffs.prosecution_response.versions` | 内部稿件的 v1/v2 |
| 答复状态 | ✅ 7 态交接机 | 稿件在企业与代理之间走到哪 |

> 「第 3 通 OA」与「答复稿 v3」不是一回事。前者是官方的，后者是内部的。当前代码只有后者。

## 5. 法律底座 / 行业规则

### 5.1 审查意见通知书的类型

| 类型 | 何时发出 | 期限 | 逾期后果 | 代码支持 |
|---|---|---|---|---|
| 补正通知书 | 初审阶段（形式缺陷） | 指定期限（常见 2 个月 ⚠） | 视为撤回 | ⚠ 仅 `oaType` 选项 + seed c7 |
| 第一次审查意见通知书 | 实审开始后 | 指定期限（常见 **4 个月**） | 视为撤回 | ✅ `oa1_response` |
| 第二次及后续审查意见通知书 | 答复后仍有缺陷 | 指定期限（常见 **2 个月**） | 视为撤回 | ✅ `oa_subsequent` |
| 驳回决定 | 陈述/修改后仍不符合（专利法第三十八条） | 复审 3 个月 | 申请被驳回 | ⚠ 仅 `oaType` 选项 |
| 复审通知书 / 复审决定 | 复审程序中 | 指定期限 | 复审请求视为撤回 | ❌ |

> 「指定期限」是关键词：法律与细则都**不统一规定天数**，由审查部门在个案中指定（细则第五十条第二款、审查指南）。这是为什么 docket 规则写「常见 4 个月」而不是「法定 4 个月」——产品文案必须保留这个措辞，否则会误导用户。

### 5.2 答复期限与延期

| 项 | 规则 | 依据 | 产品落点 |
|---|---|---|---|
| 起算 | 期限开始当日不计入，自次日起算 | 细则第五条 | 期限计算器 |
| 推定收到 | 邮寄：自发文日满 15 日推定收到；电子：进入电子系统之日 | 细则第四条 | 需「送达方式」字段 |
| 届满日 | 最后一月的相应日；该月无相应日的以月末日为准 | 细则第五条 | 计算器边界用例 |
| 顺延 | 届满日为法定休假日 → 节后第一个工作日 | 细则第五条 | ❌ 未实现 |
| 延长上限 | 每次不超过**两个月**，同一通知/决定**一般只允许延长一次**（审查指南第五部分第七章第 4 节 ⚠ 需按当期指南复核） | 审查指南 | ❌ 未实现 |
| 延长时点 | 必须在期限届满**前**提出 | 细则第六条第四款 | ❌ |
| 延长费用 | 延长期限请求费：第一次每月 300 元、再次每月 2,000 元 ⚠（不予减缓） | 收费公告第 244 号 | ⚠ 仅 `officialFeeHint` 文案 |
| 逾期后果 | 期满未答复 → 申请**视为撤回** | 细则第五十条第二款 | ❌ 无终止态 |
| 恢复 | 因不可抗拒事由：自障碍消除起 2 个月内且自期限届满起 2 年内；其他正当理由：自收到通知起 2 个月内；须缴恢复权利请求费 1,000 元 ⚠ | 细则第六条第一、二款 | ❌ |

**产品含义**：这条链上有三个「不可逆」的时点——期限届满、申请视为撤回、恢复窗口关闭。系统当前只画了第一个，后两个不存在。

### 5.3 五种争点类型与各自的答复策略

| 类型（代码值） | 审查员在说什么 | 首选策略 | 次选 | 关键陷阱 |
|---|---|---|---|---|
| `novelty`（22.2） | 单篇对比文件公开了权项**全部**特征 | 缩限（加入区别特征） | 争辩（指出该文献未公开某特征） | 不得用两篇拼凑来否定/主张新颖性 |
| `inventiveness`（22.3） | 最接近现有技术 + 区别特征 + 技术启示 = 显而易见 | 「区别特征 + 技术效果 + 非显而易见」三段论证，必要时缩限 | 补充实验数据（受限于能否被接受） | 只讲「效果更好」不讲「为何预料不到」 |
| `clarity`（26.4 前半 / 细则第二十二条） | 权项用语含义不清、缺少必要技术特征 | 澄清修改（用说明书已有表述替换） | 争辩（本领域有确定含义） | 澄清不得引入原说明书没有的术语 |
| `support_disclosure`（26.4 / 26.3） | 权项概括超出说明书支持，或公开不充分 | 缩限至上位概念的下位实施例 | 争辩（说明书已给出足够指引） | 26.3 类缺陷**无法**通过补充内容修复（33 条） |
| `other`（实用性 / 形式 / 其他） | 不符合 22.4、细则形式要求等 | 形式补正；实用性争辩需证据 | — | 代码把「实用性」与「形式缺陷」合并（§3.4） |

**策略选择的硬约束**（必须写进产品文案）：

1. **能争辩就不修改**——每修改一次，范围就永久小一块；
2. **能修改就不分案**——分案是成本与时间的双倍支出；
3. **但**：如果争辩成功的概率低，硬撑一轮 = 多一轮 OA + 多一次代理费 + 可能被驳回。**期望值算法**：`P(争辩成功) × 保住的范围价值` vs `一轮 OA 成本 + 缩限损失`。

### 5.4 修改的边界（本节点最重要的合规线）

**专利法第三十三条**：对发明和实用新型申请文件的修改不得超出原说明书和权利要求书记载的范围；对外观设计不得超出原图片或照片表示的范围。

**细则第五十七条**（修改时机与范围）：

| 阶段 | 可修改范围 |
|---|---|
| 发明：提出实审请求时 + 收到进入实审阶段通知书起 3 个月内 | **主动修改**（范围较宽，但仍受 33 条约束） |
| 实用新型 / 外观：自申请日起 2 个月内 | 主动修改 |
| 收到审查意见通知书后 | 应当**针对通知书指出的缺陷**进行修改 |
| 复审阶段 | 针对驳回决定与复审通知书指出的缺陷 |

**「针对通知书指出的缺陷」的实务含义**（这是产品最该内置的一条规则）：

- 不能顺手把没被指出的权项也改一遍（除非是为消除与已修改权项的引用矛盾）；
- 不能借答复之机扩大范围（33 条 + 修改超范围）；
- 修改后的权项必须能从**原说明书**中找到每一处文字依据。

**失效后果**：

| 违规 | 后果 |
|---|---|
| 修改超范围（33 条） | 该修改不被接受；严重时成为无效理由 |
| 修改不针对缺陷 | 审查员可不予考虑，本轮答复视为未克服 |
| 主动修改超窗口 | 不予接受 |

### 5.5 意见陈述的结构

行业通行的三段式，与代码组装模板的差距：

| 段 | 内容 | 代码是否生成 |
|---|---|---|
| 一、修改说明 | 逐项列出对权项的修改：删了什么、加了什么、依据在说明书第几段 | ❌ 只有「修改前/修改后」两块原文 |
| 二、争点分析 | 按争点逐条：审查员观点 → 申请人意见 → 法律依据 → 结论 | ⚠ 有「争点/审查员观点/策略/要点」四要素，但无法律依据与结论 |
| 三、证据 | 对比文件分析、实验数据、公知常识证据 | ❌ 完全缺失 |

**「证据」段缺失的后果**：创造性答复里最常见的失败就是「只讲道理不拿证据」。系统若不预留证据位，代理师就只能把证据写进「答复要点」的自由文本里，最终无法统计、无法复用。

### 5.6 分案申请

| 项 | 规则 | 依据 |
|---|---|---|
| 触发场景 | 申请包含两项以上发明而缺乏单一性；或审查员要求删除权项时，把被删的方案另案保护 | 细则第四十八条 |
| 最晚时点 | **办理登记手续期限届满前**（即收到授权通知起 2 个月内） | 细则第四十八条第一款引第六十条第一款 |
| 禁止情形 | 原申请已被驳回、撤回或视为撤回的，不能提分案 | 细则第四十八条 |
| 类别 | 分案不得改变原申请类别 | 细则第四十八条 |
| 申请日 | 保留原申请日；有优先权的保留优先权日 | 细则第四十九条 |
| 范围 | 不得超出原申请记载的范围 | 细则第四十九条 |
| 实审请求 | 分案时原申请已过 3 年实审期限的，须在分案提交时提出实审请求并缴费 ⚠（审查指南） | 审查指南 |
| 费用 | 分案按新申请缴申请费；已缴费用不退还 | 收费办法 ⚠ |

**产品含义**：分案是**答复策略的第三条腿**，也是「权项被要求删除时的止损手段」。当前系统完全没有它，导致最坏情况下代理师只能「删掉就没了」。

### 5.7 驳回与复审

| 项 | 规则 | 依据 |
|---|---|---|
| 驳回 | 陈述意见或修改后仍不符合规定的，应当予以驳回 | 专利法第三十八条 |
| 复审请求期 | 自收到驳回决定之日起 **3 个月** | 专利法第四十一条 |
| 复审费 | 发明 1,000 元；实用新型 300 元；外观设计 300 元 ⚠ | 收费公告第 244 号 |
| 逾期救济 | 延误复审请求期的，可自期限届满起 2 个月内请求恢复（细则第六条第二款） | 细则 |
| 复审后不服 | 收到复审决定起 3 个月内起诉 | 专利法第四十一条 |
| 复审中的修改 | 针对驳回决定与复审通知书指出的缺陷 | 细则 |

**这是一条完整的「第二条命」链路**：驳回 → 3 个月复审 → 复审决定 → 3 个月诉讼。系统当前只在 `oaType` 里有一个「驳回决定」字符串，没有任何后续。

### 5.8 为什么 `oa_meta` 与 `oa_statement` 是两道闸

这是本节点最值得讲的设计，因为它把「代理师的专业判断」拆成了两个可审计的时点：

| 闸 | 触发动作 | 校验内容 | 设计意图 | 失效会怎样 |
|---|---|---|---|---|
| `oa_meta` | `approve` | 争点类型已选 + 策略要点非空 | 强迫在**批准策略之前**把「这是哪类问题、打算怎么办」写下来 | 企业批的是「一份文件」，不是「一个策略」；事后无法复盘为什么这么答 |
| `oa_statement` | `authorize` / `file` | `oaStatementConfirmed === true` | 区分「答复草稿」与「已确认陈述」 | 草稿被当作正式陈述递交；出问题时无法界定是代理笔误还是企业确认过的立场 |

**两道闸的分工**：

```
争点+策略 ──[oa_meta]──► 企业批准策略 ──► 撰写陈述 ──[oa_statement]──► 授权递交
   （做什么）                                    （写成什么）
```

- `oa_meta` 管**方向**：答哪个争点、走争辩还是缩限。
- `oa_statement` 管**定稿**：这段文字是否被确认为对外立场。

**当前的实现偏差**：`oa_meta` 只校验**当前激活的那一条争点**（`ProsecutionFlow.tsx:353-374` 只传 `activeIss`），因此有 3 条争点时，只要第 1 条填了就能批准。这与「逐条争点」的界面语义直接矛盾。

### 5.9 期限计算口径

四个口径必须固定：发文日 vs 收到日（§5.2「推定收到」行）、起算日不计入、月末规则、节假日顺延（后三条均出自细则第五条，见 §5.2）。系统当前只做了「月份加算」（`computeDueDate`），其余三条都没做——单是纸件 15 天推定这一项，算错就意味着代理师实际少了 15 天准备时间。

**`evaluateFullCheck` 的 oa 分支**（`fullFilingCheck.ts:83-87`）：

```
scope === 'oa' →
  !oaStatementConfirmed  → '意见陈述未确认'
  !oaIssueType           → '未选 OA 争点类型'
  !oaStrategyNotes.trim()→ '未填策略要点'
  （再加 lite 三项：术语 / 支持 / 非法律意见戳）
```

**设计评价**：`oa_meta` 与 `oa_statement` 是两道语义清晰的闸，值得保留；问题在**入参**——工作台只把当前激活争点塞进 `session`，使闸门覆盖面小于界面承诺（§5.8）。

## 8. 步骤序列 / 工作流

### 8.1 四个 Flow 步骤

| # | 步骤 | 谁做 | 典型耗时 | 产出 | 完成条件（代码） | 失败回退 |
|---|---|---|---|---|---|---|
| 1 | OA 登记 | 流程岗 / 代理师 | 0.5 天 | 发文日、期限、类型 | `oaDate` 或 `deadline` 非空（`:147`） | 文件不全 → 补收文 |
| 2 | 争点策略 | 代理师 + 企业 IP | 1–5 天 | `issues[]` 含类型/观点/策略/要点 | 任一争点 `strategy` 与 `response` 非空（`:146`） | 策略被退 → 重定 |
| 3 | 权利要求修改 | 代理师 | 1–7 天 | `claimOriginal` / `claimAmended` | `claimAmended` 非空（`:145`） | 纯争辩 → 仍被阻断 |
| 4 | 答复书 | 代理师 → 企业确认 | 1–3 天 | 陈述草稿 + 确认 + 递交 | `oaStatementConfirmed` 或已批准/授权/归档（`:144`） | 未确认 → 不可递交 |

### 8.2 真实答复工作流（9 步，代码覆盖 4 步）

| # | 动作 | 依据 | 代码 |
|---|---|---|---|
| 1 | 收文、登记发文日与送达方式、算期限 | 细则第四、五条 | ⚠ 手填 |
| 2 | 通读 OA，识别对比文件与法条 | — | ❌ |
| 3 | 逐条拆争点，判定可争辩性 | — | ⚠ 手动录入 |
| 4 | 定策略：争辩 / 缩限 / 删除 / 分案 | 33 条 + 细则第五十七条 | ⚠ 5 选 1，无分案 |
| 5 | 做修改，逐处标说明书依据 | 33 条 | ❌ |
| 6 | 写意见陈述（三段式） | — | ⚠ 模板缺证据段 |
| 7 | 企业确认策略与陈述 | `oa_meta` / `oa_statement` | ✅ |
| 8 | 递交，取回执，写 docket | — | ⚠ 回写语义错 |
| 9 | 等下一通 / 授权 / 驳回 | — | ❌ 无轮次 |

### 8.3 一通的时间窗

D0 为发文日。纸件送达的，推定收到在 D0+15，实际可用时间约 105 天；电子送达的，从进入电子系统之日起算满 4 个月。届满前可申请延期一次（≤2 个月，须缴延期请求费）；届满未答复即视为撤回，之后还有「收到撤回通知起 2 个月」的恢复窗口。产品必须在 D-30 / D-14 / D-7 / D-3 设四个提醒点，并把「是否延期」做成一次显式决策，而不是让它在沉默中过期。

**Docket 回写的实际行为**（`AppContext.tsx:1233-1273`）：

| 项 | 代码 | 应有 |
|---|---|---|
| `ruleId` | `oa1_response`（`prosecution_response` → 固定这一条） | 递交给的是「下一轮」还是「等授权」，不是「新一轮一通」 |
| `triggerDate` | `filedAt`（内部归档日） | 递交日可以，但语义是「等下一轮 OA」 |
| `dueDate` | `filedAt + 4 个月` | 无固定期限；下一轮由官方发文触发 |
| `status` | `'done'` | `upcoming`（或干脆不生成，等官方事件） |
| `title` | 「OA 答复已递交 · <案名>」 | 可以，但需区分轮次 |
| 后续 | 无 | 应生成「等下一轮 OA」的软提醒 + 若终局则授权/驳回分支 |

> 一句话：**当前回写把「答复已递交」记成了一条已经完成的「4 个月答复期限」**。这会让 Docket 页出现一条 done 状态的假期限，同时丢失「正在等下一轮」的真实状态。

**内存态问题**：`fullCheckLiteByCase` 是 `useState`（`AppContext.tsx:470`），刷新即丢；`oaStatementConfirmed` 在 `cases` 里，随 case 持久化（若 case 有持久化策略）。

### 10.1 法定/指定期限

|---|---|---|---|---|

| 复审起诉 | 3 个月 | 收到复审决定之日 | 决定生效 | ❌ |

## 12. 指标（验收尺子）

| 指标 | 定义 | 健康区间 | 说明 |
|---|---|---|---|
| 首通 OA 答复后授权率 | 第一次答复后直接授权 / 总案数 | > 40%（经验值，差异大） | 最核心的质量指标 |
| 平均 OA 轮次 | 从一通到授权/驳回的轮数 | 1.5–2.5 | 越高越贵 |
| **每轮答复成本** | 代理费 + 官费 + 内部工时 | 越低越好 | **能换算成钱** |
| 期限逾期率 | 逾期未答复案件 / 总案件 | 0% | 硬指标，一票否决 |
| 延期使用率 | 申请延期的案件占比 | < 15% | 高 → 内部流转慢 |
| 争点一次克服率 | 本轮答复后被审查员接受的争点 / 总争点 | > 60% | 反映论证质量 |
| 修改幅度中位数 | 独权新增特征数 / 修改案 | 1–2 条 | 过多 = 范围损失 |
| 陈述确认前递交率 | 未确认即递交的次数 | 0 | 合规红线 |
| 平均答复周期 | 收文到递交的工作日数 | < 25 | 与期限配合 |
| **驳回率** | 驳回 / 结案 | < 10% | **能换算成钱**：驳回 = 前序投入全损 + 复审费 |

> 卖点优先讲 **每轮答复成本** 与 **驳回率**：前者是代理所与企业都能立刻算清的账，后者直接对应「前序投入是否打水漂」。

## 13. 产品化切分建议

| 层 | 内容 | 可独立交付 |
|---|---|---|
| L1 收文层 | OA 登记、期限倒计时、多案看板 | 是（最低配，替代 Excel） |
| L2 争点层 | 争点拆解、法条标注、对比文件绑定、状态跟踪 | 是（差异化） |
| L3 修改层 | 权项结构化 diff、33 条出处核对、替换页生成 | 是（**核心卖点**） |
| L4 陈述层 | 三段式生成、证据位、模板库 | 是 |
| L5 程序层 | 轮次、分案、复审、家族视图 | 是（大所与涉外所买单） |

**定价锚点**：按「件/轮」计价（每轮 OA 处理费）最自然；L3 与 L5 可按席位或按家族计价。

**竞品参照系**：国外（Anaqua / Clarivate / Black Hills IP）在 docket 与轮次管理上成熟，但中国法条校验（33 条、57 条、指定期限口径）几乎空白；国内工具多为「代理所内部 OA 流程」，缺少争点结构化与家族视图。**「中国法条校验 + 争点结构化」是空位**。

## 14. 现状差距表

| # | 差距 | 严重度 | 影响 |
|---|---|---|---|
| 1 | 不校验 `draft_claims = filed` 即可进入本节点 | 中 | 无申请即可「答复」，流程可被绕过 |
| 2 | 无 OA 轮次对象（`oaType` 是字符串） | **高** | 无法做多轮管理、无法统计轮次成本 |
| 3 | `deadline` 手填，不由发文日推算 | **高** | 期限错误直接导致视为撤回 |
| 4 | 期限基准日写死 `DEMO_ANCHOR` | 中 | 演示之后所有案都显示逾期 |
| 5 | `oaStatementConfirmed` 案级布尔，不随轮次重置 | **高** | 第二轮可未经确认即递交 |
| 6 | `oa_meta` 只校验当前激活争点 | **高** | 多争点时闸门形同虚设 |
| 7 | `claims_amended` 硬必填，堵死纯争辩 | **高** | 合法策略无法执行 |
| 8 | 递交回写生成假期限且标 done | **高** | Docket 数据失真 |
| 9 | 无修改超范围（33 条）检查 | **高** | 法律风险敞口 |
| 10 | 无「针对通知书指出的缺陷」约束 | 高 | 修改可能不被接受 |
| 11 | 争点无法律依据、对比文件、状态字段 | 高 | 无法复盘、无法复用 |
| 12 | 实用性 / 形式缺陷并入 `other` | 中 | 统计与策略失真 |
| 13 | 陈述模板缺证据段 | 中 | 创造性答复质量上限受限 |
| 14 | 无分案申请 | 高 | 权项被要求删除时无法止损 |
| 15 | 无驳回 → 复审 → 诉讼链路 | 高 | 案件在最关键处断流 |
| 16 | 无延期、无恢复权利、无终止态 | 高 | 期限管理只剩「提醒」 |
| 17 | 无送达方式与节假日顺延 | 中 | 期限计算系统性偏差 |
| 18 | `fullCheckLite` 内存态、刷新丢失 | 中 | 演示可接受，交付不可 |
| 19 | 角色芯片非真鉴权 | 中 | 交付前必须替换 |
| 20 | 无真实 OA 文件流入（仅 seed） | 高 | 产品化必须对接收文 |

**优先补的三件事**（投入产出比排序）：

1. **期限计算内核 + 轮次对象**（差距 2、3、4、17）。理由：期限错一次就是「申请没了」，是唯一会直接造成不可逆损失的缺陷；轮次对象同时解决统计与「下一轮」回写。
2. **修改边界检查（33 条 + 57 条）**（差距 9、10）。理由：把代理师脑子里最专业的一条判断变成可执行、可追溯的检查，是这类产品最难被替代的地方。
3. **闸门入参改为「全部争点」+ `claims_amended` 改为条件必填**（差距 6、7）。理由：两处都是小改动，但直接修复「界面承诺了、闸门没做到」的信任问题。

## 15. 术语表

| 术语 | 含义 |
|---|---|
| OA / 审查意见通知书 | Office Action，审查员指出缺陷并要求答复的官方文件 |
| 指定期限 | 官方在个案中指定的答复期限，法律不统一规定天数 |
| 一通 / 后续 OA | 第一次审查意见通知书 / 第二次及以后 |

| 复审 | 对驳回决定不服，向复审和无效审理部请求重新审查，3 个月 |
| 视为撤回 | 逾期不答复导致申请失去效力（可恢复） |
| 恢复权利 | 在丧失权利后一定期限内请求恢复，须缴费 |
| 延期请求 | 在指定期限届满前请求延长，须缴费，每次 ≤2 个月 |
| 33 条边界 | 修改不得超出原说明书和权利要求书记载的范围 |
| 针对通知书指出的缺陷 | 答复阶段修改的范围限制（细则第五十七条） |
| 分案申请 | 从原申请中分出另一件申请，保留原申请日 |
| 替换页 | 修改后提交的权项/说明书页面 |
| 争点 | 通知书中指出的一个独立缺陷单元 |
| `oa_meta` | 批准策略前的闸：争点类型 + 策略要点 |
| `oa_statement` | 授权/递交前的闸：陈述已确认 |
| 陈述确认 | 「答复草稿」变为「已确认陈述」的分界动作 |
