# 节点 00 · 发明交底（Invention Disclosure）· 产品级业务规格

## 0. 一句话讲清这个节点

**发明交底：把「做过什么」写成后面能检索、能撰写的交底包——这里不拍板要不要申请。**

| | |
|---|---|
| **目的** | 技术事实 → 可交接材料；权属、署名、奖酬依据、公开时点在此定死 |
| **谁做** | 发明人写事实；部门审核人初审；IPR 勾建议并批准交底包（法务会签权属例外） |
| **交出什么** | 已批准的 `disclosure_pack`（六项技术 + 四组事实）+ 一份是否值得往下走的**建议**（非决议） |
| **下一站** | [01 查新](01-research.md)；正式发明点在交底完成且检索后确认（见 [00b](00b-invention-point-chain.md)）。Go/No-Go 在 [02](02-decision.md) |

### 白话摘要

交底书用发明人的技术语言，回答三件事：要解决什么问题、怎么做、有什么效果。读者是 IPR 和代理人，不是审查员。交底写不清，后面检索、撰写、答复、维权都要还债。要不要申请、申请什么类型，**建议在此、终裁在立项（02）**。

下文 §1 起是完整规格（六项、四组、判据与规则）；先读本表即可知道本站在主链上干什么。

## 1. 核心作用

工程师做出新东西之后，这一步把技术事实收成一份下游能用的交底包（`disclosure_pack`）。它是技术事实进主流程的入口。交底不是审查程序里的一个阶段。

交底书是发明人用自己的技术语言，把做过的事告诉后面写申请的人。读者是知识产权负责人和代理人。交底书按三元组写，不按说明书章节排列，也不代替说明书。

交底写不清，后面检索、撰写、答复、维权都要还债。

交底书要说清的是一个三元组：要解决的技术问题、技术方案、有益效果。三块必须咬住：方案解决的就是这个问题，效果是这个方案做出来的。交底书要回答的就是这三块。落笔见 §3.1。三元组说不清，六项齐了也没用。交底书的上限，就是这件专利的上限。

要不要申请，这里不拍板。本节点只交一份评分建议。做不做检索、立项做还是不做，都不在这里定。Go/No-Go 是立项做还是不做，决定权在立项（02）。总纲 §7 的 D1（要不要申请）落在立项，用这一份建议，不在交底里再判一次。节点索引把 D1 和 D2（D2 是申请什么类型）放在 02。两处用同一份分数。

这一步不出检索报告，也不出科技查新报告。检索报告在 01，按可核验文献判断新颖性、创造性。新颖性是：申请日前没有同样的技术方案，须单篇公开全部技术特征才丧失。创造性是：相对现有技术并非显而易见。科技查新报告是另一份：由科技部或教育部认定的查新机构回答国内外有没有相同或类似研究报道，典型结论是「未见相同报道」，口径比新颖性宽，审查员不采信。

## 2. 要说清楚什么

批准时过两关。技术上六项都为真。另外四组事实定死。四组不计入六项，也不要改成七项。齐套按这六项计 `n/6`。

发明人提交提报单时，不要求六项已经齐。六项和四组在批准交底包时卡死。交底完成还须发明人确认初稿，IPR 只勾一条建议并批准。全文判据在 §4。

六项仍是批准计数。其中要说清的是三元组。其余项是让这三块站得住。写法在 §3.1，不是六项的另一种数法。

### 2.1 六项技术

六项只计技术。字段表在 §8.2。

**问题。** 现有做法缺在哪。要解决的到底是哪件事。

**方案。** 实际怎么做。哪些事实删掉，这个问题就解不了。删掉还解得了的，不是必要事实。删除测试用来挑必要技术事实。例子在 §3.1。

**效果。** 这个方案做出来以后发生了什么变化，和什么比。发明人知道的数据和对比就写上。没有现成数据，写清观察到的变化。不要编数据。

三块必须咬住：方案解决的就是这个问题，效果是这个方案做出来的。三元组在六项里计 `structure` 一项，不拆成三个齐套项。必要特征另计 `features` 一项。

三元组要立住，批准时其余技术项也必须同时为真：类型当场确认、至少一个真实例子、发明人印象中的最接近现有技术、缺口两类。四组事实见 §2.2，不计入六项。

1. **专利类型当场确认**（`patent_type`）。发明、实用新型、外观设计必须显式选定。实用新型保护产品的形状、构造。外观设计保护产品外观。表上默认发明，不算通过。这里记下的类型，立项还可以再定最终类型。D2 在 02。

2. **三元组**（`structure`）。要说清的就是上面三块：要解决的技术问题、技术方案、有益效果。方案解决的就是该问题，效果由该方案产生。

3. **必要技术特征**（`features`）。就是上面方案里，删掉就不解决技术问题的事实。六项里单独计这一项。例子在 §3.1。

4. **至少一个真实例子**（`embodiments`）。参数、材料、条件，是发明人做过或能说清的做法。后面写申请的人不用编造事实。

5. **发明人印象中的最接近现有技术，至少一条**（`prior_art_1_1`）。写清是什么：产品、论文、展会，或写不知道。现有技术是申请日以前公众能够得知的技术。这是印象，不是检索报告，也不是科技查新报告。口径见 §1。公开号可空，空着不是缺项。写了怎么才算数，见 §3.2。

6. **缺口分两类**（`gaps`）。`blocking` 是不补就不能往下写申请。`non_blocking` 是可以后补。前一类还在，不能批准。下文把前一类简称「不补就不能写」。

候选发明点不另设齐套键。它就是 `features` 里的必要特征，加上 `structure` 里的效果，加上 1.1 印象。正式发明点在交底完成且检索之后确认，见 00b。

### 2.2 四组事实

四组不计入六项。缺了不能批准。法条在 §10，这里写判据。

**权属。** 字段 `employment`、`conclusion`。发明人填写在职、离职未满 1 年，或外部或兼职。部门审核人做初判。结论是职务、非职务、未决之一。没有结论，不能批准。未决、离职未满 1 年、外部合作，必须法务会签。该会签而法务未通过，不能批准。职务发明是执行本单位任务，或主要利用本单位资金、设备、零部件、原材料、不对外公开的技术资料完成的发明。离职、调离或劳动关系结束后 1 年内作出的，若与原单位本职或原单位交办的任务有关，仍可能是职务发明。跳槽后 11 个月提交的，原单位仍可能主张权利。

**署名。** 字段 `inventors[]`：每名发明人写姓名，并写明对实质性特点作出的贡献。贡献为空，或只写「参与讨论」「提供设备」，不能列入。只负责组织、提供物质条件方便或其他辅助工作的人，不是发明人。名单由发明人填写并确认。IPR 不能代加。署名随申请提交后，更正很困难。

**奖酬依据。** 字段 `rule_version` 或 `agreed_amount`。本节点只登记依据，不发钱。有规章记规章版本；有约定记约定金额；都没有则记法定底数：一件发明不低于 4000 元，一件实用新型或外观设计不低于 1500 元。依据空缺，不能批准。发放时点是授权公告日起 3 个月内。不在立案时登记，也不拖到授权才登记。金额按 2023 年修订的实施细则，对外引用前对照当期官方文本复核。⚠

**公开时点。** 字段 `disclosed`、日期、`grace`、`foreign_plan`、`made_in_china`。发明人填写是否公开、公开日期。IPR 核定 `grace`，取其一：未公开、四种情形之一、或不适用。已公开但情形空着，不能批准。宽限期是特定情形公开后 6 个月内申请仍可不丧失新颖性。申请日以前 6 个月内，四种情形不丧失新颖性：国家紧急状态或非常情况下为公共利益首次公开；在中国政府主办或承认的国际展览会上首次展出；在规定的学术会议或技术会议上首次发表；他人未经申请人同意泄露。不适用只锁定事实。还申不申请，写入建议，交给立项。建议只按 §4.5 的分数勾一条。本节点不因此终止。

宽限期是补救：已经公开的，这 6 个月内还可能救，但要在提出申请时声明，并自申请日起 2 个月内提交证明。申请日前已知他人擅自泄露的，在知晓后 2 个月内声明。公开日是这 6 个月的起算点。声明和证明在申请时办，不要求在本次批准前办完。建议仍只按 §4.5 的分数勾。

保密审查是在中国完成的发明或实用新型向外国申请前，须经国家知识产权局审查。有向外国申请的计划时，必须标明技术是否在中国完成（`made_in_china`）。未标明，不能批准。未做保密审查就向外国申请、再在中国申请的，可以不授权，也可以成为无效理由。手续在向外国申请前办完即可，不要求在本次批准前办完。手续未完成，阻断的是向外国申请，不是本次交底批准。

字段与判据：

| 组 | 字段 | 谁填 | 不闭合就不能批准 |
|---|---|---|---|
| 权属 | `employment`：在职 / 离职未满 1 年 / 外部或兼职。`conclusion`：职务 / 非职务 / 未决 | 发明人填就业状态；部门审核人确认；未决、离职未满 1 年、外部合作必须法务会签 | 无结论，或该会签而法务未通过 |
| 署名 | `inventors[]`：姓名 + 实质贡献 | 发明人填写并确认名单 | 贡献为空，或只写「参与讨论」「提供设备」。IPR 不得添加发明人 |
| 奖酬依据 | 有规章则 `rule_version`；有约定则 `agreed_amount`；都没有则记下法定底数（发明 ≥ 4000 元，实用新型或外观 ≥ 1500 元）⚠ | IPR 登记 | 依据空缺。本节点不发放。发放时点仍是授权公告日起 3 个月 |
| 公开时点 | `disclosed`（是/否）、日期、`grace`（未公开 / 四种情形之一 / 不适用）、`foreign_plan`、`made_in_china` | 发明人填事实；IPR 核定 `grace` | 已公开但 `grace` 空着；有海外计划但未标是否在中国完成。保密审查手续在向外国申请前办完，不要求在本次批准前办完 |

法务认定「事实已清楚，但不归本单位」：权属按非职务定死，不因此终止交底。建议仍按 §4.5 勾选，交给 02。法务认定「还判断不了」：退回补充，不能批准。

## 3. 怎么说清楚

按三元组写，用发明人能写出来的技术语言。批准时数的是 §2.1 的六项。

### 3.1 三元组怎么落笔

三块紧挨着写。方案解决的就是这个问题，效果是这个方案做出来的。只写结果不写做法，例如「通过智能识别优化」，没有信号、判据、阈值，说不清。没有现成数据，写观察到的变化。不要编数据。

电池组工程师小陈：

**问题。** 现有电池判断热失控，缺在不能提前。要解决的就是提前判断热失控。

**方案。** 用单体电压变化率与温度变化率的比值做故障判据，提前判断。

**效果。** 按这个比值做出来以后，观察到的变化，和现有判断比。

**真实例子。** 至少一个。参数、材料、条件，是发明人做过或能说清的做法。后面写申请的人据此写，不用编造事实。

必要事实从这条方案里标。口径在 §2.1。

逐个删掉一条事实，问：删掉这条，问题还解不解得了？

- 解不了 → 必要技术事实，记入必要技术特征。
- 还能解 → 不是必要事实。

**正例。** 比值是必要事实。删了，提前判断热失控就不成立。

**反例。** 「使用 ResNet-50 模型。」换个模型也能判断。具体模型名不是必要事实。

### 3.2 最接近现有技术另列

1.1 是发明人印象，用来衬出「现有做法缺什么」。它不是三元组的第四块，也不是检索结论。检索报告、科技查新报告的口径在 §1。单独列出，是为了挡住两件事：把印象当成检索结论，以及编一个公开号凑齐套。没挡住，下游从零检索，或把假号写进后面的申请文件。

1. **印象可以没有公开号。** 写清产品、论文、展会或「不知道」即可。无号不是缺项。
2. **有公开号就必须打得开。** 打不开，该条作废，改记无号印象。禁止编造。
3. **检索从这里起步，但不把这里的文字抄成结论。** 01 另出可核验命中。
4. **自家尚未公开的申请，标成内部资料，不能写成现有技术。**

业务上无号可以通过。规则见 R00-13。

## 4. 怎么保障说清楚

保障的是技术事实说清了，三元组咬住了：方案解决的就是这个问题，效果是这个方案做出来的。不是说明书的表格填满了。

助手只出初稿。助手不能代确认，不能批准，不能把印象写成检索结论，不能在材料为空时装成完成。

发明人必须确认问题、方案、效果、必要技术特征、真实例子、1.1 和署名。未确认，不能批准。

IPR 是批准交底包的知识产权人员。IPR 核对后批准。六项为真、四组事实定死、没有「不补就不能写」的缺口、发明人已确认、建议已勾，才能批准。批准即交底完成。IPR 不能改已确认的技术事实，不能添发明人，不能把建议写成已经决定申请。

权属未决、离职未满 1 年、外部合作，必须法务会签。该会签没通过，不能批准。法务不能改技术方案，不能批准齐套。

没说清，走退回补充，并列缺项。退回的典型是只写结果不写做法：「通过智能识别优化」，没有信号、判据、阈值。部门审核人、IP 受理人或 IPR 都可以退回。退回后只有发明人能改完重提，不能绕过发明人直接回到部门审核。退回补充不是决定不申请。

批准后发现写不出来：由发现方提请 IPR 撤回批准，再走退回补充。交底完成取消。不另设状态。

评分建议另算。勾一条建议，是交给立项看要不要申请，不是用来证明已经说清楚。建议没勾，仍然不能批准。

**交底完成 = 六项技术齐套（六项都为真），并且权属、署名、奖酬依据、公开时点四组事实已经定死，发明人已确认初稿，IPR 只勾一条建议并批准。** 缺了不能批准。立案早于完成。要不要申请不在这里定。

提报单是发明人交上去的流程单，表示报了一个想法。上面有发明名称、发明人、部门，并显式选择公开状态：未公开，或已公开并写上日期。还要选择立案路由（`targetStage`）。它不是 §4.5 按分数勾的那一条建议（申请发明 / 建议申请 / 技术秘密或防御性公开 / 不申请）。单据经过草稿、已提交、部门审核、受理、已立案。退回后可以修改再交。撤回、与已有单合并、或确认涉密转出，进入终止。已立案只说明组织受理了，不说明交底已经完成。

受理是组织收下提报单，决定立案或退回。

案件是受理通过时新建的在办事项。标题写成「原名称（研发交底）」，归发明人所在部门，发明人先记提报人。有公开风险日，风险标高，下一期限用该日期；没有，风险标中，期限按 14 天计。此时交底包仍是 `drafting`，还在整理，不能拿去写申请文件。

立案是受理通过并生成案件编号。立案早于批准。立案把想法变成有编号的在办事项，交底包仍在整理。

交底包是整理好、交给下游的材料。要解决的问题、方案、效果要写上；哪些事实删掉就不成立；至少一个真实例子；发明人知道的最接近做法；还缺什么，缺的那些挡不挡往下写申请。权属、署名、奖酬依据、公开时点定死。发明人自己确认过。IPR 勾一条建议并批准。下游用的是这一包。

提报单是「报了」。案件是「受理了，有编号了」。交底包是「批准了，可以往下交」。

### 4.1 谁按什么顺序做

没有权属风险时，法务那一步跳过，不空等。完成判据以 §4.2 为准。第 6 步是发明人确认初稿。

1. **发明人**提交提报单。名称、至少一名发明人、部门、公开状态，缺了停在草稿。进入部门审核之后不能直接改，只能等退回，改完再交。逐人写明实质贡献。他可以撤回。撤回后本件不再做交底。他不能批准，不能立案，不能把初稿点成已批准。

2. **系统**把单子送进部门审核队列。入队不做判断。审核人没分配，不得显示为已审核。

3. **部门审核人**确认四件事：技术是否真实、权属初判、是否涉密、与本部门生意的相关度（`biz_score`，1–5 分）。四项都有记录，才转受理。材料不够则退回，并写明理由。确认涉密则终止普通交底。他不能立案，不能批准交底包，不能在这里决定申不申请。

4. **IP 受理人**决定收不收。收了就立案，生成案件，交底包仍在整理。不收则退回。与已有交底重复则合并，关掉的那件终止，并指向留下的那件。他不能代替发明人写技术事实，不能批准齐套。

5. **助手**（步骤表里的 Agent）出结构化初稿。助手只出初稿：把口语整理成问题、方案、效果和必要技术特征，把发明人说的最接近做法整理成印象，并标出缺口。缺口分成「不补就不能写」和「可以后补」。不能代替发明人确认，不能批准，不能把印象写成检索结论，不能在材料为空时装成完成。

6. **发明人**确认初稿中的问题、方案、效果、必要技术特征、真实例子、1.1 和署名。未确认，不能批准。

7. **法务**只在三种情况会签：离职未满 1 年、外部合作、权属未决。该会签而没有通过，不能批准。法务认定事实已清楚、但不归本单位：权属按非职务定死，交底继续，不因此终止。法务认定还判断不了：退回补充，不能批准。法务不能改技术方案，不能批准齐套。职务发明的口径在 §2.2。

8. **IPR** 批准交底包。他核对六项技术与四组事实，把部门的商业相关度原样抄进评分，自打其余五维，勾唯一一条建议，然后批准。六项为真、四组事实闭合、没有「不补就不能写」的缺口、发明人已确认、建议已勾，才能批准。批准即交底完成。他不能改发明人确认过的技术事实，不能添加发明人，不能把建议写成已经决定申请。

退回满 3 次，由 IP 负责人督办。IP 负责人与 IPR 不是同一步。督办是盯着办完，不是批准，也不是终止。

专利委员会在本节点不开会，不打分，不做决议。代理所是受托办理专利的外部机构，只能查看协作状态，不能做部门审核、受理或批准。

角色不能做的细表在 §7；谁有权决定在 §7.1。

### 4.2 步骤与责任人

| 步 | 谁 | 做什么 | 完成判据 | 失败则 |
|---|---|---|---|---|
| 1 | 发明人 | 提交提报单 | R00-01、R00-46 | 停在草稿 |
| 2 | 系统 | 进入部门审核队列 | 审核人已分配 | 不分配则不得显示为已审核 |
| 3 | 部门审核人 | 确认技术真实、权属初判、涉密、`biz_score` | 通过转 IP 受理 | 材料不足 → 退回发明人。涉密 → `已终止` / `secret_patent` |
| 4 | IP 受理人 | 立案 | 生成案件，包 = `drafting` | 不予受理 → 退回发明人。重复 → `已终止` / `merged` |
| 5 | Agent | 出结构化初稿 | 有草稿，且未标已确认、未标已批准 | 空材料不得装完成 |
| 6 | 发明人 | 确认问题、方案、效果、必要技术特征、真实例子、1.1 和署名 | `tech_confirmed_at` 有值 | 不确认则 IPR 不能批准 |

### 4.3 发明人确认

人工确认与建议同样缺了不能批准，不计入六项。

| 项 | 谁 | 判据 |
|---|---|---|
| `ai_draft` | Agent | 只出初稿 |
| `tech_confirmed_at` | 发明人 | 确认问题、方案、效果、必要技术特征、真实例子、1.1 和署名 |
| `biz_score` | 部门审核人 | 商业相关度 1–5。IPR 抄入评分卡，不得改 |
| `recommendation` | IPR | §4.5 勾唯一一条 |
| `approved_by` / `approved_at` | IPR | 六项为真、四组闭合、无 `blocking` 缺口、发明人已确认、建议已勾 |

发明人确认：问题、方案、效果、必要技术特征、真实例子、1.1 和署名，由发明人认账。助手只出初稿，不能把初稿标成已确认。

### 4.4 三个出口

一次只走一个。三个出口是：退回补充、交底完成交下游、终止交底。建议去向不是第四个出口。

| 出口 | 落在哪 | 谁 | 何时 | 禁止混用 |
|---|---|---|---|---|
| 退回补充 | 提报 `退回`；包离开 `approved` | 部门审核人、IP 受理人，或 IPR | 材料或四组事实不够，还要发明人改 | 不是不申请 |
| 交底完成，交下游 | 包 `approved`，§4 闭合 | IPR | 六项为真、四组事实闭合、发明人已确认初稿、无 `blocking` 缺口、§4.5 已勾一条建议 | 不是立案。包交给下游。00b 初审决定进不进 01；02 用这份建议做 D1 |
| 终止交底 | 提报 `已终止` | 发明人，或部门审核人，或 IP 受理人 | 理由只允许 `withdrawn`（发明人撤回）、`merged`（IP 受理人合并）、`secret_patent`（部门审核人确认涉密，转出普通流程） | 不是不申请，不是技术秘密（不走专利、靠保密来保护），不是防御性公开（主动把技术公开，使同样方案以后难以再被授权） |

同一次退回只有一个责任人：实际点退回的部门审核人、IP 受理人或 IPR。见 §11.1。

不申请、转技术秘密、防御性公开只写在 `recommendation` 里，随「交底完成」交给 02。02 可以据此 No-Go，不把提报改成 `已终止`。

下游在批准后发现写不出来：由发现方提请 IPR 撤回批准，走退回补充，交底完成取消。不另设状态。

退回满 3 次：升级到 IP 负责人督办（盯着办完，不是批准；场景见 §16）。升级不是终止。

立案之后材料不够，提报从 `已立案` 退回补充，见 §11.1。批准后发现写不出来，撤回批准再退回。

**退回补充的情形。** 小陈只写「通过智能识别优化电池」，没有信号、判据和阈值。做法没说清，退回并列出缺项。法律后果见 §10.6。IPR 不能批准。退回后只有发明人能改完重提，不能绕过发明人直接回到部门审核。退回补充不是决定不申请。

**交底完成的情形。** 小陈的比值判据、真实例子、印象中的最接近做法写清了，权属和署名贡献已定，奖酬依据已登记，技术尚未公开，他已确认，IPR 勾了「建议申请发明」并批准。此时包交给下游。批准是交底完成，不是立案。

**终止的情形。** 两个部门把同一套比值判据各报一次。IP 受理人合并，被关掉的那张单终止，并指向留下的那件。终止不是不申请。

**写在建议里的情形。** 上个月展会已经公开。先按 §2.2 锁定是否公开、公开日期、宽限情形（未公开 / 四种之一 / 不适用）。不适用只锁定事实。还申不申请写入建议。建议只按 §4.5 的分数勾一条。本节点不因此终止。

### 4.5 评分建议

只勾一条建议。建议是下面这张卡。这是建议，不是决定。勾建议是交给立项看要不要申请，不是用来证明已经说清楚。

交底的终点是 §4 的交底完成。立案早于完成。要不要申请不在这里定。

这里只产出一份评分建议，随已批准的包交给 02。02 用这一份做 D1，不另打一套分。专利委员会不在本节点开会。

参考行业专利委员会通行的三维，加上法务三性中的新颖性、创造性，合并为六维。三性是新颖性、创造性、实用性这三项的合称。新颖性、创造性的口径见 §1。实用性是能够制造或使用，并且产生积极效果。本表「新颖性/创造性」只用前两项。实用性不是交底批准条件。

| 维度 | 权重 | 打分问题 | 1 分 | 5 分 |
|---|---|---|---|---|
| 新颖性/创造性 | 25% | 与 1.1 最接近现有技术的差异是否明显 | 已被完全公开 | 明显区别且非显而易见 |
| 商业价值 | 25% | 是否落在主营产品/核心收入路径上 | 边缘试验 | 直接对应主力产品 |
| 可检测性（侵权可发现） | 20% | 竞争对手用了，能否从外部发现并取证 | 纯内部工艺，无法取证 | 体现在可拆解的产品特征上 |
| 保护广度 | 15% | 能否用较少特征覆盖较大范围 | 只能锁死一个具体实现 | 可覆盖多种实现方式 |
| 战略布局 | 10% | 是否填补布局空白 / 阻碍对手 | 与布局无关 | 关键卡位 |
| 生命周期成本 | 5% | 全球申请 + 维持 20 年的总成本是否可承受 | 成本远超价值 | 成本可忽略 |

**总分 → 建议去向**（全文只此一套。02 沿用这些阈值。本表不是 §4.4 的出口）：

| 分数 | `recommendation` | 交给 02 的建议 |
|---|---|---|
| ≥ 4.0 | `file_invention` | 建议申请发明。理由可注明「建议评估海外」。海外布局不在本节点决定 |
| 3.0–3.9 | `file_choose_type` | 建议申请。类型先用已确认的 `patent_type`（含外观）。最终类型是 02 的 D2 |
| 2.0–2.9 | `trade_secret` 或 `defensive_publication` | 必须二选一。禁止两条同时成立 |
| < 2.0 | `no_file` | 建议不申请，并写理由。提报状态仍是交底完成，不是 `已终止` |

`trade_secret` 是技术秘密：不走专利，靠保密来保护。`defensive_publication` 是防御性公开：主动把技术公开，使同样方案以后难以再被授权。两条都只写在建议里，不是本节点的出口。

打分责任：商业相关度一维只抄部门审核人的 `biz_score`，IPR 不得改。其余五维由 IPR 打。新颖性一维必须标 `evidence = impression`（未经检索）。检索之后若要改分，由 02 追加调整记录，不回头重开一份评分卡。

转化率只在 §17 定义一次。

**建议必须留痕。** 每条建议记录：六维分、总分、`recommendation`、填写人（IPR）、日期、理由，以及被抄入的 `biz_score` 和部门审核人。02 的决议另记，不覆盖这条原文。

### 4.6 交给下游

交底完成之后，初审决定进不进检索，不改交底是否完成。立项用这一份建议决定要不要申请。

## 6. 边界与上下游

### 6.1 在生命周期中的位置

```
研发活动 ──► 【交底】 ──交底完成──► 00b 初审 ──► 检索(01) ──► 立项(02) ──► 撰写(03) ──► …
                │                      │
                │                      └── 初审可以不进检索，把同一份建议直接交给 02
                └── disclosure_pack（IPR 批准才算完成；立案早于批准）
```

IPR 是批准交底包的知识产权人员。立案是受理（组织收下提报单）通过后生成案件编号，早于批准。图中的初审在交底完成之后，只决定进不进检索，不改交底是否完成。

- **无 `StageId`（主轴上的阶段编号）**：它是轴外入口，不占专利阶段主轴上的一格。交底把技术事实注入主轴，本身不是一个专利阶段。
- **产物键**：`disclosure_pack`。
- **立案路由**：`targetStage ∈ {'pre_research', 'decision'}`。立案时按这个路由建案。它不是 §4.5 按分数勾的建议。它不决定做不做检索，也不决定 Go。下游改阶段，不必重做交底。
- **壳与路由（原型落点）**：workbench :5174 → `/inventor`。

### 6.2 它是什么 / 不是什么

| 是 | 不是 |
|---|---|
| 技术事实的**结构化记录** | 法律文件（申请文件） |
| 撰写申请文件的**原料** | 权利要求（划定保护范围的文字）的草稿（可以有建议，但不是正式权项，即还不是已定稿的权利要求） |
| 权属、署名、奖酬依据、公开时点的**定死留痕** | 奖酬发放（发放在授权公告日，即授权对外公布之日起 3 个月） |
| 发明人对最接近现有技术的**印象**（`prior_art_1_1`） | 检索报告（检索在 01；正式发明点在检索之后，见 00b） |
| 交给立项的**一份评分建议** | 要不要申请、Go/No-Go（决定权在 02，用这一份建议，不另打一套分） |

1.1、检索报告、科技查新报告、新颖性、创造性的口径在 §1、§2.1。三元组落笔在 §3.1。交底不产出这两份报告。

> 最容易错的是写成论文摘要，或按 §9 的八块写交底。要写的是三块咬住。

## 7. 角色不能做什么

| 角色 | 代码对应 | 能做什么 | 不能做什么 |
|---|---|---|---|
| 发明人 | `inventor` persona | 填技术事实、逐人写贡献、确认 Agent 初稿、撤回本件 | 不能批准、不能立案、不能把初稿点成已批准 |
| 部门审核人 | `actingAs: 'dept'` | 确认技术真实、权属初判、涉密、商业相关度；通过则转 IP 受理；不通过则退回 | 不能立案、不能批准交底包、不能做 D1 |
| IP 受理人 | `actingAs: 'ip'`（立案） | 受理并立案、不予受理则退回、合并重复单、涉密转出时终止普通交底 | 不能代替发明人写技术事实、不能批准齐套 |
| IPR | `actingAs: 'ip'`（批准） | 核对六项与四组事实、抄录部门的商业相关度、勾一条建议、批准交底包 | 不能改发明人确认过的技术事实、不能添加发明人、不能把建议写成已 Go |
| 法务 | — | 仅在离职未满 1 年、外部合作、权属未决时会签 | 不能改技术方案、不能批准齐套 |
| 专利委员会 | `committee` persona | 本节点无动作 | 不在本节点打分或决议。D1 在 02 |
| 代理师（代理所承办人） | `agency` | 只读协作交底状态 | 不能做部门审核 / IP 受理 / 批准 |
| 系统 Agent | `agent-disclosure` | 出结构化初稿、抽特征、把发明人印象整理进 1.1、标缺口 | 不能把印象写成检索结论；不能确认初稿；不能批准；不能空材料装完成；不能改立项报价 |

**当前实现的权限真相**（务必对实习生讲清，避免误以为是真鉴权）：

- 角色切换是**同一登录下的角色芯片**（`actingAs: 'dept' | 'ip'`），不是真实身份认证。
- 非企业工作区（代理所）整块只读，文案：「代理所工作区仅可查看协作交底状态（只读）。部门审核 / IP 受理请切换企业租户。」
- 真实产品必须换成 RBAC（按角色授权）+ 租户隔离；这条列在 §19 差距表。

### 7.1 决策权（谁决定要不要申请）

§7 回答「谁能做什么」。本节回答「谁说了算、说了算多大」。

交底是整条链上唯一一个发明人、部门、IP、法务四方同时在场的节点，也是「要不要申请」这条决策的**材料生产地**。材料在这里生产，拍板不在这里。把这两件事混成一件，是本节点最常见的越权。

#### 7.1.1 四种权能，不得合并

| 权能 | 含义 | 本节点谁持有 | 系统要求 |
|---|---|---|---|
| 建议权 | 提方案，不产生约束力 | 发明人（提报、确认技术事实、书面意见）、部门审核人（`biz_score`、权属初判）、Agent（初稿）、IPR（六维分与一条建议） | 建议可被驳回，驳回须写理由；建议不得被改写成决定 |
| 决定权 | 拍板，并对结果负责 | IPR（交底是否完成）、IP 受理人（收不收、合并谁）、IP 总监与专利委员会（D1 / D2，在 02） | 决议记录：决定人 + 时间 + 依据 |
| 否决权 | 单方面叫停已决定的事 | 法务（权属、涉密、保密审查）、财务（预算超限） | 一票否决，书面理由，进审计清单 |
| 知情权 | 必须被告知，不参与决策 | 业务部门、发明人、HR（离职与奖酬）、财务（成本） | 通知与订阅，不阻断流程 |

#### 7.1.2 三条界线（背下来）

| 常见误解 | 错在哪 | 正确口径 |
|---|---|---|
| 「发明人报了，就该申请」 | 把建议权当决定权 | 发明人**只能建议**。他可以提报、可以确认技术事实、可以书面坚持，但不能决定是否申请，也不能决定申请什么类型。是否申请由 02 按 §4.5 的同一份分数拍板 |
| 「IPR 批了，说明这件有价值」 | 把齐套判定当商业判断 | IPR 批准只证明**技术事实说清楚了**（六项齐套 + 四组事实闭合 + 发明人已确认）。商业价值一维来自部门审核人的 `biz_score`，IPR 只抄不改；值不值得申请，是 02 的事 |
| 「业务着急，先找代理所报上去」 | 绕过 IP 部门 | 业务部门有**知情权与主张权**：可以提要求、可以书面反对、可以在 02 陈述意见。但提报入口只有一个，不得绕过 IP 部门直接向代理所或专利局提报 |

> 一句话：**建议权与决定权必须分离，且分离要在系统里看得见**（签字、留痕、不可代签）。分离失败时，冲突不是被解决了，是被掩盖了。

#### 7.1.3 D1 与 D2 在本节点的位置

本节点不拍板 D1，也不定 D2 的最终类型。总纲把 D1、D2 放在 02，本节点只交同一份建议（§4.5）。但 D1 需要的**全部决策材料**在这里产生：六维分、`biz_score`、公开事实、权属结论、齐套结论。所以本节点真正决定的是「这份材料够不够格进入 D1」，不是 D1 本身。

| 决策 | 建议者 | 决定者 | 否决者 | 知情者 | 依据 | 级别 |
|---|---|---|---|---|---|---|
| D1 要不要申请 | IPR（六维分 + 一条建议）、发明人书面意见 | IP 总监；重大件报专利委员会。**拍板在 02** | 法务（权属 / 合规）、财务（预算） | 业务部门、发明人 | §4.5 分数 + 01 检索结果 | L4 |
| D2 申请什么类型 | 发明人当场选、IPR 核对 | 本节点只记录 `patent_type`；最终由 IPR / IP 总监在 02 定 | — | 业务部门 | 显式选定，默认发明不算通过；实用新型限产品形状、构造 | L2 |
| 交底是否完成 | Agent 出初稿、部门审核人给 `biz_score` | IPR | 法务（权属未决时） | 发明人、IP 受理人 | §4 全部条件满足 | L2 |
| 勾哪一条建议 | IPR | IPR | — | 02、业务部门 | §4.5 阈值，四档只勾一条 | L2 |
| 立案 / 不受理 / 合并 | IP 受理人 | IP 受理人 | 部门审核人（涉密时先终止） | 发明人、部门 | 重复检测、涉密结论 | L2 |

**D1 的负面清单**：命中任一条，不得进普通申请通道。这不是「不建议」，是「不得」。

| 情形 | 处置 | 谁定 |
|---|---|---|
| 自己公开已超 6 个月 ⚠ | 只可建议防御性公开或不申请；仍坚持申请的，须书面风险告知 + L4 | IP 总监（在 02） |
| 技术事实编造、无研发过程证据 | 不得申请（非正常申请） | 系统硬阻断 |
| 权属归他人（含前雇主）且未获授权 | 不得以本单位名义申请 | 法务 |
| 涉密、未转保密程序 | 不得走普通申请 | 部门审核人 + 保密办 |
| 明显超出本单位研发能力与资源条件 | 不得申请（非正常申请特征） | IPR + 法务 |
| 检索后确认已属现有技术 | 不申请；转防御性公开评估 | 02 |

#### 7.1.4 支撑决策：署名、权属、公开、保密、齐套

这五件事不是流程动作，是决策。它们各自有一个「谁说了算」。

| 决策 | 建议者 | 决定者 | 否决者 | 知情者 | 依据 | 级别 |
|---|---|---|---|---|---|---|
| 发明人署名 | 发明人集体列名并逐人写贡献 | 发明人确认；有争议时由法务 + HR 共同认定 | 法务（署名不实） | HR、IPR | 细则第十四条：只认创造性贡献 | L3 |
| 权属认定（职务 / 非职务 / 未决） | 部门审核人初判 | 法务会签定论 | 法务本身即把关方；IP 总监可升级 | HR、财务 | 专利法第六条、细则第十三条 | L3 |
| 公开事实与宽限归类 | 发明人申报事实 | IPR 核定 `grace` 归类；**事实本身由发明人负责** | 法务（隐瞒公开即触红线） | 02、业务部门 | §2.2、§10.4 | L3 |
| 是否触发保密审查 | IPR 依 `foreign_plan` × `made_in_china` 判定 | 法务 / 合规 | 法务一票否决 | IP 总监、业务 | 专利法第十九条 | L4 |
| 齐套不合格：退回还是特批 | IPR | `blocking` 缺口只能退回；`non_blocking` 缺口 IP 负责人可特批 | 法务（权属组不适用特批） | 发明人、部门 | §4、R00-15、R00-59 | L3 |

**三处不能含糊**：

1. **署名。** 名单由发明人确认，IPR 不得代加、不得代删。贡献为空或只写「参与讨论」「提供设备」的，不得列入。有争议时，IPR 既不裁决也不和稀泥，直接转法务 + HR；争议未决不得递交申请。
2. **权属。** 部门审核人只做初判，不能自行下「职务」或「非职务」的结论。离职未满 1 年、外部合作、权属未决三种情形，法务会签未通过就不能批准。
3. **公开。** 发明人申报的是事实，IPR 核定的是归类。IPR 不能替发明人「认为没公开」，也不能把「已经公开」改成「未公开」。已超宽限期的，照实记录，再在建议里体现。

#### 7.1.5 分级：按不可逆性 × 金额

| 级别 | 条件 | 本节点对应动作 | 谁批 | 留痕 |
|---|---|---|---|---|
| L1 | 可逆 + 低金额 | 勾齐套项、退回补充、受理 | 经办人（IPR / IP 受理人） | 系统记录 |
| L2 | 可逆 + 高金额 | 勾建议、选立案路由、记录 `patent_type` | 部门主管 / IPR | 审批流 + 理由 |
| L3 | 不可逆 + 低金额 | 撤回批准、合并终止、署名认定、`grace` 归类 | 双人复核（发起人 ≠ 批准人） | 双签 |
| L4 | 不可逆 + 高金额 | D1 拍板、保密审查结论、涉密转出、超宽限期仍申请 | 高层 + 双人复核 | 双签 + 决议纪要 |

本节点不直接花钱，花的是下游检索、撰写、申请与维持的预算。金额阈值按商务线（12）配置，产品里必须可配，文中不写死数字。⚠ 阈值一律以企业授权制度为准，不得硬编码。

#### 7.1.6 交底阶段哪些动作不可逆

| 动作 | 为什么不可逆 | 本节点内会不会发生 | 必须具备 |
|---|---|---|---|
| 公开技术（论文、展会、发布会、客户演示、供应商沟通） | 一经公开，新颖性永久丧失（宽限期只救四种法定情形） | 会，而且在系统外发生 | 发明人申报日期；IPR 归类 `grace`；L3 留痕 |
| 递交申请 | 申请日锁定，内容不得超范围修改 | 不会（在 03 / 04） | 交底已批准；涉外的保密审查已办 |
| 对外披露（向合作方、客户、供应商展示方案） | 可能构成公开，也可能构成泄密 | 会，而且在系统外 | NDA 前置；涉密不走普通流程 |
| 对外承诺（保证授权、保证不侵权、承诺授权率） | 无法收回，且触红线 | 会 | 任何层级都不得批 |
| 撤回批准 / 合并终止 | 交底完成取消，须重走退回补充 | 会 | L3 双签，并写明理由 |

**产品含义**：这五类动作不得提供「一键执行」。公开与递交尤其不能由本节点触发——本节点只负责把事实和日期记准，让下游知道还剩多少时间。⚠

## 8. 对象字段

实习生最大的理解障碍是：**交底有两个状态机，长得像，含义完全不同。**

### 8.1 第一层：提报单 `InventionDisclosure`

发明人视角的「我提了一个想法」，是流程单据。

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | string | 系统 | `d-<ts>` |
| `title` | string | ✅ | 发明名称 |
| `inventor` | string | ✅ | 发明人（当前是单字符串，真实产品须为数组，见 §19） |
| `dept` | string | ✅ | 部门，也是立案后的 `ownerTeam` |
| `tech` | string | — | 技术方案自由文本（当前实现只有这一个正文字段） |
| `techTheme` | string? | — | 技术主题，对齐立项 intake 的 `techTheme` |
| `patentType` | `PatentType`? | — | 默认「发明」 |
| `contact` | string? | — | 联系人，缺省「待填写」 |
| `riskDate` | string | — | **公开风险日**：已知的论文/展会/客户演示/供应商沟通日期 |
| `targetStage` | `'pre_research' \| 'decision'` | ✅ | 立案路由。不是 §4.5 的建议去向 |
| `status` | `DisclosureStatus` | 系统 | 见 §11 |
| `submittedAt` | string | 系统 | |
| `caseId` | string? | 系统 | 立案后回填 |
| `timeline` | `DisclosureTimelineEntry[]` | 系统 | 每次状态变化一条 |

### 8.2 第二层：交底包 `disclosure_pack`（齐套校验对象）

这是**办理交接**用的产物，不是提报单的字段。它有 6 个 REQUIRED 键（`DISCLOSURE_PACK_CHECK_ITEMS`，`packages/domain/src/handoff.ts:49`）：

| 键 | 中文标签 | 真实含义 | 合格线 |
|---|---|---|---|
| `patent_type` | 专利类型（默认发明） | 发明 / 实用新型（保护产品的形状、构造） / 外观设计（保护产品外观） | 必须显式确认，不能「默认就算过」 |
| `structure` | 结构化技术披露（问题/方案/效果） | 三段闭环 | 三段必须能对上：方案解决该问题、效果由方案产生 |
| `features` | 必要技术特征 | 删掉就不解决技术问题的技术事实 | 每条都不可缺少。删掉，要解决的技术问题就解不了 |
| `embodiments` | 真实例子 | 至少一个真实例子。原型标签仍叫实施例 | 至少一个带参数、材料或条件、发明人做过或能说清的例子 |
| `prior_art_1_1` | 现有技术 1.1 | 发明人对最接近现有技术的印象 | 至少一条，写清是什么。不是检索结果。公开号可空；写了公开号就必须带能打开的 url，编造的号作废 |
| `gaps` | 缺口清单（阻塞 / 非阻塞） | 还缺什么才能往下写申请 | 必须区分 `blocking`（不补就不能往下写申请） / `non_blocking`（可以后补） |

> **六项只计技术齐套。** 早期文档写过「7 项齐套」，是错的。不要把权属、署名、奖酬、公开时点塞进这六项，也不要因此改成七项。这四组是 §2.2 的批准条件：不计入 `n/6`，缺了照样不能批准。

### 8.3 第三层：案件 `PatentCase`

`advanceDisclosure(id, '已立案')` 触发 `addCase()`，映射关系：

| 案件字段 | 取值来源 |
|---|---|
| `title` | `${d.title}（研发交底）` |
| `stage` | `d.targetStage` |
| `type` | `d.patentType ?? '发明'` |
| `ownerTeam` | `d.dept` |
| `inventor` | `d.inventor` |
| `risk` | `d.riskDate ? '高' : '中'` |
| `nextDeadline` | `d.riskDate`，否则 +14 天 |
| `fulfillmentMode` | `'self_serve'`（交底阶段不派所） |
| `handoffs.disclosure_pack` | `{ status: 'drafting', note: '待结构化交底包…' }` |
| `summary` | 拼接 techTheme / tech / riskDate / contact |

**业务含义**：立案 = 从「想法」变成「有编号的在办事项」，但**此时交底包还是 `drafting`**。**立案 ≠ 交底完成。** 交底完成只看 §4。

### 8.4 完成契约放在 §4

批准条件不在这里再列一遍。六项字段见 §8.2。四组事实见 §2.2。发明人确认、一条建议见 §4。缺了不能批准。

## 9. 下游写说明书时查阅

交底书不按这个交。

| # | 说明书里的块 | 审查员在问什么 | 撰写时的口径 |
|---|---|---|---|
| 1 | 名称 | 主题是否清楚 | 不超过 25 个字。不用商标、人名、夸张词。「一种革命性的…」要初审补正。初审补正是国家知识产权局形式审查要求改正文件，不是 00b 的初审分流 |
| 2 | 技术领域 | 分类落在哪 | 写「本发明涉及……技术领域」。不过宽，例如「电子技术」。不过窄，例如「某型号电池的某工位」。写成产品线名，分类号会错。分类号是技术分类编号 |
| 3 | 背景技术 | 最接近的现有技术，和它的缺陷 | 缺陷与要解决的问题对应。贬低对手，或写进自家未公开技术，创造性论证没有靶子 |
| 4 | 发明内容·要解决的技术问题 | 这个目的能否被实现 | 一句话说清。目的写成「提高竞争力」，无法判断能否实现 |
| 5 | 发明内容·技术方案 | 是否清楚、完整，本领域技术人员能否实现 | 写全必要特征。只写结果不写做法，说明书公开不充分。后果见 §10.6 |
| 6 | 发明内容·有益效果 | 效果有没有支撑 | 撰写时通常要对比基线和数据。交底时发明人没有现成数据，不在交底里编 |
| 7 | 具体实施方式 | 权利要求有没有说明书支持 | 至少一个能复现的做法，可以再写变体。只写「实施例一：如图」，权利要求会写得比说明书宽（专利法第二十六条第四款） |
| 8 | 附图说明 | 图和文字是否对得上 | 结构图或流程图。标号与文字一一对应。放渲染图，或在图上标尺寸，理解成本高，容易出错 |

删除测试在交底里用来挑必要技术事实，见 §3.1。下游写权利要求时，才决定哪些事实进独立权利要求、哪些进从属权利要求。独权是独立权利要求，一项里保护范围最大的那项。从权是从属权利要求，写在独权后面，保护范围更窄。

## 10. 法律

法律口径以《专利法》（2020 修正）与《专利法实施细则》（2023 修订，2024-01-20 施行）为准，凡金额/条号均标 ⚠ 需按当期官方文本复核。

这一节是交底产品的**护城河**：市面上的表单工具做不到，因为它们不懂法。缺了不能批准的字段在 §2.2。本节不另立出口。

### 10.1 职务发明认定（专利法第六条 + 实施细则第十三条）

**规则**：执行本单位任务，或主要利用本单位物质技术条件完成的发明创造，为职务发明，申请专利的权利属于单位。

实施细则第十三条明确三种「执行本单位任务」：

1. 在本职工作中作出的；
2. 履行本单位交付的本职工作之外的任务作出的；
3. **退休、调离原单位后，或劳动、人事关系终止后 1 年内**作出的，与其在原单位承担的本职工作或原单位分配的任务有关的。

**产品落点**：

- 交底表单必须采集「发明人当前是否在职 / 是否离职未满 1 年 / 是否兼职或临时工作单位人员」。
- 「本单位」**包括临时工作单位**；「物质技术条件」指资金、设备、零部件、原材料、**不对外公开的技术资料**。
- 离职未满 1 年的交底，系统应自动打**权属风险旗标**，并强制法务会签。

> 这条最容易出事：员工跳槽后 11 个月提交的专利，原单位可以主张权属，哪怕新单位也参与了。

### 10.2 发明人署名（实施细则第十四条）

**规则**：发明人是指**对发明创造的实质性特点作出创造性贡献**的人。仅负责组织工作、为物质技术条件利用提供方便、或从事其他辅助工作的人，**不是**发明人。

**产品落点**：

- 交底必须逐人填写**具体贡献**，而不是只列名字。
- 贡献描述为空，或只写「参与讨论」「提供设备」：不得列入发明人。IPR 不能代为添加。
- 署名一旦随申请提交，后续更正极其困难（需办理著录项目变更，即改正申请上记载的发明人等事项，并举证）。

### 10.3 奖励与报酬（专利法第十五条 + 实施细则第九十二、九十三条）

**规则**：

- **约定/规章优先**：单位可以与发明人约定，或在依法制定的规章制度中规定奖励、报酬的方式和数额（第九十二条）。国家鼓励股权、期权、分红等产权激励。
- **法定兜底**（第九十三条）：无约定也无规章时，应自**授权公告日起 3 个月内**发放奖金；一项发明专利奖金**不低于 4000 元**，实用新型或外观设计**不低于 1500 元**。若发明创造源于发明人的建议被单位采纳，应从优发给。⚠ 金额按 2023 修订文本
- **报酬**（区别于奖金）：细则不再设固定比例；2010 版曾规定的「实施后按营业利润 2% / 0.2%、许可费 10%」等比例已被删除，无约定时实务多参照《促进科技成果转化法》给予合理报酬。⚠ 需按当期文本复核

**产品落点**：

- **批准交底时**登记奖酬依据（发明人、专利类型、规章版本或约定金额、法定底数）。立案时交底尚未完成，不在立案时登记，也不要等授权才登记。
- 系统应能算「若按法定兜底，本件应发多少」，给 HR/财务一个底数。
- **奖金发放时点 = 授权公告日 + 3 个月**，这条应进 docket（期限台账；当前未建，见 §19）。

### 10.4 保密与新颖性宽限（已经公开的，法定情形下 6 个月内申请仍可不丧失新颖性；专利法第二十四条）

**规则**：申请日以前 6 个月内，下列情形**不丧失新颖性**：

1. 国家出现紧急状态或非常情况时，为公共利益目的**首次公开**的（2020 年修法新增）；
2. 在中国政府主办或承认的**国际展览会**上**首次展出**的；
3. 在**规定的学术会议或技术会议**上**首次发表**的；
4. **他人未经申请人同意而泄露**其内容的。

**程序要求**：主张宽限期须在**提出申请时于请求书中声明**，并自申请日起 **2 个月内**提交证明材料；若申请日前已知晓他人未经同意泄露，应在知晓后 2 个月内提交声明。

**产品落点**：

- 是否公开、公开日期、宽限情形按 §2.2 锁定。不适用只锁定事实。还申不申请写入建议。建议只按 §4.5 的分数勾一条。本节点不因此终止。
- 宽限情形是四种之一时，`riskDate` 是宽限期倒计时起点。系统应显示：「距 6 个月宽限期届满还有 N 天」。申请时声明、2 个月内交证明。不要求在交底批准前办完。倒计时不是建议去向。
- 宽限期是补救。已经公开的，这 6 个月内还可能救，但要在申请时声明并交证明，而且只救这 6 个月内的公开。

### 10.5 保密审查（专利法第十九条）

**规则**：任何单位或个人将**在中国完成的**发明或实用新型向外国申请专利的，应当**事先**报经国务院专利行政部门进行保密审查。违反规定向外国申请后再在中国申请的，**不授予专利权**——且构成无效理由（他人可据此请求宣告该专利权无效）。

**产品落点**：

- 交底表单必问：「是否有海外申请计划？技术是否在中国境内完成？」
- 有海外计划 → 必须标明，并标明技术是否在中国境内完成。缺标记不得批准。保密审查手续在向外国申请前完成；手续未完成的向外申请硬阻断。不要求在交底批准前办完手续。
- 这条对跨国企业/有出海业务的公司是刚需，也是「产品级 vs 表单级」的分水岭。

### 10.6 充分公开（专利法第二十六条第三款）

交底没写的做法，说明书补不进来，审查答复也不能补。

合格线仍用 §3：有没有把做法说出来（信号、判据、阈值）。

### 10.7 非正常申请（《规范申请专利行为的规定》，2024，局令第 77 号）

**规则**（承接 2021 年《关于规范申请专利行为的办法》）：不以保护创新为目的、不以真实发明创造活动为基础，为牟取不正当利益或虚构创新业绩而提交专利申请的，属非正常申请。典型情形包括：

- 多件内容明显相同；
- 明显抄袭现有技术/现有设计；
- 不同材料、组分、配方、部件、结构或步骤的**简单替换、拼凑**；
- **编造、伪造、变造**发明创造内容、实验数据或技术效果；
- 发明创造与申请人、发明人的**实际研发能力及资源条件明显不符**。

**产品落点**：

- 这是「禁止空材料装完成」这条产品纪律的法律根据。
- 系统应记录**研发过程证据**（实验记录、样机、测试报告），并在交底与「研发能力画像」明显不匹配时提示。
- KPI（考核指标）不能只考核「申请量」——那正是非正常申请的诱因。见 §17。

### 10.8 企业知识产权合规体系（GB/T 29490-2023）

**规则**：GB/T 29490-2023《企业知识产权合规管理体系要求》（2023-08-06 发布，2024-01-01 实施，替代 2013 版）对**立项、研发、采购、生产、销售、售后**各环节提出知识产权管理要求；立项环节要求对项目涉及的知识产权进行分析（检索、侵权风险）。

**产品落点**：

- 交底流程是这套体系认证的**必备证据链**之一。卖产品时可以直说：「用这个系统，认证时的研发环节记录自动生成。」
- 这也是面向国企/上市公司的销售话术支点。

## 11. 两个状态机

### 11.1 第一层：提报状态机 `DisclosureStatus`

```
草稿 ──► 已提交 ──► 部门审核 ──► IP受理 ──► 已立案
  ▲                    │            │          │
  └──── 退回 ◄─────────┴────────────┴──────────┘
  草稿、已提交、部门审核、IP受理、退回、已立案
                └──► 已终止（撤回 / 合并 / 涉密转出）
```

**业务迁移**（谁做见下表；`已立案` 不是终态，也不是交底完成）：

| 当前 | 可迁往 | 谁 |
|---|---|---|
| `草稿` | `已提交`、`已终止` | 发明人提交；发明人可撤回 |
| `已提交` | `部门审核`、`已终止` | 系统入队；发明人可撤回 |
| `部门审核` | `IP受理`、`退回`、`已终止` | 部门审核人 |
| `IP受理` | `已立案`、`退回`、`已终止` | IP 受理人 |
| `退回` | `已提交`、`已终止` | 只允许发明人重提或撤回 |
| `已立案` | `退回`、`已终止` | 退回补充：部门审核人、IP 受理人或 IPR。终止：发明人撤回，或 IP 受理人合并 |
| `已终止` | — | 终态 |

`退回 → 部门审核` 在业务上禁止。

批准后发现写不出来，仍是撤回批准再退回。终止只限撤回、合并、涉密转出。

**每一步的业务含义与责任角色**：

| 迁移 | 谁做 | 业务含义 | 出口条件 |
|---|---|---|---|
| 草稿 → 已提交 | 发明人 | 交给组织 | 名称、至少一名发明人、部门、公开状态已显式选择（含「未公开」） |
| 已提交 → 部门审核 | 系统 | 入队，不做判断 | 部门审核人已分配 |
| 部门审核 → IP受理 | 部门审核人 | 技术真实、权属已初判、不涉密、`biz_score` 已填 | 四项都有记录 |
| 部门审核 → 退回 | 部门审核人 | 材料不足，还要发明人改 | 结构化退回理由 |
| 部门审核 → 已终止 | 部门审核人 | 涉密，普通交底停止 | 理由 `secret_patent` |
| IP受理 → 已立案 | IP 受理人 | 建案。包仍是 `drafting` | 生成 `PatentCase`，回填 `caseId` |
| IP受理 → 退回 | IP 受理人 | 不予受理 | 结构化理由 |
| IP受理 → 已终止 | IP 受理人 | 与已有交底合并，本件关闭 | 理由 `merged`，并指向保留件 |
| 已立案 → 退回 | 部门审核人、IP 受理人或 IPR | 材料或四组事实不够，退回补充。批准后发现写不出来，IPR 撤回批准再退回 | 结构化退回理由 |
| 退回 → 已提交 | 发明人 | 改完重提 | 带版本。禁止不经发明人直接回到部门审核 |
| 任一非终态 → 已终止 | 发明人 | 撤回，本件不再做交底 | 理由 `withdrawn` |

原型迁移表（`AppContext.tsx:2061`）与上表不一致，只作落点记录：`草稿` 可到 `已提交`/`退回`；`已提交` 可到 `部门审核`/`退回`；`部门审核` 可到 `IP受理`/`退回`；`IP受理` 可到 `已立案`/`退回`；`已立案` 被写成终态；`退回` 可到 `已提交`/`部门审核`。原型没有 `已终止`。

**当前实现的偏差（必须在文档里点名，避免实习生照着错的理解做）**：

1. `submitDisclosure` 直接写入 `status: '部门审核'`，**跳过了 `已提交`**，但 timeline 里又补了「已提交」这一条。→ 状态机与时间线不一致。
2. `退回 → 部门审核` 允许直接跳，等于退回后可以不经发明人修改就重新进审核。
3. `草稿` 态在 UI 上不可达（一提交就是部门审核）。
4. 退回**没有理由字段**，只有 timeline 的 note 字符串。
5. 退回后重新提交**没有版本/diff**，看不出改了什么。

→ 这 5 条全部进 §19 差距表。

### 11.2 第二层：交底包状态机 `handoff`

这是通用 7 态交接机（`packages/domain/src/handoff.ts` 的 `TRANSITIONS`）：

```
drafting → submitted_to_enterprise → enterprise_review → approved → authorized_to_file → filed
                    ↕                        ↕
              changes_requested  ◄───────────┘
```

**它与提报状态机的关系**：

- 提报状态机管「这张单走到哪了」；
- 交底包状态机管「这份材料能不能交给下游用」。
- **立案时交底包仍是 `drafting`** —— 这是最容易混的一点。立案只是开了案，材料还没整理。

**下游阻断**（`guardrails.ts`）：

- `go_nogo`（立项决策）被 `disclosure_approved` 阻断：「交底包未批准：须 disclosure_pack 为已批准/授权/归档后方可 Go」。
- `draft_claims` 路径的 `approve / authorize / file / submit` 全部被 `disclosure_approved` 阻断。
- `disclosure_pack` 自身的 `approve` 被 `disclosure_pack` blockers 阻断：6 项未齐 → `交底包未齐套（n/6）· 缺项见 ConfirmBar`。

**`disclosureApproved()` 的判定口径**：`approved` / `authorized_to_file` / `filed` 三者之一。注意 **`submitted_to_enterprise` 和 `enterprise_review` 都不算批准**。业务上的批准还要满足 §4，不只是六项为真。

### 12.7 例外情形

规则说「不得」，业务上总有人要问「什么情况下可以」。不给合法出口，用户就会绕过系统线下做，反而失去留痕。本节只收**有依据的例外**，不收「客户强烈要求」。

例外来源只有三类：**法定例外**（宽限期、恢复权利等，内置为规则，不做成特批按钮）、**合同例外**（合作、许可条款约定，法务批）、**内部例外**（企业自定，按级别批）。

| # | 例外 | 来源 | 例外条件 | 谁批准 | 风险 | 留痕 |
|---|---|---|---|---|---|---|
| E1 | 发明人坚持提报，但评分明显无价值 | 内部 | 总分 < 2.0 ⚠（阈值可配）或 IPR 判断无商业路径，发明人书面坚持 | IP 总监 + 发明人书面意见；不得由 IPR 单独放行 | 占用检索与撰写预算；转化率被拉低；若为凑数还可能触非正常申请 | 必留：发明人坚持理由书 + IPR 反对意见 + 决议人 + 后续复盘时点 |
| E2 | 部门审核超时未处理 | 内部 | 超过部门审核 SLA（建议 5 个工作日 ⚠）且审核人无响应 | IP 负责人代核；涉密与权属两项**不得**代核，缺这两项仍须等或升级 | 技术真实性与权属初判被跳过，后续法务兜底成本上升 | 必留：催办记录 + 代核范围声明 + 原审核人事后追认 |
| E3 | 交底后才发现已公开超 6 个月 | 法定（宽限期已过） | 自行公开已超 6 个月 ⚠，或不属于四种法定情形 | 不适用特批。IP 总监在 02 决定是否仍申请（L4）+ 书面风险告知 | 新颖性已丧失，申请必败；官费与代理费沉没；可能构成对客户的误导 | 必留：公开事实与日期、`grace = 不适用`、风险告知书签署、02 决议 |
| E4 | 发明人离职或失联，无法确认署名 | 内部 | 已尽力联系（建议 3 次、覆盖 2 种以上渠道 ⚠）仍无回应 | 法务 + HR 共同认定署名；IPR 不得自行增删名单 | 署名不实是无效理由之一；后续著录项目变更举证极难 | 必留：联系记录、HR 在职/离职证明、认定依据、名单版本 |
| E5 | 外部合作方要求共同申请 | 合同 | 合作协议或委托开发合同约定共有，或对方以出资、提供实质性技术条件主张共有 | 法务终审 + 业务负责人会签（L4） | 权属不清影响后续许可、维权、无效应对；单方处分可能违约 | 必留：合同条款原文、出资或贡献证据、共有方式（按份/共同）、处分规则 |
| E6 | 涉密技术不得走普通流程 | 法定（保密专利程序） | 涉及国家安全或重大利益，需按保密专利程序办理 | 部门审核人确认涉密 + 保密办复核；走 `已终止` / `secret_patent` | 走普通流程即泄密；转出后本节点不再持有技术细节 | 必留：涉密认定结论、认定人、转出去向、知悉范围清单 |
| E7 | 同一技术重复提报 | 内部 | 标题相似度 > 0.9 ⚠，或必要特征高度重合 | IP 受理人合并；被关件走 `已终止` / `merged` 并指向保留件 | 重复申请可能构成非正常申请；两部门各自推进导致口径不一 | 必留：相似度比对结果、保留件编号、合并理由、双方部门确认 |
| E8 | 交底涉及前雇主技术（离职未满 1 年） | 法定（权属规则） | 发明人离职未满 1 年 ⚠，且技术与原单位本职工作或原任务有关 | 法务会签，未通过不得批准；结论只允许职务 / 非职务 / 未决 | 原单位可主张权属；已投入的研发与申请费用可能全部损失；可能引发诉讼 | 必留：离职日期、原单位工作内容说明、法务意见、会签记录 |
| E9 | 齐套未达标，但外部时点已到 | 内部 | 展会、论文投稿、客户验收等固定时点在前，`blocking` 缺口无法在时点前补齐 | 不适用特批。**`blocking` 缺口不得特批**；只能加速补齐，或由 02 决定改走防御性公开 | 带病交底进入撰写，返工率与公开不充分风险同时上升 | 必留：时点证明、缺口清单、加速记录；若改走防御性公开，记 02 决议 |

**例外的三条纪律**：

1. **例外不是豁免**：每条须记录批准人、时间、理由、有效期；只对本案生效，不做全局开关。
2. **例外率要可统计**：E2（审核超时）与 E9（时点压迫）占比异常升高，说明 SLA 定错了，应改 SLA 而不是继续特批。
3. **红线不可例外**：见 §12.9。不设特批入口，系统硬阻断。

### 12.8 规则冲突与裁决

规则之间会打架。不预先给出裁决顺序，执行时就会由「谁声音大」决定。

**六组真实冲突**：

| # | 冲突 | 典型表现 | 裁决 | 裁决人 |
|---|---|---|---|---|
| C1 | 发明人要报 vs IPR 认为无价值 | 评分 1.7，发明人认为「这是核心技术」 | **两条线分开走**：发明人的主张进入建议附件（保留原话），IPR 的分数不改；是否申请由 02 用同一份分数决定。不得把分数改高来平息争议，也不得压着不报 | IPR 出分，02 决定；分歧留痕 |
| C2 | 业务要保密 vs 合规要求留痕 | 业务担心交底内容外泄，要求不上系统、只口头沟通 | **留痕优先**。可缩小知悉范围、可加密、可只留摘要与哈希，但不得无记录。无记录的交底不予受理 | 法务（合规）一票否决；IP 负责人执行 |
| C3 | 赶时间先提交 vs 齐套未达标 | 客户演示在即，`features` 还缺，业务要求「先递上去再补」 | **先补再递**。`blocking` 缺口不得带病递交；时间不够只能走 E9 的正规路径（加速补齐或改防御性公开），不得「先递后补」——申请日一锁，内容不得超范围修改 | IPR 拒绝批准；争议升级 IP 总监 |
| C4 | 发明人署名争议 vs 申请期限临近 | 两人争第一发明人，递交窗口只剩几天 ⚠ | **争议未决不得递交**。期限压力不构成虚列的正当理由；可先按已确认名单推进，争议部分另行认定，但不得为赶期限随意增减 | 法务 + HR 认定；IP 总监对期限风险签字 |
| C5 | 多部门争同一发明权属 | 两个部门都主张是本部门立项产出 | **按事实归属，不按职级或嗓门**：看任务来源、资源投入、研发过程证据。争议期间照常立案，但不得以任一方名义递交 | 法务定权属，业务负责人会签；未决则标 `未决` |
| C6 | 宽限期将过 vs 技术方案仍未完善 | 距 6 个月届满只剩数周 ⚠，`embodiments` 还不全 | **期限优先，但不得编造**。先按现有真实材料提交，能补的实施例在申请日前补；不能补的记入缺口并书面告知风险。禁止为赶期限编数据 | IP 总监 + 发明人风险确认 |

**裁决顺序（无法自行消解时，自上而下适用）**：

| 序 | 原则 | 含义 | 例外 |
|---|---|---|---|
| 1 | **法定优先于约定** | 宽限期、保密审查、权属规则、署名规则不可被内部流程覆盖 | 法定例外本身是规则的一部分，不是破例 |
| 2 | **合规优先于效率** | 涉密、权属、留痕要求高于业务节奏 | 无。红线不设例外 |
| 3 | **不可逆优先于可逆** | 公开、递交这类不可逆动作，优先获得决策资源与时间 | — |
| 4 | **期限优先于质量** | 有法定死线的先做，质量在其后 | 不得以期限为由编造事实或虚列署名 |
| 5 | **一致优先于局部最优** | 同一发明的分数、类型、权属口径在全链统一 | 单案特殊情况由 02 书面说明并占用组合额度 |
| 6 | **专业判断与商业判断分离** | 技术事实听发明人，可专利性听检索与代理师，值不值得做听 02 | 任一方越界，另一方有否决权 |
| 7 | **书面留痕优先于口头一致** | 任何偏离上述顺序的决定，须有书面理由 | — |

**无法裁决时怎么办**（三步，缺一不可）：

| 步 | 做什么 | 落到哪 |
|---|---|---|
| 1 | **升级**：提交给上一级决策者（IPR → IP 总监 → 法务分管 / 总经理） | 升级记录，含时限 |
| 2 | **留痕**：记录双方意见、各自依据、最终决定人。系统支持「意见分歧」状态，不强迫达成一致 | 分歧记录，不可编辑，只能新建版本 |
| 3 | **免责**：专业意见（法务、检索人、代理师）必须书面提出，并明确「已告知风险」 | 风险告知书 + 签署 |

> **最重要的一条**：C4 这类冲突不能靠「谁职级高」解决。署名是法律事实，不是管理安排；期限是管理事实，不是法律依据。把两者混成一个签字，结果是交底带着署名瑕疵进入申请，而瑕疵在授权后几乎无法补救。
>
> 记录分歧比假装一致更有价值——诉讼、审计、无效程序里，这份记录就是证据。

| R00-71 | 系统须支持「意见分歧」状态；分歧记录不可编辑，修改须新建版本并保留原版 | ❌ |

### 12.9 红线（任何批准都不得突破）

| ID | 红线 | 为什么 | 系统处置 |
|---|---|---|---|
| R00-80 | 编造、伪造 `prior_art_1_1` 的公开号或公开内容 | 诚信问题，构成非正常申请；假号会流入申请文件 | 硬阻断，无特批入口 |
| R00-81 | 虚列、增删发明人以换取利益或平息争议 | 侵犯署名权，且构成无效风险 | 硬阻断，只能由法务 + HR 按 E4 认定 |
| R00-82 | 隐瞒已知的公开事实（展会、论文、销售、演示） | 新颖性已丧失，申请必败，且构成欺诈风险 | 硬阻断，不得把「已公开」改为「未公开」 |
| R00-83 | 编造、变造实验数据或技术效果 | 违法；非正常申请的典型情形 | 硬阻断 |
| R00-84 | 伪造研发过程证据（实验记录、样机、测试报告） | 违法 | 硬阻断 |
| R00-85 | 对外承诺「保证授权」「保证不侵权」或承诺授权率 | 法律上不可能保证；诱导非正常申请 | 文案与话术层拦截 |
| R00-86 | 未经保密审查直接向外申请，或未标 `made_in_china` 即放行涉外 | 可导致中国不授权，并构成无效理由 | 硬阻断向外申请路径，本节点批准不受影响（§10.5） |

> **这七条不是「高风险」，是「不可做」。** 系统不提供特批入口，也不提供「我已了解风险，继续」的按钮。任何一条被触发，交底停在当前状态，由人工按 §12.7 的合法路径处理。

## 13. 放行

`evaluateGuardrails` 是唯一放行入口，任何 UI 都必须过它。

| 闸门 / blocker | 触发条件 | 文案 | 位置 |
|---|---|---|---|
| `disclosure_pack` | `kind === 'approve'` 且走交底路径且 6 项未齐 | `交底包未齐套（n/6）· 缺项见 ConfirmBar` | `guardrails.ts:293` |
| `disclosure_approved` | Claims 路径的 approve/authorize/file/submit 且交底未批准 | `交底包未批准 · 请先交底整理/门户` | `guardrails.ts:312` |
| `disclosure_approved`（Go） | `go_nogo` 且交底未批准 | `交底包未批准：须 disclosure_pack 为已批准/授权/归档后方可 Go` | `guardrails.ts`（research/decision 段） |
| `persona` | 当前 Persona 不可执行该动作 | 按 `personaBlocksHandoffAction` | `guardrails.ts:251` |
| `enterprise` | 非企业执行企业专属闸 | `仅企业可批准` 等 | `guardrails.ts:262` |

**在门户侧的二次校验**：`InventorPortal` 的 `HandoffActionBar.validateBefore` 对 `approve/authorize/file` 再跑一次 `evaluateGuardrails`，「以更严为准」。这是有意的双保险，不是冗余。

业务上的批准比上表更严：六项之外，还须 §2.2 的四组事实，以及 §4 的发明人确认和一条建议。原型闸门目前只拦六项。

## 15. 期限

### 15.1 法律期限（硬）

| 期限 | 长度 | 起算 | 后果 |
|---|---|---|---|
| 新颖性宽限期 | 6 个月 | 首次公开日 | 超期 → 公开成为现有技术，不可专利 |
| 宽限期声明与证明 | 申请时声明 + 2 个月提交证明 | 申请日 | 未声明 → 视为不主张 |
| 他人泄密的声明 | 2 个月 | 知晓或应当知晓泄露之日 | 同上 |
| 保密审查 | 事先 | 向外国申请前 | 违反 → 中国不授权 + 无效理由 |
| 奖金发放 | 3 个月 | 授权公告日 | 逾期 → 违约/违法风险 |

### 15.2 业务 SLA（软，可配置）

部门审核 5 工作日 / IP 受理 3 工作日 / 结构化 2 工作日 / 补齐 10 工作日。

### 15.3 与 docket 引擎的关系

**当前 docket 的 7 条规则（`oa1_response`、`oa_subsequent`、`application_fee`、`substantive_exam_request`、`grant_registration`、`annuity`、`pct_national_entry`）全部在立案之后**。交底阶段零期限管理。

**待补的两条**：

- `disclosure_dept_review`（部门审核 SLA）
- `disclosure_novelty_grace`（`grace` 为四种之一时，公开日起 6 个月倒计时。不是建议去向）

## 16. 失败场景

| # | 场景 | 正确处置 | 现状 |
|---|---|---|---|
| 1 | 发明人填了 3 个字就提交 | 没有发明人或没有公开状态：不能提交。过了提报层但六项不齐或四组事实不闭合：IPR 不能批准，退回并列出缺项 | ⚠ 提报层只校验 2 个必填 |
| 2 | 部门审核通过，但发明人印象里方案已被公开 | 先按 §2.2 锁定是否公开、公开日期、宽限情形（未公开 / 四种之一 / 不适用）。不适用只锁定事实。还申不申请写入建议。建议只按 §4.5 的分数勾一条。本节点不因此终止 | ❌ 无建议字段 |
| 3 | 交底里 1.1 编了个公开号 | 该条作废。可改成无号印象后齐套。假号不能通过 | ⚠ 原型正则能挡住一部分假号，也会挡住无号印象 |
| 4 | 发明人下月离职 | 可立案。权属风险未会签前，IPR 不能批准 | ❌ |
| 5 | 已在上月展会公开 | 先按 §2.2 锁定是否公开、公开日期、宽限情形（未公开 / 四种之一 / 不适用）。不适用只锁定事实。还申不申请写入建议。建议只按 §4.5 的分数勾一条。本节点不因此终止 | ❌ |
| 6 | 客户要求先看方案再签合同 | 保密协议前置检查 | ❌ |
| 7 | 同一技术两个部门各提一次 | IP 受理人合并。关闭件走 `已终止` / `merged`，并指向保留件 | ❌ |
| 8 | 立案后发明人要求加名字 | 走著录项目变更，不进交底流程 | ❌ |
| 9 | 交底包批了但下游说写不出来 | `blocking` 缺口本不能批准。若批准后才发现，发现方提请 IPR 撤回批准，走退回补充 | ⚠ 有 `gaps` 字段但无回路 |
| 10 | 代理所要看交底 | 只读协作视图 | ✅ |
| 11 | 交底涉密（军工/涉国家安全） | 部门审核人终止普通交底，理由 `secret_patent`，转保密专利程序 | ❌ |
| 12 | 发明人是外部合作方 | `employment` 记为外部或兼职。法务未会签前，IPR 不能批准 | ❌ |
| 13 | 交底被退回 3 次 | 升级到 IP 负责人 | ❌ |
| 14 | 立案后 6 个月没人管 | docket 提醒 | ⚠ 只有 `nextDeadline` 静态日期 |
| 15 | 发明人已离职，奖金无人认领 | 奖酬台账标记待认领 | ❌ |

## 17. 指标

| 指标 | 定义 | 健康区间 | 说明 |
|---|---|---|---|
| 交底→申请转化率 | 申请数 / 交底完成数 | 20%–40% | 全文只此一个转化率。高于 60% 说明下游评审失效。分母是交底完成，不用提报数，也不用立案数 |
| 齐套一次通过率 | 发明人确认初稿后，IPR 第一次审核即六项为真的比例 | > 60% | 分母不是提报提交。提报提交不要求六项已齐 |
| 平均退回次数 | 每件交底被退回次数 | < 1.2 | 高 → 培训或表单有问题 |
| 部门审核时长 | 中位数工作日 | < 5 | SLA 核心 |
| 立案时长 | 提交到立案中位数 | < 10 工作日 | 端到端效率 |
| 提报完成率 | 交底完成数 / 提报数 | — | 过程量。不设区间，也不叫转化率 |
| 撰写返工率 | 撰写阶段因交底不清退回次数 | < 10% | **最能证明交底价值的指标** |
| 1.1 无编造率 | 写了公开号的条目中，url 能打开的比例 | 100% | 无号印象不进分母 |
| 首通 OA（第一次审查意见通知书）无驳回率 | 一案授权且无实质驳回 | 越高越好 | 滞后指标，但最有说服力 |

> 卖产品时优先讲 **「撰写返工率」** 和 **「首通 OA 无驳回率」**——它们直接换算成钱（代理费 + 时间）。

## 18. 单独交付切分

产品化视角下，这个节点能独立成产品，因为它同时满足三条：

1. **有独立买方**：企业 IP 部门买它做内部提案管理（替代 Excel + 邮件 + 微信群）。
2. **有独立价值**：它直接决定专利质量与授权率，而质量是可以量化考核的（见 §17）。
3. **有独立边界**：它的输入是研发人员，输出是 `disclosure_pack`，不依赖检索、撰写、答复任何下游模块即可交付价值。


如果要把这个节点做成独立产品，建议这样切：

| 层 | 内容 | 是否可独立交付 |
|---|---|---|
| L1 表单层 | 在线交底表单 + 附件 + 进度查询 | 是（最低配，可白牌：贴客户自己的牌子卖） |
| L2 结构化层 | Agent 整理问题/方案/效果/必要技术特征/真实例子 + 缺口标注 | 是（差异化） |
| L3 合规层 | 职务发明、署名、奖酬、宽限期、保密审查、非正常申请 | 是（护城河，法务买单） |
| L4 建议层 | 六维评分 + 一条建议去向 + 留痕。决议在 02 | 建议可随包交付；Go/No-Go 不在此交付 |
| L5 交接层 | `disclosure_pack` 输出到检索/撰写/代理所 | 依赖下游，但可做 API |

**定价锚点**：按「立案数」计价最自然（每件 X 元），或按席位（IP 团队 + 研发提报人）。

**竞品参照系**：Anaqua / CPA Global 的交底模块偏重流程，缺中国法合规；国内表单工具缺结构化与评分。**「中国法合规 + 结构化 + 评分」三件套是空位。**

## 19. 差距

完成条件以 §4 完成契约、§4.4 三个出口为准。下表只记原型还没做到的地方。

| # | 差距 | 严重度 | 影响 |
|---|---|---|---|
| 1 | `submitDisclosure` 跳过 `已提交` 态 | 中 | 状态机与时间线不一致 |
| 2 | `退回` 无结构化理由字段 | 中 | 无法统计退回原因 |
| 3 | `退回 → 部门审核` 允许跳过重提 | 中 | 发明人可绕过修改 |
| 4 | 退回后无版本/diff | 中 | 看不出改了什么 |
| 5 | 无交底阶段 docket（SLA / 宽限期） | **高** | 产品缺口最明显的一块 |
| 6 | 无 §4.5 评分建议。`agent-disclosure` 只做结构化与齐套，不做评分 | **高** | 02 没有唯一一份分数，会另打一套 |
| 7 | 无职务发明/离职 1 年权属检查 | **高** | 法律风险敞口 |
| 8 | 无署名贡献度采集 | 高 | 后续署名纠纷无据 |
| 9 | 无奖酬台账 | 高 | 4000 元兜底与 3 个月时点无法追踪 |
| 10 | 无宽限期倒计时与声明流程 | 高 | 四种情形的 6 个月时钟未建。声明在申请时。不适用不倒计时 |
| 11 | 无保密审查前置 | 高 | 涉外申请可能直接失去专利权 |
| 12 | `gaps` 的 `blocking` 未做硬阻断 | 中 | 带病交底可批准 |
| 13 | 齐套勾选无留痕 | 中 | 无法审计 |
| 14 | 发明人字段是单字符串 | 中 | 不支持多发明人署名 |
| 15 | 无相似交底去重 | 低 | 重复提报 |
| 16 | 无批量导入 / 创新活动直转交底 | 低 | 大规模落地阻力 |
| 17 | 角色芯片非真鉴权 | 中 | 演示可接受，交付不可 |
| 18 | 非企业工作区整块只读，无代理协作写权限 | 低 | 代理所无法补材料 |

**优先补的三件事**（按投入产出比）：

1. **交底阶段 SLA + 宽限期倒计时**（差距 5、10）——docket 引擎现成，接上即可。
2. **评分建议留痕**（差距 6）——让 02 用同一份分数做 D1。
3. **合规三件套：权属、署名、奖酬**（差距 7、8、9）——法务买单的理由。

## 20. 术语

| 术语 | 含义 |
|---|---|
| 交底书 / IDF | Invention Disclosure Form，发明人提交的技术披露材料 |
| 交底包 / `disclosure_pack` | 系统内结构化后的交底产物，6 项齐套，交接下游 |
| 1.1 现有技术 | 发明人对最接近现有技术的印象，不是检索报告，也不是科技查新报告。公开号可空；有号则必须能打开。交底不产出这两份 |
| 必要技术特征 | 删掉就不解决技术问题的技术事实。六项里单独计 `features`。见 §2.1 |
| 职务发明 | 执行本单位任务或主要利用本单位物质技术条件完成的发明，权利归单位 |
| 宽限期 | 特定情形公开后 6 个月内申请不丧失新颖性 |
| 保密审查 | 在中国完成的发明向外国申请前须经 CNIPA（国家知识产权局）审查 |
| 非正常申请 | 不以保护创新为目的、无真实研发基础的专利申请 |
| 齐套 | 6 项 REQUIRED 全部为真 |
| 建议去向 | §4.5 的四档，全文只此一套。2.0–2.9 档在技术秘密与防御性公开中勾一个。不是本节点出口，也不是立案路由 |
| 立案路由 | 提报单字段 `targetStage`：`pre_research` 或 `decision`。立案时用来建案。不是 §4.5 按分数勾的建议去向 |
| 三个出口 | 退回补充、交底完成交下游、终止交底。见 §4.4 |
| 交底完成 | §4：六项齐套 + 四组事实闭合 + 发明人确认初稿 + IPR 勾建议并批准 |
| 候选发明点 | `features` + 效果 + 1.1 印象。正式发明点不在本节点确认 |
| 检索报告 | 01 按可核验文献作的可专利性结论。不是 1.1 印象。交底不产出 |
| 科技查新报告 | 查新机构说明有无相同或类似研究报道。口径比新颖性宽，审查员不采信。交底不产出 |
| 新颖性 | 申请日前没有同样的技术方案。三性之一 |
| 创造性 | 相对现有技术并非显而易见。三性之一 |
| 实用性 | 能够制造或使用，并产生积极效果。三性之一。不是本节点批准条件 |
| 三性 | 新颖性、创造性、实用性。交底评分只用前两项 |
| 技术秘密 | 不申请专利，靠保密保护。只写在建议里，不是出口 |
| 防御性公开 | 主动公开技术，使同样方案以后难以授权。只写在建议里，不是出口 |
| 实用新型 | 保护产品形状、构造的专利类型 |
| 外观设计 | 保护产品外观的专利类型 |
| 实施例 | 本节点字段 `embodiments` 的原型标签。业务上是发明人做过或能说清的真实例子，带参数、材料或条件。说明书里的具体实施方式是下游撰写的事，见 §9 |
| 独权 | 独立权利要求，一项里保护范围最大的那项。下游写权利要求时用，见 §9 |
| 从权 | 从属权利要求，写在独权后面，保护范围更窄。下游写权利要求时用，见 §9 |
| IPR | 批准交底包的知识产权人员。与 IP 负责人不是同一步 |
| IP 负责人 | 退回满 3 次时督办。督办是盯着办完，不是批准 |
| 受理 | 组织收下提报单，决定立案或退回 |
| 立案 | 受理通过并生成案件编号。早于批准 |
| Go/No-Go | 立项做还是不做。决定在 02 |
| 建议权 | 可提出方案，但不定。发明人在本节点只有建议权 |
| 决定权 | 拍板并对结果负责。在本节点属于 IPR（交底完成）、IP 受理人（立案）；D1 的决定权在 02 |
| 否决权 | 可单方面叫停已决定的事。本节点属法务（权属 / 涉密 / 公开）与财务（预算） |
| 知情权 | 必须被告知，但不参与决策。业务部门与发明人持有 |
| 不可逆决策 | 执行后难以或无法恢复的决策。交底阶段指公开技术、递交申请、对外披露、对外承诺、撤回批准 |
| 例外 | 有法定、合同或内部依据的破例。须记依据、批准人、风险、期限 |
| 红线 | 任何批准都不能突破的禁止事项。见 §12.9 |
| 分歧留痕 | 记录不同专业意见与最终决定人，而非强迫达成一致。见 §12.8 |
