## 0. 一句话讲清这个节点

**撰写：把已批准的交底（和查新结论）写成能受理、能审查、无效时站得住的申请文件——圈地、铺路、定国别与费用，再交企业确认后递交。**

| | |
|---|---|
| **目的** | 单案权利边界成型（D3）；不是组合「布局」 |
| **谁做** | 代理师主写；企业 IP 审策略与授权递交；发明人配合补实施例 |
| **交出什么** | `draft_claims`（权项+说明书等）+ 递交齐套清单；国别/费用在本站落入定稿 |
| **下一站** | 定稿批准 → 递交 → [04 审查答复](04-prosecution.md)。组合布网见 [08](08-layout.md)；08 只建议，单案国别最终确认在本站 |

### 白话摘要

解决的是**范围与成本的取舍**，不是「把交底抄进模板」。独权多写一条特征就少一块保护范围；说明书少一个实施例，答复时可能无路可退。索引层勿再称「撰写与布局」——布局组合在 08。

产品化三条件：独立买方（代理所+企业 IP）、独立价值（授权率与无效存活率）、独立边界（输入交底+检索，输出申请稿）。

### 1.3 它是什么 / 不是什么

| 是 | 不是 |
|---|---|
| 申请文件的**生产车间**（权项 + 说明书 + 摘要 + 附图 + 请求书） | 检索与可专利性判断（01 已完成，这里只消费结论） |
| 保护范围的**最终定型点** | 交底整理（交底包在 00 已批准，这里只引用） |
| 国别与成本的**一次性决策** | 后续年费与维持（05） |
| 递交前的**责任交接**（企业批准 → 代理递交） | 官方的受理与审查（04 才有 OA） |

> 最容易误判的一点：**撰写不是「把交底抄进模板」**。抄出来的东西在答复阶段一定会被 26.3 / 26.4 打回，而这两类缺陷**无法用修改挽救**（专利法 33 条不许超范围）。

### 1.5 独立产品的形态

**产品名建议：撰写工作台 / Draft Studio**

| 模块 | 能力 | 谁用 |

## 2. 角色与权限矩阵

| 角色 | 代码对应 | 能做什么 | 不能做什么 |
|---|---|---|---|
| 代理师 | `role === 'agency'` / persona `agency` | `save_draft` / `submit` / `file`；起草权项与说明书 | 不能 `approve` / `authorize`（企业专属） |
| 企业 IP | `role === 'enterprise'` / persona `enterprise_ip` | `start_review` / `request_changes` / `approve` / `authorize` | 委托模式下不能 `submit` / `file` |
| 企业自助 | `fulfillmentMode === 'self_serve'` | 企业身份下可执行代理动作（`AGENCY_ACTIONS` 提升） | 无（这是有意放宽） |
| 发明人 | persona `inventor` | 只读 + 交底门户 | 禁批准/授权/file（`persona.ts` 硬禁） |
| 委员 | persona `committee` | 只读 | 禁批准/授权/file |
| Agent | `agent-claims` | 起草、扩展从权、支持检查、国别建议 | 无企业身份时禁 `authorize_file` |

**当前实现的权限真相**（必须对交付方讲清）：

- 角色切换是**同一登录下的角色芯片**（`role` + `persona` 双变量），不是真 SSO/IAM。
- 委托模式下，企业租户做 `submit` 会被 `canPerformHandoff` 拦下，文案「企业租户不可执行代理专属操作（请切换办理模式为自助，或切换至代理所工作区）」（`handoff.ts:226-231`）。
- SKU 未购 → 「未购 SKU，不写交接」（`HandoffActionBar.tsx:104-107`），这是商业闸，不是权限闸，勿混。
- 真实产品需 RBAC + 租户隔离 + 代理师执业资格校验，见 §14 差距 17。

### 2.1 决策权

角色矩阵回答「谁能做什么」，不回答「谁说了算」。撰写阶段的两条核心决策是 **D3（保护范围多大）** 与 **D4（去哪里申请）**，二者都不可逆：权项一旦递交，修改受 33 条限制；国别一旦选定，就是未来 20 年的持续支出。

**四种权能，不得混用**：

| 权能 | 定义 | 本节点的典型场景 | 系统落点 |
|---|---|---|---|
| 建议权 | 提出方案与理由，不产生约束力 | 代理师起草权项、给国别建议；布局工具给覆盖度体检 | 建议稿与终稿分开存储，退回意见须可追溯 |
| 决定权 | 拍板并对结果负责 | 代理师定技术实现与撰写质量；企业 IPR 定范围与预算 | 双签：代理师署「质量」、企业署「范围与成本」 |
| 否决权 | 单方面叫停他人已决定的事 | 代理师拒绝写入不可支撑的范围；企业拒绝超出预算的国别；法务拒绝未过保密审查的涉外申请 | 一票否决，须书面说明并进审计 |
| 知情权 | 被动获知，不参与决策 | 发明人知悉权项定稿；财务知悉国别费用；业务知悉公开时点 | 订阅与通知，不阻断流程 |

**D3（保护范围）与 D4（去哪里申请）的归属**：

| 决策 | 建议权 | 决定权 | 否决权 | 依据与条件 |
|---|---|---|---|---|
| 权利要求范围（独权写多大） | 代理师（技术判断 + 检索结论） | **企业 IPR 审核确认**，代理师对可支撑性负责 | 代理师（范围超出交底可支撑部分时）；企业（超出预算或战略范围时） | L2。企业不得强迫代理师写入明知不可支撑的范围 |
| 独权删减到哪一步（删除测试结论） | 代理师（逐条给出「可删 / 不可删」及理由） | 代理师技术判断；企业可要求复核但不得指定「必须删/必须留」 | 代理师保留技术否决 | 删除测试记录须随案归档，作为日后答复的策略基线 |
| 从权梯度设计 | 代理师 | 代理师（委托范围内自主） | — | 不得少于 2 层；企业可要求补梯度但不得指定具体权项文本 |
| 国别策略（D4） | 代理师、布局工具 | **企业 IP 负责人**（按预算分级），非 IPR 单人 | 财务（超预算、无年度池）；法务（未过保密审查） | L4（不可逆 + 高金额）。须与 02 的预算决议对齐 |
| 是否主张优先权 | 代理师 | 企业 IP 负责人（涉及成本与国别链） | 财务（优先权要求费） | 12 个月窗口 ⚠；错过不可恢复 |
| 是否分案 | 代理师（单一性判断） | 企业 IP 负责人（新申请 = 新费用） | 财务 | 分案是独立申请，须重新走预算与委托 |
| 是否走 PCT vs 巴黎公约 | 代理师（成本/时限测算） | 企业 IP 负责人 | 财务 | 路径在 12 个月内定 ⚠；两者不能并行主张同一优先权 |
| 说明书公开程度（留多少技术秘密） | 代理师 + 技术负责人 | **企业**（技术秘密是资产处置决策） | 法务（公开导致不可逆） | 递交即公开风险不可逆，L4；须企业书面确认 |
| 递交前终审 | 代理师（自检 + Full-check）、企业 IPR（清单） | 企业（`authorize`） | 法务（涉外保密审查） | 授权动作不可由代理所代签（R03-50） |

**责任边界：代理师对质量负责，企业对范围与预算负责**：

| 事项 | 代理师 | 企业 |
|---|---|---|
| 权项结构合法（细则第二十二至二十五条） | **负责**。写错即专业过失 | 不承担结构责任，但须核对是否覆盖业务 |
| 26.3 充分公开 | **负责**。说明书无法实现即为撰写缺陷 | 负责提供真实、完整的技术事实与实验数据 |
| 26.4 支持 | **负责**。上位概念须有实施例支撑 | 负责确认实施例与真实产品一致 |
| 保护范围是否覆盖竞品 | 提供专业建议 | **负责**。范围是商业决策，代理师不能替企业定商业目标 |
| 国别与费用 | 提供测算 | **负责**。花多少钱由企业定 |
| 是否递交 | 执行 | **决定**（`authorize` 是企业专属动作） |

**三条硬约束**：

1. **企业不得强迫代理师写入明知不可支撑的范围**。企业可以要求「尽量宽」，但代理师判断某上位概念无实施例支撑时，有权拒绝写入独权并书面说明。企业坚持的，须书面记录「已被告知 26.4 风险，仍要求」，且该记录进案卷。
2. **代理师不得擅自缩小范围**。为求快速授权而主动把独权并入从权、或删除交底中的必要特征，属于改变委托标的，须企业书面同意。代理师可建议，不可单方执行。
3. **代理所不得代企业做 `authorize`**。递交授权是企业的处分行为，代理所只能 `submit` 与 `file`。

**预算额度分级（金额为示意 ⚠，须按企业授权制度配置）**：

| 层级 | 单件国别预算 | 批准人 | 典型情形 |
|---|---|---|---|
| L1 | ≤ 2 万元 ⚠ | 企业 IPR | 仅中国 |
| L2 | 2–8 万元 ⚠ | IP 主管 | 中国 + 1 国，或一案两报 |
| L3 | 8–30 万元 ⚠ | IP 总监 + 财务 BP | 中国 + PCT + 3–5 国 |
| L4 | > 30 万元，或 > 5 国 ⚠ | 法务总 / CFO | 全球同族布局 |

**期限压力下的临时授权**（优先权窗口临近而决策人失联）：

1. 递交前 15 个工作日 ⚠ 即启动决策确认，不等到最后一周。
2. 预设 A/B 角决策人，授权书事先签署。
3. 约定时点仍未答复 → 升级 B 角；事后 5 个工作日内追认。
4. **沉默不构成同意**：未获明确答复不得 `authorize`；宁可错过该国，不可无授权递交。

## 3. 业务对象（字段级）

### 3.1 交接产物 `draft_claims` 的三项必填

`REQUIRED_BEFORE_SUBMIT.draft_claims`（`handoff.ts:120-124`）：

| 键 | 中文标签 | 业务含义 | 合格线 | 现状 |
|---|---|---|---|---|
| `claims` | 至少一条独立权利要求 | 保护范围的载体 | ≥1 项非空独权 | ✅ 由 `claims.some(type==='独立' && text.trim())` 推导 |
| `countries` | 申请国别策略 | 花多少钱、覆盖哪些市场 | ≥1 国 | ✅ `countries.length > 0` |
| `filing` | 递交检查清单齐套 | 形式与责任确认 | 5/5 全勾 | ✅ 派生自 `DraftFilingCheck` |

**三个键都是「派生值」而非独立存储字段**（`DraftFlow.tsx:469-473`）——这带来一个副作用：`claims` 项只要有一条非空独权就算满足，**不要求权项结构合法**；合法性由另一个变量 `claimsValid` 单独把关（见 §7）。

### 3.2 递交检查清单 `DraftFilingCheck`（5 项）

`types/index.ts:197-199`；标签 `handoff.ts:32-38`；默认全假 `handoff.ts:40-46`。

| 键 | 标签 | 真实业务含义 | 谁验证 |
|---|---|---|---|
| `spec` | 说明书章节齐套（技术领域/背景/发明内容/实施例） | 26.3 的**最低形式门槛**（有这四段不等于写够） | 代理师自检 |
| `claims` | 权利要求已校验（≥1 独权，从属引用有效） | 形式合法性 | 代理师自检 |
| `country` | 国别 / 途径已确认 | 优先权与 PCT 路径已定 | 企业 IPR |
| `fees` | 费用估算已核对 | 官费与代理费两账已对齐预算 | 企业 IPR / 财务 |
| `disclosure` | 交底书发明内容已确认 | 发明人已确认技术事实 | 发明人 + IPR |

**关键认知**：这 5 项**全部是人工勾选**（`AppContext.tsx:1534-1542`），系统不校验内容。它的产品价值不在「校验」，而在「**留痕 + 责任归属**」——谁在什么时候确认了什么。

### 3.3 权项树节点 `Claim`（类型在 Flow 内定义）

`DraftFlow.tsx:35`：`type Claim = { id: string; type: '独立' | '从属'; text: string; dependsOn?: string }`

| 字段 | 类型 | 必填 | 说明 | 问题 |
|---|---|---|---|---|
| `id` | string | 系统 | `cl-<ts>` | — |
| `type` | `'独立' \| '从属'` | ✅ | 二值 | 无法表达「多项从属」 |
| `text` | string | ✅ | 权项全文 | 自由文本，无结构解析 |
| `dependsOn` | string? | 从属必填 | 被引用权项号 | **字符串**，单值；删项不重编号（§14 差距 6） |

**这个数据结构只支撑「一独一从、单引用」**。它表达不了的东西，也就是产品表达不了的东西：

1. 多项从属权利要求（「根据权利要求 1 或 2 所述的方法」）——细则第二十五条只允许择一引用，但**允许多项从属存在**；
2. 前序部分 / 特征部分的二分（细则第二十四条）——只有一个 `text` 字段；
3. 类别标注（方法 / 产品 / 用途）——`type` 只有独/从。

### 3.4 Full-check 轻量三项 `FullCheckLite`

`fullFilingCheck.ts:8-15`，与实际业务的距离：

### 4.9 例外情形

规则说「不得」，业务上总有人要问「什么情况下可以」。不给合法出口，用户就会绕过系统线下做，反而失去留痕。本节只收**有依据的例外**，不收「客户强烈要求」。

| # | 例外 | 例外条件 | 谁批准 | 风险 | 留痕 |
|---|---|---|---|---|---|
| E1 | 交底不足以支撑拟定的独权 | 交底包已批准，但实施例只覆盖单一实现，无法支撑企业想要的宽范围 | 代理师建议 + 企业 IPR 确认 | 写宽则 26.4 败；写窄则白让范围 | 必留：删除测试记录 + 缺失实施例清单 + 企业选择（缩范围 / 回 00 补充交底） |
| E2 | 企业要求超出交底范围 | 企业口头提出交底未记载的实施例或参数，要求写入说明书 | 代理师拒绝默认；须企业书面确认并补交底 | **新增内容无原文支持，构成 33 条超范围风险**，且可能被认定非正常申请 | 必留：拒绝记录 或 企业书面确认 + 补充交底版本号 |
| E3 | 国别预算临时削减 | 财年中预算池被压缩，已选国别需砍 | 企业 IP 负责人（L3/L4 重批） | 砍错国别等于放弃主市场；已发生的翻译/检索费沉没 | 必留：砍留理由 + 排序依据（制造地/销售地/对手所在地）+ 变更后的国别清单 |
| E4 | 优先权期限临近（< 15 个工作日 ⚠） | 决策未完成但 12 个月窗口将闭 | 企业 IP 负责人紧急授权 + A/B 角 | 仓促定范围；仓促选国别 | 必留：倒计时记录 + 紧急授权书 + 后续 30 日 ⚠ 内复核并记录是否调整 |
| E5 | 同日双申（发明 + 实用新型） | 硬件类结构改进，需快速拿证又要 20 年保护 | 企业 IP 负责人 + 代理师 | 须声明且发明授权时放弃实用新型；漏声明则重复授权风险 | 必留：关联案号 + 声明文本 + 「发明授权时放弃实用新型」的 docket |
| E6 | PCT 与巴黎公约路径切换 | 12 个月窗口内改变主意，或目标国数量变化 | 企业 IP 负责人 | 两条路径不能并行主张同一优先权；切换涉及已发生费用 | 必留：切换理由 + 原路径已发生费用 + 新路径的 30/32 个月 ⚠ 倒排 |

**例外不是豁免**：每条须记录批准人、时间、理由、有效期，只对本案生效。E2 尤其危险——它表面上只是「客户说了就写」，实质是把不可补救的缺陷写进正式文件。系统应对「说明书中出现交底包未记载的技术特征」做强提示，而不是静默接受。

### 4.10 规则冲突与裁决

规则之间会打架。不预先给出裁决顺序，执行时就会由「谁声音大」决定。

**五类真实冲突**：

| # | 冲突 | 典型表现 | 裁决 | 裁决人 |
|---|---|---|---|---|
| C1 | 范围要宽 vs 授权率要高 | 企业要独权覆盖全品类，代理师判断该上位概念只有 1 个实施例 | **以可支撑的最宽范围定独权**，把不可支撑的宽范围拆成从权梯度与说明书实施例补强；不得为授权率直接缩到最窄，也不得为宽度写无支撑的上位概念 | 代理师对可支撑性负责（技术否决），企业选择「保宽冒险 / 稳妥缩范围」并留痕 |
| C2 | 企业要省钱 vs 国别要覆盖 | 预算只够 3 国，业务要 6 国 | **先按「制造地 > 销售地 > 主要竞争对手所在地」排序**保 3 国；其余以 PCT 保留至 30/32 个月 ⚠ 再定，而不是直接放弃 | 企业 IP 负责人决定；财务只批额度 |
| C3 | 代理师要保护质量 vs 客户催稿 | 客户要求 3 天内定稿递交，删除测试与 26.3 自检未做 | **质量项不可跳过**：至少完成删除测试、26.4 覆盖检查、5 项清单。可压缩的是说明书润色与附图美观，不可压缩的是结构合法性与支持性 | 代理师技术否决；客户可改交期或改范围（E4），不可要求跳过检查 |
| C4 | 技术秘密 vs 充分公开 | 核心工艺参数企业不愿写进说明书，但不写则 26.3 无法实现 | **先判断「不写能否实现」**：能实现 → 可留秘密；不能实现 → 必须公开或以参数范围/效果数据替代公开，否则不申请 | 企业决定是否申请（可转技术秘密），代理师判定公开充分性；法务确认无出口管制/保密义务冲突 |
| C5 | 独权宽 vs 从权梯度 | 独权已写到最上位，从权只剩形式性限定，无退守空间 | **从权梯度优先于独权极限宽度**：独权每多一个上位概念，须同步补至少 1 层实质从权；无梯度的宽独权在无效程序中一击即溃 | 代理师技术判断；企业可要求「更宽」，但须接受梯度不足的风险并留痕 |

**裁决顺序（无法自行消解时，自上而下适用）**：

| 序 | 原则 | 含义 | 例外 |
|---|---|---|---|
| 1 | **法定硬规则优先** | 33 条不得超范围、26.3 / 26.4、保密审查、优先权 12 个月 ⚠ 不可让渡 | 仅 §4.9 列明的例外可偏离流程，不可偏离法律 |
| 2 | **不可逆优先** | 递交锁定申请日与公开内容；国别锁定 20 年支出 | — |
| 3 | **支持性优先于范围** | 无实施例支撑的上位概念不得进独权，宁窄不塌 | E1 的补充交底路径 |
| 4 | **质量项优先于交期** | 结构合法性、删除测试、支持检查不可因催稿跳过 | 可压缩非质量项（排版、附图美观） |
| 5 | **专业判断与商业判断分离** | 可支撑性、结构合法性听代理师；范围目标与预算听企业 | 任一方越界，另一方有否决权 |
| 6 | **组合优先于单案** | 单案范围让位于同族整体布局（避免母案过宽导致分案无空间） | 单案具独立许可价值时，由 IP 总监书面说明 |
| 7 | **书面留痕优先于口头一致** | 企业坚持超范围、坚持跳检查的，须书面确认并进案卷 | — |

> **最重要的一条**：C1 与 C3 不能靠「谁付钱听谁的」解决。代理师对**可支撑性**负责，企业对**商业目标**负责。把两者混成一个签字，结果是代理师被迫写入自己知道撑不住的范围——而这个缺陷在递交后**无法用修改补救**（33 条），最终由企业承担。

| R03-58 | 四种权能（建议 / 决定 / 否决 / 知情）须分别配置到人，不得合并为一个审批按钮 | ❌ |
| R03-59 | 例外情形须记录批准人、理由、有效期，并按案件统计例外率（§4.9） | ❌ |
| R03-60 | 规则冲突的裁决须记录适用的裁决原则序号（§4.10）及两方原始意见 | ❌ |

## 5. 法律底座 / 行业规则

### 5.1 三种专利类型的撰写差异

| 维度 | 发明 | 实用新型 | 外观设计 |
|---|---|---|---|
| 保护客体 | 产品、方法及其改进 | **仅产品**的形状/构造/结合 | 产品的形状/图案/色彩的新设计 |
| 审查方式 | 初审 + **实质审查** | **仅初步审查**（含明显实质性缺陷） | 仅初步审查 |
| 撰写核心 | 权项 + 说明书 + 摘要 + 附图 | 权项 + 说明书 + **必须有附图** | **图片/照片 + 简要说明**，无说明书与权项 |
| 权项结构 | 独/从，前序+特征 | 同发明，但不得含方法权项 | **无权利要求书** |
| 保护期 | 20 年 | 10 年 | 15 年（2021-06-01 起申请）⚠ |
| 本案代码支持 | ✅ 全流程 | ⚠ 同一套字段，无差异校验 | ❌ 无图片通道、无简要说明字段 |

**实用新型初审不是「走过场」**。《专利法实施细则》第五十条第一款第二项的「明显实质性缺陷」审查，在 2023 年修订后**新增了「明显不具备创造性」**（以及对体现同一设计构思的外观设计的「明显区别」）⚠ 条号与表述需按当期文本复核。这意味着：

- 实用新型的独权同样要过创造性门槛（虽然标准低于发明）；
- 系统若把实用新型当「简化版发明」处理，等于把风险留到授权后无效程序。

**产品落点**：`PatentType` 已有三值（`types/index.ts:24`），但 DraftFlow **完全不读这个字段**（只在交底卡里显示）。选「实用新型」时，系统应当：禁方法权项、强制附图、提示「初审会查明显创造性」。

### 5.2 第四种情形：一案两报（同日申请发明 + 实用新型）

《专利法》第九条第一款允许同一申请人同日就同样发明创造既申请实用新型又申请发明，但须**声明**，且在发明授权时放弃已授权的实用新型。⚠ 条文与操作细节需复核。

| 产品要求 | 现状 |
|---|---|
| 一案两报的关联对象（母案 ↔ 平行案） | ❌ 无 |
| 声明文本的强制勾选 | ❌ 无 |
| 发明授权时「放弃实用新型」的 docket | ❌ 无 |

这是中国申请人（尤其硬件类）的主流策略，缺失即意味着产品无法服务真实场景。

### 5.3 权利要求书的法定结构

《专利法实施细则》第二十二条至第二十五条（条号来自 2023 修订文本，⚠ 需复核）：

| 条 | 要求 | 产品落点 | 失效后果 |
|---|---|---|---|
| 第二十二条 | 权项应记载技术特征；阿拉伯数字顺序编号；术语与说明书一致；可有化学式/数学式但**不得有插图**；附图标记括号内且不构成限制 | 编号自动化（现在靠 `idx+1` 隐式编号） | 初审补正；术语漂移导致 26.4 |
| 第二十三条 | 独权「从整体上反映技术方案，记载解决技术问题的**必要技术特征**」；从权「用附加技术特征进一步限定」 | 删除测试（未实现） | 独权写多 → 白让范围；写少 → 无新颖性 |
| 第二十四条 | 独权分**前序部分**（主题名称 + 与最接近现有技术共有的必要特征）与**特征部分**（其特征在于…）；一项发明应当只有一个独立权利要求 | 单 `text` 字段（未实现） | 形式缺陷；范围解释不清 |
| 第二十五条 | 从权含**引用部分**（编号 + 主题名称）与**限定部分**；多项从属只能择一引用在前权项 | `dependsOn` 单值（部分实现） | 引用错误 → 权项不清楚 |

> 「一项发明应当只有一个独立权利要求」的实务含义：同一申请里出现多个独权，**必须**分别对应属于一个总的发明构思的多项发明（即满足单一性）。系统允许无限多独权且不查单一性（R03-10），是形式上的合规风险。

### 5.4 独权「必要技术特征」的判定：删除测试落点

判定法在 [00b §2.5](00b-invention-point-chain.md) 已给出。这里只写**它在产品上应该长什么样**：

| 步骤 | 产品动作 | 现状 |
|---|---|---|
| 1 | 从交底包 `features` 取出候选特征清单 | ⚠ 交底包有 `features` 勾选，但 DraftFlow 不读 |
| 2 | 逐条标记「删掉后是否仍解决技术问题」 | ❌ 无 UI |
| 3 | 判为「仍可解决」的，自动建议移入从权并生成对应从权草稿 | ❌ 无 |
| 4 | 判为「不可删除」的，标记为必要特征并锁定在独权 | ❌ 无 |
| 5 | 输出「独权特征数 / 从权覆盖数 / 未覆盖候选特征」三数报表 | ❌ 无 |

**为什么必须做**：这是唯一一个能把「代理师经验」变成「可审计流程」的动作。没有它，撰写质量完全取决于谁在写。

### 5.5 单一性（专利法第三十一条）

| 规则 | 内容 | 产品落点 |
|---|---|---|
| 一件申请限于一项发明 | 专利法第三十一条第一款 | 多独权须逐一说明对应的发明 |
| 合案申请条件 | 属于一个总的发明构思、技术上相互关联、包含**相同或相应的特定技术特征**；特定技术特征 = 对现有技术作出贡献的特征（细则第三十九条） | 需读取检索结论判断「特定技术特征」 |
| 外观设计合案 | 同一产品的多项相似设计可合案，**不得超过 10 项**；成套产品须属分类表同一大类、习惯上同时出售或使用（细则第四十条） | 外观通道缺失，无从落地 |
| 不满足单一性的后果 | 通知在指定期限内修改或分案，「期满未答复的，该申请视为撤回」（细则第四十八条第二款） | 需 docket 规则，现无 |

### 5.6 说明书六段结构与 26.3 / 26.4 的对应

| 段 | 对应法条 | 功能 | 写砸的直接后果 | 代码字段 |
|---|---|---|---|---|
| 名称 | 细则关于说明书名称的规定 ⚠ 条号需复核 | 定主题、定分类 | 初审补正 | 借用 `c.title` |
| 技术领域 | 细则第二十条（一） | 定 IPC/CPC 分类 | 检索不准 | `field` |
| 背景技术 | 细则第二十条（二），「有可能的，并引证反映这些背景技术的文件」 | 立靶子 | 创造性无从论证 | `background` |
| 发明内容 | 细则第二十条（三），问题/方案/有益效果 | 支撑 26.3 能否实现 | 公开不充分 | `invention` |
| 附图说明 | 细则第二十条（四） | 支撑理解 | 标号不一致 → 补正 | ❌ 缺失 |
| 具体实施方式 | 细则第二十条（五），「详细写明优选方式」 | 支撑 26.4 概括范围 | 被迫缩权 | `embodiment` |
| 摘要 | 专利法第二十六条第三款末段 + 细则第二十六条 | 检索入口 | 补正 | ❌ 缺失 |

**26.3 与 26.4 的分工**（这是撰写阶段唯一必须记住的判据）：

- **26.3（充分公开）**：说明书要「清楚、完整」，以**所属技术领域的技术人员能够实现**为准。检验法：把权项删掉，只看说明书，一个本领域技术人员能否照做并得到预期效果。
- **26.4（支持）**：权利要求要「以说明书为依据」。检验法：权项里的每个上位概念，说明书里是否有至少一个下位实施例。
- **两者的共同后果**：都属于**不能靠修改补救**的缺陷——补内容就超范围（33 条）。所以 26.3/26.4 的检查必须在撰写阶段完成，答复阶段只能缩小权项。

### 5.7 摘要、附图、请求书的形式要件

| 文件 | 形式要求 | 依据 | 现状 |
|---|---|---|---|
| 摘要 | 写明名称、技术领域，清楚反映技术问题、方案要点、主要用途；指定一幅摘要附图；不得用商业宣传用语 | 细则第二十六条 | ❌ 无字段 |
| 附图 | 多幅按「图1，图2…」编号；说明书未提及的标记不得出现在附图，反之亦然；同一部件标记一致；除必需词语外不得含其他注释 | 细则第二十一条 | ⚠ 辅台壳存在，本 Flow 无编号一致性检查 |
| 补交附图 | 有附图说明但无附图/缺图的，须在指定期限内补交或声明取消；补交附图的**以提交日为申请日** | 细则第四十六条 | ❌ 无 |
| 请求书 | 申请人、发明人、代理机构、优先权声明、费减声明等 | 专利法第二十六条 + 细则 | ❌ 无对象 |
| 外观设计 | 请求书 + 图片/照片 + 简要说明 | 专利法第二十七条 | ❌ 无 |

**「补交附图即以提交日为申请日」是撰写阶段最容易造成实质损失的一条**：答应客户「先交文字、图后补」= 自动放弃原申请日。

### 5.8 33 条边界必须在撰写时就想清楚

《专利法》第三十三条：对发明和实用新型申请文件的修改**不得超出原说明书和权利要求书记载的范围**；对外观设计不得超出原图片或照片表示的范围。

**这条法条的产品含义**：

1. 撰写阶段写进说明书的每一句，都是**未来答复时的修改素材库**；
2. 说明书写得越窄，答复时能退的空间越小；
3. 系统若允许「交底没写、撰写时凭想象补」的内容进入说明书，等于给未来埋一颗无效地雷（无效程序中可主张超范围）。

> 结论：`applyApprovedPack` 只允许从**已批准的交底包**引入内容，这个设计方向是对的；但它生成的是**占位文案**而不是真实内容（§14 差距 4），实际效果是反的。

### 5.9 18 个月公布与优先权链

| 节点 | 期限 | 起算 | 依据 | 现状 |
|---|---|---|---|---|
| 发明公布 | 18 个月 | 申请日 | 专利法第三十四条 | ❌ 无 docket |
| 优先权（外国） | 发明/实用新型 12 个月、外观 6 个月 | 首次申请日 | 专利法第二十九条 | ❌ 无倒计时 |
| 优先权（本国） | 同上 | 首次申请日 | 专利法第二十九条第二款 + 细则第三十五条 | ❌ 无 |
| 优先权增加/改正 | 优先权日起 16 个月或申请日起 4 个月 | — | 细则第三十七条 | ❌ 无 |
| PCT 国家阶段 | 30 个月（宽限 32 个月，按缔约国） | 优先权日 | PCT 细则 | ⚠ 有 `pct_national_entry` 规则（`docketRules.ts:92-100`），但不与 `pct` 复选框联动 |
| 实审请求 | 3 年 | 申请日（有优先权的自优先权日） | 专利法第三十五条 | ⚠ 有规则（`docketRules.ts:61-69`），递交时不生成 |
| 逾期不请求实审 | 申请**视为撤回** | — | 专利法第三十五条 | ❌ 无终止态 |

**对国别策略的直接约束**：`countries` 不是一张勾选表，它是**一条时间链**——先在国内递交拿到申请日，12 个月内决定走巴黎公约还是 PCT，30/32 个月决定进入哪些国家。系统当前把这三件事压缩成一个布尔 `pct` 加一个数字 15,000，等于把一条 32 个月的决策链退化成一次点击。

### 5.10 保密审查（专利法第十九条）

在中国完成的发明或实用新型向外国申请前，须事先报经国务院专利行政部门进行保密审查；违反的，在中国**不授予专利权**，且构成无效理由。

| 产品要求 | 现状 |
|---|---|
| 选国别时自动判定「是否涉外」 | ⚠ 可选 US/EP/JP/KR，但无提示 |
| 涉外时强制保密审查前置 | ❌ 无 |
| 保密审查请求的 docket | ❌ 无 |

## 6. 状态机

### 6.1 交接状态机（`draft_claims`）

```
drafting ──submit──► submitted_to_enterprise ──start_review──► enterprise_review
   ▲                          │                        │
   │                          │◄──request_changes──────┤
   │                          ▼                        ▼
   └────save_draft──── changes_requested ◄──────── approved
                                                      │
                                        authorize ────┤──► authorized_to_file ──file──► filed
                                                      └────────────────────────file──► filed
```

### 6.2 合法迁移表

| 当前态 | 动作 | 可迁往 | 谁做 | 业务含义 | 出口条件 |
|---|---|---|---|---|---|
| `drafting` / `changes_requested` | `save_draft` | `drafting` | agency | 存草稿 | 无 |
| `drafting` / `changes_requested` | `submit` | `submitted_to_enterprise` | agency | 代理交稿 | 3 项必填 + 5 清单 |
| `submitted_to_enterprise` | `start_review` | `enterprise_review` | enterprise | 企业开始审 | 无 |
| `submitted_to_enterprise` / `enterprise_review` / `approved` | `request_changes` | `changes_requested` | enterprise | 退回 | 无（理由写 note/annotation） |
| `submitted_to_enterprise` / `enterprise_review` | `approve` | `approved` | enterprise | 确认策略 | 交底已批准 + 3 项必填 |
| `approved` / `enterprise_review` / `submitted_to_enterprise` | `authorize` | `authorized_to_file` | enterprise | 授权递交 | 5 清单 + Full-check |
| `authorized_to_file` / `approved` | `file` | `filed` | agency | 归档并填回执 | 回执号 + 递交日 |

> 注意 `authorize` 的 `from` 包含 `submitted_to_enterprise`（`handoff.ts:176-180`），即**企业可在未 approve 的情况下直接授权**。这在业务上等于跳过了「确认策略」这一步，与 HITL `approve_strategy` 的设计意图冲突。

### 6.3 当前实现的偏差（逐条点名）

1. **`authorize` 可从 `submitted_to_enterprise` 直达**（`handoff.ts:177`），绕过 `approve`。§14 差距 1。
2. **Flow 进度与 handoff 状态双轨**：`usePersistedFlowStep` 存 4 步 index，`handoff` 存 7 态，二者无映射校验。可能出现「Flow 显示第 4 步、handoff 仍是 drafting」。§14 差距 2。
3. **权项手动编辑被覆盖**：`draft` 文本域可编辑，但 `useEffect(() => setDraft(assembled), [assembled])`（`DraftFlow.tsx:204`）在任何依赖变化时重置，用户手改的正文会丢。§14 差距 3。
4. **`file` 后无申请号锚点**：`filed` 只写回执号与日期，没有官方申请号字段，后续 04 的 OA 无法与真实申请建立对应。§14 差距 12。
5. **`applyApprovedPack` 写占位文案**（`DraftFlow.tsx:84-99`）：「技术领域（自交底包）· 发明」「背景/1.1 摘要：交底包已批准（…）」这类字符串会进入组装稿并被当作说明书内容。§14 差距 4。
6. **无「OA 回来改权项」回流**：04 修改权项后，03 的 `draft_claims` 不更新，两处权项文本永久分叉。§14 差距 13。

## 8. 步骤序列 / 工作流

### 8.1 四个 Flow 步骤

### 8.2 撰写阶段内部真实动作（8 个，代码只覆盖 3 个）

| # | 动作 | 法律/业务依据 | 代码覆盖 |
|---|---|---|---|
| 1 | 读交底包 6 项、确认必要特征集 | 26.4 / 细则第二十三条 | ❌ |
| 2 | 读检索报告，标注 X/Y 类，决定哪些特征进独权 | 22.2 / 22.3 | ❌ |
| 3 | 独权删除测试 | 细则第二十三条 | ❌ |
| 4 | 从权梯度设计（无效退守） | 实务 | ❌ |

## 12. 指标（验收尺子）

| 指标 | 定义 | 健康区间 | 说明 |
|---|---|---|---|
| 一次通过率（递交齐套） | 首次提交即 5/5 + Full-check 通过 | > 70% | 反映流程成熟度 |
| 权项返工率 | 企业退回并修改权项的次数 / 案 | < 1.0 | 高 → 代理与企业预期不符 |
| 独权特征数 | 每件独权的技术特征条数 | 3–6 条（经验） | 过多 = 白让范围 |
| 从权梯度深度 | 每独权下最长从权链长度 | ≥ 2 层 | 无效退守能力 |
| **首通 OA 无驳回率** | 首次 OA 未收到驳回倾向的比例 | 越高越好 | **能换算成钱**：每少一轮 OA，省 1 次代理费 + 3–6 个月 |
| **撰写返工成本** | 因撰写缺陷导致的额外代理工时 × 费率 | 越低越好 | **能换算成钱** |
| 交底→递交周期 | 中位数工作日 | < 15 | 端到端效率 |
| 费用估算偏差 | 实际官费+代理费 vs 估算 | < 15% | 影响客户信任 |
| 国别决策留痕率 | 有结构化理由的国别选择占比 | 100% | 便宜且高价值 |

> 卖点时优先讲 **首通 OA 无驳回率** 与 **撰写返工成本**：前者直接对应「少花一轮代理费 + 早 4–6 个月拿证」，后者对应「每件省 X 元」。

## 13. 产品化切分建议

| 层 | 内容 | 可独立交付 |
|---|---|---|
| L1 文档层 | 权项树 + 说明书编辑器 + 导出 docx | 是（最低配，可白牌） |
| L2 校验层 | 引用校验、编号重排、术语一致性、六段完整性 | 是（差异化明显） |
| L3 布局层 | 删除测试、梯度视图、单一性检查、26.4 覆盖检查 | 是（**核心卖点**，IP 总监买单） |
| L4 成本层 | 国别沙盘、官费+代理费两账、附加费、费减、优先权/PCT 倒排 | 是（财务与 IP 负责人买单） |
| L5 交接层 | 5 项齐套 + Full-check + 版本 + 回执 + docket 回写 | 依赖下游 |

**定价锚点**：按「件」计价（每件撰写工作台使用费）最自然；L3 可单独按「布局体检报告」计件。

**竞品参照系**：国外工具（Anaqua / Clarivate / PatSnap 的撰写模块）强在流程与文档管理，弱在中国法条内置校验（尤其 26.3/26.4 与细则第二十二至二十五条的结构约束）；国内工具多为「模板 + 协作」，几乎不做结构校验。**「中国法结构校验 + 布局体检」是空位**。

**优先补的三件事**（投入产出比排序）：

1. **权项数据结构升级 + 结构校验下沉到 domain**（差距 6、7、5）。理由：改动集中在一个类型与一个校验函数，收益是让「细则第二十二至二十五条」第一次真正落地；顺带解决删项重编号这个会直接产出错误文件的 bug。
2. **优先权 / PCT / 18 个月 / 实审请求的期限链**（差距 10、11、12）。理由：docket 引擎现成，只需在 `file` 时多生成 2–3 条事件并补 2 条规则，是「少投入、防大额损失」的典型。
3. **专利类型分流 + 费用两账**（差距 8、9、15）。理由：决定产品能否服务实用新型/外观这两个中国市场最大的量；费用两账是财务与 IP 负责人最直接的付费理由。

## 15. 术语表

| 术语 | 含义 |
|---|---|
| 独立权利要求（独权） | 不引用其他权项、从整体上反映技术方案的权利要求 |
| 从属权利要求（从权） | 用附加技术特征对引用权项作进一步限定的权利要求 |
| 前序部分 / 特征部分 | 独权的两段：与最接近现有技术共有的必要特征 vs 区别特征 |
| 必要技术特征 | 缺一即无法解决技术问题的特征，只能进独权 |
| 多项从属权利要求 | 一项从权以择一方式引用两项以上在前权项 |
| 单一性 | 一件申请限于一项发明；合案须属同一总的发明构思 |
| 特定技术特征 | 对现有技术作出贡献、使多项发明技术关联的特征 |
| 26.3 / 26.4 | 专利法第二十六条第三款（充分公开）/ 第四款（以说明书为依据） |
| 删除测试 | 逐条删特征判断是否仍能解决问题，用于判定必要特征 |
| 从权梯度 | 独权被无效后逐级退守的从权层级结构 |
| 一案两报 | 同日就同一发明创造申请实用新型与发明，发明授权时放弃实用新型 |
| 主动修改窗口 | 提出实审请求时、收到进入实审阶段通知书起 3 个月内（细则第五十七条）⚠ |
| 申请附加费 | 权项超 10 项、说明书超 30 页时加收的官费 |
| 费减 | 符合条件的申请人可减缴申请费/实审费/前 3 年年费 |
