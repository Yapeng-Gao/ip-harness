# 交底之后 · 发明点翻译链（Disclosure → Claims → Specification）

> 这篇回答一个问题：**交底书写完之后，到底发生什么，谁做，产出什么。**
> 阅读顺序建议：先读 [00-inventor-disclosure.md](00-inventor-disclosure.md)，再读本文，然后读 [01-research.md](01-research.md) / [03-drafting.md](03-drafting.md)。
>
> 法律口径：《专利法》（2020 修正）第 22 条、第 26 条；《专利法实施细则》（2023 修订）。凡金额标 ⚠ 需按当期官方标准复核。

---

## 0. 一句话结论

**交底后面不是「一个步骤」，是一条把「技术事实」翻译成「法律权利」的链，中间要过四道翻译。**

| 翻译 | 输入 | 输出 | 失败后果 |
|---|---|---|---|
| 第 1 道 | 已完成交底里的候选特征 + 检索对比文件 | **正式发明点**（区别技术特征 + 效果） | 保护错东西 |
| 第 2 道 | 发明点 | **权利要求**（独权最小集 + 从权梯度） | 范围过窄或过宽 |
| 第 3 道 | 权利要求 | **说明书**（充分公开 + 支持） | 26.3 / 26.4 驳回 |
| 第 4 道 | 全部材料 | **申请文件**（请求书 + 权项 + 说明书 + 附图 + 摘要） | 不予受理 / 补正 |

### 0.1 交底完成前后

交底完成的定义在 [00](00-inventor-disclosure.md) §3.4、§6.3。完成前，本链不开始。

发明点从交底产生，分两段：

- **完成前只有候选。** 材料是交底里的必要技术特征、效果，以及发明人对最接近现有技术的印象（`prior_art_1_1`）。
- **完成后才有正式发明点。** 检索给出可核验的对比文件。正式发明点 = 交底已经写明的特征里，相对该对比文件多出来的区别特征，加上这个特征产生的效果。交底没写的特征，不能在本链新造。

00 的出口只有三个：退回补充、交底完成交下游、终止交底。本文 §2.1 是交底完成之后的初审分流，不改写这三个出口。

## 1. 先拆「查新」：三张纸不是一回事

中文语境里「查新」被滥用，实际上有三份目的完全不同的报告。**混淆它们是行业常见事故。**

| 名称 | 出具方 | 回答的问题 | 典型用途 | 专利法上的效力 |
|---|---|---|---|---|
| **科技查新报告** | 科技部/教育部认定的查新机构（如中国科学技术信息研究所、各省科技情报所、部分高校图书馆） | 国内外**是否已有相同或类似研究报道** | 科研立项、成果鉴定、奖励申报、高新技术企业认定、职称评审 | **无**。审查员不采信 |
| **专利检索报告**（可专利性检索） | 代理所 / 企业 IPR / 商业数据库 | **是否具备新颖性、创造性，能否授权** | 是否申请的决策、撰写依据 | 有参考价值，非法定文件 |
| **FTO 检索报告** | 代理所 / 律所 | **实施该技术是否侵犯他人专利权** | 产品上市、投资尽调 | 无，但是侵权预警的唯一依据 |

### 1.1 为什么科技查新不能当可专利性依据

**结论口径不同**：

- 科技查新结论的典型表述是「**未见国内外相同报道**」——它比专利新颖性**宽**，不要求单篇文献公开权利要求全部技术特征。
- 专利新颖性（专利法 22.2）要求**单篇对比文件公开全部技术特征**，是严格的一一对应。

用科技查新报告支撑「可以申请」，在逻辑上是不成立的。

> 企业实务：内部口语常把「做个查新」等同于「做个专利检索」。产品文案里必须写清是哪一种，否则交付时会对不上。

## 2. 真实链路：六步，各有各的闸门

```
交底书（已完成）
  │
  ├─① IPR 初审（triage）
  │      闸门：值不值得花钱检索
  │
  ├─② 检索（初步 + 正式）
  │      闸门：有没有新颖性
  │
  ├─③ 发明点提炼
  │      闸门：保护什么（区别特征 + 效果）
  │
  ├─④ 权利要求布局
  │      闸门：圈多大（类型 / 层级 / 梯度 / 变体）
  │
  ├─⑤ 说明书撰写
  │      闸门：守不守得住（26.3 充分公开 / 26.4 支持）
  │
  └─⑥ 递交前检查 → 递交
```

### 2.1 ① IPR 初审 —— 花钱闸门（1–3 天，免费）

**回答的问题**：这份交底值不值得进入（付费的）检索？

**四项判断**：

| # | 判断 | 不合格的处理 |
|---|---|---|
| 1 | **是技术方案吗** | 只是需求/想法/纯商业方法 → 退回 00 补充。发明人不再补充的，走 00 的终止出口，不记成「不申请」 |
| 2 | **公开了吗** | 公开事实已在交底定死。若已超宽限而建议仍是申请，初审不改 `recommendation`，只在交给立项时注明「宽限已过」 |
| 3 | **权属清楚吗** | 权属已在交底定死。初审只核对；对不上则退回 00，不在这里改结论 |
| 4 | **业务上要吗** | 不在主营路径时，可以不进付费检索，把原建议和这条事实一起交给立项。不另勾去向 |

**初审分流三个**（交底完成之后，不是 00 的出口）：退回 00 补充 · 进入检索 · 不进入检索并交给立项。去向只有 00 §8.1 那一套。初审不改提报状态，也不另打分。立项用这一份建议做 D1。

**为什么这一步在产品上必须独立**：检索要花钱。没有这道闸，等于所有交底都无条件进入付费环节。现实中没有企业这样运作。

### 2.2 ② 检索 —— 初步与正式是两次

| | 初步检索 | 正式检索 |
|---|---|---|
| 执行方 | 企业 IPR | 代理所 / 检索机构 |
| 耗时 | 1–2 天 | 3–10 天 |
| 成本 | 0 | ¥3,000–15,000（视范围，⚠ 需按当期市场价） |
| 目的 | 快速判断「还有没有戏」 | 出正式报告，支撑撰写与决策 |
| 数据库 | 免费库（CNIPA 专利检索及分析系统、Google Patents、Espacenet） | 商业库（Derwent、IncoPat、智慧芽等） |

**检索报告必须能回答三件事**：

1. 最接近的现有技术是哪一篇（或哪几篇）；
2. 每篇与本方案的区别是什么；
3. 可专利性初判（新颖性有无 / 创造性高低 / 主要风险点）。

### 2.3 检索报告的读法：X / Y / A / E 分类

这是国际通行的对比文件标注法，直接决定后面怎么写。

| 标记 | 含义 | 对撰写的影响 |
|---|---|---|
| **X** | 单独一篇即破坏新颖性或创造性 | 必须避开；发明点要重新找 |
| **Y** | 与另一篇结合破坏创造性 | 权项需加入「组合非显而易见」的特征 |
| **A** | 一般背景技术，不影响三性 | 写进背景技术段落 |
| **E** | **抵触申请**：申请日在前、公开日在后 | 只破坏新颖性，**不能**用于论创造性 |
| **P** | 申请日介于本申请优先权日与申请日之间的文献 | 需核实是否构成抵触申请 |

**法条口径**（必须分清）：

- **新颖性**（专利法 22.2）= **单篇对比**。一篇文献必须公开权利要求的**全部**技术特征。
- **创造性**（专利法 22.3）= **组合对比**。判断现有技术整体上是否给出技术启示，是否显而易见。
- **抵触申请** = 任何单位或个人就同样的发明在申请日以前向国务院专利行政部门提出过申请、并记载在申请日以后公布的专利申请文件中。**破坏新颖性，但不属于现有技术，不能用于论创造性。**

> 常见错误：拿两篇文献拼起来否定新颖性。这是创造性论证，不是新颖性论证。

### 2.4 ③ 发明点提炼 —— 整条链的重心

**发明点 ≠ 技术方案。**

- 技术方案 = 「我做了什么」
- 发明点 = 「我比别人**多**做了什么，而这个多出来的东西带来了**什么效果**」

**三问法**（可直接用于培训）：

1. **最接近的现有技术是哪一篇？**（检索报告里的 X，或最相关的 Y）
2. **我与它的区别技术特征是什么？**（逐条比对，不能笼统说「更先进」）
3. **这个区别特征带来了什么技术效果？**（效果必须**预料不到**，否则就是显而易见）

写成公式：

```
发明点 = 区别技术特征 + 由该特征产生的技术效果
```

区别特征必须能在已批准交底的 `features` 里找到。检索里看到、交底没写的手段，不能算进发明点，只能退回 00 补充。

**判定「预料不到」的实操口径**：

- 效果是**质的差异**（原来做不到，现在能做到）→ 强
- 效果是**量的显著提升**（需要数据支撑，且不能是线性外推）→ 中
- 效果是**可预期的优化**（换材料必然更轻）→ 弱，通常不足以支撑创造性

**例（仓库内边缘计算案）**：

| 项 | 内容 |
|---|---|
| 最接近现有技术 | CN114882901A，按负载调度 |
| 区别技术特征 | 用「能耗约束」与「负载预测」的**联合阈值**做调度决策 |
| 技术效果 | 峰值功率下降约 18%，吞吐基本持平 |
| 发明点一句话 | 以能耗约束与负载预测的联合阈值替代单一负载阈值，在不牺牲吞吐的前提下压低峰值功率 |

反例：只说「用了负载预测」——那是现有技术已有内容，不构成发明点。

### 2.5 ④ 权利要求布局 —— 「圈地」，不是「写字」

这一步决定专利值多少钱，却常被当作撰写的一部分糊过去。**布局决定打哪，撰写决定怎么打。**

**五个布局维度**：

| 维度 | 问题 | 示例 |
|---|---|---|
| **类型** | 只报产品？还是产品 + 方法 + 用途？ | 装置 + 制造方法 + 新用途 = 三组权项 |
| **层级** | 只保护整机？还是覆盖零部件与下游？ | 电池模组 / 电芯 / 搭载该模组的整车 |
| **梯度** | 独权被无效后往哪退？ | 独权写「比值判据」→ 从权退到「比值 + 温度补偿」 |
| **变体** | 别人换材料/参数/顺序，是否仍落入？ | 用范围而非点值；用上位概念而非具体型号 |
| **单/多独权** | 一个独权还是并列多个？ | 满足单一性时，多独权覆盖更多场景 |

**独权铁律**：只放**必要技术特征**——删掉任何一条就无法解决技术问题的那些。多写一条 = 白送一块保护范围。

**从权的真实价值**：不是「补充说明」，是**无效程序里的纵深阵地**。独权被打掉，还有从权可退。一件只有独权没有梯度的专利，等于只有一道防线。

**布局必须回看检索报告**：X 类文献决定了哪些特征必须进独权（否则没有新颖性），Y 类决定了哪些特征组合必须写进来（否则没有创造性）。

### 2.6 ⑤ 说明书撰写 —— 「铺路」，为权项兜底

**权利要求与说明书是互相约束的**：

```
权利要求：我想要多大地
              │
              │  26.4 必须以说明书为依据
              ▼
说明书：   我能不能守住这么大地
              │
              │  26.3 必须充分公开、能够实现
              ▼
        本领域技术人员能否照做
```

**法定顺序**（实施细则）：名称 → 技术领域 → 背景技术 → 发明内容 → 附图说明 → 具体实施方式。

**每段的功能与写砸的后果**：

| 段 | 功能 | 写砸的后果 |
|---|---|---|
| 名称 | 定主题 | 初审补正 |
| 技术领域 | 定分类号 | 检索不准、审查员找错对比文件 |
| 背景技术 | 立靶子，引出最接近现有技术及其缺陷 | 创造性无从论证 |
| 发明内容 | 问题 / 方案 / 效果三段闭环 | 26.3 无法判断能否实现 |
| 附图说明 | 支撑理解 | 标号不一致，补正 |
| 具体实施方式 | 支撑权项的概括范围 | 26.4 权项无支持，被迫缩权 |

**最重要的认知**：说明书是权利要求的**字典**。日后解释权项、答复 OA、打无效，都以说明书为准。**交底里没写的内容，说明书里补不进去**（不能超范围修改）。

这就是「交底质量决定专利上限」的机制性原因，不是口号。

## 3. 分工矩阵：谁做哪一段

| 环节 | 发明人 | 企业 IPR | 代理师 |
|---|---|---|---|
| 交底 | **主笔**，并确认技术事实 | 收单并批准交底包。初审在交底完成之后，见 §2.1 | — |
| 检索 | 提供技术线索 | 初步检索 / 委托 | 正式检索（可选） |
| **发明点** | **确认**（关键） | 初提 | **主提**（正式） |
| 权项布局 | 提供实施细节 | 审核 | **主笔** |
| 说明书 | 补技术细节 | 审核 | **主笔** |
| 递交 | — | 授权 | 执行 |

**正式发明点的确认是三方共同动作**，发生在检索之后。交底里发明人确认的是技术事实（00 §8.4 第 6 步），不是这一步。这一步最容易出事：

- 代理师提的发明点，发明人不认；
- 发明人认了，但说明书里没写支撑；
- 确认过程无留痕，事后无法追溯。

→ 产品上必须有独立的「发明点确认」对象与签字留痕。

## 4. 与代码的对应关系

| 环节 | 仓库现状 | 权威源 | 缺口 |
|---|---|---|---|
| ① IPR 初审 | ❌ **缺** | — | 无花钱闸门，交底直接进检索 |
| ② 检索 | ✅ | `research_report` 7 项齐套（`packages/domain/src/handoff.ts`） | kw / db / hits / **hits_verifiable** / conclusion / **binding** / fto |
| ③ 发明点 | ❌ **缺对象** | `agent-claims` 有「独权起草」能力 | 无 `inventive_point` 实体；DraftFlow 无「区别技术特征」步骤 |
| ④ 布局 | ⚠ 半有 | `draft_claims` + DraftFlow 权利要求树 | 仅有独/从之分，无类型/层级/梯度维度 |
| ⑤ 说明书 | ⚠ 半有 | DraftFlow 的 `field / background / invention / embodiment` 四字段 | 纯文本框，无 26.3 / 26.4 校验 |
| ⑥ 递交检查 | ✅ | `DraftFilingCheck` 5 项（spec / claims / country / fees / disclosure） | 均为人工勾选 |

### 4.1 检索侧已有亮点（值得保留）

`research_report` 的两个必填项比多数产品细：

- **`hits_verifiable`**：命中必须 pubNo + 可点 url，正则 `(?:CN|US|EP|WO|JP)[A-Z0-9]{5,}` + `https?://`。防编造。
- **`binding`**：命中必须绑定结论，不允许「检索了一堆文献但结论无依据」。

这两个设计直接呼应交底包的 `prior_art_1_1` 可核验规则，思路一致。

### 4.2 建议补的三个对象

**① `InventionPoint`（发明点）**

```ts
interface InventionPoint {
  id: string
  caseId: string
  closestPriorArtRef: string      // 指向 research hit 的 id
  distinguishingFeatures: string[] // 区别技术特征
  technicalEffect: string          // 由区别特征产生的效果
  effectEvidence?: string          // 数据支撑
  nonObviousRationale?: string     // 为何非显而易见
  confirmedBy: Array<{ role: 'inventor' | 'ipr' | 'agent'; name: string; at: string }>
  status: 'draft' | 'confirmed' | 'disputed'
}
```

放在 `disclosure_pack` 批准之后、`draft_claims` 起草之前，作为独立交接物。

**② `TriageDecision`（初审决议）**

```ts
interface TriageDecision {
  disclosureId: string
  outcome: 'need_more_info' | 'search' | 'no_filing' | 'trade_secret' | 'defensive_publication'
  reasonCodes: string[]   // 结构化理由，可统计
  decidedBy: string
  decidedAt: string
}
```

**③ 说明书校验（26.3 / 26.4）**

不是评分，是最低限度的一致性检查：

- 26.3：技术方案段是否只含功能描述而无实现手段；实施例是否给出可复现参数。
- 26.4：权项里的每个上位概念，在说明书中是否有至少一个下位实施例支撑。

## 5. 常见误区（培训可直接用）

| # | 误区 | 正解 |
|---|---|---|
| 1 | 查新报告 = 可专利性结论 | 科技查新口径更宽，不能替代专利检索 |
| 2 | 新颖性可以用两篇文献否定 | 新颖性必须单篇对比；两篇是创造性论证 |
| 3 | 抵触申请可以用来论创造性 | 抵触申请只破坏新颖性，不属于现有技术 |
| 4 | 发明点 = 技术方案 | 发明点 = 区别特征 + 效果，必须相对现有技术 |
| 5 | 独权写得越全越安全 | 独权多一条特征就少一块范围；必要特征之外一律下放从权 |
| 6 | 从权只是补充说明 | 从权是无效程序里的梯次防线 |
| 7 | 说明书是权项的复述 | 说明书是权项的字典与支撑；写不到就守不住 |
| 8 | 交底没写，撰写时补上就行 | 不能超范围修改，交底没写的基本补不进去 |
| 9 | 检索一次就够 | 初步检索（IPR，判断有无戏）+ 正式检索（代理所，出报告） |
| 10 | 所有交底都该进检索 | 检索要花钱，必须先过 IPR 初审闸门 |
