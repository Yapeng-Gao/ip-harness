## 0. 一句话讲清这个节点

**布局 = 在「技术维度 × 地域维度 × 时间维度」上提前布网，让对手无论从哪条路走都会碰到你的权利。**

它不是「多申请几件」。单件专利保护一个点，布局保护一条线、一张面；单件专利的价值是「能不能告赢」，组合的价值是「对手能不能绕开、绕开要付多大代价」。

产品化视角下它能独立成产品，因为三条同时成立：

1. **有独立买方**：IP 总监 / 战略部 / 投资并购方（尽调看组合，不看单件）。
2. **有独立价值**：组合价值 > 单件之和。一件核心专利被无效，组合还在；一个空白点被对手先占，再想进去要付十倍成本。
3. **有独立边界**：输入是「技术树 + 竞品密度 + 已布局清单」，输出是 `layout_insight`，不依赖任何具体案件的办理状态。

> 讲给实习生的一句话：**撰写是「把这件写好」，布局是「决定写哪几件、写在哪几个国家、什么时候写」。布局错了，后面每一件都白写。**

## 2. 角色与权限矩阵

| 角色 | 代码对应 | 能做什么 | 不能做什么 |
|---|---|---|---|
| 企业 IP 经理 | `role: 'enterprise'` | 审核空白点、批准补强方向、确认可建案 | 不能提交（`submit` 属代理动作） |
| 代理师 / 战略顾问 | `role: 'agency'` | 写洞察摘要、空白点、补强建议、提交 | 不能批准（`approve` 属企业动作） |
| 布局 Agent | `agent-layout`（`beta`） | 出矩阵、找空白、建议补强、建议国别 | 不能批准；补强须人工批准后才建案 |
| 专家席 | `expert-layout`（Phase 灰显） | 只读提案（`layout_plan`） | 无写命令（`writeCommands: null`） |
| 发明人 | `persona: 'inventor'` | — | 工作台整块被挡 |

**当前实现的权限真相**：

- 补挂（`attachHandoffArtifact`）**不区分角色**：任何能进本台的人都能把 `layout_insight` 挂到别人的调研案上（`LayoutFlow.tsx:183-205`）。这是本节点权限面最大的口子。
- 批准走 `evaluateGuardrails` + `canPerformHandoff`，是**通用 7 态校验**，没有布局专属闸（`LayoutFlow.tsx:425-438`）。
- `expert-layout` 在专家席表里是 **Phase 灰显席**，`handoffKeys: null`、`writeCommands: null`（`apps/agent/src/projects/patentMidMap.ts:68-75`）——它只能提案，不能落地。
- Agent `tier: 'beta'`，`tierNote` 明写「Beta·非采购闭环：洞察矩阵/建案示意仍薄，勿当布局采购主路径」（`agents.ts:294`）。**这条诚实口径要保留到产品里。**

### 2.1 决策权

角色矩阵回答「谁能做什么」。布局要回答的是另一个问题：**「下一批申请什么」这件事，谁说了算。**

布局与单案最本质的差别在这里：单案决策的后果止于一件申请；布局决策的后果是**一整批申请、一整年预算、一整个技术方向的资源配置**。所以布局是**组合级决策**，不能沿用单案负责人的权限模型。

**四种权能，在布局里这样落**：

| 权能 | 在本节点的含义 | 典型场景 | 系统落点 |
|---|---|---|---|
| 建议权 | 出矩阵、找空白、提补强、给国别打分 | 代理师、战略顾问、布局 Agent、企业 IPR 均可提 | 建议与决议分表存储，驳回须给理由 |
| 决定权 | 决定布哪几格、进哪几国、花多少钱 | **IP 总监及以上**（组合级）；单格转案可按额度下放 IPR | 决议 + 决策人签署 + 「组合级」标识 |
| 否决权 | 单方面叫停已决定的事 | 财务（超预算）、法务（权属/保密/合规）、业务负责人（技术方向失真） | 一票否决，须书面理由 |
| 知情权 | 被动获知 | 业务部门、发明人、财务、下游 03/09 | 订阅通知，不阻断流程 |

> **一条硬边界**：**布局是组合级决策，须 IP 总监及以上拍板，单案负责人无权决定。** 反过来也成立——IP 总监不能替代理师决定「这一格的检索够不够」，那是专业判断。**决定权管资源与取舍，建议权管事实与可行性，两者不可互换。**

**决策归属**：

| 决策 | 建议权 | 决定权 | 否决权 | 分级与依据 |
|---|---|---|---|---|
| 布局方案（技术域、矩阵维度、布局法） | 代理师 / 战略顾问、企业 IPR | IP 总监 | 业务负责人（技术方向失真时） | L3：方案可改，但一经转案即锁定预算 |
| 空白点是否补强（单格转案） | 企业 IPR、布局 Agent | IPR（额度内）/ IP 总监（超额度或批量） | 财务 | L2–L4，见下表 |
| 布局专项预算 | IPR + 财务 BP | IP 总监 + 财务；超阈值升 CFO | 财务 | L4（阈值按企业授权制度配置 ⚠） |
| 是否发起新申请族 | 代理师、IPR | IP 总监（须与 D1 一致） | 法务（权属、保密审查） | **L4**：申请日一经锁定不可逆 |
| 国别建议的采纳 | 战略 / 涉外 | IP 总监 | 财务 | 采纳结果即 D4 的输入；30 个月硬期限 ⚠ |
| 布局与单案的冲突 | 单案负责人、IPR | IP 总监 | — | 组合优先（§4.9 C2） |
| 放弃某个技术方向 | 战略、IPR | IP 总监 + 业务负责人会签 | 业务负责人 | L4：须同时处置存量资产 |
| 布局复盘结论 | IPR（数据）、代理师（专业） | IP 总监 | — | 年度；结论须能改预算与矩阵 |

**额度分级**（金额为示意 ⚠，须按企业授权制度配置，不得硬编码）：

| 层级 | 触发条件 | 批准人 | 典型情形 |
|---|---|---|---|
| L1 | 可逆 + 低金额 | 经办 IPR | 单格补检索、矩阵数据更新 |
| L2 | 可逆 + 高金额 | IP 总监 | 单格转案、单国补充布局 |
| L3 | 不可逆 + 低金额 | 双人复核 | 单件申请递交、同族补充 |
| L4 | 不可逆 + 高金额 | IP 总监 + 财务会签 + 双人复核 | 批量转案、新申请族、国别包 |

> **组合级决策的三条约束**（缺一条，布局台就退化成「申请量生成器」）：
>
> 1. **预算约束**：**布局不能成为无限申请的理由。** 每个补强建议须绑定预算科目与退出条件，无科目的建议不得转案。
> 2. **证据约束**：每个转案须有研发证据（交底、实验记录、样机），否则触碰非正常申请红线（§5.6）。
> 3. **质量约束**：组合价值在阻断与冗余，不在件数。**任何以「申请量」考核布局的做法都应被拒绝**（R08-01）。

**业务部门的位置：给方向，不给布局。** 业务部门最清楚市场在哪、产品往哪走，所以它对**技术方向**有输入权，方向明显失真时有否决权；但它不掌握专利密度、审查实践与预算结构，**不能决定布哪几格、进哪几国**。把布局决定权交给业务部门，结果是「哪个产品经理声音大，哪个方向就多申请」。

| ID | 规则 | 现状 |
|---|---|---|

### 3.6 三个容易混的对象

| 对象 | 是什么 | 有状态机吗 | 会变成案件吗 |
|---|---|---|---|
| `PatentLayoutDomain` | **域级**矩阵模板（可复用的图） | 无 | 否 |
| `LayoutCell` | 矩阵里的**一格**（决策单元） | 无 | 是（空白点转案） |
| `layout_insight` | 某个**案件上**的布局产物（交接对象） | 有（通用 7 态） | 否（它是交接，不是案） |

> 实习生最容易混的一点：**矩阵和交接产物不是一回事**。矩阵是共享的战略底图（可跨案复用），`layout_insight` 是挂在某个具体调研案上的交接记录。**同一张矩阵可以产出 N 份 `layout_insight`。**

## 4. 业务规则（编号 `R08-xx`）

### 4.1 布局的本质（组合而非数量）

| ID | 规则 | 现状 |
|---|---|---|
| R08-01 | 布局评价单位是**组合**，不是单件；考核指标不得用「申请量」 | ❌ 系统无组合对象 |

### 4.8 例外情形

布局规则写的是「须三维齐全」「须有研发证据」「不得超预算」。现场总有「这一次必须先动」的时候。**不给出口，人就在系统外做，矩阵就永远停在申请那天。**

本节只收**有依据、可复核**的例外。**「客户说这个方向一定火」不构成例外。**

| # | 例外 | 例外条件 | 谁批准 | 风险 | 留痕 |
|---|---|---|---|---|---|
| E1 | 竞品突然密集布局（某格 `rivalCount` 短期飙升） | 增速证据（近 12 月新增）可核，且该格属技术必经路径 | IP 总监（紧急通道，可在 3 个工作日内事后补矩阵） | 抢位易写成低质量申请，反成无效靶子；对手公开可能尚未入库，判断失真 | 必留：增速数据 + 数据截止日 + 抢位理由 |
| E2 | 核心专利被无效后的补救布局 | 已有无效/部分无效结论；补救方案落在**新格或新层级**，不是原权项改头换面 | IP 总监 + 法务会签 | 同族重复申请被认定非正常；补救若照抄原方案，仍会被同一证据打掉 | 必留：无效决定要点 + 与原方案的差异对照 |
| E3 | 预算削减仍需保布局 | 有明确的「必须保住」清单（制造地 / 主销售地 / 主对手所在地）与相应的放弃清单 | IP 总监 + 财务（L4） | 削减落在错误维度（保了国别、砍了核心格）；放弃后不可逆 | 必留：取舍依据 + 每项放弃的后果评估 |
| E4 | 技术路线转向致原布局失效 | 有立项文件或产品路线图变更可证；原矩阵格须标注「失效」而非删除 | IP 总监 + 业务负责人 | 存量资产成为沉没成本却仍缴年费；新旧路线交界处出现空档 | 必留：转向证据 + 存量处置方案（维持 / 转让 / 放弃） |
| E5 | 并购获得他方专利组合后整合 | 已完成权属尽调；组合存在重叠、断链或空档 | IP 总监 + 法务 + 财务 | 重复维持同一覆盖（白缴年费）；对方组合的既有许可负担被一并继承 | 必留：尽调结论 + 重叠映射表 + 处置决议 |

**E2 的边界（唯一需要单独建模的例外）**——「补救布局」最容易退化成「照原样再申请一遍」：

| 判断项 | 问什么 | 结论 |
|---|---|---|
| 无效理由是什么 | 新颖性 / 创造性 / 26 条 / 权属 | 26 条与权属类不构成对技术方案的否定，补救空间小 |
| 破坏性证据覆盖到哪 | 是否覆盖原独权全部特征 | 全覆盖 → 只能在**未公开的改进**上补救，原方案不得重提 |
| 是否有新研发证据 | 补救方案是否形成于无效之后且有记录 | 无 → 不得转案（R08-71） |
| 是否落在新格 | 矩阵格是否与原告不同 | 同格同方案 → 视为重复申请，走红线 |

> **例外不是豁免**：每条例外必须记录**依据、批准人、风险、有效期**四件，缺一视为违规（[decision-rights.md](../decision-rights.md) §4.2）。例外率异常升高，说明规则本身定错了，而不是执行者不听话。

**本节点的红线（任何批准都不能突破）**：

| 红线 | 原因 |
|---|---|
| 无研发证据的批量转案 | 非正常申请，全批驳回并影响信用（§5.6） |
| 用同一方案在核心专利被无效后原样重提 | 同一证据可再次打掉，且构成重复申请 |
| 用申请量作为布局的考核指标 | 直接把组合目标替换成数量目标（R08-01） |
| 矩阵格数据编造或回填「对手件数」 | 决策建立在假数据上，比没有矩阵更危险 |
| 对外承诺「布局完成后一定不侵权」 | 布局不产生 FTO 结论，法律上无法保证 |
| 未经保密审查即按布局向外国申请 | 中国完成的发明，中国专利权直接丧失 |

### 4.9 规则冲突与裁决

布局是**多目标决策**：要覆盖全、要花钱少、要快、要跟业务节奏。这四件事在本节点天天打架，而且**没有一个冲突能靠「谁职级高」解决**——因为它们衡量的是不同的东西。

**五类真实冲突**：

| # | 冲突 | 典型表现 | 裁决 | 裁决人 |
|---|---|---|---|---|
| C1 | 布局要全 vs 预算有限 | 矩阵识别 30 个空白点，预算只够 8 个 | **先排序后分配**：按「机会大小 × 进入成本 × 时间窗口」排序，取前 N；**不平均分配**。分配结果须标「未覆盖格」及监控方式，不得静默 | IP 总监，财务会签 |
| C2 | 单案最优 vs 组合最优 | 单案负责人要为一件核心案争最大范围，挤压同族其余各案预算 | **组合优先**（原则 3）：单案让步须书面记录「组合理由」；但**核心案的范围不得为凑数让位** | IP 总监 |
| C3 | 前瞻布局 vs 当期业绩 | 业务要今年见销量，布局要投 3 年后才见效的方向 | **两者并行、预算分离**：前瞻布局走专项预算，不占当期产品线预算；用「国别覆盖匹配度」「单点依赖度」而非「申请量」汇报 | IP 总监 + 业务负责人 |
| C4 | 技术方向未定 vs 布局需提前 | 产品路线未定，但 12 个月优先权窗口在走 | **先布可确定的下层**（材料、工艺、通用结构），上层应用留待方向明确；**不得为占位编造技术方案** | 代理师建议，IP 总监决定 |
| C5 | 自研 vs 收购 | 某格对手密集、自研赶不上，是否直接买一个组合 | **按「时间价值 + 断链风险 + 整合成本」三维比较**：自研能形成研发证据且时间够 → 自研；缺的是时间或关键族 → 收购；**两者不得同时全额立项** | IP 总监 + 财务（L4） |

**裁决顺序（自上而下适用）**：

| 序 | 原则 | 含义 | 本节点例 |
|---|---|---|---|
| 1 | **法定期限与合规优先** | 12 个月优先权、30 个月进入、保密审查不可让渡 | 窗口将关，先递合规版本（原则 4 联动） |
| 2 | **不可逆优先于可逆** | 先处理撤回不了的动作 | 申请日锁定先于矩阵美化 |
| 3 | **组合优先于单案** | 局部最优让位于组合整体 | C2：单案为组合让位，须留痕 |
| 4 | **期限优先于完备** | 有硬窗口的先占位，完备性其后 | 先布可确定的下层（C4） |
| 5 | **证据优先于判断** | 数据（`ourCount` / `rivalCount` / 增速）优先于直觉 | 矩阵过期时先更新数据，不先下结论 |
| 6 | **预算约束优先于覆盖愿望** | 无预算科目的建议不进入执行 | C1：排序后取前 N，不摊薄 |
| 7 | **书面留痕优先于口头一致** | 任何偏离须有书面理由与决策人 | 分歧不掩盖（[decision-rights.md](../decision-rights.md) §5.3） |

> **最重要的一条**：C2 是本节点最容易做错、后果最隐蔽的冲突。**单案负责人天然对「他那一件」负责，而组合的价值恰恰来自「某一件可以不那么强」。** 如果系统只按单案给 KPI，所有人都会去争自己那一件的最优解，组合反而塌掉。产品上必须让「组合结论」成为一类**可签署的对象**，而不是散落在各案备注里。

**冲突规则补遗**：

| ID | 规则 | 现状 |
|---|---|---|
| R08-77 | 偏离 §4.8 任一条例外的操作，须记录依据、批准人、风险、有效期四项，缺项不得执行 | ❌ 无例外对象 |
| R08-78 | 预算不足以覆盖全部空白点时，须输出「已覆盖 / 未覆盖 / 监控」三张清单，未覆盖项不得静默消失 | ❌ |
| R08-79 | 单案决策与组合结论冲突时，组合优先；单案偏离须附组合理由并由 IP 总监批准 | ❌ 无组合对象 |
| R08-80 | 前瞻布局须独立预算科目，不得与当期产品线预算混列；汇报不得以申请量代替组合指标 | ❌ |
| R08-81 | 技术方向未定时，只允许在技术树下层（材料/工艺/通用结构）布点，不得为占位虚构应用方案 | ❌ |
| R08-82 | 自研与收购两条路径须做三维比较（时间价值 / 断链风险 / 整合成本），不得同时全额立项 | ❌ 无组合对象 |
| R08-83 | 每格补强须绑定「若不布，多久后被对手占位」的倒计时；无倒计时的建议按最低优先级排 | ❌ 无时间维 |
| R08-84 | 矩阵数据截至日超过阈值（建议 30 天 ⚠）时，不得据此作出批量转案决议 | ❌ 无数据时间戳 |
| R08-85 | 任何布局决议须记录适用的裁决原则序号（§4.9），以便事后审计与复盘 | ❌ |

## 5. 法律底座 / 行业规则

布局本身没有「第 X 条」直接规定，它的约束来自**它依赖的下游程序**。这一节写的是**约束源**，不是发明出来的法条。

### 5.1 优先权：12 个月的窗口决定了同族的边界

**规则**：发明和实用新型在我国首次提出申请后 **12 个月**内（外观 6 个月 ⚠ 按类型核），就相同主题提出后续申请的，可享有优先权。PCT 国际申请同样须在优先权日起 12 个月内提出才可主张优先权。

**产品落点**：时间维度上，「这一格现在不申请，下次再补」是有代价的——**12 个月之后申请的同一技术，优先权日往后挪，中间公开的任何东西都成为现有技术**。系统必须在矩阵格上显示「若本月不立项，最晚什么时候必须进优先权」。

**失效后果**：错过 12 个月 → 优先权断，同族瓦解，中间的自家公开/对手公开直接摧毁新颖性。

### 5.2 PCT 30 个月：决定国别的时间闸

**规则**：自最早优先权日起 **30 个月**进入国家阶段；中国为 **30 个月**，缴宽限费后可延至 **32 个月**（详见节点 09）。

**产品落点**：地域维度的选择不是在申请时定的，而是在 30 个月这个闸口定的。**布局台给出的国别建议，实际是给 30 个月决策准备的材料**。系统应把「国别建议 → 30 个月倒计时 → 09 国家阶段」串成一条线。

**失效后果**：国别没想清楚，30 个月到了只能草率选几个国，或者放弃整个海外。

### 5.3 同族：布局的最小交付单元

**规则**：同一优先权下的一组申请构成专利族（patent family）。同族成员共享优先权日，但**各自独立审查、独立授权、独立维持**。

**产品落点**：组合管理的单位不是「件」，是「族」。系统必须能回答：「这个格子下有几族？每族覆盖几个国家？哪一族是核心？」

**失效后果**：按件管理会重复计算覆盖度，误以为某个国家已覆盖。

### 5.4 标准必要专利（SEP）：布局里唯一带强制义务的一类

**规则**：纳入标准的产品，其必要专利的权利人须按公平、合理、无歧视（FRAND）原则许可。标准必要专利的布局与普通专利在**许可义务**和**禁令救济**上受显著限制。

**产品落点**：矩阵格上须有 `SEP` 标记位。标了 SEP 的格子，补强建议不能只写「多申请」，必须写「参与标准提案 / 声明必要专利 / FRAND 报价策略」。

**失效后果**：把 SEP 当普通专利布局，承诺了 FRAND 又想拿禁令，会被反垄断与合同双重夹击。

### 5.5 组合价值 > 单件之和（实务，非条文）

**行业口径**：组合的价值来自四点，每一点都可写进产品：

| 来源 | 机制 | 产品落点 |
|---|---|---|
| **阻断** | 对手绕不开，只能谈许可 | 路障式布局评分 |
| **冗余** | 单件被无效，组合仍有效 | 单点依赖度指标 |
| **时效** | 不同申请日接力覆盖，延长整体保护期 | 时间维度视图 |
| **谈判** | 交叉许可时的筹码数量 | 组合规模与覆盖国数 |

> 这四条是**卖点**，也是**验收尺子**：一个布局产品如果算不出这四件事，它就只是张图。

### 5.6 非正常申请：批量布局的反向约束

**规则**（见节点 00 §10.7）：不以保护创新为目的、无真实研发基础的大量申请属非正常申请。

**产品落点**：布局台的「批量转案」必须有**研发证据校验**——一个空白点转成一个案，必须有对应的技术方案来源（交底、实验记录、样机）。**这是「地毯式布局」与「凑数」的分界线**，也是产品必须内置的合规闸。

**失效后果**：客户用布局台批量生成 200 个案，次年被认定为非正常申请，全部驳回并影响信用。

## 6. 状态机

### 6.1 矩阵格状态机（当前：静态，无迁移）

```
laid ⇄ blank ⇄ rival_dense      （代码里：无迁移，seed 写死）
```

**应有的状态机（产品口径）**：

```
未评估 ──► 已评估(laid/blank/rival_dense) ──► 布局中 ──► 已覆盖 ──► 需复核
                    │                          │                      │
                    └────── 放弃（记录理由）────┘                      │
                    ▲                                                 │
                    └───────────────── 复核触发 ◄─────────────────────┘
```

| 当前态 | 可迁往 | 谁做 | 业务含义 | 出口条件 |
|---|---|---|---|---|
| 未评估 | 已评估 | IPR | 完成一次矩阵扫描 | 有 `ourCount`/`rivalCount` |
| 已评估·空白 | 布局中 | IPR | 决定补强，已转案 | 生成了调研案 |
| 布局中 | 已覆盖 | 系统 | 案件授权 | 至少 1 件授权 |
| 任意 | 放弃 | IP 总监 | 战略放弃 | 填理由 + 影响评估 |
| 已覆盖 | 需复核 | 定时 | 年度复核 / 权利到期 | 距上次复核 > 12 月 |

### 6.2 `layout_insight` 交接状态机（通用 7 态）

```
drafting → submitted_to_enterprise → enterprise_review → approved → authorized_to_file → filed
                    ↕                        ↕
              changes_requested  ◄───────────┘
```

动作中文名（`packages/domain/src/handoff.ts:368-374`）：提交布局洞察 / **批准补强方向** / 确认可建案 / 归档布局洞察 / 退回布局建议。

> 「批准补强方向」这个命名值得保留——它准确表达了这一步批准的是**方向**，不是某件申请。

### 6.3 当前实现的偏差（逐条点名）

1. **矩阵不可编辑**：`MATRIX_SEED` 是 `LayoutFlow.tsx:29-33` 的模块级常量，**只有 3 行**，与 `PATENT_LAYOUTS`（9 格）是**两套数据**。工作台上的矩阵不是 `PatentLayoutDomain` 类型，只是临时数组。
2. **两套矩阵并存**：`src/pages/InsightLayout.tsx` 用 `PATENT_LAYOUTS`（9 格，带转案/派所），`apps/workbench/src/flows/layout` 用 `MATRIX_SEED`（3 行，无操作）。**同一个产品概念，两个不相通的实现。**
3. **`LayoutCell` 类型在工作台侧完全没用上**：`LayoutCell` 只在老中台 `InsightLayout.tsx` 里被 import。
4. **国别 chip 是游离态**：`countries` 只是 `string[]`，不进齐套（`countriesReady` 计算了但没进 `checkedRequired`，`LayoutFlow.tsx:414-418`），只写进草稿文本。
5. **补挂无授权**：见 §2。
6. **批准后自动同步补挂**是个隐式副作用：在批准成功时顺手改了另一个案的状态（`LayoutFlow.tsx:461-473`），且用的是 `silent: true`，只在 toast 里体现。
7. **无复盘态**：矩阵一旦写死，永远显示申请时的判断。

## 8. 步骤序列 / 工作流

`FLOW_CATALOG.layout` 三步（`src/data/flowSteps.ts:37`）：

| # | 步骤 | 谁做 | 耗时 | 产出 | 失败回退 |
|---|---|---|---|---|---|
| 1 | 洞察摘要 | 代理 / 战略 | 3–10 工作日 | 矩阵 + 空白点 + 补强建议 | 数据不足 → 退回 01 补检索 |
| 2 | 国别建议 | 战略 + 涉外 | 2–5 工作日 | 国别清单 + 理由 + 预算 | 预算超限 → 缩减国别、标记放弃后果 |
| 3 | 交接 | 代理提交 → 企业批准 | 1–3 工作日 | `layout_insight` + 建案 | `changes_requested` 退回 |

**每步完成条件（代码口径，`LayoutFlow.tsx:156-163`）**：

| 步骤 | 判据 |
|---|---|
| 1 | `matrixReady || blanksReady`（几乎是「打开了就有」） |
| 2 | `countriesReady && suggestReady` |
| 3 | 交接进入 `submitted_to_enterprise` 及以后 |

**应补的离线子流程（产品口径）**：

```
① 定域：选技术域 → 建技术树（上下游/替代/SEP）
② 建矩阵：行 × 列 定维度 → 填 ourCount / rivalCount（拉数据，不手填）
③ 标空白：算法判 blank → 人工复核 → 排序（机会 × 成本）
④ 选布局法：路障 / 包围 / 地毯 → 记录理由
⑤ 定国别：四维打分 → 必须进 / 可选进 → 预算
⑥ 定时间：12 月优先权 → 30 月 PCT → 排期
⑦ 转案：空白点 → 调研案（批量 / 派所）
⑧ 复盘：授权后回填实际覆盖
```

## 12. 指标（验收尺子）

| 指标 | 定义 | 健康区间 | 说明 |
|---|---|---|---|
| 空白点覆盖率 | 已转案空白格 / 识别出空白格 | 30%–70% | 过低=识别了不落地；过高=乱申请 |
| 矩阵数据新鲜度 | 距最近一次数据更新 | < 30 天 | 过期矩阵比没有更糟 |
| 组合单点依赖度 | 核心专利数 / 组合总件数 | < 30% | 过高=一无效就塌 |
| 国别覆盖匹配度 | 已布局国 ∩ 实际销售国 / 实际销售国 | > 80% | **能换算成钱**（漏一个市场=漏一份收入） |
| 优先权窗口命中率 | 12 个月内完成同族布局的比例 | > 90% | 硬指标 |
| 每空白点转案成本 | 调研+撰写+申请总成本 / 转案数 | — | 反推布局 ROI |
| 布局复盘完成率 | 年度复盘的组合占比 | 100% | 战略纪律 |
| 组合许可收入 | 组合整体许可/转让收入 | — | **能换算成钱** |

> 卖点时优先讲「国别覆盖匹配度」和「组合许可收入」——前者是风险敞口，后者是直接回报。

## 13. 产品化切分建议

| 层 | 内容 | 是否可独立交付 |
|---|---|---|
| L1 矩阵层 | 技术树 + 热力矩阵 + 空白标注 | 是（最低配，易白牌） |
| L2 数据层 | 我方/对手件数自动拉取（替代手填） | 依赖数据源 |
| L3 组合层 | 族/依赖/单点风险/时效接力 | 是（差异化核心） |
| L4 地域层 | 四维打分 + 预算 + 与 09 对接 | 是（涉外客户买单） |
| L5 时间层 | 12/30 月倒计时 + 排期 | 是（与 docket 打通） |
| L6 转案层 | 批量转案 + 派所 + 幂等 + 回写 | 是（落地闭环） |

**定价锚点**：按「技术域数」或「矩阵格数」计价；也可按「组合管理件数」年费。

**竞品参照系**：PatSnap / Incopat 的「技术全景」强在数据可视化，弱在**转案闭环**；Anaqua 强在组合管理，弱在中国国别与本地渠道。**「矩阵 → 空白点 → 转案 → 回写」这条闭环是空位**——市面上的工具大多停在「看图」，不走到「建案」。

| 15 | 批准时静默同步补挂另一个案（隐式副作用） | 低 | 难以审计 |
| 16 | 提交未走中央闸（只走本地 `validateBefore`） | 低 | 与 00 不一致 |

**优先补的三件事**（按投入产出比）：

1. **持久化 + 统一矩阵模型**（差距 1、2）—— 不做这两条，其余全部无从谈起；工作量小，全靠把 `PATENT_LAYOUTS` 提到 domain 层并落地 store。
2. **结构化齐套 + 国别四维**（差距 3、6）—— 把「非空」换成「矩阵有 ≥N 格且有 ourCount/rivalCount」「国别有理由与预算」，直接决定产品能否卖。
3. **组合对象 + 时间维度**（差距 4、5）—— 这是与「看图工具」拉开差距的地方，也是 09 PCT 的上游依据。

## 15. 术语表

| 术语 | 含义 |
|---|---|
| 布局 / Layout | 在技术、地域、时间三维上成体系地布置专利权利 |
| 组合 / Portfolio | 围绕一个技术目标的一组专利族，按整体而非单件评价 |
| 专利族 / Family | 共享同一优先权的一组申请，各自独立审查与维持 |
| 路障式布局 | 在对手必经路径上布点，迫使其绕行或交叉许可 |
| 包围式布局 | 围绕核心专利在外围布多件，核心被绕开仍被外围拦住 |
| 地毯式布局 | 细分领域密集布点，靠覆盖面取胜（成本高） |
| 空白点 / Blank Spot | 我方与对手都稀疏的矩阵格，通常是补强机会 |
| 对手密度 / Rival Density | 某一格内对手公开量，反映拥挤程度与 FTO 风险 |
| SEP / 标准必要专利 | 实施标准必然使用的专利，权利人负 FRAND 许可义务 |
| FRAND | 公平、合理、无歧视的许可承诺 |
| 单点依赖度 | 组合对单一核心专利的依赖程度，越低越稳 |
| 优先权窗口 | 首次申请后 12 个月（外观 6 个月）内可主张优先权的期间 |
| `layout_insight` | 本节点的交接产物键，轴外键，不占 `research_report` |
| 补挂 | 把 `layout_insight` 写到已存在的调研案上，仅置 `drafting`，不等于批准 |
