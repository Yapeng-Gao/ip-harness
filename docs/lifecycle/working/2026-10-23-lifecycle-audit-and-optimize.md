## 1) 我理解的业务总图（短）

专利业务 = **把技术事实变成可主张、可维持、可变现的法律权利**。仓库用「三转换」说清本质：确权 → 维持 → 变现。

**默认「拿专利」主链（讨论已确认合成方向）**：

```
激发(可轻) → 捕获 → 挖掘(可粗检) → 交底(00) → 查新/可专利性(01)
  → (FTO 01b 按需，不堵申请) → 布局刷新(08/Nl) + 单案决策(02)
  → 撰写∥附图(03) → 定稿 → 递交→缴费→初审→公布∥实审→答复(04)
  → 授权登记 → 年费(05)
```

**必经分层**：

| 层 | 含义 | 例子 |
|---|---|---|
| 法律必经 | 法条/程序硬规则，产品不得「业务跳过」 | 递交齐套、期限答复、年费、保密审查（涉外时） |
| 业务必经 | 代理所/企业质控 SOP，零交底零检索零立项开写不合格 | 交底、查新、立项签字、撰写定稿 |
| 条件触发 | 触发后有规则；不触发不堵主链 | 激发加重、FTO、PCT、附图（结构类）、复审/无效/诉讼 |

**仓库骨架（应保留为母本）**：六主体、五层对象、A–E 规则、三时钟、四口袋、D1–D7、12 失败模式、节点 17 节规格、横切 10–13、product-logic SKU。

**一句话理解**：spine/nodes 已经把「确权后到变现/对抗」和「单节点怎么做成可测规则」写深了；缺的是**交底之前的前端主链**（激发/捕获/挖掘）、**主链必经分层写死**、以及多处**命名与决策落点不一致**——优化应以「补齐 + 对齐」为主，不是推倒重写。
