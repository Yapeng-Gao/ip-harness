## 1. 产品理念

### 1.1 为谁

| 使用人 | 他们是谁 | 他们不懂什么 | 他们要什么 |
|---|---|---|---|
| **中小企业研发人员**（发明人 / 技术负责人） | 做产品、写方案、跑实验的人；公司往往没有专职 IP 部 | 不懂专利程序、不懂「Agent」、不懂交底写到什么粒度才够 | 少填表、快有人接、知道现在卡在哪、关键节点有人告诉自己「过」还是「补」 |
| **代理所代理人**（代理人 / 流程员） | 接案、检索、撰写、答复、盯期限的人 | 不需要再学一套开发黑话；要的是案卷清楚、闸门清楚、责任清楚 | 把客户当「外挂 IP 部」一起用：材料齐、确认快、期限不漏 |

**不是首要用户（本层叙事不优先）**：大型企业已建制的 IP 总监（他们更吃 spine / product-logic 的组合管理语言）；纯诉讼律所（支线能力，不进默认「拿专利」上手路径）。

### 1.2 卖什么（价值主张）

**一句话**：给没有 IP 部（或 IP 部人手不够）的团队，装上一个**外挂知识产权部**——按专利全流程办事，帮你把技术尽快变成可递交、可授权、可维持的专利。

展开三句：

1. **覆盖拿专利全流程**（激发/挖掘可选加重 → 交底 → 查新 → 策略 → 撰写定稿 → 递交 → 审查答复 → 年费），不是单点写交底或单点查新工具。  
2. **简单、拟人、像公司**：你不学「智能体」，你只进「公司」，找「当前部门」，看「专家」交卷，铃铛里点确认。  
3. **关键关有人拍板**：部门交卷后默认「待你确认」再往下；产品替你防的是「空材料装完成」「无人确认就递交」这类失败，而不是替你签字。

### 1.3 拟人化隐喻（对外唯一叙事）

| 隐喻 | 是什么 | 不是什么 |
|---|---|---|
| **公司** | 整案 / 整条专利管线的「虚拟 IP 部」；一个案子 = 公司里的一条业务线（或一个项目） | 不是用户的真实工商主体；不是聊天机器人品牌名 |
| **部门** | 主链上的一个**流程节点**（或紧密捆绑的一小段）；部门有交卷入、交卷出 | 不是组织架构图上的真实科室；不是「功能菜单分组」随便起的名字 |
| **专家** | 部内协作的角色位：起草、检索、制图、质检、对发明人访谈等；多人/多角色协作把本部门交卷做好 | 不是对外宣传的「AI Agent」；不是可以无人确认就改法律状态的自动签字人 |
| **交卷 · 待你确认** | 部门产出齐套后停下，等使用人（或指定负责人）确认，再移交下一部门 | 不是装饰按钮；不是「下一步」的文案替换 |

**对外禁用词（产品文案 / 上手引导）**：Agent、Harness、智能体编排、Seat、HITL（可用「待你确认」「部门闸」等白话）。  
**对内文档可用**：spine、nodes、D1–D7、HITL、交接机——写给做产品的人，不写进用户第一屏。

### 1.4 上手三步（小白路径）

1. **开案子**（成立这条业务线 / 进公司）  
2. **看当前部门**（现在卡在交底部还是查新部）  
3. **铃铛确认**（部门交卷 → 待你确认 → 进入下一部门）

发明人与代理人可以分工：发明人主要在「交底部」补材料与确认技术真实；代理人贯通多部门；企业侧负责人在策略部、定稿部、答复部等关键闸上点确认。

## 2. 产品逻辑

### 2.1 三层结构如何运转

```
公司（整案）
  └── 部门（主链节点 / 节点组）  —— 有输入契约、输出交卷、完成标准
        └── 专家（部内角色）    —— 协作把交卷做齐；产出多为「建议稿」
              └── 交卷闸「待你确认」—— 人采纳后才移交下一部门或改法律相关状态
```

规则（业务口径，非代码）：

1. **一案一公司视图**：用户始终知道「这个案子现在在哪个部门」。  
2. **一部门一交卷**：没有可核验产物，不得标完成（对齐 spine INV-7）。  
3. **专家可并行，部门默认串行**：部内专家可同时干活；部门之间按主链顺序推进，允许标注的回流（如查新后退回交底部补强）。  
4. **确认权跟人走，不跟「专家」走**：专家（含自动化起草）只有建议权；确认权落在发明人 / 代理人 / 企业负责人等真实主体（对齐 decision-rights / spine 决策落点）。  
5. **法定动作不可「业务跳过」**：递交、缴费、实审请求、年费等法律必经，产品可以提醒、准备材料，但期限与效力以法条为准。

### 2.2 默认「部门」划分（对外）

部门名用业务白话；括号内为讨论主链代号。合并 spine 后编号以正式节点为准。

| 顺序 | 对外部门名 | 主链 | 部门一句话 | 典型交卷 | 典型「待你确认」 |
|---|---|---|---|---|---|
| 1 | 创新激发部 | Ni | 还有哪些方向值得做成专利 | 方向清单 | 哪些方向进捕获 |
| 2 | 捕获台 | Nc | 点子/项目正式挂进专利管线 | 线索台账项 | 是否进入挖掘、是否先保密 |
| 3 | 挖掘部 | Nm | 申什么、拆几案、怎么分级 | 挖掘报告（可含粗检） | 哪些点开交底、优先级 |
| 4 | 交底部 | 00 / N1 | 写成可检索、可撰写的技术方案 | 技术交底书 | 交底是否齐套、发明人确认真实 |
| 5 | 查新部 | 01 / N2 | 能不能授权（可专利性） | 检索报告 | 继续 / 改写 / 暂缓 / 放弃 |
| — | 自由实施部（按需） | 01b / N3 | 能不能安全卖（FTO） | FTO 报告 | 规避 / 许可 / 挑战 / 推迟上市 |
| 6 | 布局办 | 08·Nl | 整盘怎么护（组合图） | 布局图 / 族谱 | 核心-外围与地域时序 |
| 7 | 立项部 | 02 / N4 | 这一案申不申、申什么、预算 | 单案决策书 | **签字或可追溯确认后才开写**（D1/D2） |
| 8 | 撰写部 | 03 / N5 | 说明书与权利要求成型 | 申请文件稿 | 权要范围与敏感披露（D3） |
| 9 | 附图部（按需） | N6 | 图文一致、类型所需视图 | 附图 / 外观视图 | 图文是否可定稿 |
| 10 | 定稿部 | 定稿闸 | 递交前齐套与最终确认 | 电子申请包 + 检查表 | 主体/优先权/是否提交 |

| 13 | 维持部 | 05 | 年费与权利去留 | 续费/放弃决议 | 续费或放弃（D6） |

**支线部门**（不进默认上手主链，公司内可按需开设）：运用部（06）、监控部（07）、国际部（09）、无效部（22）、终止恢复（23）、维权诉讼部（24）。权利比对（25）是多部门共用的「工具台账」，不单独做成必经部门。

**横切（对内能力，对外弱化成公司后勤）**：交接与审批（10）、期限台（11）、商务结算（12）、自动化边界（13）——用户感知为「铃铛、期限、账单、谁在起草」，不感知为独立「Agent 产品」。

### 2.4 HITL = 部门交卷 · 待你确认

对内词 HITL，对外只说：

> **本部门已交卷，待你确认后进入下一部门。**

产品逻辑要求：

| 规则 | 说明 |
|---|---|
| 交卷齐套 | 部门完成标准未满足 → 不能点「交卷」 |
| 确认才移交 | 未确认 → 下一部门不可正式开工（允许预读材料，不允许当作已立项/已定稿） |
| 确认可驳回 | 驳回必须带回意见，案子回到本部门或指定回流部门 |
| 关键确认对齐 D1–D7 | 立项部确认 ≈ D1/D2；撰写/定稿关键范围确认 ≈ D3；答复策略 ≈ D5；续费 ≈ D6 等——**不得退化成无决策含义的「下一步」** |
| 不可逆动作 | 递交、放弃、对外承认等：专家只能准备到「差一个确认」；确认人承担采纳责任（对内见 nodes/13 铁律，对外只保留白话责任提示） |

### 2.5 专家在部内怎么出现（叙事层）

每个部门展示「本部门专家协作」，例如交底部：访谈专家、交底结构化专家、齐套质检；查新部：检索专家、对比文件解读；撰写部：权要专家、说明书专家、发明人审阅席。

原则：

- **专家 = 岗**，可以是人，也可以是「辅助起草」——对用户都叫专家协作，不叫 Agent。  
- **多个专家服务一个部门交卷**；跨部门不靠用户记得「该找哪个机器人」，而靠案子自动停在当前部门。  
- 与仓库 nodes/13「Agent 是手、专家席是岗」**对内一致**；**对外只保留「岗 / 专家」**。

## 3. 与 A/B 合成的对应

| 层级 | 采用 | 本工作稿中的落点 |
|---|---|---|
| 业务骨架（三转换、六主体、对象、规则、时钟、口袋、D1–D7、失败模式） | **B** | 部门确认对齐 D1–D7；交卷对齐 INV-7；不另起决策编号 |
| 节点规格深度（17 节、R 编号） | **B** | Ni/Nm/Nc 将来按模板补；本稿只定部门意图 |
| 默认主链前段 + 法律/业务/条件分层 | **A** | §2.2 部门顺序与必经列 |
| 交底→查新；FTO 按需；布局图+单案决策两份产出 | **A** | 交底部→查新部；自由实施部按需；布局办与立项部可同会两份交卷 |
| 03 vs 08 拆清 | **A 主张 + B 已有节点** | 撰写部 ≠ 布局办 |
| 对外叙事 | **本稿（拟人化）** | 公司/部门/专家；禁用 Agent 黑话 |
| 商业化 SKU / 定价 / 采购 | **仍以 product-logic 为准** | 本稿不重写；以后叙事入口可指向「外挂 IP 部」再映射 SKU |

**冲突裁决**：业务实务与法条 > 经确认的工作稿 > 旧原型；骨架以 spine 为准；主链前段与部门顺序以经确认的 A + 本理念稿为准。
