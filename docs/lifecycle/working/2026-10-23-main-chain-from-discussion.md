## 1. 默认主链（中国发明 · 确权前段 + 确权后段）

临时节点代号仅用于讨论对齐；合并进 spine 时再正式编号。

| 代号 | 名称 | 说明 |
|---|---|---|
| Ni | 创新激发 | 方向清单；可轻做，可与研发并行 |
| Nc | 捕获 | 技术事实入池（点子/项目产出登记） |
| Nm | 专利挖掘 | 申什么、拆几案、分级；可粗检，不替代单案查新 |
| 00 | 发明交底 | 技术事实 → 可撰写材料 |
| 01 | 查新 / 可专利性检索 | 授权可能性证据 |
| 01b | FTO | **按需**；侵权风险，非申请必经 |
| Nl + 02 | 布局刷新 + 单案决策（立项） | 可同会，须两份可追溯产出 |
| 03 | 撰写 ∥ 附图 | 权利边界成型；附图条件触发 |
| — | 定稿 | 递交前齐套与签字 |
| — | 递交 → 缴费 → 初审 → 公布 ∥ 实审请求 → 实审 ↔ 答复 → 授权登记 → 年费 | 国知局法定主链（维持见 05） |

**默认顺序（一句话）**：

```
激发(可轻) → 捕获 → 挖掘(可粗检) → 交底 → 查新 → (FTO 按需)
  → 布局刷新 + 单案决策 → 撰写 ∥ 附图 → 定稿 → 递交 → … → 年费
```

**实用新型 / 外观设计**：初审后跳过公布与实审（仍须业务前段与递交齐套）。  
**支线**（不进默认主链）：复审、无效（22）、诉讼维权（24）、PCT/国际（09）、监控（07）、运用（06）等。

### 1.1 边界一句话（讨论已对齐）

| 能力 | 回答的问题 |
|---|---|
| 创新激发 Ni | 还有什么方向值得做 |
| 专利挖掘 Nm | 申什么、拆几案、怎么分级 |
| 布局 Nl / 08 | 整盘怎么护（技术/地域/时间） |
| 查新 01 | 能不能拿到授权（可专利性） |
| FTO 01b | 能不能安全卖（侵权风险） |
| 单案策略 / 立项 02 | 这一案要不要申、申什么类型、预算与委托 |

查新与 FTO **不能互代**。

## 2. 法律必经 vs 业务必经 vs 条件触发

### 2.1 法律必经（程序 / 法定硬规则）

以专利法和实施细则、审查指南及官费程序为准。大致包括：递交齐套、缴费、初审、公布（发明）、实审请求（发明）、实审与期限答复、授权登记、年费维持等。  
**产品不得用「业务跳过」绕开法定动作与期限。**

### 2.2 业务必经（拿专利流水线质控 · 行业 SOP）

从「有技术事实」到「可负责任地递交」的企业内部 / 代理所质控默认必走：

- 捕获（或等价入池）
- 挖掘（至少判定申不申、拆不拆案；可与交底紧耦合）
- **交底（00）**
- **查新 / 可专利性检索（01）**
- **单案决策 / 立项（02）** —— 签字（或可追溯确认）后再开写
- **撰写与定稿（03 + 定稿闸）**
- 递交准备（保密审查等法定前置按情形触发）

创新激发 **可轻做**，但「零交底、零检索、零立项直接开写」不符合代理所 / 企业质控常识。

### 2.3 条件触发（可选，但触发后有规则）

| 项 | 触发条件（示例） |
|---|---|
| 创新激发 Ni 加重 | 研发规划季、新品立项前、布局空白域 |
| 挖掘阶段粗检 | 海量点子筛选；**不替代**单案 01 |
| FTO 01b | 产品定型 / 上市 / 融资尽调 / 高风险领域；**不是「申请专利」本身的必经** |
| 附图 | 产品 / 结构类；纯方法可视案情减免 |
| PCT / 多国（09） | 出海、制造地/销售地策略 |
| 复审 / 无效 / 诉讼 | 驳回不服、被诉、主动清障等 |

## 3. 三个顺序问题 · 实务结论与依据摘要

### 3.1 交底与查新：谁先？

**结论：先交底（可撰写粒度），再做完整可专利性检索（01），再立项（02），再撰写。**

| 依据类型 | 摘要 |
|---|---|
| 代理所 / 企业质控 SOP | 无齐套交底则检索对象不清（技术方案、实施例、拟保护点漂移），完整查新无法收敛；挖掘阶段允许粗检筛案。 |
| 与仓库节点一致 | [01](../nodes/01-research.md) 定位为「供立项决定要不要申请」的证据；[00](../nodes/00-inventor-disclosure.md) 上游提供可检索 / 可撰写材料；[00b](../nodes/00b-invention-point-chain.md) 链为交底 → 初审 → 检索 → 发明点 → … |
| 回流 | 查新可导致交底补强或拆合案；允许回流，但不把「先随便写说明书再补交底」当默认。 |

**不采纳**：以旧原型「查新 → 立项 → 交底」界面顺序作为业务默认。

### 3.2 FTO 是不是「拿专利」必经？

**结论：不是申请 / 确权主链的法律或业务必经；是产品商业化与风险控制的条件触发节点。**

| 依据类型 | 摘要 |
|---|---|
| 概念区分 | 可专利性 = 我能否获得权利；FTO = 我实施会否落入他人有效权项。见 [01b](../nodes/01b-fto.md) 实习生口径。 |
| 实务 | 中小企业大量「先确权、后视上市再 FTO」；上市、定型、融资、高竞争赛道则应触发。 |
| 产品 | 默认主链可跳过 01b；跳过须可标记风险接受，不得暗示「有专利 = 可自由卖」。 |

### 3.3 策略 / 立项要不要独立、签字才开写？

**结论：业务必经关。** 交底 + 检索之后，必须有可追溯的「要不要申 / 申什么 / 预算与委托」决策，再进入撰写。

| 依据类型 | 摘要 |
|---|---|
| 决策落点 | spine §7：D1/D2 在立项（02）；不得在交底里再判一次「要不要申请」。 |
| 商业 | 前置花钱、后置收益不确定；无立项开写是最常见的白花钱模式之一。 |
| 与布局 | 可与布局同会召开，但产出须可拆：**布局图 / 组合决议（Nl·08）** + **单案决策书（02）**。 |
