# 决策权 · 例外 · 冲突裁决（跨节点统一框架）

> **这是一份横向标准，不是流程节点。** 它规定三件在每篇节点文档里都必须回答的事：
> 1. **谁有权决定**（决策权）
> 2. **什么情况下可以不遵守常规规则**（例外）
> 3. **两条规则打架时听谁的**（冲突裁决）
>
> 用法：各节点在 §2 之后写 `§2.1 决策权`，在 §4 之后写 `§4.x 例外` 与 `§4.y 冲突裁决`，内容以本文为准则，按本节点实际决策条目化。
>
> 上游：[business-spine.md](business-spine.md) §2（主体与冲突）、§4（五类规则）、§7（七个决策点）。

## 0. 为什么单独立这份文档

审计现有 21 篇节点文档，发现一个系统性缺口：

| 检查项 | 覆盖情况 |
|---|---|
| 角色权限矩阵（谁能看/能操作） | 21/21 有 |
| **决策权（谁能拍板、拍多大）** | **5/21 有，且不成体系** |
| **例外情形（何时可破例）** | **6/21 有，零散** |
| **规则冲突与裁决（听谁的）** | **3/21 有，且无原则** |

**后果**：规则写了 700 条，却回答不了三个真问题——

- 谁有权决定「这件不申请了」？
- 客户坚持要打，但律师认为必输，听谁的？
- 两条规则都成立但结论相反，按哪条？

**这是业务逻辑与操作手册的分界线。** 没有决策权的规则清单，只能培训，不能上线。

## 1. 决策权模型：四种权力，必须分开

### 1.1 四种权力

不是「谁能做」，而是「谁有权决定」。四个层级：

| 权力 | 含义 | 能否被推翻 | 典型持有者 |
|---|---|---|---|
| **知情权** | 必须被告知结果 | — | 业务部门、财务、被影响方 |
| **建议权** | 可以提出方案，但不定 | 可 | 代理师、律师、IPR、系统 |
| **决定权** | 拍板，并对结果负责 | 不可（除非更高层） | 客户、IP 总监、法务总 |
| **否决权** | 可以叫停已决定的事 | **可以** | 法务（合规）、财务（预算超限）、合规官 |

### 1.2 最容易错的三处

| 错误 | 表现 | 后果 |
|---|---|---|
| **把建议权当决定权** | 代理师写的方案直接执行，客户没签字 | 出事后责任不清，客户不认账 |
| **把决定权给执行者** | 财务直接决定「不缴年费了」 | 越权处置资产 |
| **忘记否决权** | 业务决定上市，法务不知情 | 高风险产品带着已知侵权上市 |

### 1.3 一条铁律

> **建议权与决定权必须分离，且分离要在系统里体现（签字、留痕、不可代签）。**

理由：专利业务的每一次重大决策都伴随**利益冲突**（业务要快、法务要稳、财务要省）。如果决策者与建议者是同一人，冲突就被掩盖了，而不是被解决了。

## 2. 决策分级：按「不可逆性 × 金额」定审批层级

### 2.1 分级矩阵

不按「重要性」这种模糊标准分级，按两个可量化维度：

| | 可逆 | 不可逆 |
|---|---|---|
| **低金额** | L1 经办人自主 | L3 双人复核 |
| **高金额** | L2 主管批准 | **L4 高层批准 + 双人复核** |

### 2.2 四级的定义

| 级别 | 条件 | 谁批 | 留痕要求 |
|---|---|---|---|
| **L1** | 可逆 + 低金额 | 经办人（IPR / 代理师） | 系统记录 |
| **L2** | 可逆 + 高金额 | 部门主管 | 审批流 + 理由 |
| **L3** | 不可逆 + 低金额 | 双人复核（发起人 ≠ 批准人） | 双签 |
| **L4** | 不可逆 + 高金额 | 高层 + 双人复核 | 双签 + 决议纪要 |

> **金额阈值因企业而异，产品上必须可配置。** 文中不写具体数字，只写结构。

### 2.3 哪些决策是「不可逆」的（这是分级的核心）

| 决策 | 为什么不可逆 |
|---|---|
| 主动放弃专利 | 声明后一般不可撤回 |
| 放弃恢复权利 | 错过期限即永久丧失 |
| 公开技术（论文、展会、发布会） | 一经公开，新颖性永久丧失 |
| 递交申请文件 | 申请日锁定，内容不得超范围修改 |
| 承认侵权 / 和解签字 | 法律效力，难以推翻 |
| 撤回起诉 / 撤回无效请求 | 同一理由再提受限 |
| 对外发表声明（PR） | 无法收回 |
| 删除已提交的证据材料 | 举证机会丧失 |

**产品含义**：这八类操作在系统里必须走 L3/L4，且**不得提供「一键执行」**。

## 4. 例外情形：什么情况下可以破例

### 4.1 例外的三种来源

破例不是「特批」，必须有依据。三类：

| 来源 | 含义 | 谁能批准 |
|---|---|---|
| **法定例外** | 法律本身规定了例外（如宽限期、恢复权利） | 不需要内部批准，但须留痕 |
| **合同例外** | 合同/许可条款约定的特殊安排 | 法务 |
| **内部例外** | 企业自定的破例规则（如紧急通道） | 按分级 |

> **产品含义**：法定例外不能做成「特批按钮」，它是**规则的一部分**，应该内置。

### 4.2 例外必须带的四件事

任何破例，系统必须记录：

| 项 | 说明 |
|---|---|
| **依据** | 法定某条 / 合同某款 / 内部某规则 |
| **批准人** | 谁批的，级别是否够 |
| **风险** | 破例带来什么后果 |
| **期限** | 是一次性还是长期有效 |

**缺任何一项的破例，视为违规操作。**

### 4.3 不能破例的红线

有些事无论谁批都不能做：

| 红线 | 原因 |
|---|---|
| 编造现有技术公开号 | 诚信问题，构成非正常申请 |
| 虚列发明人 | 署名权纠纷 + 无效风险 |
| 隐瞒已知的公开事实 | 新颖性已丧失，申请必败 |
| 对外承诺「保证不侵权」 | 法律上不可能保证 |
| 承诺授权率 | 诱导非正常申请 |
| 伪造研发过程证据 | 违法 |
| 绕过保密审查直接向外申请 | 直接丧失中国专利权 |

**这些不是「高风险」，是「不可做」。** 系统应硬阻断，不提供特批入口。

## 5. 冲突裁决：两条规则打架时听谁的

### 5.1 五条裁决原则（按优先级）

当规则冲突时，按以下顺序裁决，**上位优先**：

| 序 | 原则 | 含义 | 例 |
|---|---|---|---|
| 1 | **法定优先于约定** | 法律强制规定不能被内部规则覆盖 | 答复期限不能因「内部流程慢」而延长 |
| 2 | **合规优先于效率** | 合规否决权高于业务决定权 | 保密审查未过，业务不能先发样品 |
| 3 | **不可逆优先于可逆** | 不可逆决策优先获得决策资源与时间 | 放弃声明 vs 缴费延后，先处理放弃 |
| 4 | **期限优先于质量** | 有法定死线的先做，质量在其后 | OA 答复临近，先递合规版本 |
| 5 | **一致优先于局部最优** | 对外口径、组合策略统一 | 单案最优让位于组合最优 |

### 5.2 常见冲突与裁决表

| 冲突 | 一方 | 另一方 | 裁决 |
|---|---|---|---|
| 省钱 vs 布局需要 | 财务 | IP 总监 | 组合层面权衡；单件服从组合（原则 5） |
| 业务要快 vs 法务要稳 | 业务 | 法务 | 合规优先（原则 2） |
| 客户要求打 vs 律师认为必输 | 客户 | 律师 | **客户决定，但律师意见必须书面留痕** |
| 检索不充分 vs 期限临近 | 质量 | 期限 | 期限优先，但须书面声明局限（原则 4） |
| 保密 vs 公开审理 | 技术保密 | 程序公开 | 申请不公开审理；不能因此放弃举证 |
| 多案资源冲突 | 各案 | 全局 | 按「金额 × 胜率 × 紧迫度」排序 |
| 代理所报价 vs 服务质量 | 采购 | IP | 质量指标优先，价格其次 |
| 同族多国预算不足 | 各国 | 总预算 | 按「制造地 > 销售地 > 对手所在地」优先 |

### 5.3 无法裁决时怎么办

有些冲突没有客观答案（如「客户坚持要打」）。处理方式：

1. **升级**：提交给上一级决策者；
2. **留痕**：记录双方意见与最终决定人；
3. **免责**：专业意见（律师/代理师）必须以书面形式提出，明确「已告知风险」。

> **产品含义**：系统应支持「意见分歧」状态，而不是强迫达成一致。**记录分歧比假装一致更有价值**——诉讼、审计、纠纷时，这份记录就是证据。

## 7. 术语

| 术语 | 含义 |
|---|---|
| 建议权 | 可提出方案但不定 |
| 决定权 | 拍板并对结果负责 |
| 否决权 | 可叫停已决定的事 |
| 知情权 | 必须被告知 |
| 不可逆决策 | 执行后难以或无法恢复的决策 |
| 法定例外 | 法律本身规定的例外情形 |
| 红线 | 任何批准都不能突破的禁止事项 |
| 分歧留痕 | 记录不同专业意见与最终决定，而非掩盖 |
