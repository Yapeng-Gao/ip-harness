# 产品理念（Product Vision）

> **一句话（核心理念）**：给没有 IP 部（或人手不够）的团队，装上一个**外挂知识产权部**——按专利全流程办事，把技术尽快变成可递交、可授权、可维持的专利。  
> **公司 / 部门 / 专家**不是产品本身，而是把核心理念讲清楚、让人容易上手的**对外叙事与流转隐喻**。  
> **上游**：业务总纲 [business-spine.md](business-spine.md)、节点 `nodes/`、参考来源 [sources.md](sources.md)。  
> **下游**：商业切分 / SKU / 定价见 [product-logic.md](product-logic.md)（理念定「像什么、怎么走」；产品逻辑定「怎么卖、先做哪个」）。  
> **定稿**：2026-10-23（Asia/Shanghai）。工作讨论底稿：[working/2026-10-23-product-vision-company-dept-expert.md](working/2026-10-23-product-vision-company-dept-expert.md)。

## 1. 核心理念

| | |
|---|---|
| **是** | 外挂知识产权部：覆盖「拿专利」主链，关键关有人拍板，材料与期限按实务与法条走 |
| **不是** | 单点交底模板、单点查新插件、或「AI Agent 目录」 |
| **成功标准** | 研发知道案子卡在哪、该补什么；代理人案卷齐、确认快、期限不漏；无人确认不能装成已递交/已立项 |

展开三句：

1. **全流程，不只单点**：激发/挖掘可按需 → 交底 → 查新 → 立项 → 撰写 → 递交 → 答复 → 年费（支线按需开设）。  
2. **简单、拟人、像公司**：用户不学编排黑话；进「公司」、看「当前部门」、认「专家交卷」。  
3. **关键关人拍板**：部门交卷后默认「待你确认」再往下；产品防的是空材料装完成、无人确认就递交，**不替人签字**。

## 2. 为谁

| 使用人 | 不懂什么 | 要什么 |
|---|---|---|
| **中小企业研发**（发明人 / 技术负责人） | 专利程序、交底粒度、黑话 | 少填表、有人接、知道卡点、过/补说清楚 |
| **代理所代理人**（代理人 / 流程员） | 不需要再学开发黑话 | 客户像外挂 IP 部一起用：材料齐、确认快、期限不漏 |

**非上手第一用户**：大型已建制 IP 总监（更吃 spine / 组合管理语言）；纯诉讼律所（支线能力）。

## 3. 对外叙事：公司 · 部门 · 专家

> 设计这套隐喻的**唯一目的**：把核心理念传出去，降低上手成本。对内仍可用 spine / nodes / D1–D7 / HITL。

| 隐喻 | 是什么 | 不是什么 |
|---|---|---|
| **公司** | 整案的虚拟 IP 部；一案 = 一条业务线 | 用户的真实工商主体；聊天机器人品牌名 |
| **部门** | 主链上的一站（或紧密一小段）；有输入契约、交卷出 | 真实科室；随便起的菜单分组 |
| **专家** | 部内协作岗：起草 / 检索 / 制图 / 质检等；把本部门交卷做齐 | 对外「AI Agent」；可无人确认就改法律状态的签字人 |
| **交卷 · 待你确认** | 产出齐套后停下，等人确认再移交下一部门 | 装饰按钮；无决策含义的「下一步」 |

**对外禁用**：Agent、Harness、智能体编排、Seat、HITL（改用「待你确认」「部门闸」等）。  
**部内可见岗**：默认控制在少量（约 2–3），避免滑回「机器人目录」。

### 3.1 运转规则（业务口径）

```
公司（整案）
  └── 部门（主链节点）  —— 输入契约 · 交卷 · 完成标准
        └── 专家（部内岗） —— 协作做齐交卷；多为建议稿
              └── 交卷闸「待你确认」—— 人采纳后才移交或改法律相关状态
```

1. **一案一公司视图**：始终能回答「现在在哪个部门」。  
2. **一部门一交卷**：无可核验产物不得标完成（对齐 spine INV-7）。  
3. **专家可并行，部门默认串行**；允许标注的回流（如查新退回交底补强）。  
4. **确认权跟人走**：发明人 / 代理人 / 企业负责人等；专家（含辅助起草）只有建议权。  
5. **法定动作不可业务跳过**：递交、缴费、实审、年费等以法条与期限为准。

### 3.2 上手路径（主链 hops）

> 一页图+禁区交卷物：[working/2026-10-23-onboarding-path-and-forbid.md](working/2026-10-23-onboarding-path-and-forbid.md)。

**主链（人人同一骨架）：**

```
登录 → 产品首页 /agent →（代理：多案流水｜企业：开案子/公司首页）
     → 公司首页 → 七部部门工作台 → 确认页（铃铛）
```

| # | 这一跳 | 用户应感到什么 | 禁止什么 |
|---|---|---|---|
| 0 | **登录** | 「选我是代理还是企业，然后进外挂 IP 部」 | 登录后无首页直跳乱页；同页滤权限冒充双角色；营销落地页当登录后首页 |
| 1 | **产品首页** `/agent` | 「这是外挂 IP 部；我该点哪个主按钮；有没有待我确认」 | 部门地图/交卷作业堆在这；空总工作台抢公司首页；替代案盘或公司首页；Agent 目录墙 |
| 2a | **多案流水**（代理） | 「我的案子清单：卡在哪、谁待确认、期限红点」 | 做成企业单案陪跑页；塞七部作业；无案名/当前部门就进深页 |
| 2b | **开案子**（企业无案） | 「三步立一条业务线，然后进公司」 | 长表单；先丢进交底 Word；跳过公司首页认知 |
| 3 | **公司首页**（一案） | 「这是本案的 IP 部；现在在哪个部门；专家点开才见；去当前部门干活」 | 直进交底表单；十二部一屏全开；专家花名册墙；与产品首页同构的第二套总览 |
| 4 | **部门工作台**（七部） | 「本站交卷是什么、齐套了没、专家建议稿、点交卷」 | 无交卷物装完成；>3 专家岗变机器人目录；无公司顶栏（案名/当前部门/铃铛） |
| 5 | **确认页** | 「这是拍板，不是下一步；过/驳回有决策含义」 | 无决策含义的「下一步」；起草人自批；空材料装通过；不可逆无责任提示 |

**双角色（从产品首页分出，不是同页滤权限）：**

| 角色 | 产品首页主 CTA | 之后 |
|---|---|---|
| **代理** | → **多案流水** | 点进某案 → 公司首页 → 部门台 → 铃铛 |
| **企业** | → 无案**开案子** / 有案**公司首页** | 「去当前部门」→ 部门台 → 铃铛 |

进公司后壳与部门台骨架共用。

## 6. 信息架构：页面清单 · 工作台 · 理由

> 与上手路径对齐：**登录 → 产品首页（薄总览）→ 开案子/多案流水 → 公司首页看懂部门/专家 → 进部门干活 → 铃铛确认**。  
> **「工作台」= 部门页**（部门工作台）。**禁止**与公司首页抢戏的空「总工作台」；**允许**登录后人人可见的**薄产品首页** `/agent`（定位 + 角色主 CTA + 待确认），它**不**替代公司首页 / 多案流水，也**不**承载部门作业。公司首页是案级认知与导航壳，不是作业台。  
> **逐页规格（布局 / 首屏 / 硬闸 / 交卷物）见 [product-pages.md](product-pages.md)。**

### 6.2 上手路径（先看到谁）

> 每一跳「应感到 / 禁止」见 **§3.2**；一页图见 [working/2026-10-23-onboarding-path-and-forbid.md](working/2026-10-23-onboarding-path-and-forbid.md)。

```

 ├─ 代理人主 CTA → 多案流水 → 点进某案 → 公司首页
 └─ 企业研发主 CTA →（无案则开案子）→ 公司首页
```

**产品首页（已定）：** 登录后**默认先落** `/agent`；首屏仅定位句、按角色主 CTA、待确认摘要。  
**双角色两套页面（已定）：** 「开案子」与「多案流水」是**两张开始页**（从产品首页分出）；不得用单页+权限开关代替。  
**案级默认落点：** 有案时进**公司首页**（先认知，再干活）；不是直接进交底表单。产品首页**不**替代公司首页。

### 6.3 每页做什么 · 怎么设计 · 对哪条产品逻辑

| 页 | 用户得到什么 | 设计要点 | 产品逻辑 |
|---|---|---|---|
| **产品首页** `/agent` | 知道这是外挂 IP 部；按角色往哪走；有哪些待确认 | **薄**：定位句；角色主 CTA；待确认摘要；**禁止**部门地图作业区 / 万能功能堆 | L2 登录后壳；**不**替代公司首页 |
| 开案子 | 立一条业务线 | 字段极少；一句「外挂 IP 部」 | L2 案件中台 · 建案 |
| 多案流水 | 选案、看卡住哪 | 案名 / 当前部门 / 待确认 / 期限红点 | L2；代理人案盘（非产品首页） |
| **公司首页** | 知道产品是外挂 IP 部、有哪些部门、专家怎么来、本案在哪 | 定位句；七部地图（当前高亮）；点部门才展开 2–3 专家岗；铃铛；主按钮「去当前部门」 | L2 壳；**理念传达**；不承载 P01 表单 |
| **部门工作台** | 把本站交卷做齐 | 统一骨架见 §6.4；部门白话名；主按钮「交卷」 | **L1 SKU 作业面**：交底≈P01，查新≈P02，立项≈决策/预算，撰写≈P03，附图≈P03 内，递交≈L2 程序，答复≈P04 |
| 确认页 | 人拍板后再往下 | 交卷摘要；决策含义（对齐 D1–D7）；通过/驳回+意见；不可逆责任提示 | L2 交接与审批；**不是**普通「下一步」 |
| 期限台 | 法定/程序期限 | 列表 + 绝限强调 | L2 docket（节点 11） |
| 账单/委托 | 钱与委托清楚 | 官费/代理费分口袋 | L2 商务（节点 12） |
| 成员与权限 | 谁能确认 | 角色白话；非 Agent 花名册 | decision-rights |

**更多部门工作台**（折叠）：激发 00a、挖掘 00c、布局 P03b、FTO P02b、维持 P05、终止与恢复 23、运用 06、监控 P06、国际 P09、无效 P07、诉讼 P08，以及工具页「权利比对台账」25 —— 结构同 §6.4（工具页略变）；入口在公司首页「更多部门」。**逐页规格见 [product-pages.md §5](product-pages.md)**（导航仍默认折叠「更多」）。

### 6.4 部门工作台统一骨架

1. **公司顶栏常在**：案名 · 当前部门 · 铃铛 · 期限入口  
2. **本部门一句话** + 在七部主链上的位置  
3. **主区**：交卷物（编辑 / 预览）  
4. **齐套 / 完成标准**（硬闸；未齐套不能交卷）  
5. **专家条**：≤2–3 岗；产出为建议稿，可采纳  
6. **主按钮**：交卷 → 进入确认页；驳回则回流本工作台并带意见  

ASCII 布局与交卷物/齐套/专家示例见 [product-pages.md §2–§5](product-pages.md)（含扩展部门）。

### 6.5 为什么这样切页（理由）

1. **先薄产品首页，再案级公司首页，再工作台**：登录先认产品；进案后再认「一个部」；避免一上来像 Word 模板。  
2. **工作台 = 部门页；禁空总工作台，允薄产品首页**：作业必须落在某一站。禁止的是与公司首页抢戏的功能堆「总工作台」；允许的是不替代案盘/公司首页的 `/agent` 薄总览。  
3. **产品首页后开始页分流 + 代理多案流水**：研发少案、代理多案；同隐喻、两入口。  
4. **七部默认、其余更多**：对齐业务「必经 vs 条件触发」，降低上手惊吓。  
5. **确认页独立**：关键关要对齐 D1–D7，防空材料装完成、无人确认就递交。  
6. **后勤弱化**：期限/账单是 L2 能力，要有入口但不抢公司首页。  
7. **L1 进部门、L2 做壳**：对外说部门名，对内映射 SKU；平台不重复造十二套导航。

### 6.6 明确不做（本阶段）

- 用官网 / 宣传页当登录后首页（登录后首页 = **薄产品首页** `/agent`，不是营销落地页）  
- Agent 目录墙、专家花名册墙  
- 十二部一屏全开  
- **与公司首页抢戏的空「总工作台」**（把部门作业/万能功能堆在登录后总览上）。**允许**薄产品首页：定位 + 角色主 CTA + 待确认；不替代公司首页 / 多案流水  
- 把 L4 诊断咨询做成上手第一屏
