# 产品理念（Product Vision）

> **一句话（核心理念）**：给没有 IP 部（或人手不够）的团队，装上一个**外挂知识产权部**——按专利全流程办事，把技术尽快变成可递交、可授权、可维持的专利。  
> **对外品类**：可称「**虚拟知产公司**」（品类说法）；壳内一案视图仍叫「公司」；**项目 ≈ 案**。品牌句钉死「外挂知识产权部」，不换品类口号顶替品牌句。  
> **公司 / 部门 / 专家**不是产品本身，而是把核心理念讲清楚、让人容易上手的**对外叙事与流转隐喻**。  
> **结构句**：**一项目 · 一套已确认事实 · 两角色工作台重心 · 多部门接力**（工作台仍=部门页；禁空总台；人保留关键决策权）。  
> **上游**：业务总纲 [business-spine.md](business-spine.md)（含 §1.5 双轨、§3.3 G1–G3）、节点 `nodes/`、参考来源 [sources.md](sources.md)。  
> **下游**：商业切分 / SKU / 定价见 [product-logic.md](product-logic.md)（理念定「像什么、怎么走」；产品逻辑定「怎么卖、先做哪个」）。  
> **定稿**：2026-10-23（Asia/Shanghai）；**2026-10-24** Leslie 开闸增补（对齐 spine `6afa178`）。工作讨论底稿：[working/2026-10-23-product-vision-company-dept-expert.md](working/2026-10-23-product-vision-company-dept-expert.md)。

## 1. 核心理念

| | |
|---|---|
| **是** | **外挂知识产权部**（品牌句钉死）：覆盖「拿专利」主链，关键关有人拍板，材料与期限按实务与法条走。对外品类可称「**虚拟知产公司**」；壳内一案视图仍叫公司；**项目 ≈ 案** |
| **不是** | 单点交底模板、单点查新插件、「AI Agent 目录」、**外挂聊天窗**、**万能 Agent**、或把助手/项目/专业做成**三套割裂产品** |
| **成功标准** | 研发知道案子卡在哪、该补什么；代理人与企业在**同一案子、同一套已确认事实**上协同（案卷齐、确认快、期限不漏）；无人确认不能装成已递交/已立项 |

展开四句：

1. **全流程，不只单点**：激发/挖掘可按需 → 交底 → 查新 → 立项 → 撰写 → 递交 → 答复 → 年费（支线按需开设）。业务双轨见 spine [§1.5](business-spine.md)（权利形成主线 + 风险防控副线）；七部=导航投影，不另开第二条主链、不强制扩默认七部。  
2. **简单、拟人、像公司**：用户不学编排黑话；进「公司」、看「当前部门」、认「专家交卷」。统一入口是**知产负责人**（说业务目标 → 计划 → 部门），**不是**万能 Agent。  
3. **关键关人拍板（硬闸）**：齐套不过不能交卷；交卷后默认「待你确认」；无人确认不能推进下一部门；专家建议稿≠确认；**质检 ≠ 确认权**（跟齐 spine §3.3）。产品防空材料装完成、无人确认就递交，**不替人签字**。细则 §3.1a。  
4. **一项目 · 一套已确认事实 · 两角色工作台重心 · 多部门接力**：工作台仍=部门页；**两工作台按 B**（企业默认简版重心 / 代理默认卷宗三栏）；禁空总台。详见 §3.1b / §6.3a。

| 使用人 | 不懂什么 | 要什么 |

## 3. 对外叙事：公司 · 部门 · 专家

> 设计这套隐喻的**唯一目的**：把核心理念传出去，降低上手成本。对内仍可用 spine / nodes / D1–D7 / HITL。

| 隐喻 | 是什么 | 不是什么 |
|---|---|---|
| **公司** | 整案的虚拟 IP 部视图；**一案 = 一条业务线**；对外品类可称「虚拟知产公司」；**项目 ≈ 案** | 用户的真实工商主体；聊天机器人品牌名；用「项目」另开一套壳 |
| **部门** | 主链上的一站（或紧密一小段）；有输入契约、交卷出 | 真实科室；随便起的菜单分组 |
| **专家** | 部内协作岗：起草 / 检索 / 制图 / 质检等；把本部门交卷做齐 | 对外「AI Agent」；可无人确认就改法律状态的签字人；质检通过冒充确认 |
| **知产负责人** | **统一入口角色**：用户说业务目标 → 出计划 → 落到部门干活（可参考「顾言」式说目标，产品内落此名） | **万能 Agent**；替代确认权；外挂聊天窗顶替同案协同 |
| **交卷 · 待你确认** | **硬闸体验**：齐套后才能交卷；交卷后停下等人确认，才移交下一部门或改法律相关状态 | 装饰按钮；灰了还能点；无决策含义的「下一步」；专家自批冒充确认；质检勾选冒充确认 |

**对外禁用**：Agent、Harness、智能体编排、Seat、HITL（改用「待你确认」「部门闸」「知产负责人」等）。  
**部内可见岗**：默认控制在少量（约 2–3），避免滑回「机器人目录」。  
**代理所定位**：同案专业协同方——共享同一项目（案）与已确认事实；不是另开聊天窗旁路。

### 3.1 运转规则（业务口径）

```
公司（整案）
  └── 部门（主链节点）  —— 输入契约 · 交卷 · 完成标准
        └── 专家（部内岗） —— 协作做齐交卷；多为建议稿
              └── 交卷闸「待你确认」—— 人采纳后才移交或改法律相关状态
```

1. **一案一公司视图**：始终能回答「现在在哪个部门」。  
2. **一部门一交卷（G1）**：齐套清单未勾齐 → 不得标部门完成 → 不得进「待你确认」（spine §3.3；INV-7）。  
3. **专家可并行，部门默认串行**；允许标注的回流（如查新退回交底补强；确认驳回回流当前部）。  
4. **确认权跟人走（G2）**：确认人=发明人/代理人/企业负责人等；专家仅建议；起草人不得自批。  
5. **法定动作不可业务跳过**：递交、缴费、实审、年费等以法条与期限为准。

### 3.1a 「交卷 · 待你确认」硬闸体验（Leslie 已定 · 已跟业务）

> **问题**：理念叙事已在页上，仍缺「外挂部真在办事」——要把交卷闸 + 确认权**做实**（期限 / 账单后置，不抢本闸）。  
> **边界**：仍用公司 / 部门 / 专家隐喻；**对外禁用** Agent / Harness / Seat / HITL 等黑话。  
> **业务硬口径（已收口）**：[business-spine.md §3.3](business-spine.md) G1–G3；演示优先段 nodes `00` / `01` / `02`。逐页硬闸见 [product-pages.md](product-pages.md)。

**登录后路径不变：** 公司首页 → 部门工作台 → 铃铛确认（见 §3.2）。

#### 业务三条硬规则（原文 · 跟齐）

1. **一部门一交卷**：本部门齐套清单未勾齐 → 不得标「部门完成」→ 不得进入「待你确认」推进态。  
2. **确认权跟人走**：确认人 = 发明人 / 代理人 / 企业负责人等真实主体；专家只有建议权；起草人不得自批自己的交卷。  
3. **无人确认 → 不得移交下一部门**，不得装成已递交 / 已立项。确认页：过 → 移交；驳回 → 回流当前部补齐（可标回流）。

#### 用户应感到什么 / 禁止什么（体验层）

| # | 对应 | 用户应感到什么 | 禁止什么 |
|---|---|---|---|
| 1 | G1 | **齐套不过 → 交卷 CTA 不可用**（灰且点不动；明示缺什么）；进不了「待你确认」 | 灰了还能点；点了装「部门完成 / 已交卷」；未齐套溜进待确认 |
| 2 | G2 | **专家建议稿 ≠ 确认**；确认权跟人；**质检 ≠ 确认权** | 专家采纳 / 起草人自批 / 质检勾选冒充确认；「AI 已通过」当拍板 |
| 3 | G3 | **交卷后默认进「待你确认」**；过才移交、驳回回流当前部；无人确认卡住可见 | 无决策含义的「下一步」换部；无人确认装成已递交 / 已立项 |

**成功标准（体验）：** 用户能指出「卡在齐套 / 卡在等人确认 / 已确认可往下」；截图不能把未齐套或未确认的案子读成已办完。

### 3.1b 结构句与两工作台（Leslie 开闸 · 2026-10-24）

> **结构句**：**一项目 · 一套已确认事实 · 两角色工作台重心 · 多部门接力**。  
> **工作台仍 = 部门页**。**禁止**空「总工作台」。G1–G3 硬闸原文跟齐 [business-spine.md §3.3](business-spine.md)（含 **质检 ≠ 确认权**），本文不改闸门口径。

| 项 | 定稿 |
|---|---|
| **一项目** | 对外可说「项目」；壳内 = **一案一公司视图**（项目 ≈ 案） |
| **一套已确认事实** | 企业与代理在同一案子上共享已确认事实；确认后才进下一接力，不各写各的真相 |
| **两角色工作台重心（B）** | **同一部门页模板**，按角色默认重心不同——**企业**：简版重心（事项 / 已确认事实 / 待决策）；**代理**：卷宗三栏重心（对齐 Cursor 三栏：左目录 / 中产出 / 右对话）。**不是**两套产品，**不是**空总台 |
| **多部门接力** | 默认七部串行接力 + 标注回流；不扩默认七部（更多进折叠） |
| **人保留关键决策权** | 确认权跟人；专家建议稿 ≠ 确认；质检 ≠ 确认权 |

### 3.1c 知产负责人 · 业务目标入口（MVP 增强）

> **增强现有 hops，不拆掉** 登录 → 薄入口 → 公司 → 部门 → 铃铛。

| 项 | 定稿 |
|---|---|
| **入口角色** | **知产负责人**：说业务目标 → 出计划 → 落到部门；对外禁用「万能 Agent」 |
| **MVP 增强面** | **开案子**与/或**产品首页**可交办业务目标（四类目标清单由产品逻辑 / 页面规格承接细目）；交办后仍进公司首页认知，再「去当前部门」 |
| **不是** | 拆掉双角色分流；用聊天窗替代公司/部门页；跳过交卷闸与确认权 |

### 3.1d 三档使用深度（同一底座）

| 档 | 像什么 | 边界 |
|---|---|---|
| **助手** | 轻量帮一句 / 补一块 | 不另开产品壳 |
| **项目** | 一案跟着七部跑完 | 默认上手深度 |
| **专业** | 代理卷宗与多案协同加重 | 仍同底座、同隐喻；非第二套 SaaS |

三档 = **同一底座的使用深度**，不是三套产品、不是三套导航。

### 3.2 上手路径（主链 hops）


> 一页图+禁区交卷物：[working/2026-10-23-onboarding-path-and-forbid.md](working/2026-10-23-onboarding-path-and-forbid.md)。

**主链（人人同一骨架）：**

```
登录 → 产品首页 /agent →（代理：多案流水｜企业：开案子/公司首页）
     → 公司首页 → 七部部门工作台 → 确认页（铃铛）
```

| # | 这一跳 | 用户应感到什么 | 禁止什么 |
|---|---|---|---|
| − | **未登录宣传站**（官网式） | 「一眼品类 + 货架：七部、专家、场景、案卡/交卷橱窗」——**宣传/教育放这里**（pages §4.0p） | 做成必须登录才看懂；与登录后 `/agent` 同构第二套产品首页 |
| 0 | **登录** | 「选我是代理还是企业，然后进干活入口」 | 登录后无首页直跳乱页；同页滤权限冒充双角色；**把宣传站整页复制成** `/agent` |
| 1 | **产品首页** `/agent` | 「薄入口：一屏一个主 CTA + 待确认，马上进干活」 | **三卡平铺**；货架/七部墙/专家宣传墙；整页官网卖点；首页编辑交卷；空总工作台；替代案盘/公司；Agent 目录 |
| 2a | **多案流水**（代理） | 「我的案子清单：卡在哪、谁待确认、期限红点」 | 做成企业单案陪跑页；塞七部作业；无案名/当前部门就进深页 |
| 2b | **开案子**（企业无案） | 「三步立一条业务线，然后进公司」 | 长表单；先丢进交底 Word；跳过公司首页认知 |
| 3 | **公司首页**（一案） | 「七部等宽卡片总览；点某部右侧抽屉见 ≤3 专家+交卷态；主 CTA 去当前部门」 | 直进交底表单；十二部一屏全开；专家花名册墙；暗色皮肤照搬；右侧假指标/执行集群/工具引擎卡；与产品首页同构的第二套总览 |
| 4 | **部门工作台**（七部） | 「像 Cursor：左目录 / 中产出 / 右对话含确认；齐套不过右侧交卷点不动；专家建议稿≠确认」 | 无交卷物装完成；齐套不过仍可点交卷；>3 专家岗变目录；无公司顶栏；右侧假指标/执行集群/工具引擎；抄暗色；专家采纳当确认；退回「主区+右钉」两栏 |
| 5 | **确认页** | 「这是拍板，不是下一步；过/驳回有决策含义；不过不能换部」 | 无决策含义的「下一步」；起草人/专家自批；空材料装通过；无人确认推进下一部门；不可逆无责任提示 |

**双角色（从产品首页分出，不是同页滤权限）：**

| 角色 | 产品首页主 CTA（一屏一个；禁三卡平铺） | 之后 |
|---|---|---|
| **代理** | → **进入案盘**（多案流水） | 点进某案 → 公司首页 → 部门台（**卷宗三栏重心**）→ 铃铛 |
| **企业** | → 无案**开案子**（可交办业务目标） / 有案**进入本公司** | 「去当前部门」→ 部门台（**简版重心：事项/事实/决策**）→ 铃铛 |

进公司后壳与部门台**骨架共用**（两工作台 **B**：同模板、角色默认重心不同；禁空总台）。知产负责人目标入口见 §3.1c（MVP 增强，不拆本表 hops）。

#### B. 登录后产品首页 `/agent`（薄入口）

| 问题 | 定稿 |

### 6.5 为什么这样切页（理由）

1. **宣传在登录前，干活入口在登录后**：未登录站讲清品类与货架；登录后 `/agent` 只分流。进案后再认「一个部」；避免一上来像 Word 模板。  
2. **工作台 = 部门页；两角色重心 B；禁空总工作台，钉死薄产品首页**：作业必须落在某一站。同模板下企业简版 / 代理卷宗；禁止与公司首页抢戏的「总工作台」；`/agent` 仅主 CTA+待确认（可增强目标交办），不堆宣传货架。  
3. **产品首页后开始页分流 + 代理多案流水 + 同案协同**：研发少案、代理多案；同隐喻、两入口；代理=同案协同方，非外挂聊天窗。  
4. **七部默认、其余更多**：对齐业务「必经 vs 条件触发」，降低上手惊吓。  
5. **确认页独立 + 交卷闸做实**（§3.1a）：齐套不过不能交卷；交卷后待你确认；无人确认不换部；专家≠确认权跟人。防空材料装完成、无人确认就递交。  
6. **后勤弱化**：期限/账单是 L2 能力，要有入口但不抢公司首页。  
7. **L1 进部门、L2 做壳**：对外说部门名，对内映射 SKU；平台不重复造十二套导航。

### 6.6 明确不做（本阶段）

- 把**未登录官网宣传站**整页复制成登录后 `/agent`（登录后 = **薄入口**，见 §3.3 B）
