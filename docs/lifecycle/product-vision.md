# 产品理念（Product Vision）

> **目标（核心理念）**：**尽快把专利申请办下来**——把技术变成**可递交、可授权、可维持**的专利。  
> **手段与品类（不是另立目标）**：**外挂知识产权部**（品牌句钉死）= 办成这件事的**手段**；对外品类可称「**虚拟知产公司**」；壳内一案视图仍叫「公司」；**项目 ≈ 案**。不把「像公司」「装外挂部」当成与办专利并列的第二目标；不换品类口号顶替品牌句。  
> **公司 / 部门 / 专家**不是产品本身，而是把核心理念讲清楚、让人容易上手的**对外叙事与流转隐喻**。  
> **为了什么**：少盯流程、少材料扯皮；交底→递交**同案接力**；关键关**人拍板**。  
> **结构句**：**一项目 · 一套已确认事实 · 两角色工作台重心 · 多部门接力**（工作台仍=部门页；禁空总台；人保留关键决策权）。

> **下游**：商业切分 / SKU / 定价见 [product-logic.md](product-logic.md)（理念定「像什么、怎么走」；产品逻辑定「怎么卖、先做哪个」）。

## 1. 核心理念

> **变更理由（2026-10-25 · Leslie 定）**：此前开篇易把「外挂知识产权部 / 虚拟知产公司」读成与办专利并列的目标。现钉死——**目标只有一个**：尽快把专利申请办下来（可递交、可授权、可维持）；外挂部与虚拟公司是**手段与品类**，不是另立目标。下文「依据四条」写进文档，供 pages / 叙事对齐。

| | |
|---|---|
| **目标** | **尽快把专利申请办下来**（可递交 → 可授权 → 可维持） |
| **手段与品类** | **外挂知识产权部**（品牌句钉死）= 手段；对外品类可称「**虚拟知产公司**」；壳内一案视图仍叫公司；**项目 ≈ 案**。手段服务目标，不另立「像公司运营」目标 |
| **不是** | 另立「虚拟公司 / 外挂部」第二目标；单点交底模板、单点查新插件、「AI Agent 目录」、**外挂聊天窗**、**万能 Agent**、或把助手/项目/专业做成**三套割裂产品** |
| **为了什么** | **少盯流程、少材料扯皮**；交底→递交**同案接力**；关键关**人拍板** |
| **成功标准** | 研发知道案子卡在哪、该补什么；代理人与企业在**同一案子、同一套已确认事实**上协同（案卷齐、确认快、期限不漏）；无人确认不能装成已递交/已立项 |

#### 依据（四条）

1. **主链 = 申请链**：交底 → 查新 → 立项 → 撰写 → 递交 → 答复（激发/挖掘、年费等支线按需；业务双轨见 spine [§1.5](business-spine.md)；七部=导航投影，不另开第二条主链、不强制扩默认七部）。  
2. **G1–G3 硬闸**挡空转 / 假完成：齐套不过不交卷；确认权跟人；无人确认不移交（跟齐 spine §3.3；体验落点 §3.1a）。  
3. **部门 = 多 agent 协同（Cursor 式），人只拍板**：默认只和**部门 leader（父 agent）**聊，由他调度专家 subagent；专家工作/产出/进度**可见**；**可选**点开与单个专家 1:1（非主路径强制）。拍板在右栏；专家产出 ≠ 人确认。  
4. **一案一公司视图，事实不散**：企业与代理在同一项目（案）上共享已确认事实；不各写各的真相。

展开四句（手段如何服务目标）：

1. **全流程，不只单点**：主链按申请链走；支线按需开设。  
2. **简单、拟人、像公司**：用户不学编排黑话；进「公司」、看「当前部门」、认「专家交卷」。统一入口是**知产负责人**——**持续委托**（说目标 → 计划可调 → 部门执行 → 确认 → 接力），**不是**万能 Agent。品牌句仍「外挂知识产权部」。  
3. **关键关人拍板（硬闸）**：齐套不过不能交卷；交卷后默认「待你确认」；无人确认不能推进下一部门；专家产出≠确认；**质检 ≠ 确认权**。**拍板在工作台右栏**（**禁主拍板另开页**；审计/历史类确认查阅面可有，**不得**抢右栏闸）；中栏须先见交卷物正文。细则 §3.1a。  
4. **一项目 · 一套已确认事实 · 两角色工作台重心 · 多部门接力**：工作台仍=部门页；**两工作台按 B**（企业默认简版重心 / 代理默认卷宗三栏）；禁空总台。详见 §3.1b / §6.3a。

## 3. 对外叙事：公司 · 部门 · 专家

> 设计这套隐喻的**唯一目的**：把核心理念传出去，降低上手成本。对内仍可用 spine / nodes / D1–D7 / HITL。

| 隐喻 | 是什么 | 不是什么 |
|---|---|---|
| **公司** | 整案的虚拟 IP 部视图；**一案 = 一条业务线**；对外品类可称「虚拟知产公司」；**项目 ≈ 案** | 用户的真实工商主体；聊天机器人品牌名；用「项目」另开一套壳 |
| **部门** | 主链上一站；**多 agent 协同面（Cursor 式）**——**部门 leader（父 agent）**调度专家 subagent 完成本站交卷。进工作台后用户主对象 = **本部门 / 本节点**（不是顾言）；一部做完→下一部，有问题可**退回上一部** | 真实科室；随便起的菜单分组；右栏人人并排主聊；专家只当名片墙；无 leader 的散聊 |
| **专家** | 独立 **subagent/bot**（**按实际编制**上岗）：工作/产出/进度**可见**；**可选**点开 1:1（非主路径强制）；由 leader 调度协作。产出仍**≠**人确认 | 仅 tip/名片；强制人人并排主聊；可无人确认就改法律状态；产出冒充确认；专家墙/凑编；首屏看不见 |
| **知产负责人（顾言）** | **统一入口 · 持续委托**：听目标 → 计划可调 → **分发 / 路由到部门** → 跨部接力。产品内可落名「顾言」 | **万能 Agent**；**部门内改文书时的主聊伴**；替代部门执行；替代确认权；外挂聊天窗顶替同案协同；只 toast 不走通链路 |
| **你（确认权）** | **工作台右栏拍板**：G1 齐套后交卷 → 同屏待你确认（通过/驳回）；过才移交 / 改法律相关状态；**主拍板不另开页**（审计/历史查阅面可有，不抢闸） | 装饰「下一步」；专家/起草人自批；质检勾选冒充确认；中栏无交卷物正文就点确认；把审计面做成主拍板页 |
| **交卷 · 待你确认** | **硬闸体验**：齐套后才能交卷；交卷后在**工作台右栏**停下等人确认，才移交下一部门或改法律相关状态 | 装饰按钮；灰了还能点；无决策含义的「下一步」；专家自批冒充确认；质检勾选冒充确认；把主拍板做成另开确认/pending 页 |

**对外用语**：可用「专家 bot / 跟专家聊」白话；**禁用** Harness、Seat、HITL、智能体编排黑话；**禁止**登录后堆「Agent 目录墙」。理念侧钉「独立 agent」≠ 对外喊编排口号。  
**部内编制**：**按实际需要**上岗（**废 ≤3 硬顶**）；**交底部**默认约 **5–6**；其他部按岗需要。仍**禁**凑编/专家墙/花名册墙——可见几个上几个，不为凑数加人；每个在岗专家仍是可私聊的独立 bot。  
**代理所定位**：同案专业协同方——共享同一项目（案）与已确认事实；不是另开聊天窗旁路。

### 3.1 运转规则（业务口径）

```
公司（整案 · 项目≈案）
  └── 工作台（部内作业面 · 多 agent 协同 · Cursor 式 · 对外称「工作台」）
        ├── 部门 leader（父 agent）—— 默认主对话；调度专家 subagent
        ├── 专家 bot₁…ₙ（subagent · 按编制）—— 工作/产出/进度可见；可选 1:1
        └── 右栏闸「交卷 · 待你确认」—— 人通过/驳回后才移交或退回上一部
```

1. **一案一公司视图（以项目为单位）**：始终能回答「现在在哪个部门」。  
2. **一部门一交卷（G1）**：齐套清单未勾齐 → 不得标部门完成 → 不得进「待你确认」（spine §3.3；INV-7）。  
3. **部门接力串行**：一部做完 → 下一部继续；有问题可**退回上一部**补齐（确认驳回 / 标注回流同理）。部内多专家 bot **可并行干活**，再汇成交卷。  
4. **确认权跟人走（G2）**：确认人=发明人/代理人/企业负责人等；专家产出 ≠ 确认；起草人不得自批；**拍板落点=工作台右栏**（非另页）。  
5. **法定动作不可业务跳过**：递交、缴费、实审、年费等以法条与期限为准。

### 3.1a 「交卷 · 待你确认」硬闸体验（Leslie 已定 · 2026-10-25 改口）

> **问题**：理念叙事已在页上，仍缺「外挂部真在办事」——要把交卷闸 + 确认权**做实**（期限 / 账单后置，不抢本闸）。  
> **变更理由（2026-10-25 · Leslie 定口径）**：**主路径拍板不另开页**——拍板落工作台右栏（废的是「主拍板另开确认/pending 页」）。工作台（对外勿称「部门台」）= 以**项目**为单位的**多 agent 作业面**。部门接力：一部做完→下一部；有问题可退回上一部。**拍板在工作台右栏**：中栏必须先见交卷物正文作依据，再通过/驳回；「什么都看不到就确认」禁止。右栏仍是 AI 交互主区；通过/驳回是右栏闸。  
> **变更理由（2026-10-26 · Leslie 纠偏 · 进阶可配 / 确认可审计面）**：理念不换（IP harness；不懂 agent 也能上手；熟了进阶）。**上手仍简单**：主路径（薄入口→公司→工作台拍板）**不堆**技能/MCP/独立确认当第一屏墙。**进阶可选用**：专业档（或明确「进阶」入口）允许**轻量**技能 / MCP **配置面**——给熟客；**默认收折**；**不是**第一屏墙 / 不是第三套产品主叙事（软化此前绝对「禁技能墙」）。**确认**：主路径拍板**仍在工作台右栏**（G1–G3 体验落点不变）；若加「确认」相关面，定位为**记录 / 审计 / 历史**或进阶查阅——**不得**再变成主拍板页、**不得**抢右栏闸（软化「废单独确认页」绝对禁令：废的是主拍板另开页）。三 skill 审计 P0/P1 升为产品级体验要求（§3.1g）。pages 跟；壳/原型本单不动。  
> **变更理由（2026-10-25 · Leslie 工作台截图批 fix-both）**：**中栏** = **干净文书主舞台**（交卷物正文）；**禁止**在中栏头顶叠「事项 / 已确认事实 / 待决策」三格/三卡——企业简版**也不例外**（简版改的是默认密度与信息露出，**不是**往中栏头顶塞三卡）。**右栏**须像 **Cursor AI 区**：以**对话为主高度**；**专家按编制首屏露头**（有几个露几个；禁凑编/专家墙），不得整栏只剩缺项清单+闸、专家看不见。逐页细则 pages §2。  
> **变更理由（2026-10-25 · Leslie 定 · 部门多 agent）**：**部门 = 多 agent 协同**。专家是独立 bot（可见工作/产出/进度；可点开），废「仅建议、不可私聊」。  
> **变更理由（2026-10-25 · Leslie 补 · Cursor 式交互）**：交互像 **Cursor**——默认只和**部门 leader = 父 agent** 交互（他调度专家 subagent）；专家工作/产出/进度仍可见；与单个专家 **1:1 可选**（非主路径强制）。**禁止**右栏人人并排主聊；主对话挂在 leader。顾言仍薄入口/跨部/改目标；尽快申下来不变。细则 §3.1f；pages 跟；壳/原型先别动。  
> **变更理由（2026-10-25 · Leslie 定 · 编制与右栏 UX）**：**放开编制 ≤3 上限**——编制**按实际需要**（**交底部**默认约 **5–6**；其他部按岗需要；仍禁凑编/专家墙）。右栏 UX：**缺项**按推荐——聊头顶 **chip** → 点开**抽屉**（**禁止**右栏长清单抢对话高度）；**composer 贴底**；**删**身份旁长 tip，与右栏「为你的目标」。**多 bot Cursor 式不变**（默认 leader 主聊；专家可见+1:1 可选；禁并排主聊）；顾言/中栏/拍板/申下来不变。pages 跟；壳/原型先别动。  
> **边界**：仍用公司 / 部门 / 专家隐喻；对外可用「专家 bot / 跟专家聊」；**禁用** Harness / Seat / HITL；**禁**登录后 Agent 目录墙。  
> **业务硬口径（已收口）**：[business-spine.md §3.3](business-spine.md) G1–G3；演示优先段 nodes `00` / `01` / `02`。逐页硬闸见 [product-pages.md](product-pages.md)。

**登录后路径：** 公司首页 → **工作台**（交卷与拍板同屏）→ 下一部或退回上一部（见 §3.2）。铃铛可作待办提醒，**深链回工作台右栏闸**（主拍板不另开页；审计/历史查阅另面不抢闸）。

#### 业务三条硬规则（原文 · 跟齐 · 落点更新）

1. **一部门一交卷**：本部门齐套清单未勾齐 → 不得标「部门完成」→ 不得进入「待你确认」推进态。  
2. **确认权跟人走**：确认人 = 发明人 / 代理人 / 企业负责人等真实主体；专家可干活、可私聊，但**产出 ≠ 确认**；起草人不得自批自己的交卷。  
3. **无人确认 → 不得移交下一部门**，不得装成已递交 / 已立项。**工作台右栏**：过 → 移交下一部；驳回 → 回流本台或退回上一部补齐（可标回流）。

#### 用户应感到什么 / 禁止什么（体验层）

| # | 对应 | 用户应感到什么 | 禁止什么 |
|---|---|---|---|
| 1 | G1 | **齐套不过 → 交卷 CTA 不可用**（灰且点不动；明示缺什么）；进不了「待你确认」 | 灰了还能点；点了装「部门完成 / 已交卷」；未齐套溜进待确认 |
| 2 | G2 | **专家产出 ≠ 确认**；确认权跟人；**质检 ≠ 确认权**；拍板在右栏，且**中栏已见交卷物正文** | 专家产出/采纳冒充确认；起草人自批；质检勾选冒充确认；「AI 已通过」当拍板；**中栏空白就点通过**；把主拍板做成另开确认/pending 页 |
| 3 | G3 | **交卷后同屏「待你确认」**（右栏闸）；过才下一部、驳回可退回上一部；无人确认卡住可见 | 无决策含义的「下一步」换部；无人确认装成已递交 / 已立项 |

**成功标准（体验）：** 用户能指出「卡在齐套 / 卡在等人确认 / 已确认可往下」；截图同屏可见**中栏干净交卷物正文** + **右栏与 leader 的主对话**与闸；能**看见**各专家进度/产出；1:1 专家为可选；不能把未齐套或未确认的案子读成已办完；产品内**无**「主拍板另开页」路由（审计/历史类确认查阅面可有，**不得**抢右栏闸）。

### 3.1b 结构句与两工作台（Leslie 开闸 · 2026-10-24）

> **结构句**：**一项目 · 一套已确认事实 · 两角色工作台重心 · 多部门接力**。  
> **工作台** = 部内作业面（对外称「工作台」，**勿**对外叫「部门台」）；以**项目**为单位。**禁止**空「总工作台」。G1–G3 **业务口径**跟齐 [business-spine.md §3.3](business-spine.md)（含 **质检 ≠ 确认权**）；**体验落点**见 §3.1a（拍板在右栏；禁主拍板另开页；审计/历史查阅可有）。

| 项 | 定稿 |
|---|---|
| **一项目** | 对外可说「项目」；壳内 = **一案一公司视图**（项目 ≈ 案） |
| **一套已确认事实** | 企业与代理在同一案子上共享已确认事实；确认后才进下一接力，不各写各的真相 |
| **两角色工作台重心（B）** | **同一部门页模板**，按角色默认**密度**不同——**企业**：简版（信息更少、更易扫）；**代理**：卷宗更满。简版**不等于**中栏头顶「事项/已确认事实/待决策」三卡；那三词是信息类型提示，**禁止**落成中栏头顶三格。**不是**两套产品，**不是**空总台 |
| **一屏 Cursor 三栏（Leslie 已定 · fix-both · 多 agent）** | 工作台固定同屏三栏：**左**可折 ~200px；**中栏 = 干净文书主舞台 `1fr`**（禁头顶三卡）；**右栏 ~260–280px**：**主对话挂部门 leader（父 agent）** + 专家工作/产出/进度可见 + 齐套/通过驳回闸；与专家 **1:1 可选**（非强制）。**禁**右栏人人并排主聊；**禁**专家仅 tip；**禁**墙/凑编。顾言仅弱入口。细则 §3.1f / §6；pages §2 |
| **多部门接力** | 一部做完 → 下一部继续；有问题可**退回上一部**补齐；不扩默认七部（更多进折叠） |
| **人保留关键决策权** | 确认权跟人；专家产出 ≠ 确认；质检 ≠ 确认权 |

### 3.1c 持续委托边界（知产负责人 / 顾言 · Leslie / Kimi 结合）

> **依据**：[2026-10-24-kimi-combine-design.md](../superpowers/specs/2026-10-24-kimi-combine-design.md) `4483d2e`。  
> **增强现有 hops，不拆掉** 登录 → 薄入口 → 公司 → 工作台（含右栏拍板）。硬闸 G1–G3 **业务口径**、七部导航投影、薄入口骨架**不动**；确认**体验**落右栏（§3.1a）。品牌句仍「**外挂知识产权部**」。  
> **变更理由（2026-10-24 · Leslie 开闸）**：钉清 **顾言 vs 部门 vs 专家 vs 你** 交互归属——顾言只管入口/路由/跨部接力，**不**当部内改文书主聊伴、**不**替代部门执行。

| 项 | 定稿 |
|---|---|
| **结合原则（理念侧）** | 一家公司 + **一个知产负责人（顾言）持续委托** + 部门按需可见 + 可信交付 |
| **可点链（须走通）** | **提目标 → 计划可调 → 部门执行 → 确认 → 接力**。原型 / 规格须可点通，**禁止**只弹 toast 假装委托 |
| **MVP 落点** | 薄入口主 CTA / 开案子可发起持续委托；交办后仍进**公司首页**认知，部门由负责人路由（部门退二线，不拆七部投影）。**四类目标细目**权威清单 → [product-logic.md §0.3](product-logic.md)（交底齐套 / 开案保护 / 上市风险排查 / 审查答复） |
| **薄入口轻量轨** | 主 CTA（持续委托）之外：「**现在需要我处理**」= 待确认 / 待接力；**禁止**做成跨案「公司经营首页」完整经营台 |
| **不是** | 万能 Agent；拆掉双角色分流；用聊天窗替代公司/部门页；跳过交卷闸与确认权；Kimi 式跨案经营台顶替薄入口 |

#### 交互归属（顾言 · 部门 · 专家 · 你）

| 角色 | 管什么 | 不管什么 |
|---|---|---|
| **顾言（知产负责人）** | 听目标、计划可调、**分发/路由到部门**、跨部接力 / 改目标 | 部内主聊伴；替代部门 leader；替代确认权；**替代案盘 / 开案子 / 右栏闸**；聊天代办选案或新建 |
| **部门** | **多 agent 协同**完成本站；进部后用户主对象 = **本部门 / 本节点** | 被总对话架空；跨部经营台；右栏人人并排主聊 |
| **部门 leader（父 agent）** | **默认主对话**；调度专家 subagent 协作；汇总进度/缺项 | 取消专家可见性；冒充唯一干活且专家不可见 |
| **专家（subagent）** | 独立 bot：工作/产出/进度**可见**；**可选** 1:1（非主路径强制）；由 leader 调度（**按实际编制**） | 仅 tip；强制并排主聊；产出当确认；专家墙/凑编 |
| **你** | **确认权**（工作台右栏通过/驳回）；G1 齐套 → 交卷 → 同屏待你确认；中栏须见正文 | 装饰下一步；自批 / 专家代签；把主拍板做成另开确认页；盲确认 |

**工作台里的顾言：** 仅**弱入口**（换部 / 改目标）；部内**主对话挂部门 leader**，不是顾言、也不是默认跟每个专家并排聊。

### 3.1e 空间与交付快照（一句）

确认通过后，用户须能看见**本站交付快照**（交卷摘要 / 已确认事实一小格）——可信交付可见，不是黑箱过闸；快照落在**工作台/公司进度**；主拍板**不**另开确认页（审计/历史查阅可有，不抢闸）。Kimi 四类确认仅作**类型标签**（页面规格承接细目），**不**另开闸门、**不**改 G1–G3 业务口径。空间仍落在公司 / 工作台内，不另起「总空间」壳。

### 3.1f 部门 = 多 agent 协同 · Cursor 式（Leslie 定 · 2026-10-25）

> **变更理由（2026-10-25 · Leslie 定）**：旧口径把专家收成「右栏 ≤3、仅建议、非独立私聊」——与「外挂部真在办事」不符。现钉：专家是独立 bot（工作/产出/进度可见）。  
> **变更理由（2026-10-25 · Leslie 补）**：交互像 **Cursor**——**默认只和部门 leader = 父 agent 交互**（他调度专家 subagent 协作）；专家仍独立、进度可见；与单个专家 **1:1 可选**（不是主路径强制）。**不是**「右栏人人并排主聊」；主对话挂在 leader。**先改理念+规格，再动原型**；壳本轮不动。  
> **变更理由（2026-10-25 · Leslie 定 · 编制与右栏 UX）**：**废编制 ≤3 硬顶**；按实际需要上岗（交底部默认约 5–6）。缺项 = 聊头顶 chip → 抽屉；composer 贴底；删身份旁长 tip 与右栏「为你的目标」。Cursor 式 / 顾言 / 中栏 / 拍板不变；pages 跟；壳/原型先别动。  
> **仍守**：产品核心 = **尽快把专利申下来**；顾言 = 薄入口 / 跨部接力 / 改目标；中栏 = 交卷物主舞台；拍板在工作台内（**禁**主拍板另开页；审计/历史查阅可有）；G1–G3 业务口径不变（专家产出仍 ≠ 人确认）。

| 交互 | 定稿 |
|---|---|
| **默认** | 只和**部门 leader（父 agent）**聊；leader 调度专家 subagent 把本站做完 |
| **看见** | 每个专家的工作 / 产出 / 进度（首屏可感） |
| **可选 1:1** | 可点开与单个专家会话；**非**主路径强制；**禁**做成右栏人人并排主聊 |
| **禁** | 专家仅 tip/名片；默认强制跟每个专家开主会话 |

| 角色 | 定稿 |
|---|---|
| **部门 leader（父 agent）** | 默认主对话对象；调度 / 汇总；对外可称「本部门负责人 / 部内助手」等白话 |
| **专家（subagent）** | 独立 bot；编制有几个上几个（**无 ≤3 硬顶**；交底部默认约 5–6；禁凑编）；可见进度；1:1 可选 |
| **顾言** | **不变**：薄入口 / 跨部 / 改目标；**不**部内主聊伴 |
| **你** | 确认权仍在工作台右栏；看中栏交卷物再拍板 |

**废：** 「右栏 ≤3 专家仅建议、非独立私聊」；「编制 ≤3 硬顶」；「右栏人人并排主聊」；右栏缺项长清单抢对话高度；身份旁长 tip；右栏「为你的目标」。  
**验收：** 右栏主会话是 **leader**；能看见 ≥1 个专家在办/产出；可选进专家 1:1；不是并排多条专家主聊 + 无 leader。

### 6.4 工作台统一骨架

> **对外称「工作台」**（勿称「部门台」）。**版面权重：** 左可折 **~200px** · 中 **1fr 主舞台** · 右瘦辅栏 **~260–280px**。纸墨浅色；禁文书/协同双视图；**禁主拍板另开页**（审计/历史查阅可有）。专业能力/编制在**专业部门页**（§3.1d）。

2. **本部门一句话** + 在七部主链上的位置  
3. **左栏 · 目录**（可折 ~200px）：本站材料 / 节点树  
4. **中栏 · 交卷物正文（1fr 主舞台）**：编辑 / 预览——**拍板前必须可见**；与右栏同屏  
5. **右栏 · Cursor 式多 agent + 闸（瘦辅栏 ~260–280px）**：以**对话为主高度**——**默认主会话 = 部门 leader（父 agent）**（**composer 贴底**）；专家工作/产出/进度**可见**（**按实际编制**；交底部默认约 5–6；无 ≤3 硬顶；禁凑编）；与专家 **1:1 可选**（非强制）；**缺项**按推荐——聊头顶 **chip** → 点开**抽屉**（禁右栏长清单抢对话高度）+ **G1 交卷**；交卷后同栏 **通过 / 驳回**（G2 落点）；专家产出 ≠ 确认；质检 ≠ 确认权——**禁止**右栏人人并排主聊；**禁止**专家仅 tip；**删**身份旁长 tip 与右栏「为你的目标」；**禁止**把主拍板另开确认页；**禁止**顾言抢主聊伴；**禁止**中栏无正文就通过；**禁止**中栏头顶叠三卡

### 6.5 为什么这样切页（理由）

1. **宣传在登录前，干活入口在登录后**：未登录站讲清品类与货架；登录后 `/agent` 只分流。进案后再认「一个部」；避免一上来像 Word 模板。  
2. **工作台 = 部门页；两角色重心 B；禁空总工作台，钉死薄产品首页**：作业必须落在某一站。同模板下企业简版 / 代理卷宗；禁止与公司首页抢戏的「总工作台」；`/agent` 仅主 CTA+待确认（可增强目标交办），不堆宣传货架。  
3. **产品首页后开始页分流 + 代理多案流水 + 同案协同**：研发少案、代理多案；同隐喻、两入口；代理=同案协同方，非外挂聊天窗。  
4. **七部默认、其余更多**：对齐业务「必经 vs 条件触发」，降低上手惊吓。  
5. **交卷闸做实 + 拍板在工作台右栏**（§3.1a）：齐套不过不能交卷；交卷后同屏待你确认；无人确认不换部；专家≠确认权跟人；**禁**主拍板另开页（审计/历史查阅可有）。防空材料装完成、盲确认、无人确认就递交。  
6. **后勤弱化**：期限/账单是 L2 能力，要有入口但不抢公司首页。  
7. **L1 进部门、L2 做壳**：对外说部门名，对内映射 SKU；平台不重复造十二套导航。
