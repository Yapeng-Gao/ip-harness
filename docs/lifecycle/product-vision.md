# 产品理念（Product Vision）

> **一句话（核心理念）**：给没有 IP 部（或人手不够）的团队，装上一个**外挂知识产权部**——按专利全流程办事，把技术尽快变成可递交、可授权、可维持的专利。  
> **对外品类**：可称「**虚拟知产公司**」（品类说法）；壳内一案视图仍叫「公司」；**项目 ≈ 案**。品牌句钉死「外挂知识产权部」，不换品类口号顶替品牌句。  
> **公司 / 部门 / 专家**不是产品本身，而是把核心理念讲清楚、让人容易上手的**对外叙事与流转隐喻**。  
> **结构句**：**一项目 · 一套已确认事实 · 两角色工作台重心 · 多部门接力**（工作台仍=部门页；禁空总台；人保留关键决策权）。  
> **上游**：业务总纲 [business-spine.md](business-spine.md)（含 §1.5 双轨、§3.3 G1–G3）、节点 `nodes/`、参考来源 [sources.md](sources.md)。  
> **下游**：商业切分 / SKU / 定价见 [product-logic.md](product-logic.md)（理念定「像什么、怎么走」；产品逻辑定「怎么卖、先做哪个」）。  
> **定稿**：2026-10-23（Asia/Shanghai）；**2026-10-24** Leslie 开闸增补（对齐 spine `6afa178`；Kimi 结合 [2026-10-24-kimi-combine-design.md](../superpowers/specs/2026-10-24-kimi-combine-design.md) `4483d2e`）。工作讨论底稿：[working/2026-10-23-product-vision-company-dept-expert.md](working/2026-10-23-product-vision-company-dept-expert.md)。  
> **品牌句不变**：钉死「**外挂知识产权部**」（品类可称虚拟知产公司，不顶替品牌句）。

## 1. 核心理念

| | |
|---|---|
| **是** | **外挂知识产权部**（品牌句钉死）：覆盖「拿专利」主链，关键关有人拍板，材料与期限按实务与法条走。对外品类可称「**虚拟知产公司**」；壳内一案视图仍叫公司；**项目 ≈ 案** |
| **不是** | 单点交底模板、单点查新插件、「AI Agent 目录」、**外挂聊天窗**、**万能 Agent**、或把助手/项目/专业做成**三套割裂产品** |
| **成功标准** | 研发知道案子卡在哪、该补什么；代理人与企业在**同一案子、同一套已确认事实**上协同（案卷齐、确认快、期限不漏）；无人确认不能装成已递交/已立项 |

展开四句：

1. **全流程，不只单点**：激发/挖掘可按需 → 交底 → 查新 → 立项 → 撰写 → 递交 → 答复 → 年费（支线按需开设）。业务双轨见 spine [§1.5](business-spine.md)（权利形成主线 + 风险防控副线）；七部=导航投影，不另开第二条主链、不强制扩默认七部。  
2. **简单、拟人、像公司**：用户不学编排黑话；进「公司」、看「当前部门」、认「专家交卷」。统一入口是**知产负责人**——**持续委托**（说目标 → 计划可调 → 部门执行 → 确认 → 接力），**不是**万能 Agent。品牌句仍「外挂知识产权部」。  
3. **关键关人拍板（硬闸）**：齐套不过不能交卷；交卷后默认「待你确认」；无人确认不能推进下一部门；专家建议稿≠确认；**质检 ≠ 确认权**（跟齐 spine §3.3）。产品防空材料装完成、无人确认就递交，**不替人签字**。细则 §3.1a。  
4. **一项目 · 一套已确认事实 · 两角色工作台重心 · 多部门接力**：工作台仍=部门页；**两工作台按 B**（企业默认简版重心 / 代理默认卷宗三栏）；禁空总台。详见 §3.1b / §6.3a。

## 3. 对外叙事：公司 · 部门 · 专家

> 设计这套隐喻的**唯一目的**：把核心理念传出去，降低上手成本。对内仍可用 spine / nodes / D1–D7 / HITL。

| 隐喻 | 是什么 | 不是什么 |
|---|---|---|
| **公司** | 整案的虚拟 IP 部视图；**一案 = 一条业务线**；对外品类可称「虚拟知产公司」；**项目 ≈ 案** | 用户的真实工商主体；聊天机器人品牌名；用「项目」另开一套壳 |
| **部门** | 主链上一站；**实际执行本站交卷**。进部门后用户主对象 = **本部门 / 本节点**（不是顾言） | 真实科室；随便起的菜单分组；被「总对话」替代的执行面 |
| **专家** | 部内 ≤3 岗：起草 / 检索 / 制图 / 质检等；**出建议稿**；部门台右栏**折叠**呈现 | 对外「AI Agent」；可无人确认就改法律状态的签字人；建议稿冒充确认；质检通过冒充确认 |
| **知产负责人（顾言）** | **统一入口 · 持续委托**：听目标 → 计划可调 → **分发 / 路由到部门** → 跨部接力。产品内可落名「顾言」 | **万能 Agent**；**部门内改文书时的主聊伴**；替代部门执行；替代确认权；外挂聊天窗顶替同案协同；只 toast 不走通链路 |
| **你（确认权）** | **确认页拍板**：G1 齐套后交卷 → 待你确认；过才移交 / 改法律相关状态 | 装饰「下一步」；专家/起草人自批；质检勾选冒充确认 |
| **交卷 · 待你确认** | **硬闸体验**：齐套后才能交卷；交卷后停下等人确认，才移交下一部门或改法律相关状态 | 装饰按钮；灰了还能点；无决策含义的「下一步」；专家自批冒充确认；质检勾选冒充确认 |

**对外禁用**：Agent、Harness、智能体编排、Seat、HITL（改用「待你确认」「部门闸」「知产负责人」等）。  
**部内可见岗**：默认控制在少量（约 2–3），避免滑回「机器人目录」。  
**代理所定位**：同案专业协同方——共享同一项目（案）与已确认事实；不是另开聊天窗旁路。

### 3.1 运转规则（业务口径）

```
公司（整案）
  └── 部门（主链节点）  —— 输入契约 · 交卷 · 完成标准
        └── 专家（部内岗） —— 协作做齐交卷；多为建议稿
              └── 交卷闸「待你确认」—— 人采纳后才移交或改法律相关状态
```

1. **一案一公司视图**：始终能回答「现在在哪个部门」。  
2. **一部门一交卷（G1）**：齐套清单未勾齐 → 不得标部门完成 → 不得进「待你确认」（spine §3.3；INV-7）。  
3. **专家可并行，部门默认串行**；允许标注的回流（如查新退回交底补强；确认驳回回流当前部）。  
4. **确认权跟人走（G2）**：确认人=发明人/代理人/企业负责人等；专家仅建议；起草人不得自批。  
5. **法定动作不可业务跳过**：递交、缴费、实审、年费等以法条与期限为准。

### 3.1a 「交卷 · 待你确认」硬闸体验（Leslie 已定 · 已跟业务）

> **问题**：理念叙事已在页上，仍缺「外挂部真在办事」——要把交卷闸 + 确认权**做实**（期限 / 账单后置，不抢本闸）。  
> **边界**：仍用公司 / 部门 / 专家隐喻；**对外禁用** Agent / Harness / Seat / HITL 等黑话。  
> **业务硬口径（已收口）**：[business-spine.md §3.3](business-spine.md) G1–G3；演示优先段 nodes `00` / `01` / `02`。逐页硬闸见 [product-pages.md](product-pages.md)。

**登录后路径不变：** 公司首页 → 部门工作台 → 铃铛确认（见 §3.2）。

#### 业务三条硬规则（原文 · 跟齐）

1. **一部门一交卷**：本部门齐套清单未勾齐 → 不得标「部门完成」→ 不得进入「待你确认」推进态。  
2. **确认权跟人走**：确认人 = 发明人 / 代理人 / 企业负责人等真实主体；专家只有建议权；起草人不得自批自己的交卷。  
3. **无人确认 → 不得移交下一部门**，不得装成已递交 / 已立项。确认页：过 → 移交；驳回 → 回流当前部补齐（可标回流）。

#### 用户应感到什么 / 禁止什么（体验层）

| # | 对应 | 用户应感到什么 | 禁止什么 |
|---|---|---|---|
| 1 | G1 | **齐套不过 → 交卷 CTA 不可用**（灰且点不动；明示缺什么）；进不了「待你确认」 | 灰了还能点；点了装「部门完成 / 已交卷」；未齐套溜进待确认 |
| 2 | G2 | **专家建议稿 ≠ 确认**；确认权跟人；**质检 ≠ 确认权** | 专家采纳 / 起草人自批 / 质检勾选冒充确认；「AI 已通过」当拍板 |
| 3 | G3 | **交卷后默认进「待你确认」**；过才移交、驳回回流当前部；无人确认卡住可见 | 无决策含义的「下一步」换部；无人确认装成已递交 / 已立项 |

**成功标准（体验）：** 用户能指出「卡在齐套 / 卡在等人确认 / 已确认可往下」；截图不能把未齐套或未确认的案子读成已办完。

### 3.1b 结构句与两工作台（Leslie 开闸 · 2026-10-24）

> **结构句**：**一项目 · 一套已确认事实 · 两角色工作台重心 · 多部门接力**。  
> **工作台仍 = 部门页**。**禁止**空「总工作台」。G1–G3 硬闸原文跟齐 [business-spine.md §3.3](business-spine.md)（含 **质检 ≠ 确认权**），本文不改闸门口径。

| 项 | 定稿 |
|---|---|
| **一项目** | 对外可说「项目」；壳内 = **一案一公司视图**（项目 ≈ 案） |
| **一套已确认事实** | 企业与代理在同一案子上共享已确认事实；确认后才进下一接力，不各写各的真相 |
| **两角色工作台重心（B）** | **同一部门页模板**，按角色默认重心不同——**企业**：简版重心（事项 / 已确认事实 / 待决策）；**代理**：卷宗三栏重心。**不是**两套产品，**不是**空总台 |
| **一屏 Cursor 三栏（Leslie 已定）** | 部门工作区固定同屏三栏，**版面权重**：左目录可折 **~200px**；**中可编产物 `1fr` 主舞台**；右对话+齐套闸 **瘦辅栏 ~260–280px**。协同面落右栏/同屏；**禁止**文书/协同双视图或 Tab 两套工作面。顾言在部门台仅**弱入口**（换部 / 改目标），不是部内主聊伴。细则 §6.3a / §6.4 |
| **多部门接力** | 默认七部串行接力 + 标注回流；不扩默认七部（更多进折叠） |
| **人保留关键决策权** | 确认权跟人；专家建议稿 ≠ 确认；质检 ≠ 确认权 |

### 3.1c 持续委托边界（知产负责人 / 顾言 · Leslie / Kimi 结合）

> **依据**：[2026-10-24-kimi-combine-design.md](../superpowers/specs/2026-10-24-kimi-combine-design.md) `4483d2e`。  
> **增强现有 hops，不拆掉** 登录 → 薄入口 → 公司 → 部门 → 铃铛。硬闸 G1–G3、七部导航投影、薄入口骨架**不动**。品牌句仍「**外挂知识产权部**」。  
> **变更理由（2026-10-24 · Leslie 开闸）**：钉清 **顾言 vs 部门 vs 专家 vs 你** 交互归属——顾言只管入口/路由/跨部接力，**不**当部内改文书主聊伴、**不**替代部门执行。

| 项 | 定稿 |
|---|---|
| **结合原则（理念侧）** | 一家公司 + **一个知产负责人（顾言）持续委托** + 部门按需可见 + 可信交付 |
| **可点链（须走通）** | **提目标 → 计划可调 → 部门执行 → 确认 → 接力**。原型 / 规格须可点通，**禁止**只弹 toast 假装委托 |
| **MVP 落点** | 薄入口主 CTA / 开案子可发起持续委托；交办后仍进**公司首页**认知，部门由负责人路由（部门退二线，不拆七部投影） |
| **薄入口轻量轨** | 主 CTA（持续委托）之外：「**现在需要我处理**」= 待确认 / 待接力；**禁止**做成跨案「公司经营首页」完整经营台 |
| **不是** | 万能 Agent；拆掉双角色分流；用聊天窗替代公司/部门页；跳过交卷闸与确认权；Kimi 式跨案经营台顶替薄入口 |

#### 交互归属（顾言 · 部门 · 专家 · 你）

| 角色 | 管什么 | 不管什么 |
|---|---|---|
| **顾言（知产负责人）** | 听目标、计划可调、**分发/路由到部门**、跨部接力 | 部门内改文书时的**主聊伴**；替代本站执行；替代确认权 |
| **部门** | **实际执行本站交卷**；进部后用户主对象 = **本部门 / 本节点** | 被总对话架空；跨部经营台 |
| **专家** | 部内 ≤3 岗出**建议稿**；右栏**折叠**呈现 | 建议稿当确认；质检冒充确认 |
| **你** | **确认权**（确认页）；G1 齐套 → 交卷 → 待你确认 | 装饰下一步；自批 / 专家代签 |

**部门台里的顾言：** 仅**弱入口**（换部 / 改目标）；右栏默认对话对象是**本部门 / 本节点**，不是顾言主会话。

### 3.1d 三档可见性 · 真行为（同一底座）

> **变更理由（2026-10-24 · Leslie 开闸）**：对照 Kimi「顶栏三档 + 侧栏专业工作室」——**只取顶栏三档递进**；**拒绝**侧栏再开「专业工作室」目的地（部门模板 / Skill / Prompt / MCP / 测试发布）。专业深度落在**同一案子干活面上的密度**，不是组装后台。依据结合 spec [2026-10-24-kimi-combine-design.md](../superpowers/specs/2026-10-24-kimi-combine-design.md)，本条钉死取舍。  
> 三档 = **同一案子底座的使用深度**，入口仅在**顶栏切换**。可见性必须有**真行为差**（截图能分出），不是换皮标签，**不是**三套产品壳。

| 档 | 真行为（可见性） | 边界 |
|---|---|---|
| **助手** | **藏**侧栏与**部门地图**（七部墙弱化/收起）；以知产负责人对话与轻量事项为主 | 不另开产品壳；公司页七部网格可弱化但仍可按需唤回 |
| **项目** | **日常干活默认**：保留公司页七部认知锚 + 部门工作台；持续委托链完整可走 | 默认上手深度 |
| **专业** | **同一干活面加重**：公司多案 / 卷宗密度↑、案盘信息加重、部门 Cursor 三栏更满（代理默认靠此档） | **禁止**侧栏「专业工作室」总页；**禁止**把专业做成第二套产品壳或「组装部门模板」后台 |

**入口规则：** 只留**顶栏**助手 / 项目 / 专业；**禁止**侧栏（或第二入口）再开「专业工作室」目的地。  
**公司页：** 七部网格仍是**认知锚**（不扩默认七部）；助手档弱化部门墙，项目档保留；部门作业退二线，由知产负责人路由进部。  
**后置（不进主干活路径）：** 若未来要「配专家 / 部门模板」，须标为**后置 / 另面**，**不进** 宣传→登录→薄入口→公司→部门台→确认。

|---|---|---|
| **顶栏三档** | 有（助手/项目/专业） | **要**：同一案子底座的使用深度（本§） |
| **侧栏「专业工作室」** | 有 → 部门模板 / Skill / Prompt / MCP / 测试发布 | **不要**：禁止侧栏目的地；专业≠组装后台 |
| **专业真行为** | 进工作室配置墙 | **公司多案/卷宗密度、案盘加重、部门三栏更满** |
| **可参考的逻辑** | 三档递进上手；专业侧能力更重；代理偏专业深度；持续委托/负责人 | **理念层可借**；落点仍外挂 IP 部隐喻 |
| **明确不抄** | 专业工作室总页、部门模板目录、MCP/Prompt 配置墙、橙皮、双入口进专业 | 写入 §6.6；品牌句仍「外挂知识产权部」 |

### 3.1e 空间与交付快照（一句）

确认通过后，用户须能看见**本站交付快照**（交卷摘要 / 已确认事实一小格）——可信交付可见，不是黑箱过闸。Kimi 四类确认仅作**类型标签**（页面规格承接细目），**不**另开闸门、**不**改 G1–G3。空间仍落在公司 / 部门页内，不另起「总空间」壳。

### 3.2 上手路径（主链 hops）


> 一页图+禁区交卷物：[working/2026-10-23-onboarding-path-and-forbid.md](working/2026-10-23-onboarding-path-and-forbid.md)。

**主链（人人同一骨架）：**

```
登录 → 产品首页 /agent →（代理：多案流水｜企业：开案子/公司首页）
     → 公司首页 → 七部部门工作台 → 确认页（铃铛）
```

| # | 这一跳 | 用户应感到什么 | 禁止什么 |
|---|---|---|---|
| − | **未登录宣传站**（官网式） | 「一眼品类 + 货架：七部、专家、场景、案卡/交卷橱窗」——**宣传/教育放这里**（pages §4.0p） | 做成必须登录才看懂；与登录后 `/agent` 同构第二套产品首页 |
| 0 | **登录** | 「选我是代理还是企业，然后进干活入口」 | 登录后无首页直跳乱页；同页滤权限冒充双角色；**把宣传站整页复制成** `/agent` |
| 1 | **产品首页** `/agent` | 「薄入口：一屏一个主 CTA（可持续委托）+『现在需要我处理』轻量轨（待确认/待接力），马上进干活」 | **三卡平铺**；货架/七部墙/专家宣传墙；整页官网卖点；首页编辑交卷；空总工作台；**跨案经营台**；替代案盘/公司；Agent 目录 |
| 2a | **多案流水**（代理） | 「我的案子清单：卡在哪、谁待确认、期限红点」 | 做成企业单案陪跑页；塞七部作业；无案名/当前部门就进深页 |
| 2b | **开案子**（企业无案） | 「三步立一条业务线，然后进公司」 | 长表单；先丢进交底 Word；跳过公司首页认知 |
| 3 | **公司首页**（一案） | 「七部等宽卡片仍是认知锚；点某部右侧抽屉见 ≤3 专家+交卷态；主 CTA 去当前部门 / 负责人路由；助手档可弱化部门墙」 | 直进交底表单；十二部一屏全开；专家花名册墙；暗色皮肤照搬；右侧假指标/执行集群/工具引擎卡；与产品首页同构的第二套总览；拆掉七部投影 |
| 4 | **部门工作台**（七部） | 「一屏三栏权重：左可折~200 / 中`1fr`主舞台 / 右瘦辅栏~260–280；右栏默认节点一句+对话+齐套+单闸，专家/契约折叠；顾言仅弱入口；齐套不过交卷点不动；建议稿≠确认」 | 无交卷物装完成；齐套不过仍可点交卷；>3 专家岗变目录；无公司顶栏；右侧假指标/执行集群/工具引擎；抄暗色；专家采纳当确认；退回「主区+右钉」两栏；**文书/协同双视图或 Tab 两套工作面**；顾言抢成部内主聊伴；右栏胖过中栏 |
| 5 | **确认页** | 「这是拍板，不是下一步；过/驳回有决策含义；不过不能换部；确认后可见交付快照」 | 无决策含义的「下一步」；起草人/专家自批；空材料装通过；无人确认推进下一部门；不可逆无责任提示；过闸无快照黑箱 |

**双角色（从产品首页分出，不是同页滤权限）：**

| 角色 | 产品首页主 CTA（一屏一个；禁三卡平铺） | 之后 |
|---|---|---|
| **代理** | → **进入案盘**（多案流水） | 点进某案 → 公司首页 → 部门台（**卷宗三栏重心**）→ 铃铛 |
| **企业** | → 无案**开案子**（可交办业务目标） / 有案**进入本公司** | 「去当前部门」→ 部门台（**简版重心：事项/事实/决策**）→ 铃铛 |

进公司后壳与部门台**骨架共用**（两工作台 **B**：同模板、角色默认重心不同；禁空总台）。持续委托可点链见 §3.1c（增强、不拆本表 hops）；三档真行为见 §3.1d。

### 3.3 登录前宣传站 · 登录后薄入口（Leslie 已定）

> **已定（2026-10-23）**：宣传页 = **登录前**（官网式）；登录后 `/agent` = **薄入口**（主 CTA + 待确认进干活）。货架 / 七部徽章墙 / 专家等**宣传内容上登录前站**，**不上**登录后产品首页。  
> **施工细化（Leslie 选 A · 禁止三卡平铺）**：[../superpowers/specs/2026-10-23-welcome-thin-home-dual-role.md](../superpowers/specs/2026-10-23-welcome-thin-home-dual-role.md)。

#### A. 未登录宣传站（官网 · 获客）

| 问题 | 定稿 |
|---|---|
| 像什么 | **官网式宣传站**：品类大标题 + 看得见的货（可参考 [kuaipao.pro](https://kuaipao.pro) 一类「一眼品类」） |
| 大标题 | 固定「**外挂知识产权部**」（字号明显大于后文） |
| 定位句 | 钉死一句：「**把办专利的全流程，拆成七个可交卷的部门。专家出建议稿，你来拍板。**」——禁再堆理念散文 |
| 放什么 | **货架宣传**：示范案卡、**七部全展示**徽章墙（部名+职责一句）、每部 **≤3 专家岗**（头像占位+岗名）、**场景**（≥2：企业走七部 / 代理多案；可选确认拍板）、交卷/待确认样例橱窗——让未登录访客看懂「外挂 IP 部」 |
| CTA | 主「**登录干活**」→ 登录；次「**先看货架**」锚到本页货架 |
| 边界 | **不在**登录后产品信息架构内（获客另做）；不替代案盘/公司/部门作业；逐页规格见 [product-pages.md §4.0p](product-pages.md)；施工细化见 [welcome-thin-home-dual-role](../superpowers/specs/2026-10-23-welcome-thin-home-dual-role.md) |
| 禁止 | 与登录后 `/agent` **同构**成第二套产品首页；要求登录才能完成「看懂品类」；本页交卷/齐套/拍板/进部门作业 |

#### B. 登录后产品首页 `/agent`（薄入口）

| 问题 | 定稿 |
|---|---|
| 像什么 | **薄入口**：人人登录后先落这里；一眼知道往哪走、有哪些待处理（持续委托 + 轻量轨） |
| 必须有 | **角色主 CTA 一屏一个**（可持续委托 / 代理→进入案盘；企业有案→进入本公司 / 无案→开案子；**禁止三卡平铺**）+ **「现在需要我处理」轻量轨**（待确认 / 待接力，点进确认或接力）；另一角色入口仅弱链 |
| 可有 | ≤1 句极短定位（可省）；可选弱链（多案/开案子/最近案等）；**不得**压过 CTA / 轻量轨，**不得**做成第二货架或跨案经营台 |
| 规格 | 逐页见 [product-pages.md §4.0a](product-pages.md)；结合依据 [kimi-combine-design](../superpowers/specs/2026-10-24-kimi-combine-design.md) |
| 验收 | 截图应读出：「马上能进干活 / 持续委托」——不是「再看一遍官网」、不是跨案经营台 |
| 不是什么 | **不是**宣传货架；**不是**七部徽章墙 / 专家橱窗；**不是**作业台；**不是**跨案「公司经营首页」；不替代案盘 / 公司首页 |

**主 CTA（离开首页去干活）：** 代理→案盘；企业有案→公司；无案→开案子；均可挂**知产负责人持续委托**入口。首页成功 = 用户点主 CTA 或「现在需要我处理」离开，而不是留在首页看宣传。

#### 禁放（登录后 `/agent`）

- 货架三件套 / 七部徽章墙 / 专家岗宣传（含「默认露出 ≤3」橱窗）——这些属**登录前宣传站**  
- 把未登录官网**整页复制**成登录后首页  
- 整页卖点墙、理念长文、路径微图作业区  
- 首页交卷 / 齐套 / 确认拍板 / 部门作业  
- 空「总工作台」抢戏；第二套公司首页；**跨案经营台**；Agent 目录 / 专家花名册墙  
- 对外 Agent / Harness / 智能体编排 / Seat / HITL；只 toast 的「假持续委托」

## 6. 信息架构：页面清单 · 工作台 · 理由

```
        → 交卷 → 确认页（铃铛）→ 回公司首页或下一部门工作台
```

**产品首页（已定）：** 登录后**默认先落** `/agent` = **薄入口**（§3.3：主 CTA + 待确认）。宣传货架上登录前站。  
**双角色两套页面（已定）：** 「开案子」与「多案流水」是**两张开始页**（从产品首页分出）；不得用单页+权限开关代替。  
**案级默认落点：** 有案时进**公司首页**（先认知，再干活）；不是直接进交底表单。产品首页**不**替代公司首页。

> **版面权重（Leslie 已定）：** 左可折 **~200px** · 中 **`1fr` 主舞台** · 右瘦辅栏 **~260–280px**。纸墨浅色；禁专业工作室；禁文书/协同双视图。

2. **本部门一句话** + 在七部主链上的位置（右栏默认露出这一句）  
3. **左栏 · 目录**（可折 ~200px）：本站材料 / 节点树（点开换中栏）  
4. **中栏 · 可编产物（`1fr` 主舞台）**：交卷正文编辑 / 预览（与右栏**同屏**，不切「文书模式」全屏）

### 6.5 为什么这样切页（理由）

1. **宣传在登录前，干活入口在登录后**：未登录站讲清品类与货架；登录后 `/agent` 只分流。进案后再认「一个部」；避免一上来像 Word 模板。  
2. **工作台 = 部门页；两角色重心 B；禁空总工作台，钉死薄产品首页**：作业必须落在某一站。同模板下企业简版 / 代理卷宗；禁止与公司首页抢戏的「总工作台」；`/agent` 仅主 CTA+待确认（可增强目标交办），不堆宣传货架。  
3. **产品首页后开始页分流 + 代理多案流水 + 同案协同**：研发少案、代理多案；同隐喻、两入口；代理=同案协同方，非外挂聊天窗。  
4. **七部默认、其余更多**：对齐业务「必经 vs 条件触发」，降低上手惊吓。  
5. **确认页独立 + 交卷闸做实**（§3.1a）：齐套不过不能交卷；交卷后待你确认；无人确认不换部；专家≠确认权跟人。防空材料装完成、无人确认就递交。  
6. **后勤弱化**：期限/账单是 L2 能力，要有入口但不抢公司首页。  
7. **L1 进部门、L2 做壳**：对外说部门名，对内映射 SKU；平台不重复造十二套导航。

### 6.6 明确不做（本阶段）

- 把**未登录官网宣传站**整页复制成登录后 `/agent`（登录后 = **薄入口**，见 §3.3 B）  
- 登录后 `/agent` 再堆**货架 / 七部墙 / 专家宣传**（这些只属登录前站，见 §3.3 A）  
- 登录后 `/agent` **三卡平铺**（案盘/公司/开案子同屏同级大卡）；真双角色见 §3.3 B  
- Agent 目录墙、专家花名册墙（登录后产品壳）  
- 部门台退回「主区交卷 + 右钉」两栏（权威 = **一屏 Cursor 三栏**，§3.1b / §6.3a / pages §2）  
- 「文书工作 / 协同工作」**双视图**或 Tab 切成两套工作面（协同须落右栏/同屏）  
- 部门台把**顾言**做成部内改文书主聊伴，或用顾言对话替代本部门执行  
- 右栏胖过中栏主舞台；右栏默认摊开专家墙/契约全文（正确=折叠；默认只露节点一句+对话+齐套+单闸）  
- 公司/部门右侧堆**假指标、执行集群、工具引擎卡**；照搬参考图**暗色皮肤**（只借信息结构）  
- 十二部一屏全开  
- **与公司首页抢戏的空「总工作台」**；产品首页不堆部门作业，也不替代案盘/公司首页  
- 把「两工作台」做成**两套产品壳**或空总台（正确 = B：同部门页模板、角色默认重心不同）  
- 用**万能 Agent / 外挂聊天窗**替代知产负责人持续委托或同案协同；**只 toast 不走通**委托链  
- 登录后做成 Kimi 式**跨案公司经营首页**（薄入口 hops 不动）  
- **扩默认七部**为全生命周期墙（更多仍折叠；对齐 spine §1.5）  
- 把助手/项目/专业做成**三套割裂产品**或仅换皮无真行为差  
- **侧栏「专业工作室」**目的地；部门模板目录 / Skill / Prompt / MCP / 测试发布墙；双入口进专业；把专业做成「组装部门模板」后台  
- 确认过闸无**交付快照**（黑箱）；把四类确认标签升级成新硬闸  
- 把 L4 诊断咨询做成上手第一屏  
- 齐套不过仍可点交卷装完成；交卷后无确认「下一步」换部；专家/起草人自批冒充确认；**质检勾选冒充确认**（见 §3.1a / spine §3.3）
