# Findings

- 当前工作树有大量用户未提交改动，修改必须增量落在相关 UI。
- Agent 首页、交底部工作台、待办驾驶舱已在浏览器检查；首次使用大厅当前可隐藏专家预览，八部门仍可直达。
- 交底部工作台已有当前步骤、职责边界、负责人状态和移交确认；仍有工作区辅助文本/术语需检查。
- 待办列表默认展示方案与等待时间，依据和专家建议折叠；部门状态构建错误已通过传入 confirmKind 修复。
- 新发现：`buildAskEvidence` 对缺少来源/对比的确认项会填入标注为“示意”的兜底文案，但将其当作 present，可能错误显示“依据已齐”。需将样例兜底与真实依据分开计算。
- 产品理念中的多人拍板仲裁、真实分层记忆、真实鉴权和后端服务并非纯 UI 可实现，评估时必须单列。
- 接待跳转曾把新用户来意挂到最近更新的预置样例案（如“传感校准套件”）上，导致真实来意和示例稿/已完成状态并置。首页“最近案”现在排除预置业务种子；无自建案件时进入开案流程，来意预填在案名和技术描述中。
- 浏览器主路径：输入“我想整理技术交底，缺少测试数据”→建议交底部→新建案件页。来意和拟案名均可见，尚未创建持久化测试案。
- 当前理念覆盖判断：前台领路、部门职责、人的拍板权、依据/示意区分、退回/交接方向已有可见表达；首用案卷归属行为刚修复。多人权限、真实身份鉴权、真实法律/检索来源、真实文件校验与官方提交、付款、跨会话/跨设备记忆未连接，不能据 UI 认定已实现。
